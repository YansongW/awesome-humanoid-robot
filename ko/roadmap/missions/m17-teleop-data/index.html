M17 · 원격 조작과 데이터 수집: 모방 학습의 밑거름은 이렇게 만들어진다

전체 위치: 팔(M15)과 인식 스택(M16) 준비 완료 후, 모방 학습 훈련(M18) 전. 입력은 안전하게 움직일 수 있는 로봇 + 보정된 인식 스택 한 세트이며, 출력은 ≥50개의 품질 검사를 통과한 에피소드 데이터셋입니다. M18의 훈련 스크립트를 바로 사용할 수 있으며, 재작업이 필요 없습니다.

전제 조건: M16 검수 통과(인식 출력 안정, 시간 동기화 확인 완료); 로봇 안전하게 전원 공급 및 작동 가능, 비상 정지 회로 사용 가능(3단계 개요 15단계 참조).

이론적 배경: 제17장 원격 조작과 인간-로봇 협력은 원격 조작 시스템 설계를 다루고, 제21장 데이터 인프라는 데이터 파이프라인을 다루며, 부록 B 주요 데이터셋 목록은 비교 가능한 공개 데이터셋입니다.

1단계: 원격 조작 방식 선택

【무엇을 할 것인가】 네 가지 옵션을 비교하여 예산과 작업에 따라 하나를 선택합니다:

방식 비용 규모 데이터 품질 적합 대상
leader-follower 주종 팔(ALOHA 방식) 세트 약 2만 달러 수준(카드 기준) 높음: 동형 매핑, 관절 수준 대응 양팔 정밀 작업
VR 컨트롤러/헤드셋 소비자용 VR 기기 가격 중간: 말단 자세 + 자세 재지정 이동형 휴머노이드, 전신 원격 조작
외골격 공급업체에 직접 문의 필요 높지만 착용이 번거로움 연구형 팀
키보드/조이스틱 거의 무료 낮음: 속도 느림, 동작 거침 최후의 수단 파이프라인 검증

두 가지 중요한 변형:

  • 전체 기기 없이도 수집 가능: UMI 그리퍼 인터페이스 – 손에 쥐는 그리퍼 + 손목 카메라, 사람이 그리퍼를 들고 시연하면 훈련 데이터 수집 가능(카드 기준).
  • 이동형 휴머노이드 실용적 분업: 하체 조이스틱 고정 + 상체 주종, Mobile ALOHA의 전신 원격 조작 아이디어 차용(3단계 기준) – 원격 조작으로 걸으면서 정밀 파지를 동시에 하려고 하지 마세요.

앵커: ToddlerBot은 동형 시연 팔(그립 내장 FSR 힘 감지 저항) + 휴대용 게임기 조이스틱/버튼 사용, 2.0 버전은 Meta Quest 2 VR 원격 조작 추가; Berkeley Humanoid Lite는 SteamVR 베이스 스테이션 + 컨트롤러로 양팔 원격 조작하여 큐브 맞추기, 글쓰기, 블록 쌓기 시연 수행(ToddlerBot 논문 및 Berkeley Humanoid Lite GitHub 참조).

【이유】 원격 조작은 일석삼조: 하드웨어 도달 가능성 검증, 모방 학습 데이터 수집, 작업 기준선(baseline) 구축(3단계). VR 방식에는 두 가지 엄격한 제약이 있습니다: 지연 시간(종단 간 지연이 수백 밀리초 수준이면 조작자 감각이 현저히 나빠짐, 엔지니어링 경험치, 시스템 실측에 따름)과 멀미 – 먼저 소규모로 지연 시간을 측정한 후 장시간 수집을 계획하세요.

【상황 분석】 예산이 매우 제한적: UMI로 먼저 수집하고 형식을 맞춘 후, 나중에 실제 로봇으로 교체하여 재사용; 이족 보행 휴머노이드 보유: 상체 주종 + 하체 조이스틱 고정; 파이프라인만 검증하려는 경우: 조이스틱으로 "녹화 → 재생 → 훈련" 루프를 기본적으로 돌리고, 이후 장비 업그레이드.

2단계: 수집 파이프라인 구축

【무엇을 할 것인가】 "무엇을 녹화할지, 어떻게 녹화할지, 어디에 저장할지"를 규격으로 고정:

  1. 기록 필드(3단계 9단계와 일치): 다중 시점 이미지(머리 + 양쪽 손목), 관절 상태(위치/속도), 동작(주종 매핑 후 목표 관절 위치), 언어 명령, 타임스탬프.
  2. 통합 프레임률: 모든 스트림을 10–30 Hz로 통일 샘플링(엔지니어링 권장값, 저장 및 연산 능력에 따라 실측 후 확정), M16의 시간 동기화 시설을 재사용하여 정렬.
  3. 저장 형식: ROS 2 bag으로 시작; 오픈소스 훈련 생태계와 연동하려면 LeRobot 또는 RLDS 스타일 사용 – Open X-Embodiment는 바로 통일된 RLDS 형식으로 여러 본체의 수백만 개 시연 프레임을 집계하며, VLA 사전 훈련 표준 말뭉치입니다(카드 기준).
  4. 디렉토리 및 명명: 작업명/날짜/조작자/에피소드_번호, 메타데이터(보정 버전, 명령 텍스트, 성공 레이블)는 패키지와 함께 저장.

【이유】 형식이 재사용성을 결정합니다: 필드 하나가 누락되면(예: 언어 명령 미저장), 나중에 명령 조건부 정책을 훈련하려면 전체 배치를 다시 수집해야 합니다. 명명 규칙을 통해 "어느 데이터가 어떤 보정 버전으로 수집되었는지" 추적 가능 – 보정이 만료된 배치는 전체를 걸러낼 수 있어야 합니다.

【상황 분석】 단일 기기 단일 작업: bag + 파싱 스크립트 하나면 충분; 다중 작업/다중 로봇 계획: 바로 LeRobot/OXE 형식에 맞추고, 처음부터 독자적인 형식을 만들지 마세요.

3단계: 작업 및 시나리오 설계

【무엇을 할 것인가】

  1. 단일 작업부터 시작: 첫 번째 작업은 "컵을 잡아 상자에 넣기"로 고정, 전체 파이프라인을 돌린 후 작업 종류 확장.
  2. 시나리오 무작위화 목록: 물체 위치/자세(작업 공간 내 균일 분포), 조명(밝기/방향 변화), 배경(식탁보/잡동사니 교체), 방해물(점진적으로 무관한 물체 추가). 각 에피소드 녹화 전에 무작위화 수준을 결정.
  3. 명령 템플릿화: "{물체}를 {용기}에 넣어" 형식의 템플릿, 어휘 목록 고정, 에피소드에 저장되는 명령 문자열은 항상 템플릿에서 생성.
  4. 성공 기준 사전 정의: 예: "그리퍼 닫힌 후 물체가 3초 동안 정지하여 떨어지지 않고, 최종적으로 용기 안에 들어감" – 각 에피소드는 즉시 성공/실패 레이블 지정.

【이유】 정책은 데이터 분포를 학습합니다: "컵이 정중앙에만 있는" 데이터만 수집하면 정중앙에서만 잡습니다. 무작위화 목록은 정책의 일반화 경계이며, 수집 계획에 명시해야지 당일 기분에 따라 정해서는 안 됩니다. 성공 기준이 모호하면 레이블 노이즈가 발생 – M18 훈련 시 "같은 시연인데 어떤 것은 학습되고 어떤 것은 안 되는" 현상으로 나타납니다.

【상황 분석】 고정형 데스크탑 기기: 무작위화는 먼저 물체 위치/자세 두 가지(가성비 최고); 조명과 배경 등은 단일 작업 성공률이 안정된 후에 추가. 무작위화 수준 하나 추가 시, 에피소드 예산은 두 배로 증가.

4단계: 수집 실행 규칙

【무엇을 할 것인가】

  1. 품질 > 수량: 동작 안정적, 속도 적절(조작자가 "약간 느리다"고 느끼는 템포가 적절), 가림 없음; 화면에 항상 말단과 목표물이 동시에 보여야 함.
  2. 실패 에피소드 처리: 시연 중간에 실패한 전체 에피소드는 보존하고 실패 레이블 지정, 단 M18 훈련은 기본적으로 성공 집합만 사용; 조작자가 의도적으로 시연한 "실수로부터 회복" 조각(떨어뜨린 후 다시 잡기)은 별도 표시 – 회복 데이터는 정책 오류 수정을 가르치며 가치가 높지만, 비율은 20~30% 이내로 제어(엔지니어링 권장값), 그렇지 않으면 정책이 "의도적 실수"를 학습할 수 있음.
  3. 생산성 예상: 숙련된 조작자 시간당 10–20개 수준(엔지니어링 권장값, 시나리오 재설정 및 샘플 검사 포함); 50개 고품질 데이터는 3–5시간 작업 계획.
  4. 즉시 재생 샘플 검사: 5–10개 수집 시 1개 재생, 화면, 시간 정렬, 레이블 확인; 다중 조작자 수집 시 각 에피소드의 조작자 ID 기록 – 스타일 차이는 데이터 분포의 일부.

【이유】 모방 학습은 시연 품질에 극도로 민감: 떨리고 빠른 시연을 학습하면 정책도 떨리고 빠르게 나옵니다. 즉시 샘플 검사는 "하루 종일 수집했는데 타임스탬프가 모두 어긋난" 사고를 10개 이내로 압축합니다.

【상황 분석】 단독 프로젝트: 자신의 템포를 정하고, 차라리 하루 20개 고품질; 교대 근무: 작업 시작 전 3개의 "표준 시연"을 함께 보고 감각을 교정하고, 작업 종료 후 서로의 2개를 교차 확인.

5단계: 데이터 품질 검사 및 분할

【무엇을 할 것인가】

  1. 자동 품질 검사 스크립트, 각 에피소드 세 가지 검사 통과:
  2. 시간 정렬: 이미지와 동작 타임스탬프 오차 < 1프레임 수준(엔지니어링 권장값);
  3. 프레임 드롭 감지: 각 스트림 실제 프레임률 vs 목표 프레임률, 프레임 드롭률 초과 시 노란색 표시;
  4. 이미지 품질: 흐림(라플라시안 분산), 과다/과소 노출(히스토그램)을 임계값으로 필터링.
  5. 훈련/검증 9:1 분할: 에피소드별 무작위 분할, 검증 집합은 한 번 정해지면 고정, M18의 모든 실험에서 동일한 집합 사용.
  6. 데이터셋 카드(dataset card): 로봇 모델/센서 구성/보정 버전/수집 날짜/작업 정의/명령 템플릿/에피소드 수 및 통계, 한 페이지로 정리. DROID는 분산 다중 실험실 수집의 규범 참조(카드 기준, 한계: 고정 팔만 포함); Open X-Embodiment는 교차 본체 집계의 형식 참조.

【이유】 "데이터를 사용할 수 있는지"는 기억이 아닌 스크립트에 의존: 품질 검사 보고서(정렬 오차, 프레임 드롭률, 흐림 비율)를 보관하면, M18 훈련 중 문제 발생 시 데이터 의혹을 먼저 배제할 수 있습니다. 데이터셋 카드는 한 달 후, 또는 다른 사람이 인수할 때 유일한 진실 출처입니다.

【상황 분석】 50개도 전체 절차를 따라야 함: 스크립트를 한 번 작성하면 500개일 때 비용 없이 재사용; 검증 집합 5개도 남겨야 함 – 고정된 검증 집합이 없으면 M18의 모든 "개선"을 원인 규명할 수 없습니다.

검수 기준

  • [ ] ≥50개의 품질 검사를 통과한 에피소드(Stage 3 판정 기준), 성공/실패 레이블 완비.
  • [ ] 기록 필드와 프레임률 규격이 문서화되어 있으며, 실제 측정 시 M18 훈련 스크립트에서 직접 읽을 수 있음.
  • [ ] 시나리오 무작위화 목록과 명령 템플릿이 고정되었으며, 에피소드가 무작위화 각 단계를 포함함.
  • [ ] 품질 검사 보고서 보관: 시간 정렬 오차, 드롭 프레임률, 이미지 품질 통계에 숫자 포함.
  • [ ] 훈련/검증 9:1 분할 완료, 검증 세트 고정.
  • [ ] 데이터 세트 카드 문서화: 로봇/센서/캘리브레이션 버전/날짜/작업 정의/통계 및 운영자 정보 포함.
  • [ ] 데이터 백업 완료: 원본 bag과 파싱된 형식 각각 1부씩, 다른 디스크 또는 다른 장소에 보관.

일반적인 문제점 및 점검

증상 가능한 원인 점검 조치
정책 동작이 항상 화면보다 느림 이미지-동작 타임스탬프 드리프트를 인지하지 못함 품질 검사 스크립트로 정렬 오차 확인; M16에서 이중 기계 시간 동기화 확인
재생 시 특정 구간 이미지 프레임 끊김 수집 중 드롭 프레임(USB 대역폭/디스크 쓰기 병목) 드롭 프레임 보고서 확인; 해상도 낮추거나 SSD 교체; M16에서 USB 토폴로지 확인
정책이 떨리는 동작을 학습함 시연 자체가 빠르고 떨림 시연 재생 비디오 샘플링; 조작 속도 낮춰 재수집
물체 위치만 바뀌면 잡지 못함 중심 영역/단일 자세만 수집함 무작위화 목록 대조하여 가장자리와 다양한 자세 추가 수집
