M06 · 펌웨어와 캘리브레이션: 쇳덩이가 처음으로 명령을 이해하게 하다

전체 위치: M05 조립 완료 후, M07 벤치 테스트 전. 입력은 조립되었지만 아직 "지능"이 없는 관절 모듈이고, 출력은 통신 가능하고, 캘리브레이션 완료되었으며, 세 루프가 조정된 관절 모듈입니다. M07은 이를 벤치에 올려 데이터로 다리에 장착할 자격이 있는지 결정합니다. 이 페이지는 1단계 개요의 6단계(폐루프 제어 계단)를 단계별 수준으로 확장합니다.

전제 조건: M05 조립 승인 완료(전 구간 걸림 없음, 무부하 전류 정상); 드라이버 보드, 모터, 엔코더, 케이블 번들 준비 완료; 컴퓨터에 드라이버 보드 전용 상위 툴 설치 완료.

이론 배경: FOC(자계 방향 제어), PID 제어, 전류-속도-위치 3중 루프 캐스케이드 카드, 교과서는 제4장 액추에이터 및 제14장 로봇 제어 기초 참조.

1단계: 펌웨어 플래싱 및 버전 고정

【무엇을 하는가】펌웨어는 M04에서 선택한 드라이버 보드에 의해 결정되며, 해당 보드에 맞게 사용합니다:

드라이버 보드 펌웨어 경로 비고
ST B-G431B-ESC1 Berkeley Humanoid Lite 오픈소스 FOC 펌웨어 보드 $19; 실제 기기 저수준 코드는 해당 저장소 berkeley_humanoid_lite_lowlevel 하위 디렉토리(C 언어, 훈련 스택과 독립적 — Berkeley Humanoid Lite GitHub)
ODrive ODrive 공식 펌웨어 + odrivetool Berkeley 방식은 ODrive / moteus / VESC와도 호환 가능(조사 아카이브)
moteus moteus 공식 펌웨어 + tview 펌웨어와 상위 툴 버전이 호환되어야 함

플래싱 세 가지 작업을 순서대로 수행:

  1. 툴체인 설치(ST 계열은 ST-Link + STM32CubeProgrammer 또는 DFU 모드 사용; 먼저 bootloader 진입 가능 여부와 칩 정보 읽기 가능 여부 확인);
  2. 플래싱 후 즉시 펌웨어 버전 번호/커밋 기록 — 전체 기기 22대의 액추에이터(Berkeley 구성은 6512×10대 + 5010×12대, 조사 아카이브)는 동일한 버전을 플래싱해야 하며, 버전 혼용 = 통신 프로토콜 및 기본 매개변수 불일치;
  3. 출고 시 기본 매개변수 백업(dump하여 저장), 조정 실패 시 한 번에 복원 가능.

【이유】펌웨어는 드라이버 보드의 "운영 체제"입니다: FOC 정류, 3중 루프 계산, CAN 프로토콜 스택이 모두 포함되어 있습니다. 버전 혼용은 대량 디버깅에서 가장 은밀한 함정입니다 — 현상은 "이 관절은 말을 잘 듣는데, 저 관절은 말을 안 듣는다"이며, 3일 동안 조사해야 펌웨어가 두 커밋 차이인 것을 발견합니다.

【당신의 상황 분석 방법】Berkeley 방식을 그대로 따릅니다: 해당 문서에서 지정한 펌웨어 버전을 사용하고, main 브랜치의 최신 커밋을 따라가지 마십시오. 자체 개발 펌웨어: "컴파일 가능, 플래싱 가능, 버전 읽기 가능"을 먼저 스크립트로 고정하십시오. 22대 양산 시 자신에게 감사할 것입니다.

2단계: 모터 매개변수 입력 — 하나라도 잘못 입력하면 전체가 실패

【무엇을 하는가】각 기기별로 4개의 핵심 매개변수를 입력하고, 매개변수 등록표에 기록합니다(동일 모델이라도 개체 차이가 있으므로 기기별 등록):

매개변수 획득 방법 잘못 입력 시 결과
극 쌍 수 자석 수 계산: 극 쌍 수 = 자석 조각 수 ÷ 2; 또는 모터 매뉴얼 확인 정류 오류 — 윙윙거림, 회전 불가 또는 불규칙한 떨림
상 저항 R 매뉴얼 값; 또는 밀리옴 미터/LCR 미터로 선간 저항 측정 ÷ 2(성형 결선) 전류 루프 이득 불일치
상 인덕턴스 L 매뉴얼 값; 또는 LCR 미터(1 kHz 모드)로 선간 인덕턴스 측정 ÷ 2 전류 루프 자동 튜닝 실패
KV 값 M02 선정 시 결정된 매뉴얼 값 속도 피드포워드 및 최대 속도 추정 모두 오류

계산 예시(성형 결선 환산): 측정된 임의의 두 상 간 선간 저항이 0.20 Ω이면, 상 저항 = 0.20 ÷ 2 = 0.10 Ω; 선간 인덕턴스도 동일하게 2로 나눕니다.

【이유】이 네 가지 값은 FOC의 "신분증 정보"입니다: 극 쌍 수는 전기각과 기계각의 변환을 결정하고(전기각 = 기계각 × 극 쌍 수), R/L은 전류 루프 이득의 물리적 크기를 결정하며, KV 값은 속도-전압 매핑을 결정합니다. 드라이버 보드의 자동 튜닝도 본질적으로 이 값들을 추정하는 것입니다 — 추정값은 반드시 매뉴얼/실측값과 대조해야 하며, 한 자릿수 차이가 나면 배선 또는 측정에 문제가 있음을 의미합니다.

【당신의 상황 분석 방법】드론 브러시리스 DC 모터(예: Berkeley에서 사용하는 MAD M6C12 150KV, $129, 조사 아카이브) 매뉴얼에는 R/L이 없는 경우가 많습니다: 100위안 대 LCR 미터를 구매할 가치가 있습니다; 없으면 드라이버 보드의 자동 튜닝 값을 사용하되, 등록표에 "출처: 자동 튜닝, 재측정 안 함"이라고 표시하십시오. M07의 Kt 캘리브레이션이 대신 검증해 줄 것입니다.

3단계: 엔코더 오프셋 캘리브레이션 — 전기각 영점과 기계적 영점 정렬

【무엇을 하는가】FOC는 정류를 위해 회전자 자극의 고정자에 대한 정확한 각도를 알아야 하지만, 관절 엔코더를 장착할 때 영점은 무작위입니다. 자동 캘리브레이션의 원리: 드라이버 보드가 천천히 회전하는 개루프 전류 벡터를 주입하면, 회전자가 전자기 토크에 의해 "끌려" 따라 회전하며, d축에 정렬될 때 엔코더 판독값을 기록합니다 — 이것이 오프셋입니다. 캘리브레이션 후 반드시 플래시에 저장하고, 전원을 끄고 재부팅하여 판독값이 여전히 있는지 확인합니다.

검증 기준(엔지니어링 권장 값, 드라이버 보드 매뉴얼에 따라 확인 필요): 연속 5회 전원 켜기 재캘리브레이션 시 오프셋 드리프트 < 5° 전기각. 드리프트가 기준을 초과하면 자석 또는 엔코더 설치에 문제가 있는 것이므로, 매개변수 조정으로 해결할 수 없으며 M05로 돌아가 조립을 확인하십시오.

【이유】오프셋이 조금만 틀려도 모터는 여전히 회전하지만, 출력 토크는 cos(오프셋 오차 각도)에 비례하여 감소하고, 초과된 전류는 모두 열이 됩니다; 90° 전기각까지 틀리면 모터가 전혀 힘을 내지 못합니다. 전원을 켤 때마다 오프셋이 드리프트하면, 매일 낯선 모터를 작동하는 것과 같습니다.

【당신의 상황 분석 방법】캘리브레이션 실패/오프셋 불규칙 점프 시 확인 순서: 엔코더 원시 판독값이 깨끗한지(손으로 모터를 돌려 판독값이 단조 증가하는지 확인) → 자석과 칩의 동축도 → 캘리브레이션 전류가 충분한지(회전자를 끌지 못하면 캘리브레이션 전류를 높이되, 상 전류 정격을 초과하지 않도록 주의). 자기 엔코더는 설치 동축도와 상선 전자기 간섭에 민감하므로(제5장 센싱 및 인식 하드웨어), 엔코더 케이블 번들은 대전류 상선에서 멀리 떨어뜨리십시오.

4단계: 3중 루프 튜닝 계단 — 내부에서 외부로, 단계별 길들이기

【무엇을 하는가】엄격히 전류 루프 → 속도 루프 → 위치 루프 순서로 튜닝하고, 각 단계는 계단 응답으로 검증한 후 다음 단계로 넘어갑니다. 대역폭은 5–10배씩 감소시킵니다(3중 루프 캐스케이드 카드의 원칙): 내부 루프는 외부 루프보다 훨씬 빨라야 하며, 그래야 외부 루프가 내부 루프를 "이상적인 액추에이터"로 간주할 수 있습니다.

  1. 전류 루프: R/L로 이득을 추정하거나, 드라이버 보드의 자동 튜닝을 직접 사용합니다. 극점 배치 추정식(엔지니어링 일반적인 시작점, 드라이버 보드 매뉴얼에 따라 확인 필요):
L = 0.05 mH = 0.00005 H, R = 0.10 Ω, 목표 대역폭 fc = 500 Hz
ωc = 2π × fc = 2π × 500 ≈ 3142 rad/s
Kp_i = L × ωc = 0.00005 × 3142 ≈ 0.16
Ki_i = R × ωc = 0.10 × 3142 ≈ 314

계단 응답 검증: 정격의 30–50% 전류 계단을 인가하고, 상승 시간(ms 단위)과 링잉 확인 — 링잉이 많으면 대역폭을 낮춥니다.

  1. 속도 루프: 대역폭은 전류 루프의 1/5–1/10로 설정(위 예시 500 Hz → 50–100 Hz, 엔지니어링 권장 값). 정격의 20% 작은 속도 계단을 인가하여 검증; 이득이 너무 높은 전형적인 증상은 모터의 고주파 울음(고주파 윙윙거림)이며, 즉시 이득을 낮춥니다.
  2. 위치 루프: 대역폭을 다시 5–10배 낮춥니다(10–20 Hz 수준, 엔지니어링 권장 값). 30° 계단 응답 검증: 오버슈트 < 10%, 정상 상태 오차 < 0.5°(1단계 개요의 기준과 일치하며, M07에서 부하 상태로 재측정). 오버슈트가 크면 P를 낮추기 전에 속도 피드포워드를 추가하는 것이 더 근본적인 해결책인 경우가 많습니다: 위치 명령이 변경될 때 동시에 속도 명령을 피드포워드하면 오차가 축적되기 전에 상쇄됩니다.

【이유】3중 루프 캐스케이드의 물리적 의미: 전류 루프는 "얼마나 많은 힘을 낼지"(토크 ∝ 전류), 속도 루프는 "얼마나 빨리 회전할지", 위치 루프는 "어디에 멈출지"를 관리합니다. 외부 루프의 대역폭이 내부 루프를 초과하면, 근시안적인 사람이 현미경을 조종하는 것과 같아 반드시 진동합니다. 이는 PID 제어의 캐스케이드 구조에서 표준적인 사용법이며, 이론은 제14장 로봇 제어 기초를 참조하십시오.

【당신의 상황 분석 방법】드라이버 보드에 전류 루프가 내장되어 있는 경우(Berkeley 펌웨어, ODrive, moteus 모두 내장): 당신의 주요 작업은 속도 루프와 위치 루프입니다. 오실로스코프가 없는 경우: 상위 툴의 파형 기록 기능(tview / odrivetool / 사용자 정의 로그)으로 충분하며, 샘플링 속도는 최소한 측정 대상 루프 대역폭의 10배 이상이어야 합니다. 서보 모터 경로는 3중 루프가 내부에 폐쇄되어 있으므로, 이 단계는 "매뉴얼을 읽고 레지스터를 조정하는" 것으로 축소됩니다.

5단계: 통신 네트워킹 및 파라미터 아카이빙

【수행할 작업】

  1. CAN ID 할당: 각 장치를 개별적으로 전원을 켜고, 기본 ID를 할당표의 고유 ID로 변경한 후 라벨(관절명 + ID)을 부착합니다. 모든 변경이 완료된 후 네트워킹합니다. 할당표는 "왼쪽 엉덩이 pitch = 0x01" 형식으로 문서화합니다.
  2. 통일된 보레이트: 전체 네트워크에 동일한 속도를 적용합니다. 참고값: Berkeley는 CAN 2.0 @ 1 Mbps를 사용하며, 각 사지에 하나의 버스, USB-CAN 어댑터를 통해 메인 컨트롤러에 연결, 단일 버스 최대 64개 장치(조사 문서 참조).
  3. 송수신 테스트: 상위 컴퓨터가 250 Hz로 전체 네트워크 관절에 대해 송수신을 수행합니다(Berkeley 액추에이터 및 IMU 통신 250 Hz 기준, 조사 문서 참조). 1시간 연속 테스트에서 끊김 없음, 오류 프레임 급증 없음이 통과 기준입니다(판단 기준은 1단계 개요와 동일).
  4. 파라미터 아카이빙: 각 관절의 최종 파라미터(모터 파라미터 + 오프셋 + 3루프 게인 + ID)를 파일로 저장하고, git 저장소 + 테이블로 이중 백업합니다.

버스 부하 용량 대략 계산(엔지니어링 권장값, 프레임 길이에 따라 재계산): 확장 프레임 최대 약 130 µs/프레임, 6개 관절 1개 버스(Berkeley 각 사지 버스 약 5–6대), 250 Hz 양방향 송수신 = 6 × 250 × 2 × 130 µs ≈ 점유율 39%, 양호; 12대를 모두 하나의 버스에 연결하면 약 80%에 근접하므로 반드시 버스를 분리해야 합니다.

【이유】CAN 버스는 다중 노드가 한 쌍의 선을 공유합니다. ID 충돌 시 두 장치가 동일한 프레임을 동시에 전송하면 오류 프레임이 눈덩이처럼 불어나 버스 폭풍이 발생하고 전체 네트워크가 마비됩니다. 또한 현상은 "무작위 끊김"으로 나타나 위치 파악이 매우 어렵습니다. 파라미터 아카이빙은 M07 및 전체 기기 단계에서 생명줄과 같습니다. 22개의 관절 중 3개월 후에는 아무도 7번 관절의 오프셋을 기억하지 못할 것입니다.

【상황 분석 방법】네트워킹의 첫 번째 단계는 항상 전원을 차단하고 CANH-CANL 저항을 측정하는 것입니다. 양쪽 끝에 120 Ω 터미네이터가 있을 때 약 60 Ω이어야 합니다. 무한대 = 터미네이터 미연결, 60 Ω보다 훨씬 낮음 = 터미네이터 과다 연결(1단계 개요 점검표 참조). 통신 프로토콜 및 미들웨어 선택은 제22장 소프트웨어 미들웨어를 참조하십시오.

승인 기준

  • [ ] 모든 관절 펌웨어 버전이 일치하며, 버전 번호/커밋이 기록되어 있고, 출고 기본 파라미터가 백업되었습니다.
  • [ ] 각 모터 파라미터(극수/R/L/KV)가 개별적으로 등록되었으며, 출처(매뉴얼/실측/자체 튜닝)가 명시되었습니다.
  • [ ] 전원 켜짐 자동 보정 통과, 연속 5회 반복 보정 오프셋 드리프트 < 5° 전기각(또는 드라이버 보드 매뉴얼 지정값), 보정 결과가 플래시에 기록되었습니다.
  • [ ] 3루프 튜닝 완료: 무부하 30° 계단 응답 오버슈트 < 10%, 정상 상태 오차 < 0.5°, 곡선이 아카이빙되었습니다.
  • [ ] CAN 네트워킹 완료: ID 할당표 문서화, 250 Hz 송수신 1시간 연속 끊김 없음.
  • [ ] 모든 파라미터가 저장되고 이중 백업(git + 테이블)되었으며, 원클릭으로 모든 관절에 다시 구울 수 있습니다.
