M10 · URDF 모델링 및 내보내기: 쇳덩이를 계산 가능한 모델로 만들기

전체 위치: 전체 조립 완료(M09) 또는 구조 확정 후, 시뮬레이션(M11–M13) 이전. 입력은 기계 설계(CAD 또는 실물)이며, 출력은 검증을 통과한 URDF 모델 패키지(urdf 파일 + mesh + 관성 매개변수)입니다. 이는 M11 시뮬레이션 변환, M12 기립, M13 강화 학습의 공통 기반이 됩니다.

전제 조건: URDF 구조를 이해할 수 있어야 함(Stage 0의 시뮬레이션 첫 경험); 구조 치수와 질량 분포가 확정되어 있어야 함.

이론적 배경: URDF 로봇 설명 형식 카드와 제22장 소프트웨어 미들웨어, 제23장 시뮬레이션 및 물리 엔진.

단계 1: link/joint 트리 및 명명 규칙 정하기

【무엇을 할까】먼저 종이에 운동학 트리를 그립니다: 베이스(base_link) → 엉덩이 → 다리 → 발목 → 발, 몸통 → 어깨 → 팔 → 손목. 그런 다음 세 가지 명명 규칙을 정하고 전체 과정에서 준수합니다:

  1. 측면 접두사: l_ / r_ (좌우 다리/팔);
  2. 관절 유형 접미사: _pitch / _roll / _yaw (회전축);
  3. 각 link의 좌표계: 원점은 해당 관절 축선 상에, z축은 관절 축을 따름 (내보내기 기본값과 일치하여 나중에 문제를 줄임).

【왜 필요한가】URDF 문제의 90%는 형식 오류가 아니라 좌표계 규칙 불일치입니다: 축선 반대 방향, 원점 이동, 좌우 미러링 오류. 먼저 종이에 규칙을 고정한 후 소프트웨어를 엽니다. 관절 유형(revolute/prismatic/fixed)과 축 방향 규범은 URDF 로봇 설명 형식 카드를 참조하세요.

【상황별 분석】오픈소스 플랫폼(M08)을 복제하는 경우: 공식 URDF를 직접 사용하며, 이 작업에서는 단계 4(관성 검증)와 단계 6(검증)만 수행하고 나머지는 건너뜁니다. 자체 설계 구조: 여섯 단계를 모두 수행합니다.

단계 2: CAD에서 골격 내보내기

【무엇을 할까】세 가지 경로 중 선택:

경로 도구 적합한 대상
SolidWorks 내보내기 sw_urdf_exporter 플러그인 구조가 SolidWorks에서 설계된 경우
Onshape 내보내기 onshape-to-robot 클라우드 CAD, 다중 사용자 협업
URDF/xacro 수동 작성 텍스트 편집기 + xacro 매크로 구조가 간단하거나 매개변수화가 필요한 경우(다리 길이 조정 가능)

내보내기 후 첫 번째 작업: RViz 또는 urdf-viz에서 열고, 관절을 하나씩 수동으로 드래그하여 축 방향 및 양/음 방향이 단계 1의 규칙과 일치하는지 확인합니다.

【왜 필요한가】내보내기 도구가 생성한 골격에는 종종 중복된 fixed 관절과 중첩된 프레임이 있으며, 축 방향 규칙도 사용자 규범과 일치하지 않을 수 있습니다. xacro 매크로는 20개의 유사한 관절을 하나의 매개변수화된 템플릿으로 통합하여 한 곳을 수정하면 전체에 적용됩니다. 수동 골격 작성 전에 각 joint의 origin rpy를 머릿속으로 설명할 수 있는지 확인하세요.

【상황별 분석】CAD 모델 없이 실물만 있는 경우: 캘리퍼스로 관절 거리를 측정하고 직접 xacro를 수동 작성합니다. 데스크탑급 로봇은 10여 개의 link를 반나절 안에 작성할 수 있습니다. mesh 파일(단계 5)은 먼저 기하 도형(box/cylinder)으로 대체할 수 있습니다.

단계 3: 관성 매개변수 입력——모델의 핵심

【무엇을 할까】각 link에는 <inertial>이 있어야 합니다: mass, origin(질량 중심), inertia(관성 모멘트 3×3). 세 가지 획득 경로를 정밀도 순으로 나열:

  1. CAD 재료 할당 후 읽기: 각 부품에 실제 재료 밀도를 할당하고 CAD에서 직접 질량 중심과 관성 텐서를 출력;
  2. 실물 중량 측정 + 기하학적 근사: 중량 측정으로 mass를 얻고, 등가 기하 도형(직육면체/원기둥)의 관성 공식으로 추정;
  3. 진자법으로 주기 측정: 매달아 진동시켜 주기를 측정하고 관성을 역산(정밀도 최고, 작업량 최대, 자세한 내용은 제9장 핵심 서브시스템 설계 및 시스템 식별 카드 참조).

구동기가 질량의 대부분을 차지: M02에서 선택한 모터/감속기의 질량을 데이터 시트에 따라 해당 link에 입력하고, 균등 분배하지 마십시오.

【왜 필요한가】시뮬레이션에서 80%의 "불가사의한 넘어짐"은 관성 매개변수 오류에서 비롯됩니다: 질량이 20% 틀리면 컨트롤러 튜닝이 완전히 무효화되고; 관성 텐서가 한 자릿수 차이 나면 동적 응답이 완전히 달라집니다. M14 sim-to-real에서 시스템 식별을 통해 이 값들을 정밀 수정하게 됩니다.

【상황별 분석】3D 프린팅 부품의 경우 CAD 밀도 × 프린팅 충전율로 환산(PLA 약 1.24 g/cm³ × 충전율). 초기 버전에서는 10–15% 오차를 허용하지만, 질량 중심 위치는 반드시 실측 검증해야 합니다: 실물 link를 줄로 매달아 수직선의 교차점이 질량 중심이며, 모델과 일치하지 않으면 수정합니다.

단계 4: 관절 리미트, 감속비 및 안전 경계

【무엇을 할까】각 revolute 관절에 <limit>를 입력합니다: lower/upper(각도 리미트, 도→라디안), effort(토크 상한, M01 사양표의 피크 토크 사용), velocity(회전 속도 상한, M01의 정격 회전 속도를 rad/s로 변환). 감속비가 있는 전동 장치는 <transmission>에 명시하거나 주석에 감속비(M03 값)를 표시합니다.

【왜 필요한가】시뮬레이터는 리미트에 따라 운동을 제한합니다. RL 훈련(M13)에서 동작 클리핑도 이 값을 읽습니다——effort를 너무 크게 설정하면 정책이 실제 기기에서 실행 불가능한 동작을 학습하여 sim-to-real이 직접 실패합니다. 안전 관련 소프트웨어 리미트는 기계적 하드 리미트보다 5–10° 작아야 합니다.

【상황별 분석】리미트 각도는 구조 도면에서 측정하고, 측정할 수 없으면 실물 관절을 양 끝으로 움직여 각도기로 측정합니다. effort는 모터 피크 토크 × 감속비 × 효율(0.7–0.9 추정값, 감속기 유형에 따라 검증 필요——M03)을 사용합니다.

단계 5: visual 및 collision 기하 분리

【무엇을 할까】

  • <visual>: 정밀 mesh(STL/DAE) 배치, 시각적 목적만;
  • <collision>: 단순화된 기하 배치——box/cylinder/sphere 조합 또는 convex hull로 단순화된 mesh 우선; 각 link의 충돌체 정점 수는 수백 개 이내로 제어.

발바닥 충돌체는 별도 처리: 평평한 바닥 box 사용, 실제 발바닥보다 약간 작은 치수(모서리 오접촉 방지), 마찰 매개변수는 M11에서 조정.

【왜 필요한가】물리 엔진은 collision 기하로 접촉을 계산하며, 복잡한 mesh는 느리고 불안정합니다(날카로운 모서리, 자체 교차). 시각적 mesh가 아무리 예뻐도 시뮬레이션에 기여하지 않습니다. MuJoCo 물리 엔진과 Gazebo의 공식 문서는 모두 "충돌체 단순화"를 성능과 안정성을 위한 최우선 권장 사항으로 제시합니다.

【상황별 분석】3D 프린팅 부품은 프린팅 STL을 visual로 직접 사용; collision은 CAD에서 동일한 부품의 외접 box를 수동으로 작성하는 것이 convex hull로 변환하는 것보다 더 제어하기 쉽습니다. mesh 단위에 주의——STL이 밀리미터인지 미터인지 확인: URDF는 기본적으로 미터를 사용하므로 내보내기 시 스케일 오류는 전형적인 함정입니다.

단계 6: 검증 및 내보내기 인계

【무엇을 할까】네 가지 관문을 순서대로 통과:

  1. check_urdf model.urdf: 운동학 트리 구문 분석 오류 없음;
  2. RViz / urdf-viz 시각화: 축 방향, 리미트, mesh 스케일 정확;
  3. 질량 보고서: 전체 모델 총 질량 = 실물 중량 측정 ±10%, 총 질량 중심 위치 합리적(기립 시 지지면 내 투영);
  4. 패키징 인계: robot_description/(urdf + meshes + 좌표계 규칙 및 관성 출처를 기록한 README), 버전 관리에 제출.

【왜 필요한가】이 네 가지 관문은 M11의 입장권입니다——모델 변환(URDF→MJCF/USD)은 작은 오류를 "시뮬레이션 실행 시 비행"으로 증폭시킵니다. 인계 패키지를 버전 관리에 넣으면 M13에서 모델을 수정할 때 무엇을 변경했는지 알 수 있습니다.

【상황별 분석】검증 오류 발생 시 우선 확인: origin 단위 누락(도 vs 라디안), 관성 텐서 비양정치, mesh 경로 대소문자. 이 세 가지가 URDF 오류의 대부분을 차지합니다.

합격 기준

  • [ ] 운동학 트리 및 명명 규칙 문서화(종이 한 장: 트리 다이어그램 + 축 방향 규칙).
  • [ ] check_urdf 통과, RViz에서 관절별 드래그 시 축 방향/방향 정확.
  • [ ] 각 link에 관성 매개변수 있음, 총 질량과 실물 중량 측정 편차 ≤ 10%, 질량 중심 실측 검증 통과.
  • [ ] 각 revolute 관절에 limit(각도/effort/velocity) 있음, 값이 M01 사양표와 일치.
  • [ ] visual/collision 기하 분리, 충돌체는 단순화된 기하.
  • [ ] 모델 패키지 저장소에 등록(좌표계 규칙 README 포함), M11에서 직접 변환 가능.

일반적인 함정과 문제 해결

증상 가능한 원인 문제 해결 조치
RViz에서 모델이 "폭발"하거나 흩어짐 관절 origin 오기입 / mesh 단위 오류 (mm를 m로 사용) 단계별로 joint 주석 처리하여 확인; mesh 스케일 ×0.001 시도
시뮬레이션 기립 시 천천히 넘어짐 질량 중심 위치 오류 / 총 질량이 실제와 불일치 추선법으로 질량 중심 재측정; 재중량 비교 확인
MJCF 변환 시 관성 텐서 오류 발생 관성 행렬이 양정부호가 아님 (수기 추정 오류) ixx/iyy/izz가 삼각 부등식을 만족하는지 확인, CAD로 재추출
RL 정책이 기립을 학습하지 못함 effort/velocity 제한이 과도하게 높음 4단계로 돌아가 모터 실제 성능에 따라 재입력
좌우 다리 동작 비대칭 미러 관절 축 방향/부호 반대로 기입 명명 규칙에 따라 관절별로 rpy와 axis 대조 확인
