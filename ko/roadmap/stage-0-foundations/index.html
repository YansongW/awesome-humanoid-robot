Stage 0 기초 다지기: 휴머노이드 로봇 제작의 입장권 획득

본 단계의 위치

Stage 0의 목표는 "모든 기초를 다 배우는 것"이 아닙니다. 그것은 끝없는 구렁텅이이며, 많은 사람들이 그 안에서 실패합니다. 목표는 네 가지 입장권을 획득하는 것입니다:

  1. 수학: 제어 논문에서 나오는 행렬, 확률, 동역학 방정식, QP에 낯설지 않게 됩니다;
  2. 프로그래밍 및 도구 체인: Python/C++/git/ROS 2를 실무에 사용할 수 있고, 3D 프린팅이 무엇인지 알게 됩니다;
  3. 회로 개념: 전기가 어디서 오는지, 신호가 어떻게 흐르는지 알게 되어, 이후 실제 하드웨어를 다룰 때 보드를 태우지 않습니다;

  4. 시뮬레이션: URDF 파일 하나를 읽고, MuJoCo에서 이족 모델을 일으켜 세웁니다.

  5. 시간 예산:业余 6–10주 (주당 8–10시간), 전일제 3–4주.

  6. 예산: 약 ¥0 – 본 단계의 소프트웨어는 모두 오픈소스입니다; 선택적 3D 프린팅 시제품 제작 경험 비용은 공급업체에 직접 확인해야 합니다.
  7. 핵심 규율: 각 주제에 대해 "어느 정도 배워야 충분한지"에 대한 기준을 제시하며, 기준에 도달하면 즉시 중단하고, 다시 돌아와 문제를 풀지 않습니다. 실제 부족한 점은 이후 단계에서 드러나며, 그때 구체적인 문제를 가지고 돌아와 보충하면 효율이 열 배는 높아집니다.

단계 1: 수학 네 가지

수학과처럼 (정의-정리-증명) 배우지 말고, "제어 엔지니어의 최소 무기고" 방식으로 배웁니다. 네 가지 모두의 기준은 시연 가능해야 하며, "이해한 것 같다"가 아닙니다.

1.1 선형대수학 (Linear Algebra)

【할 일】 벡터와 행렬 연산, 고윳값/고유벡터, 회전 행렬과 동차 변환, 최소 제곱법과 유사 역행렬. 실습: NumPy로 4×4 동차 변환을 작성하여 발끝 좌표를 발목 관절 좌표계에서 몸통 좌표계로 변환; 2링크 평면 팔의 정기구학을 작성.

【이유】 선형대수는 휴머노이드 로봇의 모든 공간 관계를 표현하는 언어입니다: 정기구학은 동차 변환의 연속 곱셈이고, 야코비 행렬은 관절 속도를 말단 속도로 매핑하며, 전신 제어의 모든 QP는 행렬 연산입니다. 카드: 선형대수학 (벡터 공간, 선형 변환, 행렬과 선형 방정식 시스템을 연구하는 수학 분야). Wiki 8장의 운동학 유도는 모두 이것을 기반으로 합니다.

【상황별 분석】 CS 배경: 계산은 이미 익숙하므로, 기하학적 직관을 보충하는 데 집중하세요 – 회전 행렬은 아홉 개의 숫자가 아니라, 하나의 좌표계를 구성하는 세 개의 축입니다; 물리/수학 배경: 위 실습을 바로 수행하여 검증하세요; 초보자: 먼저 3Blue1Brown의 "선형대수의 본질"을 보고 직관을 쌓은 후, 직접 계산해보세요.

어느 정도면 충분한가 (세 가지 모두 통과 시 중단): ① 2D 회전 행렬을 직접 유도하고 각 열의 기하학적 의미를 설명할 수 있음; ② 2링크 평면 팔 정기구학 코드가 실행되고, 출력이 수동 계산과 일치함; ③ 야코비의 유사 역행렬 J⁺를 보고 최소 제곱 문제를 푸는 것임을 알 수 있음.

1.2 확률론 (Probability Theory)

【할 일】 확률 변수, 기댓값과 공분산, 가우스 분포, 베이즈 정리, 조건부 확률과 주변화. 실습: NumPy로 가우스 잡음이 있는 "관절 엔코더 판독값"을 시뮬레이션하고, 히스토그램을 그리고 평균/분산 계산; 베이즈 정리를 사용하여 "센서 경보 → 실제 고장 확률" 문제를 수동으로 계산.

【이유】 실제 센서는 항상 잡음을 동반하며, 상태 추정 (칼만 필터 계열)은 본질적으로 순환적인 베이즈 추론입니다; 이후 사용될 모방 학습, VLA 모델도 결정론적 값이 아닌 동작의 확률 분포를 출력합니다. 카드: 확률론 – 로봇 공학과 머신러닝의 모든 확률 모델의 기초.

【상황별 분석】 AI 배경: 기준으로 자가 점검하면 대부분 바로 통과합니다; 하드웨어 배경: 이 과목이 네 가지 중 가장 약할 가능성이 높으며, 상태 추정을 이해하는 데 직접적인 영향을 미치므로 – 수학 예산의 절반을 여기에 투자할 가치가 있습니다; 초보자: 선형대수 이후에 학습하세요.

어느 정도면 충분한가: ① 공분산 행렬의 대각선 요소와 비대각선 요소가 각각 무엇을 의미하는지 한 문장으로 설명할 수 있음; ② 베이즈 문제를 수동으로 계산하고 숫자가 정확함; ③ 칼만 필터의 다섯 가지 공식을 보고 당황하지 않음 – 유도를 요구하지는 않지만, 각 공식의 역할 (예측, 이득, 갱신)을 설명할 수 있어야 함.

1.3 고전역학 (Classical Mechanics)

【할 일】 뉴턴-오일러 방정식, 라그랑주 방법, 운동 에너지/위치 에너지, 관성 텐서, 각운동량. 실습: 라그랑주 방법으로 단진자, 이중진자의 동역학 방정식을 유도하고, 수치 적분으로 5초간 시뮬레이션하여 각도 곡선을 그림.

【이유】 휴머노이드 로봇은 부유 기저 다중 강체 시스템이며, M(q)q̈ + C(q,q̇) + g(q) = τ 방정식은 이후 읽게 될 모든 제어 논문에 등장합니다; 이족 보행 균형 (ZMP, 포착점)은 모두 고전역학의 직접적인 결과입니다. 카드: 고전역학 (뉴턴 법칙, 보존 원리 및 강체 동역학 포함). Wiki 8장과 14장 로봇 제어 기초의 유도는 모두 여기서 시작됩니다.

【상황별 분석】 기계/자동차 배경: 이 과목은 대부분 충분하므로, 이중진자 실습으로 검증하고 넘어가면 됩니다; 순수 소프트웨어 배경: 이 과목이 본 단계에서 가장 중요한 보충 과목입니다 – 역학적 직관이 없으면, 시뮬레이션에서 로봇이 넘어졌을 때 제어기의 문제인지 모델의 문제인지 구분할 수 없습니다.

어느 정도면 충분한가: ① 이중진자 방정식을 유도할 수 있음 (책을 보면서 유도해도 되지만, 책을 덮고 각 단계가 무엇을 하는지 설명할 수 있어야 함); ② "왜 몸통 관성이 큰 휴머노이드 로봇이 오히려 안정적으로 서 있기 쉬운지"를 정성적으로 설명할 수 있음; ③ URDF의 <inertial> 태그 각 필드의 의미를 이해함 – 이는 단계 4를 위한 직접적인 준비입니다.

1.4 볼록 최적화 (Convex Optimization)

【할 일】 볼록 집합/볼록 함수 판별, 표준 QP (2차 계획법) 형식, 등식/부등식 제약 조건의 기하학적 의미, 기성 솔버를 호출하여 QP를 푸는 방법. 실습: Python으로 min ‖x‖² s.t. Ax=b, x≥0 풀기 (솔버는 OSQP, quadprog 등 환경에 맞게 선택).

【이유】 휴머노이드 제어의 실시간 계층은 거의 항상 QP를 풉니다: 전신 제어 (WBC)는 "작업 추적 + 접촉력 제약 + 토크 상한"을 역동역학 QP로 작성하여 매 밀리초마다 풀고, MPC는 순환적으로 QP를 풉니다. 볼록성은 모든 지역 최적해가 전역 최적해임을 보장합니다 – 이것이 엔지니어가 QP를 kHz급 제어 루프에 사용할 수 있는 근본적인 이유입니다. 카드: 볼록 최적화. 자세한 내용은 Wiki 14장 참조.

【상황별 분석】 이 과목은 네 가지 중 한계 효용 체감이 가장 빠른 과목입니다: 직접 제어기를 작성하지 않는다면, "볼록성 판별 + 솔버 조정 + QP 구조 이해"만으로 충분하며, KKT 유도는 필요할 때 나중에 보충하면 됩니다. 운영 연구 배경은 자가 점검으로 통과합니다.

어느 정도면 충분한가: ① 주어진 문제가 볼록한지 판별할 수 있음 (2차 양정의 목적 함수 + 선형 제약 조건 → 볼록); ② 연습 문제의 해가 모든 제약 조건을 만족함을 검증할 수 있음; ③ 다른 사람에게 "왜 WBC가 실시간 루프에서 QP를 사용할 수 있는지" 설명할 수 있음.

단계 2: 프로그래밍 및 도구 체인

【할 일】 ① Python 능숙도 달성: NumPy 벡터화, matplotlib 그래프, class 작성 가능; ② C++ "읽고 수정 가능" 수준: 포인터/참조, 헤더 파일, 컴파일/링크; ③ git 일상 작업: clone, branch, commit, push, PR 제출; ④ ROS 2 LTS 설치, talker/listener 실행 및 자체 발행/구독 노드 쌍 작성; ⑤ FDM 3D 프린팅 기본 프로세스 (모델링 → 슬라이싱 → 프린팅) 및 강도 상식 이해.

【이유】 휴머노이드 소프트웨어 스택의 사실상 표준은 ROS 2 미들웨어입니다 – DDS 기반 발행/구독 메커니즘, 실시간 지원 (출처: ros.org, 카드 참조). 이후 단계의 시뮬레이션, 구동, 상태 추정은 모두 노드/topic으로 구성됩니다. 하위 레벨 실시간 루프는 C++, 알고리즘 프로토타입은 Python을 사용하는 것이 업계의 기본적인 역할 분담입니다. 3D 프린팅은 이후 전체 로봇 단계의 제조 주력 수단입니다: 오픈소스 휴머노이드 Berkeley Humanoid Lite의 구조 부품과 사이클로이드 감속기는 모두 프린팅 부품이며, 전체 로봇 BOM은 미국 조달 시 약 $4,312, 중국 조달 시 약 $3,236입니다 (출처: EECS-2025-207 기술 보고서) – 지금 배우는 슬라이싱과 공차 상식은 그때 직접 비용과 시간으로 이어집니다. 소프트웨어 생태계 전반은 Wiki 22장 소프트웨어 미들웨어 참조.

【상황별 분석】 순수 소프트웨어 배경: Python/git 자가 점검 통과 시 건너뛰고, 시간을 C++ 메모리 및 실시간 개념, ROS 2의 노드/topic/service 세 가지에 투자하세요; 하드웨어 배경: NumPy로 Python을 시작하는 것이 가장 효율적이며, MATLAB 사고 방식과 가장 가깝습니다; 초보자: Python 먼저, git은 그 다음, C++은 필요할 때까지 미루세요, 사용하지 않으면 잊어버립니다.

어느 정도면 충분한가: ① ROS 2: 독립적으로 두 개의 노드를 작성하여 하나는 발행하고 하나는 구독하며, ros2 topic echo로 데이터 흐름을 확인할 수 있음; ② git: 독립적으로 fork→branch→commit→PR 전체 과정을 한 번 수행 (자신의 연습 저장소로 연습); ③ 3D 프린팅: FDM 적층 방향이 부품 강도에 미치는 영향과, 왜 끼워맞춤 구멍에 공차를 남겨야 하는지 설명할 수 있음 (구체적인 기계의 공차 수준은 공급업체에 직접 확인 필요).

3단계: 회로 및 임베디드 기초

【할 일】 이 단계에서는 보드를 만들지 않고, 세 가지 개념을 확립합니다: 전원 공급(전압 레일, 전류 예산, 선경과 전압 강하, 퓨즈와 스위치), 접지(공통 접지, 접지 루프), 신호(디지털 레벨, 차동 전송, 노이즈 내성). 그런 다음 CAN 버스의 역할에 중점을 둡니다: 이는 휴머노이드 로봇 관절 모터 드라이버와 중앙 컨트롤러를 연결하는 필드버스입니다(출처: 카드, Wikipedia CAN bus 2024). 선택적 실습: 입문용 CAN 어댑터를 하나 구매하여(가격은 공급업체에 직접 확인 필요), can-utils를 사용해 실제 버스 데이터를 캡처하여 프레임 구조를 확인해 보세요.

【이유】 전체 시스템 단계에 이르면, 10여 개에서 20여 개의 관절 드라이버가 버스에 연결됩니다: Berkeley Humanoid Lite는 CAN을 사용하여 각 액추에이터를 연결하며, 메인 컨트롤러는 Intel N95 미니 PC(약 $129, 동체에 위치, 하위 레벨 제어와 RL 정책을 동시에 실행)입니다(출처: EECS-2025-207 기술 보고서 BOM). 전체 시스템 디버깅 시 절반 이상의 "미스터리한 문제"는 전기적 계층에서 발생합니다: 전압 강하, 공통 접지, 종단 저항, 배선 하네스. 지금 개념을 확립하면, 나중에 보드를 태우는 일이 줄어듭니다. 전원 시스템 공학 세부 사항은 Wiki 6장: 컴퓨팅, 전원 및 열 관리를 참조하세요.

【당신의 상황 분석】 전기/자동화 배경: 이 섹션은 30분 만에 개념을 훑어보면 됩니다; 소프트웨어 및 비전공자: 회로 설계를 할 수 있을 필요는 없지만, "감히 측정하고, 측정할 줄 알아야" 합니다 – 멀티미터로 전압과 도통을 측정하고, 24V 버스 단락이 무엇을 의미하는지 알아야 합니다. 안전 주의사항: 리튬 배터리와 버스 커패시터는 장난감이 아닙니다. 전원이 인가된 상태에서 작업하기 전에 안전 규정을 직접 확인하고, 확신이 없으면 하드웨어 경험이 있는 사람이 있는 곳에서 작업하세요.

어느 정도면 충분한가: ① "배터리 → 퓨즈/비상 정지 → 버스 → 각 드라이버"의 전원 공급 토폴로지 스케치를 손으로 그릴 수 있어야 합니다; ② CAN 버스 양 끝에 120Ω 종단 저항을 추가해야 하는 이유를 설명할 수 있어야 합니다; ③ 차동 신호가 단일 종단 신호보다 노이즈 내성이 강한 이유를 설명할 수 있어야 합니다.

4단계: 시뮬레이션 첫 경험 – URDF 이해하고, 이족 보행 로봇을 일으켜 세우기

【할 일】 ① MuJoCo 물리 엔진을 설치합니다; ② 오픈소스 휴머노이드/이족 보행 로봇의 URDF 로봇 설명 형식 파일을 찾아 정독합니다 – URDF는 XML을 사용하여 로봇의 링크, 관절, 관성 및 형상을 설명하는 형식입니다(출처: wiki.ros.org/urdf, 카드 참조); ③ 모델을 MuJoCo에 로드합니다(또는 프로젝트 자체 MJCF 사용); ④ 가장 기본적인 위치 PD 컨트롤러를 작성합니다: 서 있는 자세의 관절 목표 각도를 주고, 이족 보행 모델이 제자리에 10초 동안 서 있게 합니다.

【이유】 MuJoCo는 풍부한 접촉 역학을 갖춘 고충실도 물리 엔진으로, 휴머노이드 제어 연구에 널리 사용됩니다(출처: mujoco.org, 카드 참조) – 이족 보행의 핵심 난제는 바로 발바닥 접촉과 균형이며, 이것이 MuJoCo의 강점입니다. URDF를 읽는 것은 오픈소스 휴머노이드 저장소를 여는 첫 번째 열쇠입니다: 실제 오픈소스 프로젝트는 URDF/MJCF/USD 세 가지 설명 형식을 동시에 유지 관리합니다(Berkeley Humanoid Lite, 출처: Berkeley Humanoid Lite GitHub). 이 형식을 이해하면, 다른 사람의 로봇 "뼈대 도면"을 읽을 수 있습니다. 시뮬레이션 기술 스택에 대한 체계적인 설명은 Wiki 23장: 시뮬레이션 및 물리 엔진을 참조하세요.

【당신의 상황 분석】 GPU가 없어도 괜찮습니다 – 서 있는 수준의 강체 시뮬레이션은 CPU로 충분합니다. 모델 선택 시 "크기가 작고 문서가 완전한" 오픈소스 이족 보행 로봇을 우선 선택하세요(공개 조사 아카이브에는 Berkeley Humanoid Lite, ToddlerBot 등의 후보와 비용 및 진입 장벽 분석이 있습니다). 처음부터 전체 크기 모델을 시도하지 마세요. 이 단계에서 한 가지만 완료해야 한다면, 이것을 완료하세요 – 역학, 프로그래밍 및 도구 체인 세 가지를 동시에 검증합니다.

어느 정도면 충분한가: 아래 합격 기준 1, 2번 항목 – 이 단계가 바로 Stage 0의 졸업 설계입니다.

합격 기준

항목별로 자체 점검하고, 모두 통과해야만 Stage 1로 진행할 수 있습니다:

  1. URDF 독해: 본 적 없는 이족 보행 로봇 URDF를 받았을 때, 문서 없이 구두로 답변할 수 있어야 합니다 – 제어 가능한 관절은 총 몇 개인지, 루트 링크는 어디인지, 발목 관절의 origin/axis는 각각 무엇인지, <inertial>에서 ixx/iyy/izz의 의미는 무엇인지; 그리고 check_urdf 또는 동등한 도구를 사용하여 구문 분석 오류가 없음을 확인합니다.
  2. MuJoCo 서 있기: 이족 보행 모델을 로드하고, 직접 작성한 위치 PD 제어를 사용하여 외력 없이 10초 이상 넘어지지 않고 서 있어야 합니다; 몸통에 작은 충격을 가한 후, 모델이 서 있는 자세를 회복하거나, 회복하지 못하는 이유(게인, 접촉 또는 모델 문제)를 올바르게 설명할 수 있어야 합니다. 이 항목은 역학적 직관을 테스트하는 것이지, 게인 튜닝의 운을 테스트하는 것이 아닙니다.
  3. 수학 확인: 4종 세트의 "충분 조건"에서 각 항목을 무작위로 하나 뽑아, 즉석에서 시연(수동 계산 또는 코드 실행)할 수 있어야 합니다.
  4. 도구 체인: ROS 2 talker/listener가 실행된 기록이 있어야 합니다(터미널 스크린샷 또는 녹화); 이 단계의 모든 연습 코드는 git 저장소에 있으며, 커밋 기록이 명확하게 읽을 수 있어야 합니다.
  5. 회로 개념: 동료(또는 허공)에게 전원 공급 토폴로지, CAN 종단 저항 및 차동 신호 세 가지를 명확하게 설명할 수 있어야 합니다; 설명하지 못하면 미달로 간주합니다.

"충분하지 않음"을 알리는 두 가지 경고 신호: 튜토리얼 없이 PD 컨트롤러를 작성할 수 없는 경우(4단계는 따라 하면서 배우는 단계입니다); URDF의 origin을 변경했을 때 모델이 왜 떠다니는지 모르는 경우(1.1 기하학적 직관이 확립되지 않음). 둘 중 하나라도 발생하면, 해당 소절로 돌아가서 재검증하세요.

일반적인 함정 및 문제 해결

증상 가능한 원인 문제 해결 조치
MuJoCo에서 모델을 로드하자마자 분해되거나 날아감 초기 자세 관통(관절이 서로 끼임); 특정 링크에 <inertial>이 없어 질량/관성이 0임 먼저 시뮬레이터 컴파일 경고 확인; 모델에 합리적인 초기 키프레임 제공; 각 링크의 관성 매개변수를 하나씩 확인
PD 서 있을 때 관절 고주파 떨림 게인过高, 적분 단계 크기过大, 수치적 강성 먼저 P 게인을 절반으로 줄인 후 천천히 다시 증가; 시뮬레이션 timestep을 줄여 재현 및 비교; 원하는 댐핑을 스프링 강성으로 잘못 작성했는지 확인
발바닥이 미끄러져 빙판 위를 걷는 듯함 접촉 마찰 매개변수가 기본값을 사용하여 실제 신발 바닥-지면 조합보다 낮음 geom/접촉 쌍의 friction 매개변수 확인; 신발 바닥 재료(고무/인쇄 PLA)에 따라 마찰 계수 크기 조정, 구체적인 값은 재료에 따라 직접 확인 필요
URDF를 MJCF로 변환 후 관절 운동 방향이 반대 URDF axis 정의가 대상 시뮬레이터 규칙과 일치하지 않음; 각도 단위 혼용(도 vs 라디안) 뷰어에서 단일 관절을 하나씩 구동하여 방향 확인; 각도 필드를 전체 검색하여 단위 확인
ROS 2 두 노드가 서로 메시지를 수신하지 못함 ROS_DOMAIN_ID 불일치; 방화벽이 DDS 트래픽 차단; 토픽 이름/QoS 불일치 먼저 동일 머신에서 실행 후 크로스 머신 시도; ros2 topic list로 양쪽이 동일한 토픽을 보는지 확인; 환경 변수 확인(사용 중인 배포판 공식 문서 기준)
Stage 1으로 진입을 계속 망설이며 수학을 반복 학습 완벽주의 함정: "기초 다지기"를 지연의 핑계로 삼음 합격 기준을 항목별로 체크하고, 통과하면 바로 진행; 실제 부족한 점은 Stage 1에서 드러나게 함

여기까지 Stage 0 완료. 다음은 Stage 1: 관절(액추에이터) 만들기입니다: 3단계의 회로 개념과 PD 제어를 실제 하드웨어에 처음 적용합니다; URDF와 MuJoCo 기초는 Stage 2: 이족 보행 플랫폼의 시뮬레이션 보행에서 활용됩니다.
