OpenVLA: An Open-Source Vision-Language-Action Model

요약

Open X-Embodiment 데이터셋의 97만 개 실제 로봇 데모로 사전 학습된 70억 개 매개변수의 오픈소스 VLA 모델로, Llama 2, DINOv2, SigLIP을 결합하여 범용 조작을 수행함.

출처

  • OpenVLA: An Open-Source Vision-Language-Action Model

관련 개체

  • is_based_on Open X-Embodiment 데이터셋 OpenVLA는 Open X-Embodiment 데이터셋의 97만 개 실제 로봇 데모로 사전 학습되었음.
  • cites DROID OpenVLA 논문은 사전 학습에 사용된 다양한 로봇 데모 데이터의 일부로 DROID를 다룸.

개요

OpenVLA는 스탠포드 등 기관이 공동 개발한 7B 파라미터 오픈소스 비전-언어-액션(VLA) 모델로, Llama 2와 융합된 DINOv2-SigLIP 비전 인코더를 기반으로 하며 Open X-Embodiment 데이터셋에서 사전 학습되었습니다. 핵심 기여는 다음과 같습니다: 독점 모델인 RT-2-X(55B)를 능가하는 성능을 제공하는 최초의 오픈소스 VLA를 제공했으며, 데이터 효율적 미세 조정(LoRA) 및 양자화 추론의 실현 가능성을 체계적으로 검증하여 VLA를 소비자용 GPU에서 배포 가능하게 만들었습니다.

그것이 바꾼 것

OpenVLA 이전에는 로봇 분야의 범용 정책에 근본적인 딜레마가 있었습니다: RT-2-X와 같은 폐쇄형 독점 모델은 성능이 뛰어나지만 미세 조정이 불가능하고 재현할 수 없었으며, Octo와 같은 오픈소스 모델은 파라미터 수가 작지만(<100M) 일반화 능력이 약해 분포 이동 하에서 성공률이 약 20%에 불과했습니다. OpenVLA는 이러한 교착 상태를 깨뜨렸습니다—파라미터 수가 7배 적은 오픈소스 모델이 BridgeData V2 평가에서 RT-2-X보다 절대 성공률이 20% 포인트 높은 성과(70.6% vs 50.6%)를 달성할 수 있음을 증명했으며, 동시에 가중치와 학습 코드를 완전히 공개했습니다.

더 중요한 것은, "VLA 미세 조정 비용이 감당하기 어렵다"는 기본 가정을 바꿨다는 점입니다. LoRA(rank=32)를 통해 전체 파라미터의 1.4%만 학습하여도 전체 미세 조정과 동등한 성능(68.2% vs 69.7%)을 달성할 수 있으며, VRAM 요구량이 163.3GB에서 59.7GB로 줄어들어 단일 A100 GPU에서 미세 조정이 가능해졌습니다. 동시에 4-bit 양자화는 성능을 유지하면서(71.9% vs bfloat16의 71.3%) VRAM을 16.8GB에서 7.0GB로 줄여, VLA가 처음으로 소비자용 GPU에서 3Hz 주기로 실시간 추론할 수 있게 했습니다.

방법 분석

모델 아키텍처

  • 백본: Prismatic-7B VLM(Llama 2 기반), DINOv2와 SigLIP 비전 특징을 융합하고 프로젝터를 통해 언어 임베딩 공간에 매핑
  • 입력: 224×224 이미지(384×384와 성능 차이 없음, 학습 시간 3배 단축)
  • 액션 표현: 각 액션 차원을 256개의 bin으로 이산화하며, bin 경계는 최소-최대값이 아닌 학습 데이터의 제1 및 제99 백분위수를 기반으로 하여 이상치를 무시
  • 액션 토큰: Llama 어휘의 마지막 256개 중 가장 적게 사용된 토큰을 활용

학습 전략

  • 목표: 표준 다음 토큰 예측, 액션 토큰에 대해서만 교차 엔트로피 손실 계산
  • 데이터: Open X-Embodiment 필터링(최소 1개의 3인칭 카메라 + 단일 암 엔드 이펙터), Octo 혼합 가중치 적용, DROID 추가 포함(10% 가중치, 마지막 1/3 제거)
  • 핵심 결정:
  • 비전 인코더 미세 조정이 중요(동결 시 성능 저하)
  • 액션 토큰 정확도가 95%를 초과할 때까지 27 에폭 학습
  • 고정 학습률 2e-5, 워밍업 없음
  • 각 데모의 첫 번째 전환(전체 0 액션)을 필터링하지 않으면 정책이 no-op을 빈번히 예측하고 정지

미세 조정 및 추론 최적화

  • LoRA: rank=32가 기본값, 랭크가 성능에 미치는 영향은 무시 가능
  • 양자화: bfloat16 저장/로드(메모리 절반), 4-bit 양자화는 bfloat16 성능과 일치하며 VRAM은 절반 이상 감소
  • 추론: bfloat16에서 15GB VRAM, RTX 4090에서 약 6Hz(가속 기법 없음)

핵심 혁신

  1. 오픈소스 + 고성능의 최초 결합: 이전에는 VLA 분야에서 "오픈소스"와 "고성능"이 양립할 수 없었습니다. OpenVLA는 7B 파라미터로 BridgeData V2에서 70.6% 평균 성공률을 달성하여 55B의 RT-2-X보다 20% 포인트 높았으며, 가중치, 코드, 학습 레시피를 완전히 공개하여 재현 가능한 벤치마크를 구축했습니다.

  2. 데이터 효율적 미세 조정의 체계적 검증: VLA에서 처음으로 전체 미세 조정, LoRA, Sandwich 미세 조정, 비전 인코더 동결 등의 전략을 체계적으로 비교하여 LoRA(1.4% 파라미터)가 전체 미세 조정 성능과 일치함을 증명했습니다. 이는 VLA 도입의 문턱을 직접 낮췄습니다—하위 사용자는 대규모 GPU 클러스터 없이도 새로운 작업에 적응할 수 있습니다.

  3. 양자화 추론의 실용적 분석: 단순히 양자화 후 토큰 정확도를 보고하는 대신, 논문은 핵심 엔지니어링 세부 사항을 공개했습니다: 8-bit 양자화는 대부분의 GPU에서 오히려 추론 속도를 저하시키며(양자화 연산 오버헤드), 4-bit는 메모리 전송 감소로 오버헤드를 보상하여 A5000에서 3Hz를 달성할 수 있습니다. 이는 실제 배포를 위한 명확한 선택 지침을 제공합니다.

핵심 발견: OpenVLA는 의미적 일반화 작업에서 RT-2-X보다 약하지만(예: "Lift White Tape" 1/10), 물리적 일반화(예: "Lift AAA Battery" 7/10 vs RT-2-X의 2/10) 및 시각적 일반화에서 크게 앞섰습니다. 데이터 효율적 미세 조정에서 OpenVLA는 모든 테스트 작업에서 성공률 ≥50%를 달성한 유일한 방법이었습니다.

경계 및 한계

  • 아키텍처 제한: 단일 이미지 관측만 지원하며, 다중 이미지, 고유수용감각 입력 또는 관측 이력을 지원하지 않아 양팔/정밀 조작 작업에 적용이 제한됨
  • 추론 주파수 부족: 6Hz(RTX 4090)는 ALOHA와 같은 50Hz 고주파 제어 요구를 충족할 수 없음; A5000에서 int8 양자화는 1.2Hz에 불과하여 시스템 동역학을 크게 변화시킴
  • 성능 상한: 테스트 작업 성공률이 일반적으로 <90%로 여전히 개선 여지가 있음
  • 탐구되지 않은 방향: 이기종 센서 모달리티 및 액션 공간에 걸친 VLA 학습, 기본 VLM 크기가 VLA 성능에 미치는 영향, 로봇 데이터와 인터넷 데이터의 공동 학습 효과
  • 평가 편향: 원본 BridgeData V2의 정확한 객체와 위치를 얻을 수 없어 모든 평가에 분포 이동이 도입됨; RT-2-X는 독점이라 재학습이 불가능하여 "두 번째로 가능성 높은 액션" 쿼리로 평가되어 실제 성능이 과소평가될 수 있음
  • DROID 데이터 문제: 학습 중 액션 토큰 정확도가 낮아 최종적으로 학습 데이터에서 제거되었으며, 이는 현재 모델 용량이 다양한 데이터를 처리하기에 충분하지 않을 수 있음을 시사

엔지니어링 시사점

  1. 재현 체크리스트: 학습 전에 각 데모의 첫 번째 전환(전체 0 액션)을 반드시 필터링해야 합니다. 그렇지 않으면 고표현력 모델이 no-op을 빈번히 예측합니다; 최소-최대값 대신 제1/99 백분위수를 사용하여 액션 bin을 나눕니다; 비전 인코더 미세 조정은 필수이며, 동결 시 성능이 크게 저하됩니다.

  2. 미세 조정 선택: LoRA(rank=32)를 우선 선택하십시오. 단일 A100으로 10-15시간 내에 새 작업 적응이 가능하며 성능은 전체 미세 조정과 동등합니다. "마지막 레이어만" 또는 "비전 인코더 동결" 방식은 피하십시오(성공률 30-47%에 불과). 최고 성능을 추구하고 GPU 자원이 충분하다면 전체 미세 조정(8×A100, 작업당 5-15시간)이 여전히 상한선입니다.

  3. 배포 시 함정 경고: 8-bit 양자화는 대부분의 GPU에서 오히려 추론 속도를 저하시킵니다(양자화 연산 오버헤드가 메모리 절약보다 큼). 4-bit가 더 나은 선택입니다(성능은 bfloat16과 일치하고 VRAM은 절반). 추론 주파수는 컨트롤러와 일치해야 합니다—BridgeData V2의 5Hz 비차단 제어에서 A5000의 int8 1.2Hz는 시스템 동역학을 크게 변화시키므로, 반드시 대상 하드웨어에서 실제 주파수를 측정하십시오.

  4. 데이터 혼합 가중치: DROID 데이터는 학습 후반에 학습 속도가 느리므로, 논문의 방식대로 마지막 1/3에서 제거하는 것이 좋습니다; 새 데이터셋을 추가하려면 각 데이터 소스의 액션 토큰 정확도를 모니터링하여 데이터 불균형으로 인한 특정 하위 집합의 과소적합을 피해야 합니다.
