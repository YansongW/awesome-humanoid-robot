요약

A fully open-source wheeled biped robot built from about 3,000 USD of off-the-shelf components plus 3D-printed parts, using mjbots quasi-direct-drive actuators and a Raspberry Pi 4, with Python-first software and out-of-the-box PID, MPC and reinforcement-learning balancing examples.

출처

  • upkie/upkie GitHub Repository
  • Upkie Wheeled Biped Robots on Hackaday
  • upkie on PyPI

개요

Upkie는 커뮤니티 주도의 완전 오픈소스 휠형 이족 로봇(wheeled biped)으로, 핵심 저자는 Stéphane Caron(Inria) 등이며, mjbots 오픈소스 액추에이터 생태계 위에 구축되었습니다. Upkie Zero / Upkie Standard / 2026 하드웨어 v2 등의 구성이 포함됩니다. 전체 로봇은 약 3,000달러의 기성 부품 + 60시간 이상의 3D 프린팅으로 재현 가능합니다(공식 Hackaday 기준). 6자유도(각 다리 3개: 고관절, 무릎, 구동 휠)를 가지며, 키/무게는 공식 통일 수치가 없습니다(출처: 조사 아카이브 upkie.md, 이하 동일). Upkie가 진정으로 바꾼 것은 "로봇이 얼마나 강한가"가 아니라 "개인이 실제 하드웨어에서 균형 제어를 배우는 진입 장벽이 얼마나 낮은가"입니다.

핵심 내용

무엇인가: 정확한 정의

Upkie는 휠형 이족 로봇 플랫폼입니다: 두 다리 각각에 구동 휠이 달려 있어, 휠로 균형을 유지하고 다리로 고르지 않은 지형에 대응합니다. 장난감도 아니고 연구용 프로토타입도 아닌, 재현 가능한 완전한 시스템입니다—3D 프린팅 구조 부품, mjbots 액추에이터 선정, 라즈베리파이 메인 컨트롤러부터 Python 소프트웨어 스택과 세 가지 균형 제어 예제까지, 전부 오픈소스이며 직접 구축할 수 있습니다.

플랫폼이 Upkie 생태계에 속하는지 판별하는 세 가지 특징:

  1. 휠형 이족 형태: 각 다리 끝은 발바닥이 아닌 구동 휠로, 균형 문제가 "역진자 + 발바닥 접촉"에서 "역진자 + 휠-지면 접촉"으로 단순화됩니다;
  2. 준직구동 액추에이터: mjbots qdd100 준직구동(quasi-direct-drive) 브러시리스 서보를 사용하며, 펌웨어가 오픈소스이고 힘 제어가 가능합니다;
  3. Python 우선: 소프트웨어 스택은 Python 중심이며, Gymnasium 표준 인터페이스를 사용하고, 시뮬레이션과 실기기가 동일한 코드를 사용합니다.

원리 분석

① 휠형 이족 균형: 역진자에서 휠형 역진자로

Upkie의 균형은 본질적으로 휠형 역진자(wheeled inverted pendulum) 문제입니다. 족형 이족과 달리, 휠형 로봇의 지지점은 이산적인 발바닥이 아니라 연속적인 휠-지면 접촉이므로, 균형 제어가 "보행 계획 + 영점 모멘트(ZMP) 조절"에서 "무게 중심 투영이 휠-지면 접촉선 내에 위치"로 단순화됩니다. 이 단순화로 제어 주파수를 더 높이고 강건성을 더 강화할 수 있으며, PID 같은 고전적 제어기도 실제 하드웨어에서 처음으로 실현 가능해집니다.

② 준직구동 액추에이터: 힘 제어 투명성의 원천

Upkie의 고관절, 무릎 관절은 mjbots qdd100 준직구동 액추에이터를 사용합니다. 준직구동의 핵심 특징은 낮은 감속비(보통 3:1–10:1)로, 외부 토크가 모터 측으로 직접 "투과"될 수 있어 모터 전류만 측정하면 출력 토크를 추정할 수 있습니다:

\[ \tau_{\text{out}} \approx G \, k_t \, I_m - J_{\text{eq}} \ddot{\theta}_m \]

여기서 \(G\)는 감속비, \(k_t\)는 모터 토크 상수, \(I_m\)은 q축 전류, \(J_{\text{eq}}\)는 등가 관성, \(\ddot{\theta}_m\)은 모터 각가속도입니다. 두 번째 항은 관성 보상 항입니다. 감속비가 작아 마찰과 백래시 비선형성도 작으므로, 이 추정은 공학적으로 충분히 정확합니다—이것이 "토크 센서 없이도 힘 제어가 가능한" 모든 비밀입니다(출처: 준직구동 액추에이터 기술 문서).

③ 소프트웨어 스택: 시뮬레이션에서 실기기로의 마찰 없는 전환

Upkie의 소프트웨어 스택은 upkie Python 라이브러리를 핵심으로 하며, Gymnasium 환경을 제공하여 동일한 코드로 시뮬레이션(PyBullet)과 실기기를 제어할 수 있습니다. 즉, 사용자는 시뮬레이션에서 알고리즘을 디버깅한 후 라즈베리파이 4에 직접 배포할 수 있으며, 인터페이스 코드를 다시 작성할 필요가 없습니다. 기본 제공되는 세 가지 균형 제어 패러다임 예제: PID, MPC(qpmpc), 강화 학습(Stable-Baselines3)으로, 고전 제어부터 현대 학습까지의 전체 스펙트럼을 포괄합니다.

Upkie의 핵심 차이는 형태 선택입니다: 휠형 이족은 "퇴화된 휴머노이드"가 아니라 "균형 제어 학습을 위해 최적화된 형태"입니다. 보행 능력을 희생하는 대신, 더 낮은 제어 난이도, 더 낮은 기계적 위험, 더 낮은 비용을 얻습니다—이 세 가지는 정확히 개인 학습자의 핵심 제약입니다(비교 데이터 출처: 조사 아카이브 toddlerbot.md, berkeley-humanoid-lite.md).

누가 사용하는가·적용 사례

Upkie의 주요 사용자 그룹은 개인 학습자, 교육 기관, 오픈소스 로봇 애호가입니다. 대표적인 적용 시나리오:

  1. 균형 제어 입문: PID 예제로 실제 하드웨어에서 "휠형 역진자"의 균형 조절을 경험하고, 피드백 제어의 핵심 개념을 이해;
  2. MPC 및 강화 학습 연구: qpmpc 또는 Stable-Baselines3 예제로 시뮬레이션에서 정책을 훈련한 후 실기기에 배포하여 sim-to-real 전환 검증;
  3. 로봇 강좌 교육: 저비용 실험 플랫폼으로, 학생들이 실제 하드웨어의 센서 노이즈, 액추에이터 지연, 통신 문제를 접하게 함;
  4. 커뮤니티 2차 개발: upkie/parts(CAD/프린트 부품)와 upkie/upkie_description(URDF)을 기반으로 구조를 수정하거나 센서를 추가.

GitHub 저장소 upkie/upkie 386 stars / 52 forks(2026-07-01 스냅샷, 여전히 높은 빈도로 업데이트 중), awesome-open-source-robots 등 유명 목록에 포함되어 있으며, 커뮤니티 토론은 GitHub Discussions와 Matrix 채팅방에서 활발히 이루어집니다.

한계와 경계

  1. 보행 불가: 휠형 이족 형태는 고르지 않은 지형에서 "걷는" 것이 아니라 "구르는" 것만 가능하며, 계단이나 층계를 넘을 수 없습니다;
  2. 키/무게 공식 통일 수치 없음: 구성에 따라 다르며, 특정 버전의 파라미터를 직접 확인해야 합니다;
  3. 부하 용량 제한: 데스크톱급 크기로, 중부하 또는 장시간 야외 작업에는 적합하지 않습니다;
  4. mjbots 생태계 의존: 액추에이터, 드라이버, 펌웨어가 모두 mjbots에서 나오므로, 해당 생태계가 유지보수를 중단하면 Upkie의 공급망이 영향을 받습니다;
  5. 강화 학습 예제의 실기기 전환은 여전히 튜닝 필요: Stable-Baselines3 예제를 제공하지만, sim-to-real 격차(모델링 오차, 지연)는 사용자가 직접 처리해야 합니다.

흔한 오해

  1. "Upkie는 장난감이다"—틀림. 실제 하드웨어의 힘 제어, 상태 추정, 통신 문제를 포함한 완전한 로봇 연구 플랫폼이며, 이러한 문제는 시뮬레이션에서 경험할 수 없습니다;
  2. "휠형 이족이 족형보다 단순해서 가치가 없다"—틀림. 휠형 이족이 단순화하는 것은 균형 제어뿐이며, 관절 힘 제어, 상태 추정, 고르지 않은 지형 적응 같은 다리형 로봇의 핵심 도전은 그대로 유지됩니다;
  3. "3,000달러면 완전한 로봇을 얻을 수 있다"—부정확. 3,000달러는 기성 부품 비용이며, 60시간 이상의 3D 프린팅 시간과 조립·디버깅이 추가로 필요해 총 시간 비용은 금액 자체보다 훨씬 큽니다;
  4. "반드시 Python을 사용해야 한다"—부정확. 소프트웨어 스택은 Python과 C++를 지원하며, Python은 기본 권장일 뿐 C++ 사용자도 개발·배포할 수 있습니다.

  • ent_robot_system_toddlerbot — 동일한 오픈소스 로봇이지만 족형 보행 형태를 채택하여, 제어 복잡도가 Upkie의 휠형 이족 방식보다 현저히 높음;
  • ent_robot_system_berkeley_humanoid_lite — 동일한 오픈소스 로봇으로, 비용은 Upkie와 비슷하지만 족형 보행 연구를 지향;
  • ent_software_mujoco_physics_engine_2022 — PyBullet과 함께 물리 시뮬레이션 엔진으로, Upkie의 시뮬레이션 훈련에 사용 가능;
  • ent_method_model_predictive_control — Upkie 기본 제공 MPC 균형 제어 예제(qpmpc)가 바로 이 알고리즘 기반;
  • ent_software_pinocchio — Upkie의 동역학 모델링과 운동학 계산에 사용 가능하며, MPC 등 제어 알고리즘을 지원.
