# ZOZO's Contact Solver 🫶 A contact solver for physics-based simulations involving 👚 shells, 🪵 solids, 🪢 rods, 🧱 rigid bodies and ⏳ sand. Institutions per source list: Ryoichi Ando 等、ZOZO、Inc.（st-tech）.

개요

ZOZO, Inc. 소속 Ryoichi Ando가 유지 관리하는 오픈소스 접촉 솔버로, 천, 고체, 봉, 강체 및 모래를 위한 통합 물리 시뮬레이션을 대상으로 합니다. 핵심 판매 포인트는 GPU 단정밀도에서의 무관통 접촉 해석과 탄성-접촉 커플링의 "탄성 포함 동적 강성(Elasticity-Inclusive Dynamic Stiffness)"입니다. 프로젝트는 Apache 2.0 라이선스로 오픈소스이며, Docker, Windows 네이티브 실행 파일, Blender 플러그인 및 JupyterLab 프런트엔드를 제공하고, LLM 기반 MCP 서버를 지원합니다. 목표는 1억 8천만 개 이상의 접촉이 있는 대규모 시나리오에서 견고성과 재현성을 유지하는 것입니다.

무엇을 바꾸었는가

이 프로젝트가 실제로 바꾼 것은 "또 하나의 접촉 솔버"가 아니라, "재현 가능한 대규모 물리 시뮬레이션"을 학술 논문의 부산물에서 감사 가능하고 배포 가능한 엔지니어링 산출물로 만든 것입니다. 과거에는 접촉 솔버 논문이 알고리즘과 소수의 예제만 제공하여, 재현하려면 독자가 직접 환경을 구축하고, 의존성을 처리하고, 매개변수를 추측해야 했습니다. 그러나 여기서 저자는 솔버, 프런트엔드, Docker 이미지, AWS/GCP/vast.ai 배포 스크립트, 로그 API를 모두 오픈소스로 공개했으며, 각 예제의 특정 GPU에서의 비용과 프레임 시간까지 제공합니다. 이는 "실험"을 "제품 설명서"로 바꾼 셈입니다.

더 중요한 점은 "접촉 솔버"와 "탄성 솔버"의 관계를 바꾸었다는 것입니다. 전통적인 방식은 두 가지를 분리하는 것입니다: 먼저 탄성을 풀고, 그다음 접촉을 처리하며, 수렴할 때까지 반복합니다. 그러나 여기서의 "탄성 포함 동적 강성"은 접촉 강성이 사후 수정이 아니라 탄성 시스템의 야코비 행렬에 직접 들어가, 접촉과 변형이 동일한 비선형 솔버에서 커플링되도록 합니다. 이는 천 시뮬레이션의 고질적인 문제인 "관통/교차(clipping/snagging)"에 직접 대응합니다. 사후 감지가 아니라 솔버 과정에서 무관통을 보장하는 것입니다.

방법 분석

솔버 아키텍처

  • 접촉 및 탄성 솔버는 모두 GPU에서 실행되며, 전부 단정밀도(single precision)를 사용하고 배정밀도는 사용하지 않습니다. 이는 GPU 메모리 대역폭과 연산 능력에 대한 절충이지만, 기호 힘 야코비 행렬(symbolic force jacobians)을 통해 수치적 견고성을 유지합니다.
  • 변형체는 유한요소법(FEM)을 사용하며, 삼각형(셸) 및 사면체(체적) 요소를 지원합니다. 봉(rods) 및 강체(Painless Differentiable Rotation Dynamics 기반)는 독립 요소 유형으로 동일한 프레임워크에 연결됩니다.

접촉 해석 프로세스

  • 접촉 해석은 무관통(penetration-free)을 보장하며, 삼각형 변형률은 엄격한 상한(예제 기본 5%, 1%까지 조정 가능)을 가집니다.
  • 각 단계 종료 시 명시적 교차 검사를 수행하며, 교차가 감지되면 오류를 보고합니다. 이는 테스트가 통과하면 모든 단계가 수학적으로 무관통임을 의미합니다.

탄성-접촉 커플링(Elasticity-Inclusive Dynamic Stiffness)

  • 논문은 구체적인 공식을 명시하지 않았지만, 프로젝트 설명에 따르면 접촉 강성은 외부 제약 조건으로 반복 처리되는 것이 아니라 탄성 시스템의 동적 강성 행렬에 포함됩니다.
  • 핵심 설계 결정: 접촉력의 변위에 대한 도함수(즉, 접촉 강성)를 탄성 강성 행렬과 병합하여 통합 비선형 시스템을 형성하고, Newton 방법으로 해결합니다.

프런트엔드 및 API 설계

  • 프런트엔드 API는 메서드 체이닝(method chaining)을 사용하며, 단일 임포트(from frontend import App)로 파이프라인 내에서 삼각형/사면체를 생성합니다(.triangulate() 및 .tetrahedralize()). 메시 데이터는 포함되지 않으며, 사용자가 직접 제공하거나 다운로드해야 합니다.
  • time-per-frame, newton-steps, num-contact, max-sigma 등의 로그 조회 API를 제공하여 모니터링 및 디버깅을 지원합니다.

배포 및 통합

  • Blender 플러그인(Blender 5+ 필요) 및 JupyterLab 프런트엔드를 제공하며, 둘 다 동일한 솔버 엔진과 통신합니다. 원격 GPU 시뮬레이션(vast.ai 등)을 지원합니다.
  • MCP 서버를 제공하여 LLM이 자연어로 시뮬레이션 프로세스를 구동할 수 있게 합니다. 이는 물리 시뮬레이션을 AI 에이전트 워크플로우에 연결하려는 시도입니다.

핵심 혁신

  1. 탄성 포함 동적 강성(Elasticity-Inclusive Dynamic Stiffness): 접촉 강성을 외부 제약 조건으로 반복 처리하는 대신 탄성 시스템의 야코비 행렬에 직접 통합합니다. 이는 전통적인 "탄성 먼저, 접촉 나중"의 교대 반복에서 발생할 수 있는 수렴 속도 저하와 관통 잔여 문제를 제거하며, 접촉-변형 커플링 솔버의 실질적인 개선입니다.

  2. 단정밀도 GPU 대규모 솔버: RTX 4090에서 820만 개의 정점, 1억 8410만 개의 접촉을 가진 시뮬레이션을 처리하며, 프레임당 144.5초가 소요됩니다. 이는 알고리즘 혁신일 뿐만 아니라 엔지니어링 능력의 표현입니다. 단정밀도는 메모리 사용량을 절반으로 줄이지만, 정밀도 손실을 보상하기 위해 기호 야코비 행렬이 필요하며, 이러한 조합은 공개 프로젝트에서 드뭅니다.

  3. 재현성을 최우선으로: 사전 컴파일된 Docker 이미지, Windows 네이티브 실행 파일, AWS/GCP/vast.ai 배포 스크립트, GitHub Actions 스트레스 테스트(연속 10회 실행에 지터 추가), 각 예제의 비용 및 프레임 시간 표를 제공합니다. 이는 "논문 코드"의 전달 기준을 바꾸어, 하류 사용자가 채택 가치를 직접 평가할 수 있게 합니다.

경계 및 한계

  • 논문은 명시하지 않음: Elasticity-Inclusive Dynamic Stiffness의 구체적인 공식 유도와 수렴성 증명은 제공되지 않았으며, 프로젝트 설명에서 메커니즘을 추론한 것뿐입니다.
  • 솔버는 오프라인 설계이며 실시간이 아닙니다. 대규모 예제(large-twist, large-five-twist, large-woven)는 완료에 며칠에서 몇 주가 걸릴 수 있어 GitHub Actions 테스트에 포함되지 않았습니다. 이는 이러한 예제의 안정성이 자동화된 회귀 검증을 거치지 않았음을 의미합니다.
  • x86 아키텍처만 지원하며 arm64는 지원하지 않습니다. 문서와 튜토리얼 비디오는 "충분히 정교하지 않으며", 저자는 커뮤니티 기여를 환영합니다.
  • 프로젝트 유지 관리는 1인 파트타임(Ryoichi Ando)으로 이루어지며, issue 처리가 느릴 수 있습니다. 직접 pull request는 받지 않습니다(저작권 및 라이선스 문제 관련). issue 또는 fork를 통해 제출해야 합니다.
  • 메인 브랜치는 자주 업데이트되어 논문과 불일치할 수 있습니다. 논문 참조 구현은 sigasia-2024 브랜치에 있으며, 유지 관리 업데이트만 수행되고 최신 알고리즘 변경 사항은 포함되지 않습니다. 이는 논문 결과를 재현하려면 특정 브랜치를 사용해야 함을 의미합니다.

엔지니어링 시사점

  • 브랜치 먼저 확인: 논문 결과를 재현하는 것이 목표라면 메인 브랜치가 아닌 sigasia-2024 브랜치를 반드시 사용하세요. 메인 브랜치는 최신 알고리즘 변경 사항을 포함하여 논문과 불일치할 수 있습니다.
  • 하드웨어 선택: 대규모 시뮬레이션(>100만 정점)은 RTX 4090 또는 5090이 필요합니다. 중소 규모(<20만 정점)는 RTX 3090, 4070 또는 5070으로 충분합니다. 단정밀도는 VRAM 요구량을 절반으로 줄이지만, CUDA 12.8+ 드라이버 요구 사항에 주의해야 합니다.
  • 가장 흔한 함정: 메시 데이터는 프로젝트에 포함되지 않으므로 사용자가 직접 생성하거나 다운로드해야 합니다. 이는 "즉시 사용 가능"한 경험이 메시 준비 단계에서 중단됨을 의미합니다. 먼저 yarn 또는 drape 같은 작은 예제로 환경을 검증한 후 점진적으로 규모를 키우는 것이 좋습니다.
  • 비용 추정: AWS L4 인스턴스는 약 $1/시간이며, 작은 예제 비용은 \(0.01-\)0.39입니다. 대규모 예제는 RTX 4090의 vast.ai 비용(<$0.5/시간)으로 추정해야 합니다. 그러나 대규모 예제의 프레임당 시간(46-437초)은 2,000프레임 시뮬레이션에 1-10일이 소요됨을 의미하므로 예산을 사전에 계획해야 합니다.
  • 로그 API는 디버깅에 유용: time-per-frame, newton-steps, num-contact, max-sigma 지표를 수용 기준으로 사용해야 합니다. max-sigma가 변형률 제한을 초과하면 접촉 강성 또는 시간 단계를 조정해야 합니다.
