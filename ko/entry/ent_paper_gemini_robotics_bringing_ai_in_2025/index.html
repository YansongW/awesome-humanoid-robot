Gemini Robotics: Bringing AI into the Physical World

Gemini Robotics: Bringing AI into the Physical World

요약

Gemini Robotics 的实现路径是先把语言指令、相机图像/多视角观测编码成多模态表征，再用ACT/行为克隆模仿学习、扩散策略/流匹配、VLA 多模态动作模型预测全身轨迹/动作序列、动作 chunk/token。关键点是保留 VLM 的语义理解，同时增加机器人状态和动作头，避免只停留在语言规划。

출처

  • Gemini Robotics project page
  • Gemini Robotics: Bringing AI into the Physical World

개요

Google DeepMind 팀은 Gemini 2.0의 다중 모달 이해 능력을 물리적 세계로 확장하는 것을 목표로 하는 Gemini Robotics 시리즈 모델을 제안한다. 핵심 기여는 다음과 같다: 구현 추론 벤치마크 ERQA 구축, 추론 강화 Gemini Robotics-ER 모델 개발, VLA 아키텍처 기반 Gemini Robotics 제어 모델을 통해 실제 로봇에서 제로샷 및 퓨샷 조작 구현.

무엇을 바꾸었는가

이 작업의 진정한 변화는 '물리적 세계 이해'와 '물리적 세계에서의 행동'이라는 오랫동안 분리되어 있던 두 연구 경로를 처음으로 동일한 모델 패밀리로 연결했다는 점이다. 이전에는 VLM 벤치마크(RealworldQA, BLINK 등)가 원자적 능력(객체 인식, 카운팅, 위치 파악)만 평가했으며, 이러한 능력과 로봇이 실제 조작을 수행하는 데 필요한 '구현 추론' 사이에는 큰 격차가 존재했다. Gemini Robotics의 야망은 충분히 강력한 다중 모달 기반 모델이 적절한 증류와 미세 조정을 거치면 전통적인 VLA처럼 전용 정책 네트워크를 처음부터 훈련하는 대신 직접 로봇 제어의 백본이 될 수 있음을 증명하는 것이다.

더 중요한 것은 저자가 '모델이 장면을 이해할 수 있다'는 수준에 머물지 않고 '이해한 후 어떻게 동작으로 전환하는가'라는 엔지니어링 과제를 해결했다는 점이다. 추론 지연 시간을 수 초에서 160ms 미만으로 압축하고 클라우드 백본과 로컬 동작 디코더의 하이브리드 아키텍처를 채택함으로써, 그들은 천억 파라미터급 VLM을 실제 실시간 제어 루프에 진입시켰다. 이러한 '대형 모델이 직접 로봇 팔을 구동하는' 패러다임은 π₀ 등의 오픈소스 VLA의 '전용 소형 모델' 경로와 뚜렷한 대비를 이루며, 범용 로봇 기반 모델의 실현 가능성 경계를 재정의했다.

방법 분석

3계층 모델 아키텍처

  • Gemini Robotics-ER: Gemini 2.0 Flash 기반의 강화된 구현 추론 버전으로, 추가 로봇 데이터 없이 로봇 애플리케이션에 사용 가능. 새로운 기능에는 탑다운 그랩 예측(y, x 및 회전 각도 θ 출력)이 포함.
  • Gemini Robotics: VLA 모델로, Gemini Robotics-ER의 증류 버전이 클라우드 백본을 구성하고 로봇 온보드 컴퓨터에서 실행되는 로컬 동작 디코더를 추가. 백본 쿼리-응답 지연 시간은 160ms 미만으로 최적화되었으며, 엔드투엔드 지연 시간은 약 250ms, 액션 블록 사용 시 유효 제어 주파수는 50Hz.
  • 제로샷 코드 생성 제어: ALOHA 2 이중 로봇 팔에서 API를 통해 모델이 직접 제어 코드(그리퍼 이동, 개폐, 상태 읽기)를 출력하도록 함. API에는 인식 기능(객체 감지, 포인트 위치 파악, 그랩 포즈 생성)이 내장되어 있으며, 실행 루프에서 모델이 이미지, 상태, 피드백을 반복적으로 수신하여 반응하고 재계획할 수 있음.

핵심 설계 결정

  • 좌표 규약: 2D 경계 상자는 [y₀, x₀, y₁, x₁], 포인트는 [y, x] 튜플, 3D 경계 상자는 [x, y, z, w, h, l, r1, r2, r3], 탑 그랩 포인트는 y, x 및 회전 각도 θ(-90° ~ 90°) 사용. 모든 좌표는 0-1000 정수로 정규화되어 모델이 텍스트 토큰 형태로 출력하기 용이.
  • 퓨샷 ICL 제어: 10개의 원격 조작 궤적을 객체 및 엔드 이펙터 포즈 목록으로 변환하여 텍스트 형태로 프롬프트에 추가. Gemini Robotics-ER는 외부 모델 없이(참고 작업은 외부 모델 필요) 시각적 키포인트를 자체적으로 추출할 수 있으며, 관측과 동작 사이에 언어 설명을 삽입하여 추론을 유도.
  • CoT 프롬프트: ERQA의 각 질문 끝에 "Reason step by step about the answer, and show your work, for each step. Only after that, proceed to the final answer."를 추가.
  • 훈련 데이터: Gemini Robotics는 ALOHA 2 차량군에서 12개월간 수집된 수천 시간의 실제 원격 조작 데이터로 훈련되었으며, 웹 문서, 코드, 다중 모달 콘텐츠 및 구현 추론 데이터를 혼합 사용.

핵심 혁신

  1. ERQA 벤치마크 제안: '구현 추론'을 위해 특별히 설계된 최초의 오픈소스 벤치마크로, 400개의 수작업 주석 다지선다 문제가 공간 추론, 궤적 추론, 동작 추론, 상태 추정, 포인팅, 다중 시점 추론 및 작업 추론의 7가지 범주를 포괄. 28%의 문제는 여러 이미지를 포함하며, 기존 VLM 벤치마크가 원자적 능력만 측정하고 '물리적 세계에서 행동하는 데 필요한 능력'을 측정하지 않는 공백을 메움.

  2. '추론-동작' 증류 아키텍처: Gemini Robotics-ER의 추론 능력을 VLA 백본에 증류한 후, 로컬 동작 디코더를 통해 추론 중간 결과를 연속적인 저수준 동작으로 변환. 이러한 '추론 강화 후 제어로 증류'하는 2단계 설계는 VLA를 직접 엔드투엔드로 훈련하는 것보다 효율적이며, 모델의 제어 행동에 해석 가능성을 부여——모델이 ER 모델과 유사한 인간이 읽을 수 있는 추론 궤적을 출력할 수 있음.

  3. 제로샷 코드 생성 제어 패러다임: VLM이 동작 토큰을 예측하는 대신 코드 형태로 로봇 제어 명령을 직접 출력하도록 함. 이러한 추상화 계층 설계는 모델이 사전 훈련된 코드 지식을 활용할 수 있게 하며, API 내장 인식 기능(객체 감지, 그랩 포즈 생성)을 통해 VLM의 수치 예측 정밀도 부족을 보완. Gemini Robotics-ER는 Gemini 2.0 대비 작업 완료율이 약 2배 향상(53% vs 27%).

경계 및 한계

저자가 명시적으로 인정한 경계는 다음과 같다: Gemini 2.0은 복잡한 운동 계획(예: 장애물 회피)을 수행할 수 없으며, 관측 이미지 기반의 유용한 궤적만 생성 가능; Gemini Robotics-ER는 실제 세계 banana handover에서 시뮬레이션보다 낮은 성공률(30% vs 54%)을 기록하며, 이는 보정 불완전성과 실제 노이즈에 기인; 충분히 정밀한 그랩을 생성할 수 없어 dress folding을 수행할 수 없음; VLM으로서 더 손재주가 필요한 작업에서 고유한 한계가 있으며, 추론과 동작을 연결하는 중간 단계가 필요. 또한 Gemini 2.0은 긴 비디오에서 공간 관계 접지에 어려움을 겪을 수 있으며, 수치 예측(포인트 및 상자)의 정밀도가 더 세밀한 제어 요구를 충족하기에 부족. 새로운 본체 적응 실험은 저자가 명시적으로 예비 탐색으로 표시. 논문은 모델 파라미터 수, 훈련 계산량, 구체적인 추론 지연 시간 수치, 훈련 epoch 수 등 핵심 재현 정보를 언급하지 않음.

엔지니어링 시사점

재현 및 모델 선택에 있어 가장 먼저 확인해야 할 것은 좌표 규약이다——모든 2D 상자는 [y₀, x₀, y₁, x₁]을 사용하고 0-1000 정수로 정규화, 포인트는 [y, x] 튜플, 탑 그랩 회전 각도 θ 범위는 -90° ~ 90°(0°는 그리퍼가 수평 이미지 축과 정렬됨을 의미). 이러한 세부 사항은 모델 출력이 로봇에 의해 올바르게 해석될 수 있는지 직접 결정하며, 가장 쉽게 실수하는 부분이기도 하다. 둘째, ICL 제어에서 10개 데모의 궤적 번역 품질이 매우 중요하다——관측과 동작 사이에 삽입된 언어 설명은 추론 품질에 큰 영향을 미치므로, 소규모 작업에서 프롬프트 형식을 검증한 후 확장하는 것이 좋다. 셋째, 제로샷 코드 생성은 시스템 프롬프트의 물리적 제약 설명(그리퍼 길이 0.09m, 개구 0.065m, 테이블 크기 0.8m×0.4m, 좌우 팔 도달 범위)에 의존하며, 이러한 제약은 실제 하드웨어와 엄격히 일치해야 한다. 그렇지 않으면 모델이 도달 불가능한 그랩 포즈를 생성할 수 있다. 마지막으로 ERQA 벤치마크 코드는 오픈소스(github.com/embodiedreasoning/ERQA)로 제공되어 자체 VLM의 구현 추론 능력을 평가하는 출발점이 될 수 있지만, 400문제 규모가 작다는 점에 유의하고 RealworldQA 및 BLINK와 교차 검증하는 것이 좋다.
