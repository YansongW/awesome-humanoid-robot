개요

데이터 수집 및 데이터 파이프라인(Data Collection and Data Pipelines)은 VLA / WAM / AI 알고리즘 통합 단계(P12)에서 번호가 P12.2.2인 로드맵 공정 노드로, 메서드(method) 유형에 속하며, 소속 도메인은 07_ai_models_algorithms, 가치 사슬 계층은 intelligence입니다. 이는 원시 데이터 수집부터 훈련 가능한 데이터셋 전달까지의 완전한 엔지니어링 체인을 정의하며, 원격 조작, 시뮬레이션 데이터, 인터넷 비디오, 데이터 정제 및 증강의 네 가지 방법 도구와 입력 정리, 방안 설계, 시제품 구현, 결과 검증, 문서 전달의 다섯 가지 표준화 공정 동작을 포함합니다. 이것이 실제로 바꾸는 것은 데이터 양의 축적 방식이 아니라, 데이터를 '수집된 소재'에서 '검수 가능하고, 추적 가능하며, 재현 가능한 엔지니어링 자산'으로 만드는 것입니다.

핵심 내용

무엇인가: 정확한 정의

데이터 수집 및 데이터 파이프라인(P12.2.2)은 VLA/WAM 모델 개발에서 데이터 측 엔지니어링을 담당하는 공정 노드입니다. 이는 특정 데이터셋이 아니라, 원시 데이터를 고품질 훈련 코퍼스로 변환하는 일련의 프로세스 규범입니다. 이 노드는 WBS V3에서 다섯 개의 3차 하위 작업으로 전개됩니다: P12.2.2.1 입력 정리 및 목표 정량화, P12.2.2.2 방안/방법 설계, P12.2.2.3 모델링/시뮬레이션 및 시제품 구현, P12.2.2.4 시뮬레이션 결과 검증 및 최적화, P12.2.2.5 문서 출력 및 하위 전달.

각 하위 작업은 통일된 4단계 핵심 동작 템플릿을 따르며, '정리→설계→구현→검증→전달'의 폐루프를 형성합니다. 그 방법 도구 상자에는 명확히 네 가지 유형이 포함됩니다: 원격 조작(Teleoperation), 시뮬레이션 데이터(Simulation Data), 인터넷 비디오(Internet Videos), 데이터 정제 및 증강(Data Cleaning and Augmentation). 이 네 가지 방법은 각각 실제 물리적 상호작용 데이터, 가상 환경 생성 데이터, 인간 행동 사전 데이터, 그리고 데이터 품질 관리 수단에 해당합니다.

원리 분해

① 입력 정리 및 목표 정량화(P12.2.2.1)

이 하위 작업의 핵심 동작은 세 가지입니다: 모든 상류 입력 목록을 나열하고 버전을 확인하며, 검수 기준을 정량화 가능한 KPI로 전환하고, 작업 Owner, 시간 노드 및 위험 등록을 수립합니다.

상류 입력 목록에는 인식 스택의 센서 선정 문서, 캘리브레이션 파라미터, 장면 정의 파일, 그리고 P12 단계 전체의 요구사항 명세서가 포함됩니다. 버전 확인의 의미는 데이터 수집이 인식 구성의 특정 버전과 바인딩되어야 하며, 그렇지 않으면 수집된 데이터가 이후 모델 입력과 정렬되지 않기 때문입니다. 검수 기준을 정량화 가능한 KPI로 전환하는 전형적인 방법은 '데이터셋 품질 양호'를 '라벨링 정확도 ≥ 자체 확인 필요 %, 무효 샘플 비율 ≤ 자체 확인 필요 %, 커버 시나리오 수 ≥ 자체 확인 필요 개' 등의 측정 가능한 지표로 전환하는 것입니다. Owner와 마일스톤 수립은 책임을 개인에게 할당하여 데이터 작업이 '모두가 책임지지만 아무도 책임지지 않는' 상황을 방지합니다.

② 방안/방법 설계(P12.2.2.2)

이 하위 작업은 2개 이상의 후보 방안을 구성하고, 평가 매트릭스를 수립하여 정량적으로 점수를 매기며, 심의를 조직하고 방안을 동결할 것을 요구합니다. 후보 방안은 일반적으로 네 가지 데이터 소스의 다양한 조합을 중심으로 전개됩니다:

방안 차원 원격 조작 중심 시뮬레이션 중심 혼합 방안
데이터 실제성 최고 낮음 중간
수집 비용 최고 최저 중간
시나리오 커버리지 제한적 광범위 비교적 넓음
라벨링 난이도 낮음(자연스러운 동작 라벨 보유) 중간(자동 라벨링 필요) 중간
규모 상한 낮음(물리적 머신 시간 제한) 높음(병렬 생성 가능) 중상

평가 매트릭스의 정량적 점수는 일반적으로 데이터 품질, 비용, 시간, 위험의 네 가지 차원에서 가중치를 두고 평가합니다. 심의 및 방안 동결의 의미는 데이터 수집이 대규모로 시작되면 중간에 방안을 변경하면 이미 수집된 데이터가 무효화되므로, 방안 동결이 위험을 통제하는 핵심 노드이기 때문입니다.

③ 모델링/시뮬레이션 및 시제품 구현(P12.2.2.3)

이 하위 작업은 시뮬레이션/수학적 모델 또는 프로토타입 시제품을 구축하고, 계산 또는 실험을 실행하며, 핵심 파라미터와 경계 조건을 기록할 것을 요구합니다. 데이터 파이프라인의 경우 '시제품'은 다음이 될 수 있습니다: 원격 조작 수집 시스템(마스터 핸드, 슬레이브 핸드, 힘 피드백 장치 포함), 시뮬레이션 데이터 생성기(물리 엔진 기반 도메인 무작위화 구성), 또는 데이터 정제 파이프라인 프로토타입. 핵심 파라미터에는 수집 주파수, 해상도, 힘 감각 샘플링 속도, 장면 조명 조건, 객체 재질 속성 등이 포함됩니다. 경계 조건에는 로봇 관절 한계, 작업 공간 범위, 센서 측정 범위 등이 포함됩니다.

④ 시뮬레이션 결과 검증 및 최적화(P12.2.2.4)

이 하위 작업은 시뮬레이션 결과와 이론/실험 데이터의 일관성을 검증하고, 취약점을 식별하여 반복 최적화할 것을 요구합니다. 전형적인 검증 방식은 다음과 같습니다: 시뮬레이션 생성 데이터와 소량의 실제 원격 조작 데이터의 분포 차이 비교; 데이터 증강 후 샘플이 물리적 합리성을 유지하는지 확인(예: 객체 관통 없음, 힘 감각 급변 없음); 정제 규칙이 유효 샘플을 잘못 삭제하지 않는지 검증. 취약점 식별 후 반복 루프에 진입합니다: 시뮬레이션 파라미터 조정, 증강 전략 최적화, 정제 규칙 수정.

⑤ 문서 출력 및 하위 전달(P12.2.2.5)

이 하위 작업은 최종 보고서/도면/규격을 출력하고, ICD/BOM/SOP/요구사항 추적 체인을 업데이트하며, 하위 단계로의 공식 전달을 완료할 것을 요구합니다. 구체적 동작은 다음과 같습니다: 템플릿에 따라 문서를 작성하고 원시 데이터를 참조하며, 내부 심의 및 버전 제어를 완료하고, 게시 및 하위 의존자에게 통지. 여기서 '문서'는 데이터셋 설명뿐만 아니라 데이터 수집 SOP(표준 작업 절차), 데이터 형식 규격, 품질 검사 보고서, 버전 변경 기록도 포함합니다. 요구사항 추적 체인은 각 데이터 요구사항이 특정 수집 배치 및 정제 규칙까지 추적될 수 있도록 보장합니다.

핵심 파라미터 및 규격

데이터 파이프라인의 핵심 파라미터는 네 가지 계층에 분포합니다:

수집 계층 파라미터: 원격 조작 수집 주파수(일반적으로 자체 확인 필요 Hz), 힘 감각 샘플링 속도(자체 확인 필요 Hz), 이미지 해상도(자체 확인 필요 픽셀), 동기화 정밀도(자체 확인 필요 ms). 시뮬레이션 데이터 생성 파라미터에는 물리 엔진 스텝(자체 확인 필요 s), 도메인 무작위화 범위(자체 확인 필요), 시나리오 수(자체 확인 필요 개)가 포함됩니다.

품질 계층 파라미터: 라벨링 정확도(자체 확인 필요 %), 무효 샘플 비율(자체 확인 필요 %), 중복률(자체 확인 필요 %), 시나리오 커버리지(자체 확인 필요 %). 이러한 파라미터는 P12.2.2.1의 KPI 구체적 지표를 구성합니다.

규모 계층 파라미터: 데이터셋 총 샘플 수(자체 확인 필요 개), 유효 샘플 수(자체 확인 필요 개), 클래스 균형도(자체 확인 필요), 시간 범위(자체 확인 필요 일).

버전 계층 파라미터: 데이터셋 버전 번호(시맨틱 버전), 변경 기록 수(자체 확인 필요 개), 하위 의존자 수(자체 확인 필요 개).

수평 비교

P12.2.2를 인접 공정 노드와 비교하면 그 경계를 더 명확히 파악할 수 있습니다:

비교 차원 P12.2.2 데이터 수집 및 데이터 파이프라인 P12.1 인식 스택 P12.2.3 모델 훈련(추론)
핵심 산출물 훈련 가능한 데이터셋 센서 구성 및 캘리브레이션 파라미터 훈련된 모델 가중치
주요 방법 원격 조작, 시뮬레이션, 정제 증강 캘리브레이션, SLAM, 탐지 추적 지도 학습, 강화 학습
전달물 형태 데이터셋 + 문서 + SOP 구성 파일 + 캘리브레이션 보고서 모델 파일 + 평가 보고서
품질 측정 데이터 품질 지표 캘리브레이션 정밀도 지표 작업 성공률
반복 주기 주 단위 일 단위 월 단위

P12.2.2와 가장 가까운 이웃은 P12.2.1(데이터 요구사항 분석으로 가정, 자체 확인 필요)이며, 전자는 '어떤 데이터가 필요한지'를 정의하고, 후자는 '이 데이터를 어떻게 확보하고 처리할지'를 해결합니다.

누가 사용하는가·적용 사례

사례 1: 이중 팔 조작 작업의 원격 조작 데이터 수집. 한 팀이 '양손 협력 운반' 작업을 수행하는 VLA 모델을 훈련해야 합니다. P12.2.2.1에 따라 먼저 상류 입력을 정리합니다: 인식 스택이 제공하는 이중 팔 관절 각도 범위, 엔드 이펙터 힘 감각 측정 범위, 작업 공간 크기. 이후 P12.2.2.2 단계에서 두 개의 후보 방안을 구성합니다: 방안 A는 순수 원격 조작 수집(예상 자체 확인 필요 시간), 방안 B는 원격 조작 + 시뮬레이션 데이터 혼합(예상 자체 확인 필요 시간). 평가 매트릭스는 방안 B가 비용 차원에서 더 높은 점수를 보여 최종적으로 방안 B를 동결합니다. P12.2.2.3 단계에서 원격 조작 수집대를 구축하고 핵심 파라미터를 기록합니다: 수집 주파수 자체 확인 필요 Hz, 힘 감각 샘플링 속도 자체 확인 필요 Hz. P12.2.2.4 단계에서 시뮬레이션 데이터와 실제 데이터를 혼합한 후 분포 차이를 확인하고, 시뮬레이션 데이터의 객체 마찰 계수가 실제와 큰 차이가 있음을 발견하여 반복 조정 후 검증을 통과합니다. P12.2.2.5 단계에서 데이터셋 v1.0을 출력하고, 데이터 설명 문서와 정제 규칙 SOP를 첨부하며, 하류 모델 훈련 팀에 통지합니다.

사례 2: 인터넷 비디오 데이터의 정제 파이프라인. 한 팀이 인터넷 비디오를 활용하여 인간 조작 사전 지식을 보충하려고 합니다. P12.2.2.1 단계에서 '비디오 사용 가능률'을 KPI로 전환합니다: 사용 가능한 비디오 비율 ≥ 자체 확인 필요 %. P12.2.2.2 단계에서 정제 파이프라인 방안을 설계합니다: 방안 A는 순수 수동 선별(비용 높음), 방안 B는 자동 사전 선별 + 수동 검토(비용 적정). 평가 후 방안 B를 선택합니다. P12.2.2.3 단계에서 자동 사전 선별 프로토타입을 구현합니다: 장면 분류기를 기반으로 관련 없는 비디오를 필터링하고, 동작 감지기를 기반으로 조작 클립을 추출합니다. P12.2.2.4 단계에서 검증 결과 사전 선별 오삭제율이 자체 확인 필요 %임을 발견하고, 분류기 임계값을 조정하여 허용 가능한 범위로 최적화합니다. P12.2.2.5 단계에서 정제된 비디오 데이터셋을 라벨 파일 및 정제 로그와 함께 전달합니다.

한계 및 경계

데이터 수집 비용 경계. 원격 조작 수집은 물리적 로봇 수와 운영자 작업 시간에 제한되며, 일일 유효 데이터 양에는 하드 상한이 존재합니다. 프로젝트가 수백만 개 샘플을 필요로 할 때, 순수 원격 조작 방안은 비용 측면에서 불가능하며, 반드시 시뮬레이션 데이터나 인터넷 비디오로 보충해야 합니다. 이것은 P12.2.2.2 방안 평가에서 반드시 정량화해야 하는 제약입니다.

프라이버시 및 규정 준수 경계. 인터넷 비디오는 인물 초상권, 장면 프라이버시, 플랫폼 이용 약관 등의 법적 문제를 수반합니다. 데이터 정제 단계에는 얼굴 모자이크, 장면 비식별화, 출처 규정 준수 심사 등의 동작이 포함되어야 합니다. 이 경계는 P12.2.2.1의 KPI 설정에서 '규정 준수율 100%'의 하드 지표로 반영되어야 합니다.

라벨링 품질 경계. 수동 라벨링이든 자동 라벨링이든 오류율이 존재합니다. 라벨링 품질은 하류 모델 훈련 효과에 직접 영향을 미치지만, 라벨링 정확도를 과도하게 추구하면 비용이 크게 상승합니다. 엔지니어링 판단: 라벨링 정확도 목표는 일반적으로 자체 확인 필요 %에서 자체 확인 필요 % 사이로 설정되며, 구체적 값은 작업 난이도와 모델 오류 허용 능력에 따라 달라집니다.

시뮬레이션과 실제의 도메인 격차. 시뮬레이션 데이터는 비용이 낮고 규모가 크지만, 물리 엔진의 근사 특성으로 인해 데이터 분포가 실제 세계와 편차가 있습니다. P12.2.2.4의 검증 단계는 바로 이 격차를 정량화하고 줄이기 위한 것이지만, 완전히 제거할 수는 없습니다. 힘 감각에 민감한 작업(예: 정밀 조립)의 경우 시뮬레이션 데이터의 신뢰성을 신중히 평가해야 합니다.

일반적인 오해

  1. '데이터가 많을수록 좋다' — 틀림. 데이터 규모는 KPI 중 하나일 뿐이며, 품질, 다양성, 라벨링 정확도가 동등하게 중요합니다. 맹목적으로 데이터 양을 늘리면 많은 중복 샘플이 유입되어 오히려 유효 정보 밀도가 희석될 수 있습니다. P12.2.2.1의 KPI 설정에는 규모 지표와 품질 지표가 동시에 포함되어야 합니다.

  2. '시뮬레이션 데이터가 실제 데이터를 완전히 대체할 수 있다' — 틀림. 시뮬레이션 데이터는 커버리지와 비용에서 장점이 있지만, sim-to-real 격차는 항상 존재합니다. 엔지니어링 판단: 접촉이 많은 조작 작업의 경우 실제 데이터 비율은 자체 확인 필요 % 이상이어야 하며, 그렇지 않으면 실제 환경에서 모델 성능이 크게 저하될 수 있습니다.

  3. '데이터 정제는 단지 나쁜 샘플을 걸러내는 것' — 틀림. 데이터 정제에는 중복 제거, 정렬, 라벨 수정, 증강 생성 등의 긍정적 작업도 포함됩니다. P12.2.2.3의 '이상 및 편차 기록' 동작은 정제 과정 자체가 데이터 문제를 발견하고 수집 방안을 개선하는 중요한 피드백 채널임을 보여줍니다.

  4. '데이터셋 전달 후 작업이 끝난다' — 틀림. P12.2.2.5는 '게시 및 하위 의존자 통지'를 요구하지만, 하위 사용 과정에서 새로운 데이터 문제가 발견될 수 있으며 버전 반복이 필요합니다. 데이터 파이프라인은 지속적으로 운영되는 시스템이지, 일회성 전달의 정적 산출물이 아닙니다.
