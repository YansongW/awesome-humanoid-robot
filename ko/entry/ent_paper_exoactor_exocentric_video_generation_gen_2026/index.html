요약

Humanoid control systems have made significant progress in recent years, yet modeling fluent interaction-rich behavior between a robot, its surrounding environment, and task-relevant objects remains a fundamental challenge. Institutions per source list: ** Beijing Academy of Artificial Intelligence (BAAI).

개요

ExoActor는 3단계 파이프라인(비디오 생성→모션 추정→모션 실행)을 제안하며, 대규모 비디오 생성 모델의 일반화 능력을 활용하여 3인칭 비디오 생성을 휴머노이드 로봇 상호작용 역학을 모델링하는 통합 인터페이스로 사용한다. Unitree G1에서 작업별 데이터 수집 없이도 대화형 제어를 구현한다. 핵심 기여는 로봇-인간 신체화 전이와 작업-행동 분해를 결합하여 생성된 비디오를 실행 가능한 행동의 중간 표현으로 만들고, B/A/S 3단계 작업에서 엔드투엔드 실현 가능성을 검증한 것이다.

무엇을 바꾸었는가

휴머노이드 로봇 제어는 오랫동안 근본적인 모순에 시달려 왔다. 실제 세계의 상호작용 행동은 공간 맥락, 시간 역학, 작업 의도를 공동으로 모델링해야 하지만, 통제된 환경에서 훈련된 정책은 새로운 장면을 만나면 빠르게失效한다. 전통적인 해법은 값비싼 데이터 수집에 의존하거나 도메인별 튜닝이 필요했으며, 본질적으로 작업 분포를 "패치식"으로 확장하는 것이었다. ExoActor가 진정으로 바꾼 것은 문제 프레임워크이다. 더 이상 로봇이 "상태에서 행동으로"의 매핑을 직접 학습하도록 하지 않고, 3인칭 비디오 생성을 통합 상호작용 모델링 인터페이스로 사용하여 비디오 생성 모델의 내재적 세계 지식과 일반화 능력이 상호작용 역학 모델링 부담을 담당하게 한다. 이는 작업 일반화의 병목이 "로봇 데이터"에서 "비디오 생성 품질"로 이동했음을 의미하며, 후자는 현재 대규모 생성 모델이 이미 갖춘 능력이다. 또 다른 미묘하지만 중요한 변화는 로봇-인간 신체화 전이를 통해 로봇 관측을 인간형 표현으로 매핑하여 인간 중심 비디오 생성 모델의 사전 지식을 직접 활용할 수 있다는 점이다. 이는 본질적으로 로봇 전용 생성 모델을 훈련하는 대신 로봇을 "인간으로 위장"하여 인간 행동의 사전 분포를 차용하는 것이다.

방법 분해

3단계 파이프라인

  1. 비디오 생성 단계
  2. Robot-to-Human Embodiment Transfer: Nano Banana Pro (Gemini 3.1 Pro)를 사용하여 프롬프트 기반 이미지 편집을 통해 로봇 관측을 인간형 표현으로 변환한다. 핵심 제약 조건은 다음과 같다: 1:1 각도별 정밀한 공간 자세, 방향, 운동학적 구성 복제; 전/후 일관성 최우선; "호빗식" 체형(넓은 어깨, 긴 팔다리, 짧은 몸통, 매우 가는 허리); 타이트한 무브랜드 어두운 색 의류; 양손 자연스럽게 펼침.
  3. Task-to-Action Decomposition: GPT-5.4 Thinking을 사용하여 상위 명령 G를 시간 순서대로 정렬된 행동 체인 C = {a₁, a₂, …, a_T}로 분해하며, 각 행동은 원자적이고 시각적으로 관찰 가능하며 물리적으로 실행 가능하다. 예시: "앞에 있는 갈색 상자를 집고 일어서세요" → 접근 → 구부리기 → 잡기 → 들어올리기 → 똑바로 서기.
  4. 프롬프트 템플릿: 구조화된 필드에는 Shot(10초 고정 정적 장면), Scene(첫 프레임 환경 완전 불변), Subject(타이트한 옷을 입은 남성), Task(행동 체인 실행), Motion(자연스럽고 연속적이며 물리적으로 실제적인), Execution(휴머노이드 로봇 스타일: 짧고 신중하며 부드럽고 의도적인), Consistency(스케일 드리프트, 원근 변형 없음), End State(안정적인 최종 자세)가 포함된다. A/S급 작업에는 manipulation 및 long-horizon execution 제약이 추가된다.

  5. 비디오 생성: 기성 API를 사용하며, 주로 Kling 3를 사용한다(소거 실험에서 Veo 3.1 및 Wan 2.6보다 우수).

  6. 모션 추정 단계

  7. 전신 모션: GENMO(확산 모델)는 모션 추정을 제약 생성 과정으로 공식화하며, 비디오 특징과 2D 키포인트를 조건으로 SMPL 파라미터 M = {q_t, p_t}_{t=1}^T를 출력한다.
  8. 손 모션: WiLoR가 프레임별로 양손 자세 H = {h_t^l, h_t^r}{t=1}^T를 추정하며, 각 손에 이산 상호작용 상태 S = {s_t^l, s_t^r}는 open, half-open, closed에 해당한다.}^T가 할당되고, s ∈ {0, 1, 2

  9. 상호작용 인식 모션 표현: M̃ = {q_t, p_t, h_t^l, h_t^r, s_t^l, s_t^r}_{t=1}^T.

  10. 모션 실행 단계

  11. SONIC을 모션 추적 컨트롤러로 사용하며, 현재 상태 s_t와 참조 모션 시간 창 q̂_{t:t+k}를 입력으로 받고 작업별 보상 엔지니어링이 필요 없다.
  12. 손 상태는 Unitree Dex3-1 호환 7-DoF 관절 목표로 매핑되며, 이벤트 큐를 통해 SMPL 신체 궤적과 함께 스트리밍된다.
  13. 현재 구현은 리타게팅(retargeting)이 필요 없다.

핵심 혁신

  1. 비디오 생성을 통합 상호작용 모델링 인터페이스로 사용: 비디오 생성을 "시각화 도구"가 아니라 로봇-환경-객체 3자 상호작용 역학을 모델링하는 핵심 표현으로 사용한다. 이는 전통적인 방법의 "작업별 보상 함수 설계" 또는 "작업별 데모 수집" 병목을 우회하여 대규모 비디오 생성 모델의 내재적 물리 상식을 상호작용 모델링 책임으로 활용한다.
  2. 로봇-인간 신체화 전이: 엄격한 프롬프트 제약(1:1 자세 복제, 전/후 일관성, 호빗식 체형)을 통해 로봇 관측을 인간형 도메인으로 매핑하여 인간 중심 비디오 생성 모델의 사전 지식을 차용한다. 이는 "도메인 적응"의 교묘한 조작이다. 현재 비디오 생성 모델이 본질적으로 인간 중심임을 인정하고, 대항하기보다 활용하는 것이다.
  3. 작업-행동 명시적 분해: 상위 명령을 시간 순서, 시각적 관찰 가능, 물리적 실행 가능한 행동 체인으로 분해하고, 초기 상태 정보(Gemini 3.1이 첫 프레임에서 추출)를 결합하여 공간 및 작업 인식 프롬프트를 구성한다. 이는 "상위 명령→픽셀 수준 비디오" 사이의 의미론적 간극을 해결하여 생성된 비디오가 작업 구조에서 해석 가능성을 갖게 한다.

경계 및 한계

저자가 명시적으로 인정한 경계는 다음과 같다: 비디오 생성에 객체 환각(예: 작은 우산이 더 큰 우산으로 환각됨), 부정확한 행동 시퀀스, 물리적으로 불합리한 종료 자세가 존재; 모션 추정은 폐색, 빠른 움직임, 후방 시점에서 신뢰성이 낮아짐; 손목 모션 추정은 수직 파지 장면에서 종종 수평 방향으로 예측되어 세밀한 회전이 시각적 단서에 의해 약하게 제약됨을 나타냄. 현재 프레임워크는 오프라인 파이프라인이며, 비디오 생성이 주요 병목(13.2초/초 비디오)이다. 생성된 비디오는 개루프 모션 참조를 제공하며, 로봇은 환경에 대한 명시적 인식이 없어 인식 노이즈와 동적 장애물에 대한 견고성이 제한적이다. 외부 감시 카메라에 의존하여 3인칭 관측을 제공하며, 1인칭에서 3인칭 비디오를 생성하는 모델은 개발되지 않았다. 스타일 전이는 추가 도메인 변화를 도입하여 생성된 모션과 실행 가능한 행동 간의 일관성을 약화시킬 수 있다. 더 세밀한 손/손가락 상태는 향후 작업으로 남겨둔다. 논문은 구체적인 성공률 수치, 정량적 오류 지표 또는 엔드투엔드 기준선과의 정량적 비교를 언급하지 않는다.

공학적 시사점

ExoActor를 재현할 때 가장 먼저 확인해야 할 것은 프롬프트 템플릿의 제약 강도이다. 신체화 전이에서 "전/후 일관성"과 "호빗식 체형"은 스타일 선호가 아니라 이후 모션 추정 신뢰성을 보장하는 핵심 설계이며, 어떤 이탈도 생성된 비디오의 인간 운동학과 로봇 실제 구성 간의 불일치를 초래한다. 가장 쉽게 함정에 빠지는 곳은 손목 모션 추정이다. 수직 파지 장면에서 모델이 종종 수평 손목 방향을 출력하므로, 하류 작업이 정밀 조작을 포함한다면 모션 추정 후 손목 방향에 대한 명시적 검증 또는 후처리가 필요하다. 또 다른 공학적 함정은 리타게팅이다. 리타게팅은 고주파 떨림을 줄일 수 있지만 공간 편향을 도입하므로, 정밀한 공간 정렬이 필요한 작업(예: 병을 바구니에 넣기)에는 오히려 해로우므로 기본적으로 비활성화를 권장한다. 지연 측면에서 비디오 생성(13.2초/초 비디오)과 손 모션 추정(16.4초/초 비디오)이 주요 병목이며, 실시간성이 필요하다면 병렬화 또는 다운샘플링이 필요하다. 마지막으로 S급 작업에서 저자는 때때로 목표 물체 아래에 작은 지지 베이스를 배치하여 높이 오차를 보정하는데, 이는 실행 단계의 높이 보정이 현재 프레임워크의 취약점임을 시사하므로 재현 시 높이 보상 메커니즘을预留해야 한다.
