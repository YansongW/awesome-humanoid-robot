요약

풍부한 접촉 역학을 가진 고충실도 물리 엔진, 휨로봇 제어 연구에 널리 사용.

출처

  • MuJoCo Physics Engine

개요

MuJoCo(Multi-Joint dynamics with Contact)는 "다관절 시스템 + 풍부한 접촉" 시나리오를 위해 설계된 고충실도 물리 엔진입니다: 일반화 좌표 동역학과 볼록 최적화 접촉 해법을 사용하여 CPU에서도 고정밀·고처리량으로 보행과 정밀 조작을 시뮬레이션할 수 있으며, 오랫동안 로봇 제어 및 강화 학습 연구의 사실상 표준 시뮬레이터로 자리 잡았습니다. 이 엔진은 Emo Todorov 팀(Roboti LLC)이 창립했으며, 2021년 10월 Google DeepMind에 인수되어 무료로 공개되었고, 2022년 5월 오픈소스로 전환되어 현재 DeepMind가 지속적으로 유지보수하고 있습니다(출처: MuJoCo 공식 문서 overview; GitHub README).

핵심 내용

무엇인가: 정확한 정의

MuJoCo는 C/C++ 물리 엔진 라이브러리(C API + 공식 Python 바인딩)로, MJCF(XML 형식)로 기술된 로봇 모델을 입력으로 받아 고정밀·재현 가능한 동역학 시뮬레이션을 출력합니다. 세 가지 식별 특징(출처: GitHub README; 공식 문서 overview):

  1. 접촉을 위해 설계됨: 접촉 동역학이 볼록 최적화 문제로 표현되어 접촉력이 매끄럽고 물리적 일관성이 우수합니다;
  2. 제어를 위해 설계됨: 일반화 좌표 + 사전 할당된 저수준 데이터 구조로 런타임 시 메모리 할당이 전혀 없어 제어/학습 루프에 자연스럽게 내장됩니다;
  3. 연구를 위해 설계됨: 모델, 상태, 도함수가 모두 API로 접근 가능하며, "정방향 동역학에 유일하게 정의된 역"이 있어 데이터 분석과 제어에 용이합니다.

왜 존재하는가: 문제점과 역사적 위치

2010년 전후의 로봇 시뮬레이션에는 어색한 공백이 있었습니다: 게임 엔진(ODE, Bullet 등)은 시각 효과에 최적화되어 접촉 해법에 근사와 떨림이 가득했고, 제어 알고리즘은 그 위에서 "학습"한 것이 물리 법칙이 아닌 시뮬레이터의 아티팩트인 경우가 많았습니다; 반면 동역학 라이브러리(각 연구실의 자체 코드 등)는 정확했지만 통일된 모델 형식과 사용 가능한 도구 체인이 없었습니다. Todorov, Erez, Tassa는 2012년 IROS에서 MuJoCo: A physics engine for model-based control을 발표하며 모델 기반 제어를 목표로 하는 엔진을 제안했습니다: 접촉은 볼록 최적화로 엄밀하게 해결하고, 동역학은 일반화 좌표에서 재귀적으로 계산하며, 모델은 통일된 XML로 기술합니다(출처: IROS 2012 논문; 프로젝트 Wiki 23장).

이것이 실제로 바꾼 것은 시뮬레이션 속도가 아니라 "시뮬레이션 결과를 신뢰할 수 있는지"에 대한 기본 기대였습니다——보행 제어 논문은 처음으로 투고 시 심사위원이 시뮬레이터의 접촉 역학을 인정할 것이라는 기본 전제를 가질 수 있게 되었습니다. 2021년 DeepMind가 인수하여 무료로 공개하고, 2022년 오픈소스화된 이후, 이 엔진은 "연구계의 고가 도구"에서 전 커뮤니티의 기반 시설로 변모했습니다(출처: 공식 문서 overview).

원리 분석

① 일반화 좌표 동역학과 ABA

MuJoCo는 관절 공간(일반화 좌표)에서 직접 다물체 동역학을 재귀적으로 계산하여 라그랑주 승수법의 대규모 희소 시스템을 피합니다; 정방향 동역학은 관절체 알고리즘(ABA)을 사용하여 질량 행렬을 명시적으로 구성하지 않고 O(n) 복잡도로 관절 가속도를 계산합니다——이것이 중소 규모 시스템에서 높은 처리량을 가능하게 하는 알고리즘적 기반입니다(출처: 프로젝트 Wiki 23장 §23.2, §23.3.1).

② 볼록 최적화 접촉 해법

접촉의 물리적 본질은 상보성 조건(비관통 + 쿨롱 마찰 원뿔)입니다. MuJoCo의 독특한 선택은 접촉을 볼록 최적화 문제로 모델링하는 것입니다: 소프트 접촉(contact softness)과 제약 조건 정규화를 허용하여 물리적 타당성을 보장하면서도 수치적 안정성과 미분 가능성의 잠재력을 얻습니다(출처: 프로젝트 Wiki 23장 §23.2). 기본 솔버는 Newton 방법이며, 타원 마찰 원뿔을 처리할 수 있는 Projected Gauss-Seidel(PGS)도 제공합니다; 제약 조건 솔버는 독립적인 "제약 섬(constraint islands)"을 자동으로 발견하고 정지된 섬을 휴면 상태로 전환하여 대규모 장면의 오버헤드를 크게 줄입니다(출처: 공식 문서 overview).

③ MJCF 모델 형식

MJCF는 MuJoCo의 네이티브 XML 형식입니다: "접촉 + 액추에이터 + 센서"를 위한 관절 강체 시스템을 대상으로 하며, 물리 파라미터(마찰, 감쇠, 액추에이터 이득, 소프트 접촉 파라미터)의 표현이 URDF보다 훨씬 완전하고, 각 형상 쌍에 대해 condim과 소프트 접촉 파라미터를 구성할 수 있어 볼록 접촉 솔버의 의미론과 정렬됩니다(출처: 프로젝트 Wiki 23장 §23.4.2).

④ 두 가지 GPU 경로: MJX와 MuJoCo Warp

원본 MuJoCo는 CPU 중심입니다; 대규모 병렬 처리는 두 백엔드가 담당합니다——MJX(JAX 기반)와 MuJoCo Warp(NVIDIA Warp 기반)로, 둘 다 동일한 MJCF 모델을 사용합니다(출처: 공식 문서 overview). 이는 "모델을 한 번 작성하면 CPU에서 접촉 정밀도를 조정하고 GPU에서 만 단위 병렬 학습을 실행하는" 워크플로우를 가능하게 합니다.

누가 사용하는가 / 적용 사례

  • DeepMind Control Suite(ent_paper_deepmind_control_suite_2018): MuJoCo 위에 구축된 고전적 연속 제어 벤치마크로, RL 논문의 실험 패러다임을 거의 정의했습니다;
  • HumanoidBench(ent_benchmark_humanoidbench): 휴머노이드 로봇 전신 작업 벤치마크로, MuJoCo를 물리 백엔드로 사용합니다;
  • MuJoCo Playground(ent_paper_202501_mujoco_playground_2025): MJX 기반 GPU 병렬 휴머노이드/사족 보행 훈련장으로, MuJoCo 모델을 대규모 RL에 직접 연결합니다;
  • 휴머노이드 제어 연구: 전신 제어 및 MPC의 알고리즘 검증, 중소 규모(수십~수백 병렬 환경) 정책 학습, 정밀한 접촉 동작이 필요한 조작 시뮬레이션은 Wiki 23장에서 요약한 전형적 용도입니다;
  • 학술 계보: Todorov 팀(워싱턴 대학교)이 창립했으며, 현재 Google DeepMind가 유지보수합니다(공식 overview).

한계와 경계

  • 렌더링 단순함: 네이티브 렌더링은 디버깅 시각화를 목표로 하며, 포토리얼리스틱 카메라 데이터는 Isaac 계열 또는 외부 렌더러가 필요합니다(출처: Wiki §23.3.1);
  • GPU 병렬 처리는 "별도의 제품 라인": MJX/Warp는 CPU 버전과 접촉 세부 사항에서 비트 단위로 동일하지 않으며, 백엔드 간 결론은 재검증이 필요합니다(엔지니어링 판단);
  • 소프트 바디/유체는 주력 분야가 아님: 변형 가능체, 유체 등의 통합 모델링은 Genesis와 같은 신흥 엔진의 목표 시나리오입니다(Wiki §23.3.6);
  • MJCF 학습 비용: 의미론이 URDF와 완전히 대응하지 않아 모델 마이그레이션 시 접촉 및 액추에이터 파라미터를 다시 보정해야 합니다;
  • 접촉 모델의 "소프트함"은 보정이 필요: 소프트 접촉 파라미터는 수치적 안정성을 개선하지만, 실제 접촉 강성과의 대응은 시스템 식별이 필요합니다(출처: Wiki §23.2 소프트 접촉 정의; 엔지니어링 판단).

흔한 오해

  1. "MuJoCo는 게임 엔진식 시뮬레이터다"——설계 목표는 모델 기반 제어 연구이며, 접촉 역학의 엄밀성이 시각적 표현보다 우선합니다.
  2. "MJX는 MuJoCo의 GPU 가속 스위치다"——MJX/Warp는 독립 백엔드로, 모델은 동일하지만 수치적 동작에 차이가 있어 결과가 상호 교환 가능하다고 직접 가정할 수 없습니다.
  3. "소프트 접촉 = 비현실적"——소프트 접촉은 정규화 수단이며, 물리적 일관성은 볼록 최적화 프레임워크가 보장합니다; 오히려 강성 LCP의 고주파 떨림이 아티팩트를 더 쉽게 생성합니다.
  4. "MJCF와 URDF는 같은 것이다"——MJCF는 액추에이터, 센서, 소프트 접촉 등 시뮬레이션 의미론을 담고 있으며, URDF는 구조 설명에 불과합니다; URDF를 MJCF처럼 사용하는 것은 sim-to-real 실패의 흔한 출발점입니다.
  5. "오픈소스 = 발전 중단"——정반대로, 3.x 시리즈는 여전히 높은 빈도로 업데이트되고 있으며(최신 3.11.0, 2026-07-27), MJX/Warp 이중 백엔드가 현재 발전의 주축입니다.
