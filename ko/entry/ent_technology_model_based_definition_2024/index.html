요약

기하학, 운 동학, 질량 특성, GD&T 및 주석을 단일 디지털 마스터 모델에 포함하는 CAD 중심 접근법.

출처

  • Model-Based Definition

개요

모델 기반 정의(Model-Based Definition, MBD)는 3D 디지털 모델을 유일한 권위 있는 데이터 소스로 사용하는 엔지니어링 방법으로, 기하학적 치수, 공차 표기(GD&T), 재료 속성, 운동학적 제약 및 제조 공정 정보를 CAD 모델에 직접 내장하여 기존 2D 엔지니어링 도면을 제품 정의 및 전달의 핵심 매개체로 대체합니다. MBD가 진정으로 바꾸는 것은 도면 작성 방식이 아니라, 제품 데이터가 "도면 중심"에서 "모델 중심"으로 권위가 이동하는 것이며, 설계, 시뮬레이션, 제조 및 품질 검사가 동일한 디지털 마스터 모델을 공유하게 합니다.

핵심 내용

무엇인가: 정확한 정의

모델 기반 정의(MBD)는 기술 유형에 속하며, 관련 분야는 설계 엔지니어링 및 제조 공정이며, 가치 사슬 계층은 중류와 상류를 포괄합니다. 핵심 아이디어는 기하학, 운동학, 질량 특성, GD&T 및 주석을 단일 디지털 마스터 모델에 내장하는 CAD 중심 방법입니다. 영어 명칭은 Model-Based Definition입니다.

전통적인 프로세스에서 3D 모델은 기하학적 표현에만 사용되었고, 치수 공차, 표면 거칠기, 열처리 요구 사항 등의 핵심 정보는 2D 도면에 분산되어 있어 모델과 도면 간의 수동 동기화가 필요했으며, 버전 드리프트가 쉽게 발생했습니다. MBD는 이를 완전히 바꿉니다—3D 모델 자체가 제품 정의의 유일한 법적 소스가 되며, 모든 하류 단계(공정 계획, 지그 설계, 검사 프로그래밍, 공급업체 협업)는 도면 변환에 의존하지 않고 모델 데이터를 직접 소비합니다.

원리 분해

① 단일 데이터 소스: 마스터 모델(Master Model) 아키텍처 MBD의 핵심 메커니즘은 모든 제품 정의 정보를 포함하는 CAD 파일인 "마스터 모델" 개념을 구축하는 것이며, 일반적으로 다음 계층으로 구성됩니다:

  • 기하학 계층: 솔리드/서피스 기하학으로, 모델의 기본 골격입니다.
  • 주석 계층: GD&T 주석(치수, 공차, 데이텀), 표면 거칠기, 용접 기호 등이 3D 주석 형태로 기하학적 피처에 직접 부착됩니다.
  • 속성 계층: 재료 등급, 열처리 상태, 질량 특성(질량, 질량 중심, 관성 모멘트) 등의 비기하학적 속성이 PMI(Product and Manufacturing Information) 형태로 저장됩니다.
  • 연관 계층: 기하학적 피처와 주석 간의 연관 관계로, 모델 수정 시 주석이 자동으로 업데이트되도록 보장합니다.

② PMI: 컴퓨터가 공차를 "이해"하게 하기 PMI는 MBD의 핵심 기술 요소입니다. 전통적인 도면의 공차 주석은 사람이 읽는 그래픽 기호인 반면, PMI는 공차 정보를 구조화된 데이터 형식(예: STEP AP242 표준)으로 모델에 내장하여 CAM 시스템이 공차 값을 직접 읽고 가공 매개변수를 최적화하며, CAQ 시스템이 자동으로 검사 계획을 생성할 수 있게 합니다. 이것이 MBD가 "3D 주석"과 다른 본질입니다—단순한 표시 방식의 변화가 아니라 데이터 의미론화의 도약입니다.

③ 디지털 스레드: 설계에서 제조까지의 원활한 전달 MBD 모델은 디지털 스레드의 매개체로서 제품 전 수명 주기를 관통합니다:

설계 모델(PMI 포함) → 공정 계획(공차 읽기→공정 수립) → 지그 설계(모델 기반 피팅) → NC 프로그래밍(기하학 직접 참조) → 온라인 검사(실측과 PMI 비교) → 품질 폐루프(설계에 피드백)

각 단계는 모델 데이터를 직접 소비하며, 수동 재입력이 필요 없어 데이터 변환 오류를 근본적으로 제거합니다.

핵심 매개변수 및 사양

MBD 구현과 관련된 핵심 매개변수 및 사양은 다음과 같습니다:

매개변수/사양 일반적 요구 사항 설명
데이터 형식 표준 STEP AP242, JT, 3D PDF 기하학 교환만이 아닌 PMI 의미론적 저장을 지원해야 함
주석 완전성 100% 핵심 특성 주석 기업 표준을 직접 확인해야 함
모델 정밀도 제조 정밀도와 일치 직접 확인 필요
PDM/PLM 통합 수준 버전 관리, 권한 제어, 승인 흐름 직접 확인 필요
하류 도구 호환성 CAM/CAQ/CAE 직접 읽기 직접 확인 필요

선정 핵심 사항: MBD는 단일 소프트웨어 기능이 아니라 기업 수준의 데이터 거버넌스 체계입니다. 핵심 결정 사항은 PMI 데이터 형식 표준 선택(STEP AP242가 현재 주류), 주석 규범 확정(ASME Y14.41 또는 ISO 16792 참조), PLM 시스템과 CAD 도구의 통합 깊이 계획입니다.

수평 비교

MBD vs 전통적 2D 도면

차원 전통적 2D 도면 MBD
데이터 권위 도면이 법적 근거 모델이 유일한 근거
정보 완전성 3D 정보를 투영으로 표현해야 하며 손실 쉬움 3D 주석이 공간 관계를 완전히 보존
하류 자동화 수동 도면 해독, 재모델링 필요 데이터가 CAM/CAQ를 직접 구동
변경 관리 모델과 도면 이중 동기화 단일 데이터 소스, 자동 연관
구현 장벽 낮음, 업계 성숙 높음, 프로세스와 표준 재구축 필요

MBD vs 경량화 모델(예: 3D PDF) 경량화 모델은 시각화 확인에만 사용되며, PMI 의미론적 데이터 구조가 없어 하류 시스템이 자동으로 해석할 수 없습니다. MBD 모델은 완전한 구조화된 제품 정의 정보를 포함하며, 제조 및 검사에 사용할 수 있는 "살아있는 데이터"입니다.

누가 사용하는가·적용 사례

MBD는 항공우주, 자동차, 중장비 등 분야에서 대규모로 적용되었으며, 휴머노이드 로봇 산업도 빠르게 따라가고 있습니다:

  • Tesla Optimus: 고도로 통합된 전기기계 제품으로, Optimus의 관절 모듈, 감속기, 구조 부품 설계 및 제조는 MBD가 지원하는 디지털 스레드에 크게 의존합니다. Gen 3 손은 11 DOF에서 22 DOF로 향상되었으며, 한 손에 25개의 액추에이터, 양손에 총 50개의 액추에이터(이웃 카드 자료 기준)를 탑재하고 있어, 이러한 고밀도 통합 설계는 MBD를 통한 공차 체인 분석과 조립 시뮬레이션에 반드시 의존해야 합니다.
  • 관절 모듈 공급업체: 하모닉 감속기, 행성 롤러 나사 등의 정밀 부품 제조는 MBD가 GD&T 정보를 CNC 가공 및 온라인 검사 시스템에 직접 전달하여 미크론 수준의 정밀도 요구 사항(구체적 수치는 직접 확인 필요)을 보장해야 합니다.
  • 연구 기관: 대학 휴머노이드 로봇 연구실은 MBD를 활용하여 빠른 설계 반복과 다분야 최적화를 구현하고 프로토타입 검증 주기를 단축합니다.

한계와 경계

  1. 구현 비용 높음: MBD는 기업 설계 프로세스, 표준 체계 및 인력 역량을 재구축해야 하며, 초기 투자가 크므로 중소 팀은 신중히 평가해야 합니다.
  2. 표준이 여전히 진화 중: PMI 데이터 교환 표준(예: STEP AP242)은 여전히 개선 중이며, 서로 다른 CAD 도구 간의 PMI 상호 운용성은 직접 확인해야 합니다.
  3. 공급망 협업 과제: MBD의 가치는 상하류 파트너가 공동으로 채택하는 데 의존하며, 공급업체가 여전히 도면으로 납품하면 디지털 스레드가 단절됩니다.
  4. 모든 시나리오에 적합하지 않음: 단순 부품이나 낮은 복잡도의 제품의 경우 MBD의 투자 대비 효과는 전통적 방식보다 낮을 수 있습니다.
  5. 법률 및 규정 문제: 일부 산업 규제는 여전히 종이 도면 보관을 요구하며, MBD의 규제 인정 여부는 직접 확인해야 합니다.

일반적인 오해

  1. "MBD는 3D 주석이다"—틀림. 3D 주석은 표시 계층일 뿐이며, MBD의 핵심은 PMI의 구조화된 데이터 의미론으로, 컴퓨터가 해석하고 하류 시스템을 구동할 수 있어야 합니다.
  2. "MBD를 도입하면 도면이 필요 없다"—완전히 맞지는 않음. MBD는 도면이 "법적 근거"로서의 지위를 대체하지만, 일부 상황(예: 현장 조립 지침, 공급업체 커뮤니케이션)에서는 여전히 도면 형태의 파생 뷰가 필요할 수 있습니다.
  3. "MBD는 CAD 소프트웨어의 기능이다"—틀림. MBD는 기업 수준의 데이터 거버넌스 체계로, 표준 수립, 프로세스 재구축, PLM 통합, 인력 교육을 포함하며, 소프트웨어는 도구일 뿐입니다.
  4. "MBD는 대기업에만 의미가 있다"—완전히 맞지는 않음. 휴머노이드 로봇 스타트업 팀의 경우 MBD는 초기 투자가 크지만 후기 데이터 재작업을 피할 수 있으며, 팀 규모에 따라权衡해야 합니다.
