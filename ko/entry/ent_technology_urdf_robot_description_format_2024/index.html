요약

시뮬레이션 및 제어를 위한 로봇 링크, 관절, 관성 및 기하를 설명하는 XML 기반 형식.

출처

  • URDF Robot Description Format

개요

URDF(Unified Robot Description Format)는 XML 기반의 로봇 설명 형식으로, 로봇의 링크, 관절, 관성, 기하학 및 운동학적 파라미터를 표준화된 방식으로 설명하는 데 사용됩니다. 그것이 진정으로 바꾼 것은 "그리기 방식"이 아니라 "로봇 모델의 교환 및 재사용 방식"입니다. 동일한 기계적 설명이 시뮬레이션, 제어, 내비게이션 및 시각화 등 서로 다른 소프트웨어 스택 간에 원활하게 흐를 수 있게 하여 ROS 생태계에서 로봇 모델링의 사실상 표준이 되었습니다.

핵심 내용

무엇인가: 정확한 정의

URDF는 XML 형식으로, 핵심은 <link>와 <joint> 두 가지 요소를 사용하여 로봇의 트리형 운동 체인을 설명하는 것입니다. <link>는 강체 속성(시각적 기하학, 충돌 기하학, 관성 텐서)을 정의하고, <joint>는 인접 링크 간의 운동 제약(관절 유형, 회전 축, 위치, 한계)을 정의합니다. 완전한 휴머노이드 로봇 URDF 파일은 본질적으로 기계 설계의 운동학적 트리(kinematic tree)를 기계가 읽을 수 있는 텍스트 형태로 고정시킨 것입니다.

일반적인 구조는 다음과 같습니다:

<robot name="humanoid">
  <link name="base_link">
    <inertial>
      <mass value="12.0"/>
      <inertia ixx="0.1" ixy="0.0" ixz="0.0"
               iyy="0.1" iyz="0.0" izz="0.08"/>
    </inertial>
    <visual>
      <geometry><mesh filename="base.dae"/></geometry>
    </visual>
  </link>
  <joint name="hip_pitch" type="revolute">
    <parent link="base_link"/>
    <child link="thigh"/>
    <origin xyz="0 0 -0.4" rpy="0 0 0"/>
    <axis xyz="0 1 0"/>
    <limit lower="-1.57" upper="1.57" effort="150" velocity="3.0"/>
  </joint>
</robot>

원리 분석

① 트리 구조: 운동학적 체인의 텍스트 매핑

URDF는 로봇 설명을 트리 구조(각 링크는 최대 하나의 부모 관절)로 강제하며, 이는 대부분의 로봇 운동학적 체인과 일치합니다. 각 <joint>는 <parent>와 <child>를 통해 링크 간의 부모-자식 관계를 설정하여 좌표 변환 체인을 암시적으로 정의합니다. 휴머노이드 로봇의 경우 일반적인 트리 루트는 골반(pelvis)이며, 다리, 몸통, 팔이 하위 트리로 연결됩니다.

② 관성 파라미터: 동역학 시뮬레이션의 기초

<inertial> 요소의 질량과 관성 텐서(<inertia>의 6개 독립 성분)는 동역학 시뮬레이션과 제어의 핵심 입력입니다. 관성 텐서의 정확성은 시뮬레이션에서 관절 토크 계산에 직접적인 영향을 미칩니다. 고관절을 예로 들면, 전신 무게를 지탱하고 대퇴부를 통해 지면 반력을 전달하므로, 관성 파라미터 오류는 시뮬레이션 관절 토크가 실제와 크게 편차가 나게 합니다(공학적 판단).

③ 관절 유형: 운동 제약의 인코딩

URDF는 6가지 관절 유형을 지원합니다: revolute(회전), continuous(무한 회전), prismatic(슬라이딩), fixed(고정), floating(6-DOF 자유), planar(평면 운동). 휴머노이드 로봇에서 고관절, 무릎, 발목은 일반적으로 revolute를 사용하고 한계를 설정합니다. 예를 들어 고관절의 3-DOF 직교 축계(roll/pitch/yaw)는 URDF에서 세 개의 revolute 관절 직렬 연결로 표현됩니다:

\[ T_{\text{hip}} = R_z(\theta_{\text{yaw}}) \cdot R_y(\theta_{\text{pitch}}) \cdot R_x(\theta_{\text{roll}}) \]

④ 기하학과 충돌: 시뮬레이션과 시각화의 이중 채널

<visual>과 <collision>은 각각 시각적 메시와 충돌 기하학을 정의합니다. 이 둘을 분리한 설계는 고정밀 CAD 모델을 표시용으로 사용하면서, 충돌 감지에는 단순화된 기하체(예: 박스, 구체)를 사용하여 시뮬레이션 계산량을 줄일 수 있게 합니다.

핵심 파라미터 및 사양

파라미터 설명 일반적인 값(휴머노이드 로봇)
<mass> 링크 질량 (kg) 고관절 링크 약 3–5 kg (공학적 판단)
<inertia> 관성 텐서 (kg·m²) CAD 또는 실측 교정 필요
<limit lower/upper> 관절 한계 (rad) 고관절 pitch 약 ±1.57 rad
<limit effort> 최대 관절 토크 (N·m) 고관절 약 150–300 N·m (공학적 판단)
<limit velocity> 최대 관절 속도 (rad/s) 약 3.0–6.0 rad/s
<origin xyz/rpy> 부모 링크 기준 관절 자세 기계 설계에 의해 결정
<axis xyz> 관절 회전 축 고관절 pitch는 [0,1,0]

URDF의 주요 한계는 폐쇄 운동 체인 미지원(예: 병렬 메커니즘)이며, 센서, 마찰, 구동기에 대한 표준화된 설명이 부족합니다. 휴머노이드 로봇과 같은 개방 체인 중심 시스템에는 URDF로 충분하지만, 병렬 발목 관절이나 다지성 손의 폐루프 구조가 포함되면 MJCF 또는 SDF를 고려해야 합니다.

누가 사용하는가·응용 사례

① 시뮬레이션 검증 (SiL/HiL): URDF는 SiL(Software-in-the-Loop) 시뮬레이션의 기본 입력입니다. 순수 소프트웨어 환경에서 제어 알고리즘을 검증할 때 URDF는 피제어 객체의 동역학 모델을 제공합니다. HiL(Hardware-in-the-Loop) 테스트에서도 URDF는 실시간 시뮬레이션 머신의 plant model 생성에 사용됩니다.

② 운동 계획 및 장애물 회피: MoveIt은 URDF를 직접 소비하여 충돌 장면과 운동학적 트리를 구축하고, 로봇 팔 또는 전신 운동 계획에 사용합니다. 휴머노이드 로봇의 파지, 보행 계획은 모두 URDF가 제공하는 기하학 및 운동학 정보에 의존합니다.

③ 시각화 및 디버깅: RViz는 URDF를 로드하여 3D 시각화를 구현하고, 엔지니어가 개발 단계에서 관절 운동, 센서 위치, 배선 경로를 직관적으로 확인할 수 있게 합니다.

④ 데이터 생성: 합성 데이터 파이프라인에서 URDF 기반 시뮬레이션 환경(예: Isaac Sim)은 강화 학습 및 VLA 모델 훈련을 위한 주석이 달린 훈련 데이터를 대량 생성할 수 있습니다.

한계와 경계

  1. 트리 구조 제한: URDF는 하나의 링크가 여러 부모 노드를 가지는 것을 허용하지 않아 병렬 메커니즘 또는 폐쇄 운동 체인을 직접 설명할 수 없습니다. 휴머노이드 로봇의 개방 체인 구조(두 다리+몸통+두 팔)에는 충분하지만, 다지성 손의 다중 손가락 폐루프는 다른 형식이 필요합니다.
  2. 센서 및 마찰 모델 부족: URDF는 센서(IMU, 힘 센서)의 표준화된 설명을 포함하지 않으며, 마찰, 감쇠 등 접촉 파라미터도 지원하지 않습니다. 이러한 것은 Gazebo의 <gazebo> 확장 또는 MJCF로 보완해야 합니다.
  3. 버전 관리 없음: URDF 파일 형식 자체에는 버전 정보가 포함되지 않아, 서로 다른 ROS 버전 간의 호환성은 직접 확인해야 합니다.
  4. 관성 파라미터 정확성: URDF의 관성 파라미터가 CAD 추정에서 직접 온 경우 실제와 편차가 있을 수 있습니다. 고동적 제어(예: 달리기, 점프)의 경우 시스템 식별을 통한 수정이 필요합니다(공학적 판단).

일반적인 오해

  1. "URDF는 3D 모델이다" — 틀림. URDF의 핵심은 운동학적 트리와 관성 파라미터이며, 3D 메시는 <visual>의 부수적 속성일 뿐입니다. 올바른 관절 정의와 관성 파라미터가 없으면 URDF는 동역학 시뮬레이션에 사용할 수 없습니다.
  2. "URDF는 모든 로봇 구조를 지원한다" — 틀림. URDF의 트리 구조는 병렬 메커니즘 또는 폐루프 체인을 설명할 수 없습니다. 이러한 구조에는 SDF 또는 MJCF를 사용해야 합니다.
  3. "URDF의 관성 파라미터는 중요하지 않다" — 틀림. 관성 텐서는 동역학 시뮬레이션의 관절 토크를 직접 결정합니다. 고관절을 예로 들면, 전신 무게를 지탱하므로 관성 파라미터 오류는 시뮬레이션 토크가 실제와 크게 편차가 나게 합니다.
  4. "URDF는 자동 생성될 수 있다" — 부분적으로 맞음. SolidWorks와 같은 CAD 도구가 URDF를 내보낼 수 있지만, 내보낸 파일은 일반적으로 관절 한계, 관성 파라미터, 충돌 기하학을 수동으로 수정해야 하며 시뮬레이션에 직접 사용할 수 없습니다.

관련 지식

  • ent_software_nvidia_isaac_sim_2024 — GPU 가속 시뮬레이터로, URDF를 직접 가져와 고충실도 환경을 구축하여 합성 데이터 생성 및 강화 학습 훈련에 사용할 수 있습니다.
  • ent_software_gazebo — 클래식 로봇 시뮬레이터로, URDF는 기본 지원 모델 형식이며 <gazebo> 확장을 통해 물리 속성을 보완합니다.
  • ent_technology_mjcf_simulation_format_2024 — MuJoCo의 MJCF 형식으로, URDF와 위치가 유사하지만 폐루프 체인과 더 풍부한 접촉 모델을 지원하며 상호 변환이 가능합니다.
  • ent_method_hardware_in_the_loop — HiL 테스트에서 URDF는 실시간 시뮬레이션 머신의 plant model 생성에 사용되어 실제 하드웨어에서 컨트롤러의 타이밍과 성능을 검증합니다.
  • ent_benchmark_humanoidbench — Unitree H1 기반 시뮬레이션 벤치마크로, 작업 환경은 URDF로 로봇 모델을 설명하며 VLA 및 제어 알고리즘의 통제된 비교에 사용됩니다.
  • ent_robot_unitree_h1_humanoid_robot_2024 — Unitree H1 휴머노이드 로봇으로, 그 URDF 모델은 커뮤니티에서 널리 사용되며 HumanoidBench와 같은 벤치마크의 기초입니다.

관련 개체

벤치마크

HumanoidBench

Unitree H1 로봇을 기반으로 한 전신 휨로봇 로코모션 및 조작 시뮬레이션 벤치마크로, VLA 및 제어 알고리즘의 통제된 비교를 위해 40개 이상의 작업을 제공함.

 기술

MJCF 시뮬레이션 형식

접촉, 액추에이터 및 센서가 있는 관절 강체 시스템을 위한 MuJoCo의 XML 모델링 형식.

 소프트웨어 플랫폼

NVIDIA Isaac Sim

GR00T 합성 데이터 파이프라인을 지원하는 GPU 가속 사실감 로봇 시뮬레이터.

 벤치마크

ManiSkill

일반화 가능한 조작 기술을 위한 통합 벤치마크로, 표준화된 과제·시뮬레이션 환경·평가 프로토콜을 제공.

 방법

하드웨어 인 더 루프(HIL)

실제 하드웨어 컨트롤러가 플랜트의 실시간 시뮬레이션과 상호작용하여 제어 소프트웨어를 안전하고 반복 가능하게 검증하는 방법.

 소프트웨어 플랫폼

Gazebo

물리 엔진·센서 모델·장면 작성을 제공하는 오픈소스 3D 로보틱스 시뮬레이터로, 알고리즘 개발·테스트에 사용.
