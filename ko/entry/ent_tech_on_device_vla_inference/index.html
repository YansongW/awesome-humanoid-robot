개요

온디바이스 VLA 추론(On-Device VLA Inference)은 비전-언어-행동 모델을 로봇에 내장된 엣지 컴퓨팅 장치에 직접 배포하는 것을 의미하며, 지연 시간, 연결성, 프라이버시 제약을 충족하기 위해 엣지 서버나 클라우드로 오프로드하지 않는다. 이것이 실제로 바꾸는 것은 모델 자체의 정확도가 아니라 로봇이 물리적 세계에 반응하는 속도의 상한선이다——제어 폐루프가 엔드투엔드 추론 지연 시간 20ms 미만을 요구할 때, 네트워크 왕복의 비용은 이미 수용할 수 없는 수준이다.

핵심 내용

무엇인가: 정확한 정의

온디바이스 VLA 추론은 배포 패러다임으로, 핵심 제약은 "추론이 로봇 본체에서 발생한다"는 점이다. 입력 데이터를 업로드하고 원격 컴퓨팅 파워에서 실행한 후 동작 명령을 다시 전송하는 클라우드 추론과 달리, 온디바이스 추론은 비전 인코더, 언어 인코더, 행동 디코더가 모두 로봇이 휴대하는 컴퓨팅 하드웨어에서 실행되어야 한다——대표적으로 NVIDIA Jetson 시리즈 임베디드 플랫폼이 있다.

시스템 아키텍처 관점에서 온디바이스 VLA 추론은 인식과 결정의 경계에 위치한다: egocentric 카메라 스트림의 시각적 관측, 로봇 상태(관절 각도, IMU 데이터), 자연어 명령을 수신하여 온보드 컴퓨팅 유닛에서 다중 모달 융합과 행동 생성을 완료하고, 출력은 직접 제어 법칙 계산 모듈로 전달된다. 이러한 위치는 실시간 운영체제(RTOS), 미들웨어 직렬화 계층, 액추에이터 드라이버와 긴밀하게 결합되어야 함을 결정한다.

원리 분석

① 지연 시간 예산의 분해: 온디바이스 추론의 물리적 기반

온디바이스 VLA 추론의 실현 가능성은 핵심 등식에 달려 있다: 엔드투엔드 지연 시간은 제어 폐루프의 주기 요구보다 작아야 한다. 50Hz 시각 폐루프를 예로 들면, 지연 시간 예산은 다음과 같이 분해된다:

\[ L_{\text{total}} = L_{\text{sensor}} + L_{\text{preprocess}} + L_{\text{inference}} + L_{\text{control}} + L_{\text{actuator}} \]

여기서 \(L_{\text{inference}}\)는 VLA 모델의 순방향 추론 시간이다. 자료에 따르면 50Hz 시각 폐루프는 엔드투엔드 추론 지연 시간이 20ms 미만이어야 한다. 추론을 클라우드에 두면 \(L_{\text{inference}}\) 자체는 5ms로 줄일 수 있지만, 네트워크 왕복 \(L_{\text{network}}\)가 추가로 20–100ms(링크 품질에 따라 다름)를 더하고 지터도 제어할 수 없다. 온디바이스 추론은 최고 컴퓨팅 파워를 희생하는 대신 지연 시간의 예측 가능성을 얻는다——이것이 하드 실시간 제어의 전제 조건이다.

② 배포 체인: PyTorch → ONNX → TensorRT

자료는 현재 NVIDIA Jetson 플랫폼에서 가장 주류인 배포 경로를 제시한다: PyTorch → ONNX → TensorRT. 훈련 단계에서 사용되는 PyTorch 모델은 동적 그래프 구조와 많은 연산자를 포함하여 임베디드 GPU에서 직접 실행하기에 적합하지 않다. ONNX 중간 표현으로 변환한 후, TensorRT는 대상 GPU 아키텍처에 맞춰 레이어 융합, 정밀도 보정, 커널 자동 튜닝을 수행하여 고도로 최적화된 추론 엔진을 생성한다.

양자화는 이 체인의 핵심 단계이다: FP32에서 FP16, INT8로 갈수록 각 단계에서 정밀도와 속도 사이의 균형을 맞춘다. 자료는 FP16이 일반적으로 지연 시간-전력-정밀도의 최적 균형점이며, INT8은 반드시 전체 검증이 선행되어야 한다고 강조한다——인식 오류가 직접 충돌이나 낙상으로 이어질 수 있기 때문이다.

③ 메모리와 스케줄링: 온디바이스 추론의 시스템 제약

온디바이스 하드웨어 리소스는 제한적이며, GPU 전역 메모리는 트랜잭션(transaction) 단위로 접근된다. 동일한 warp의 32개 스레드가 연속 주소에 접근하면 하드웨어가 여러 접근을 소수의 트랜잭션으로 병합하여 유효 대역폭을 크게 향상시킬 수 있다. 점유율(occupancy)은 각 SM에서 활성 warp 수와 최대 warp 수의 비율을 의미한다; 높은 점유율은 메모리 지연 시간을 숨기는 데 도움이 되지만, 너무 높으면 레지스터/공유 메모리 리소스 경쟁이 발생할 수 있다.

운영체제 수준에서 범용 Linux는 하드 실시간용으로 설계되지 않았다. PREEMPT_RT 패치는 커널의 대부분 코드를 선점 가능하게 하고 인터럽트도 스레드화하여 수십 마이크로초의 스케줄링 지연 시간을 제공하며, 로봇 메인 컨트롤러의 일반적인 선택이다. 온디바이스 VLA 추론 작업은 일반적으로 비실시간 Linux 사용자 공간에서 실행되지만, 그 출력은 실시간 커널 스케줄러를 통해 제어 작업으로 전달되어야 한다——두 세계 사이의 핸드오버 지연 시간도 지연 시간 예산의 일부이다.

온디바이스 추론, 엣지 서버 추론, 클라우드 추론은 세 가지 배포 옵션을 구성하며, 차이는 지연 시간, 대역폭, 프라이버시 세 가지 차원에 집중된다:

자료에 따르면 VLA-Perf 분석 프레임워크는 배포 관점에서 "추론이 어디에서 실행되어야 하는가——온디바이스, 엣지 서버, 클라우드"를 검토하고 하드웨어 성능과 네트워크 성능이 함께 엔드투엔드 지연 시간을 결정한다고 강조한다. 엔지니어링 판단: 휴머노이드 로봇의 균형 제어와 정밀 조작의 경우 온디바이스 추론이 하드 실시간 제약을 충족하는 유일한 옵션이다; 클라우드 추론은 모델 반복 검증과 교차 시나리오 일반화 평가에 더 적합하다.

누가 사용하는가: 적용 사례

NVIDIA Isaac GR00T N1.6은 온디바이스 VLA 추론의 대표적 사례이다. 이 모델은 multimodal vision-language-action 모델로, egocentric 카메라 스트림, 로봇 상태, 자연어 명령을 통합 정책 표현으로 통합하고, 세계 모델(예: NVIDIA Cosmos Reason)을 통해 고수준 명령을 장면 이해 기반의 단계별 행동 계획으로 분해한다. sim-to-real 파이프라인은 NVIDIA Isaac Lab에서 전신 강화 학습 훈련을 완료하고, 배포 시 Jetson 플랫폼을 기반으로 온디바이스 추론을 구현한다.

VLA-Perf 벤치마크 연구(arXiv:2602.18397)는 VLA 추론 성능의 전체 그림을 체계적으로 조사하여, 모델 설계 관점에서 모델 스케일링, 아키텍처 선택, 장문맥 비디오 입력, 비동기 추론, 이중 시스템 모델 파이프라인이 추론 성능에 미치는 영향을 분석하고, 배포 관점에서 온디바이스, 엣지, 클라우드의 실행 위치 선택을 분석한다. 이 연구는 15가지 핵심 결론을 도출하여 온디바이스 VLA 추론의 엔지니어링 실무에 정량적 근거를 제공한다.

한계와 경계

온디바이스 VLA 추론의 경계는 먼저 컴퓨팅 파워 천장에서 온다. 임베디드 GPU/NPU의 컴퓨팅 파워는 전력 및 방열 제약을 받아 최대 규모의 VLA 모델을 실행할 수 없다——자료는 전력 소비를 부작용이 아닌 제약으로 명시한다. 이는 모델 스케일링(model scaling)이 온디바이스에서 하드 상한선을 가지며, 이를 초과하면 모델 증류나 양자화 압축에 의존해야 함을 의미한다.

둘째, 온디바이스 추론은 모델 자체의 추론 효율성 문제를 해결하지 않는다. VLA 모델의 Transformer 스택 구조는 깊은 계층의 계산 중복을 초래하며, 조기 종료 메커니즘(예: DeeAD 프레임워크)과 적응형 프루닝(예: AutoPrune)은 상호 보완적인 최적화 수단이지만, 그 효과는 작업 복잡도 분포에 달려 있다——복잡도가 일정한 작업에서는 적응형 전략의 이점이 제한적이다.

마지막으로, 온디바이스 추론과 실시간 제어 사이의 인터페이스는 여전히 엔지니어링 난제이다. VLA 추론은 Linux 사용자 공간에서 실행되는 반면, 관절 제어는 하드 실시간 주기를 요구하며, 두 세계 사이의 데이터 핸드오버 지연 시간과 스케줄링 지터는 엔드투엔드 지연 시간에서 무시할 수 없는 구성 요소를 형성한다.

일반적인 오해

  1. "온디바이스 추론은 모델 압축이다"——틀림. 양자화와 증류는 온디바이스 배포의 가능 기술이지만, 온디바이스 추론의 본질은 배포 위치의 선택이다. 압축되지 않은 소형 모델이 온디바이스에서 실행되는 것도 온디바이스 추론이다; INT8 양자화된 대형 모델이 클라우드에 배포되면 클라우드 추론에 속한다.

  2. "온디바이스 추론 지연 시간이 반드시 클라우드보다 낮다"——반드시 그렇지 않음. 단일 추론의 경우 클라우드의 고급 GPU 컴퓨팅 파워가 \(L_{\text{inference}}\)를 온디바이스보다 훨씬 낮출 수 있다; 온디바이스의 장점은 네트워크 지연 시간 \(L_{\text{network}}\)와 지터를 제거하여 총 지연 시간을 예측 가능하게 만드는 것이다. 지연 시간에 민감하지 않은 작업(예: 오프라인 데이터 분석)에서는 클라우드 추론이 오히려 더 우수하다.

  3. "FP16 양자화는 정밀도 손실이 없다"——주의 필요. FP16은 FP32 대비 정밀도 손실이 일반적으로 수용 가능하지만, INT8 양자화는 상당한 오류를 도입할 수 있다. 자료는 INT8 전에 반드시 전체 검증이 필요하다고 강조하는데, 인식 오류가 직접 충돌이나 낙상으로 이어질 수 있기 때문이다.

  4. "온디바이스 추론은 운영체제를 고려할 필요가 없다"——틀림. 범용 Linux의 스케줄링 지연 시간은 수십에서 수백 마이크로초 사이에서 지터가 발생하여 가장 엄격한 루프의 결정성 요구를 충족할 수 없다. PREEMPT_RT 또는 듀얼 코어 실시간 아키텍처는 온디바이스 추론이 제어 폐루프에 진입하기 위한 전제 조건이다.
