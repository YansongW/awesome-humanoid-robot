HomeWorld: A Unified Floorplan-to-Furnished Framework for Generating Controllable, Densely Interactive Whole-Home Scenes

摘要

HomeWorld 是一个由研究团队提出的统一分层框架，用于生成可控且密集交互的全屋场景。其核心贡献包括：构建了包含 30 万真实住宅平面图的大规模数据集，并利用大语言模型实现细粒度平面图生成；结合图像生成模型与 VLM 优化器，实现从家具布局到小物体放置的完整室内场景合成，最终输出可直接用于具身 AI 模拟的 3D 场景。

概述

HomeWorld 是一个从自然语言提示生成可控、密集交互整屋场景的统一分层框架，由研究团队提出。其核心贡献在于将整屋生成分解为平面图合成、分层漫游布置、递归细化和可操作物体放置四个阶段，结合大规模真实平面图数据训练的 LLM 与显式 3D 锚定，解决了现有方法在全局连贯性、物理可行性和仿真就绪性上的不足。

它改变了什么

整屋场景生成长期被割裂为平面图合成、单房间布局、物体摆放等孤立子任务，导致生成的场景缺乏全局拓扑一致性和跨房间的语义连贯性。现有方法要么依赖手工规则（如 ProcTHOR）产生重复且有偏的布局，要么直接进行 3D 学习但受限于训练数据稀缺和计算成本，要么采用 2D 提升（如 Text2Room）但缺乏强 3D 先验锚定，在扩展到整屋时产生几何碎片化。HomeWorld 真正改变的是将"生成"重新定义为"可控的层次化实例化"过程：先用 LLM 在结构化表示上合成拓扑正确的平面图，再通过显式 3D 外壳约束下的 2D 修复逐步填充家具，最后用 VLM 递归校正物理违规。这一范式将数据稀缺的 3D 生成问题转化为数据相对充足的 2D 生成与 3D 验证问题，使得生成结果在拓扑有效性、物体密度和物理合理性上同时得到提升。

方法拆解

阶段 1：平面图生成（LLM + K-D 树）

  • 数据构建：从在线房地产仓库收集 108.4 万张平面图图像，用 2K 张手动标注图像训练检测模型识别门、窗、墙和尺寸链，检测框转中心线并合并邻近端点重建矢量化结构；OCR 提取房间标签和尺寸，经质量过滤后得到 31.4 万张验证平面图。
  • 表示设计：将平面图编码为二叉 K-D 树，内部节点存储分割轴和坐标，叶节点对应空间单元并分配房间语义；门、窗等附件在 JSON 中单独表示。相比直接预测多边形坐标，K-D 树输出空间更结构化，确定性避免多边形重叠和空洞。
  • 训练：使用 Qwen3-4B-Instruct，LoRA 监督微调，数据划分 281K/15K/15K。

阶段 2：分层漫游布置（2D 提升 + 3D 锚定）

  • 外壳实例化：在 Blender 中创建空的无家具外壳，带基本光照和材质，作为漫游的显式 3D 约束。
  • 全局布局（俯视图）：渲染俯视图，标注门、窗及门相邻房间，用图像修复模型（Gemini 3.0 Image Pro Preview）合成带家具俯视图，SAM-3 提取实例掩码和 2D 框，VLM 进行开放词汇类别识别。
  • 细节细化（自我中心视图）：基于热图的视点选择策略，将地板离散化为网格，贪心选择覆盖最少观测区域的视点；对每个视点渲染自我中心图像并修复合成次要物体，SAM-3D 重建 3D 几何，几何对齐模块集成到房间。
  • 漫游顺序：先俯视图放置大型功能家具（床、沙发），再自我中心视图逐步丰富小物品。

阶段 3：递归布局细化（VLM 顺序决策）

  • 将细化表述为顺序决策过程：VLM 细化器观察当前布局状态，预测结构化纠正动作（平移、旋转或组合变换），动作确定性应用于 3D 边界框，重新渲染检查，循环直到通过验证或达到迭代限制。
  • 微调数据构建：损坏布局构造（注入边界违规、碰撞、门道阻塞等扰动）、Oracle 标记修复动作（按残余误差、新引入违规、移动成本和语义合理性评分选真值）、模型在环样本（初始细化器滚动，中间状态由 oracle 重新标记）。

阶段 4：可操作物体放置

  • 根据语义类别和几何属性（水平表面存在性和足够可用面积）识别可支撑小物体的家具。
  • 为每个家具构建局部表面画布，用修复模型合成表面级排列。
  • 使用 PhysX-Anything 推断物理属性（密度、杨氏模量、泊松比），密度和网格体积估计质量。
  • VLM 将合成表面图像解析为可操作物体集合（语义类别、尺度、相对位置和方向），变换到全局坐标系。
  • 插入前进行轻量物理过滤：移除超出支撑边界、严重碰撞、漂浮或违反类别级支撑约束的物体，保留显式支撑关系。

关键创新

  1. K-D 树平面图表示：将平面图生成从自由多边形预测转化为结构化递归分割预测，从根本上消除了重叠、空洞和不连通等拓扑错误。这是对输出空间的重构而非简单约束，使得 LLM 生成在结构上天然合法，且可确定性转换回传统表示。
  2. 分层漫游（Hierarchical Roaming）：先俯视图全局布局再自我中心视图细节细化，配合显式 3D 外壳约束，解决了纯 2D 提升方法在整屋尺度上的几何不一致问题。这一设计将 2D 生成先验与 3D 锚定有效结合，避免了直接 3D 学习的数据瓶颈。
  3. VLM 递归细化器：将布局校正建模为顺序决策过程，通过损坏布局构造 + Oracle 标记 + 模型在环的三阶段数据构建，训练 VLM 输出可执行的 3D 边界框编辑动作。这使得细化过程可验证、可迭代，而非一次性生成。

边界与局限

论文未明确讨论局限性，但从事实要点可推断：外壳纹理生成采用简单策略（复用 3D-FRONT 资产或 2D 生成模型合成），未引入专用材质管线；光照采用规则生成而非学习式方法。未提及对生成场景的物理仿真验证结果、与真实世界场景的泛化性测试、生成时间/计算成本的具体数字、用户研究的详细统计结果。未提及 VLM 细化器的迭代限制具体数值、视点选择的具体参数（网格分辨率、视场角、安全距离）。未提及可操作物体数量的具体统计（除表 1 中 >15 外）。此外，LayoutGPT 仅支持 living room 和 bedroom，因此在 kitchen 和 bathroom 比较中未评估，可能影响基线对比的完整性。

工程启示

复现或采用 HomeWorld 时，优先核对以下环节：K-D 树表示的正确实现是平面图生成质量的基石，消融显示 canonical representation 会导致 9.2% 重叠、2.0% 空洞和 16.2% 不连通，而 K-D 树将不连通降至 12.3%，但仍非零，需关注叶节点语义分配的约束。VLM 细化器的数据构建是最易踩坑处——损坏布局注入的扰动类型和幅度直接影响 oracle 标记质量，建议严格按论文的边界违规、碰撞、门道阻塞、旋转、尺度、类别级错误六类扰动构造，并保留模型在环样本以覆盖中间状态。分层漫游的视点选择对最终物体密度影响显著（移除后 FOD 从 4.16 降至 2.6），热图覆盖策略的网格分辨率需根据房间尺度调参。可操作物体放置依赖 PhysX-Anything 的物理属性推断，建议先验证密度和网格体积估计的准确性，否则质量估计偏差会导致物理过滤误删。最后，数据集发布（300K 平面图 + 5K 场景）是复现的关键依赖，若无法获取，可先用 31.4 万验证平面图子集训练 LLM，但需注意分布差异。
