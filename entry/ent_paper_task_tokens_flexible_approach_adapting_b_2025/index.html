Task Tokens: A Flexible Approach to Adapting Behavior Foundation Models

Task Tokens: A Flexible Approach to Adapting Behavior Foundation Models

领域
AI 模型与算法
层级
智能层
审校
AI 全文核验

摘要

Task Tokens 是一种通过强化学习为行为基础模型（BFM）学习任务特定编码器的方法，由研究团队提出。其核心贡献在于在冻结原始 BFM 参数的前提下，通过新增的 token 输入引导模型适应具体任务，同时保留其多模态控制与泛化能力。

来源与参考

  • arXiv:2503.22886 Task Tokens: A Flexible Approach to Adapting Behavior Foundation Models
  • 智元、众擎都在卷的人形机器人运控基座：41篇论文看懂BFM

概述

本文提出 Task Tokens 方法，通过任务编码器将任务目标映射为 token 序列，以灵活适配行为基础模型（Behavior Foundation Models）。作者通过架构消融实验和人类偏好研究，验证了该方法在不同编码器规模、是否拼接当前位姿及是否使用关节条件化下的鲁棒性，并评估了生成动作的类人质量。核心贡献在于提供了一种轻量、模块化的任务适配机制，无需微调基础模型即可适应多种下游任务。

它改变了什么

行为基础模型（如机器人操作或运动生成模型）通常在大规模数据上预训练，但下游任务适配往往依赖全量微调或复杂的 prompt 设计，代价高昂且灵活性差。Task Tokens 改变了这一范式：它不修改基础模型权重，而是通过一个可学习的任务编码器将任务描述转换为紧凑的 token 序列，作为条件输入注入模型。这真正改变的是“适配成本”与“任务可扩展性”之间的权衡——下游团队不再需要为每个新任务重新训练或存储模型副本，只需训练一个轻量编码器（MLP 规模仅 [256,256] 或 [512,512,512]），即可在推理时动态切换任务。这种设计将任务适配从“模型级”降维到“输入级”，是行为模型工程化部署的关键一步。

方法拆解

任务编码器架构

  • 输入：任务目标（如方向、目标位置）与可选当前位姿（头部/骨盆位置）拼接。
  • 编码器：MLP，两种配置——[256,256]（默认）与 [512,512,512]（Bigger MLP）。
  • 输出：Task Tokens，作为条件 token 序列注入行为基础模型的 transformer 层。

关键设计决策

  • 关节条件化（Joint Conditioning, J.C.）：在 Direction、Steering、Reach 任务中，将关节状态与任务 token 一起输入。消融显示，J.C. 能显著提升性能稳定性，尤其在小编码器 + 无当前位姿组合下（Steering Success 从 84.28% 提升至 86.88%）。
  • 当前位姿拼接（Using Current Pose）：将 head/pelvis 位置与任务目标拼接。消融显示，该操作在无 J.C. 时反而降低性能（如 Bigger MLP=False 时从 84.28% 降至 66.31%），说明冗余的位姿信息可能干扰任务编码。
  • 编码器规模：[512,512,512] 在无 J.C. 时略优于 [256,256]（83.30% vs 84.28% 并不显著），但在有 J.C. 时两者几乎持平（87.58% vs 86.88%），表明任务编码器并非越大越好，J.C. 提供了更关键的条件信号。

人类研究协议

  • 每问题展示 3 个并排视频（随机采样序列），参与者选择最像人类的动作。
  • 算法顺序随机打乱，视频拍摄角度相似，Task Tokens 确保每次出现。
  • 胜率公式：winning percentage^A_env = (# Task Tokens chosen) / (# Task Tokens chosen + # Algorithm A chosen)。

关键创新

  1. 任务适配的“输入级”抽象：将任务编码为 token 序列而非修改模型权重，使得一个基础模型可同时服务多个任务，且任务切换成本趋近于零。这与 prompt tuning 类似，但针对行为序列生成做了专门设计（如与关节条件化结合）。
  2. 对冗余条件的鲁棒性分析：通过消融明确“当前位姿拼接”在无 J.C. 时是有害的（性能下降 18 个百分点），这为实践者提供了明确的输入设计准则——不要盲目堆叠条件特征。
  3. 人类偏好验证的严谨性：96 人参与、3 份表单、每问题随机打乱顺序，胜率计算排除了自身对比偏差，为“类人”质量提供了可复现的评估协议。

关键解读： - 使用 J.C. 时，除“小编码器 + 当前位姿”外，所有配置成功率均 >86%（由表内数值 5.71→0.79 计算），说明 J.C. 是性能稳定性的主要来源。 - 不使用 J.C. 时，“当前位姿拼接”显著有害（66.31% vs 84.28%），且方差增大（±13.11），表明冗余输入会引入噪声。 - 人类研究：96 人参与，每表单 40 题，Task Tokens 胜率未在事实要点中给出具体数值，但实验设计确保了其与各算法的对比公平性。

边界与局限

论文未明确提及以下局限： - 未报告 Task Tokens 在人类研究中的具体胜率数值，仅说明实验协议，无法量化其相对优势。 - 未涉及多任务同时推理时的 token 冲突或注意力干扰问题。 - 未测试编码器规模超过 [512,512,512] 时的性能上限，也未说明训练数据量与编码器收敛的关系。 - 消融仅在 Steering 任务上报告，Direction 和 Reach 任务的结果未给出，泛化性存疑。

工程启示

  • 优先启用 Joint Conditioning：消融数据强烈表明，J.C. 是性能稳定性的关键，复现时应默认开启，尤其在 Direction、Steering、Reach 类任务中。
  • 不要盲目拼接当前位姿：无 J.C. 时拼接 head/pelvis 位置会显著降低性能（66.31% vs 84.28%），建议先做消融再决定是否引入该特征。
  • 编码器规模选择：[256,256] 在有 J.C. 时与 [512,512,512] 几乎持平（86.88% vs 87.58%），优先选小模型以降低过拟合风险和推理开销。
  • 人类评估协议可复用：96 人、3 表单、随机打乱顺序的设计值得借鉴，但需注意视频采样随机性可能引入方差，建议固定随机种子并增加重复次数。
  • 最易踩坑点：当前位姿拼接在无 J.C. 时是“性能杀手”，若下游任务本身包含位姿信息，务必验证是否与任务 token 冗余。
