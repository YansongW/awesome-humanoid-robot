概述

VLA / WAM / AI 算法集成（AI & Perception）是人形机器人产品开发全流程中的第 12 个阶段，在 WBS V3 中展开为若干三级子任务。该阶段以感知栈（传感器选型与标定、SLAM 与场景理解、人体/物体检测与跟踪）为输入前端，以视觉-语言-动作模型（VLA）与世界模型（WAM）为决策核心，通过"输入梳理→方案设计→实施/原型→验证闭环→文档交付"的标准化工程动作，将算法能力固化为可量化、可追溯、可交付的产品模块。它真正改变的不是单个算法的精度，而是让 AI 能力从"实验室演示"变成"可验收的工程交付物"。

核心内容

是什么：准确定义

VLA / WAM / AI 算法集成（AI & Perception）是 WBS V3 中编号为 P12 的路线图工序节点，属于方法（method）类型，归属领域为 07_ai_models_algorithms，价值链层级为 intelligence。它不是一个单一算法，而是一组工程化流程的集合：将感知、决策、预测等 AI 能力按照统一的工序标准（P12.x.y.z 三级子任务）进行拆解、实施与验证。

该阶段的核心工作包包括三大块：感知栈（P12.1）、VLA 与操作策略（P12.2）、世界模型 / WAM 构建（P12.3）。每个工作包下再细分为若干三级子任务，每个子任务遵循相同的五步法：输入梳理与目标量化、候选方案建立与评估、实施/原型/样件制作、验证与问题闭环、文档输出与下游交付。

为什么存在：痛点与历史定位

在人形机器人产品化进程中，AI 算法长期面临一个结构性困境：研究阶段的"跑通"与产品阶段的"可交付"之间存在巨大鸿沟。研究论文只需报告平均精度或成功率，而产品开发要求每个模块有明确的输入输出接口、可量化的验收指标、可追溯的版本记录、可复现的测试流程。

P12 阶段的存在正是为了填平这道鸿沟。它将 AI 算法开发从"自由探索"纳入"工程流水线"：每个子任务必须有 Owner、时间节点、风险登记；每个方案必须形成不少于 2 个候选方案并量化打分；每个输出必须按模板编写文档并引用原始数据。这套工序的引入，使得 AI 模块能够与机械、电气、软件等其他子系统在同一节奏下协同迭代，而不是成为整个产品周期的"黑箱瓶颈"。

从历史定位看，P12 处于仿真验证（P7）之后、系统集成之前。它承接仿真平台验证过的算法原型，将其转化为可在真实硬件上运行的感知与决策模块，同时为下游的整机联调提供经过验证的算法输入。它真正改变的不是 AI 算法的理论边界，而是 AI 算法进入产品的方式——从"论文附属品"变为"工程资产"。

原理拆解

① 感知栈：从原始传感器数据到结构化环境理解

感知栈（P12.1）是 AI 算法集成的输入前端。其核心任务是将 RGB-D 相机、LiDAR、IMU、麦克风阵列、触觉阵列等异构传感器的原始数据，转化为机器人可理解的环境表征。这一过程涉及三个关键环节：

  • 传感器选型与标定（P12.1.1）：确定传感器组合方案，完成内参/外参标定，输出感知模块架构与精度指标。关键约束包括算力、延迟、光照鲁棒性、成本。
  • SLAM 与场景理解（P12.1.2）：解决"我在哪、周围有什么、如何到达目标"三个基本问题，涉及视觉/激光 SLAM、语义分割、3D 场景图等技术。
  • 人体/物体检测与跟踪（P12.1.3）：为人机交互、避障、操作提供感知输入，涉及 2D/3D 检测、多目标跟踪、人体姿态估计。

感知栈的输出质量直接决定上层决策的可靠性。以检测任务为例，其完成标准可量化为检测准确率、跟踪 ID 稳定性、延迟三项指标，其中延迟直接受算力约束——这构成了感知栈的工程边界。

② VLA 与操作策略：从语言指令到动作序列

VLA（Vision-Language-Action）模型是 P12.2 的核心。它将视觉观测与语言指令联合编码，直接输出动作序列。其数学本质是学习条件策略：

\[ \pi_{\theta}(a_t \mid o_t, l) = \arg\max_{a} \; \mathbb{E}_{p_{\theta}} \left[ \sum_{k=0}^{K} \gamma^k \, r(o_{t+k}, a_{t+k}) \right] \]

其中 \(o_t\) 为视觉观测，\(l\) 为语言指令，\(a_t\) 为动作输出。VLA 的关键在于跨模态对齐——视觉 token 与语言 token 需要在共享语义空间中建立对应关系，这通常通过大规模预训练实现。

③ 世界模型 / WAM 构建：预测动作后果

世界模型（WAM，World Action Model）是 P12.3 的核心，用于预测动作后果，支持长程规划与风险预判。其方法工具包括视频生成模型、动力学模型、神经辐射场、MPC 结合。关键约束是模型幻觉、计算开销、预测时域。

世界模型的数学表达可概括为状态转移预测：

\[ \hat{s}_{t+1} = f_{\phi}(s_t, a_t), \quad \hat{R} = \sum_{t=0}^{T} r(\hat{s}_t, a_t) \]

其中 \(f_{\phi}\) 为学习到的动力学模型，\(\hat{s}_{t+1}\) 为预测的下一状态。世界模型的价值在于：机器人可以在"想象"中推演多种行动方案的结果，从而在真实执行前规避高风险动作。

关键参数与规格

P12 阶段的关键参数与规格主要体现在各子任务的完成标准中：

子任务 方法/工具 关键约束 完成标准/输出物
传感器选型与标定（P12.1.1） RGB-D 相机、LiDAR、IMU、麦克风阵列、触觉阵列 算力、延迟、光照鲁棒性、成本 感知模块架构、标定结果、精度指标
SLAM 与场景理解（P12.1.2） 视觉/激光 SLAM、语义分割、3D 场景图 动态环境、计算资源、地图更新 定位精度、地图一致性、场景理解准确率

每个三级子任务（如 P12.1.1.1 输入梳理与目标量化）都要求：列出所有上游输入清单并确认版本、将验收标准转化为可量化 KPI、建立任务 Owner 与风险登记。这些动作确保每个模块的规格可追溯、可验证。

横向对比

P12 阶段与相邻工序节点存在明确的分工边界：

  • 与 P7（仿真平台搭建与验证）对比：P7 在虚拟环境中验证算法原理，P12 将算法部署到真实硬件或高保真原型上。P7 关注"算法在理想条件下是否有效"，P12 关注"算法在工程约束下是否可用"。
  • 与 P10（系统集成）对比：P12 完成单个 AI 模块的开发与验证，P10 将各模块组装为完整系统。P12 的输出是"经过验证的模块"，P10 的输入是"多个模块的协同"。
  • 与 P12.1.3（人体/物体检测与跟踪）对比：P12.1.3 是感知栈的子模块，专注于检测与跟踪；P12 整体则涵盖感知、决策、预测全链路。P12.1.3 的输出（检测准确率、跟踪 ID 稳定性）是 P12 整体验证的输入之一。

谁在用·应用案例

P12 阶段的应用主体是人形机器人产品开发团队中的 AI 算法组、感知组与系统集成组。典型应用场景包括：

  • 家庭服务机器人：通过 P12.1.1 完成 RGB-D 相机与麦克风阵列的选型标定，P12.1.3 实现人体检测与跟踪以支持跟随与交互，P12.3.1 构建世界模型以预测物体被碰倒的后果。
  • 工业巡检机器人：通过 P12.1.2 的 SLAM 与场景理解实现自主导航，P12.2 的 VLA 模型支持"检查 3 号阀门"这类语言指令直接映射为巡检动作序列。
  • 科研平台：高校实验室使用 P12 的工序框架，将扩散策略（Diffusion Policy）等新型算法纳入标准化的验证流程，确保算法改进可量化评估。

局限与边界

P12 阶段存在明确的边界与局限：

  1. 不解决算法创新问题：P12 是工程化流程，不是研究框架。它不负责提出新算法，只负责将已有算法转化为可交付的工程模块。算法本身的创新属于研究阶段的工作。
  2. 依赖上游输入质量：P12 的每个子任务都要求"列出所有上游输入清单并确认版本"。如果上游（如 P7 仿真验证）输出的算法原型存在缺陷，P12 的验证环节只能发现问题，无法从根源上修复。
  3. 验证深度受限于测试环境：P12 的验证环节（P12.x.x.4）依赖测试/评审计划与通过准则。在仿真环境与真实环境差距较大的情况下（如光照变化、动态遮挡），验证结论可能过度乐观。
  4. 文档交付成本高：每个子任务都要求"按模板编写文档并引用原始数据、完成内部评审与版本控制、发布并通知下游依赖方"。在快速迭代阶段，这套流程可能成为瓶颈。

常见误区

  1. "P12 就是写代码"——错。P12 的核心是工程化流程，代码实现只是其中一个环节（P12.x.x.3 实施/原型/样件制作）。输入梳理、方案评估、验证闭环、文档交付占据同等重要的地位。
  2. "完成标准就是算法跑通"——错。每个子任务的完成标准是"可量化的验收指标"，如检测准确率、跟踪 ID 稳定性、延迟。算法跑通只是起点，达到指标才是完成。
  3. "候选方案越多越好"——错。工序要求"形成不少于 2 个候选方案"，但更重要的是"建立评估矩阵并量化打分、组织评审并冻结方案"。方案数量服务于决策质量，而非堆砌选项。
  4. "验证通过就万事大吉"——错。验证环节要求"输出问题清单与改进措施"，问题闭环（跟踪至关闭）才是验证的终点。验证通过只是阶段性结论，问题清单的关闭才是真正的完成标志。
