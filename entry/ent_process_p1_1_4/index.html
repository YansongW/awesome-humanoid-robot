概述

人因工程与交互需求（P1.1.4）是需求定义与系统方案阶段（Concept / Pre-A）中的三级子任务，其核心使命是将"机器人与人共融场景的高度、视野、声音、动作必须可接受"这一模糊诉求，转化为可量化、可验证、可追溯的工程约束。它真正改变的不是交互界面的美观程度，而是"从直觉判断到数据驱动"的决策方式——通过人体测量数据库、可达域分析、惊吓反应实验与 HMI 原型四大工具，将人的生理极限与心理预期变成设计输入。

核心内容

是什么：准确定义

人因工程与交互需求（Human Factors Engineering and Interaction Requirements）是 P1 阶段需求工程工作包下的一个三级子任务，编号为 P1.1.4。它关注的是人形机器人在真实物理空间中与人类共处时，其几何尺寸、运动范围、感知输出（视觉/听觉）与行为模式是否处于人类可接受区间。

该子任务在 WBS V3 中展开为五个四级关键动作：P1.1.4.1 输入梳理与目标量化、P1.1.4.2 方案/方法设计、P1.1.4.3 实施/原型/样件制作、P1.1.4.4 验证与问题闭环、P1.1.4.5 文档输出与下游交付。每个动作都有明确的输入、方法、输出与验收标准，形成完整的闭环。

其完成标准/输出物包括三件套：人因需求报告（记录所有量化指标与依据）、关键交互姿态包络（定义机器人各关节在交互场景中的允许运动范围）、HMI 原则（指导后续界面与交互设计的基本规范）。

为什么存在：痛点与历史定位

在人形机器人早期开发中，人因工程往往被推迟到样机集成之后才考虑。后果是灾难性的：机械工程师按负载与速度选型电机，却忽略了机器人头部高度恰好位于儿童视线水平——摄像头与扬声器的位置让儿童感到压迫；软件工程师定义了丰富的语音交互，却未考虑在嘈杂环境中惊吓反应导致的误操作；工业设计追求科幻感，却让老年用户无法理解机器人的意图。

这些问题的共同根源是：人因约束没有被前置到需求阶段。等到发现时，修改机械结构意味着重新开模，修改交互逻辑意味着推翻软件架构，成本呈指数级上升。P1.1.4 的存在，就是要在概念阶段用数据回答"人能不能接受、愿不愿意接受、会不会害怕"这三个问题。

原理拆解

① 人体测量数据库：几何适配的统计学基础

人形机器人的高度、臂展、操作面高度必须覆盖目标用户群体的人体尺寸分布。人体测量数据库（如 GB 10000、NHANES）提供各百分位（P5、P50、P95）的静态尺寸数据。设计原则是：关键交互面（如触摸屏、取物口）应适配 P5 至 P95 区间，即身高较矮的用户能够触及，身高较高的用户不需过度弯腰。这一原则直接决定机器人躯干高度、手臂长度与关节行程的上下限。

② 可达域分析：运动学与安全边界的交集

可达域（Reachability Envelope）是机器人末端执行器在关节限位下能到达的空间集合。人因工程中的可达域分析，是将机器人的运动学可达域与人类的"舒适交互域"求交集：

\[ \mathcal{R}_{\text{interaction}} = \mathcal{R}_{\text{robot}} \cap \mathcal{R}_{\text{human, comfortable}} \]

其中 \(\mathcal{R}_{\text{robot}}\) 由关节角度限位 \(\theta_{\min} \le \theta_i \le \theta_{\max}\) 决定，\(\mathcal{R}_{\text{human, comfortable}}\) 是人类在自然站立/坐姿下无需过度伸展即可舒适操作的空间范围。交集之外的区域，要么机器人够不到，要么人类够着不舒服——两者都应在设计阶段被识别并消除。

③ 惊吓反应实验：心理安全的量化手段

惊吓反应（Startle Response）是人类对突发刺激（巨响、快速逼近的物体）的本能防御反应，表现为肌肉紧张、后退、心跳加速。在人与机器人共融场景中，机器人的突然启动、快速挥手、异常声响都可能触发惊吓反应，导致用户摔倒或误操作。惊吓反应实验通过受控条件下测量参与者的生理信号（心率、肌电）与行为反应（后退距离、躲避时间），确定安全运动速度阈值与最小接近距离。这些数据直接转化为机器人运动规划中的速度限制与安全距离参数。

④ HMI 原型：交互逻辑的快速验证载体

HMI（Human-Machine Interface）原型是将上述量化约束转化为可感知交互体验的载体。它可以是软件界面模拟、实体按键面板或带屏幕的简易机器人头部。HMI 原型的作用是在投入昂贵硬件之前，验证交互逻辑是否清晰、反馈是否及时、错误恢复是否自然。它让设计师和用户能够在低成本条件下"体验"最终产品，从而在概念阶段就发现交互流程中的断裂点。

谁在用·应用案例

案例一：社区药房辅助机器人（角色扮演与层级任务分析）

在社区药房辅助机器人开发中，研究者采用角色扮演方法——药剂师在受控环境中扮演机器人角色，通过即兴互动捕捉真实顾客需求与行为模式。随后用层级任务分析（HTA）将观察到的行为分解为层级任务结构，确保每个交互步骤（如问询、取药、用药指导）的建模准确性。这一方法直接服务于 P1.1.4 的"方案/方法设计"环节，将专家隐性知识系统化捕获，并映射到机器人控制代码。

案例二：社交机器人面部情绪表达（惊吓反应与接受度实验）

一项针对社交机器人面部情绪识别的研究显示，全动画投影面部（无论外观类人或机械）的情绪表达识别率与人类基线无显著差异；但当仅显示眼部区域时，所有条件的识别准确率均下降，且类人外观机器人（准确率约 65%）显著优于机械外观机器人（准确率约 52%）。这一发现直接指导 HMI 设计：如果机器人面部被部分遮挡（如戴帽子或处于暗光环境），类人外观能更好地维持情绪传达效果，从而降低用户的困惑与不安。

案例三：动态人格设计（长期交互的心理安全）

社交辅助机器人（SAR）在高度敏感环境中运行，对安全性和用户通信提出高要求。研究指出，现有研究多聚焦于不同通信模态（如语音、手势、表情），但缺乏长期研究来揭示用户通信需求随时间的变化。动态人格设计主张：初始阶段采用透明、外向的"相识"人格以建立初步信任，随后过渡到更温和、习惯化的人格以维持长期互动。这一思路直接回应 P1.1.4 中"心理安全"与"用户群体多样性"的关键约束——不同用户、不同阶段需要不同的交互风格。

局限与边界

P1.1.4 的边界在于：它定义的是需求与约束，而非具体实现方案。它告诉设计团队"机器人头部高度应在目标人群百分位范围内（示例区间 1400–1650mm，工程建议值，需按目标市场人体数据校核）"，但不规定"用哪种升降机构实现"；它要求"最大接近速度不超过 X m/s"，但不指定"用哪种传感器检测距离"。这些实现细节属于 P1.2 系统方案设计的范畴。

另一个边界是：人因工程数据具有文化与群体特异性。P5–P95 人体尺寸区间基于特定人群的统计数据，不同国家、不同年龄段、不同性别人群的分布差异显著。P1.1.4 的输出必须明确标注数据来源与适用人群，否则在跨市场部署时会产生适配偏差。此外，惊吓反应实验的结论受实验环境与参与者样本影响，外推到真实场景时需保留安全裕度（工程判断）。

常见误区

  1. "人因工程就是做外观设计"——错。外观只是 HMI 的一部分，人因工程的核心是量化约束：高度、速度、距离、响应时间，每一项都是可测试的工程参数，而非审美偏好。

  2. "有了人体测量数据库就够"——不够。数据库提供静态尺寸，但交互是动态过程：人的关节活动范围、反应时间、认知负荷同样关键。P1.1.4 需要结合可达域分析、惊吓反应实验和 HMI 原型验证，才能覆盖动态交互场景。

  3. "惊吓反应实验只针对儿童"——错。不同年龄段、不同文化背景的人群对突发刺激的反应阈值差异显著。实验设计必须覆盖目标用户群体的多样性，否则安全参数可能对某些群体过松或过紧。

  4. "HMI 原型验证可以推迟到样机阶段"——错。HMI 原型存在的意义就是在硬件投入之前发现交互逻辑缺陷。推迟验证意味着将问题留到成本最高的阶段去修复，违背了 P1 阶段"前置约束"的根本目的。
