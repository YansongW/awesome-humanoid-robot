摘要

MuJoCo的XML建模格式，用于描述具有接触、执行器和传感器的铰接刚体系统。

来源与参考

  • MJCF Simulation Format

概述

MJCF（MuJoCo Simulation Format）是 MuJoCo 物理引擎的原生建模格式，一种基于 XML 的语言，用于描述具有接触、执行器和传感器的铰接刚体系统。它真正改变的不是"如何描述机器人"，而是"如何让仿真建模像写网页一样可迭代"——通过类似 CSS 的默认值机制，让用户从最小模型起步、逐步细化，将建模从一次性工程变成交互式实验。

核心内容

是什么：准确定义

MJCF 是 MuJoCo 的原生模型格式，一种基于 XML 的语言，专门设计用于描述复杂动力学系统。它能够表达包含接触、执行器、传感器在内的多种模型元素，并通过内置编译器完成从模型描述到仿真数据结构的转换。

MJCF 的三个判别特征（来源：MuJoCo 官方文档 Modeling 章节）：

  1. 可扩展性优先：允许用户从小模型起步，逐步添加细节，而非一开始就构建完整系统；
  2. CSS 式默认值机制：受 HTML 中 Cascading Style Sheets（CSS）启发，通过默认值设置大幅减少重复描述；
  3. 编译期计算：内置编译器自动执行大量复杂的编译期计算，使 MJCF 介于建模格式与编程语言之间。

为什么存在：痛点与历史定位

在 MJCF 出现之前，机器人仿真建模面临一个核心矛盾：表达力与易用性不可兼得。通用物理引擎的建模格式要么过于底层（需要逐顶点描述几何），要么缺乏对关节、执行器、传感器等机器人学原语的一等支持。研究者被迫在"模型精度"与"建模效率"之间做痛苦权衡。

MJCF 的定位正是填补这一空档。它借鉴了 Web 开发的核心理念——渐进增强：用户可以先定义一个只有躯干和腿的简单模型，跑通控制算法，再逐步添加关节限位、接触摩擦、传感器噪声等细节。这种设计哲学让 MJCF 成为连接"快速原型验证"与"高保真仿真"的桥梁。

原理拆解

① XML 树形结构与编译管线

MJCF 模型本质是一棵 XML 树，根节点 <mujoco> 下包含 <worldbody>（世界坐标系与刚体树）、<actuator>（执行器定义）、<sensor>（传感器定义）等子节点。模型文件通过 MuJoCo 内置编译器（compiler）处理，生成高效的 C 数据结构 mjModel，供仿真器使用。

② 默认值机制：建模的"CSS"

MJCF 最精巧的设计是 <default> 节点——它允许用户为某类元素设定默认参数，子节点可继承或覆盖。例如：

<default>
    <joint type="hinge" damping="0.1"/>
    <geom friction="1.0" density="1000"/>
</default>

这段声明让所有后续定义的关节默认带 0.1 的阻尼、所有几何体默认摩擦系数 1.0、密度 1000。这大幅减少了重复描述，使模型文件保持简洁。

③ 编译期自动计算

MJCF 的编译器会自动执行多项计算，包括：惯性参数聚合（由几何体密度推导质量与惯量张量）、运动学树拓扑构建、接触对筛选等。这意味着用户无需手动计算连杆质心位置或转动惯量——只需定义几何形状与密度，编译器自动完成剩余工作。

关键参数与规格

MJCF 的核心规格参数（来源：MuJoCo 官方文档 Modeling 章节）：

参数/特性 说明
模型元素 刚体（body）、关节（joint）、几何体（geom）、执行器（actuator）、传感器（sensor）、接触对（pair）、肌腱（tendon）等
默认值机制 支持 <default> 节点，类 CSS 级联覆盖
编译期计算 自动推导惯性参数、运动学树、接触筛选
外部格式支持 可加载 URDF（通过 URDF extensions）、MJZ 压缩包、OpenUSD 模型
程序化建模 支持通过 mjSpec API 在 C/C++ 或 Python 中加载、编辑、编译、保存模型

横向对比

MJCF 与机器人领域其他主流描述格式的对比：

维度 MJCF URDF SDF
原生引擎 MuJoCo ROS Gazebo
默认值机制 有（CSS 式） 无 部分支持
接触参数描述 一等公民 需扩展 支持

MJCF 的核心优势在于为 MuJoCo 物理引擎量身定制——接触模型、执行器模型、传感器模型与引擎的求解器深度耦合，避免了格式转换中的信息丢失。URDF 的优势在于 ROS 生态的广泛采用，但表达力相对有限。

谁在用·应用案例

MJCF 已广泛应用于人形机器人的仿真建模与算法验证（来源：语料 chapter-08 中仿真平台列表）：

  1. Unitree H1：基于 MJCF 构建仿真模型，用于运动控制与强化学习训练（关联实体 ent_robot_unitree_h1_humanoid_robot_2024）；
  2. HumanoidBench：基于 Unitree H1 的全身运动与操作基准，提供 40 余项任务，依赖 MuJoCo/MJCF 作为底层仿真环境（关联实体 ent_benchmark_humanoidbench）；
  3. ManiSkill：面向可泛化操作技能的统一基准，使用 MuJoCo 作为物理引擎，MJCF 描述操作场景（关联实体 ent_benchmark_maniskill）；
  4. 学术研究：在强化学习、模型预测控制（MPC）、全身控制（WBC）等领域，MJCF 是构建数字孪生模型的标准选择。

局限与边界

MJCF 并非万能，其边界需要明确：

  1. 非通用编程语言：MJCF 不具备通用编程语言的表达能力，复杂逻辑需借助外部脚本或 mjSpec API 实现；
  2. 柔体支持有限：虽然 MuJoCo 支持一定程度的柔体（soft body），但 MJCF 对柔性材料的描述能力弱于专用有限元格式；
  3. 生态绑定：MJCF 是 MuJoCo 的原生格式，若需迁移到其他物理引擎（如 Bullet、PhysX），需转换为 URDF 或 SDF，可能丢失部分细节；
  4. 学习曲线：虽然默认值机制降低了入门门槛，但高级特性（如接触对筛选、编译期计算）需要深入理解 MuJoCo 内部机制。

常见误区

  1. "MJCF 就是 URDF 的另一种写法"——错。MJCF 的默认值机制、编译期计算、接触/执行器/传感器的一等支持远超 URDF 的表达能力；URDF 更偏向运动学描述，MJCF 则是为动力学仿真深度优化。

  2. "MJCF 只能用于 MuJoCo"——部分正确。虽然 MJCF 是 MuJoCo 原生格式，但通过转换工具可导出为 URDF/SDF 供其他引擎使用，只是会损失部分物理细节。

  3. "模型越详细越好"——工程判断：过度详细的模型（如每个螺栓都建模）会显著增加计算开销且未必提升仿真精度。MJCF 的设计哲学是"渐进增强"——从满足需求的最小模型起步，按需添加细节。

왜 존재하는가:痛点과 역사적 위치

MJCF가 등장하기 전, 로봇 시뮬레이션 모델링은 핵심 모순에 직면했습니다: 표현력과 사용 용이성은 동시에 얻을 수 없다. 범용 물리 엔진의 모델링 형식은 너무 저수준이거나(정점별로 지오메트리를 설명해야 함), 관절, 액추에이터, 센서와 같은 로봇 공학 프리미티브에 대한 일급 지원이 부족했습니다. 연구자들은 "모델 정밀도"와 "모델링 효율" 사이에서 고통스러운 절충을 강요받았습니다.

MJCF의 위치는 바로 이 공백을 메우는 것입니다. 웹 개발의 핵심 개념인 점진적 향상을 차용했습니다: 사용자는 먼저 몸통과 다리만 있는 간단한 모델을 정의하고 제어 알고리즘을 실행한 다음, 관절 제한, 접촉 마찰, 센서 노이즈 등의 세부 사항을 점진적으로 추가할 수 있습니다. 이러한 설계 철학은 MJCF를 "빠른 프로토타입 검증"과 "고충실도 시뮬레이션"을 연결하는 다리로 만듭니다.
