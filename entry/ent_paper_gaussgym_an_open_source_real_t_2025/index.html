GaussGym: An open-source real-to-sim framework for learning locomotion from pixels

摘要

GaussGym 是一个 2025 年开源的实到仿框架，由研究团队提出，用于从像素学习人形机器人运动。其核心贡献是将 3D Gaussian Splatting 作为可替换渲染器集成到 IsaacGym 等物理仿真器中，实现每秒超过 100,000 步的高通量仿真，同时保持高视觉保真度，并展示了在 sim-to-real 场景中的有效性。

来源与参考

  • GaussGym: An open-source real-to-sim framework for learning locomotion from pixels (arXiv)

概述

GaussGym 是一个开源的真实到仿真（real-to-sim）框架，将 3D Gaussian Splatting（3DGS）作为可替换渲染器集成进 IsaacGym 向量化物理仿真器，支持从 RGB 像素直接学习四足机器人运动与导航策略。其核心贡献在于将照片级真实渲染与高吞吐量物理仿真解耦，并引入运动模糊模拟与辅助重建损失，在单张 RTX 4090 上实现 4,096 个机器人、640×480 分辨率下超过 100,000 步/秒的训练吞吐量，且策略可零样本迁移至真实世界。

它改变了什么

现有 sim-to-real 框架在视觉信息处理上存在根本性矛盾：IsaacGym 等物理仿真器吞吐量高但渲染保真度低，无法利用语义线索（如人行横道、水坑）；而 LucidSim 等照片级真实渲染方案单环境仅 3 FPS，完全无法支撑大规模 RL 训练。GaussGym 真正改变的是打破了“物理仿真速度”与“视觉真实感”之间的零和博弈——通过将渲染频率与控制频率解耦（50Hz 控制、10Hz 相机更新），并利用 3DGS 的并行光栅化能力，首次让照片级真实渲染达到与纯物理仿真同量级的训练吞吐量。这使得视觉策略可以直接从 RGB 像素学习，而非依赖 LiDAR 或深度输入，从而解锁了依赖语义理解的任务类型（如识别楼梯、避开彩色惩罚区域）。

方法拆解

场景构建流水线

  • 数据源多样化：带位姿数据集（ARKitScenes、GrandTour）、智能手机扫描（内参标定）、生成式视频模型（Veo）输出的无位姿 RGB 序列，共 2,500 个场景。
  • 统一处理：所有数据先格式化为重力对齐参考系，用 VGGT 估计相机内参、外参、稠密点云和法线。
  • 网格生成：用 Neural Kernel Surface Reconstruction（NKSR）从 VGGT 输出生成高质量网格，用于碰撞检测与辅助重建损失。
  • 高斯初始化：3DGS 直接从 VGGT 点云初始化，避免从头优化，提升几何保真度与收敛速度。

渲染与仿真解耦

  • 渲染频率（10Hz）与控制频率（50Hz）分离，按相机真实帧率渲染而非控制频率，减少无效计算。
  • 多环境并行光栅化：使用多线程 PyTorch 内核进行批处理渲染，支持 4,096 个环境、128 个独特场景同时训练。

运动模糊模拟

  • 渲染一组沿相机速度方向偏移的小帧，按快门速度 alpha 混合成单张图像，模拟足部接触楼梯等剧烈运动时的真实模糊伪影，提升视觉保真度与迁移鲁棒性。

策略架构

  • LSTM 编码器融合本体感受（基座角速度、投影重力角、关节位置/速度、摆动相位）与 DinoV2 RGB 特征。
  • 双任务头：体素预测头（3D 转置卷积预测占据和地形高度）+ 策略头（LSTM 输出高斯动作分布）。
  • 非对称 actor-critic 框架，端到端单阶段学习，无 student-teacher 蒸馏。
  • 辅助重建损失由地面真值网格引导，显著加速学习。

奖励设计

  • 通用奖励：角速度惩罚（-0.2）、姿态偏差（-0.5）、动作速率（-1.0）、足距惩罚（-10.0）、足相位奖励（5.0）、绊倒惩罚（-3.0）。
  • 任务特定：速度跟踪（线速度 1.0、角速度 0.5）、目标跟踪（位置 10.0、偏航 10.0）。

关键创新

  1. 渲染-控制频率解耦：这是 GaussGym 吞吐量优势的关键。传统方案要么以控制频率渲染（浪费算力），要么完全离线渲染（无法交互）。GaussGym 按相机真实帧率（10Hz）渲染，配合 3DGS 并行光栅化，使照片级真实渲染首次达到 100,000 步/秒——比 LucidSim 快约 33,000 倍（由表内数值 100,000 与 3 计算），比 IsaacLab 向量化快 125 倍（由表内数值 100,000 与 800 计算）。
  2. 运动模糊模拟：现有 sim-to-real 框架普遍忽略动态模糊，导致策略在真实世界剧烈运动（如爬楼梯）时因视觉伪影失稳。GaussGym 通过沿速度方向 alpha 混合多帧，低成本地模拟了真实相机快门效应，这是提升迁移鲁棒性的关键细节。
  3. 辅助重建损失：利用 NKSR 生成的网格作为监督信号，让视觉编码器同时学习几何理解（体素预测）与运动控制，而非仅依赖任务奖励。消融显示移除该损失后，高楼梯场景成功率从 94.4 降至 80.8（A1），证明其对困难地形泛化至关重要。

关键结论： - 视觉策略在楼梯场景显著优于盲态（高楼梯 A1：94.4 vs 74.0），证明 RGB 信息对地形理解不可或缺。 - 体素预测头与 DINO 预训练特征均贡献显著，移除后高楼梯成功率分别下降 13.6（由表内数值 88.1→100.0 计算） 与 6.1（由表内数值 94.3→100.0 计算） 个百分点（A1）。 - 场景多样性至关重要：仅用 1/10 场景训练时，高楼梯成功率暴跌至 67.3（A1），说明大规模真实场景覆盖是泛化基础。

边界与局限

  • 视觉 sim-to-real 迁移仍是未完全解决的问题：策略未在训练中未见过的楼梯上评估，真实部署时足部放置精度下降。
  • 真实硬件引入物理延迟（如图像延迟）与自我中心观测依赖；基于几何的方法（400Hz 高程图+高频状态估计）可大幅简化运动问题，GaussGym 的优势主要体现在视觉语义理解任务。
  • 缺乏自动生成成本/奖励函数的机制：对于遵守社会规范（走人行道、人行横道）等任务，仍需手工设计成本项。
  • 所有资产以统一物理参数（如摩擦系数）初始化，无法仿真冰面、泥地、沙地等表面，割裂了“外观”与“触感”的关联。
  • 继承基础视觉模型局限：Veo 输出可能不一致需重新提示，文本控制相机能力有限；无法处理动态场景、流体和可变形资产。
  • 论文未明确训练步数、批量大小、多 GPU 扩展的具体加速比等工程细节。

工程启示

复现或采用 GaussGym 时，优先核对以下环节： 1. 场景数据质量：VGGT 估计的相机位姿与点云质量直接决定 3DGS 初始化与 NKSR 网格质量。若使用 Veo 生成视频，需验证输出一致性，必要时重新提示；GrandTour 等带位姿数据集可跳过 VGGT 位姿估计，降低误差累积。 2. 渲染-控制频率解耦：这是吞吐量优势的核心，但需确保相机更新频率（10Hz）与策略推理频率（50Hz）的接口正确——LSTM 需处理异步观测，否则会出现时间错配。 3. 运动模糊参数：快门速度与帧偏移量需根据实际相机型号标定，过强模糊会损害训练初期学习，过弱则迁移时鲁棒性不足。 4. 辅助重建损失的权重：论文未明确具体权重，建议从 0.1 起步并监控体素预测头与策略头的收敛平衡，权重过大可能干扰策略学习。 5. 场景多样性：消融显示 1/10 场景（约 250 个）时高楼梯成功率降至 67.3，建议至少使用 1/2 场景（约 1,250 个）以获得可接受的泛化；若计算资源有限，优先覆盖地形多样性而非数量。 6. 硬件配置：单张 RTX 4090 即可支撑 4,096 环境训练，但多 GPU 扩展需确保场景分配均匀，避免部分 GPU 因渲染负载不均成为瓶颈。
