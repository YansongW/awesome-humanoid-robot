概述

URDF/SDF 文件生成是人形机器人开发流程 P6 阶段（URDF 建模与运动学校核）的首个三级子任务，其核心工作是将 CAD 设计数据转化为可被仿真、控制与规划工具链正确解析的标准化机器人描述文件。它真正改变的不是"导出文件"这个动作本身，而是让"设计意图"与"算法可执行性"之间第一次建立起可量化、可追溯的工程桥梁。

核心内容

是什么：从 CAD 到可计算模型的工程翻译

URDF（Unified Robot Description Format）是 ROS 生态中描述机器人运动学与动力学属性的 XML 格式，通过 <link>（连杆）与 <joint>（关节）的树状结构定义机器人的拓扑连接关系、关节类型（revolute/prismatic/fixed）、运动学参数（原点、轴、极限）以及惯性属性。SDF（Simulation Description Format）则是 Gazebo 仿真环境原生支持的格式，在 URDF 基础上扩展了物理属性（摩擦系数、阻尼、材质）与传感器模型描述。

本工序节点 P6.1.1 的具体任务，是使用 ROS URDF、Xacro、SolidWorks/NX → URDF 插件、惯性参数校核等方法工具，完成从 CAD 模型到 URDF/SDF 文件的转换与验证。其设计思考逻辑要求：连杆、关节、惯性、碰撞体、视觉模型需与 CAD 完全一致；质量属性来自 P3.1.2/P3.1.3。关键约束包括坐标系一致性、单位统一、碰撞体不能太密。完成标准是可在 RViz/Gazebo/Isaac Sim 中正确加载、无解析错误。

为什么存在：仿真与实机之间的"翻译误差"痛点

人形机器人是典型的"高自由度、强耦合、多约束"系统。若直接将 CAD 模型导入仿真环境，会面临三个致命问题：第一，CAD 模型包含大量装饰性几何（圆角、螺纹、倒角），直接用于碰撞检测会导致计算量爆炸；第二，CAD 装配体中的坐标系定义往往基于设计便利，而非运动学约定（如 D-H 参数或 ROS REP 103 规定的右手定则），导致关节轴方向混乱；第三，CAD 软件导出的惯性参数（质量、质心、惯性张量）默认基于零件坐标系，而 URDF 要求基于连杆坐标系，且单位制可能不一致（kg·m² vs g·mm²）。

URDF/SDF 文件生成工序的存在，正是为了消除这三层"翻译误差"。它真正改变的不是"画一个机器人模型"这件事本身，而是让"设计意图"与"算法可执行性"之间第一次建立起可量化、可追溯的工程桥梁。没有这一步，后续的运动学验证、动力学仿真、控制算法开发都将建立在错误的模型之上，导致"仿真能跑、实机就炸"的经典工程灾难。

原理拆解

① 树状拓扑：URDF 的数学本质

URDF 采用树状结构描述机器人，每个 <joint> 连接一个父 <link> 与一个子 <link>。这种结构对应运动学中的传递链：

\[ T_{\text{child}}^{\text{parent}} = T_{\text{joint\_origin}} \cdot T_{\text{joint\_axis}}(\theta) \]

其中 \(T_{\text{joint\_origin}}\) 是关节坐标系在父连杆坐标系中的固定变换（由 <origin> 标签定义），\(T_{\text{joint\_axis}}(\theta)\) 是绕关节轴的旋转或沿关节轴的平移（由 <axis> 与 <limit> 标签定义）。整个机器人的正运动学就是沿树根到叶子的变换连乘。

② Xacro：宏编程消除重复

人形机器人左右对称，若手写 URDF，双腿、双臂的连杆定义会重复数百行。Xacro（XML Macros）通过 <xacro:macro> 定义可复用的连杆模板，配合参数化（如 leg_prefix、hip_yaw_offset）实现"一次定义、两处实例化"。这不仅是代码复用，更是工程一致性的保障——修改左腿的某个参数，右腿自动同步，避免"左右不对称"的隐性错误。

③ 惯性参数校核：动力学仿真的命门

URDF 中的 <inertial> 标签包含质量（mass）、质心位置（origin）与惯性张量（inertia 的 6 个独立分量）。SolidWorks/NX 的 URDF 插件会自动导出这些参数，但存在两个常见陷阱：一是单位制——CAD 软件默认使用 g·mm²，而 URDF 要求 kg·m²，换算系数为 \(10^{-9}\)；二是坐标系——插件导出的惯性张量基于连杆原点，但若 CAD 装配体的原点定义与运动学约定不一致，需要手动旋转惯性张量：

\[ I' = R \, I \, R^T \]

其中 \(R\) 是从 CAD 坐标系到 URDF 连杆坐标系的旋转矩阵。这一步若出错，动力学仿真的力矩输出将与实机严重偏离。

谁在用·应用案例

案例一：全尺寸双足人形机器人开发（本流程）

在 P6.1.1 工序中，团队从 P3.1.2/P3.1.3 获取质量属性数据，使用 SolidWorks URDF 插件导出初始模型，再通过 Xacro 重构左右对称的腿部连杆，最后在 RViz 中加载验证。关键动作包括：列出所有上游输入清单并确认版本、将验收标准转化为可量化 KPI、建立任务 Owner 与时间节点与风险登记。

案例二：开源人形机器人项目

许多开源项目（如 awesome-humanoid-robot 仓库中收录的项目）将 URDF 文件作为标准交付物，供全球开发者下载后在 Gazebo 中仿真或在 RViz 中可视化。这些项目通常同时提供 URDF 与 SDF 两种格式，以满足 ROS 与 Gazebo 不同版本的需求。

局限与边界

① URDF 的树状结构限制：URDF 不允许闭环结构（如并联机构或闭链运动学），若人形机器人包含平行连杆机构，需改用 SDF 或其它格式。工程判断：大多数双足人形机器人采用串联结构，此限制影响有限。

② 碰撞体简化与真实性的矛盾：碰撞体不能太密（否则计算量大），但过于简化会导致仿真中的碰撞检测失真（如手指抓取）。需在精度与性能间权衡，通常对末端执行器使用较精细的碰撞体，对躯干使用简化几何。

③ 惯性参数的静态假设：URDF 中的惯性参数是固定值，无法描述负载变化（如机器人手持重物）。对于动态负载场景，需在控制层进行在线补偿，而非修改 URDF。

常见误区

  1. "URDF 导出后就能直接用"——错。CAD 插件导出的 URDF 几乎必然需要手动调整：坐标系旋转、单位换算、碰撞体简化、关节极限校准。直接使用会导致仿真与实机严重偏离。

  2. "碰撞体越精细越好"——错。碰撞体不能太密，否则仿真计算量爆炸，实时性无法保证。正确做法是：视觉模型保留细节，碰撞体使用简化几何，仅在关键交互部位（如手爪）提高精度。

  3. "惯性参数不重要，反正仿真看不出来"——错。惯性参数直接决定动力学仿真的力矩输出，若质量属性错误，控制算法在仿真中调好的参数移植到实机必然失败。质量属性必须来自 P3.1.2/P3.1.3 的校核结果。

  4. "URDF 和 SDF 可以互相替代"——部分错。URDF 是 ROS 的标准格式，SDF 是 Gazebo 的原生格式。URDF 可通过 gz sdf 工具转换为 SDF，但 SDF 支持 URDF 不具备的特性（如闭链、传感器模型）。需根据目标仿真环境选择格式。
