ExoActor: Exocentric Video Generation as Generalizable Interactive Humanoid Control

ExoActor: Exocentric Video Generation as Generalizable Interactive Humanoid Control

领域

层级
智能层
审校

摘要

ExoActor 是一个利用大规模视频生成模型泛化能力的人形机器人控制框架。其核心创新在于将第三人称视频生成作为统一接口，隐式建模机器人、环境与物体间的交互动态，并通过运动估计与通用控制器将视频输出转化为可执行行为。该方法无需额外真实数据即可泛化至新场景，为交互丰富的人形行为建模提供了可扩展方案。

来源与参考

  • arXiv:2604.27711 ExoActor: Exocentric Video Generation as Generalizable Interactive Humanoid Control
  • Project page
  • GitHub仓库 Robotics_Notebooks

概述

ExoActor 提出一种三阶段流水线（视频生成→运动估计→运动执行），利用大规模视频生成模型的泛化能力，将第三人称视频生成作为建模人形机器人交互动态的统一接口，在 Unitree G1 上实现无需任务特定数据收集的交互式控制。核心贡献在于将机器人到人体的具身迁移与任务到动作的分解结合，使生成视频成为可执行行为的中间表示，并在 B/A/S 三级任务上验证了端到端可行性。

它改变了什么

人形机器人控制长期受困于一个根本矛盾：真实世界的交互行为需要联合建模空间上下文、时间动态和任务意图，而受控环境训练的策略一旦面对新场景就迅速失效。传统解法要么依赖昂贵的数据收集，要么需要领域特定调优，本质上都是在"补丁式"地扩展任务分布。ExoActor 真正改变的是问题框架——它不再试图让机器人直接学习"从状态到动作"的映射，而是把第三人称视频生成当作一个统一的交互建模接口，让视频生成模型内隐的世界知识和泛化能力来承担交互动态的建模负担。这意味着任务泛化的瓶颈从"机器人数据"转移到了"视频生成质量"，而后者恰恰是当前大规模生成模型已经具备的能力。另一个微妙但重要的改变是：它通过机器人到人体的具身迁移，把机器人观测映射到类人表示，从而能直接利用人类中心视频生成模型的先验——这本质上是在说，与其为机器人专门训练生成模型，不如把机器人"伪装"成人，借用人类动作的先验分布。

方法拆解

三阶段流水线

  1. 视频生成阶段
  2. Robot-to-Human Embodiment Transfer：使用 Nano Banana Pro (Gemini 3.1 Pro) 通过基于提示的图像编辑，将机器人观测转换为类人表示。关键约束包括：1:1 逐度精确复制空间姿态、朝向和运动学配置；前/后一致性为最高优先级；采用"霍比特人式"体型（肩宽、四肢修长、躯干短、腰线极细）；紧身深色无品牌服装；双手自然张开。
  3. Task-to-Action Decomposition：使用 GPT-5.4 Thinking 将高层指令 G 分解为时间有序动作链 C = {a₁, a₂, …, a_T}，每个动作原子、视觉可观察、物理可执行。示例："Pick up the brown box in front of you and stand up" → approach → bend down → grasp → lift → stand upright。
  4. 提示模板：结构化字段包括 Shot（10 秒固定静态镜头）、Scene（第一帧环境完全不变）、Subject（紧身衣男性）、Task（执行动作链）、Motion（自然、连续、物理真实）、Execution（类人形机器人风格：短促、谨慎、平滑、刻意）、Consistency（无尺度漂移、透视变形）、End State（稳定最终姿势）。A/S 级任务额外加入 manipulation 和 long-horizon execution 约束。

  5. 视频生成：采用现成 API，主要使用 Kling 3（消融中优于 Veo 3.1 和 Wan 2.6）。

  6. 运动估计阶段

  7. 全身运动：GENMO（扩散模型），将运动估计表述为约束生成过程，以视频特征和 2D 关键点为条件，输出 SMPL 参数 M = {q_t, p_t}_{t=1}^T。
  8. 手部运动：WiLoR 逐帧估计双手姿态 H = {h_t^l, h_t^r}{t=1}^T，每只手分配离散交互状态 S = {s_t^l, s_t^r} 对应 open、half-open、closed。}^T，s ∈ {0, 1, 2

  9. 交互感知运动表示：M̃ = {q_t, p_t, h_t^l, h_t^r, s_t^l, s_t^r}_{t=1}^T。

  10. 运动执行阶段

  11. 使用 SONIC 作为运动跟踪控制器，输入当前状态 s_t 和参考运动时间窗口 q̂_{t:t+k}，无需任务特定奖励工程。
  12. 手部状态映射到 Unitree Dex3-1 兼容的 7-DoF 关节目标，通过事件队列与 SMPL 身体轨迹一起流式传输。
  13. 当前实现不需要重定向（retargeting）。

关键创新

  1. 视频生成作为统一交互建模接口：不是把视频生成当作"可视化工具"，而是当作建模机器人-环境-物体三方交互动态的核心表示。这绕过了传统方法中"为每个任务设计奖励函数"或"收集任务特定演示"的瓶颈，让大规模视频生成模型的内隐物理常识承担交互建模责任。
  2. 机器人到人体的具身迁移：通过严格的提示约束（1:1 姿态复制、前/后一致性、霍比特人式体型）将机器人观测映射到类人域，从而借用人类中心视频生成模型的先验。这是一个"域适配"的巧妙操作——它承认了当前视频生成模型本质上是人类中心的，与其对抗不如利用。
  3. 任务到动作的显式分解：将高层指令分解为时间有序、视觉可观察、物理可执行的动作链，再结合初始状态信息（由 Gemini 3.1 从第一帧提取）构建空间与任务感知的提示。这解决了"高层指令→像素级视频"之间的语义鸿沟，使生成视频具有任务结构上的可解释性。

实验与结果

消融维度 对比方法 结果 决策
视频生成模型 Veo 3.1, Kling 3, Wan 2.6 Kling 3 生成更连贯和物理合理的运动，视觉伪影更少 采用 Kling 3
重定向 GMR, OmniRetarget 重定向减少高频抖动但引入空间偏差 不采用重定向
视角 背对前视角 vs 正面视角 导航任务背对前视角成功率更高；操作任务正面视角更有效 任务相关
运动估计 CRISP vs GENMO GENMO 质量与 CRISP 相当但更高效稳定 采用 GENMO

延迟分析（Table 1）： | 阶段 | 延迟 | |------|------| | Robot-to-Human Embodiment Transfer | 10.7 秒/request | | Task-to-Action Decomposition | 2.5 秒/request | | Video Generation | 13.2 秒/秒视频 | | Whole-body Motion Estimation | 2.9 秒/秒视频 | | Hand Motion Estimation | 16.4 秒/秒视频 |

任务分级：Level B（基本运动+导航）、Level A（导航+粗略交互）、Level S（精细多步操作）。手部姿态以原始视频帧率估计（24 FPS 视频产生 24 Hz 序列）。

边界与局限

作者明确承认的边界包括：视频生成存在物体幻觉（如小伞被幻觉成更大的伞）、不正确动作序列、物理不合理结束姿态；运动估计在遮挡、快速运动、后视角下可靠性降低；手腕运动估计在垂直抓取场景中常预测为水平方向，表明细粒度旋转受视觉线索约束弱。当前框架为离线流水线，视频生成是主要瓶颈（13.2 秒/秒视频）；生成视频提供开环运动参考，机器人对环境无显式感知，对感知噪声和动态障碍物鲁棒性有限。依赖外部监控摄像头提供第三人称观测，未开发从第一人称生成第三人称视频的模型。风格迁移引入额外域变化，可能削弱生成运动与可执行行为的一致性。更细粒度的手/手指状态留待未来工作。论文未提及具体成功率数字、定量误差指标或与端到端基线的定量对比。

工程启示

复现 ExoActor 时，最值得先核对的是提示模板的约束强度——具身迁移中"前/后一致性"和"霍比特人式体型"不是风格偏好，而是保证后续运动估计可靠性的关键设计，任何偏离都会导致生成视频中的人体运动学与机器人实际构型不匹配。最容易踩坑的地方在于手腕运动估计：垂直抓取场景中模型常输出水平手腕方向，这意味着如果下游任务涉及精细操作，需要在运动估计后加入手腕朝向的显式校验或后处理。另一个工程陷阱是重定向——虽然重定向能减少高频抖动，但会引入空间偏差，对于需要精确空间对齐的任务（如将瓶子放入篮子）反而有害，建议默认关闭。延迟方面，视频生成（13.2 秒/秒视频）和手部运动估计（16.4 秒/秒视频）是主要瓶颈，如果追求实时性需要并行化或降采样。最后，S 级任务中作者有时需在目标物品下放置小型支撑底座补偿高度误差，这提示执行阶段的高度校准是当前框架的薄弱环节，复现时应预留高度补偿机制。
