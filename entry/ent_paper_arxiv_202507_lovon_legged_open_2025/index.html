摘要

arXiv 2025.07, LOVON: Legged Open-Vocabulary Object Navigator is a 2025 work on navigation for humanoid robots.

来源与参考

  • arXiv 2025.07, LOVON: Legged Open-Vocabulary Object Navigator project page

概述

LOVON 是一个面向四足与人形机器人的开放词汇物体导航框架，由作者团队提出，核心是将大语言模型的分层任务规划与开放词汇视觉检测集成，并引入拉普拉斯方差滤波应对视觉抖动。其关键贡献在于以 1.5 小时训练时间达到与 TrackVLA 相当的仿真成功率，同时支持三种 Unitree 平台即插即用。

它改变了什么

这个工作的真正改变在于把“开放词汇检测”和“高层任务规划”从松耦合的流水线变成了一个可训练、可部署的紧耦合系统。过去这类长时程导航要么依赖预定义物体类别，要么靠人工编写状态机来衔接感知与规划，导致系统在开放世界里遇到新物体或临时目标丢失时就会断链。LOVON 用 LLM 做规划器，让分解出的子任务直接以自然语言形式喂给检测模型，等于把“找什么”和“怎么找”统一到了同一个语义空间里，这比传统做法更接近人类处理未知环境的逻辑。

另一个值得注意的变化是它对“视觉抖动”和“盲区”这类真实世界问题的处理态度。多数导航论文在仿真里回避这些问题，但 LOVON 明确把运动模糊和临时目标丢失当作一等公民来处理，用拉普拉斯方差滤波在检测前做视觉稳定。这看起来是个小改动，实际上决定了系统能不能从仿真走到真实机器人上——很多系统死在仿真到现实的这一步，就是因为没处理这类低层次但致命的视觉噪声。

方法拆解

系统流程

  1. LLM 任务规划器接收高层指令（如“跑到背包，然后以 0.5 m/s 到椅子，然后快速接近人”），将其分解为有序的基本导航指令，并具备自适应重规划能力——当检测失败或目标丢失时，LLM 可基于当前状态重新生成子任务。
  2. 拉普拉斯方差滤波作用于机器人相机流，在每帧送入检测模型前计算图像拉普拉斯算子的方差，低于阈值的模糊帧被丢弃或加权，从而抑制动态运动带来的视觉抖动。
  3. 开放词汇检测模型接收滤波后的视频帧与 LLM 输出的自然语言目标描述，输出目标物体的边界框与类别置信度，无需预定义类别集合。
  4. 语言到运动模型（Language-to-Motion Model）将检测结果与 LLM 的子任务指令映射为底层控制向量，直接驱动机器人关节。

关键设计决策

  • 分层而非端到端：LLM 只做任务分解，不直接输出控制信号，避免了大模型推理延迟对实时控制的影响；运动控制交给轻量模型，保证响应速度。
  • 滤波前置而非后置：视觉稳定放在检测之前，而不是在检测结果上做时间平滑，因为运动模糊会直接破坏检测特征，后置平滑无法恢复丢失的目标。
  • 多形态适配：框架本体与机器人型号解耦，通过调整语言到运动模型的输出维度适配 Go2、B2、H1-2，训练时间仅需 1.5 小时，模型体积紧凑（具体参数数量论文未明确）。

关键创新

  1. LLM 规划与开放词汇检测的紧耦合：这不是简单的“LLM 输出文本，检测器吃文本”的串联。LOVON 让 LLM 的规划结果直接决定检测器的注意力焦点，同时检测失败会触发 LLM 重规划，形成闭环。这种双向交互在之前的导航框架里很少见，它让系统在目标丢失时不是盲目重试，而是重新理解任务上下文。

  2. 拉普拉斯方差滤波作为导航专用视觉预处理：这个技术本身不新，但把它用在四足/人形机器人的导航感知链路上是少见的。四足机器人的步态天然带来周期性抖动，人形机器人更甚，而大多数导航系统假设相机是稳定的。这个滤波让开放词汇检测在剧烈运动下依然可用，是系统能上真实机器人的关键前提。

  3. 极低训练成本的多形态迁移：1.5 小时训练时间对比 TrackVLA 的 360 小时，差了 240 倍（由表内数值 360→1.5 计算）。这意味着 LOVON 的架构设计让跨形态迁移变得几乎免费——不是靠大规模预训练，而是靠模块解耦和轻量适配层。这对资源有限的机器人团队是实质性的门槛降低。

实验与结果

实验分仿真与真实世界两部分。仿真中 LOVON 在大多数环境达到 SR 1.00，与 SOTA 的 TrackVLA 持平，优于 EVT。真实世界实验覆盖 3 种平台（Go2、B2、H1-2）和 14 个演示场景，包括室内办公室、实验室、螺旋楼梯，以及室外停车场、野草地带等非结构化环境。

关键数字的含义：SR 1.00 说明在仿真层面 LOVON 没有牺牲任务完成率来换取训练效率；而训练时间 240 倍（由表内数值 360→1.5 计算）的差距意味着这个框架的实用门槛远低于现有 SOTA。真实世界演示中特别值得注意的是“伞遮挡视野后恢复目标跟踪”和“跟踪野草中移动的人”这两个场景——前者验证了临时目标丢失后的重规划能力，后者验证了动态目标跟踪与安全距离保持，这些都是仿真里难以覆盖的。

需要说明的是，论文原文不可得，上述实验细节来自项目页/公开资料，具体仿真环境数量、成功率方差、真实世界实验的量化指标（如成功率、平均任务时长）论文未明确。

边界与局限

论文未明确列出局限性章节，但根据公开资料可以推断几个边界。第一，真实世界实验以演示为主，没有给出系统性的量化评估（如成功率、失败率、平均完成时间），这意味着“即插即用”的宣称缺乏统计支撑。第二，拉普拉斯方差滤波对光照突变和传感器噪声的鲁棒性未讨论，在强光或低光环境下该滤波可能误判。第三，LLM 规划器的推理延迟未报告，在需要高频响应的动态场景中，大模型的重规划可能成为瓶颈。第四，多形态适配虽然训练时间短，但未说明是否需要针对每个平台单独采集数据，以及数据量要求。第五，所有实验基于 Unitree 平台，框架对其它品牌机器人的可迁移性论文未明确。

工程启示

对想复现或采用这个框架的团队，我的建议是先核对三件事。第一，确认你的机器人视觉链路是否支持在检测前插入滤波模块——很多机器人系统把相机数据直接喂给感知模型，中间没有可插拔的图像处理节点，这需要改代码架构。第二，LLM 规划器的延迟指标必须实测，如果你的任务需要亚秒级重规划响应，当前 LLM API 的延迟可能不达标，需要考虑本地部署小模型。第三，跨形态迁移的“1.5 小时”很可能是在特定数据分布下测得的，换到你的场景（比如室内仓库 vs 野外草地）可能需要重新微调语言到运动模型，不要假设零成本迁移。

最容易踩的坑是拉普拉斯方差滤波的阈值选择——阈值太高会丢掉有效帧导致检测频率下降，阈值太低则无法抑制抖动。建议在目标平台上录制一段包含静止、慢走、快跑三种状态的视频，离线标定阈值后再上线。另外，真实世界演示中“伞遮挡视野后恢复”这个能力依赖 LLM 的重规划逻辑，你需要确认你的 LLM 提示词里是否包含了“目标丢失时如何重新理解任务”的指令，否则系统可能只是原地打转。最后，仿真 SR 1.00 这个数字不要过度解读——它是在特定环境集上测得的，你的环境分布不同，成功率大概率会下降。
