摘要

Upkie 是社区驱动的全开源轮足双足机器人（wheeled biped），约 3,000 美元现成组件加 60 小时以上 3D 打印即可复现，采用 mjbots qdd100 准直驱执行器与树莓派 4 主控，Python 优先的软件栈开箱自带 PID、MPC、强化学习三种平衡控制示例，是个人在真实硬件上学习平衡控制的低门槛路径。

概述

Upkie 是社区驱动的全开源轮足双足机器人（wheeled biped），核心作者为 Stéphane Caron（Inria）等，建立在 mjbots 开源执行器生态之上，含 Upkie Zero / Upkie Standard / 2026 硬件 v2 等构型。整机约 3,000 美元现成组件 + 60 小时以上 3D 打印即可复现（官方 Hackaday 口径），6 个自由度（每腿 3：髋、膝、驱动轮）；身高/重量未见官方统一数值（来源：调研档案 upkie.md，下同）。它真正改变的不是"机器人有多强"，而是"个人在真实硬件上学习平衡控制的门槛有多低"。

核心内容

是什么：准确定义

Upkie 是一个轮足双足机器人平台：两条腿各带一个驱动轮，靠轮子保持平衡、靠腿应对不平地形。它不是一个玩具，也不是一台研究原型机，而是一套可复现的完整系统——从 3D 打印结构件、mjbots 执行器选型、树莓派主控，到 Python 软件栈与三种平衡控制示例，全部开源、全部可自行搭建。

判别一个平台是否属于 Upkie 生态，看三个特征：

  1. 轮足形态：每腿末端是驱动轮而非脚掌，平衡问题从"倒立摆 + 足底接触"简化为"倒立摆 + 轮地接触"；
  2. 准直驱执行器：采用 mjbots qdd100 准直驱（quasi-direct-drive）无刷伺服，固件开源、可力控；
  3. Python 优先：软件栈以 Python 为主，Gymnasium 标准接口，仿真与实机同一套代码。

为什么存在：痛点与历史定位

在 Upkie 出现之前，个人想学习腿足机器人平衡控制，面临一个尴尬的断层。纯步行双足（如 ToddlerBot、Berkeley Humanoid Lite）机械复杂度高、摔机代价大，动辄数万美元；仿真器（如 MuJoCo）虽然零成本，但"仿真里学会的平衡"与"真实硬件上的平衡"之间隔着建模误差、执行器延迟与摩擦不确定性。Upkie 恰好填在这个断层中间：轮足形态把平衡问题降维，准直驱执行器让力控透明，3,000 美元的成本让个人可承受，60 小时以上的 3D 打印让结构件可自制。它真正改变的不是"机器人能做什么"，而是"谁有资格在真实硬件上做平衡控制实验"。

原理拆解

① 轮足平衡：从倒立摆到轮式倒立摆

Upkie 的平衡本质是一个轮式倒立摆（wheeled inverted pendulum）问题。与足式双足不同，轮足机器人的支撑点不是离散的脚掌，而是连续的轮地接触，因此平衡控制从"步态规划 + 零力矩点（ZMP）调节"简化为"重心投影落在轮地接触线内"。这一简化使控制频率可以更高、鲁棒性可以更强，也让 PID 这类经典控制器在真实硬件上首次变得可行。

② 准直驱执行器：力控透明度的来源

Upkie 的髋、膝关节采用 mjbots qdd100 准直驱执行器。准直驱的核心特征是低减速比（通常 3:1–10:1），外部力矩可以直接"透传"回电机侧，因此只需测量电机电流即可估算输出力矩：

\[ \tau_{\text{out}} \approx G \, k_t \, I_m - J_{\text{eq}} \ddot{\theta}_m \]

其中 \(G\) 为减速比，\(k_t\) 为电机扭矩常数，\(I_m\) 为 q 轴电流，\(J_{\text{eq}}\) 为等效惯量，\(\ddot{\theta}_m\) 为电机角加速度。第二项是惯性补偿项。由于减速比小，摩擦与齿隙非线性也小，这个估算在工程上足够准——这就是"不装力矩传感器也能力控"的全部秘密（来源：准直驱执行器技术文档）。

③ 软件栈：仿真到实机的零摩擦迁移

Upkie 的软件栈以 upkie Python 库为核心，提供 Gymnasium 环境，同一套代码可以控制仿真（PyBullet）与实机。这意味着用户可以在仿真中调试算法，然后直接部署到树莓派 4 上，无需重写任何接口代码。开箱自带三种平衡控制范式示例：PID、MPC（qpmpc）、强化学习（Stable-Baselines3），覆盖从经典控制到现代学习的完整谱系。

Upkie 的核心差异在于形态选择：轮足不是"退化的人形"，而是"为学习平衡控制而优化的形态"。它牺牲了步行能力，换来了更低的控制难度、更低的机械风险与更低的成本——这三者恰好是个人学习者的核心约束（对比数据来源：调研档案 toddlerbot.md、berkeley-humanoid-lite.md）。

谁在用·应用案例

Upkie 的主要用户群体是个人学习者、教育机构与开源机器人爱好者。典型应用场景包括：

  1. 平衡控制入门：用 PID 示例在真实硬件上体验"轮式倒立摆"的平衡调节，理解反馈控制的核心概念；
  2. MPC 与强化学习研究：用 qpmpc 或 Stable-Baselines3 示例在仿真中训练策略，再部署到实机验证 sim-to-real 迁移；
  3. 机器人课程教学：作为低成本实验平台，让学生接触真实硬件上的传感器噪声、执行器延迟与通信问题；
  4. 社区二次开发：基于 upkie/parts（CAD/打印件）与 upkie/upkie_description（URDF）修改结构或添加传感器。

GitHub 仓库 upkie/upkie 386 stars / 52 forks（2026-07-01 快照，仍高频更新），被 awesome-open-source-robots 等知名清单收录，社区讨论活跃于 GitHub Discussions 与 Matrix 聊天室。

局限与边界

  1. 无法步行：轮足形态决定了它只能在不平地形上"滚"而不是"走"，无法跨越台阶或楼梯；
  2. 身高/重量无官方统一数值：因构型而异，需自行确认具体版本参数；
  3. 负载能力有限：桌面级尺寸，不适合承载重负载或长时间户外作业；
  4. 依赖 mjbots 生态：执行器、驱动器、固件均来自 mjbots，若该生态停止维护，Upkie 的供应链将受影响；
  5. 强化学习示例的实机迁移仍需调参：虽然提供 Stable-Baselines3 示例，但 sim-to-real 的差距（建模误差、延迟）仍需用户自行处理。

常见误区

  1. "Upkie 是玩具"——错。它是完整的机器人研究平台，包含真实硬件上的力控、状态估计与通信问题，这些在仿真中无法体验；
  2. "轮足比足式简单，所以没价值"——错。轮足简化的是平衡控制，但保留了腿足机器人的核心挑战：关节力控、状态估计、不平地形适应；
  3. "3,000 美元就能拿到完整机器人"——不准确。3,000 美元是现成组件成本，还需 60 小时以上 3D 打印时间与装配调试，总时间成本远高于金额本身；
  4. "必须用 Python"——不准确。软件栈支持 Python 与 C++，Python 只是默认推荐，C++ 用户同样可以开发部署。

왜 존재하는가:痛点과 역사적 위치

Upkie가 등장하기 전, 개인이 다리형 로봇 균형 제어를 배우려면 어색한 단절에 직면했습니다. 순수 보행 이족(예: ToddlerBot, Berkeley Humanoid Lite)은 기계적 복잡성이 높고, 넘어질 때 손실이 커서 수만 달러가 들곤 했습니다; 시뮬레이터(예: MuJoCo)는 무료이지만, "시뮬레이션에서 배운 균형"과 "실제 하드웨어에서의 균형" 사이에는 모델링 오차, 액추에이터 지연, 마찰 불확실성이 존재합니다. Upkie는 정확히 이 단절 사이를 메웁니다: 휠형 이족 형태가 균형 문제를 차원 축소하고, 준직구동 액추에이터가 힘 제어를 투명하게 만들며, 3,000달러의 비용으로 개인이 감당할 수 있고, 60시간 이상의 3D 프린팅으로 구조 부품을 자체 제작할 수 있습니다. Upkie가 진정으로 바꾼 것은 "로봇이 무엇을 할 수 있는가"가 아니라 "누가 실제 하드웨어에서 균형 제어 실험을 할 자격이 있는가"입니다.
