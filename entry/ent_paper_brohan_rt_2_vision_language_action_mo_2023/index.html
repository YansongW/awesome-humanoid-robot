RT-2: Vision-Language-Action Models Transfer Web Knowledge to Robotic Control

摘要

RT-2 是 Google DeepMind 于 2023 年提出的大型视觉-语言-动作模型，旨在将互联网规模预训练的视觉-语言知识直接迁移至机器人操控任务。其核心创新在于将机器人动作编码为文本 token，与自然语言 token 共同微调，从而在 6000 次评估试验中展现出对未见物体、语义命令及多步推理的显著泛化能力。

概述

RT-2 是 Google 提出的视觉-语言-动作（VLA）模型，将机器人动作离散化为文本 token，与网络规模数据共同微调预训练 VLM（PaLI-X、PaLM-E），实现端到端机器人控制。核心贡献在于证明互联网级视觉-语言预训练可以直接迁移到低层控制策略，带来显著的泛化提升和涌现式语义推理能力。

它改变了什么

在 RT-2 之前，LLM/VLM 在机器人领域的应用被严格限定在“高层规划”角色——解析指令、输出子目标，而底层动作执行仍由独立训练的小模型（如 RT-1）完成。这种割裂意味着底层控制器永远无法从互联网规模的语义知识中获益，其泛化能力受限于机器人演示数据的规模和多样性。RT-2 真正改变的，是打破了这条边界：它让同一个模型既理解“把苹果放到和杯子同色的容器里”这种抽象语义，又能直接输出末端执行器的 7 维动作向量。这不仅是架构上的简化，更是对“机器人数据稀缺”这一根本瓶颈的回应——与其暴力收集数百万条机器人轨迹，不如复用 VLM 在数十亿图文对上习得的世界知识。

方法拆解

动作编码与 token 化

  • 基于 RT-1 的离散化方案：6 自由度末端执行器位姿（位置+旋转）+ 夹爪开合 + 终止命令，连续维度均匀量化到 256 个 bin，动作表示为 8 个整数。
  • 动作 token 映射：PaLI-X 直接复用 0-255 的整数 token；PaLM-E 则从词表中挑选 256 个最少使用的 token 作为动作词汇，避免与自然语言 token 冲突。

输入输出格式

  • 输入采用标准 VQA 格式：“Q: what action should the robot take to [指令]? A:”，输出为动作 token 字符串。
  • 推理时对动作任务施加输出约束，仅采样有效动作 token；标准 VQA 任务不受限。

共微调（Co-Fine-Tuning）

  • 关键设计：将机器人数据与原始网络数据（WebLI、VQA、图文交错等）混合训练，而非仅用机器人数据微调。通过提高机器人数据采样权重平衡批次比例（PaLI-X 约 50%，PaLM-E 约 66%）。
  • 动机：仅微调会导致模型遗忘网络预训练知识，共微调则让策略持续暴露于抽象视觉概念，从而获得更强的泛化。

实时推理

  • 部署于多 TPU 云服务，通过网络查询实现闭环控制，可同时服务多个机器人。55B 模型推理频率 1-3 Hz，5B 模型约 5 Hz。

链式思维变体

  • 在数据中增加“Plan”步骤，先用自然语言描述动作意图，再输出动作 token。仅微调几百步，定性观察有效。

关键创新

  1. 动作即文本的统一表征：将连续动作空间离散化为文本 token，使机器人控制与 VLM 的 next-token 预测目标完全对齐。这一设计看似简单，却让模型无需任何架构改动即可复用预训练权重，是 VLA 范式的奠基性工作。
  2. 共微调策略：不是“先预训练后微调”的两阶段，而是将机器人数据与网络数据持续混合训练。消融实验证明共微调显著优于仅微调（55B 模型未见平均成功率 63% vs 52%），这揭示了保持预训练知识“鲜活”的重要性。
  3. 涌现式语义推理：在未见过的指令上（如“move apple to 3”、“move the coke can to the person with glasses”），RT-2 无需额外示范即达到 60% 平均成功率，是 RT-1（17%）的 3 倍以上。这证明互联网预训练带来的符号理解、多语言、基础推理能力可以零样本迁移到动作生成。

边界与局限

  • 物理技能无新增：RT-2 不会获得机器人数据中未出现的新动作能力，只能以新方式组合已有技能。作者明确承认这是数据集技能轴多样性不足的结果。
  • 特定操作失败：按特定部位抓取（如手柄）、新奇运动（毛巾擦拭、工具使用）、灵巧操作（折叠毛巾）、多层间接推理等场景表现不佳。
  • 计算成本：55B 模型推理仅 1-3 Hz，难以满足高频控制需求；作者建议未来探索量化和蒸馏。
  • 链式思维未量化：仅做了定性观察，无定量评估。
  • 55B 从零训练未评估：因 5B 从零训练表现差（9%）而跳过，无法确认更大规模是否改变结论。

工程启示

  • 复现优先级：先核对动作 token 映射方案——PaLI-X 直接复用整数 token，PaLM-E 需挑选最少用 token，两者实现细节不同，选错会导致训练不收敛。
  • 共微调是核心：不要跳过网络数据混合。消融显示仅微调会让 55B 模型未见泛化从 63% 掉到 52%，5B 模型差距更大。机器人数据采样权重（50%-66%）是关键超参数。
  • 规模敏感：5B 与 55B 在未见泛化上差距显著（44% vs 63%），如果资源受限，优先保证模型规模而非训练步数。
  • 推理频率是硬约束：55B 模型 1-3 Hz 只适合慢速操作任务；若需高频控制，考虑 5B 版本或蒸馏方案。
  • 评估协议：未见环境 Easy 与 Hard 差距极大（63% vs 35%），报告结果时务必区分难度层级，否则会高估模型能力。

核心内容

是什么：RT-2 的准确定义

RT-2 属于 方法（method）类型实体，英文全称为 RT-2 Vision-Language-Action Model，韩文名称为 RT-2 비전-언어-동작 모델。其所属领域编码为 07_ai_models_algorithms，理论深度为 method 层级，状态为 active。

在实体分类学的本体论承诺中，RT-2 属于信息实体（Information Entity）——它以符号和数据形式存在，不占据时空、不具有质量。它与 paper、algorithm、dataset 同属一个大类，但更准确地说是"方法"而非"算法"：它不提供单一的数学求解步骤，而是定义了一种将视觉-语言预训练知识转化为机器人动作输出的建模范式。

RT-2 的核心思想可以概括为一句话：把机器人的动作当作语言来写。它将动作表示为文本 token（如"移动到 (x, y, z)"），与图像、指令一起输入到统一的 Transformer 模型中，通过自回归方式逐 token 生成动作序列。这样，模型在互联网图文数据上学到的语义知识——比如"杯子是什么""打开抽屉意味着什么"——就能直接迁移到机器人控制中。

为什么存在：痛点与历史定位

在 RT-2 出现之前，机器人学习面临一个根本性矛盾：机器人数据稀缺，而互联网数据丰富。传统方法（如行为克隆、强化学习）依赖大量机器人演示数据，采集成本极高；而互联网上数以亿计的图文对虽然蕴含丰富的语义知识，却无法直接用于机器人控制。

RT-2 的历史定位正是为了解决这一矛盾。它属于 VLA（Vision-Language-Action）模型家族，其前身 RT-1 已经证明了"用 Transformer 统一视觉-语言-动作"的可行性，但 RT-1 的训练数据仍主要来自机器人演示。RT-2 的突破在于：将网络规模的视觉-语言知识作为预训练基础，再通过少量机器人数据微调，从而大幅降低对机器人数据的依赖。

这一思路与同时期的 Unified-IO 2 一脉相承——后者将图像、文本、音频、动作、边界框等多种模态的输入输出 token 化到共享语义空间，由单一编码器-解码器 Transformer 处理，并在 120 个数据集的集成上微调。RT-2 则更聚焦于机器人动作生成这一下游任务。

原理拆解

① 动作即文本：统一 token 空间的建模基础

RT-2 的底层假设是：机器人的动作可以离散化为有限集合，并映射为文本 token。例如，机械臂的末端位姿变化可以被编码为"移动到 (x, y, z)，旋转 (roll, pitch, yaw)"这样的文本序列。这样，动作生成就变成了一个条件文本生成问题：

\[ p(a_t \mid v_t, l) = \prod_{i=1}^{N} p(t_{a,i} \mid t_{a,<i}, v_t, l) \]

其中 \(v_t\) 为当前视觉观测，\(l\) 为语言指令，\(t_{a,i}\) 为动作序列的第 \(i\) 个 token，\(N\) 为动作 token 总数。模型通过最大化条件概率来训练，推理时则用自回归解码逐 token 生成动作。

② 知识迁移：从 VLM 到 VLA 的权重继承

RT-2 的关键工程决策是直接继承预训练 VLM 的权重。它不从头训练，而是将 PaLI-X 或 PaLM-E 等 VLM 的骨干网络作为初始化，在机器人数据上继续微调。这样，模型在互联网图文上学到的物体识别、空间关系理解、指令跟随等能力被完整保留，只需学习"如何将语义理解映射为动作"这一新映射。

③ 与 RT-Affordance 的对比：中间表示的选择

RT-2 直接输出动作 token，而 RT-Affordance 则采用分层架构：先由可供性规划器（affordance planner）根据任务语言生成关键阶段的机器人姿态序列，再由策略执行器（policy executor）以该计划为条件生成具体动作。RT-Affordance 的动机是：直接输出动作的表示在复杂任务中上下文不足，而语言、目标图像等中间表示又存在过度指定问题。可供性（即任务关键阶段机器人姿态）兼具表达力与轻量性，且能通过迁移大规模互联网数据集知识实现高效学习。这两种路径代表了 VLA 设计的两种哲学：端到端直接映射 vs 分层中间表示。

谁在用：应用案例

RT-2 及其 VLA 家族主要应用于以下场景：

  1. 语义泛化操作：面对未见过的物体或场景，RT-2 能利用互联网图文知识理解"这是什么""应该怎么处理"，从而完成传统方法无法泛化的操作任务。例如，模型在训练中从未见过某个特定品牌的杯子，但通过视觉-语言预训练学到的"杯子"概念，仍能正确抓取。

  2. 指令跟随：用户用自然语言描述任务（如"把红色方块放到蓝色盘子旁边"），RT-2 将语言指令与视觉观测联合编码，生成对应的动作序列。

  3. 多任务学习：RT-2 在多个任务上联合训练，共享同一个模型参数，避免了为每个任务单独训练一个策略的开销。

  4. 与分层方法结合：如 RT-Affordance 所示，可供性规划器可以生成关键姿态序列，再由执行器细化动作——这种分层设计可以弥补 RT-2 直接输出动作在复杂任务中的上下文不足问题。

局限与边界

  1. 推理延迟：RT-2 依赖数十亿参数的 VLM 后端，推理延迟高，主要适用于准静态任务。HiRT 的实验数据表明，基线 VLA 模型的推理延迟约为 320ms，而 HiRT 通过分层设计将其降至 50ms（按语料数据推算，HiRT 延迟约为基线的 15.6%）。对于需要高频反馈的动态操作（如抓取移动物体），RT-2 类端到端模型难以胜任。

  2. 动作表示的离散化精度：将连续动作离散化为文本 token 会引入量化误差。动作空间的粒度选择需要在表达力与模型复杂度之间权衡。

  3. 数据分布偏移：RT-2 在互联网图文上预训练，但机器人操作场景的视觉分布与互联网图片存在差异（如视角、光照、背景），可能导致域偏移问题。

  4. 缺乏物理一致性保证：RT-2 生成的动作序列不保证满足动力学约束（如关节力矩极限、摩擦锥约束）。在真实机器人上部署时，需要额外的安全过滤层或后处理优化。

常见误区

  1. "RT-2 是通用机器人控制器"——错。RT-2 是方法而非完整系统，它不包含运动规划、力控制、安全监控等模块。它生成的是高层动作指令，底层执行仍需传统控制栈。

  2. "RT-2 不需要机器人数据"——错。RT-2 虽然大幅降低了对机器人数据的依赖，但仍需一定量的机器人演示数据进行微调。它真正改变的是数据效率，而非彻底摆脱机器人数据。

  3. "VLA 模型可以直接部署到人形机器人"——错。人形机器人是高维、欠驱动、强耦合系统，RT-2 类模型的动作空间通常针对机械臂设计，直接迁移到人形机器人需要重新定义动作表示并处理全身协调问题。

  4. "动作 token 化与连续控制等价"——错。离散 token 化会丢失精细的力控信息，对于需要精确力交互的任务（如装配、打磨），RT-2 类方法力有不逮。
