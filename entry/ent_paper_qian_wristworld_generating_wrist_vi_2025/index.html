WristWorld

WristWorld: Generating Wrist-Views via 4D World Models for Robotic Manipulation

摘要

WristWorld 是由北京大学、香港科技大学、新加坡国立大学和北京人形机器人创新中心联合提出的首个4D世界模型，能够仅从锚定视角生成腕部视角视频。其核心贡献在于通过两阶段架构（重建与生成）弥合锚定视角与腕部视角之间的数据鸿沟，并在Droid、Calvin和Franka Panda基准上实现了最先进的视频生成效果，同时将Calvin任务平均完成长度提升3.81%，缩小了42.4%的视角差距。

概述

WristWorld 提出用 4D 世界模型生成腕部视角图像，以解决异构机器人数据缺乏统一视觉输入的问题。核心贡献是建立 View Registry 将不同相机配置映射到固定角色-模态词汇表，并配合统一 72D 槽空间，使跨机器人训练成为可能。该方法在保持下游任务精度的同时，显著降低边缘部署的视觉 token 负担。

它改变了什么

边缘部署 VLA 的瓶颈不在模型参数量，而在 VLM 视觉 token 随输入图像数线性增长的 GEMM 计算量。π0.5 在 Orin 上端到端延迟 858.3 ms，其中 VLM Backbone 占 528.0 ms，视觉编码占 69.3 ms，三者合计超过 90% 运行时间。现有边缘硬件在 5 Hz 控制频率下已接近 roofline 极限，10 Hz 实时闭环目标难以达成。

异构机器人数据集缺乏统一输入输出接口是更深层的问题。不同平台相机数量、位置、模态各异，直接混合训练会导致模型无法区分"头部视角"与"腕部视角"的语义差异。WristWorld 通过 View Registry 将相机字段映射到固定角色-模态词汇表，从数据接口层面解决了跨机器人训练的定义模糊问题，这是此前工作未系统处理的。

方法拆解

性能分析先行

  • 在 Orin 上（理论 FP16 约 43 TFLOPS，带宽约 203 GB/s，假设 40% 利用率，有效约 17.2 TFLOPS）进行 roofline 分析
  • π0.5 延迟分解：视觉编码器 69.3 ms，VLM Backbone 528.0 ms，Action Expert 257.0 ms
  • VLM 算子级分解：gate_proj、up_proj、down_proj 合计约 74.7% 延迟；Q/K/V/O 投影合计约 7.2%；其余约 18.1%
  • MLP 投影 FLOPs = 2BSd_in d_out，随 token 数 S 线性增长

架构设计

  • 采用 2.13B 参数 Qwen3-VL 作为视觉语言骨干，224×224 图像下 64 个合并视觉 token，对比 PaliGemma-224 的 256 个，视觉 token 负担减少 4×
  • Action Expert 0.40B 参数（对比 π0.5 约 0.43B），基于 Qwen3-VL 接口重新设计
  • 每个去噪步骤条件化于 Qwen3-VL 最后 18 层 KV cache、当前 72D 机器人状态、状态/动作掩码、噪声动作块、流匹配时间和机器人实例索引

统一 72D 槽空间

  • 每个槽固定物理含义，状态和动作使用相同槽定义
  • 移动基座动作定义为速度目标
  • 二进制掩码指示有效状态和动作维度
  • 每只手保留 16 槽，按 4-3-3-3-3 分配（拇指 4 个主动 DoF，其他手指各 3 个）

训练策略

  • 预训练：Qwen3-VL 骨干冻结，优化 VLM LoRA、共享 Action Expert 和机器人实例 LoRA
  • 采样概率 p_i = N_i^0.43 / Σ_j N_j^0.43（幂律平衡）
  • 流匹配目标：x_t = (1-t)a + tz，预测 v̂_θ = f_θ(x_t, t, s, m_s, m_a, c_vlm, r)，损失 L_FM 带掩码和每槽权重 w(h,d)
  • 后训练：视觉语言编码器和预训练 VLM LoRA 冻结，仅更新目标机器人实例 LoRA

部署优化

  • 编译优化：算子级 FlashAttention 风格 tiling 适配 R1 SPM，注意力核达 >80% 理论峰值吞吐
  • 图级算子融合（归一化、线性投影、偏置、激活、残差）
  • 混合精度：INT8 权重 + FP16 激活（W8A16），避免 W8A8 精度损失

关键创新

  1. View Registry 统一视觉接口：将任意相机配置映射到固定角色-模态词汇表，使异构数据可直接混合训练。这是首次系统解决跨机器人视觉输入语义对齐问题，此前工作要么固定相机配置，要么简单拼接所有图像。

  2. 72D 槽空间与掩码机制：状态和动作共享同一物理槽定义，配合二进制掩码处理不同机器人自由度差异。这比单纯 padding 或 masking 更本质，因为槽的物理含义固定，模型可学习跨平台共享的关节语义。

  3. 机器人实例 LoRA 与后训练分离：预训练阶段学习共享表示，后训练阶段仅更新目标实例 LoRA，实现高效领域适配。部署时可合并到基础权重，不增加推理开销。

边界与局限

当前预训练模型不监督腿或脚关节，这些字段从训练目标中排除。仅使用能可靠映射到 72D 物理槽空间及其掩码的样本进行训练。论文未明确腿/脚关节的扩展方案或未来工作方向。未提及在真实机器人上的闭环部署结果，LIBERO 为模拟评估。训练数据主要来自 AgiBotWorld 系列，跨平台泛化性需更多验证。

工程启示

复现时先核对 View Registry 映射表是否覆盖目标数据集的全部相机配置，漏映射会导致训练样本被静默丢弃。72D 槽空间定义需严格遵循表 2 的物理含义，特别是 D55–D57 腰部 RPY 与 D58–D60 基座速度命令的区分，混淆会导致动作语义错乱。

部署优化中 W8A16 是关键决策，避免 W8A8 的精度损失，但需确认目标硬件支持 INT8 权重加载与 FP16 激活的混合流水线。并行编码三个图像流时，注意批次大小与显存/内存带宽的匹配，R1 上 24.31 ms 的延迟是在特定分辨率下测得，更高分辨率需重新调优。

训练时采样概率 p_i = N_i^0.43 的幂律平衡对数据分布敏感，若新增数据集需重新计算权重。后训练阶段仅更新实例 LoRA 可显著降低适配成本，但需验证目标机器人的自由度是否完全落在 72D 槽空间内，超出部分无法监督。
