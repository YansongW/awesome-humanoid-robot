概述

小批量试产（Pilot Run）是人形机器人从设计冻结走向量产爬坡的必经验证工序，属于 P16.3 试产与量产爬坡阶段的核心节点。它以 10–50 台规模的试制来检验供应链、装配、测试与软件全链路的真实状态，通过问题追踪、ECN（工程变更通知）与首件检验等手段，将设计意图转化为可量化的直通率与问题闭环率指标。它真正改变的不是"造出几台样机"，而是让团队第一次以量产视角审视产品——用有限数量的试产暴露批量性问题，从而避免在更大规模上付出代价。

核心内容

是什么：准确定义

小批量试产（Pilot Run）是指在正式量产之前，以 10–50 台的规模进行试制生产的工序节点。它不同于研发阶段的单台样机验证——样机验证回答"设计能不能工作"，而 Pilot Run 回答"设计能不能被稳定地、可重复地、以可接受的成本制造出来"。

在 WBS V3 中，P16.3.1 小批量试产（Pilot Run）被展开为五个三级子任务：输入梳理与目标量化（P16.3.1.1）、方案/方法设计（P16.3.1.2）、实施/原型/样件制作（P16.3.1.3）、验证与问题闭环（P16.3.1.4）、文档输出与下游交付（P16.3.1.5）。每个子任务下又细分为若干四级关键动作，形成从输入到交付的完整闭环。

其核心方法/工具包括：10–50 台试产、问题追踪、ECN、首件检验。设计思考逻辑是验证供应链、装配、测试、软件全链路；关键约束是时间、资源、样机成本；完成标准/输出物是试产总结报告、直通率、问题闭环率。

为什么存在：痛点与历史定位

在制造工艺体系中，子系统设计冻结的只是"几何与接口"，它并不回答"用什么设备、以什么节拍、花多少钱把它做出来"。制造工艺体系（manufacturing process system）正是连接设计与量产的桥梁：它把 CAD 模型转化为工艺路线（process routing）、工装夹具、检验规范与成本结构，并在小批量试产（Pilot Run）中接受良率与一致性的检验。

如果跳过 Pilot Run 直接进入量产，团队将面临一系列典型问题：供应商的来料一致性不足导致装配困难、工装夹具与设计不匹配导致节拍远低于预期、测试程序在批量环境下出现假阳性/假阴性、软件版本与硬件批次不匹配导致功能异常。这些问题在单台样机阶段往往被"手工调试"掩盖，只有在批量语境下才会集中爆发。

Pilot Run 的历史定位，正是制造工艺体系从"设计验证"走向"量产验证"的转折点。它用 10–50 台的有限数量，换取对全链路状态的系统认知，是量产爬坡前最后一道系统性防线。

原理拆解

① 输入梳理与目标量化（P16.3.1.1）

这一子任务的核心是将模糊的"完成标准"转化为可量化的验收指标。具体动作包括：列出所有上游输入清单并确认版本、将验收标准转化为可量化 KPI、建立任务 Owner、时间节点与风险登记。

上游输入通常包括：冻结的设计图纸与 3D 模型、BOM 初稿、工艺路线草案、测试规范、软件版本、供应商清单与来料检验标准。确认版本的意义在于：Pilot Run 期间任何输入变更都会影响问题归因——如果设计还在改，就无法判断装配问题是设计缺陷还是工艺缺陷。

KPI 的量化逻辑可表达为：

\[ \text{直通率（FPY）} = \frac{\text{一次通过全部检验的台数}}{\text{投入试产总台数}} \times 100\% \]

直通率是 Pilot Run 最核心的量化指标之一，它直接反映全链路的稳定程度。问题闭环率则衡量问题追踪与 ECN 的执行效率。

② 方案/方法设计（P16.3.1.2）

这一子任务要求形成不少于 2 个候选方案，建立评估矩阵并量化打分，组织评审并冻结方案。候选方案的差异可能体现在：试产批次划分（一次 50 台 vs 分两批各 25 台）、装配顺序（整机装配 vs 模块化并行装配）、测试策略（全项测试 vs 抽样测试）等维度。

评估矩阵的量化打分需要综合考虑时间、资源、样机成本三大约束。例如，分两批试产虽然能更早暴露问题，但会延长总周期；全项测试虽然更充分，但会占用更多测试设备与人力。

③ 实施/原型/样件制作（P16.3.1.3）

根据冻结方案执行试产实施，制作原型/样件并记录过程数据。关键动作包括：建立模型/样机并记录关键参数、执行仿真或原型验证、记录异常与偏差。

在这一阶段，首件检验（First Article Inspection）尤为重要——对试产的第一台产品进行全尺寸、全功能检验，确认工装、夹具、程序、物料均正确后才能继续批量装配。过程数据的记录质量直接决定后续问题归因的准确性。

④ 验证与问题闭环（P16.3.1.4）

对试产输出进行验证，检查是否满足完成标准，记录问题并跟踪至关闭。关键动作包括：制定测试/评审计划与通过准则、执行测试并记录原始数据、输出问题清单与改进措施。

问题闭环的核心机制是 ECN（工程变更通知）。任何设计、工艺、物料变更都必须通过 ECN 流程受控发布，确保变更可追溯、可验证。问题闭环率的计算方式为：

\[ \text{问题闭环率} = \frac{\text{已关闭问题数}}{\text{问题总数}} \times 100\% \]

⑤ 文档输出与下游交付（P16.3.1.5）

输出最终报告/图纸/规范，更新 ICD/BOM/SOP/需求追溯链，完成向下游环节的正式交付。关键动作包括：按模板编写文档并引用原始数据、完成内部评审与版本控制、发布并通知下游依赖方。

关键参数与规格

参数 规格/范围 说明
试产规模 10–50 台 过少不足以暴露批量性问题，过多则成本与时间不可控
直通率（FPY） 需自行确认 目标值通常由产品复杂度与行业基准决定
问题闭环率 需自行确认 量产放行前通常要求达到较高比例（工程判断）
候选方案数 不少于 2 个 确保方案选择有比较基础
首件检验 每批次首台 确认工装、程序、物料正确后才能批量装配
输出物 试产总结报告、直通率、问题闭环率 作为量产放行的输入依据

与上游的 P5 本体结构工程与原型阶段相比，Pilot Run 的关注点从"结构设计是否正确"转向"制造过程是否稳定"。P5 阶段的核心约束是刚度、强度、重量、装配可达性，而 Pilot Run 的核心约束是时间、资源、样机成本——这反映了从工程验证到生产验证的范式转换。

谁在用·应用案例

Pilot Run 是人形机器人产品开发全流程中的标准工序节点，适用于任何从设计走向量产的产品开发项目。在 WBS V3 中，它位于 P16.3 试产与量产爬坡阶段之下，是量产放行前的必经环节。

典型应用场景包括：整机试产（验证全链路）、关节模组试产（验证供应链与装配）、软件版本试产（验证测试程序与硬件兼容性）。在整机试产中，团队会验证供应链（来料一致性）、装配（工装夹具匹配度）、测试（测试程序有效性）、软件（版本与硬件批次兼容性）四大维度。

局限与边界

Pilot Run 的边界在于：它无法完全模拟量产的全部条件。10–50 台的规模决定了某些批量性问题（如供应商产能波动、设备长期稳定性）无法在此阶段充分暴露。此外，Pilot Run 的成本与时间约束意味着测试覆盖不可能无限充分——某些极端工况或长期可靠性问题仍需依赖后续的量产爬坡阶段持续验证。

另一个边界是：Pilot Run 的结论高度依赖输入的质量。如果上游设计尚未冻结、BOM 版本混乱、供应商来料不稳定，试产数据的可信度将大打折扣。因此，P16.3.1.1 输入梳理与目标量化是整个工序有效性的前提。

常见误区

  1. "Pilot Run 就是多造几台样机"——错。样机验证回答"设计能不能工作"，Pilot Run 回答"设计能不能被稳定制造"。两者的目的、方法、输出物完全不同。

  2. "试产通过就等于可以量产"——不完全是。Pilot Run 通过只说明 10–50 台规模下全链路稳定，量产爬坡仍需解决产能、良率、成本等规模化问题。

  3. "问题追踪就是记录 Bug"——不准确。Pilot Run 的问题追踪覆盖设计、工艺、物料、软件、测试全维度，且必须通过 ECN 受控闭环，而非简单记录。

  4. "直通率越高越好"——需要结合上下文。直通率低说明问题多，但问题在 Pilot Run 阶段暴露是"好事"——它避免了问题在量产阶段以更大代价爆发。关键是问题能否被有效闭环。
