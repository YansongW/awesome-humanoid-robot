概述

安全功能测试（Safety function test）是整机集成与验证测试阶段（P15）中验证机器人安全机制按设计动作的关键工序节点，对应 WBS 编号 P15.2.1。它通过急停、跌倒保护、碰撞检测、限位、安全区域等手段，验证任何异常情况下机器人都能安全停机或进入保护姿态，其完成标准是输出安全测试报告并确保所有安全功能通过。它真正改变的不是"测出故障"的排查动作，而是"用可量化的验收指标证明安全设计成立"的资格认定过程。

核心内容

是什么：准确定义

安全功能测试是 P15 整机集成与验证测试阶段中 P15.2 功能安全与性能验证工作包下的第一个三级子任务，在 WBS V3 中编号为 P15.2.1。它属于 DV（设计验证）矩阵中的核心试验类别之一，与性能基准测试（P15.2.2）、环境适应性测试（P15.2.3）并列，共同构成整机功能与性能验证的完整闭环。

该测试的核心对象是机器人的安全相关功能，包括急停链路、安全 MCU 监控、断电制动保持、碰撞检测等。其方法/工具明确为：急停、跌倒保护、碰撞检测、限位、安全区域。设计思考逻辑是：任何异常都能安全停机或进入保护姿态。关键约束是安全标准与人员保护。

在知识图谱的 17 个阶段实体中，P15 位于 P14 软件集成之后、P16 小批量试产与量产准备之前。安全功能测试作为 P15 的组成部分，其上游输入来自分系统集成（P15.1）的交付物，下游输出则服务于性能基准测试（P15.2.2）、耐久测试（P15.3.1）以及认证准备与预审核（P15.3.3）。

为什么存在：痛点与历史定位

在安全功能测试被系统化之前，人形机器人的安全验证往往依赖"试错"：样机在调试中暴露问题，工程师再针对性修补。这种模式存在两个根本性缺陷。

第一，安全缺陷的发现具有滞后性。当机器人以整机形态运行时，一个急停失效的问题可能只有在碰撞事故或人员受伤后才被发现。此时修复成本极高——不仅涉及硬件返工，还可能面临法规合规风险。

第二，安全验证缺乏可追溯性。没有明确的验收指标，测试结果无法量化，也就无法判断"安全功能是否真正通过"。这直接导致下游的认证准备（P15.3.3）缺乏依据。

安全功能测试的定位正是为了解决这两个痛点。它将安全验证从"事后补救"前置为"事前证明"，通过将完成标准转化为可量化 KPI，使每一项安全功能都能追溯到具体的测试用例和验收数据。在 DV 矩阵中，安全功能测试的编排逻辑以 FMEA 识别的失效模式为索引，使每一项试验都能追溯到具体风险——这正是它区别于一般功能测试的本质特征。

原理拆解

① 安全链路的层级架构 安全功能测试的底层逻辑是"纵深防御"（defense in depth）。人形机器人的安全机制通常分为三个层级：

  • 第一层：主动规避——通过感知系统识别危险（如碰撞检测、安全区域监控），在事故发生前主动调整行为；
  • 第二层：被动保护——当主动规避失效时，通过机械限位、断电制动保持等物理手段限制伤害；
  • 第三层：紧急处置——当以上层级均未能阻止事故时，通过急停链路切断动力，使机器人进入安全姿态。

安全功能测试需要验证的是：每一层级都能按设计动作，且层级之间的切换逻辑正确。

② 急停链路的完整性验证 急停是安全功能中最关键的一环。其验证要点包括：

  • 链路完整性：从急停按钮到电机驱动器的整个电气回路必须无断路；
  • 响应时间：从按下急停到机器人完全停止的时间必须满足安全标准；
  • 冗余设计：安全 MCU 监控与主控 MCU 相互独立，即使主控失效，安全 MCU 仍能触发制动。

③ 碰撞检测的灵敏度标定 碰撞检测的原理是基于关节电流或力矩的异常变化判断碰撞发生。其验证难点在于灵敏度阈值的选择——阈值过高会漏检，阈值过低会误触发。测试中需要通过注入不同力度的碰撞，标定出既能可靠检测又不会频繁误报的阈值区间。

④ 安全区域的逻辑验证 安全区域通过激光雷达或视觉系统划定，当人员或物体进入危险区域时，机器人应减速或停止。验证内容包括区域划分的准确性、检测的实时性以及响应动作的正确性。

关键参数与规格

安全功能测试的验收指标需在 P15.2.1.1 输入梳理与目标量化阶段转化为可量化 KPI。根据语料，典型的安全功能测试项目及其验证目的如下：

试验类别 典型项目 验证目的 WBS 锚点
安全功能测试 急停链路 验证急停按钮按下后动力完全切断 P15.2.1
安全功能测试 安全 MCU 监控 验证主控失效时安全 MCU 独立触发制动 P15.2.1
安全功能测试 断电制动保持 验证断电后关节保持位置不坠落 P15.2.1
安全功能测试 碰撞检测 验证碰撞发生后机器人及时停止或回退 P15.2.1

具体数值指标（如急停响应时间、碰撞检测灵敏度阈值、制动保持力矩等）需根据所选安全标准（如 ISO 13482、ISO 10218 等）和产品规格书确定，语料中未提供具体数值，需自行确认。

安全功能测试在 DV 矩阵中优先级最高，因为如果安全功能不通过，后续的性能测试和环境测试都无法安全开展。

谁在用·应用案例

安全功能测试在工业机器人领域已有成熟应用。以协作机器人为例，KUKA LBR iiwa 7 R800 机械臂与 SCHUNK Co-act EGP-C 64 夹爪的协作装配场景中，机器人需要与人共存、协作、协同操作，其安全功能（碰撞检测、力矩限制）必须经过严格验证才能投入产线。

在人形机器人领域，安全功能测试贯穿 DV 与 PV 两个阶段。DV 阶段用工程样件验证设计规范，对应 WBS P15.2 与 P15.3 系列任务；PV 阶段则在小批量试产（P16.3.1）前对生产件进行安全抽检。测试结果将直接支撑认证准备与预审核（P15.3.3），为产品获得市场准入提供依据。

局限与边界

安全功能测试存在以下边界：

  1. 无法覆盖所有失效模式：测试只能验证已识别的风险（以 FMEA 为索引），未识别的失效模式不在测试范围内；
  2. 测试环境与真实场景的差异：实验室测试无法完全模拟真实使用中的复杂工况（如极端天气、非预期操作）；
  3. 安全标准的滞后性：人形机器人属于新兴产品，现有安全标准（如针对工业机器人的 ISO 10218）可能无法完全覆盖其新型安全风险；
  4. 测试成本与时间的约束：完整的安全测试矩阵需要大量样机与测试工时，在项目进度压力下可能被迫裁剪测试项。

常见误区

  1. "安全功能测试就是按个急停按钮"——错。急停只是安全功能之一，完整的测试还包括安全 MCU 监控、断电制动保持、碰撞检测、限位、安全区域等多项内容，且每项都需要量化的验收指标。

  2. "安全测试通过 = 产品绝对安全"——错。安全测试只能证明已识别的风险得到控制，无法保证绝对安全。它真正改变的不是"消除所有风险"的承诺，而是"用可追溯的证据证明风险已被合理管控"的工程事实。

  3. "安全测试可以放在性能测试之后"——错。安全功能测试必须优先执行，因为性能测试（如行走速度、负载测试）本身存在安全风险，只有在安全功能验证通过后才能安全开展。

  4. "安全测试只需要做一次"——错。DV 阶段用工程样件验证设计规范，PV 阶段需对生产件进行抽检，且设计变更后需回归测试。

왜 존재하는가:痛点과 역사적 위치

안전 기능 테스트가 체계화되기 전, 휴머노이드 로봇의 안전 검증은 종종 "시행착오"에 의존했습니다: 시제품이 디버깅 중 문제를 드러내면 엔지니어가 맞춤형으로 수리했습니다. 이 방식에는 두 가지 근본적 결함이 있었습니다.

첫째, 안전 결함 발견의 지연성입니다. 로봇이 완제품 형태로 작동할 때, 비상정지 고장 문제는 충돌 사고나 인원 부상 후에야 발견될 수 있습니다. 이때 수리 비용은 극히 높습니다—하드웨어 재작업뿐만 아니라 법규 준수 위험에도 직면할 수 있습니다.

둘째, 안전 검증의 추적 가능성 부재입니다. 명확한 검수 지표가 없으면 테스트 결과를 정량화할 수 없어 "안전 기능이 실제로 통과했는지" 판단할 수 없습니다. 이는 직접적으로 하위의 인증 준비(P15.3.3)가 근거를 갖지 못하게 합니다.

안전 기능 테스트의 위치는 바로 이 두 가지痛点을 해결하기 위한 것입니다. 안전 검증을 "사후 보완"에서 "사전 증명"으로 앞당기고, 완료 기준을 정량화 가능한 KPI로 전환하여 각 안전 기능이 구체적인 테스트 케이스와 검수 데이터로 추적될 수 있게 합니다. DV 매트릭스에서 안전 기능 테스트의 편성 논리는 FMEA로 식별된 고장 모드를 인덱스로 삼아 각 시험이 구체적인 위험으로 추적될 수 있게 합니다—이것이 일반 기능 테스트와 구별되는 본질적 특징입니다.
