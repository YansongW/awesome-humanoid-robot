Helix

Helix: A vision-language-action model for generalist humanoid control

层级

摘要

Helix 是 FIGURE 公司于 2025 年提出的大型视觉-语言-动作模型，专为通用人形机器人操控设计。其核心贡献在于首次实现 VLA 模型对人形机器人全上半身（含手指）的高频连续控制，并首次支持双机器人协作完成未见物品的长时操控任务。

来源与参考

  • Helix source

概述

Helix 是 Figure AI 提出的首个“System 1, System 2”视觉-语言-动作（VLA）模型，用于通用人形机器人控制。它通过一个 7B 参数的慢速 VLM（System 2）负责语义理解，与一个 80M 参数的快速视觉运动策略（System 1）以 200 Hz 输出 35-DoF 连续动作，两者端到端联合训练。核心贡献在于解耦了“慢思考”与“快执行”，在约 500 小时数据（不到此前 VLA 数据集的 5%）下实现了零样本多机器人协调与数千种新物体的泛化抓取。

它改变了什么

家庭场景对机器人控制的挑战不是“更快的策略”或“更大的模型”能单独解决的，而是一个根本性的时间尺度矛盾：语义理解需要慢速、全局的推理，而灵巧操作需要快速、局部的反馈。此前的 VLA 方法被迫在“通用但慢”的 VLM 骨干与“快但不通用”的视觉运动策略之间做二选一，导致要么无法实时控制高维人形，要么泛化能力受限。

Helix 真正改变的是将这一矛盾从架构层面拆解为两个异步协作的系统，而不是试图用一个网络同时满足两种时间尺度。它证明了“慢系统”的潜在语义表征可以作为“快系统”的实时条件信号，且两者可以通过端到端梯度流联合优化。这为通用人形控制提供了一个新的设计范式：不是让一个模型变快，而是让快慢两个模型各司其职并通过训练耦合。

方法拆解

双系统架构

  • System 2 (S2)：7B 参数开源 VLM，运行于 7-9 Hz。输入单目图像、机器人状态（腕部姿态、手指位置）与自然语言命令，将所有语义信息蒸馏为单个连续潜在向量。
  • System 1 (S1)：80M 参数交叉注意力编码器-解码器 transformer，运行于 200 Hz。接收与 S2 相同的图像与状态输入，但以更高频率处理。S2 的潜在向量被投影到 S1 的 token 空间，沿序列维度与视觉特征拼接，作为任务条件。

训练机制

  • 端到端联合训练：从原始像素与文本命令映射到连续动作，使用标准回归损失。梯度通过潜在通信向量从 S1 反向传播至 S2，实现联合优化。无任务特定适配、无单独动作头、无逐任务微调。
  • 时间偏移校准：在 S1 与 S2 输入间添加时间偏移，匹配两者部署推理延迟差距，确保训练时反映实时控制要求。
  • 动作空间：35-DoF，包括期望腕部姿态、手指屈曲/外展、躯干与头部朝向。附加合成“任务完成百分比”动作，使模型能预测自身终止条件，便于序列化多个行为。

推理部署

  • S2 作为异步后台进程，持续更新共享内存中的潜在向量；S1 作为独立实时进程，维持 200 Hz 控制循环。部署策略刻意镜像训练中的时间偏移，最小化训练-推理分布差距。

数据与初始化

  • 约 500 小时多机器人、多操作员遥操作数据，自动标注 VLM 生成事后指令（提示词：“What instruction would you have given the robot to get the action seen in this video?”）。
  • S1 视觉骨干初始化来自完全在仿真中完成的预训练；S2 骨干为互联网规模预训练的开源 VLM。

关键创新

  1. 首个“System 1, System 2” VLA 架构：此前 VLA 方法要么将 VLM 直接输出动作（受限于推理频率），要么将动作 token 化（在高维人形控制中扩展困难）。Helix 通过解耦语义理解与实时控制，让每个系统在其最优时间尺度运行，同时通过端到端训练保持耦合。这是架构层面的新范式，而非简单组合。

  2. 连续高维动作直接输出：Helix 直接输出 35-DoF 连续动作，避免了 VLA 方法中复杂的动作 tokenization 方案。后者在低维控制中有些成功，但在高维人形控制中面临扩展挑战。这一设计决策使 Helix 能以 200 Hz 输出全上半身控制，且无需任务特定适配。

  3. 数据效率与零样本泛化：在不到此前 VLA 数据集 5% 的数据量下，实现了零样本多机器人协调（两个机器人共享相同权重，通过自然语言提示协作）与“Pick up anything”能力（数千种新物体无需示范）。这表明双系统架构可能比单一大模型更有效地利用数据。

实验与结果

论文片段未包含表格数据，以下关键结果来自项目页/公开资料：

能力 设置 结果
零样本多机器人协调 两个 Figure 机器人，相同权重，自然语言提示 成功完成“递饼干”“接饼干并放入抽屉”等协作任务，无需机器人特定训练
“Pick up anything” 杂乱环境，数千种新物品（玻璃器皿、玩具、工具、衣物） 成功处理，无需先前示范或自定义编程
抽象概念理解 提示“Pick up the desert item” 识别玩具仙人掌匹配抽象概念，选择最近的手并执行精确抓取
训练数据量 约 500 小时 不到此前 VLA 数据集的 5%

结果的含义：Helix 证明了在家庭级泛化任务中，数据规模并非唯一瓶颈，架构设计（快慢系统解耦）可以显著提升数据效率。零样本多机器人协调尤其值得注意，因为它展示了单一模型权重在无需显式角色分配的情况下，通过语言指令即可实现多智能体协作。

边界与局限

论文片段未明确列出局限性，但基于事实要点可推断以下边界： - 未涉及腿部控制：动作空间仅覆盖上半身（35-DoF），未包含腿部运动，因此“通用人形控制”的声明仅适用于上半身操作任务。 - 未报告定量成功率指标：论文片段中未提供系统测试的量化成功率，仅有定性描述（如“成功处理”），无法评估泛化能力的统计显著性。 - 未进行大规模扩展实验：作者提到“渴望看到扩展 1,000 倍及更远时会发生什么”，暗示当前规模（500 小时数据）尚未充分探索，扩展行为未知。 - 训练-评估污染控制：训练中处理的所有物品均从评估中排除，但论文未明确评估环境的多样性边界（如光照、背景、物体组合变化）。 - 硬件依赖：部署依赖双低功耗嵌入式 GPU，S2 与 S1 分别运行在专用 GPU 上，这限制了在更简单硬件上的可移植性。

工程启示

对复现或下游团队，以下是最容易踩坑的点：

  1. 时间偏移校准是训练-部署一致性的关键：训练中 S1 与 S2 输入间的时间偏移必须精确匹配部署时的异步推理延迟。若偏移不准确，S1 接收的潜在向量可能与当前视觉输入不匹配，导致控制抖动。复现时应先测量 S2 在目标硬件上的实际推理延迟，再设定训练偏移。

  2. S1 视觉骨干的仿真预训练不可跳过：S1 的视觉骨干初始化来自完全在仿真中完成的预训练，这是 S1 能以 80M 参数实现 200 Hz 推理的基础。若直接随机初始化，可能无法在有限真实数据下收敛。

  3. 数据标注的提示词设计影响泛化：自动标注 VLM 使用“What instruction would you have given the robot to get the action seen in this video?”生成事后指令。提示词的质量直接影响 S2 的语义理解能力，复现时应验证标注 VLM 对动作意图的捕捉是否准确。

  4. “任务完成百分比”动作是序列化的关键：这个合成动作使模型能预测自身终止条件，从而串联多个学习行为。若忽略此设计，多步任务（如“递饼干后放回”）可能无法平滑衔接。

  5. 硬件选型需匹配双 GPU 部署：S2 与 S1 分别运行在专用 GPU 上，S2 为异步后台进程。若在单 GPU 上部署，需重新设计共享内存与调度机制，可能影响 200 Hz 控制循环的稳定性。

  6. 数据规模与泛化的关系需谨慎外推：Helix 在 500 小时数据下表现良好，但作者未报告扩展至 1,000 倍数据时的行为。下游团队不应假设线性扩展，应先在小规模数据上验证双系统架构的收益，再决定数据采集投入。
