摘要

DeepMind Control Suite 是由 DeepMind 开发的连续控制任务集合，基于 MuJoCo 物理引擎，提供标准化结构和可解释奖励，旨在作为强化学习智能体的性能基准。该套件包含多种学习算法的基准测试，并公开于 GitHub 仓库。

来源与参考

  • arXiv:1801.00690 DeepMind Control Suite
  • GitHub仓库 Robotics_Notebooks

概述

DeepMind Control Suite 是一个基于 MuJoCo 物理引擎的连续控制强化学习基准平台，由 DeepMind 团队开发，旨在提供一套稳定、统一、可解释的物理控制任务集。其核心贡献在于标准化了动作、观测和奖励结构，并提供了 A3C、DDPG、D4PG 三种基线算法的系统评估，填补了连续控制领域缺乏标准基准的空白。

它改变了什么

在 ALE 主导离散视频游戏基准、Gym 虽含连续域但结构松散的时代，Control Suite 真正改变了连续控制任务的评估范式。它不再将观测简单拼接为向量，而是分离具有物理单位的量（位置、速度、力），使学习曲线和奖励结构具有跨任务的统一语义——所有任务奖励范围在 [0,1]，评估片段固定 1000 步，最大分数恒为 1000，这让不同任务的性能可直接比较，而非像 Gym 那样各任务奖励尺度迥异、难以聚合。

更重要的是，作者将"任务可解性验证"提升为基准构建的核心环节。他们不是简单发布任务，而是用多种学习智能体迭代测试，确保物理模拟稳定、无"作弊"策略、且至少一个智能体能解决。这种"验证过的基准"理念，使得 Control Suite 成为后续算法比较的可靠起点，而非像某些 Gym 任务那样存在隐藏的脆弱性或非预期解。

方法拆解

任务架构

  • 所有任务用 Python 编写，由 MuJoCo 驱动，物理模型用 MJCF 定义
  • 域（物理模型）与任务（特定 MDP 结构）分离，任务按标签组织为 BENCHMARKING 和 EXTRA 元组

标准化设计

  • 动作：除 LQR 外，动作限制在单位盒 a ∈ [-1,1]^dim(A)
  • 观测：除 point-mass:hard 外，所有任务强可观测（状态可从单观测恢复），实现为 OrderedDict
  • 奖励：除 LQR 外，奖励 r(s,a) ∈ [0,1]，由 tolerance() 函数生成，支持稀疏（{0,1}）和平滑变体
  • 终止：无终止状态或时间限制，无限时域；实际用折扣公式 ∑γ^i r，γ = e^{-h/τ}

关键设计决策

  • 积分器选择：多数域用 MuJoCo 默认半隐式欧拉，少数平滑近能量守恒动力学用四阶龙格-库塔
  • Physics.step() 顺序：先 mj_step2（依赖控制）再 mj_step1（仅依赖状态），使位置/速度量与当前状态同步，力/加速度量与前一步转移同步
  • 初始化多样性：状态在子集初始化，避免单一状态导致"死记硬背"解
  • LQR 域：解析转移矩阵和 Riccati 最优策略，因控制和奖励无界而不在基准集

基线算法配置

  • A3C：32 workers，2 层 MLP（256 隐藏单元），RMSProp（α=0.99, ε=0.1），熵正则 β=3e-3，学习率从 5e-5 线性退火到 0
  • DDPG：actor 300→200，critic 400→300，Adam（η=1e-4），软更新 τ=1e-3，OU 噪声（θ=0.15, σ=0.3），replay buffer 1e6，minibatch 64
  • D4PG：32 CPU actors + 1 GPU learner，critic 值分布 101 类 [-150,150]，N-step N=5，非均匀采样 α=0.6，硬更新每 100 步，minibatch 256

关键创新

  1. 统一奖励结构：所有任务奖励在 [0,1]，配合固定 1000 步评估，使学习曲线 y 轴一致，可直接跨任务比较。这是 Gym 无法提供的——Gym 任务奖励尺度差异巨大，聚合性能无意义。

  2. 验证驱动的任务设计：作者用多种学习智能体迭代测试任务，确保物理稳定、不可利用、至少一个智能体能解决。这避免了基准任务"过易"（可作弊）或"过难"（无算法能解）的陷阱，是基准可信度的关键保障。

  3. 像素输入变体的系统评估：D4PG 像素变体提供 84×84 RGB 帧、2 层 ConvNet（3×3 核、32 通道、ELU、stride 2）、帧堆叠 3 个观测，并发现 actor-critic 共享卷积权重（仅 critic 优化器更新）显著优于分离网络。这为视觉控制任务提供了可复现的架构基线。

关键发现： - D4PG 在多数任务上最优，但 DDPG 在 1e7 步前数据效率更高 - 像素变体在 ball_in_cup、cartpole、reacher 上接近状态特征性能，但在 humanoid run、manipulator bring_ball 上完全失败（得分≈1） - A3C 在 humanoid run 上几乎无法学习（1.0±0.0），凸显连续控制对 off-policy 方法的依赖 - 24 小时训练后（表 2），D4PG 在 acrobot swingup 达 531.1±8.9，作者认为接近上界（摆起时间限制）

边界与局限

作者明确承认：同一算法在所有任务使用相同超参数，未做穷举优化，结果不应视为性能上限。像素变体在 swimmer、fish 等任务上完全失败，归因于相机视角不适合像素-only 方案。Control Suite 缺少四足 locomotion、完整操作任务和复杂地形，这些需要推理任务和模型分布。未包含交互式可视化器、C 回调、多线程动力学、TensorFlow op 包装器和 Windows 支持。评估方差受随机目标/初始化影响，未固定跨运行的初始化序列。论文未提及多任务学习、迁移学习、分层 RL 等扩展方向。

工程启示

复现时先核对三点：奖励范围（确认任务是否在 [0,1]，LQR 除外）、观测结构（OrderedDict 中物理量分离，勿拼接为向量）、积分器类型（半隐式欧拉 vs 四阶龙格-库塔，影响动力学精度）。最容易踩坑的是 D4PG 像素变体的共享权重设计——分离 actor/critic 网络性能显著更差，必须让 critic 优化器更新共享卷积层。A3C 在连续控制上表现极差（humanoid run 得分≈1），若你的算法是 on-policy 且无经验回放，预期在 Control Suite 上会遭遇类似困难。DDPG 的 OU 噪声参数（θ=0.15, σ=0.3）和软更新 τ=1e-3 是经过验证的默认值，改动需谨慎。评估协议固定 1000 步求和，最大 1000，但许多任务实际最大值远小于 1000（如 acrobot swingup 需多步摆起），比较时需注意任务的理论上界。
