摘要

GTSAM: Factor graphs for Sensor Fusion in Robotics is a 2026 work on state estimation for humanoid robots.

来源与参考

  • GTSAM: Factor graphs for Sensor Fusion in Robotics project page

概述

本文提出 WMBench 基准与 GigaWorld-1 世界模型，系统回答“如何构建可靠的世界模型策略评估器”这一核心问题。作者基于 2,989 对真实与 rollout 轨迹、324,000 个大规模 rollout 片段和 5,000+ 视频的人工标注，给出评估协议、指标体系与 VLM 辅助评估器，并揭示视觉保真度、几何与语义指标对评估器可靠性的不同贡献。

它改变了什么

机器人策略评估长期依赖真实世界 rollout，OpenVLA 报告 2,500 次 rollout 需 100 人工小时，且物理机器人无法在多次试验间保持一致的复位状态。经典仿真受 sim-to-real 差距限制，场景级数字孪生构建开销过高。现有文献仅证明世界模型可用于评估，但未回答哪些设计对构建可靠策略评估器至关重要。本文真正改变的是将“世界模型能否评估策略”这一定性问题转化为“如何系统度量评估器质量并定位关键设计选择”的可操作框架，并给出首个大规模基准与配套数据集。

方法拆解

形式化定义

世界模型作为策略评估器：给定初始观测、任务指令和可选机器人状态，预测未来观测（公式 2），迭代生成世界模型轨迹（公式 3）。核心评估目标用排序相关性衡量（公式 4：ρ = Corr(S^real(π), S^wm(π))）。

WMBench 基准构建

  • 数据来源：2,989 对轨迹，覆盖 8 个任务族（刚体和可变形操作），遥操作与 rollout 数据比例接近 1:1
  • 数据划分：严格保证 episode 不相交、多样性保持、结果平衡；过滤后训练集 82,470 秒，测试集 7,200 秒
  • 数据清洗：移除损坏/截断视频、相机失同步片段、缺失机器人状态轨迹、时间戳无法对齐片段

大规模 rollout 数据集

从 CVPR 2026 挑战赛 100+ 参赛团队提交中采样 324,000 个片段，闭环链接成完整 episode（每个约 20-30 个片段），采用四等级 WMES 人工标注（Score 3 结果正确高保真至 Score 0 结果错误低保真），每 rollout 由 3 名标注者独立评分，第 4 名资深标注者抽查。

四步评估协议

  1. 真实世界策略数据收集（多检查点、多视角、人工标注）
  2. 世界模型训练与严格留出（测试 episode 对象布局和初始状态严格留出）
  3. 世界模型内闭环 rollout（策略预测动作→世界模型预测观测→反馈给策略）
  4. 指标计算与结果评估（自动指标 + WMES 混合评估器）

指标系统

  • 结果评估：WMES
  • 诊断指标三族：帧与表示保真度（Image Quality、JEPA Similarity、Subject Consistency 等）、几何/语义/交互（Geometry Accuracy、Instruction Following、Trajectory Accuracy 等）、运动与长时程（Dynamic Degree、Flow Score、PSNR、FID、FVD）

VLM 辅助评估器

LoRA 微调 Qwen3-VL-8B-Instruct，rank 16、scaling factor 32、dropout 0.05，应用于注意力层。采用分数聚焦训练目标：总体分数 token 权重 8.0，格式 token 权重 1.0，自由形式推理 token 长度自适应权重最小 0.05。

关键创新

  1. 首个大规模世界模型评估基准：WMBench 提供 2,989 对配对轨迹与 324,000 个 rollout 片段，覆盖 8 个任务族，数据规模与多样性远超既有工作，且严格保证 episode 不相交与结果平衡。
  2. 四等级 WMES 评分体系：将结果正确性与保真度解耦（Score 3 正确高保真至 Score 0 错误低保真），配合 3+1 人工标注流程，为评估器质量提供可靠标注基础。
  3. VLM 辅助评估器与分数聚焦训练目标：通过 token 类型感知损失加权（分数 token 权重 8.0），解决标准语言建模目标对最终结果预测重视不足的问题，实现与人类专家排序近乎完美的一致性。

长时程评估

按 40 秒分块，使用 PSNR、FID/FVD；通用骨干模型后期出现视角漂移、对象身份崩溃和纹理累积，SVD 后期退化尤为严重。

边界与局限

  • 当前 VLM 无法足够稳健地判断物理真实性以进行细粒度评估器排序（Interaction Quality 不可靠的原因）
  • 不惩罚忽略动作的指标（如静态视频基线）会偏向退化世界模型而非正确建模物理交互的模型
  • 对大型视频基础模型进行受控预训练数据消融不现实，只能分析开源视频骨干的代表性集合
  • 计划评估 Cosmos-3，但其多视图版本尚未公开发布
  • AgiBot 数据多样性比 PhysData 窄，引入其他机器人形态的演示可能造成额外失配
  • 交叉注意力控制信号容易被外观和语义 token 淹没，导致动作控制效果不佳
  • 论文未明确提供传感器前端相关细节

工程启示

  • 复现时先核对数据划分是否严格保证 episode 不相交，这是评估器质量度量的前提；测试轨迹与训练数据重叠会直接污染排序相关性
  • 指标选择上优先采用 Subject Consistency（ρ = 0.88）、Perspectivity（ρ = 0.86）、Instruction Following（ρ = 0.84），避免使用 Background Consistency 与 Photometric Consistency（负相关）
  • 控制接口优先选择通道拼接（Traj. Acc. 0.3528），避免交叉注意力控制（Traj. Acc. 0.1620），后者信号易被外观 token 淹没
  • VLM 评估器训练时采用分数聚焦损失（分数 token 权重 8.0），并保留格式 token 权重 1.0 以维持可解析输出；推理 token 权重设下限 0.05 防止冗长解释主导优化
  • 长时程评估按 40 秒分块，注意 SVD 等骨干后期退化严重，需监控视角漂移与对象身份崩溃
  • 数据集开源在 Hugging Face（open-gigaai/CVPR-2026-WorldModel-Track-Dataset），累计超过 50,000 次下载，可直接用于下游评估
