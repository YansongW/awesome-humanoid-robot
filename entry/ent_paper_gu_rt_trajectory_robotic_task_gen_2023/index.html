RT-Trajectory

RT-Trajectory: Robotic Task Generalization via Hindsight Trajectory Sketches

摘要

RT-Trajectory 是 Google DeepMind 等机构于 2023 年提出的通用视觉-语言-动作模型，通过粗糙轨迹草图实现机器人操作任务泛化。其核心贡献在于将任务表示为轨迹草图，使策略能执行训练数据中未见过的新任务，并在真实世界任务中优于语言条件与目标条件策略。

来源与参考

  • RT-Trajectory source

概述

RT-Trajectory 是 Google 团队提出的机器人任务泛化框架，核心思想是用投影到相机平面的 2D/2.5D 轨迹草图替代语言或目标图像作为策略条件。该方法在 7 个未见任务上达到 67% 成功率，显著超越 RT-1（16.7%）和 RT-2（11.1%），证明了轨迹草图在表达力与易用性之间的有效平衡。

它改变了什么

机器人学习社区长期纠结于任务条件表示的选择：语言指令语义清晰但缺乏动作特异性，难以描述折叠毛巾这类精细操作；目标图像虽能捕捉细微差别，但训练困难且测试时获取成本高。RT-Trajectory 真正改变的是将“任务表示”从语义空间拉回到几何空间——它证明了一条粗略的 2D 轨迹草图足以引导策略完成未见任务，且这种表示与训练数据的相似性直接决定了泛化能力。这一转变的深层含义是：与其追求更强大的语义理解，不如让任务条件在结构上与演示数据更接近，从而让模型更自然地进行插值而非外推。

方法拆解

轨迹草图生成

  • 从演示数据中自动提取：利用本体感觉记录末端执行器 3D 位置，通过相机内外参投影到 2D 图像平面
  • 颜色编码双通道信息：
  • 红色通道：归一化时间步 \(\frac{t+1}{T}\)，表达运动速度与方向
  • 绿色通道：归一化高度 \(\frac{h_{t+1}-h_{min}}{h_{max}-h_{min}}\)（仅 2.5D 变体）
  • 交互标记：通过夹爪关节位置差 \(\delta_t = \hat{p}_t - p_t\) 判断接触，在闭合（绿圈）或张开（蓝圈）时绘制标记

策略架构

  • 基于 RT-1 的 Transformer 架构，行为克隆训练
  • 输入为 6 张历史 RGB 图像，轨迹草图沿特征维度拼接
  • 图像分词器：ImageNet 预训练 EfficientNet-B3，第一卷积层新增权重初始化为零
  • 移除 FiLM 层（因不使用语言指令）

推理时轨迹来源（4 种）

  1. 人类 GUI 绘制：用户直接在相机图像上画曲线并标注夹爪动作
  2. 人类演示视频：Mediapipe 估计手部姿态，深度图提升到 3D，插值得到末端执行器轨迹
  3. LLM 提示（Code as Policies）：GPT-4 根据场景文本描述生成代码，输出 3D 姿态序列
  4. 图像生成模型：PaLM-E 风格模型生成 ViT-VQGAN token，解码为轨迹图像

关键创新

  1. Hindsight 轨迹标签的自动提取：无需人工标注，直接从演示数据中通过本体感觉投影生成训练标签，使得大规模数据集的轨迹条件训练成为可能。这一设计将轨迹草图的生成成本降为零，是方法可扩展性的关键。

  2. 2.5D 高度编码解决视觉歧义：2D 轨迹在区分“手臂伸向更深处”与“抬得更高”时存在本质歧义，绿色通道的高度归一化编码有效消解了这一问题（附录 E.3 的实验对比清晰展示了 2D 与 2.5D 的行为差异）。这一设计选择直接贡献了 67% 对 50% 的成功率提升。

  3. 任务表示与训练分布的相似性理论：论文明确提出“如果任务表示与训练任务相似，模型更可能插值而非外推”，并通过 Fréchet 距离分析验证了未见技能查询轨迹与训练轨迹的分布差异。这一视角将泛化问题重新定义为表示空间的距离控制问题，为后续工作提供了理论框架。

关键发现：RT-Trajectory 在 6/7 个未见任务上显著超越所有基线，尤其在 Fold Towel（75% vs 0%）和 Move within Drawer（100% vs 33%）上表现突出。LLM 生成的轨迹在 Pick 任务上接近人类绘制效果，但 Open Drawer 任务上（60% vs IK Planner 71%）略逊，说明轨迹质量对任务类型敏感。

边界与局限

  • 论文明确假设机器人基座静止，仅末端执行器执行操作，未扩展到全身移动操作场景
  • 轨迹草图无法表达“某些区域需更严格遵循”的约束（如避开易碎物体），用户无法指定局部控制权重
  • 图像生成模型产生的轨迹噪声较大且与训练分布差异明显，虽表现合理但非最优
  • 所有实验在 Everyday Robots 平台完成，未验证在其他机械臂构型上的迁移性
  • 评估场景虽包含新建筑、新物体，但未涉及动态环境或人类干扰的鲁棒性测试

工程启示

复现时优先核对三点：第一，相机标定精度直接影响轨迹投影质量，论文假设基座与相机在 episode 内静止，实际部署时需确保这一条件成立；第二，2.5D 变体的高度编码依赖准确的基座坐标系高度估计，建议先验证绿色通道的归一化范围是否覆盖实际工作空间；第三，训练时第一卷积层零初始化是保证轨迹条件有效注入的关键，若修改架构需重新验证这一设计。最容易踩坑的是推理时轨迹生成的质量控制——人类绘制草图时需注意 GUI 的交互标记（夹爪闭合/张开）必须与任务关键动作对齐，否则策略可能忽略轨迹引导。对于下游团队，建议从 2.5D 变体入手，并在未见任务上先验证轨迹与训练分布的 Fréchet 距离，距离过大时需考虑增加演示数据或调整轨迹生成方式。
