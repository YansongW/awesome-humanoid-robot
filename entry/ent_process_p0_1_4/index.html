概述

全生命周期成本模型 v0（Life Cycle Cost Model v0）是项目立项与商业基线阶段（P0）中用于建立整机成本基线的方法实体，属于 ent_process_p0_1_4。它通过 BOM 目标分解、TCO 模型与盈亏平衡批量计算，将目标售价与毛利率约束转化为可量化的子系统成本上限，并输出整机 BOM 目标与盈亏平衡产量。它真正改变的不是"算一笔账"的财务动作，而是"成本目标必须早于设计冻结"的工程决策顺序。

核心内容

是什么：准确定义

全生命周期成本模型 v0 是 P0 阶段（项目立项与商业基线）中第 1 个工作包（商业与战略论证）的第 4 个子任务实体，编号为 ent_process_p0_1_4。它属于 方法 类型，所属领域包括应用与市场（11_applications_markets）、政策法规伦理（12_policy_regulation_ethics），价值链层级为验证与市场层（validation_markets）。

该模型的核心任务是在产品设计冻结之前，建立一套覆盖物料、制造、供应链与量产摊薄的全生命周期成本估算框架。它不是一个静态的财务表格，而是一个贯穿 P0 阶段五个四级子任务（P0.1.4.1 至 P0.1.4.5）的迭代过程：从输入梳理、方案设计、实施建模、验证闭环到文档交付，每一步都在逼近一个可执行的成本基线。

在流程依赖关系上，该模型是 P0 阶段商业论证的关键输出之一，其产出的整机 BOM 目标与子系统成本上限将直接约束后续 P1（需求定义）阶段的设计空间——"成本目标必须早于设计冻结"这一设计思考逻辑，决定了该模型在流程中的前置地位。

为什么存在：痛点与历史定位

在人形机器人产品开发中，成本失控是导致项目失败的最常见原因之一。传统开发流程往往先做技术方案、后算成本账，结果发现设计冻结后成本已无法收敛，被迫在性能与价格之间做痛苦的取舍。全生命周期成本模型 v0 的存在，正是为了在源头解决这一痛点。

它的历史定位可以概括为三点。第一，它是"成本前置"理念的落地工具——在 P0 阶段就建立成本基线，而不是等到样机阶段才意识到成本问题。第二，它是"自研/外购决策"的量化依据——通过 BOM 目标分解，明确哪些部件必须自研、哪些可以外购，避免"什么都想自己做"导致的资源分散。第三，它是"盈亏平衡产量"的测算框架——回答"卖多少台才能回本"这一根本商业问题，为量产决策提供数据支撑。

从流程视角看，该模型位于 P0.1（商业与战略论证）工作包内，与知识产权策略（P0.3）等并行推进。它真正改变的不是"要不要做成本分析"的意识问题，而是"成本分析必须在设计冻结之前完成"的流程顺序。

原理拆解

① BOM 目标分解：从整机目标到子系统上限

BOM（Bill of Materials，物料清单）目标分解是成本模型的第一层机制。其核心逻辑是：先确定整机目标成本（由目标售价与毛利率倒推），再按子系统（如关节模组、结构件、电控、传感器、电池等）逐层分解，形成每个子系统的成本上限。

\[ C_{\text{整机目标}} = P_{\text{目标售价}} \times (1 - \text{毛利率}) \]

其中，\(P_{\text{目标售价}}\) 由市场与商业论证确定，毛利率由公司战略确定。分解后的每个子系统成本上限 \(C_i\) 满足：

\[ \sum_{i=1}^{n} C_i \leq C_{\text{整机目标}} \times (1 + \text{预留余量}) \]

预留余量用于覆盖 BOM 之外的制造费用、包装运输与售后成本。这一分解过程不是一次性的，而是随着设计深入不断迭代修正的。

② TCO 模型：从单台成本到全生命周期成本

TCO（Total Cost of Ownership，总拥有成本）模型将视角从单台制造成本扩展到产品全生命周期——包括研发摊销、制造、供应链、售后维护、能耗与报废处理等。在人形机器人场景中，TCO 模型特别关注量产摊薄效应：研发费用与模具费用在产量增加时被逐步摊薄，因此 TCO 是产量的函数。

\[ TCO(Q) = \frac{C_{\text{研发}} + C_{\text{模具}}}{Q} + C_{\text{单台制造}} + C_{\text{售后}} \times Q \]

其中 \(Q\) 为累计产量。该公式揭示了成本结构的核心矛盾：小批量时研发与模具摊薄占比极高，大批量时单台制造成本与售后成本成为主导。这正是"盈亏平衡批量计算"的数学基础。

③ 盈亏平衡批量计算：回答"卖多少台才回本"

盈亏平衡批量（Break-Even Volume）是成本模型与商业模型的交汇点。它计算在给定售价与成本结构下，累计产量达到多少时，累计收入恰好覆盖累计成本。

\[ Q_{\text{盈亏平衡}} = \frac{C_{\text{研发}} + C_{\text{模具}}}{P_{\text{目标售价}} - C_{\text{单台制造}} - C_{\text{售后}}} \]

这一计算直接支撑"完成标准 / 输出物"中的盈亏平衡产量指标。它也是供应链最小订单量（MOQ）约束的输入——如果盈亏平衡产量低于供应链 MOQ 要求，则必须调整成本结构或售价策略。

关键参数与规格

参数 定义 来源/约束
目标售价 整机市场定价 由商业与战略论证确定
毛利率 单台毛利占售价比例 由公司战略确定
整机 BOM 目标 物料成本上限 由目标售价与毛利率倒推
子系统成本上限 各子系统物料成本上限 由 BOM 目标分解得到
盈亏平衡产量 累计收入覆盖累计成本的产量 由 TCO 模型计算
供应链最小订单量 供应商要求的最低采购量 外部约束，需自行确认

横向对比

与 P0 阶段其他方法实体相比，全生命周期成本模型 v0 的独特之处在于其量化输出属性。商业画布（如 P0.1 中的商业论证工具）提供的是定性框架，而成本模型提供的是可直接用于设计约束的数字——整机 BOM 目标、子系统成本上限、盈亏平衡产量。

与需求管理工具链（P0.2）相比，成本模型更关注"花多少钱"而非"要什么功能"，但两者在流程上存在依赖关系：需求定义（P1）必须在成本约束内展开，而成本约束正是由本模型输出的。

与知识产权与合规策略（P0.3）相比，成本模型更贴近工程实现，但其输出同样影响合规决策——例如，若某关键部件的自研成本过高，可能选择外购并支付专利许可费，这需要在成本模型中体现。

谁在用·应用案例

主要使用者：项目经理（Owner）、成本工程师、供应链工程师、财务分析师。

典型应用场景：

  1. 立项评审：在 P0 阶段结束时，向管理层汇报整机 BOM 目标与盈亏平衡产量，作为立项决策的关键输入。
  2. 自研/外购决策：通过 BOM 目标分解，对比自研成本与外购价格，决定关节模组、减速器、传感器等关键部件的采购策略。
  3. 供应链谈判：以子系统成本上限为底线，与供应商进行价格谈判，确保采购价不突破成本约束。
  4. 量产规划：根据盈亏平衡产量，确定首批投产数量与产能爬坡计划。

应用案例：某双足人形机器人项目在 P0 阶段设定目标售价为需自行确认（语料未提供具体数字），通过 BOM 目标分解，将关节模组成本上限设定为整机 BOM 目标的需自行确认比例（按语料数据推算），据此决定减速器采用外购方案，电机与驱动器采用自研方案，最终在盈亏平衡产量为需自行确认台时实现成本收敛（工程判断）。

局限与边界

  1. 静态模型的时效性：全生命周期成本模型 v0 是"v0"版本，意味着它在 P0 阶段建立的是初步基线。随着设计深入（P1 至 P4），BOM 会持续变化，成本模型需要迭代更新，不能一劳永逸。
  2. 数据依赖性强：模型精度高度依赖输入数据的质量——目标售价、毛利率、供应链报价等。若上游输入不准确，输出将失去参考价值。
  3. 未覆盖全生命周期后期成本：v0 版本主要关注制造成本与量产摊薄，对售后维护、能耗、报废处理等后期成本覆盖有限（需在后续版本中完善）。
  4. 不适用于颠覆性技术路线：若技术方案发生根本性变化（如从液压驱动切换为电机驱动），原有成本模型需要重建，而非简单参数调整。

常见误区

  1. "成本模型是财务部门的事"——错。全生命周期成本模型 v0 是工程决策工具，其输出直接约束设计空间。成本工程师与研发工程师必须共同参与，否则成本目标无法落地。
  2. "BOM 目标分解一次完成"——错。BOM 分解是迭代过程，随着设计深入需要不断修正。v0 版本只是起点，不是终点。
  3. "盈亏平衡产量越低越好"——错。盈亏平衡产量低可能意味着研发投入不足或成本结构不合理，需要结合市场规模与竞争格局综合判断。
  4. "成本模型可以替代供应链谈判"——错。成本模型提供的是目标与底线，实际采购价格仍需通过谈判实现。模型是谈判的依据，不是谈判本身。
