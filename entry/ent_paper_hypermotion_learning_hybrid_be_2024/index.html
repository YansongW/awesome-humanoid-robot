HYPERmotion｜学习自主移动操作的混合行为规划

HYPERmotion: Learning Hybrid Behavior Planning for Autonomous Loco-manipulation

层级

摘要

HYPERmotion 先从语言指令、相机图像/多视角观测、本体状态与关节序列恢复场景、目标或运动表征，再用PPO/RL 策略训练、VLM 语义规划/路由、全身控制器/WBC/MPC生成可执行动作命令。关键点是把任务拆成可路由的技能或专家策略，再用高层模块在执行中选择和组合。

来源与参考

  • HYPERmotion project page

概述

HYPERmotion 是意大利理工学院（IIT）提出的类人机器人全身自主操作框架，将强化学习（RL）与全身模型预测控制（MPC）结合，为 37 个驱动关节生成运动，并利用大语言模型（LLM）构建分层任务图、视觉语言模型（VLM）驱动形态选择器，实现从自由文本指令到非结构化场景任务执行的闭环。核心贡献在于将技能学习、在线规划与形态选择统一在一个可扩展的框架中，覆盖单臂/双臂、腿式/轮式等多种运动模式。

它改变了什么

现有类人全身控制方法在演示特定技能时表现惊艳，但一旦任务变化或场景非结构化，往往需要重新训练或手工调整，缺乏面向新任务的即插即用能力。HYPERmotion 真正改变的，是把“学过的技能”变成“可被在线调度的资源”——通过运动库存储技能、LLM 做高层任务分解、VLM 做形态选择，让机器人面对长时域任务时不再依赖预先编排的固定流程，而是根据指令和视觉反馈动态组合已有能力。

这一转变的实质，是将传统“端到端学习一个策略”的思路，替换为“学习一组可复用的行为原语 + 在线规划如何组合它们”。对工程实践而言，这意味着新任务不再需要从头训练，而是从库中检索、组合、微调，显著降低了部署成本。同时，LLM 输出可缓存、闭环视觉反馈可触发重规划，使得系统对在线扰动具备鲁棒性——这是以往纯 RL 或纯 MPC 方案难以兼顾的。

方法拆解

框架四模块

  • 运动生成：用 RL 训练全身运动技能（如开门、抓取、放置），训练完成后存入运动库；MPC 负责在 37 个驱动关节上生成平滑、满足动力学约束的轨迹。
  • 用户输入：接收自由文本指令（如 "Open the drawer and pick up the mustard"）与初始化提示集，作为高层规划的输入。
  • 任务规划：LLM 将指令分解为分层任务图（hierarchical task graph），图中节点为原始行为（primitive behaviors），边为执行顺序；生成的代码在整个任务中保持不变，因此可缓存 LLM 输出，并利用闭环视觉反馈重新评估代码，通过 MPC 实现快速重规划。
  • 形态选择器：基于 VLM 蒸馏的空间几何与 2D 观测，结合机器人内在特征（如关节配置、运动模式），为每个子任务选择单臂/双臂、腿式/轮式等合适形态。

关键设计决策

  • RL + MPC 混合：RL 负责学习高维非线性技能（如抓取策略），MPC 负责保证全身动力学可行性与平滑性，二者互补。
  • LLM 输出缓存：由于任务级规划在整个执行过程中不变，缓存可避免重复推理，同时保留对扰动响应的重规划能力。
  • VLM 落地知识：将空间几何与 2D 观测蒸馏为形态选择依据，避免手工设计规则，使选择过程可泛化到新场景。

参数与细节

  • 机器人：37 个驱动关节的类人平台（IIT）。
  • 训练配置、数据量、推理频率、硬件规格：论文未明确。

关键创新

  1. 技能库 + 在线规划的统一框架：以往工作要么专注技能学习（RL），要么专注规划（MPC/LLM），HYPERmotion 首次将两者以“运动库 + 分层任务图”的形式耦合，使新任务可通过组合已有技能完成，而非重新训练。
  2. LLM 输出缓存 + 闭环重规划机制：利用任务级规划不变性缓存 LLM 输出，同时保留视觉反馈触发的重规划路径，兼顾了推理效率与在线鲁棒性——这是对 VoxPoser 类方法的直接改进。
  3. VLM 驱动的形态选择器：将空间几何与 2D 观测蒸馏为形态决策依据，使机器人能在单臂/双臂、腿式/轮式之间自主切换，扩展了任务覆盖范围，且无需人工标注形态标签。

工程启示

  • 复现前先核对运动库规模与技能覆盖：框架效果高度依赖运动库中技能的质量与多样性，若库中缺乏目标任务的相似技能，LLM 分解出的任务图可能无法执行。
  • LLM 输出缓存是双刃剑：缓存可提速，但若场景动态变化超出视觉反馈可检测范围，缓存的任务图可能失效；需确认重规划触发条件（如检测到碰撞、目标位移）是否覆盖实际扰动类型。
  • 形态选择器的输入依赖 VLM 蒸馏质量：2D 观测与空间几何的蒸馏结果直接影响形态选择，建议在部署前针对目标场景的物体类别与布局做 VLM 微调或提示工程。
  • 最容易踩坑的点：37 个关节的 MPC 实时性——论文未明确 MPC 求解频率与计算平台，若下游团队使用较低算力硬件，需先验证 MPC 能否在控制周期内完成求解，否则需降维或简化动力学模型。
  • 代码与数据：代码即将发布（Code coming soon），数据已公开；复现时优先核对数据格式与运动库的存储结构，避免因接口不匹配浪费调试时间。
