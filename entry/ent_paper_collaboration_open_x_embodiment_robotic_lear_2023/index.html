RT-X

Open X-Embodiment: Robotic Learning Datasets and RT-X Models

摘要

Open X-Embodiment 是由 21 个机构合作构建的机器人学习数据集与 RT-X 模型，发表于 ICRA 2023。其核心贡献是整合了 22 种不同机器人的 527 项技能（160266 个任务），并训练出通用型 X-robot 策略 RT-X，证明了跨平台经验迁移能提升多机器人操作能力。

来源与参考

  • RT-X source

概述

本文提出 Hiveformer，一个面向机器人操作的多视角、历史感知、指令条件化 transformer 架构，在 RLBench 基准上显著超越先前方法。核心贡献在于通过交叉注意力机制分离建模视觉-指令与视觉-历史关系，并引入当前观察掩码训练策略，有效提升长时任务与多任务泛化能力。

它改变了什么

机器人操作学习长期受困于两个问题：一是现有方法（如 CLIPort、BC-Z）将指令压缩为全局向量，丢失物体级细粒度信息；二是策略仅依赖当前观察，无法处理对象状态隐藏或需记忆先前动作的顺序任务。Hiveformer 改变了这一局面——它不再将历史视为可选的辅助输入，而是通过架构设计将其变为一等公民，同时用交叉注意力替代自注意力来显式区分“指令-视觉”与“历史-视觉”两类关系，这比单纯堆叠 transformer 模块更具针对性。

方法拆解

架构总览

Hiveformer 由特征编码、多模态 transformer、动作预测三部分组成。

特征编码

  • 指令：冻结的 CLIP 语言编码器，逐词输出 token 嵌入（线性层投影）。选择 CLIP 而非 BERT，因其视觉-语言预训练更擅长区分颜色等视觉语义。
  • 观察：每个相机分别编码 RGB（与二进制夹爪注意力图通道拼接）经 UNet 编码器得特征图，再与均值池化后的点云通道拼接。UNet 编码器 6 层卷积，前两层步长 1（输出通道 8、16），后四层步长 2（输出通道 16），图像 128×128×3 编码为 8×8×16 特征图。
  • 视觉 token：每个 patch 添加相机 ID、步骤 ID、patch 位置、视觉类型四种嵌入。

多模态 transformer

  • 交叉注意力层：学习当前视觉 token 与指令 token、历史上下文 token 的关系。
  • 自注意力层：学习多相机视角 patch token 间关系。
  • 前馈网络。 设计理由：先前工作用自注意力捕获所有关系，Hiveformer 用不同注意力层捕获不同类型关系，强化上下文重要性。

动作预测

  • 位置：分解为点云上的期望点与偏移量之和。偏移量由指令预测任务 ID，结合可学习任务-步骤嵌入获得。
  • 旋转与夹爪：CNN 解码器回归 5 维向量（4 维四元数 + 1 维夹爪状态）。CNN 两层卷积（3×3 核、步长 2、输出通道 64），后接组归一化、LeakyReLU、平均池化、前馈网络。
  • 训练损失：行为克隆，夹爪动作 MSE 与任务分类 CE 之和。
  • 当前观察掩码：训练时以 0.1 概率随机掩码当前观察 patch 特征，强制模型利用历史。

关键创新

  1. 交叉注意力替代自注意力：将“指令-视觉”与“历史-视觉”关系分离建模，消融显示带来 3.8% 绝对增益（88.4 vs 84.4）。这是对“所有关系一视同仁”范式的直接挑战，且更符合认知直觉。
  2. 当前观察掩码训练：以 0.1 概率随机遮蔽当前观察 patch，迫使模型在训练期就依赖历史上下文，而非仅在测试时被动使用。这一简单策略带来 0.5% 增益，且对长时任务（如 Long Term 类别）尤为关键。
  3. patch token 化：将通道 token 改为 patch token，使视觉特征保留空间结构，消融增益 2.2%。这比全局池化更利于细粒度定位任务。

边界与局限

  • 长时任务：超过 10 步的任务（如 "take shoes out of box"）表现差，因平均步数比其他任务高 2-4 倍，易受分布偏移和累积误差影响。层次化建模或 RL、dagger 留作未来工作。
  • 人类指令：仅用合成指令训练，在人类书写指令上表现较差；未在人类指令上微调，论文指出微调预期可改进。
  • 计算成本：transformer 序列长度增加时计算成本二次方增长。
  • 暴露偏差：行为克隆可能遭受暴露偏差问题。
  • RLBench 任务覆盖：106 个支持任务中仅 74 个可生成演示，32 个因脚本或运动规划器问题被排除。

工程启示

复现时先核对三处：一是 UNet 编码器输出通道数与 patch 位置嵌入维度是否匹配（128×128 输入对应 8×8 特征图）；二是宏步定义（夹爪状态改变或关节速度接近零）是否与你的控制器一致，这直接影响历史长度与训练效率；三是运动规划器——论文用最多 10 次不同种子重试来规避 RLBench 默认规划器失败，若你的环境规划器不稳定，需同样处理否则成功率会虚低。最容易踩坑的是当前观察掩码概率 0.1 与历史窗口长度的配合，掩码过小模型仍会偷懒只看当前帧，过大则训练不稳定。真实机器人迁移时，预训练权重在 unseen 变体上带来 72.4% 绝对提升（由 85.7 与 13.3 计算），但需注意论文用 6-DoF UR5 与 2 指夹爪，若你的机械臂自由度或夹爪不同，需重新微调。
