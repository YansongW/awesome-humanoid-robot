Stabilizing Humanoid Robot Trajectory Generation via Physics-Informed Learning

Stabilizing Humanoid Robot Trajectory Generation via Physics-Informed Learning

摘要

这是一项2025年关于双足人形机器人运动轨迹生成的研究，由研究团队提出。核心贡献在于通过物理信息学习策略，在模仿学习过程中融入物理先验知识，并利用比例-积分控制器减少推理时的轨迹漂移，从而提升生成轨迹的稳定性和物理约束符合度。

来源与参考

  • Stabilizing Humanoid Robot Trajectory Generation via Physics-Informed Learning (arXiv)

概述

该研究针对类人机器人模仿学习轨迹生成中物理保真度不足与输入跟随性差的问题，提出在Mode-Adaptive Neural Networks（MANN）框架上引入物理信息（PI）损失与基于控制的校正块。核心贡献在于无需重新训练或修改架构，即可显著降低支撑脚滑动与轨迹漂移，提升生成轨迹的物理可行性。

它改变了什么

现有基于MANN的轨迹生成仅依赖数据拟合损失（MSE），完全忽略物理约束，导致生成轨迹在机器人执行时出现支撑脚滑动和整体漂移。这本质上是监督学习在回归高维运动状态时，缺乏对接触动力学约束的显式建模，使得输出在数学上最优但在物理上不可行。作者真正改变的是将物理约束从“事后修正”前置为“训练目标的一部分”，同时引入一个轻量级控制闭环在推理时抑制累积误差，从而在不改变学习架构的前提下，显著提升轨迹的物理一致性与控制器的可接受度。

方法拆解

架构与输入输出

  • 采用MANN，含门控网络（Mixture of Experts，K=4）与运动预测网络。
  • 输入特征 x_i ∈ R^{2n+78}：12维基座线/角速度（体坐标系，6 Hz采样，2秒窗口）、关节位置/速度、基座位置/姿态。
  • 输出 y_i ∈ R^{2n+48}：7维未来基座速度（1秒窗口）及完整3D运动学状态（区别于先前仅地面投影的工作）。

物理信息损失

  • 接触脚滑动约束：v_SF = J_SF ν = [J_SF^B J_SF^ṡ] [v_B; ṡ] = 0，其中 J_SF^B 为上三角块矩阵且对角块为旋转矩阵，保证可逆。
  • PI损失形式： L_B(x;θ) = || [v̂_{I,B}^B; ω̂_{I,B}^B] + [α(J_LF^B)^{-1}J_LF^ṡ + (1-α)(J_RF^B)^{-1}J_RF^ṡ] ŝ̂ ||^2 其中 α∈{0,1} 指示支撑脚。
  • 总损失：L = L_D + w L_B，设置 w_D = 1 简化调参。

控制信息校正块

  • 线性速度控制器：v_{I,B}^c^B = v̂_{I,B}^B - k_0 (R_B^I)^T (p_B^I - p_B^d^I)
  • 角速度控制器：ω_{I,B}^c^B = ω̂_{I,B}^B - k_1 skew(R_B^d^T^I R_B^I)^∨
  • 该校正块在推理时闭环修正速度指令，不参与训练，直接抑制漂移。

关键创新

  1. 物理约束嵌入损失函数：将接触脚零速度约束以可微形式加入训练目标，使网络在参数更新时主动学习满足物理可行性的映射，而非依赖后处理。这是对纯数据驱动IL的关键补强。
  2. 无需重训的推理时校正：控制信息校正块作为即插即用模块，在推理阶段修正速度指令，与训练解耦。这为现有IL模型提供了一条低成本、低风险的物理一致性增强路径。
  3. 完整3D状态输出：相比先前仅输出地面投影，本工作输出完整基座姿态与位置，使下游控制器（如DCM、MPC）能直接使用，扩展了IL轨迹的适用范围。

实验与结果

实验基于ergoCub机器人（160 cm，56 kg，n=26关节），训练数据约200000点（50 Hz，30分钟多方向人类运动，镜像增强）。

边界与局限

论文未明确说明以下边界：仅验证了一种PI实现类型（接触脚零速度约束），未探索其他物理先验（如地面反作用力、动态稳定性）。需要后处理网络输出以采样其他控制层所需的接触点，增加了系统复杂度。结论基于单一机器人平台（ergoCub）与特定数据采集方式（XSens），对其它构型或数据源的泛化性未验证。w=100 时模型无法行走，表明PI权重过大可能导致过约束，参数选择敏感。

工程启示

复现或应用时，首先核对数据预处理：输入中基座速度采样频率为6 Hz（2秒窗口），输出为1秒窗口，降采样到50 Hz训练。训练配置为4个专家、150 epoch、门控网络32神经元、预测网络512神经元、AdamW优化器，单张RTX 3050 Ti耗时约24小时。最易踩坑的是PI权重 w 的调节：从 w=10 起步，若出现行走不稳定则降低，若滑动未有效抑制则微增，避免直接使用 w=100。推理时务必启用控制校正块，否则高 w 下轨迹可能退化。下游团队集成时，需注意输出为完整3D状态，可直接对接DCM或MPC控制器，但需自行实现接触点采样逻辑。代码与数据已开源，建议先复现基线（w=0）再逐步引入PI损失，以隔离变量影响。
