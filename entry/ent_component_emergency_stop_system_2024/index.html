摘要

操作员或故障触发时立即切断电源或命令安全状态的硬接线安全电路。

来源与参考

  • Emergency Stop System

概述

急停系统（Emergency Stop System）是一种由操作员或故障触发时立即切断电源或命令安全状态的硬接线安全电路。它不依赖软件逻辑或通信总线，而是通过独立的物理回路直接作用于接触器或驱动器使能端，是人形机器人功能安全架构中的最后一道防线。它真正改变的不是“停机速度”，而是“故障时系统行为是否可预测”。

核心内容

是什么：急停系统的准确定义

急停系统（Emergency Stop System，简称 E-Stop）属于 零部件（component） 类型，英文名称为 Emergency Stop System，所属领域包括零部件（02_components）与政策法规伦理（12_policy_regulation_ethics），价值链层级覆盖上游（upstream）与验证市场层（validation_markets）。

从功能安全的角度，急停系统是一种硬接线安全电路：它由急停按钮、安全继电器、接触器、电源切断回路及状态反馈触点组成，当操作员按下急停按钮或系统检测到故障信号时，直接切断执行器的动力电源或命令驱动器进入安全状态。其核心特征是独立性——急停回路不依赖主控制器、不依赖操作系统、不依赖通信总线，即使主控完全失效，急停系统仍能独立完成安全动作。

在人形机器人产业链中，急停系统属于第 4、5、6 章所覆盖的 component 实体类型，与执行器、传感器、计算单元等硬件并列。按第 2 章的本体论分类，它属于物理实体（Physical Entity），具有质量、能量和空间属性，其类层次可形式化表示为：

\[\mathcal{A}(e) = \{ \text{emergency\_stop\_system}, \text{component}, \text{physical\_entity}, \text{entity} \}\]

这一分类结构意味着：若本体规定 component 必须具有 mass 属性，则所有急停系统实体自动继承该约束（继承推理）。

为什么存在：痛点与历史定位

急停系统的存在源于一个朴素的工程事实：软件会崩溃，但物理定律不会。在人形机器人中，主控制器可能因内存溢出、算法死循环、电源波动或电磁干扰而失效；通信总线可能因线缆断裂、连接器松动或协议错误而中断。在这些场景下，如果安全功能完全依赖软件实现，故障发生时系统将处于“无人驾驶”状态——这正是急停系统要消除的盲区。

从历史定位看，急停系统源自工业机械安全实践，其设计理念可追溯至机床、工业机器人和自动化产线的安全标准体系。在人形机器人领域，急停系统被纳入从设计到认证的链路中：

安全原理 → 功能安全标准 → 安全设计 → 急停系统 → 机器人 → CR/CE 认证

这条链路（见第 2 章链路 3）表明，急停系统不仅是硬件零部件，更是连接安全设计与整机认证的关键环节。没有符合标准的急停系统，人形机器人无法通过 CR/CE 认证，也就无法进入市场。它真正改变的不是“停机方式”，而是“安全责任从软件转移到了硬件”。

原理拆解

① 硬接线回路：不经过软件的物理直连

急停系统的核心是一条独立的硬接线回路。典型拓扑为：急停按钮（常闭触点）串联安全继电器线圈，安全继电器的输出触点串联接触器线圈，接触器的主触点串联在电机驱动器的动力电源线上。当急停按钮被按下时，常闭触点断开，安全继电器失电，其输出触点断开，接触器线圈失电，主触点切断动力电源。

这条回路的关键在于不经过任何可编程器件。信号路径为：

急停按钮 → 安全继电器 → 接触器 → 动力电源切断

每一级都是机电元件，响应时间由机械动作时间和触点断开时间决定，通常在毫秒级。与之对比，软件急停的路径为“传感器 → 主控 → 驱动器 → 电机”，中间经过 AD 采样、协议解析、控制周期调度，延迟可达数十毫秒甚至更长。

② 双通道与反馈监控：冗余设计的物理基础

工业级急停系统通常采用双通道结构：两个独立的急停按钮触点串联，或同一按钮的两组常闭触点分别接入两个安全继电器通道。双通道的意义在于单点故障不会导致安全功能丧失——如果一个通道因触点粘连而失效，另一个通道仍能切断电源。

同时，安全继电器会监控自身触点状态：如果检测到触点粘连或回路断线，会进入故障安全状态并输出诊断信号。这一机制可用状态机描述：

\[ S = \begin{cases} \text{RUN} & \text{若 } C_1 \land C_2 \text{ 均闭合} \\ \text{TRIP} & \text{若 } C_1 \lor C_2 \text{ 断开} \\ \text{FAULT} & \text{若 } C_1 \neq C_2 \text{（不一致）} \end{cases} \]

其中 \(C_1\)、\(C_2\) 为两个通道的触点状态。当两通道状态不一致时，系统判定存在故障并进入 FAULT 状态，防止因单通道失效而丧失保护。

③ 与安全 MCU 的协同：分级安全架构

在高端人形机器人中，急停系统并非孤立工作，而是与安全 MCU（如 ent_component_safety_mcu）协同构成分级安全架构。急停系统负责最高级别的“硬切断”，安全 MCU 负责次级别的“软停止”——即通过通信总线向驱动器发送安全停止指令，使电机按受控减速度停机。

两级架构的配合逻辑为：正常运行时，安全 MCU 持续监控关节状态；当检测到异常但未达到急停阈值时，执行软停止；当操作员按下急停按钮或安全 MCU 判定需要立即切断时，硬接线回路直接切断动力电源。这种分级设计在“保护人身安全”与“避免不必要的停机”之间取得平衡。

关键参数与规格

急停系统的选型需要关注以下关键参数（具体数值需根据所选型号确认，以下为工程判断的典型范围）：

参数 说明 典型范围（工程判断）
触点额定电流 接触器主触点可安全切断的电流 10–100 A
响应时间 从按钮按下到电源切断的总延迟 10–50 ms
机械寿命 按钮可操作次数 10 万–100 万次
电气寿命 触点带载分断次数 1 万–10 万次
防护等级 按钮防尘防水能力 IP65–IP67
工作温度 安全继电器与接触器的环境温度范围 −25°C 至 +70°C
安全等级 符合的功能安全标准 ISO 13849 PL d/e 或 IEC 61508 SIL 2/3

选型时需综合考虑：机器人整机功率决定接触器额定电流；关节数量与驱动器类型决定需要切断的电源回路数；应用场景（实验室/工厂/家庭）决定防护等级与安全等级要求。此外，急停按钮的安装位置与数量需符合人机工程学——操作员在紧急情况下应能在 1 秒内触及。

横向对比

急停系统与相近概念的对比如下：

维度 急停系统（E-Stop） 软停止（Soft Stop） 安全力矩关断（STO）
实现方式 硬接线电路，独立于主控 软件指令，依赖主控与通信 驱动器内部硬件逻辑
切断对象 动力电源（接触器） 电机力矩指令 驱动器功率级输出
响应速度 毫秒级（机械触点） 数十毫秒（软件周期） 微秒级（硬件逻辑）
独立性 完全独立 依赖主控 依赖驱动器
恢复方式 手动复位 软件复位 手动或软件复位
适用层级 整机级 关节级 关节级

三者并非互斥，而是互补关系。完整的安全架构通常同时包含三者：急停系统负责整机断电，软停止负责受控减速，STO 负责驱动器级的快速切断。急停系统的独特价值在于其最高级别的独立性——它是唯一不依赖任何可编程器件的安全手段。

谁在用·应用案例

① 科研与原型验证

在高校实验室与科研机构中，急停系统是人形机器人原型机的标配。由于原型机控制算法尚未成熟，运动轨迹不可预测，操作员需要随时准备按下急停按钮。典型配置为：机器人本体上安装 2–4 个急停按钮（分布在躯干前后），操作员手持无线急停遥控器，实验区域周边设置安全围栏并串联急停回路。

② 工业与商业化产品

在面向工业场景的人形机器人（如汽车制造、物流仓储）中，急停系统需符合 ISO 13849 或 IEC 61508 的功能安全要求，并与产线的安全 PLC 联动。例如，当人形机器人与工人共享工作区域时，急停信号需同时传送给机器人本体与产线安全系统，实现联动停机。

③ 认证与合规

按第 2 章链路 3，急停系统是机器人通过 CR/CE 认证的必要条件。认证机构会检查急停系统的设计是否符合相关标准、是否具备双通道冗余、是否提供状态反馈信号等。未配置合规急停系统的机器人无法进入市场。

局限与边界

急停系统并非万能，其局限性包括：

  1. 无法防止所有事故。急停系统只能在“检测到危险并触发”的前提下起作用。如果故障发生速度极快（如电机抱死导致的结构断裂），急停可能来不及响应。
  2. 机械冲击问题。直接切断动力电源会导致电机失去力矩，在负载作用下可能产生冲击或倾倒。对于高动态人形机器人，急停后的机械行为需要额外评估。
  3. 恢复成本高。急停触发后需要手动复位，且重新上电后系统需重新初始化，这在产线场景中意味着停机时间。
  4. 覆盖范围有限。急停系统主要覆盖“动力电源”这一路径，对于非动力类风险（如电池热失控、结构疲劳）需要其他安全机制配合。
  5. 标准适用性仍在演进。人形机器人属于新兴产品，现有功能安全标准（如 ISO 13482）主要针对个人护理机器人，对人形机器人的急停要求尚需补充。

常见误区

  1. “急停就是软件里的一个停止按钮”——错。急停系统的核心是硬接线回路，不依赖软件。软件停止按钮在控制器崩溃时完全失效，而急停系统在此时仍能工作。
  2. “有了急停系统就安全了”——错。急停系统只是安全架构的一环，还需要配合安全 MCU、软停止、STO、机械防护等形成完整的安全方案。
  3. “急停按钮越多越好”——错。按钮过多会增加误触概率，且每个按钮都需要接入安全回路，增加系统复杂度和故障点。合理数量取决于机器人尺寸、应用场景与操作员可达范围。
  4. “急停响应越快越好”——错。过快的切断可能导致机械冲击或倾覆。对于高动态机器人，需要在“快速切断”与“受控停止”之间权衡，这正是分级安全架构存在的意义。
  5. “急停系统不需要维护”——错。触点磨损、按钮卡滞、线缆老化都会导致急停失效，需要定期测试与维护。

왜 존재하는가:痛点과 역사적 위치

비상정지 시스템의 존재는 소박한 공학적 사실에서 비롯됩니다: 소프트웨어는崩溃할 수 있지만, 물리 법칙은 그렇지 않다. 휴머노이드 로봇에서 메인 컨트롤러는 메모리 오버플로, 알고리즘 무한 루프, 전원 변동 또는 전자기 간섭으로 인해失效할 수 있습니다; 통신 버스는 케이블 단선, 커넥터 느슨함 또는 프로토콜 오류로 인해 중단될 수 있습니다. 이러한 시나리오에서 안전 기능이 완전히 소프트웨어 구현에 의존한다면, 고장 발생 시 시스템은 '무인 주행' 상태에 놓이게 됩니다 — 이것이 바로 비상정지 시스템이 제거하려는 사각지대입니다.

역사적 위치에서 보면, 비상정지 시스템은 산업 기계 안전 실무에서 유래했으며, 그 설계理念은 공작기계, 산업용 로봇 및 자동화 생산 라인의 안전 표준 체계로 거슬러 올라갑니다. 휴머노이드 로봇 분야에서 비상정지 시스템은 설계부터 인증까지의 체인에 편입됩니다:

안전 원리 → 기능 안전 표준 → 안전 설계 → 비상정지 시스템 → 로봇 → CR/CE 인증

이 체인(제2장 체인 3 참조)은 비상정지 시스템이 단순한 하드웨어 부품일 뿐만 아니라 안전 설계와 완제품 인증을 연결하는 핵심 고리임을 보여줍니다. 표준을 충족하는 비상정지 시스템이 없으면 휴머노이드 로봇은 CR/CE 인증을 통과할 수 없으며, 시장에 진입할 수 없습니다. 이것이 실제로 바꾸는 것은 '정지 방식'이 아니라 '안전 책임이 소프트웨어에서 하드웨어로 이동한 것'입니다.
