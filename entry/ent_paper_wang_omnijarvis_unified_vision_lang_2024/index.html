OmniJARVIS

OmniJARVIS: Unified Vision-Language-Action Tokenization Enables Open-World Instruction Following Agents

摘要

OmniJARVIS 是北京大学、香港中文大学（深圳）联合提出的 2024 年大型视觉-语言-动作模型，发表于 NIPS24。其核心贡献在于通过统一的多模态交互数据分词化，使智能体在 Minecraft 开放世界中同时具备强推理与高效决策能力。关键创新包括自监督行为编码器与基于行为标记的模仿学习策略解码器。

来源与参考

  • OmniJARVIS source

概述

OmniJARVIS 提出一种统一的视觉-语言-动作（VLA）tokenization 框架，使智能体能够在开放世界指令跟随任务中，仅基于单目 RGB 输入进行导航与操作。其核心贡献在于通过潜在全景梦境（LPD）自监督任务，让单目智能体学习统一导航表示（UNR），从而在 R2R-CE 和 RxR-CE 基准上显著缩小了与全景 RGB-D 方法的性能差距，同时保持零外部数据依赖。

它改变了什么

视觉语言导航（VLN）长期依赖全景 RGB-D 传感器提供空间线索，但这类传感器在真实机器人部署中成本高、功耗大且机械结构复杂。现有单目 VLA 方法虽避免了传感器负担，却因窄视野无法推断全局布局与几何关系，性能明显落后于全景方案。OmniJARVIS 改变了这一权衡：它不再试图从单目图像中直接“看见”全景，而是通过训练时的潜在特征对齐，让模型学会在内部表征中“想象”出全景信息。这意味着部署时只需一个普通 RGB 摄像头，却能在导航决策中利用到类似全景的空间推理能力——这是从“传感器依赖”到“表征补偿”的范式转变。

方法拆解

统一 Tokenization 与 UNR

  • 所有输入（单目图像、指令、历史动作）被 token 化为统一序列，送入基于 NVILA-lite-2B 的 VLA 主干（SigLIP 视觉编码器 + Qwen2 语言模型）。
  • 在每一时间步 t，模型从单目观测中提取共享特征 h_t，即统一导航表示（UNR），它同时对齐导航语义（布局、深度、未来线索）与语言接地动作意图。

潜在全景梦境（LPD）自监督

  • 训练时，LPD 模块要求模型仅凭单目输入，预测当前步与下一步的全景 RGB 和深度图的潜在特征（cubemap 格式，四方向：左、前、右、后）。
  • 监督信号来自共享权重的视觉编码器 Φ_vis，确保预测目标与单目特征处于同一嵌入空间。
  • 损失函数：L_t^Fea(θ) = Σ_{m∈M} ||h_t - ℋ_t^m||² + Σ_{m∈M} ||h_t - ℋ_{t+1}^m||²，其中 M = {PI（全景RGB）, PD（全景深度）}。

多任务联合训练

  • 动作预测：预测未来三步动作 (a_t, a_{t+1}, a_{t+2})，损失 L_t^Act(θ) = -Σ_{k=0}^K log π_θ(a_{t+k}^*|h_t)，K=3。
  • 指令推理：从视觉轨迹上下文反推指令，损失 L_τ^Ins(θ) = -log π_θ(I_τ|h_T)。
  • 总损失：L = Σ_{τ∈D}(Σ_t^{T_τ}(L_t^Act(θ) + λ L_t^Fea(θ)) + L_τ^Ins(θ))，λ 为权重超参数。
  • 推理时 LPD 模块完全移除，仅保留单目 RGB 输入。

训练数据与配置

  • 数据：R2R-CE 320K 步、RxR-CE 600K 步、DAgger 策略收集 500K 步，全部来自模拟环境，无外部数据。
  • 硬件：8×NVIDIA H20 GPU，5 epoch，学习率 1e-5，预热 0.03，批大小 80，历史帧 N=8。

关键创新

  1. 潜在空间的全景想象：LPD 不是生成像素级全景图，而是在特征空间预测全景 RGB-D 的潜在表示。这避免了高维重建的计算开销，同时迫使 h_t 编码全局空间信息——这是首个将“全景补全”作为 VLA 自监督任务的工作。
  2. 零外部数据依赖：相比 NaVid-4D（1500K 外部数据）、Uni-NaVid（2300K）、NaVILA（2215K），OmniJARVIS 仅用模拟器内数据（R2R-CE + RxR-CE + DAgger）即达到可比性能，证明自监督表征学习可替代大规模数据堆砌。
  3. 训练-推理不对称设计：LPD 只在训练时激活，推理时无额外计算或传感器需求。这种“训练时富信息、部署时轻量化”的策略，直接回应了真实机器人对传感器成本和推理延迟的约束。

消融实验

  • 移除 LPD 和指令推理两个辅助任务时性能最差。
  • 仅引入指令推理带来适度增益，LPD 是主要贡献者。
  • LPD 四个子任务（当前/未来 × RGB/深度）均有效，其中未来深度预测贡献最大（论文未明确具体数值）。

边界与局限

  • 作者明确承认，单目智能体的导航性能仍显著落后于全景 RGB-D 输入系统（如 BEVBert 的 SR 59.0 vs OmniJARVIS 的 55.8）。
  • 论文未明确讨论在真实物理机器人上的部署验证，所有实验均在模拟环境（R2R-CE、RxR-CE）中进行。
  • 未涉及低比特量化（8-bit/4-bit）下的性能表现，而这是边缘设备部署的关键问题。
  • 未与视觉-语言数据联合训练，虽然保留 VQA 能力，但未提供具体对话示例或开源结果。

工程启示

  • 复现优先级：先核对 LPD 的 cubemap 渲染与对数深度缩放实现——这是最容易出错的地方，直接影响特征对齐质量。深度图需先对数缩放再基于 colormap 渲染为 RGB，顺序颠倒会导致监督信号失真。
  • 数据配比：R2R-CE（320K）+ RxR-CE（600K）+ DAgger（500K）的混合比例是关键。若只使用 R2R-CE，跨数据集泛化能力会显著下降；DAgger 数据对提升 SPL 至关重要。
  • 训练稳定性：学习率 1e-5、预热 0.03、批大小 80 在 8×H20 上可复现。若 GPU 数量减少，需同步降低批大小并相应调整学习率，否则 LPD 损失可能震荡。
  • 下游集成：推理时务必移除 LPD 模块，否则会引入不必要的计算开销。动作空间（前进 25/50/75 cm，转弯 15°/30°/45°）是离散的，若下游需要连续控制，需额外设计动作解码头。
  • 最易踩坑：LPD 监督信号来自共享权重编码器 Φ_vis，若在训练中冻结该编码器，UNR 与全景特征将无法对齐，导致 LPD 失效。务必保持所有组件可训练。
