Action Token Prediction

摘要

一种将机器人动作生成建模为自回归“下一个 token 预测”问题的方法，类似于语言建模，但输出离散或连续的动作 token。

来源与参考

  • OpenVLA: An Open-Source Vision-Language-Action Model

知识关联

  • formalizes Transformer 动作解码器形式化 动作 token 预测实例化了 Transformer 动作解码器的形式化。
  • has_prerequisite 线性代数 动作 token 预测依赖 Transformer 内部的线性代数运算。

概述

动作 token 预测（action token prediction）是把机器人连续动作量化为离散 bin、映射进语言模型词表，从而把动作生成转化为"下一个 token 预测"问题的动作表示方法。它由 RT 系列确立、被 OpenVLA 等开源 VLA 继承，最大优点是完全复用 LLM 训练与推理生态；代价是量化误差、序列长度与高频抖动，催生了 FAST 频域压缩与扩散/流匹配连续动作头两条改良路线（来源：项目 Wiki 第 19 章 §19.2.2）。

核心内容

是什么：准确定义

动作 token 预测的标准流程（来源：项目 Wiki 第 19 章 §19.2.2）：

  1. 量化：把每个自由度的连续动作按均匀分箱离散化（RT-2 使用 256 个 bin）；
  2. 映射：把 bin 编号映射到语言模型词表中（常用词表尾部最少使用的 token，避免与文本冲突）；
  3. 生成：策略按 \(p_\theta(y_i \mid o_t, \ell, y_{<i})\) 自回归逐 token 输出，再解码回连续动作：
\[ \hat{a}_{t} = \mathrm{decode}\big(\mathrm{tokenizer}^{-1}(y_1, y_2, \dots, y_D)\big) \]

为什么存在：痛点与历史定位

VLA 的核心难题之一是动作接口：VLM 的输入输出都是离散 token，而机器人动作是连续向量。早期方案给 VLM 外挂回归头，但回归头丢掉了语言模型的生成式训练管线（下一个 token 预测、teacher forcing、采样控制）。RT-2 的答案是"把动作变成语言"：一旦动作被 token 化，训练基础设施、正则技巧乃至强化学习后训练（RLHF 类方法）都可以直接借用语言模型生态（Wiki §19.2.2）。

它真正改变的不是动作精度，而是技术栈的复用率——机器人策略训练第一次可以零改造地站在整个 LLM 工程生态的肩膀上。这个接口选择直接塑造了 2023–2025 年 VLA 的主流形态。

原理拆解

① 为什么是词表尾部 token

把动作 bin 映射到最少使用的 token，是为了让预训练词嵌入中"闲置"的槽位承载动作语义，最大限度减少与语言知识的干扰——这是"不改结构复用 VLM"的关键细节（Wiki §19.2.2；OpenVLA 沿用同法）。

② 三个结构性代价（Wiki §19.2.2）

  1. 量化误差：256 bin 对高精度装配类任务可能不足，提高分辨率又会拉长序列；
  2. 序列长度：D 个自由度 × H 步动作块的 token 数随维度线性增长，自回归逐 token 解码使推理延迟居高不下，典型模型只能以数 Hz 输出动作块；
  3. 高频抖动：离散化破坏时序平滑性，需要后处理或时间集成。

③ 改良一：FAST 频域压缩

FAST（Efficient Action Tokenization）用离散余弦变换（DCT）对动作块做频域压缩再 token 化，以远少于逐维量化的 token 数表示高频动作序列，显著降低自回归解码步数（Wiki §19.2.2）。

④ 改良二：连续动作头（范式替代）

扩散/流匹配动作头保留动作连续性：VLM 输出语义表征作条件，由动作专家生成连续动作块——π0 与 GR00T N1 均采用流匹配，RDT-1B 与 DexVLA 采用扩散路线。连续头在高维高频动作（双臂 50 Hz、灵巧手多指协调）上天然占优，且天然支持多峰分布（Wiki §19.2.3）。

谁在用 / 应用案例

  • RT-2（Google DeepMind）：确立路线，展示网络知识向动作迁移（arXiv:2307.15818）；
  • OpenVLA：开源继承者，LoRA 微调生态以此接口为基础（Wiki §19.3.2）；
  • Octo：扩散头之前的早期版本亦用离散 token 路线（Wiki §19.2.3 对比表列入离散阵营代表）；
  • 机载推理：ent_tech_on_device_vla_inference 等边缘部署工作需正面处理逐 token 解码的延迟。

局限与边界

  • 高频任务结构性不利：自回归延迟随动作维度线性增长，灵巧手/全身 50 Hz 控制难以直接承载（Wiki §19.2.2）；
  • 量化分辨率与序列长度的零和：加细 bin 就拉长序列；
  • 时序平滑性缺失：需后处理；
  • 多峰表达样本效率低：理论上自回归可表达多峰，实践中需要更多数据（Wiki §19.2.3 对比表）。

常见误区

  1. "离散 token 就是 VLA 的定义"——它只是两条动作表示路线之一；流匹配/扩散连续头已是人形 VLA 主流（π0、GR00T N1）。
  2. "bin 数越大越精确越好"——bin 数增加同时拉长目标序列并稀释每类样本，存在精度-延迟权衡。
  3. "token 化是无损编码"——均匀分箱引入量化误差；FAST 的 DCT 压缩正是为降低这一损失而生。
  4. "换了连续头就不能复用 LLM 生态"——语义骨干照样复用，只是动作侧需要额外采样器；二者是接口选择而非路线互斥。

왜 존재하는가:痛点과 역사적 위치

VLA의 핵심 난제 중 하나는 액션 인터페이스입니다: VLM의 입력과 출력은 모두 이산 토큰인 반면, 로봇 액션은 연속 벡터입니다. 초기 접근법은 VLM에 회귀 헤드를 추가했지만, 회귀 헤드는 언어 모델의 생성적 훈련 파이프라인(다음 토큰 예측, teacher forcing, 샘플링 제어)을 잃어버렸습니다. RT-2의 답은 "액션을 언어로 만드는 것"이었습니다: 액션이 토큰화되면 훈련 인프라, 정규화 기법, 심지어 강화 학습 후훈련(RLHF류 방법)까지 언어 모델 생태계를 직접 차용할 수 있습니다(Wiki §19.2.2).

이것이 실제로 바꾼 것은 액션 정밀도가 아니라 기술 스택의 재사용률입니다——로봇 정책 훈련은 처음으로 개조 없이 전체 LLM 엔지니어링 생태계의 어깨 위에 설 수 있게 되었습니다. 이 인터페이스 선택은 2023–2025년 VLA의 주류 형태를 직접 형성했습니다.
