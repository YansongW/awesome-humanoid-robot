HiMe: Hierarchical Embodied Memory for Long-Horizon Vision-Language-Action Control

摘要

HiMe 是一个由研究者提出的分层具身记忆框架，旨在解决当前 Vision-Language-Action (VLA) 模型在长时域任务中因依赖即时观测而缺乏长期记忆与推理能力的问题。其核心贡献在于通过将具身智能解耦为高频执行器、工作记忆哨兵和长期策略规划器三个层次，并引入基于跨模态语义模式的动态知识系统，有效平衡了实时执行与慢速推理之间的冲突，显著提升了长时域任务的成功率。

来源与参考

  • HiMe: Hierarchical Embodied Memory for Long-Horizon Vision-Language-Action Control (arXiv)

概述

HiMe 提出一种三层级具身记忆架构，将长时程 VLA 控制解耦为高频 Executor、异步 Sentry 与低频 Planner，通过显式 CRUD 记忆管理解决非马尔可夫环境下的持久信念问题。系统在真实机器人三任务上达到 90% 平均成功率，并将高层推理 API 调用减少约 3 倍。

它改变了什么

长时程具身控制的核心矛盾从来不是"存不下"，而是"记不对"。现有 VLA 的马尔可夫假设让策略在部分可观测环境中注定失明——动作依赖的过去事件链一旦滑出当前观测窗口，模型就只能靠猜。而试图用更大上下文窗口或更强推理模型硬扛的方案，要么撞上实时控制的延迟墙，要么被训练长程因果依赖的优化困难卡死。

HiMe 真正改变的是把"记忆"从模型的隐状态中剥离出来，变成系统架构中一个可显式读写、可主动修订的独立模块。它不再要求单个模型同时具备高频反应与深度推理能力，而是用 Sentry 的异步门控将 Planner 的调用频率从每个控制步降到每个子任务约 1-3 次，让重型 VLM 的延迟从控制回路中解耦。这等于承认了一个工程现实：实时控制与深度推理在物理上难以共存，不如在架构层面分而治之。

方法拆解

三层级架构与职责划分

  • Executor (π_e)：基于 π_0.5 微调的 VLA，运行于 2 Hz，预测 10 个动作的动作块（10 Hz），其中 5 个开环执行。仅依赖瞬态记忆 T_t = {o_t}，负责感觉-运动协调。
  • Sentry (π_s)：Qwen3-VL-8B 本地部署，每 n_m = 5 个 Executor 步异步查询一次。输入滑动窗口 W_t = {o_{t-h_s}, ..., o_t}（h_s = 8），输出门控 u_t = I[π_s(W_t, τ_t) > δ]，仅判断当前子目标是否完成。
  • Planner (π_p)：GPT-4o（补充实验用 Qwen3-VL-30B），仅在 u_t = 1 时被调用，管理情景记忆 E_t。

记忆系统三组件

  • 瞬态记忆 T_t：Executor 的最小充分状态，仅当前观测。
  • 工作记忆 W_t：Sentry 的滑动窗口，用于验证子目标状态与检测突发失败。
  • 情景记忆 E_t：Planner 的持久存储，分为：
  • 上下文记忆 E_t^c：多模态键值存储 M_t，视觉图像与文本描述通过标题嵌入（OpenAI text-embedding-3）索引，支持余弦相似度检索。
  • 程序记忆 E_t^p：有序语言子目标列表 {τ_i}_{i=1}^N，每个子目标携带 active/pending/done 状态标签。

Planner 两阶段更新

  1. 上下文检索：q_t = f_enc(l, W_t)，M_ret = TopK(E_t^c, q_t)，每记录使用 2-5 个标签作为主要检索机制。
  2. 记忆更新与重规划：(E_{t+1}^c, E_{t+1}^p) ← π_p(l, W_t, M_ret, E_t^p)，通过显式 Add（插入新事实/用户偏好）、Update（修订过时条目）、Delete（移除冲突信息）操作实现知识可塑性。

关键设计决策

  • Sentry 的"保守"门控（高 Precision 低 Recall）强制执行 Planner 的时间一致性，防止当前子目标完成前被干预。
  • 记忆可靠性规则：仅存储可验证事实，禁止创建虚假记忆，状态变化时创建新记录并更新旧记录，DELETE 仅用于重复或错误。
  • 规划器采用两轮交互：第一轮仅 QUERY，第二轮执行 CRUD 并输出最终计划。

关键创新

  1. 门控式分层推理调度：Sentry 的异步门控将 Planner 调用从每个控制步解耦到子任务粒度，使重型 VLM 的秒级延迟（GPT-4o P50 为 38.59 秒）不再阻塞 10 Hz 控制回路。这是首个将"何时思考"与"如何思考"分离的具身记忆架构。

  2. 显式 CRUD 记忆管理：将记忆从被动存储升级为主动维护的知识库。Add/Update/Delete 操作让机器人能修订过时信息（如对象位置变化）、注入不可见语义（如"Alice 的杯子"），并删除冲突条目——这是静态 FIFO 或固定上下文窗口无法实现的。

  3. 跨模态语义锚定：情景记忆以对象为中心，将视觉经验与高密度文本描述深度绑定。Planner 不仅能检索视觉特征，还能检索像素空间中不可见的底层所有权、程序规则和人类偏好，解决了纯视觉轨迹无法捕获密集逻辑约束的问题。

关键消融

  • 模态消融：Object Search 中 Only image 86% vs. Only text 74%；Counting 中 Only text 91% vs. Only image 78%。跨模态平均 90%，证明不同任务依赖不同模态优势。
  • 管理机制消融：FIFO 平均 68%（最差），No Management 86%，完整方法 90%。显式管理带来 4 个百分点的提升。
  • 受控记忆消融（Rearrangement）：Unlimited Active Management 87.0%，Limited Active Management（固定 8 条目）80.0%，FIFO（Limited）64.0%。
  • 记忆可扩展性（多轮 Object Search）：1 轮（4 子任务）记忆大小 5.5，进度 92.5%；3 轮（12 子任务）记忆大小 14.0，进度降至 66.7%。
  • Sentry 终止行为：上下文窗口从 1 帧增至 8 帧，Precision 从约 76% 提升至约 82%，Recall 从约 22% 提升至约 35%。高 Precision 低 Recall 验证 Sentry 的保守特性。

效率优势

HiMe 相比 Flat Memory 减少 API 调用约 3 倍（Object Search 从 5.4 降至 1.8），同时 Memory Hit 率从 68% 提升至 94%。

边界与局限

  • 评估仅在固定桌面设置的真实机器人上进行，无匹配标准仿真基准，限制了受控比较与基准级可复现性。
  • 任务依赖相对简单的操作原语（拾取-放置），未验证更广泛和更灵巧的技能。
  • 多轮扩展实验显示记忆大小从 5.5 增至 14.0 时，任务进度从 92.5% 降至 66.7%，但未提供更长期记忆压力测试。
  • 未完全表征在非常长视野、更大环境或长时间部署下的性能。
  • 开源 Planner 替换（Qwen3-VL-30B）的完整分析尚未完成。

工程启示

复现时先核对三个关键点：Sentry 的判定阈值 δ 与监控间隔 n_m——这是整个架构的节拍器，直接决定 Planner 调用频率与任务切换的保守程度；记忆检索的标签设计——每条记录 2-5 个标签是检索质量的生命线，标签过少导致召回不足，过多则引入噪声；Executor 的微调数据质量——60 个演示（50 标准 + 10 角落案例）中角落案例的比例直接影响长时程任务的鲁棒性。

最容易踩坑的地方是 Sentry 的"保守"倾向：高 Precision 低 Recall 意味着它倾向于"继续执行"而非"确认完成"，在 Counting 这类需要精确进度跟踪的任务中，Transient Memory w/ Sentry 的失败率达 23%。如果下游任务对完成判定敏感，需要单独调优 Sentry 的提示词或降低 δ。另一个坑是 Planner 的延迟：GPT-4o 的 P99 达 57.28 秒，虽然与高频控制解耦，但在子任务切换频繁的场景中会成为瓶颈——本地部署 Qwen3-VL-30B 可将 P50 从 38.59 秒降至 6.83 秒，是成本敏感场景的务实选择。
