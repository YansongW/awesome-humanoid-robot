摘要

HumanoidGen 是一个面向双臂灵巧手人形机器人的自动化数据生成框架，由研究团队于2025年提出。其核心贡献在于利用大语言模型推理与原子化灵巧操作，自动生成任务约束与演示数据，并构建了新的仿真基准。实验表明，基于生成数据训练的2D与3D扩散策略性能可随数据量提升。

来源与参考

  • HumanoidGen: Data Generation for Bimanual Dexterous Manipulation via LLM Reasoning (arXiv)

概述

HumanoidGen 是一个面向双臂灵巧操作的全自动数据生成框架，由研究团队提出，利用 LLM 推理将任务分解为原子操作序列，并通过空间标注、约束求解和 MCTS 增强推理生成高质量演示数据。核心贡献在于构建了 HGen-Bench 基准（20 个任务）并验证了生成数据对扩散策略训练的有效性，同时提出了 STCR 机制解决长时程任务中的错误恢复问题。

它改变了什么

现有机器人数据生成管线严重依赖 VR 遥操作或外骨骼设备，这不仅需要昂贵的硬件和熟练操作员，而且难以覆盖多样化任务场景。更关键的是，主流模拟基准（如 Aloha、RoboTwin）和真实世界数据集（如 Open-X）主要面向单臂机械臂平台，缺乏针对双臂灵巧手的高质量演示数据，导致双臂灵巧操作策略训练面临数据瓶颈。

HumanoidGen 真正改变的是数据生成的范式：从“人工演示”转向“LLM 推理驱动的自动生成”。它不再需要操作员手动执行任务，而是通过 LLM 将任务分解为原子操作序列，结合空间标注和约束求解自动生成可执行的演示轨迹。这一转变不仅大幅降低了数据收集成本，还使得生成数据的规模和多样性可以快速扩展，为双臂灵巧操作策略训练提供了可持续的数据来源。

方法拆解

空间标注体系

  • 对手部和资产进行三类标注：手部原子操作（接近轴、附着轴、平行轴）、资产固有信息、资产操作标注
  • 以“捏”为例：接近轴指定手接近预捏姿势的方向，附着轴从拇指尖指向食指尖，平行轴垂直于前两者且平行于手掌平面

任务分解与约束生成

  • LLM 规划器将长时程任务分解为动作序列 S = {S1, S2, ..., Sn}，每步 Si = (Si^l, Si^r) 包含左右手部分
  • 引入动态坐标系 F_act 表示每只手的上下文动作空间，约束 c ∈ {C^path, C^goal} 指定 F_act 元素与全局帧集 F_all 之间的几何关系（重合、平行或正交）

轨迹优化

  • 第一步：使用 pydrake 库的 SNOPT 求解器优化末端执行器位姿 e_T 和手臂角度 θ_T，包含运动学约束、关系动作约束和碰撞避免约束
  • 第二步：使用 mplib 库的约束运动规划器最小化代价函数 Cost(θ_t)，保证运动过程中的约束满足

MCTS 增强推理（STCR 机制）

  • Segment：按执行粒度将规划代码分段
  • Truncate：在错误发生点截断，保留有效段 S_remain = {Si | 1 ≤ i ≤ k−1}
  • Combine：合并意图一致的原子操作形成新序列 S'_remain
  • Resume：存储已执行序列代码、错误代码和场景状态信息供节点扩展时恢复
  • 搜索采用 Q_DUCB 值估计（折扣因子 γ∈(0,1)），反向传播引入内在探索奖励 R_intrinsic（如“成功抓取杯子”等有价值时刻）

场景缩放

  • 通过坐标变换 T_{O→O'} 将原始场景中的点、向量和位姿映射到新场景，无需额外标注，泛化到超过 120 个场景

关键创新

  1. 全自动双臂灵巧数据生成管线：首次将 LLM 推理、空间标注和约束求解整合为统一框架，无需人工演示或遥操作，直接生成双臂灵巧操作的高质量演示数据。这一创新打破了数据收集对硬件设备和操作员技能的依赖，使得数据规模可以快速扩展。

  2. STCR 机制与 MCTS 结合：针对长时程任务中 LLM 规划容易出错的问题，提出 Segment-Truncate-Combine-Resume 机制将规划代码抽象为树结构，通过 MCTS 搜索自动修复错误。实验表明，在标注不足时（移除立方体操作标注），MCTS 将 Blocks Stack Hard 任务成功率从 18.3% 提升至 98.3%，token 消耗仅增加约 5 倍，而成功率提升超过 5 倍。

  3. 基于扩散特征匹配的自动资产标注：利用 Stable Diffusion 编码器进行特征点匹配，从已标注资产迁移标注到新资产，将手动标注时间从 4-6 秒降至约 0.8 秒，迁移成功率超过 90%，大幅降低了框架扩展到新资产类别的成本。

实验与结果

  • HumanoidGen 在所有灵巧操作任务中平均成功率超过 50%，大多数任务类型成功率高于 75%
  • 与 RoboTwin 相比，在单臂和双臂短时程任务上表现相当

边界与局限

  • 人工干预尚未完全消除：对于未预先标注的资产类别和原子操作类型，标注迁移无法自动标注，需手动标注
  • 当前框架无法生成所有类型的灵巧操作任务：ManiSkill3 物理引擎限制，涉及可变形或流体物体的任务无法仿真
  • 手臂控制依赖低级运动规划器，难以处理目标模糊或动态的操作任务（如 push-T、布料展平），这些任务需要连续状态调整而非规划单一目标位姿
  • 对于若干极具挑战性的任务（如 blocks stack hard、handover and storage），尽管数据生成方法产生高质量演示，DP 和 DP3 均无法准确学习每一步，涉及长时程序列和精细物体操作
  • 跨具身数据适应仍是一个开放研究挑战

工程启示

复现 HumanoidGen 时，首先需要核对空间标注体系的完整性——特别是手部原子操作的三个轴（接近轴、附着轴、平行轴）定义是否与你的灵巧手型号匹配，这直接影响约束求解的可行性。最容易踩坑的地方在于 MCTS 的 STCR 机制：Segment 的粒度划分对搜索效率影响极大，过细导致树规模爆炸，过粗则无法有效定位错误点，建议从任务描述的自然语义边界开始尝试。

对于下游团队，建议优先验证生成数据对 DP3 的训练效果（而非 DP），因为实验表明 DP3 在多数任务上表现更稳定。注意 DP 在某些任务（如 Close Box Hard）会出现虚高成功率——策略未学到有效行为但偶尔碰巧成功，评估时需观察动作的稳定性和安全性，不能仅看成功率数字。真实世界迁移时，建议先用 5 条真实轨迹 + 100 条仿真轨迹的组合训练（表 5 显示与 25 条真实轨迹效果相当），可显著降低真实数据收集成本。
