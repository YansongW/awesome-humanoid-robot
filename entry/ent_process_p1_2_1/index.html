概述

概念方案发散与收敛（P1.2.1）是人形机器人系统方案设计阶段的核心工序，它通过头脑风暴、形态草图、Morphological Matrix、Pugh Matrix 等工具，在多种整机布局、驱动方案、传感方案中系统评估，最终收敛出至少 3 套概念方案并冻结选定方案。它真正改变的不是方案数量，而是"从拍脑袋到可追溯"的决策方式。

核心内容

是什么：准确定义

概念方案发散与收敛是需求定义与系统方案（Concept / Pre-A）阶段中 P1.2 系统方案设计工作包下的三级子任务，实体编号为 ent_process_p1_2_1。它的上游输入来自 P1.1 需求工程冻结的产品规格与平台化策略，下游交付则衔接详细设计阶段的机械、电气、软件接口定义。

该工序在 WBS V3 中展开为五个四级关键动作：输入梳理与目标量化、方案/方法设计、实施/原型/样件制作、验证与问题闭环、文档输出与下游交付。每个动作都有明确的输入、方法、输出和验收标准，形成完整的闭环。

为什么存在：痛点与历史定位

在人形机器人早期开发中，团队常犯两类错误：一是发散不足，仅凭工程师个人经验直接选定一种布局，错过更优的驱动方案或传感配置；二是收敛过晚，在多个方案间反复摇摆，导致详细设计阶段不断返工。

概念方案发散与收敛的存在，正是为了在设计自由度最大、变更成本最低的阶段，用结构化的方法穷举可能性，再用量化的评分矩阵压缩不确定性。它真正改变的不是方案数量，而是"从拍脑袋到可追溯"的决策方式——每一次取舍都有据可查，每一个被否定的方案都有明确理由。

原理拆解

① 发散阶段：Morphological Matrix 的组合爆炸控制

Morphological Matrix（形态矩阵）将系统拆解为若干独立功能维度（如整机布局、驱动方案、传感方案、散热方式、线束走向），每个维度下列出所有可行的实现选项。理论上，组合数量是各维度选项数的乘积：

\[ N_{\text{total}} = \prod_{i=1}^{n} m_i \]

其中 \(m_i\) 为第 \(i\) 个维度的选项数，\(n\) 为维度总数。工程判断：若 \(N_{\text{total}}\) 超过 50，必须引入约束条件（如技术成熟度、成本上限）进行预筛，否则评估工作量失控。

② 收敛阶段：Pugh Matrix 的加权评分

Pugh Matrix（决策矩阵）以基准方案为参照，对每个候选方案在各评估准则下打分（+1、0、-1），再乘以权重求和：

\[ S_j = \sum_{k=1}^{p} w_k \cdot r_{jk} \]

其中 \(S_j\) 为第 \(j\) 个方案的总分，\(w_k\) 为第 \(k\) 个准则的权重，\(r_{jk}\) 为第 \(j\) 个方案在第 \(k\) 个准则下的相对得分。总分最高的方案胜出，但必须附书面理由说明为何权重如此分配。

③ 五步法的闭环逻辑

每个四级关键动作不是孤立的：输入梳理保证起点清晰，方案设计保证路径明确，原型制作保证假设可验证，验证闭环保证问题不遗漏，文档交付保证知识可传承。这五步构成一个完整的 PDCA 循环。

横向对比

概念方案发散与收敛与相邻工序的差异在于：

  • 与 P1.1 需求工程相比：需求工程回答"做什么"（What），本工序回答"怎么做"（How）。需求工程冻结的是产品规格，本工序冻结的是实现方案。
  • 与 P1.2.2 详细设计相比：本工序只做方案级论证，不涉及具体零件尺寸、电路原理图或代码实现；详细设计是在选定方案基础上做深度展开。
  • 与 P0 项目立项相比：P0 确定目标成本、目标产量、目标市场，本工序在 P0 约束下做技术选型，不改变商业基线。

谁在用·应用案例

应用场景一：整机布局方案选择

团队在发散阶段提出三种整机布局：传统直立式、轮腿混合式、四足变形式。通过 Morphological Matrix 拆解为自由度分配、重心高度、足底传感、关节模组选型四个维度，组合出 12 种候选方案。经 Pugh Matrix 以技术成熟度、成本、可制造性为准则加权评分，最终选定直立式布局，理由是其技术风险最低且与现有供应链匹配度最高。

应用场景二：驱动方案对比

在驱动方案维度，候选包括：液压驱动、电液混合驱动、电机直驱（QDD）、电机+谐波减速器。评分结果显示电机+谐波减速器在成本与精度平衡上最优，但 QDD 在透明度（力控性能）上更佳。最终根据产品定位（教育科研 vs 工业应用）决定取舍，并记录在案。

局限与边界

  1. 评分矩阵的主观性：Pugh Matrix 的权重分配依赖团队经验，不同团队可能得出不同结论。缓解方法是引入跨部门评审（机械、电气、软件、制造、成本工程师共同参与）。
  2. 发散不充分的风险：如果 Morphological Matrix 的维度划分不完整，可能遗漏关键方案。工程判断：建议至少覆盖整机布局、驱动方案、传感方案、能源方案、散热方案五个维度。
  3. 原型验证的深度有限：本工序的原型制作以"关键步骤验证"为主，不要求完整样机。对于高风险创新点，可能需要提前启动专项预研。
  4. 不解决需求变更：如果上游需求在方案冻结后发生重大变更，本工序的输出可能作废，需要重新进入发散收敛流程。

常见误区

  1. "发散就是越多越好"——错。发散的目的是覆盖可能性空间，而非堆砌数量。当组合数超过 50 时，评估成本急剧上升，必须用约束条件预筛。
  2. "Pugh Matrix 是客观决策"——错。权重设定本身就是主观判断，矩阵只是让主观判断显性化、可追溯，而非消除主观性。
  3. "冻结方案后就不能改"——错。冻结意味着变更需要走正式变更流程（更新文档、重新评审、通知下游），而非完全禁止变更。
  4. "跳过原型验证直接收敛"——错。对于关键技术假设（如新型关节模组的峰值扭矩），必须通过仿真或简易原型验证，否则评分矩阵建立在空中楼阁上。
  5. "文档输出是最后才做的事"——错。按模板编写文档、引用原始数据应在每个四级动作进行中同步记录，而非事后补写。
