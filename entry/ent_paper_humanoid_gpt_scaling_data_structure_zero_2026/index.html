亿帧数据驱动的人形零样本动作跟踪

Humanoid-GPT: Scaling Data and Structure for Zero-Shot Motion Tracking

领域
AI 模型与算法
层级

审校

摘要

Humanoid-GPT 是一个基于因果注意力的 GPT 风格 Transformer 模型，由研究团队在十亿级运动语料上预训练，用于全身控制。其核心贡献在于通过扩展数据（20亿帧重定向语料）和模型容量，实现了对高度动态行为的零样本运动跟踪，并展现出前所未有的泛化能力。

概述

Humanoid-GPT 是一个基于 GPT 风格因果注意力 Transformer 的通用在线人形运动跟踪器，通过将训练数据扩展至 2B 帧（比先前工作大 200 倍以上）并配合 Harmonic Motion Embedding (HME) 数据策展与专家蒸馏流程，实现了对未见舞蹈动作的零样本运动跟踪。该系统在 Unitree-G1 上以 50 Hz 闭环控制运行，端到端推理延迟低于 1.5ms，在仿真与真实世界实验中均显著超越现有基线。

它改变了什么

运动跟踪领域长期被浅层 MLP 主导，训练数据停留在 10^4 量级轨迹（约 7.2M 帧），这造成了一个看似不可调和的「敏捷性-泛化性」权衡：域内敏捷动作的跟踪锐度与未见风格上的泛化能力难以兼得。作者的核心判断是，这一权衡并非根本性限制，而是数据规模不足与训练设计不匹配的症状——语言/视觉领域的大规模扩展路径在运动控制中从未被认真尝试。

真正被改变的是「规模假设」在运动跟踪中的确立。作者不仅将数据扩大了两个数量级，更重要的是证明了：当数据从百万帧增长到十亿帧时，模型结构的选择（因果 Transformer vs MLP）决定了性能是持续提升还是早期饱和。这打破了运动跟踪领域「小数据+浅模型」的默认范式，将问题重新定义为数据策展、结构匹配与训练稳定性三者的联合优化，而非单纯的算法调参。

方法拆解

数据策展与 HME 采样

  • 聚合 AMASS、LAFAN1、MotionMillion、PHUMA 及内部采集数据，经运动重定向映射至 Unitree-G1 的 29-DoF 空间
  • 过滤含物体交互序列（坐椅、游泳等），应用时间扭曲增强（均匀加减速）将数据扩展约 5 倍，最终获得 2B 帧语料
  • 训练多个 Periodic Autoencoders 提取每关节周期幅度/频率，聚合为 HME 向量；K-Means 聚类产生约 300 个运动簇（每簇 1k–2k 序列）
  • 关键设计：HME 用于多样性感知、分布平衡采样——多样性不足导致过拟合频繁模式，平衡性不足限制能力上限

运动专家训练

  • 每簇训练 PPO 策略 π: 𝒢 × 𝒮 ↦ 𝒜，状态含关节位置/速度、根部角速度、投影重力、先前动作；输出经 PD 控制器转为扭矩
  • 奖励在身体关键点级计算：R_kpt(t) = R_pos(t) + R_rot(t) + R_vel(t) + R_penal(t)，其中 R_pos(t) = Σ w_k exp(−α_pos ‖e^pos‖₁)，α_pos=1.0，α_rot=2.0，α_vel=0.03；下半身权重 1.5，上半身 0.75
  • 训练后仅保留高保真、长时稳定的专家（约 384 个为最优平衡点）

DAgger 蒸馏至通用策略

  • 采用 DAgger 框架：迭代中 rollout 学生策略并查询专家目标动作，训练学生匹配专家输出
  • 输入 token e_t = [s_t; q_t^ref]（本体感受 + 目标参考姿态拼接），长度 H=32 的序列经时间因果掩码 Transformer
  • 损失为 SmoothL1Loss，公式 (2)：â = ⋃ concat_{k∈[-H+1,0]} t_i(s_{t-k}, g_{t-k})，l = ℒ(G_θ(e_{t-H+1:t}), â)
  • 推理时维护 H 个历史 token 队列，取最后位置输出作为控制目标；batch size 不小于专家数量以避免模式崩溃

架构选择理由

  • 运动跟踪本质因果（测试时无未来观测），GPT 风格因果注意力与部署约束对齐
  • Transformer 相比 MLP 和非因果变体随数据/模型规模更干净地扩展
  • 并行序列监督 + 自回归时间预测利用 Transformer 固有优势，隐式学习位置不变的时间预测，使 episode 起始（历史稀缺）也能稳定输出

关键创新

  1. 数据规模跨越临界点：2B 帧训练语料比先前最大工作（SONIC 的 100M 帧）大 20 倍，比主流基线（7.2M 帧）大 200 倍以上。这不是增量改进，而是首次将运动跟踪推入「数据受限」区域——实验显示 200M→2B 边际增益下降，表明模型容量成为新瓶颈，这在小数据 regime 从未被观察到。

  2. HME 驱动的分布平衡采样：现有工作要么随机采样（多样性失控），要么均匀采样（频繁模式过拟合）。HME 通过周期自编码器提取谐波特征并聚类，实现「多样性感知 + 分布平衡」的双重约束。作者明确强调两者缺一不可——这是对数据策展方法论的重要补充，而非简单的数据堆砌。

  3. 因果 Transformer 作为控制架构：虽然 Transformer 在运动生成中已有应用，但将其作为在线跟踪器的核心架构并系统验证「因果性 + 规模扩展」的协同效应是新的。关键洞察是：因果注意力不仅满足部署约束，还通过隐式时间预测解决了 episode 起始阶段的冷启动问题——这是 MLP 和 TCN 均不具备的特性。

边界与局限

论文未明确提及失败案例的具体分析、特定运动类别的性能下限，以及真实世界部署中硬件磨损或安全性的讨论。作者承认的边界包括：未纳入接触、视觉或语言等更丰富模态；未扩展到交互或多智能体场景；未与长时程规划或 VLA 风格指令耦合。

值得注意的隐含局限：所有真实世界实验均基于舞蹈动作（高动态但无物体交互），对需要环境接触的任务（如操作、攀爬）可能不适用——数据策展阶段明确过滤了此类序列。此外，专家数量（约 384 个）与聚类数高度耦合，若目标运动分布与训练分布差异过大，HME 聚类的覆盖性可能不足。

工程启示

复现或借鉴此工作，建议优先核对以下环节：

  1. 数据管线是最大工程风险：2B 帧语料的获取、重定向、过滤与增强流程占整体工作量的比重远超模型设计。若无法复现同等规模数据，可先验证 HME 采样策略在 100M 帧量级是否仍优于随机采样——这决定了数据策展的边际价值。

  2. 专家数量与蒸馏稳定性：约 384 个专家是多样性、簇内一致性与计算成本的平衡点（128 过粗，1024 成本过高）。DAgger 蒸馏时 batch size 必须不小于专家数量，否则易模式崩溃——这是最容易踩坑的细节。

  3. 历史长度 H=32 是计算与性能的折中：实验显示 64 帧历史持续提升，但计算量随序列长度二次增长。若下游任务对延迟敏感，可先验证 16 帧是否可接受；若追求极致精度，可尝试 64 帧并接受推理延迟增加。

  4. 域随机化参数需按平台调整：地面摩擦 𝒰(0.3, 2.0)、外力间隔 𝒰(5.0, 10.0)、躯干 CoM 变化 𝒰(−0.15, 0.15) 等参数是针对 G1 调优的。迁移到其他硬件时，建议先做敏感性分析，特别是 armature 缩放（𝒰(1.0, 1.05)）对仿真-现实差异的影响。

  5. 部署栈已开源：ONNX 导出 + TensorRT 优化（因果注意力与融合 MLP 内核）+ C++ 流式管线，50 Hz 闭环控制。若复现时推理延迟超标，优先检查 TensorRT 是否真正融合了因果注意力掩码——这是 1.5ms 延迟的关键。
