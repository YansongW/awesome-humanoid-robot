CLIPort

CLIPort: What and Where Pathways for Robotic Manipulation

层级

摘要

CLIPort 是华盛顿大学与 NVIDIA 于 2021 年提出的视觉-语言-动作模型，发表于 CoRL 2021。其核心贡献在于融合 CLIP 的语义理解能力与 Transporter 的空间定位能力，通过双流架构实现机器人对抽象概念与精细操作的统一处理。该模型在少样本场景下数据高效，且能泛化至未见过的语义概念。

来源与参考

  • CLIPort source

概述

本文提出 CEER（compliant end-effector–root）控制抽象，作为人形机器人全身移动操作（loco-manipulation）的统一执行接口，并配套 teacher–student 训练框架，将高层任务命令（如末端执行器位姿）蒸馏为仅依赖本体感觉的低层策略。作者在 Unitree G1 上验证了该方法，实现模拟单物体操作 70% 成功率与 3.3 cm 端到端跟踪精度，并展示了真实世界遥操作书写与物体旋转任务。

它改变了什么

人形机器人操作长期卡在“感知-规划-执行”流水线无法自动化：传统 joint-tracking 方法需要全身关节目标作为输入，命令具有 embodiment-specific 特性，且纯运动跟踪缺乏显式柔顺调制。这导致每次换任务或换机器人都要重新设计控制器，无法形成可复用的操作原语。本文真正改变的是将操作命令从高维关节空间压缩到低维末端执行器-根（EE-root）空间，同时保留柔顺性——这不是简单的降维，而是重新定义了“任务级命令”的语义边界，让下游技能（遥操作、导航、操作）都能通过同一接口与底层控制器对话。

另一个关键转变在于训练范式：作者没有直接端到端学习操作策略，而是先训练一个基于 AMASS 数据集的通用运动跟踪 teacher，再蒸馏为仅消费 EE-root 命令的 student。这种两阶段设计避免了“从零学习操作”的样本效率灾难，同时让 student 策略天然具备对物体接触的柔顺响应能力——这是纯运动跟踪方法无法提供的。

方法拆解

CEER 控制抽象

  • 使用 Cartesian 阻抗公式：F = K_m(ẍ − ẍ_d) + K_d(ẋ − ẋ_d) + K_p(x − x_d)，假设零期望加速度与恒定增益。
  • 稳态下，柔顺目标为 x_t^imp = x_t^ref + K_p^{-1} f_ext,t，即外力通过刚度矩阵逆映射修正参考轨迹。

Teacher–Student 蒸馏

  • Teacher 观察空间：c_t^T ∈ ℝ^29（关节空间参考命令）+ privileged 信息（外力、阻抗跟踪状态、仿真真值、执行器状态）。
  • Student 观察空间：c_t^S ∈ ℝ^16（root 位姿 x, y, z, yaw + 末端执行器位置/方向），共享观察 o_t 仅含本体感觉（投影重力、root 角速度、关节位置历史、先前动作）。
  • 关键设计：joint-space reference 直接输入 teacher 而不经过 privileged encoder，避免削弱监督信号；引入 target joint estimator f_θ_q 预测 29 维参考关节配置，使 student 输入结构与 teacher 对齐，支持直接权重初始化与稳定微调。

三层层次架构

  • 低层：CEER 控制器（50 Hz）
  • 中层：模块化技能（teleoperation、locomotion、manipulation，10–20 Hz）
  • 高层：LLM-based task manager（second-level 时间尺度），通过 function-calling 选择技能，reason–act–observe 闭环，不微调 LLM，操作知识编码在 system prompt 中。

奖励设计

  • r_total = w_ee·r_ee + w_c·r_compliance + w_m·r_motion + w_l·r_locomotion
  • r_ee = exp(−‖x_t^ee − x_t^ref‖²) 为新增末端执行器跟踪项。

训练配置

  • Isaac Lab 模拟器，16,384 并行环境，4 块 NVIDIA L40s GPU，训练 8 小时。
  • 基于 PPO 的两阶段训练。

关键创新

  1. EE-root 控制抽象作为统一接口：将操作命令从 29 维关节空间压缩到 16 维 EE-root 空间，同时通过阻抗控制保留柔顺性。这不是简单的降维，而是重新定义了任务级命令的语义边界——下游技能（遥操作、导航、操作）都能通过同一接口与底层控制器对话，无需针对每个任务重新设计控制器。

  2. Target joint estimator f_θ_q 的引入：这是工程上最精妙的设计。它让 student 策略的输入结构与 teacher 对齐，从而支持直接权重初始化——这解决了蒸馏训练中常见的“输入分布不匹配导致微调不稳定”问题。消融实验显示，去掉 f_θ_q 后位置误差从 0.033 m 恶化到 0.124 m（由表内数值 0.033→0.124 计算），RMS jerk 从 4.5e3 恶化到 3.3e4 m/s³，证明该组件对训练稳定性至关重要。

  3. LLM 作为任务管理器但不微调：将操作知识编码在 system prompt 中，通过 function-calling 接口选择技能。这避免了机器人控制中常见的“LLM 幻觉导致不可执行动作”问题，同时保持了高层决策的灵活性。这种“不微调、只提示”的设计让系统可以快速适配新任务，无需重新训练语言模型。

实验与结果

跟踪性能（Table I）

方法 位置误差 (m) 方向误差 (rad) RMS jerk (m/s³)
Ours 0.033 (0.011) 0.320 (0.093) 4.5e3
Ours w/o f_θ_q 0.124 (0.521) 0.9 (0.494) 3.3e4
No-force RL 0.028 (0.010) 0.317 (0.110) 9.9e3
End-to-end RL 0.053 (0.184) 0.349 (0.081) 6.9e3
  • 完整方法在位置误差上优于端到端 RL（0.033 vs 0.053 m），但略逊于 No-force RL（0.028 m）——后者不感知外力，因此跟踪更“硬”，但缺乏柔顺性。
  • 去掉 f_θ_q 后性能急剧恶化（位置误差 0.124 m，jerk 3.3e4），证明该组件对训练稳定性至关重要。
  • 绝对性能：位置 RMSE 3.3 cm，方向误差 0.32 rad，RMS jerk 4.5 × 10³。

真实世界遥操作

  • 书写任务：三次尝试中两次写出可识别的字母“IROS”。
  • box-on-wall rotation：成功完成六次连续旋转而不掉落物体。

模拟系统评估

  • 房间环境：床、沙发、桌子（平面位置随机 ±0.5 m，高度 0.5–0.7 m），三个盒子（初始位置随机 ±0.25 m）。
  • 单物体 loco-manipulation 任务成功率高达 70%（30 trials，含 explicit placement、linguistic variation、spatial-relation 三个子类）。
  • 长时程任务（10 trials）与简单任务（20 trials）均有评估，但具体数字论文未明确。

边界与局限

  • 遥操作中 locomotion 行为“functional but less natural and smooth compared to manipulation”，作者认为可能需要额外的 locomotion-specific 训练数据来改进——这意味着当前方法在移动质量上仍有明显短板。
  • 未对 planner compatibility 进行定量评估，仅作为定性验证（“We focus on verifying the interface compatibility as qualitative validation”），因此“接口兼容”这一核心卖点缺乏量化支撑。
  • 系统评估中故意采用最小技能集和单一 grasp primitive，以隔离系统级行为而非技能多样性——这意味着真实场景中技能组合的复杂性可能未被充分覆盖。
  • 未微调 LLM 用于机器人控制，依赖 system prompt 编码领域知识——这限制了模型对未见任务类型的泛化能力。
  • 论文未明确长时程任务的具体成功率数字，也未报告不同任务子类之间的性能差异。

工程启示

  • 复现优先级：先核对 f_θ_q 的实现细节——这是消融实验中影响最大的组件（位置误差 0.033→0.124 m，由表内数值计算），其输入输出维度、训练方式直接决定蒸馏稳定性。建议先单独复现 teacher 训练，再逐步加入 student 蒸馏。
  • 硬件选型：Unitree G1 + RealSense D435 + 三种可拆卸末端工具（hook、pen holder、eraser holder）是完整配置。若资源有限，可先用仿真验证 CEER 接口，再迁移到真实硬件——但需注意阻抗参数 K_p、K_d 的调优对真实接触动力学敏感。
  • 最易踩坑点：① 阻抗控制中的 K_p 逆矩阵计算——若刚度矩阵病态，柔顺目标会发散；② student 策略的观察空间包含 root yaw，但实际部署时 IMU 漂移可能影响 yaw 估计；③ LLM 任务管理器的 system prompt 设计——操作知识编码不完整会导致技能选择错误，建议先用固定规则验证中层技能，再引入 LLM。
  • 下游团队适配：若你的团队已有操作技能库（如 VLM-based 或 diffusion-based），可通过 CEER 接口直接对接，无需重写底层控制器。但需注意中层技能频率（10–20 Hz）与低层控制器（50 Hz）之间的时序同步，避免命令丢帧。
