Unified Human-Scene Interaction via Prompted Chain-of-Contacts

Unified Human-Scene Interaction via Prompted Chain-of-Contacts

层级

摘要

UniHSI 是一个由 OpenRobotLab 在 2023 年提出的统一人-场景交互框架，通过语言指令实现多样化交互控制。其核心创新在于将交互定义为“接触链”（Chain of Contacts, CoC），并利用大语言模型（LLM）规划器将语言提示转化为 CoC 任务计划，再由统一控制器执行。该框架在 ScenePlan 数据集上验证了其任务执行能力与对真实扫描场景的泛化性。

来源与参考

  • Unified Human-Scene Interaction via Prompted Chain-of-Contacts (arXiv)
  • Unified Human-Scene Interaction via Prompted Chain-of-Contacts project page

概述

UniHSI 是首个以语言命令为统一输入、基于物理仿真的人-场景交互（HSI）框架，由高层 LLM Planner 与低层 Unified Controller 组成。其核心创新在于将交互形式化为 Chain of Contacts（CoC），通过接触链的逐步规划与自适应奖励权重，实现单模型对多类型、多步骤交互的统一控制。实验表明，该方法在 ScenePlan 数据集上显著优于现有基线，并支持从 PartNet 到 ScanNet 的跨场景泛化。

它改变了什么

现有 HSI 方法长期困于“一任务一策略”的碎片化范式：物理方法（如 Hassan et al. 2023、Pan et al. 2023）为每个交互任务独立训练策略网络，无法共享控制知识；语言驱动方法（如 Wang et al. 2022b）则因目标物体与接触区域的定位困难而性能受限。这些方法共同的问题是缺乏一个既能理解高层语义指令、又能输出可执行物理交互的统一接口，导致实际应用中“用户说一句话，机器人做一套动作”的愿景始终无法落地。

UniHSI 真正改变的是将“交互意图”与“物理执行”之间的鸿沟用一层可解析的中间表示（CoC）桥接起来。它不再要求为每个动作手工设计奖励或接触规则，而是让 LLM 根据语言指令自动生成接触链，再由统一控制器通过对抗运动先验（AMP）学习执行。这一设计使得“坐下”“躺下”“伸手够物”等看似迥异的任务，在底层共享同一套控制网络，仅通过接触链的差异来区分，从而首次实现了真正意义上的多功能统一控制。

方法拆解

整体架构

UniHSI 采用两层流水线：高层 LLM Planner 负责将语言命令 L 与场景背景 B（物体 O 及部件 P）、人体关节信息 J 转化为任务计划；低层 Unified Controller 基于 AMP 框架执行计划，通过 TaskParser 将 CoC 转化为可优化的任务观测与奖励。

TaskParser 与接触奖励

对每接触对 {o, p, j, c, d}： 1. 收集关节位置 v^j ∈ R^3 和物体部件点云 v^p ∈ R^{m×3} 2. 选取距关节最近点 v^{np} 为接触目标点 3. 任务观测为 {v^{np} - v^j, c, d}，统一观测 s^U 为所有接触对观测集合

接触奖励 R^G = Σ w_k R_k： - c = contact：R_k = w_dis exp(-w_dk ||d_k||) + w_dir min(d̄_k · d̂_k, 0) - c = not contact：R_k = 1 - exp(-w_dk ||d_k||) - c = not care：R_k = 1 - R_k 尺度区间 [0, 1]

步骤完成判定与自适应权重

  • 完成条件：contact 时 ||d_k|| < 0.1 且 d̄_k · d̂_k > 0.8；not contact 时 ||d_k|| > 0.1；not care 时为 True
  • 自适应权重 w_k = (1 - R_k) / (n - Σ R_k + e)，难优化部分权重高、易优化部分权重低

关键创新

  1. CoC 作为统一交互表示：将多样化的交互任务（坐、躺、够物、多物体组合）统一为接触链序列，每个接触对用五元组精确描述。这一抽象层使得 LLM 的语义理解与物理控制器的数值优化得以解耦，是 UniHSI 能够实现单模型多任务的关键。相比此前接触驱动方法局限于人工设计特定交互，CoC 具备天然的可扩展性。

  2. LLM 驱动的零标注交互规划：训练无需任何带注释的人-场景交互序列，完全依赖 LLM 的交互知识生成计划。这打破了物理方法对昂贵 MoCap 数据的依赖，使得新交互类型的扩展只需修改提示词而非重新采集数据。实验证明，LLM 生成的计划在 ScenePlan 数据集上达到 91.1% 的简单任务成功率，验证了知识迁移的可行性。

  3. 自适应接触权重机制：w_k = (1 - R_k) / (n - Σ R_k + e) 动态调整各接触对的优化权重，使策略网络自动聚焦于难以满足的接触约束。消融实验显示，移除该机制后简单任务成功率从 91.1% 骤降至 21.2%，证明其在多步骤任务中的关键作用。

实验与结果

数据集与设置

  • ScenePlan 训练集：PartNet 40 个物体，每物体生成 5 ∼ 20 个交互步骤，每场景随机选 1 ∼ 4 个物体
  • 评估集：PartNet 40 个物体 + ScanNet 10 个场景，共 1040 个 PartNet 计划和 100 个 ScanNet 计划
  • 运动数据：SAMP（100 分钟 MoCap）+ CIRCLE（10 小时，超 7000 抓取序列，取 20 个代表性片段）
  • 模拟：IsaacGym，单 Nvidia A100 GPU，8192 并行环境

结果解读

  • 自适应权重消融显示，Hard 任务成功率从 39.7% 跌至 0.1%，说明多步骤任务中权重分配是成败关键
  • Heightmap 对 Hard 任务至关重要（0.0% vs 39.7%），但对 Simple 任务影响较小（61.6% vs 91.1%），表明碰撞规避在复杂场景中才成为瓶颈
  • ScanNet 泛化性能下降（Hard 32.2% vs PartNet 39.7%）但仍在可用范围，验证了 Heightmap 对真实扫描场景的适应性
  • 对比 AMP-VC，UniHSI 在 Sit 和 Lie Down 上分别提升 31.8%（由表内数值 0.076→0.1 计算） 和 61.4%（由表内数值 63.2−1.8 计算） 成功率，证明统一控制优于简单组合

边界与局限

论文明确承认以下边界： - 仅支持固定物体交互：框架无法处理移动或携带物体，与可移动物体的交互被列为重要未来方向。这意味着当前方法不适用于动态场景或需要物体重排的任务。 - LLM 未集成训练循环：当前使用预生成计划，LLM 仅在规划阶段介入，未参与策略优化。作者指出将 LLM 纳入训练流程可提升交互类型可扩展性。 - 评估场景模态差异：ScanNet 场景与 PartNet 训练集存在模态差异，虽通过 Heightmap 缓解，但 Hard 任务接触误差 0.311 仍显著高于 PartNet 的 0.101，泛化能力有限。 - 基线对比不完整：Hassan et al. 2023 代码不可用，仅报告其论文结果做粗略比较，缺乏严格同条件对照。

工程启示

对复现与工程实施的直接建议：

  1. 优先验证自适应权重机制：这是消融实验中影响最大的组件（Simple SR 从 91.1% 降至 21.2%）。复现时应先确认 w_k 的数值稳定性，特别是分母 (n - Σ R_k + e) 在早期训练中可能接近零，需设置合理的 e 值下限。

  2. Heightmap 是跨场景泛化的前提：若目标场景包含真实扫描数据（如 ScanNet），必须实现 ego-centric heightmap 观测。注意其分辨率与采样范围需与物体尺度匹配，否则 Hard 任务可能完全失败（0.0%）。

  3. LLM 计划质量直接决定上限：训练集每物体生成 5 ∼ 20 个交互步骤，计划质量依赖提示工程。建议严格遵循论文 Table 4 的规则（如“只与静止物体交互”“接近步骤用 none 占位”），否则生成的 CoC 可能包含物理上不可行的接触对。

  4. 计算资源需求明确：单 A100 GPU + 8192 并行环境，策略网络 [1024, 1024, 512] 规模适中。但 CIRCLE 数据集 10 小时 MoCap 的预处理与采样需提前规划，20 个代表性片段的选择标准论文未明确，需自行实验确定。

  5. 最易踩坑处：接触奖励中 w_dis 与 w_dir 的权重比、以及步骤完成判定阈值（0.1 距离、0.8 方向余弦）对训练收敛影响显著。建议先在小规模场景（1 物体、3 步内）调参，再扩展到多物体 Hard 任务。
