PhysForge: Generating Physics-Grounded 3D Assets for Interactive Virtual World

摘要

PhysForge 是一个用于生成具备物理交互属性的 3D 资产的解耦式两阶段框架，由研究团队提出。其核心贡献在于构建了包含 15 万资产的四级物理标注数据集 PhysDB，并利用 VLM 规划物理蓝图，再通过引入 KineVoxel Injection 机制的扩散模型生成高保真几何与精确运动学参数。

来源与参考

  • arXiv:2605.05163 PhysForge: Generating Physics-Grounded 3D Assets for Interactive Virtual World
  • Project page
  • GitHub仓库 Robotics_Notebooks

概述

PhysForge 是一个两阶段解耦框架，旨在从单张图像生成物理可交互的 3D 资产。它先用 VLM 规划器输出层级部件边界框与物理属性，再用扩散模型生成几何与关节参数，并配套发布了 150k 规模的 PhysDB 数据集。核心贡献在于将“物理功能”作为生成的首要约束，而非事后附加的标签。

它改变了什么

现有 3D 生成竞赛的终点是“看起来对”，而 PhysForge 试图把终点移到“用起来对”。它真正改变的，是让生成资产从静态几何的“空心外壳”变成具备功能逻辑与运动学定义的实体——这直接决定了资产能否被投入具身 AI 模拟器或游戏物理引擎。此前 OmniPart 等部件级方法只按视觉边界切分部件，从不关心部件为何存在；EmbodiedGen 等物理接地方法又依赖外部部件库或代码模板，泛化受限。PhysForge 的立场是：物体的结构是其物理功能的表现形式，因此生成必须由功能逻辑驱动，而不是由几何统计驱动。

方法拆解

Stage 1: VLM 物理规划器

  • 基础模型选 Qwen2.5-VL，输入为单张图像 I、TRELLIS 第一阶段的 3D 体素 V、可选的 2D 部件掩码 M。
  • 体素编码不走常见的 3DShape2VecSet，而是先用 PartField 提取逐体素特征，再用位置感知 3D 卷积下采样为 512 维嵌入。
  • 引入 66 个新 token：<boxs>/<boxe> 界定边界，64 个离散 token 量化坐标，每个 3D 边界框仅用 6 个 token 表达。
  • 关键设计：联合预测物理属性（材料、功能）与边界框，物理引导提供语义约束，显著缓解部件歧义。

Stage 2: 扩散生成器（KineVoxel Injection）

  • 扩展 OmniPart 第二阶段，提出 KVI 机制。单个部件关节参数为 8 维向量 P_i = (O_i, A_i, L_i)，其中 O_i ∈ ℝ³ 为原点，A_i ∈ ℝ³ 为轴，L_i ∈ ℝ² 为运动限制。
  • KineVoxel 由独立轻量 2 层 MLP 编码器 E_kine 处理，与几何潜变量 Z_g 在中间 transformer 共享潜空间：z_{k,i} = E_kine(concat(S_O·O_i, S_A·A_i, S_L·L_i))。
  • KineVoxel 在下采样后注入，与几何体素序列拼接送入主去噪 transformer；关节类型嵌入 E_type 帮助 transformer 区分两类潜变量。
  • 训练目标为条件流匹配（CFM），复合损失 L = E[L_geo + λ_kine·L_kine]，λ_kine = 10 强调关节参数精度。

PhysDB 数据集

  • 150k 物体，来自 Objaverse，覆盖 7 大类。四层标注：整体层、静态属性层、功能层、交互层。
  • 标注流程为人类在环：多模态 LLM 生成初稿，人工筛选修正。因 150k 规模下精确数值轴标注不可行，PhysDB 只提供关节类型与物理属性，数值轴由 PartNet-Mobility 和 Infinite-Mobility 补充。

关键创新

  1. 物理规划与物理实现解耦：VLM 负责“想”（规划部件与物理属性），扩散模型负责“做”（合成几何与运动学）。这避免了端到端方法中物理推理与几何生成互相干扰，也摆脱了对外部部件库的依赖。
  2. KineVoxel 统一表示：将关节参数编码为与几何潜变量同空间的特殊体素，使扩散模型能在统一去噪框架内联合优化几何与运动学，而非两阶段流水线式拼接。关节类型嵌入进一步强制模型学习“什么部件配什么关节”的语义关联。
  3. 物理引导的部件分解：联合预测物理属性与边界框，比纯几何分割更符合功能逻辑。消融显示即使无 2D 掩码输入，物理引导也能产生语义连贯的规划，这降低了对分割先验的依赖。

消融关键发现

  • 移除关节类型嵌入后 Joint-Axis-Err-all 从 0.164 升至 0.292；移除运动学编码器后升至 0.204，证明两者均对关节精度有实质贡献。
  • PhysForge-bbox（仅边界框训练，无物理信息）的 Voxel IoU 从 53.74 跌至 35.53，说明物理属性联合预测是部件分解质量的关键。

边界与局限

PhysDB 明确不提供精确数值轴标注，仅靠 PartNet-Mobility 和 Infinite-Mobility 补充，这限制了在未见类别上关节参数的泛化精度。论文未提及生成资产的物理仿真稳定性定量验证（如接触稳定性、抓取成功率），也未与真实机器人操作实验对比。KVI 机制对非关节类物体（如布料、流体）的适用性未讨论，计算资源需求也未量化。VLM 规划器在完全未见类别上的泛化边界没有压力测试。

工程启示

复现时先核对三件事：一是 VLM 规划器的体素编码是否必须用 PartField，若替换为其他编码器，物理引导的消融增益可能不成立；二是 λ_kine=10 的权重对关节精度影响极大，调低会显著恶化 Joint-Axis-Err；三是 PhysDB 的标注流程依赖人类在环，直接复用其标注质量需确认筛选标准。最容易踩坑的是 KineVoxel 的缩放因子 S_O/S_A/S_L——论文未给出具体数值，若量纲不匹配，MLP 编码器可能无法收敛。下游接入 RoboTwin 或 Unity 时，注意 PhysDB 的关节类型是离散标签，数值轴需从 PartNet-Mobility 迁移，跨域时轴方向约定可能不一致。
