AutoVLA

AutoVLA: A Vision-Language-Action Model for End-to-End Autonomous Driving with Adaptive Reasoning and Reinforcement Fine-Tuning

摘要

AutoVLA 是加州大学洛杉矶分校在 NIPS25 提出的端到端自动驾驶视觉-语言-动作模型。其核心贡献在于将连续轨迹离散化为可行动作，并引入双思维模式（快速/慢速推理）与基于 GRPO 的强化微调方法，在 nuPlan、nuScenes、Waymo 和 CARLA 等基准上取得竞争性表现。

来源与参考

  • AutoVLA: A Vision-Language-Action Model for End-to-End Autonomous Driving with Adaptive Reasoning and Reinforcement Fine-Tuning (arXiv)
  • AutoVLA source

概述

AutoVLA 提出 DuoCore-FS，一种真正异步并行的慢-快双系统 VLA 架构，用于全身操作。慢系统（1–3 Hz）负责语义推理与粗粒度动作 token 生成，快系统（25–30 Hz）基于扩散策略生成连续动作，两者通过可微桥接缓冲区实现端到端联合训练。在 Astribot S1 平台上的爆米花舀取任务中，DuoCore-FS 以 32.3 Hz 推理频率达到 90% 整体成功率，显著优于基线 π₀ 的 12.5 Hz 与 85%。

它改变了什么

现有 VLA 系统要么以单一频率强制同步运行，导致策略性能受限于大 VLM 的低推理速度；要么采用异步双系统但未实现真正并行推理，快控制器更新周期仍由预定调度决定。作者真正改变的是：将慢系统的语义推理与快系统的连续动作生成解耦为两个独立运行的进程，通过桥接缓冲区实现信息交换，从而在不牺牲端到端可训练性的前提下，让快系统以 30 Hz 高频运行而无需等待慢系统输出。

这一改变的关键在于打破了“推理频率必须等于控制频率”的隐含假设。以往系统被迫在语义丰富性与控制实时性之间做取舍，而 DuoCore-FS 证明两者可以兼得——慢系统以低频率提供全局语义指导，快系统以高频率执行局部动作生成，且两者通过可微接口联合训练，避免了级联架构中高层推理与实时控制之间的信息断层。

方法拆解

整体架构

DuoCore-FS 由低频慢系统（1–3 Hz）和高频快系统（25–30 Hz）组成，通过桥接缓冲区（bridge buffer）连接。慢系统使用大型 VLM（如 PaliGemma-3B）生成语义输出 r_t，包括思维链推理轨迹、边界框预测、子任务指示符和粗粒度离散动作 token。

慢系统

  • 损失函数：L_slow(φ) = E_{(o_t, l, r_t)∼D}[−log p(r_t | o_t, l)]，采用负对数似然目标
  • 以 1–3 Hz 刷新桥接缓冲区，存储指令嵌入和融合查询嵌入

桥接缓冲区与融合查询

  • 可学习融合查询 q_ψ 跨视觉观测、本体感受状态、任务指令和 VLM 内部语义空间进行注意力聚合
  • 参数 ψ 通过快系统的动作生成目标训练
  • 关键设计决策：仍将原始任务指令表示输入快系统，因为任务指令在执行过程中保持不变，仅依赖融合查询可能导致关键任务细节丢失

快系统

  • 以约 25–30 Hz 运行，采用 Pi0-small 风格扩散策略网络
  • 基于当前视觉观测、本体感受状态、桥接缓冲区中的最新融合查询和原始指令嵌入生成连续全身动作
  • 损失函数：L_fast(θ, ψ) = E_{A, ε, τ, Δ_t}[‖ε − A_{t:t+T−1} − v_θ(X_τ, o_t, B_{t−Δ_t})‖²₂]，其中 X_τ = τ ε + (1−τ) A_{t:t+T−1}，Δ_t 表示时变观测延迟

全身动作分词器

  • Astribot 平台具有 25 DoF 动作空间，动作 a_t ∈ ℝ²⁹ 分解为 [a_t^pos, a_t^rot, a_t^grip]
  • 动作块分解为 P ∈ ℝ^{T×9}（位置）、R ∈ ℝ^{T×18}（方向）、G ∈ ℝ^{T×2}（夹爪）
  • 每个控制流由独立轻量 1D 卷积编码器-解码器处理，用流特定残差向量量化（RVQ）模块离散化，每个 RVQ 栈维护大小为 1024 的码本
  • 分词器损失：位置和夹爪分支用 ℓ₂ 重建损失；方向分支用 SO(3) 测地距离；加上标准 VQ 目标

两阶段跨时间尺度协同训练

  1. 第一阶段：独立训练慢系统，学习高层推理并对齐视觉、语言和动作相关线索
  2. 第二阶段：联合训练快慢系统，引入跨时间尺度采样策略，Δ ∼ U[0, Δ_max]
  3. 联合目标：L_joint(φ, θ, ψ) = λ_slow·L_slow + λ_fast·L_fast，其中 λ_slow = 1，λ_fast = 10

异步推理

慢系统采用 Jacobi 风格并行解码策略加速 VLM 推理；快系统即使慢系统未产生新推理输出，仍使用先前刷新的指令和桥接嵌入平滑运行。

关键创新

  1. 真正异步并行的慢-快架构：与 FiS-VLA、OpenHelix 等强制固定频率比的系统不同，DuoCore-FS 实现两个系统完全独立运行，快系统更新周期不受慢系统调度限制。这是首个在全身操作中实现真正异步并行且保持端到端联合训练的 VLA 系统。

  2. 可微桥接缓冲区：桥接缓冲区作为慢系统、快系统和融合查询之间的可微接口，使整个系统能够端到端训练。这解决了 Hume 等级联架构中高层推理与实时控制之间缺乏交互的问题，让慢系统的语义信息能够直接影响快系统的动作生成。

  3. 流特定 RVQ 动作分词器：针对全身 25 DoF 动作空间，将位置、方向、夹爪分别分词，避免 FAST 分词器因组合爆炸产生数千个动作 token 的问题。RVQ-VAE 分词器平均 token 长度 36（vs FAST 的 81.12），最大长度 36（vs 205），推理频率 3.27 Hz（vs 0.95 Hz），成功率 83.3%（vs 0%）。

实验与结果

实验在 Astribot S1 移动双臂操作器上进行，数据集包含 1780 条示范轨迹（10.22 小时），场景为商业爆米花售货亭。训练使用 24 块 NVIDIA H100 GPU，推理在单块 RTX 4090 上完成。

边界与局限

语言跟随成功率仍远非完美（42.9%），主要归因于极端数据不平衡：饮料柜关门任务仅占训练集的 1%，且未应用任何不平衡缓解策略。典型失败案例为指令混淆：模型被要求“关闭饮料柜门”时却执行“拿起杯子”。

慢系统的推理动作 token 作为连续动作的有损抽象，阻碍了精细行为（如准确对齐勺子手柄）。作者未在更广泛真实世界任务（如动态场景、长时程操作）上评估，未引入高频力觉和触觉信号，未探索减少 flow-matching 步数或单步生成以加速 fast pathway，未设计更复杂的 slow 与 fast pathway 之间的桥接机制，未进行多任务基础模型预训练。论文未明确对更大 VLM（如 7B 参数）的完整实验验证。

工程启示

复现时先核对动作分词器的实现细节——这是系统性能的关键瓶颈。FAST 分词器因组合爆炸产生数千个动作 token，导致推理速度受限且顺序预测引发累积误差；RVQ-VAE 分词器将三个 SO(3) 分量分别分词并依次预测，显著缩短 token 长度。若你的平台动作空间维度较高，务必采用流特定分词策略。

训练时注意两阶段协同训练的超参数设置：λ_slow = 1，λ_fast = 10，帧级延迟采样 Δ ∼ U[0, 25]，动作块长度 T = 32。第二阶段联合训练 12 个 epoch，峰值学习率 5×10⁻⁵。推理时快系统需编译为 TensorRT BF16 以达到 32.3 Hz 频率，慢系统采用 Jacobi 风格并行解码加速。

最容易踩坑的地方是桥接缓冲区的设计——它必须作为可微接口参与端到端训练，否则慢系统的语义信息无法直接影响快系统的动作生成。另外，原始任务指令仍需输入快系统，仅依赖融合查询的语义信息会导致关键任务细节丢失。若你的下游任务涉及语言跟随，需注意数据不平衡问题，建议在训练集中平衡各子任务比例。
