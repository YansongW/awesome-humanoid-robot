ClimbingCap: Multi-Modal Dataset and Method for Rock Climbing in World Coordinate

摘要

ClimbingCap 是 2025 年由研究团队提出的多模态数据集与运动恢复方法，专注于攀岩这类离地运动的人体运动分析。其核心贡献在于构建了包含 412k 帧 RGB、LiDAR 与 IMU 数据的大规模攀岩数据集 AscendMotion，并提出了联合优化相机坐标与全局坐标的 ClimbingCap 方法，实现了对攀岩者复杂姿态与全局位置的精确重建。

来源与参考

  • ClimbingCap: Multi-Modal Dataset and Method for Rock Climbing in World Coordinate (arXiv)

概述

ClimbingCap 提出了一套面向人形机器人双臂灵巧操作的全自动数据生成与策略学习框架，包含空间标注、场景生成、MCTS 增强推理等模块，并构建了包含 20 个任务的 HGen-Bench 基准。核心贡献在于用 LLM 规划加树搜索替代人工遥操作，实现了可扩展的高质量演示数据生成，并验证了生成数据对扩散策略训练的有效性。

它改变了什么

现有机器人数据集的瓶颈不在数量，而在获取方式。Open-X、RH20T 这类真实数据集主要靠人工遥操作，成本高且难以覆盖双臂协调场景；仿真基准如 Aloha 又缺乏灵巧手和任务多样性。ClimbingCap 真正改变的是数据生产的成本结构——它把“人写代码”变成了“LLM 写代码 + MCTS 纠错”，让数据生成从劳动密集型转向算力密集型。这个转变的意义在于，它让数据规模不再受限于操作员数量和技能水平，而是受限于仿真资产和计算资源。

另一个被改变的隐性假设是：LLM 直接生成的规划代码往往在长时程任务中因累积误差而失败。ClimbingCap 用 MCTS 的搜索树结构对 LLM 输出进行分段、截断、重组和恢复，相当于给 LLM 的“一次性生成”加上了“自我纠错”机制。这解决的不是单步动作的精度问题，而是多步任务中错误传播的结构性问题。

方法拆解

空间标注体系

三类标注构成 LLM 理解物理世界的基础： - 手部原子操作：定义接近轴、附着轴、平行轴三类关键轴，以“捏取”为例，接近轴指定手接近预捏取姿态的方向，附着轴指示手指运动方向（从拇指尖指向食指尖），平行轴垂直于前两者且平行于手掌平面。 - 资产固有信息：标注资产自身功能对应的点和轴，如杯子有倒水和存储两种功能。 - 资产操作标注：定义资产上可应用原子操作的点与轴，原子操作与资产非一一对应。

任务规划与约束优化

LLM 将长时程任务分解为动作序列 𝒮 = {S₁, ..., Sₙ}，每步包含左右手部分。手臂运动定义为约束优化问题 Mᵢ = {f(Cᵢ^goal), f(Cᵢ^path)}，其中目标姿态约束和路径约束在物体坐标系 ℱ_obj、手坐标系 ℱ_hand、世界坐标系 F_world 之间强制几何关系（重合、平行、轴向对齐）。

碰撞管理

  • 主动碰撞避免：LLM 生成包含碰撞避免行为的原子操作脚本。
  • 动态碰撞管理：LLM 维护物体忽略列表并动态调整，如拉抽屉时将抽屉加入忽略列表，之后移除以恢复碰撞检测。

STCR 机制（MCTS 增强）

  1. Segment：按执行粒度将规划代码分割为多个步骤。
  2. Truncate：在错误发生点截断，保留有效段 𝒮_remain = {Sᵢ | 1 ≤ i ≤ k−1}。
  3. Combine：合并意图一致的原子操作形成新序列 𝒮′_remain，每个组合代表树中一个可执行分支。
  4. Resume：新节点存储已执行序列的代码、错误代码和场景状态，在节点被选中扩展时恢复。

MCTS 与标准版本的区别在于扩展过程中加入模拟步骤以提供节点执行结果。

场景扩展

通过计算原始场景与新场景坐标系之间的变换矩阵进行对齐，利用 RoboCasa 资产可跨 120 多个场景泛化演示。

关键创新

1. 全自动数据生成管线替代人工遥操作：这是对现有数据生产方式的根本性替换。VR 遥操作和外骨骼设备需要操作员具备熟练技能，且难以覆盖多样化场景。ClimbingCap 用 LLM 规划加仿真执行，让数据生成从“人肉驱动”变为“算力驱动”，这是可扩展性的关键。

2. STCR 机制将 LLM 输出转化为可搜索的规划树：这不是简单的“LLM + MCTS”拼接。Segment-Truncate-Combine-Resume 四步操作让 LLM 的每次输出都成为树中的一个可执行分支，错误步骤被截断后，剩余有效段可以重组为新的搜索节点。这解决了 LLM 在长时程任务中错误累积的问题，且 token 消耗增加 26% 带来 55% 的成功率提升（由表内数值 15.3→19.3 计算）。

3. 空间标注体系让 LLM 能理解物理约束：将手部原子操作、资产功能和操作关系抽象为关键点和关键轴的集合，使 LLM 不需要从原始点云或图像中推理几何关系，而是直接操作符号化的空间约束。这是 LLM 能生成可执行规划代码的前提。

实验与结果

数据生成与执行评估

对比基线为 RobotTwin（修改官方实现添加灵巧手）。使用 DeepSeek-R1 生成和执行演示脚本。HumanoidGen 在所有灵巧操作任务中平均成功率超过 50%，大多数任务类型成功率超过 75%。在长时程和复杂碰撞任务上，HumanoidGen 优于 Robotwin。

边界与局限

论文未明确列出局限性章节，但从实验可推断：对于长时程任务如 'blocks stack easy'，DP 和 DP3 在数据有限时性能明显下降；DP 性能不佳可能归因于 RGB 信息的固有限制，DP3 需要建模高自由度动作和管理复杂长时程任务，需要更多数据。部分任务策略表现出非平稳特性，动作不稳定且有风险。未考虑双臂策略学习中的先验知识（如人-物交互、几何约束、手臂运动基元），直接训练 2D 和 3D 扩散策略。未提及真实机器人部署实验，未提及与真实遥操作数据对比。

工程启示

复现时先核对空间标注的完整性——这是整个管线的基础，如果手部原子操作的接近轴、附着轴、平行轴定义不准确，后续所有规划都会出错。最容易踩坑的地方是动态碰撞管理中的忽略列表维护，LLM 需要根据任务阶段动态调整物体碰撞状态，这个逻辑在长时程任务中容易遗漏。

对于下游团队，建议优先关注 MCTS 的 N 值选择。从表 1 看，'blocks stack hard' 任务从 N=8 到 N=12 成功率提升 20%（由表内数值 78.3→98.3 计算），但 token 消耗增加约 12%。如果算力有限，可以先跑 N=2 或 N=3 验证管线，再针对困难任务加大搜索深度。

数据有效性方面，DP3 在多数任务上优于 DP，但 'open box hard' 和 'close drawer' 任务中 DP 反而表现更好，说明 2D 策略在某些结构化任务上仍有优势。建议根据任务类型选择策略，不要盲目追求 3D 方法。另外，部分任务策略的非平稳特性（如 'close box hard' 中 DP 从 20 条演示的 82.2% 降到 100 条的 31.1%）提示，数据量增加不一定带来性能提升，需要监控训练稳定性。
