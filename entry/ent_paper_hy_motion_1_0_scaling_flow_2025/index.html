HY-Motion 1.0: Scaling Flow Matching Models for Text-To-Motion Generation

HY-Motion 1.0: Scaling Flow Matching Models for Text-To-Motion Generation

摘要

HY-Motion 1.0 是一系列基于 Diffusion Transformer (DiT) 的流匹配模型，首次将文本到3D人体运动生成模型扩展至十亿参数规模。该模型通过全阶段训练范式（包括3000小时大规模预训练、400小时高质量微调及强化学习）实现指令跟随能力，覆盖6大类200余种运动类别，显著超越现有开源基准。

来源与参考

  • arXiv:2512.23464 HY-Motion 1.0: Scaling Flow Matching Models for Text-To-Motion Generation

概述

HY-Motion 1.0 是首个将基于 DiT 的流匹配模型扩展到十亿参数规模的文本到动作生成系统，由腾讯等机构完成。它通过构建超过 3000 小时的多源动作数据管线（野外视频、动捕、3D 资产），结合层次化双条件文本编码与三阶段训练（预训练-微调-RL），在指令跟随（SSAE 78.6%）和动作质量（3.43/5）上显著超越现有开源基准。

它改变了什么

这个工作的真正改变在于把"数据规模"从配角推到了主角位置。此前领域内主流做法（MoMask、GoToZero、LoM）要么依赖 HumanML3D 这类小规模标注集，要么用离散分词器牺牲动作平滑性换取语义多样性。HY-Motion 1.0 证明了：当动作数据达到数千小时量级并经过系统化清洗标注时，纯连续表示的流匹配模型可以同时解决"语义对齐差"和"物理伪影多"这两个长期痛点——它没有发明新的数学框架，而是把 LLM 领域已被验证的"数据+规模"路线成功迁移到了动作生成。

更关键的是，它改变了行业对"动作生成 scaling 曲线"的认知。作者通过消融实验揭示了一个非平凡结论：指令跟随能力随模型规模单调提升（0.05B→1B 平均分 3.10→3.34），但动作质量在 0.46B 后饱和（3.26→3.34 仅微增）。这意味着过去社区盲目堆参数的做法是低效的——真正的瓶颈在数据多样性和语义覆盖，而非模型容量。这一发现直接为后续工作指明了资源分配方向。

方法拆解

数据管线（核心壁垒）

  • 多源采集：1200 万野外视频片段（经镜头边界检测+人体检测器筛选）→ GVHMR 重建 SMPL-X 轨迹；另加约 500 小时动捕/3D 动画资产。
  • 统一处理：全部重定向至中性 SMPL-H（22 关节无手部），三步过滤（去重、异常姿态/速度/位移检测、脚滑伪影检测），重采样至 30fps，>12 秒序列切分。
  • 标注增强：视频源直接用原始视频，3D 数据渲染成合成视频；Gemini-2.5-Pro 生成初步标注，人工验证高质量子集，LLM 标准化结构并多样化改写。

动作表示

每帧向量 f ∈ ℝ²⁰¹：全局根平移 t ∈ ℝ³、全局朝向 r ∈ ℝ⁶、局部关节旋转 jr ∈ ℝ²¹ˣ⁶、局部关节位置 jp ∈ ℝ²²ˣ³。关键决策：移除速度/脚接触标签（作者观察到收敛更快），旋转用连续 6D 表示（兼容动画工作流，不同于 HumanML3D）。

HY-Motion DiT 架构

  • 混合 Transformer：双流块（动作/文本独立 QKV+MLP，联合注意力交互）与单流块（拼接序列，并行空间+通道注意力）交替。
  • 非对称注意力掩码：动作 token 全局关注文本，文本 token 被掩码不关注动作——防止文本表征被动作噪声污染。
  • 窄带时间掩码：注意力限制在 121 帧滑动窗口内（30fps 下约 4 秒），降低长序列计算复杂度。
  • 层次化双条件：Qwen3-8B 提取 token 级语义（经 Bidirectional Token Refiner 转双向），CLIP-L 提供全局嵌入，通过分离的 AdaLN 注入。

训练策略

  • 流匹配目标：最优传输路径 x_t = (1−t)x₀ + tx₁，损失 L_FM = E[||v_θ(x_t, c, t) − (x₁−x₀)||²]。
  • 三阶段：3000+ 小时预训练（常数 LR η_pre）→ 400 小时精选微调（LR=0.1η_pre）→ 两阶段 RL（DPO 精选 9228 对 + Flow-GRPO 整合 TMR 语义奖励与脚滑/根漂移物理惩罚）。
  • 时长预测：Qwen3-30B-A3B 两阶段训练（SFT 生成"优化提示+时长"，GRPO 用 Qwen3-235B 评判语义与时间合理性）。

关键创新

  1. 首次验证动作生成模型的 scaling law：通过 0.05B/0.46B/1B 三档 DiT 的系统对比，证明指令跟随能力随规模持续提升，但动作质量存在饱和点。这一发现直接指导了"轻量版 Lite（0.46B）"的发布策略——不是所有场景都需要 1B 模型。

  2. 数据工程成为第一生产力：将 LLM 领域的"数据配比+清洗+增强"方法论完整迁移到动作领域。特别是"视频→3D 重建→统一骨架→VLM 标注→人工精修→LLM 改写"的闭环管线，解决了此前动作数据集规模小、标注不一致的根本瓶颈。3000 小时预训练数据是现有公开集（HumanML3D 约 14 小时）的 200 倍量级。

  3. 非对称注意力+窄带时间掩码：这个架构设计看似简单但很实用——文本 token 不关注动作避免了语义表征被动作噪声干扰，而窄带掩码在 121 帧窗口内保持了局部时间连贯性，同时将计算复杂度从 O(T²) 降为 O(T·W)。这是工程上"用掩码换效率"的典型范例。

实验与结果

与 SOTA 对比（2000+ 提示，人工 1-5 分）

模型 指令跟随 SSAE 动作质量
MoMask 2.31 58.0% 2.79
GoToZero 2.19 52.7% 2.86
DART 2.31 42.7% 3.11
LoM 2.17 48.9% 3.06
HY-Motion 1.0 3.24 78.6% 3.43

HY-Motion 在指令跟随上的优势（+0.93（由表内数值 2.1÷2.2 计算） vs 最强基线）远大于动作质量（+0.32（由表内数值 1.0→1.0 计算）），说明规模化主要解决的是"理解指令"而非"生成动作"。

分类别表现（HY-Motion 最强项）

  • 指令跟随：移动类 (a) 3.76 最高，游戏角色 (f) 3.01 最低——复杂角色动作仍是短板。
  • 动作质量：移动类 3.59 最佳，健身类 (c) 3.28 最弱。

规模消融（表 3/4）

模型 指令跟随 动作质量
DiT-0.05B 3.10 2.91
DiT-0.46B 3.20 3.26
DiT-0.46B-400h 3.05 3.31
DiT-1B 3.34 3.34

关键发现：DiT-0.46B-400h（仅 400h 数据）动作质量 3.31 接近 1B 的 3.34，但指令跟随仅 3.05 远低于 1B 的 3.34——数据规模对语义理解的影响远大于模型容量。

边界与局限

  • 复杂指令仍是硬伤：作者明确承认对高度详细/组合指令的理解不充分，根因是标注管线难以对细微动作生成完整准确的文本描述——这是数据工程的固有天花板，不是模型架构能单独解决的。
  • 人-物交互（HOI）缺失：当前表示不含物体几何信息，生成持工具、推车等交互动作时无法保证物理接触点准确。这是表示层面的根本限制，不是训练技巧能弥补的。
  • 未报告标准基准指标：论文未提供 HumanML3D 上的 FID、R-Precision 等定量对比，无法与历史工作直接对齐。作者可能有意回避——因为其数据分布和评估协议与 HumanML3D 差异较大。
  • 未披露关键工程细节：训练步数、batch size、硬件配置、推理延迟均未给出，复现门槛较高。

工程启示

  • 先核对数据管线再谈模型：HY-Motion 的核心壁垒是 3000 小时清洗数据。如果复现，优先验证 GVHMR 重建质量（脚滑过滤阈值、异常姿态检测参数）和 VLM 标注一致性——这两步决定了后续所有训练的上限。
  • 规模选择有讲究：如果目标是动作质量优先（如影视预演），0.46B Lite 版足够；如果目标是复杂指令跟随（如虚拟人助手），必须上 1B。不要盲目追求大模型，先评估下游任务对语义理解的需求强度。
  • 最容易踩坑的地方：① 移除速度/脚接触标签后，需要确保物理奖励（Flow-GRPO 中的脚滑惩罚）足够强，否则动作平滑性会退化；② 非对称注意力掩码实现时容易出错——文本 token 的 attention mask 必须显式置零，否则训练不稳定；③ 窄带时间掩码的窗口大小（121 帧）与采样率强相关，换采样率必须重新调参。
  • RL 阶段性价比高：DPO（9228 对）和 Flow-GRPO 带来的提升在论文中虽未单独消融，但从 0.46B-400h 与 0.46B 的对比看，数据量对指令跟随的影响远大于 RL——建议先保证预训练数据质量，再投入 RL 调优。
