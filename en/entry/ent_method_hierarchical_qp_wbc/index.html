Summary

A whole-body control method that stacks multiple tasks by priority and solves them as a cascade of quadratic programs, ensuring higher-priority tasks are fulfilled before lower-priority ones.

Overview

Hierarchical QP Whole-Body Control (HQP WBC) is a strict-priority implementation of whole-body control: tasks such as "maintain balance > track end-effector trajectory > avoid joint limits" are ordered by priority, with higher-priority tasks fully satisfied before lower-priority tasks are solved only within their null space, each layer solving a QP or synthesized via null-space projection. It addresses the unacceptable issue in safety-critical scenarios where weighted-sum methods allow tasks to "compromise" with each other (source: project Wiki Chapter 8 §8.4.10.2; Escande et al. 2014, DOI 10.1177/0278364914521306).

Content

What it is: precise definition

Given a priority-ordered task stack \(\{(\mathbf{J}_i, \ddot{x}_i^*)\}_{i=1..p}\), the strict hierarchy requires: level 1 task is optimal; level 2 is optimal within the null space of level 1; and so on. The classical two-level decomposition for joint velocities is (source: project Wiki Chapter 8 §8.4.10.2):

\[ \dot{\mathbf{q}} = \mathbf{J}_1^\dagger \dot{\mathbf{x}}_1^* + \mathbf{N}_1 \mathbf{J}_2^\dagger \left( \dot{\mathbf{x}}_2^* - \mathbf{J}_2 \mathbf{J}_1^\dagger \dot{\mathbf{x}}_1^* \right), \qquad \mathbf{N}_1 = \mathbf{I} - \mathbf{J}_1^\dagger \mathbf{J}_1 \]

The first term completes the primary task; the second term accomplishes the secondary task without affecting the primary task. Extending this to the torque/acceleration level and incorporating dynamics, friction cones, and other constraints yields Hierarchical QP (HQP): solving constrained QPs layer by layer, with each layer optimizing in the null space of the previous layers (Escande et al. 2014 provides a fast HQP solver for online humanoid motion generation).

Why it exists: pain points and historical positioning

Weighted-sum WBC expresses task importance via weights \(w_i\) in a single QP, which is simple to implement but has a structural risk: weights are soft constraints—when disturbances are large enough, the "don't fall" task can have resources diverted to the "reach the object" task. For safety-critical tasks, compromise is unacceptable.

Historical lineage of the hierarchical idea: Khatib's operational-space null-space projection (1987) → Sentis & Khatib's whole-body task prioritization (2000s) → Escande et al. turning strict hierarchy into a real-time solvable HQP (2014, IJRR). What it truly changes is not the solver but the principle for handling task conflicts: from "compromise" to "hierarchy"—rather than degrading safety tasks, secondary tasks are sacrificed.

Principle breakdown

① Intuition behind null-space projection

\(\mathbf{N}_1 = \mathbf{I} - \mathbf{J}_1^\dagger \mathbf{J}_1\) projects any joint motion onto the subspace that "does not change the primary task output." A humanoid robot has 30+ degrees of freedom while a single task requires only a few directions; the remaining DOFs are the living space for secondary tasks—redundancy is the fuel for hierarchical control (Wiki §8.4.10.1–8.4.10.2).

② Strict hierarchy vs. weighted sum (Wiki §8.4.10.2)

  • Strict hierarchy: higher-priority tasks are fully satisfied, lower-priority tasks execute in the null space; safety tasks cannot be compromised;
  • Weighted sum: all tasks are weighted and solved in one QP, allowing trade-offs between tasks; weight tuning is intuitive but carries compromise risk;
  • Relationship: strict hierarchy can be approximated by extremely large weight differences, but exact implementation requires layer-by-layer null-space projection.

③ Real-time HQP

The computational cost of layer-by-layer QPs grows with the number of layers. The 2014 work by Escande et al. provides a fast online solver, pushing HQP to online humanoid motion generation (DOI 10.1177/0278364914521306). A common engineering compromise is "hybrid hierarchy": the top 1–2 levels are strict (balance, limits), while lower levels are merged into a weighted sum (comfort tasks such as posture optimization).

Who uses it / application cases

  • Whole-body support for manipulation tasks: Wiki Chapter 16 §16.5.2 documents humanoid manipulation solving the task stack "maintain balance > track end-effector trajectory > avoid joint limits" with HQP by priority;
  • Online motion generation: Escande et al. 2014 pushes humanoid HQP to real time (DOI in references);
  • Graph neighbors: ent_formalism_inverse_dynamics_qp (inverse dynamics QP formalism), ent_equation_weighted_task_error_objective (weighted objective), ent_operator_task_jacobian (task Jacobian operator).

Limitations and boundaries

  • Computational cost grows with the number of layers: layer-by-layer QPs plus null-space projection are more expensive than a single QP; embedded real-time use requires trimming;
  • Inter-layer feasibility: if higher-priority constraints are too strong, the lower-priority null space may be empty, requiring relaxation strategies;
  • Priority design is safety design: misordering the hierarchy (e.g., placing posture optimization before balance) is a hidden source of accidents;
  • Model dependence: as with all WBC, dynamics model errors directly contaminate the null space.

Common misconceptions

  1. "Increasing the weighted-sum weight equals priority"—extremely large weight differences are only an approximation; soft priorities can still be violated under disturbances, while strict hierarchy provides inequality-based guarantees.
  2. "More layers is always better"—each layer incurs computational and feasibility costs; in engineering, 2–4 levels plus a hybrid layer is the norm (engineering judgment).
  3. "HQP outputs positions"—like WBC, the output is at the acceleration/torque level and must be executed by the servo layer.
  4. "With RL, hierarchy is unnecessary"—learned policy actions are still often passed through a WBC/HQP layer for safety constraint enforcement.
