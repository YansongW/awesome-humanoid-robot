Summary

CLoSD: Closing the Loop between Simulation and Diffusion for multi-task character control is a 2024 work on physics-based character animation for humanoid robots.

Sources

  • CLoSD: Closing the Loop between Simulation and Diffusion for multi-task character control (arXiv)
  • CLoSD: Closing the Loop between Simulation and Diffusion for multi-task character control project page

概述

CLoSD 提出一种闭环架构，将快速自回归扩散规划器（DiP）与物理跟踪控制器（基于 PHC）结合，实现单一策略完成目标到达、打击、坐下、起身等多任务。核心贡献在于利用扩散模型作为实时通用规划器，并通过闭环微调使控制器对生成计划鲁棒，无需任务专用奖励工程。

它改变了什么

现有工作将运动生成与物理控制视为两个独立问题：扩散模型擅长生成多样、文本可控的运动，但推理慢且物理不准确；RL 控制器物理合理但依赖单任务专用奖励，难以扩展到大规模数据集。CLoSD 改变了这一范式——它不再试图让扩散模型直接输出可执行运动，而是将其降级为“即时规划器”，生成短时参考轨迹，由物理控制器负责执行与修正。这解决了两个核心痛点：扩散模型的推理速度（10 步去噪，11.4 ms 生成 2 秒运动）使其首次可用于实时闭环；同时，物理仿真纠正了扩散模型固有的脚滑、穿透等物理伪影。

更关键的是，CLoSD 证明了单一策略无需任务专用奖励即可完成多种交互任务。此前 UniHSI 在起身任务上成功率仅 0.08，因其仅优化接触点距离导致角色抬骨盆而非真正站立；CLoSD 通过闭环重规划与微调，将起身成功率提升至 0.98。这表明“生成-跟踪”闭环比“直接优化接触”更鲁棒，因为规划器能根据实际状态动态调整目标。

方法拆解

架构总览

CLoSD 由两个模块组成，形成闭环： - DiP（扩散规划器）：自回归实时扩散模型，生成未来 N_g=40 帧（2 秒）参考运动。 - π_PHC（跟踪控制器）：基于 PHC 的简化版（单一策略，无专家混合），用 PPO 训练，跟踪 DiP 输出的关键点轨迹。

DiP 设计

  • 输入：干净前缀运动 x_prefix（长度 N_p=20）与带噪预测 x_t_pred（长度 N_g=40）拼接，加位置嵌入，每帧一个 token。
  • 条件注入：通过交叉注意力注入每层，条件序列为 (C_t + C_target, C_text) ∈ ℝ^(N_tokens+1)×d。C_text 用冻结 DistilBERT 编码；C_target 包含任意关节目标位置 c_j 与有效性信号 v_j，以及身体朝向角 c_θ 与 v_θ。
  • 目标损失：L_target = Σ_{j∈J} v_j ||R2G(x̂_0[N_g])_j - c_j||²₂ + v_θ ||R2G(x̂_0[N_g])_θ ⊖ c_θ||²₂，其中 R2G 是可微的相对到全局坐标转换器。
  • 总损失：L = L_simple + λ_target · L_target，λ_target 为权重。
  • 推理：标准 DDPM 迭代，从 x_T_pred ~ N(0,I) 开始，10 步去噪（相比 MDM 的 50 步加速 5 倍）。

闭环机制

  1. DiP 生成 N_g 帧计划。
  2. π_PHC 逐帧执行，PD 控制器跟踪关键点。
  3. 当到达计划末尾，取仿真状态 x_sim 最后 N_p 帧，经 G2R 转换作为新前缀输入 DiP，生成下一段计划。
  4. 简单状态机检测任务完成（如坐下：骨盆在坐区上；打击：目标与地面角度 < 75°），切换文本提示与目标。

训练流程

  • DiP 预训练：HumanML3D 数据集，MDM 框架，600K 扩散步，RTX 3090，200K 检查点对 CLoSD 最优。
  • π_PHC 预训练：AMASS 数据集，62K PPO epochs，仅跟踪关节位置（不跟踪旋转）。
  • 闭环微调：固定 DiP，PPO 微调 π_PHC 额外 4K epochs，无需奖励工程或重置工程，可同时为多个任务微调同一策略。

关键创新

  1. 扩散模型作为通用规划器：此前扩散模型仅用于离线生成，CLoSD 首次将其用于实时闭环控制（3500 fps 生成速度，175× 实时）。关键创新在于自回归前缀机制——每次仅生成 N_g 帧，用仿真状态更新前缀，使规划器能感知实际执行误差。

  2. 任意关节目标条件：DiP 支持对任意关节指定目标位置（如“用勾拳打击”+左手目标），通过有效性信号 v_j 处理部分关节无目标的情况。这比 UniHSI 仅支持末端执行器位置更灵活，且目标条件通过可微 R2G 转换直接监督全局坐标，避免了表示不一致问题。

  3. 闭环微调替代奖励工程：固定 DiP，仅微调跟踪控制器，即可让同一策略适应多个任务。这避免了为每个任务设计奖励函数（如 AMP 需要对抗奖励、InterPhys 需要接触奖励），大幅降低了工程成本。消融显示微调对交互任务至关重要（w.o. fine-tuning 起身成功率 0.53 vs 微调后 0.98）。

边界与局限

  • 无外感受：控制器与规划器均未使用视觉或高度图，仅依赖目标位置，无法处理需要环境感知的复杂场景（如动态障碍）。
  • 中期规划：仅聚焦 2 秒级规划，未处理长时间任务分解（如“先走到厨房再坐下”）。
  • 无时间自适应：循环长度固定，未实现时间自适应（快速运动需要更紧密反馈）或更长跟踪视界。
  • 物理准确性：扩散模型仍可能产生脚滑、漂浮等伪影，依赖物理仿真纠正，但极端情况（如快速旋转）可能超出控制器能力。
  • 扩展性：论文未明确多物体、动态障碍等复杂场景的表现。

工程启示

  • 复现优先级：先核对 DiP 的 10 步扩散与 N_p=20、N_g=40 配置，这是速度与质量平衡点。200K 检查点比 600K 更优，说明早期停止对闭环任务有益。
  • 最大踩坑点：闭环微调是交互任务成功的关键（起身 0.53 → 0.98），跳过此步骤会导致严重性能下降。微调时固定 DiP，仅更新 π_PHC，可同时优化多任务。
  • 表示转换：DiP 使用 HumanML3D 相对表示，RL 策略使用 PHC 全局表示，R2G/G2R 转换必须可微且正确实现，否则目标损失无法有效监督。
  • 分类器自由引导：任务实验用 2.5，纯文本到运动用 5，DiP-only 用 7.5。引导过高会降低物理合理性，需按场景调整。
  • 硬件要求：训练需 A100（3072 并行环境）与 RTX 3090（DiP 训练），推理单 GPU 即可达 3500 fps，适合实时应用。
