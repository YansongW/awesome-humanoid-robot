Overview

NVIDIA is a key component manufacturer in the humanoid robotics field, providing a full-stack solution ranging from edge computing hardware (Jetson series) to simulation training platforms (Isaac Sim / Isaac Lab) and humanoid foundation models (GR00T). What it truly changes is not the computing power of a single chip, but the physical AI development paradigm of "training—simulation—inference" three-computer collaboration, enabling robotics companies to accelerate the path from algorithms to real-world deployment in a "simulation-first" manner.

Content

What it is: From GPU vendor to physical AI platform company

NVIDIA was founded in 1993, headquartered in Santa Clara, California, USA, and is a publicly traded company (NASDAQ: NVDA). Its business covers AI computing platforms, robotics software/simulation, and chip supply, occupying a key position in the "upstream computing platform + intelligence layer" of the humanoid robotics industry chain.

NVIDIA's GPUs were originally designed for graphics rendering but have now become the mainstay of general-purpose parallel computing (GPGPU), particularly suited for matrix multiplication, convolution, deep learning, and point cloud processing. In the humanoid robotics field, NVIDIA provides Jetson edge computing modules, Isaac Sim simulation environments, Isaac Lab training frameworks, and GR00T humanoid foundation models, forming a complete "three-computer" solution: one for training, one for simulation, and one for edge inference.

Why it exists: Computing power bottlenecks and the simulation gap in robotic intelligence

Humanoid robot perception, decision-making, and control impose extremely high demands on computing power. A 50 Hz visual closed loop requires end-to-end inference latency below 20 ms, while the whole-machine thermal design power (TDP) requires the inference engine to complete as many operations as possible per watt. Traditional PC/industrial PC + motion control card architectures struggle to meet power and size constraints, making dedicated embedded SoCs the inevitable choice.

Meanwhile, real-world data collection is costly and carries safety risks; training policies purely on physical robots is neither economical nor feasible. NVIDIA's Isaac Sim provides high-fidelity physics simulation and synthetic data generation capabilities, allowing developers to train and validate policies in digital twins before transferring them to physical robots via Sim2Real—this is the core driver of the "simulation-first" methodology.

Principle breakdown

① GPU parallel computing architecture: SIMT and memory hierarchy

NVIDIA GPUs employ the SIMT (Single Instruction, Multiple Threads) execution model: 32 threads in the same warp execute the same instruction but operate on different data. When threads diverge due to branching, execution must be serialized (branch divergence), reducing efficiency.

The GPU memory hierarchy design is key to performance. Shared memory is a high-speed programmable cache within the SM, with latency approximately 1/100 that of global video memory. By loading data from global memory into shared memory and then having threads collaborate on computation, dependence on bandwidth can be significantly reduced. GPU peak computing power \(P\) is related to the number of CUDA cores \(N\), frequency \(f\), and operations per cycle per core \(o\):

\[ P = N \times f \times o \]

where \(s\) is the scale factor and \(z\) is the zero-point. After quantization, MAC operations in convolutional or fully connected layers can be completed with integer arithmetic, then dequantized back to FP32 output using scale and zero-point.

② Model deployment path: PyTorch → ONNX → TensorRT

Perception networks for humanoid robots are typically trained in PyTorch during the R&D phase, but must be converted to formats that run efficiently on embedded GPUs/NPUs for deployment. PyTorch → ONNX → TensorRT is currently the most mainstream deployment path on NVIDIA Jetson platforms. ONNX (Open Neural Network Exchange) is a cross-framework model representation format; TensorRT is NVIDIA's inference optimizer, capable of layer fusion, precision calibration, kernel auto-tuning, and dynamic tensor memory optimization.

Quantization is a critical step in deployment. FP32 is the default 32-bit floating point for training and baseline inference, offering the highest precision but with the greatest overhead; FP16 is 16-bit half-precision floating point, natively supported by NVIDIA GPU Tensor cores, typically providing significant speedup with almost no precision loss; INT8 is 8-bit integer, requiring calibration to determine scale and zero-point, which can greatly reduce memory footprint and computation but may lose precision. For robot perception tasks that are precision-sensitive (e.g., depth estimation, pose estimation), QAT or mixed precision is often adopted.

The Jetson series uses ARM64 CPUs with integrated Ampere/Volta GPUs. Power modes are configured via nvpmodel (switchable power caps such as 15 W / 30 W / 50 W), and operating frequencies can be locked using jetson_clocks to eliminate jitter from frequency switching. Monitoring tools include jtop (third-party TUI/API that reads CPU/GPU frequency, temperature, power, fan speed) and tegrastats (NVIDIA's official command-line tool that outputs raw system statistics). Jetson also integrates the DLA (Deep Learning Accelerator), a dedicated deep learning accelerator suitable for low-power inference; when operators are not supported by DLA, they are automatically executed on the GPU via a GPU fallback mechanism.

Horizontal comparison

In the edge AI computing platform space, the main competitors to the NVIDIA Jetson series include:

  • Intel NUC 13 Pro: x86 architecture, CPU is Core i5/i7, AI computing power is only several TOPS, power consumption 28–65 W, suitable for development and high-end main controllers, but AI computing power is far below the Jetson AGX Orin.
  • Qualcomm RB5 / QCS8550: ARM architecture, AI computing power 15–48 TOPS, power consumption 5–15 W, suitable for perception front-ends, but the ecosystem and simulation toolchain are less mature than NVIDIA's.
  • Tesla FSD Chip: ARM + NPU architecture, AI computing power 144 TOPS, power consumption approximately 36 W, designed for autonomous driving, with limited application in humanoid robotics.
  • Rockchip RK3588: ARM architecture, AI computing power only 6 TOPS, power consumption 5–10 W, suitable for low-cost perception scenarios, with a clear performance gap.

NVIDIA's core advantage lies in its complete software ecosystem: Isaac Sim provides high-fidelity simulation, Isaac Lab supports reinforcement learning training, TensorRT provides inference optimization, and GR00T provides humanoid foundation models—this vertical integration of "hardware + software + models" is difficult for competitors to replicate.

Who uses it · Application cases

Current mainstream humanoid robot manufacturers generally adopt a "central brain + distributed cerebellum" architecture, with the NVIDIA Jetson series being a common choice for the upper computer:

  • Agility Digit / Figure 02: Use NVIDIA Jetson or similar platforms for multi-camera perception and navigation, with lower layers connecting joint actuators via EtherCAT or similar buses.
  • UBTech Walker / Zhiyuan Expedition A2 / Fourier GR-1: Mostly use NVIDIA Jetson AGX Orin / Xavier or domestic alternative platforms as the upper computer, combined with ARM MCU/FPGA for real-time joint control.
  • Boston Dynamics Atlas: Uses embedded real-time computers for state estimation and gait control, emphasizing determinism for high-dynamic motion. Although it has not publicly adopted Jetson, it represents an alternative technical route.

In the research domain, NVIDIA Isaac Lab has become the mainstream platform for reinforcement learning training. The FastTD3 algorithm has demonstrated excellent performance on benchmarks such as HumanoidBench, IsaacLab, and MuJoCo Playground, with a single NVIDIA A100 GPU completing training on all HumanoidBench tasks within 3 hours. Additionally, NVIDIA collaborates with global robotics leaders to advance physical AI from the laboratory to the real world.

Limitations and boundaries

  1. Physical constraints of power and heat dissipation: The Jetson AGX Orin has a typical power consumption of 15–60 W, requiring effective thermal design under high load. For battery-powered humanoid robots, the power budget needs careful management, and power mode switching via nvpmodel is a necessary engineering measure.

  2. Precision loss from INT8 quantization: INT8 quantization can greatly reduce memory footprint and computation but may lose precision. For precision-sensitive tasks such as depth estimation and pose estimation, QAT or mixed precision strategies are required, adding deployment complexity.

  3. Supply chain risks: NVIDIA is a fabless design company, relying on foundries such as TSMC for chip manufacturing. Geopolitical factors and capacity fluctuations may affect the supply stability of the Jetson series, and some domestic manufacturers have already shifted to domestic alternative platforms.

  4. Simulation-to-reality gap: Although Isaac Sim provides high-fidelity physics simulation, Sim2Real transfer still faces domain gaps. Sensor noise, contact dynamics, and other factors in simulation do not perfectly match the real world, requiring additional domain randomization and real-robot fine-tuning.

Common misconceptions

  1. "Higher Jetson computing power is always better"—Wrong. Computing power (TOPS) is only one metric; actual performance depends on memory bandwidth, thermal conditions, and software optimization. The Jetson AGX Orin's 275 TOPS requires 15–60 W of power, which may be impractical on battery-powered robots. Selection should comprehensively consider power, size, thermal, and task requirements.

  2. "TensorRT is a free accelerator, and using it always makes things faster"—Not entirely. TensorRT's layer fusion and kernel auto-tuning can indeed significantly improve inference speed, but the effect depends on model structure and operator types. Certain custom operators may not be supported by TensorRT, requiring fallback to GPU or CPU execution, which can actually reduce performance.

  3. "Policies trained in simulation can be deployed directly to real robots"—Wrong. Sim2Real transfer is a recognized challenge in robotics. No matter how accurate Isaac Sim's physics engine is, it cannot fully replicate real-world contact, friction, and sensor noise. Domain randomization, system identification, and real-robot fine-tuning are necessary.

  4. "NVIDIA just sells chips"—Wrong. NVIDIA's true value lies in the complete "three-computer" ecosystem: training (DGX/cloud), simulation (Isaac Sim), and inference (Jetson). What it truly changes is not the computing power of a single chip, but the overall methodology of robot development—shifting from "trial and error on physical robots" to "simulation-first, cloud-collaborative."
