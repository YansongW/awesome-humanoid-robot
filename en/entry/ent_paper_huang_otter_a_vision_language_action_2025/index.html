Summary

OTTER: A Vision-Language-Action Model with Text-Aware Visual Feature Extraction (OTTER), is a 2025 large vision-language-action model for robotic manipulation, introduced by University of California, Berkeley, Meta AI, and published at ICML25.

Sources

  • OTTER source

概述

OTTER 是加州大学伯克利分校与 Meta AI 联合提出的视觉-语言-动作（VLA）模型，核心思路是冻结预训练视觉-语言编码器，通过显式的文本感知特征提取，仅将与语言指令语义对齐的视觉 token 传递给策略 Transformer。该方法在仿真与真实世界拾取-放置任务上均优于 Octo 与 OpenVLA，尤其在未见物体上展现出更强的零样本泛化能力。

它改变了什么

现有 VLA 路线存在一个根本性矛盾：要么像 Octo、OpenVLA 那样把视觉与语言特征独立送入策略网络，破坏预训练 VLM 中精心对齐的语义空间；要么像 RT-2 那样直接微调整个 VLM，但机器人数据集的语义多样性远低于 VLM 预训练所用的大规模图文数据，微调反而会“污染”预训练特征，导致在分布外物体或环境上性能骤降。OTTER 真正改变的是对“预训练对齐”这一资产的处置方式——不再试图在微调中保留或修复它，而是把它当作不可再生的固定资源，通过架构设计去主动提取和利用，而非被动依赖微调去维持。这一判断将问题从“如何微调得更好”转向“如何设计提取机制”，是 VLA 设计哲学上的一个转向。

方法拆解

整体架构

OTTER 由三部分组成：冻结的视觉编码器、冻结的文本编码器、可训练的策略 Transformer。视觉与文本编码器来自同一个预训练 VLM，确保两者处于同一语义空间。

文本感知视觉特征提取

  • 输入语言指令经文本编码器得到 token 序列，视觉观测经视觉编码器得到密集的视觉特征图。
  • 关键步骤：计算每个视觉 token 与每个文本 token 的相似度（如点积或交叉注意力），据此筛选出与指令语义高度对齐的视觉 token。
  • 仅将筛选后的视觉 token（而非全部视觉特征）与文本 token 拼接，送入策略 Transformer 预测动作。

设计决策与理由

  • 冻结编码器：避免机器人数据微调破坏预训练语义对齐，保留大规模预训练带来的丰富视觉-语言理解。
  • 选择性提取：与直接特征传递（Direct Feature Passing）不同，OTTER 不把全部视觉特征塞给策略网络，而是按文本相关性过滤，减少策略网络需要处理的无关视觉噪声，同时降低计算量。
  • 策略 Transformer 可训练：只在策略层进行任务适配，视觉-语言表征完全复用预训练成果。

关键创新

  1. 显式文本感知的视觉筛选机制：此前 VLA 要么全量传递视觉特征（Octo、OpenVLA），要么隐式依赖注意力（RT-2），OTTER 首次在架构层面显式地以文本为查询条件筛选视觉 token，使策略网络只看到与当前指令相关的视觉信息。这是对“语言条件化”这一概念的更彻底贯彻。
  2. 冻结编码器 + 选择性提取的组合：既避免了微调对预训练特征的破坏，又通过提取机制解决了冻结编码器输出与策略网络输入之间的语义鸿沟问题。这一组合在 VLA 领域此前未被系统验证。
  3. 对预训练对齐的“资产化”处理：将 VLM 预训练学到的语义对齐视为不可再生的固定资产，通过架构设计去提取而非通过微调去维护，这一思路对数据稀缺的机器人领域具有方法论层面的启示。

实验与结果

论文在仿真与真实世界两个层面进行验证，对比基线为 Octo 与 OpenVLA。

实验场景 OTTER Octo OpenVLA
真实世界训练任务成功率 更高（论文未明确具体数值） 较低 较低
真实世界未见任务成功率 更高（论文未明确具体数值） 明显下降 明显下降
未见物体零样本泛化 保持强性能 性能下降 性能下降
  • 真实世界实验中，OTTER 在训练过的拾取-放置任务上成功率高于两个基线，在未见过的任务上优势更明显。
  • 对未见物体的零样本泛化是 OTTER 最突出的表现，这与“冻结编码器保留预训练语义”的设计预期一致。
  • 具体成功率数字在摘要中未给出（对应表格为图片，数字未提取），论文未明确。

边界与局限

  • 论文未明确列出局限性，但根据其动机论述可推断：OTTER 的提取机制依赖文本与视觉 token 之间的语义对齐质量，若指令描述与视觉内容存在较大歧义或抽象程度过高，筛选可能失效。
  • 实验仅覆盖拾取-放置类任务，未涉及更复杂的操作（如多步装配、工具使用），结论的泛化范围有限。
  • 冻结编码器意味着无法通过机器人数据进一步适配特定场景的视觉分布，在视觉域与预训练分布差异极大的场景（如极端光照、特殊材质）下，性能可能受限。
  • 论文未明确训练配置、推理频率、硬件需求等工程细节。

工程启示

  • 复现时优先核对预训练 VLM 的选择与冻结策略，这是 OTTER 性能的根基；若更换 VLM，文本-视觉对齐质量会直接影响提取效果。
  • 最容易踩坑的地方是视觉 token 与文本 token 的相似度计算方式——不同 VLM 的 token 空间维度与语义粒度差异较大，需要针对具体模型调整匹配函数与筛选阈值。
  • 下游团队若想迁移 OTTER 到新任务，应先验证现有指令文本能否与视觉特征形成清晰对齐；若指令过于抽象或视觉场景过于复杂，建议先扩充指令描述粒度，而非直接调整策略网络。
  • 由于编码器冻结，机器人数据仅用于训练策略 Transformer，训练成本相对可控，但这也意味着视觉侧的任何缺陷都无法通过下游数据弥补，数据采集时应尽量贴近预训练分布。
