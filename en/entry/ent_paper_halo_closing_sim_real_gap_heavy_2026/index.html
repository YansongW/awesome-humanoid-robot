Overview

HALO is a two-stage differentiable simulation system identification framework for agile locomotion skills of heavy-load humanoid robots, proposed by the research team. It relies solely on joint encoders to achieve zero-shot sim-to-real transfer. Its core contribution lies in treating payload variations as structured dynamics mismatch, efficiently identifying the base model and payload parameters through analytical gradients in MuJoCo XLA, and demonstrating significant performance improvements in heavy-load walking and highly agile maneuvers on the Unitree G1.

What It Changes

Existing deep reinforcement learning policies trained under nominal dynamics suffer severe performance degradation when faced with large, structured payload variations. Domain Randomization treats payloads as perturbations to be avoided, producing conservative behavior that fails to fully exploit the robot's physical capabilities; traditional SysID relies on torque sensors or motion capture systems, which are impractical for floating-base humanoid robots. What HALO truly changes is: redefining the heavy-load carrying problem as a structured sim-to-real gap rather than random noise, thereby replacing black-box optimization or conservative randomization with analytical gradients from differentiable simulation, achieving zero-shot transfer without external sensing or robot disassembly. This shift means system identification moves from "laboratory-specific" to "field-deployable," with identification accuracy sufficient to support zero-shot deployment of highly agile maneuvers (e.g., roundhouse kicks).

Method Breakdown

Data Collection and Preprocessing

  • Two bench vises mechanically constrain one foot of the robot, using only joint encoders to reconstruct full-body trajectories via forward kinematics, eliminating global base drift ambiguity.
  • Due to sensor noise causing inconsistent left/right foot heights, a constrained QP is solved at each time step, applying minimal adjustments to the root node and lower-limb joint increments.

Two-Stage Identification Strategy

  • Stage 1 (Base Model Calibration): Using no-load trajectories, optimize all model parameters from nominal values to reduce inherent sim-to-real gap.
  • Stage 2 (Payload Parameter Identification): Using the calibrated model as initialization, optimize only the mass and CoM positions of the torso and hand links, using loaded trajectories.
  • Design rationale: Directly optimizing from nominal values on loaded trajectories produces biased estimates; restricting Stage 2 parameter ranges avoids misattributing base errors to payloads while circumventing the complexity of inertia tensor optimization.

Trajectory Matching Optimization

  • Objective function: min_θ L_total(θ) = L_track(θ) + R(θ), gradient descent θ_{k+1} = θ_k − η ∇_θ L_total(θ_k).
  • Tracking loss: position loss for all rigid bodies + additional loss for an upper-body subset (weight α^u), emphasizing links most affected by payload.
  • Regularization: R_total = λ_com R_com + λ_mass R_mass + λ_damp R_damp + λ_fric R_fric, using box-constraint function φ(α; l, u) to penalize deviations outside the interval.

Skill Acquisition

  • Motion imitation method based on mjlab, with PPO optimizing an MLP policy to maximize tracking rewards aligning joint states and body poses with reference trajectories.
  • Due to accurate parameter identification, only minimal DR (nominal range) is needed during training for zero-shot transfer.

Key Innovations

  1. Two-Stage Identification Strategy: Decouples base model calibration from payload parameter identification, avoiding error attribution confusion and significantly improving convergence robustness under extremely heavy loads (CMA-ES diverges under Setting 3 while HALO converges robustly).
  2. Joint-Encoder-Only Data Collection: Using bench vises to constrain one foot eliminates base drift, combined with QP post-processing, requiring no torque sensing or motion capture, making SysID feasible on real floating-base robots.
  3. Analytical Gradients from Differentiable Simulation: Compared to black-box optimizers like CMA-ES, HALO converges with zero variance under extremely heavy loads (Table II), with minimal data requirements (authors note that a few trajectories suffice to identify dominant differences).

Boundaries and Limitations

The paper does not explicitly mention limitations. From a methodological perspective, HALO relies on bench vises to fix one foot during data collection, limiting deployment in unstructured environments; the two-stage identification assumes payloads only affect the torso and hand links, which may fail for leg payloads or complex inertia variations; real-world experiments only validate a 6 kg torso + 2×2 kg wrist payload, leaving heavier or more complex payload distributions uncovered; training configurations (PPO hyperparameters, network architecture) and inference frequency are not disclosed, introducing uncertainty in reproduction.

Engineering Insights

When reproducing, prioritize verifying: 1) Whether MuJoCo XLA's gradient computation aligns with real simulation, especially contact models; 2) Tolerance settings for QP post-processing when fixing one foot with bench vises, which directly affect trajectory quality; 3) Stage 2 learning rates (mass 0.03, CoM 0.0002) need adjustment based on robot scale—excessively large CoM learning rates cause divergence. The most common pitfall is regularization terms—not enabled in simulation experiments, but real-world scenarios require careful tuning of λ_com and λ_mass, otherwise the parameter space may be overly constrained. For downstream teams, it is recommended to first reproduce Setting 3 in Table II to verify identification robustness before investing in real hardware; if payloads exceed the torso+hand range, the Stage 2 parameter set needs expansion.
