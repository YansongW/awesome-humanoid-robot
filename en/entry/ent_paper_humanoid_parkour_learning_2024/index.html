Summary

Humanoid Parkour Learning is a 2024 work on locomotion for humanoid robots.

Sources

  • Humanoid Parkour Learning (arXiv)
  • Humanoid Parkour Learning project page

概述

本文提出Humanoid Parkour Learning，旨在为仿人机器人（Tienkung平台）构建统一的多模态占用感知系统，解决传感器布局、数据标注与多模态融合挑战。核心贡献包括：提出畸变感知投影方法（将镜头畸变参数直接编码进视图变换，避免去畸变以保留像素），以及基于时间特征对齐（双线性插值扭曲+通道拼接）的BEV编码器与FlashOcc风格预测头，总损失融合focal、lovasz-softmax及affinity loss。在自采数据集（6相机+1 LiDAR，180训练/20验证clip）上，多帧（2帧）融合设置下达到mIoU 55.73、rayIoU 61.32，优于BEVFusion（53.21/59.56）且参数量仅40.5M；消融显示畸变投影提升mIoU约1.5，但超过2帧时间融合因位姿误差累积导致性能下降。

它改变了什么

这篇论文真正改变的，是仿人机器人感知系统的一个长期被忽视的盲区——数据与算法范式的错位。过去几年，占用预测（occupancy prediction）在自动驾驶领域被推到近乎成熟，但它的数据采集、传感器布局、标注协议乃至评估指标，全部围绕车顶传感器阵列和道路场景设计。仿人机器人研究者要么直接搬用这些预训练模型，要么在自采数据上微调，却很少有人意识到：双足平台的运动学特性、传感器安装高度、以及室内外混杂场景的语义分布，与自动驾驶有本质差异。作者没有去发明新的网络结构，而是先承认了这个前提——现有公开数据集和评估基准根本不适用于仿人机器人，因此他们从零构建了Tienkung平台的多模态数据集，并重新定义了占用预测的坐标范围（Z轴-1.5m到0.9m，而非自动驾驶常见的路面以上数米）。

更值得注意的改动在于畸变处理。常规做法是先对鱼眼或广角图像做去畸变（undistortion），再送入BEV变换，但作者反其道而行之，将镜头畸变参数直接编码进视图变换矩阵。这个细节看似工程优化，实则改变了信息流：去畸变会重采样像素、丢失边缘信息，而仿人机器人恰恰需要近距离、大视角的周边感知——直接投影保留了原始像素密度，在消融中raw图像+畸变投影比undistorted图像+针孔投影的mIoU高出0.5个点，验证了这一判断。

时间融合的发现也颇具颠覆性。作者采用StreamPETR风格的连续帧训练，但实验显示超过2帧历史信息反而导致性能下降（3帧mIoU从55.73降至55.11，4帧进一步降至54.3）。他们归因于机器人运动中的位姿误差累积——这暴露了仿人机器人相比自动驾驶的一个关键差异：车辆运动模型相对平滑，而双足行走的步态周期引入的抖动和漂移，使得跨帧特征对齐的噪声远大于收益。这实际上是在提醒社区：不能把自动驾驶的时间融合策略当作默认选项，需要针对平台运动学重新设计。

最后，参数效率的对比也值得玩味。在融合相机与LiDAR的条件下，HumaniodOcc以40.5M参数达到55.73 mIoU，而BEVFusion用60.6M参数只有53.21 mIoU。这说明作者在架构上没有堆砌模块，而是通过合理的通道-高度重分配和3D卷积块设计，在保持性能的同时大幅压缩了模型——这对算力受限的嵌入式机器人平台是实质性的改变。

方法拆解

整体架构：以时间对齐为核心的轻量级多模态占用预测

HumanoidOcc 的出发点很直接：仿人机器人（Tienkung 平台）在运动过程中存在显著的位姿变化与传感器畸变，直接套用自动驾驶的占用预测方案会因几何失真而失效。因此方法围绕三个关键设计展开——时间特征对齐、畸变感知投影、轻量级预测头，三者共同服务于“用最少参数换取最高语义-几何精度”这一目标。

时间特征对齐：基于自运动的 BEV 特征扭曲

  • 核心操作是扭曲函数 \mathcal{W}(\cdot)，利用双线性插值将历史 BEV 特征根据自运动（ego-motion）变换到当前帧坐标系。
  • 对齐后的历史特征与当前帧特征沿通道维度拼接，形成时间融合输入： F_t^{temp} = Concat([F_t, F_{t-1}^{aligned}, ..., F_{t-k}^{aligned}])
  • 关键设计决策：仅在训练第二个 epoch 之后才引入时间信息（StreamPETR 风格），避免早期训练不稳定。消融实验显示 2 帧最优（mIoU 55.73），3 帧以上性能下降（3 帧 mIoU 55.11，4 帧 54.3），作者归因于机器人运动过程中位姿误差随帧数累积——这是与自动驾驶场景的本质差异，后者通常受益于更长时序。

畸变感知投影：不做去畸变，直接编码畸变参数

  • 传统做法是先对原始图像去畸变再投影，但作者指出这会丢失边缘像素的有效信息。
  • 该方案将镜头畸变参数直接编码进视图变换矩阵，在投影过程中隐式补偿畸变，保留原始图像的完整像素。
  • 消融实验验证了这一设计的必要性：raw 图像 + 畸变投影（mIoU 47.92）优于 undistorted 图像 + pinhole 投影（mIoU 47.41），也优于 raw 图像 + pinhole 投影（mIoU 46.23）——说明畸变补偿与原始像素保留缺一不可。

预测头：FlashOcc 风格的低成本 3D 体素生成

  • 2D BEV 特征经 FPN 融合后，通过通道到高度重分配（channel-to-height reassignment）重塑为 3D 体素空间：将 BEV 特征的通道维分割为预定义的高度 bin 数，直接 reshape 成 [H, W, Z, C] 的体素特征。
  • 随后使用轻量 3D 卷积块处理体素特征，最小化计算成本——这是参数量控制的关键（总参数量仅 40.5M，显著低于 BEVFusion 的 60.6M）。
  • 输出网格为 200×200×24，体素尺寸 0.1m×0.1m×0.1m，覆盖范围 X/Y 轴 [-10m, 10m]，Z 轴 [-1.5m, 0.9m]。

损失函数：多任务联合优化

总损失为四项加权和： \mathcal{L}_{total} = \mathcal{L}_{focal} + \mathcal{L}_{ls} + \mathcal{L}^{geo}_{scal} + \mathcal{L}^{sem}_{scal} - \mathcal{L}_{focal}：处理类别不平衡的 focal loss。 - \mathcal{L}_{ls}：lovasz-softmax loss，直接优化 IoU。 - \mathcal{L}^{geo}_{scal} 与 \mathcal{L}^{sem}_{scal}：遵循 MonoScene 的 affinity loss，分别优化场景级几何 IoU 和类别级语义 mIoU——这保证了网络在几何边界与语义完整性上同时收敛。

训练策略与工程细节

  • 基于 mmdetection3d 框架，8×A100 GPU，batch size 4，AdamW 优化器，初始学习率 2e-4，余弦退火 + warmup，共 20 epoch。
  • 相机分支采用预训练 ResNet50+FPN，输入多视图图像 resize 至 960×768。
  • 评价指标采用 mIoU（3D 语义分割精度）与 rayIoU（沿 LiDAR 射线采样计算 IoU，避免深度轴不一致惩罚），后者对仿人机器人这种非规则运动场景尤为重要。

关键创新

这篇论文的核心创新在于，它没有把仿人机器人感知当作“缩小版自动驾驶”来处理，而是直面了平台差异带来的三个本质问题，并给出了工程上可落地的解法。

第一点创新：畸变感知投影（Distortion-Aware Projection）。 这是全文最“反直觉”也最值得称道的一处。现有BEV感知管线几乎默认使用针孔模型，对广角镜头先做去畸变再投影。但作者反其道而行之，将镜头畸变参数直接编码进视图变换矩阵，跳过图像去畸变步骤。消融实验给出了硬核支撑：raw图像+畸变投影达到mIoU 47.92，而undistorted图像+针孔投影只有47.41，raw图像+针孔投影更是跌到46.23。这说明去畸变过程本身会损失边缘像素的有效信息，而仿人机器人视野更近、畸变更大，这个损失被放大了。这一改动不增加任何参数量，纯粹是几何建模的胜利。

第二点创新：轻量化多模态融合架构。 在融合相机与LiDAR时，作者没有堆叠复杂模块，而是用ResNet+FPN做BEV编码，预测头沿用FlashOcc的通道到高度重分配策略，配合focal loss、lovasz-softmax loss和Monoscene的affinity loss。结果是在单帧设置下，HumaniodOcc以40.5M参数（比BEVFusion的60.6M少33%）达到rayIoU 60.49，超越BEVFusion的60.24；多帧设置下mIoU 55.73、rayIoU 61.32全面领先。这说明仿人机器人场景下，参数效率与精度可以兼得，而非靠算力堆砌。

第三点创新：时间融合的“适度原则”发现。 作者采用StreamPETR风格的连续帧训练，但实验揭示了一个反直觉结论：2帧融合最优（mIoU 55.73），3帧和4帧反而下降（55.11和54.3）。归因于仿人机器人运动时位姿误差随帧数累积。这一发现对实际部署至关重要——它意味着盲目增加历史帧数在双足平台上是有害的，为后续系统设计划定了安全边界。

三点创新共同指向一个判断：仿人机器人感知不是算法竞赛，而是对传感器特性、运动学约束和计算预算的精细化建模。畸变处理、轻量化融合、时间帧数选择，每一项都直接回应了平台痛点，且用消融实验给出了可复现的决策依据。

实验与结果

实验在自建的仿人机器人多模态数据集上进行，数据由6个摄像头与1个LiDAR采集，共180个训练clip与20个验证clip，每个clip含200帧。占用预测范围设定为X/Y轴±10m、Z轴-1.5m至0.9m，输出200×200×24的3D体素网格，体素尺寸0.1m。训练采用8块NVIDIA A100 GPU，batch size为4，AdamW优化器，初始学习率2e-4，共20个epoch，时间信息从第二个epoch起引入。

主结果（Table 2）显示，在单帧设置下，本文方法HumaniodOcc（C+L）以40.5M参数量取得mIoU 52.79与rayIoU 60.49，虽mIoU略低于BEVFusion（53.98），但rayIoU更高且参数量减少33%（由表内数值 44.57→59.13 计算）。多帧（2帧）设置下优势明显：HumaniodOcc的mIoU提升至55.73，rayIoU达61.32，均超过BEVFusion（53.21/59.56）与所有单帧基线，表明时间融合对仿人机器人场景的增益显著。

消融实验揭示了三个关键设计决策的贡献。畸变处理（Table 3）方面，直接在raw图像上使用畸变感知投影（mIoU 47.92）优于先做去畸变再投影（47.41）与pinhole投影（46.23），验证了将镜头畸变参数编码进视图变换的有效性。时间帧数（Table 4）方面，从1帧增至2帧带来mIoU提升2.94（由表内数值 47.93−50.89 计算）（52.79→55.73），但继续增加至3帧、4帧反而下降（55.11/54.30），作者归因于机器人运动中的位姿误差累积——这与自动驾驶场景中多帧融合持续获益的规律不同，是仿人平台特有的约束。模态融合（Table 5）方面，融合C+L（55.73/61.32）显著优于仅相机（50.37/55.98）与仅LiDAR（48.61/59.01），且相机在语义上占优、LiDAR在几何上占优，互补性明确。

总体而言，该方法在参数量减少约33%的前提下，以2帧时间融合取得最优性能，验证了轻量级架构与畸变感知投影在仿人机器人占用预测中的实用性。但时间融合的帧数上限（2帧）与位姿误差敏感性，是部署到真实平台时需重点关注的工程瓶颈。

边界与局限

本文的边界首先体现在数据集与平台单一性上：所有实验均基于自建的Tienkung平台数据集，训练与验证clip均来自同一机器人本体与传感器配置，未在公开数据集（如nuScenes）或异构仿人平台上验证，因此结论的泛化性存疑——不同身高、关节构型或传感器布局的机器人，其自运动模式与畸变特性可能显著改变时间对齐与投影的有效性。其次，时间融合策略存在明确上限：作者承认加入超过一个历史帧（即2帧以上）后mIoU与rayIoU均下降，归因于位姿误差累积，这意味着该方法仅适用于短时间窗口，在长时程或高动态场景（如快速转向、连续颠簸）下，性能可能进一步退化，论文未给出误差补偿或置信度加权的替代方案。第三，模态互补的边界被量化揭示：仅LiDAR时语义mIoU仅48.61，明显弱于仅相机（50.37），说明当前LiDAR分支的语义特征提取能力不足，融合增益主要来自几何补全而非语义增强，因此对低纹理或反光物体（LiDAR点云稀疏区域）的预测可能失效。第四，畸变感知投影虽在raw图像上优于去畸变方案，但增益有限（mIoU提升约0.5），且未测试极端广角镜头或鱼眼畸变下的鲁棒性。最后，论文未涉及动态障碍物速度预测、遮挡推理或与下游规划控制的闭环集成，所有指标均为静态占用精度，实际跑动中因位姿漂移导致的性能衰减未被量化。

工程启示

工程启示：复现与选型前先核对三件事

  1. 时间融合是双刃剑，别盲目堆帧数。论文明确给出：2帧最优（mIoU 55.73），3帧即回落至55.11，4帧进一步降至54.3。原因是仿人机器人运动时位姿误差随帧数累积。下游团队若在Tienkung类平台上复现，务必先标定好自运动（ego-motion）精度，否则加帧只会恶化结果。建议默认从2帧起步，不要直接照搬自动驾驶常用的4帧以上配置。

  2. 畸变感知投影是“免费午餐”，但需改视图变换代码。消融显示，raw图像+畸变投影（mIoU 47.92）优于去畸变+pinhole（47.41）和raw+pinhole（46.23）。这意味着你不需要额外做去畸变预处理，但必须把镜头畸变参数编码进视图变换层。最容易踩坑的是：若沿用现成BEVDet或BEVFusion代码，其默认pinhole投影会直接损失约1.5个mIoU点。复现时先确认代码是否支持自定义投影函数。

  3. 模态融合收益不均衡，别迷信“多模态必胜”。融合（C+L）mIoU 55.73，比仅相机（50.37）高5.36，但仅LiDAR也有48.61。更关键的是rayIoU：仅LiDAR（59.01）已接近融合（61.32），说明LiDAR对几何占用贡献极大。若你的下游任务更看重rayIoU（如避障），且相机标定质量不佳，可考虑降级为纯LiDAR方案，省去相机分支的40.5M参数和同步开销。但注意：仅LiDAR的语义区分差，若需语义分割则必须融合。

最易踩坑点：训练配置中batch size为4、8卡A100，但未提及推理频率。安全代理每10ms检查一次消息（来自Annie论文），而本论文未给推理延迟——复现时需自行benchmark，避免在真实机器人上因推理过慢导致控制频率不足。另外，代码未开源，需按mmdetection3d框架自行实现，建议先跑通单帧baseline（mIoU 52.79）再引入时间融合，否则问题定位困难。
