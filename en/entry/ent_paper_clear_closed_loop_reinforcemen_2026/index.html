Summary

arXiv:2607.02841v1 Announce Type: new Abstract: End-to-end autonomous driving (E2E-AD) aims to directly map raw sensor information to driving actions. Recently, with the rapid advancement of multi-modal large language models (MLLMs), researchers have proposed the paradigm of Vision-Language-Action (VLA) models for E2E-AD, where it seeks to integrate visual perception, language understanding and action prediction within a single policy. However, existing VLA-based policies largely adopts imitation learning, where it only learns to drive by optimizing distance-based metrics w.r.t. logged expert trajectories. Such distribution shift between open-loop training and closed-loop inference leads to suboptimal performance in closed-loop planning. To close this gap, we present CLEAR, a system that enables closed-loop training using Reinforcement Learning (RL) at scale for E2E-AD. We propose to learn a novel residual waypoint policy around the waypoint prior from pretrained VLA policies, effectively harnessing the knowledge within. On another front, one of the key challenges to scale up RL for vision-based policies is the number of parallel simulation environments since RL is data hungry. To that end, we design a heterogeneous pipeline that places the simulator and the VLA learner on distinct compute groups, which allows us to dramatically increase the number of simulation environments running in parallel while avoiding resource contention and maintaining training stability. We show that with a simple reward, CLEAR significantly outperforms previous methods and sets new state-of-the-art performance on the challenging benchmarks of CARLA longest6 v2 and Bench2Drive.

概述

CLEAR 提出了一套面向端到端自动驾驶 VLA 策略的大规模闭环强化学习微调系统，核心贡献在于通过异构流水线将 CARLA 模拟器与 VLA 学习者分离部署，从而将并行仿真环境扩展到 64 个，并基于 PPO 在 100M 样本规模下完成微调。该系统在 CARLA longest6 v2 与 Bench2Drive 基准上显著超越纯模仿学习基线，并在 nuScenes 上展现出零样本泛化能力。

它改变了什么

现有 VLA 策略的闭环性能瓶颈并非来自模型容量，而是训练范式与基础设施的错配。模仿学习仅优化与专家轨迹的距离度量，导致开环训练与闭环推理之间的分布偏移，这在安全关键场景中尤为致命。已有的闭环 RL 方法虽在特权规划任务上有效，但依赖完美感知真值，与真实部署中感知误差普遍存在的情况脱节。作者真正改变的是将闭环 RL 从“特权规划器微调”推进到“端到端 VLA 策略微调”的可行区间，这需要同时解决计算不可行性与仿真环境扩展不足两个工程难题。

更关键的是，作者识别出 CARLA 渲染栈与 VLA 学习者共享 GPU 资源是并行扩展的根本障碍——单个 CARLA 服务器初始化需约 6GB 显存，与 H100 上的模型训练形成资源争用。CLEAR 通过将模拟器部署在旧代 GPU（如 Tesla V100）上，并利用 SSH 隧道通信，绕开了这一瓶颈，使并行环境数量从个位数跃升至 64 个。这一改变不仅提升了 RL 样本效率，更使得在 100M 样本规模下进行 PPO 更新成为现实，而此前受限于环境数量，RL 微调在 VLA 上几乎不可行。

方法拆解

两阶段训练框架

  1. 开环预训练：采用 SimLingo 风格 VLA（InternVL3-1B，含 InternViT-300M-448px 视觉编码器与 Qwen2.5-0.5B LLM），在约 310 万样本（4 fps）上训练 14 个 epoch。图像、导航、语言提示分别经 f_vis、f_nav、f_tok 嵌入，经 token 交织后输入 LLM，输出经两个 MLP（ψ_p、ψ_w）解码为路径路点 P̂_t 与速度路点 Ŵ_t，以平滑 L1 损失监督。
  2. 闭环 RL 微调：将开环 VLA 视为轨迹先验，学习残差策略。定义 m=4 个固定纵向锚点位置 x_anc，通过插值提取基础横向偏移 ŷ_t 与目标速度 v̂_t。RL 策略以驾驶特征 h_t 与基础计划 û_t^wp 为条件，采样残差动作 a_t=[Δy_t^1,...,Δy_t^m,Δv_t]，经裁剪函数 Γ 得到最终路点命令，由确定性控制器 g 映射为低层控制 c_t=(δ_t,η_t)，其中 η_t∈[-1,1] 合并油门与刹车。

关键设计决策

  • 冻结视觉编码器与 LLM：RL 微调阶段完全冻结这些组件，并禁用自回归语言预测路径，理由是计算资源有限。这使得 PPO 仅优化残差策略头，大幅降低参数量。
  • 控制器不参与梯度计算：控制器被视为环境转移的一部分，PPO 仅优化采样残差路点动作的概率，避免通过控制器反向传播。
  • 异构微调流水线：CARLA 服务器运行在 32 块 Tesla V100（32GB）上，每 GPU 分配 2 个实例，共 64 个并行环境；VLA 学习者位于 8 块 H100 集群。通过 SSH 隧道通信，autossh 确保连接稳定性。CARLA 需低 NVIDIA 驱动版本（≤535）以提升稳定性。
  • 训练配置：PPO 更新使用总批/小批 16384/4096，扩展到 100M 样本，训练约 6 天。奖励 r_t=RC_t·(∏p_t)-P，其中 RC 为折扣路线完成度，p_t 为软惩罚因子，P 为硬惩罚（碰撞、违规等）并终止回合。

关键创新

  1. 残差路点动作空间：不同于直接输出控制量或完整路点，CLEAR 在锚点处学习基础计划的残差。这一设计将 RL 探索限制在专家先验附近，既保留了开环 VLA 的语义理解能力，又允许闭环优化修正分布偏移。消融实验显示，waypoint 动作空间（DS 39.89）显著优于 control 动作空间（DS 33.91），证明路点级残差比控制级残差更适合 VLA 的闭环微调。

  2. 异构计算流水线：将模拟器与学习者分离部署是工程上的关键突破。通过利用旧代 GPU 运行 CARLA，并规避驱动版本兼容问题，CLEAR 将并行环境数量提升至 64 个。这一设计直接支撑了 100M 样本的扩展实验，而扩展效果消融（10M→100M，DS 从 12.72 提升至 39.89）表明，环境数量是 RL 微调性能提升的核心杠杆。

  3. 冻结主干 + 残差微调：在计算受限条件下，冻结视觉编码器与 LLM 使得 PPO 仅需优化轻量策略头。这不仅降低了显存需求，还避免了 RL 更新破坏预训练表征的风险。该设计使闭环 RL 微调在 VLA 上首次达到实用规模，而非仅仅作为概念验证。

边界与局限

论文未明确讨论以下边界：首先，所有实验均在 CARLA 模拟器中进行，部署到真实世界需研究 Sim2Real 迁移，模拟器中的奖励设计（如碰撞惩罚）与真实物理环境存在差异。其次，当前扩展方法受限于训练时可生成的并行 CARLA 仿真环境数量，需提高 CARLA GPU 渲染栈稳定性，以便单机可靠启动更多服务器。第三，使用 [27] 的奖励函数，其全局最优与指标的全局最优相同；当指标不具有全局最优时，如何为 VLA 策略设计好的奖励是重要研究课题。此外，nuScenes 零样本评估中碰撞率高于 Senna（0.30 vs 0.18），表明闭环 RL 优化的目标与真实数据集指标并非完全一致，这可能限制其在真实场景中的直接适用性。

工程启示

复现 CLEAR 时，首先应核对硬件配置：CARLA 服务器需使用旧代 GPU（如 Tesla V100）且驱动版本 ≤535，VLA 学习者需 H100 集群，两者通过 SSH 隧道通信。最容易踩坑的是 CARLA 渲染栈的稳定性——低驱动版本是必要条件，否则并行环境数量无法达到 64 个。其次，RL 微调阶段必须完全冻结视觉编码器与 LLM，仅优化残差策略头，否则显存与计算开销将不可控。第三，锚点数量 m=4 与总批/小批 16384/4096 是经过消融验证的配置，直接采用可避免调参成本。对于下游团队，若需在自有模拟器上复现，应优先验证并行环境扩展能力，因为样本量从 10M 到 100M 的性能提升（DS 12.72→39.89）表明，环境数量是 RL 微调效果的决定性因素。最后，nuScenes 零样本评估的碰撞率偏高提示，若目标场景与 CARLA 分布差异较大，需重新设计奖励函数或引入域随机化。
