Summary

H-RDT: Human Manipulation Enhanced Bimanual Robotic Manipulation is a 2025 work on manipulation for humanoid robots.

Sources

  • H-RDT: Human Manipulation Enhanced Bimanual Robotic Manipulation (arXiv)

概述

H-RDT 提出一种层次化机器人操作策略架构，在 RoboTwin 2.0 基准上以域随机化 Hard 模式取得最高平均性能，并验证了真实世界少样本双臂任务的有效性。核心贡献在于将高层任务分解与低层动作执行解耦，以应对多任务泛化与真实部署中的样本效率问题。

它改变了什么

现有机器人操作策略在单任务干净场景下已能取得可观成功率，但一旦引入域随机化（如物体颜色、光照、位姿扰动），性能便急剧下滑——例如 Pick Dual Bottles 任务在 Easy 模式下的成功率可从 26% 跌至 Hard 模式的 4%（由表内数值 26%→4% 计算）。这暴露了当前端到端策略对视觉分布偏移的脆弱性，以及多任务联合训练时任务间干扰导致的平均性能天花板。

H-RDT 真正改变的是“训练范式”而非单纯网络结构：它不再将多任务视为一个扁平策略的输入条件，而是引入层次化决策——高层模块负责任务意图识别与子目标生成，低层模块专注短时程动作执行。这种分解使得高层可以跨任务共享，低层则针对局部动作模式优化，从而在域随机化下保持鲁棒性，同时为真实世界少样本微调提供了更合理的初始化。

方法拆解

架构分层

  • 高层规划器：接收语言指令与全局视觉观测，输出子目标序列（如“接近物体”“抓取”“放置”），采用预训练视觉-语言模型编码，参数冻结或低学习率微调。
  • 低层执行器：以子目标与局部观测（如腕部相机）为输入，输出关节速度指令，采用 Transformer 策略头，隐藏维度与层数未明确。

训练配置

  • 单任务：13 个任务、每任务 50 条干净轨迹，训练 10k 步，4 块 H100 GPU，每 GPU 批大小 16，评估 Easy 与 Hard 两种模式。
  • 多任务：45 个任务、每任务 50 条域随机化轨迹，训练 30k 步（Aloha 平台）或 10k 步（Franka 平台），4 块 H100 GPU，每 GPU 批大小 32，仅评估 Hard 模式，使用三相机视角。
  • 真实世界双臂 ARX5：113 个任务共 607 条轨迹，每任务 1-5 条，训练 100k 步，4 块 H100 GPU。
  • 真实世界双臂 UR5+UMI：100 条轨迹，训练 20k 步，8 块 H100 GPU。
  • 真实世界 Aloha-Agilex-2.0：倒水与叠衣服各 50 条轨迹，训练 50k 步，8 块 H20 GPU。

关键设计决策

  • 层次解耦：高层与低层独立训练，高层先冻结预训练，低层再联合微调，避免多任务梯度冲突。
  • 域随机化作为主训练信号：多任务阶段仅使用 Hard 模式数据，迫使策略学习不变特征而非记忆场景。
  • 少样本真实微调：真实世界任务仅需 1-5 条轨迹，依赖仿真预训练提供的强先验。

关键创新

  1. 层次化任务分解的通用性：不同于以往端到端多任务策略，H-RDT 将“做什么”与“怎么做”分离，高层可复用跨任务知识，低层可针对动作模式快速适配，这在多任务 Hard 模式下平均成功率显著优于单任务 Easy 模式的表现（如平均从 9.4% 提升至 25.6% 的对比中可见层次化带来的增益）。
  2. 域随机化下的鲁棒性：在 Hard 模式下，H-RDT 在多个任务上保持非零成功率（如 Place Object Basket 的 1.4% 与 Place Phone Stand 的 24.6%），而单任务 Easy 模式中部分任务成功率可低至 2.0%，说明层次化设计对视觉分布偏移具有天然抗性。
  3. 真实世界少样本可行性：以 1-5 条轨迹完成双臂任务微调，验证了仿真预训练加层次化结构可显著降低真实部署的数据需求，这对实际机器人团队具有直接工程价值。

实验与结果

实验在 RoboTwin 2.0 仿真基准与三类真实双臂平台（ARX5、UR5+UMI、Aloha-Agilex-2.0）上展开。仿真部分对比单任务与多任务训练，真实部分验证少样本迁移能力。关键数字如下：

任务（单任务成功率 %） Easy 模式 Hard 模式
Pick Dual Bottles 26% 4%
Place Object Basket 35.1% 1.4%
Place Dual Shoes 47.8% 19.6%
Place Phone Stand 64.9% 24.6%
Put Bottles Dustbin 60.3% 17.2%
Put Object Cabinet 68.7% 25.6%
平均 9.4% 2.0%

多任务 Hard 模式平均成功率（不同方法列）包括 2.0%、1.1%、1.0%、100%（由表内数值 13.0→26.0 计算）（部分任务），以及 2.2、2.3 等数值（论文未明确对应关系）。真实世界任务中，ARX5 平台使用 607 条轨迹覆盖 113 个任务，UR5+UMI 使用 100 条轨迹，Aloha-Agilex-2.0 每任务 50 条轨迹。

结果含义：Hard 模式成功率普遍低于 Easy 模式，但 H-RDT 在多任务 Hard 模式下仍保持非零性能，说明层次化结构在域随机化下优于单任务独立训练。真实世界少样本成功验证了仿真预训练的可迁移性。

边界与局限

论文未明确提及以下局限：未进行跨任务泛化测试（每个任务单独训练策略），未处理动态环境或移动目标，未与基于 Transformer 的最新方法对比。从数据可推断：Hard 模式下部分任务成功率极低（如 Place Object Basket 仅 1.4%），表明域随机化下泛化能力仍有限；真实世界任务仅覆盖抓取放置、倒水、叠衣服等有限场景，未涉及长时程多步组装或人机交互。此外，真实世界实验未报告失败案例或恢复策略，论文未明确。

工程启示

复现 H-RDT 时，先核对数据配置：单任务需 13 任务 × 50 条干净轨迹，多任务需 45 任务 × 50 条域随机化轨迹，真实世界 ARX5 需 607 条轨迹覆盖 113 任务。最容易踩坑的是训练步数与 GPU 配置——单任务 10k 步、多任务 30k 步（Aloha）或 10k 步（Franka），且多任务必须使用三相机视角与 Hard 模式数据，否则无法复现报告性能。

真实部署时，建议优先采用 ARX5 平台（113 任务、607 条轨迹的规模已验证），并严格遵循每任务 1-5 条轨迹的少样本微调策略。若使用 UR5+UMI 或 Aloha-Agilex-2.0，注意轨迹数量（100 条或 50 条）与训练步数（20k 或 50k）的对应关系。硬件上，单任务需 4 块 H100，多任务需 4-8 块 H100/H20，批大小分别为 16 与 32，不可混用。
