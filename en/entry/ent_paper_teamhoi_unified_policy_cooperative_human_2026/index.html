Summary

Physics-based humanoid control has achieved remarkable progress in enabling realistic and high-performing single-agent behaviors, yet extending these capabilities to cooperative human-object interaction (HOI) remains challenging. Institutions per source list: Garena、Sea AI Lab、NUS.

Overview

TeamHOI proposes a unified decentralized strategy based on Transformers for collaborative object transport tasks with humanoid agents at arbitrary scales (2-8 agents). The core contribution lies in achieving team-size-agnostic policy generalization through cross-attention mechanisms over teammate tokens, and introducing a Masked AMP discriminator to address the diversity of object interactions under limited single-human reference actions. Experiments show that the method achieves over 97% success rate across team sizes of 2-8, and can zero-shot generalize to 16 agents and unseen table geometries.

What It Changes

Multi-agent physical collaboration (e.g., carrying a table) has long been locked into fixed-input-dimension MLP policies—if you train a 4-agent policy, it only works for 4-agent scenarios; switching to 6 agents requires retraining. The deeper issue behind this is that existing methods either simplify collaboration into implicit communication through shared object dynamics (e.g., CooHOI), or rely on explicit but fixed-topology communication graphs, neither of which captures the adaptability of "perceiving teammate positions and dynamically adjusting force application points" in real human collaboration. Another overlooked bottleneck is reference action data—multi-agent coordinated actions are nearly impossible to collect, so existing frameworks degrade to barely managing with single-human demonstrations, resulting in extremely limited learned behavior patterns (e.g., only lifting front-back, not side lifting).

What TeamHOI truly changes is turning "team size" from a hard constraint of the network architecture into a dimension of the training distribution. It no longer trains a separate policy for each team size; instead, the same policy network dynamically "attends to" any number of teammates through attention mechanisms, thereby redefining multi-agent collaboration as "single-agent decision-making under variable-length sequence conditions." At the same time, it decouples "reference action style" from "object interaction degrees of freedom" using a masked discriminator, allowing limited single-human data to support diverse collaborative strategies—this is a substantive reconstruction of the AMP framework in multi-agent scenarios.

Method Breakdown

Policy Network: Teammate Tokens Cross-Attention

  • Each agent makes decisions independently, sharing the same set of Transformer parameters (decentralized).
  • Observation encoding: ego perception (ℝ²²³), object center (ℝ³), 64 candidate contact points (ℝ⁶⁴×³), nearest hand-object points (ℝ²×³), target position (ℝ³), teammate cues (ℝ^(n−1)×9, including root position, 6D orientation, relative angle around the table), each encoded into 64-dimensional tokens via independent three-layer MLP tokenizers.
  • Transformer structure: L layers alternating self-attention (on own tokens) and cross-attention (on teammate tokens); updated embeddings are passed through an action head to output 28-dimensional target joint rotations (PD controller targets).

Unified Policy Training

  • 1024 environments are instantiated in parallel, each configured with a different team size (2-8), sharing the same policy network.
  • Team-size-wise advantage normalization: Because reward scales vary significantly across sizes, PPO advantages are normalized separately by team size n: A_t^(n) ← (A_t^(n) − μ_n(A)) / (σ_n(A) + ε), rather than global normalization.
  • Virtual ceiling trick: IsaacGym requires the same number of actors per environment, so a fixed N agents are instantiated; for smaller sizes, extra agents are placed on a virtual ceiling plane, excluded from rewards, observations, gradient computation, and with PD disabled.

Masked AMP Discriminator

  • Dual discriminators: D_full evaluates full reference actions (walking), D_mask excludes body parts interacting with the object (hands, forearms).
  • Mixed style reward: r_t^style = σ(α_t)·r_t^mask + (1−σ(α_t))·r_t^full, where α_t is a continuous interaction indicator (e.g., hand-object distance) and σ is the sigmoid. The masked discriminator is used during interaction, and the full discriminator otherwise.

Formation Reward Design

  • Angular distribution reward: r_ang = exp(−k_θ·½·[(Δφ_i^ccw − 2π/m)² + (Δφ_i^cw − 2π/m)²]), where m is the team size, encouraging uniform angular distribution.
  • Principal-axis coverage reward: Project root positions onto sampled points around the object; the convex hull defines the support polygon; per-axis coverage g_i = min(d̃_i⁺/ℓ_i⁺, d̃_i⁻/ℓ_i⁻), with reward r_cov = ½(g₁ + g₂). Key design: each projected point is replaced by two points at ±2 indices around it, avoiding degeneration into a line segment for two agents.
  • Final formation reward r_form = 0.25·r_ang + 0.75·r_cov (coverage reward weighted higher; angular distribution provides early dispersion signal to make coverage reward nonzero).

Task Reward Decomposition

r_task = 0.2·r_walk^pos + 0.4·r_walk^vel + 0.2·√(r_walk^face·r_ang) + 0.6·r_form + 0.7·(r_hand·r_cov) + 0.7·r_contact + 0.7·(r_lift·r_cov) + 1.0·r_transport + 0.4·r_align + 1.0·r_put

Three-Stage Training

  1. Stage 1 (about 1.5 days): 1-4 agents, transport/alignment/put-down rewards disabled, D_full uses only forward/side-walking references, D_mask additionally receives pickup actions, target position token masked, episode length 400 timesteps.
  2. Stage 1+2 (about 5 days): 2-4 agents, all rewards enabled, target masking removed, backward walking reference added, episode length 600 timesteps.
  3. Fine-tuning (about 3 days): 2-8 agents.

Key Innovations

  1. Team-size-agnostic policy architecture: Cross-attention handles variable-length teammate sequences, replacing fixed-input MLPs. This is the first physical humanoid collaboration policy that zero-shot generalizes to team sizes unseen in training (e.g., 16 agents) without fine-tuning. Its significance lies in freeing multi-agent RL from the "one model per size" paradigm.

  2. Masked AMP discriminator: By masking body parts interacting with the object, it decouples "style imitation" from "task-driven interaction." This enables learning diverse collaborative lifting strategies (e.g., side grips, edge lifts) from single-human reference actions (walking + pickup in AMASS), rather than being locked into reference-action behavior patterns. Unlike PMP, which directly learns part-level priors, TeamHOI uses task rewards to enforce diversity in masked regions, making it lighter and more scalable.

  3. Geometric robustness of principal-axis coverage reward: Support polygon coverage is computed via principal axes of inertia, naturally adapting to irregular geometries and non-uniform mass distributions (generalized formulas provided in supplementary materials), and the "projection point ±2 index replacement" avoids degeneration in small teams. This is a substantive improvement over traditional fixed contact point assignment (e.g., manual specification in CooHOI).

Ablations

  • Removing Masked AMP: coordination failure rate during the lifting phase increases significantly (motion realism conflicts with object interaction objectives).
  • Removing principal-axis coverage reward: agents fail to distribute along the object's principal axes, exhibiting excessive rotation around the vertical axis and unnatural diagonal gaits.

Boundaries and Limitations

  • The paper does not explicitly discuss limitations, but supplementary materials and experimental data reveal the following boundaries:
  • Large-team crowding issue: With 12-16 agents, table perimeter becomes crowded, t_coop drops sharply to 15.1% (16A), and agents fail to learn positioning in narrow support gaps.
  • Two-agent large-table scenario: Insufficient mechanical leverage makes stable lifting difficult, SR drops to 71.0%.
  • Heavy-load generalization ceiling: Under 5× table weight, 4A success rate is only 3.5%, indicating that policy robustness to mass increase relies on team-size compensation.
  • Not validated: Unseen object masses (>5×), real-world deployment, non-uniform mass distributions (supplementary materials provide only formulas, no experimental numbers).
  • Reference action dependency: Still relies on AMASS single-human data; although masking expands behavioral diversity, it does not break through the "no reference action" extreme scenario.

Engineering Insights

  • Reproduction priority: First verify the team-size-wise advantage normalization implementation—this is key to mixed-size training stability; global normalization leads to reward scale imbalance (Figure 7 shows significant task reward degradation).
  • Most common pitfall: The virtual ceiling trick. IsaacGym requires consistent actor counts per environment; extra agents must be fully disabled (no rewards, no observations, no gradients, PD off), otherwise noisy gradients are introduced.
  • Reward tuning: In r_form, the higher weight on r_cov (0.75) over r_ang (0.25) is intentional—r_cov remains effective under irregular geometries but can be sparse, while r_ang provides early dispersion signal to make r_cov nonzero. If your task object has more extreme shapes, verify whether the convex hull computation for r_cov degenerates first.
  • Training budget: On a single A100, three stages total about 9.5 days (1.5+5+3). If compute is limited, you can skip Stage 1 and train 2-4 agents directly, but note that the walking foundation skills (position/velocity/orientation rewards) established in Stage 1 are prerequisites for subsequent collaboration.
  • Downstream teams: If deploying to real robots, note that the MuJoCo humanoid has simplified spherical hands (no fingers)—differences in real hand contact dynamics may affect the validity of r_contact and r_lift.
