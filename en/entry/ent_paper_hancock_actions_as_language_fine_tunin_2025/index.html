Summary

Actions as Language: Fine-Tuning VLMs into VLAs Without Catastrophic Forgetting (VLM2VLA), is a 2025 large vision-language-action model for robotic manipulation, introduced by Princeton University.

Sources

  • Actions as Language: Fine-Tuning VLMs into VLAs Without Catastrophic Forgetting (arXiv)
  • VLM2VLA source

概述

本文提出 VLM2VLA，一个将视觉-语言模型（VLM）微调为视觉-语言-动作模型（VLA）的框架，核心贡献在于通过自动化的语言标注流程和动作令牌化设计，在不发生灾难性遗忘的前提下实现机器人操作策略学习。作者基于 Gemma-3-12B 骨干，利用 Gemini 2.5 生成轨迹的语言分解，并引入闭环保真器机制提升子任务执行的鲁棒性，在分布内、边界分布和分布外任务上验证了方法的有效性。

它改变了什么

机器人策略学习长期面临一个结构性矛盾：VLM 具备丰富的语义先验和泛化能力，但直接微调为动作预测模型时，往往以灾难性遗忘为代价——模型记住了新任务的动作分布，却丢失了原有的视觉-语言理解能力。现有 VLA 方法（如 OpenVLA）通常从零训练或依赖大规模配对数据，难以利用现成 VLM 的预训练知识。VLM2VLA 试图改变这一格局：它不把动作当作离散的低维向量，而是将动作序列转化为语言令牌，使微调过程在语言模型的语义空间内进行，从而保留 VLM 的既有能力。另一个关键转变在于数据生成方式——不再依赖人工标注或手工设计的轨迹分解，而是用 Gemini 2.5 自动将原始轨迹分解为子步骤和运动规划，将数据标注成本从人力转向算力。

方法拆解

数据标注流程

  • 输入：轨迹 τ = {(o_t, a_t)}（RGB 观测 + 相对末端执行器动作）与主任务指令 L。
  • 提示 Gemini 2.5（初版 Pro，后改用 Flash 降本）进行链式思维推理，输出结构化 JSON，包含 step_description、reasoning、main_movements、actions。
  • 关键设计：提供机器人坐标系与符号约定（如 WidowX 250S 的 6-DoF，正 x 向前、负 y 向右），帮助模型确定最佳时间步切割轨迹。

动作后处理

  • 沿单维度分块动作以增大幅度，阈值设为单维度无符号变化 2.5 厘米，绝对阈值 5 厘米，避免预测动作过小。
  • 构建正负子任务完成示例 (ō_i, ō_j, l_i)，j≠i，成功当且仅当 j=i+1；但模型无法可靠执行验证步骤，仅作为辅助训练信号。
  • 训练模型预测移动方向（左、右或无），使用 2.5 厘米阈值，运行时不用但有益于下游性能。

动作令牌化

  • 将数字 0-9 映射到 Gemma-3-12B-IT 模型词汇表中第十个最不可能的令牌：0→<unused6133>（ID 262035），1→<unused6134>（262036），依此类推至 9→<unused6142>（262044）。

推理流程（三步）

  1. 子任务预测：给定初始图像，提示模型将主指令分解为高层步骤列表，以 'Move to' 开头。
  2. 运动规划：给定当前观测和子任务，进行空间推理，输出高层动作描述（坐标约定：+dx 向前，-dx 向后，+dy 向左，-dy 向右，+dz 向上，-dz 向下，1 夹爪开，0 夹爪闭）。
  3. 动作生成：输出低层 [dx, dy, dz, gripper] 动作序列，格式为 Python 列表的列表。

闭环保真器

  • 查询验证器 V: 𝒪 × 𝒪 × ℒ × ℒ → ℒ，输入执行前后观测与当前/下一子任务，判断当前子任务是否成功，决定下一动作生成周期使用的子任务。
  • 本工作使用 Gemini 2.5 Pro 作为验证器，提示其为“精度导向的机器人检查员”，输出 JSON 含 success、confidence、reasoning 字段。

采样策略

  • 所有输出使用 nucleus 采样，p=0.95。运动规划温度 0.1，动作预测温度 0.5，初始子任务分解在分布内任务为 0.5，其他场景为 1.0。

关键创新

  1. 动作即语言：将连续动作映射为语言模型词汇表中的低概率令牌，使微调过程完全在语言建模框架内进行。这一设计避免了传统 VLA 中动作头与语言头分离带来的表示不一致，是防止灾难性遗忘的关键机制——模型无需学习新的输出模态，只需调整既有令牌的分布。
  2. 自动化语言标注管线：用 Gemini 2.5 替代人工标注，将轨迹分解为子步骤和运动规划。这不仅降低了数据成本（整个数据集生成约 900 美元），还提供了结构化的中间监督信号，使模型在推理时能够显式地进行任务分解和空间推理，而非端到端黑箱预测。
  3. 闭环保真器机制：在动作生成周期之间插入验证器，判断子任务是否真正完成。这解决了长程任务中错误累积的问题——即使动作预测有偏差，验证器也能纠正后续子任务的选择，提升了策略对分布偏移的鲁棒性。

实验与结果

评估在 6-DoF WidowX 250S 机械臂、玩具厨房环境（Realsense D435 相机）中进行，每个策略每个任务 30 次 rollout。对比模型包括 OpenVLA、ECoT（均为 Prismatic-7B 骨干）、原始 Gemma-3-4B/12B、MolmoAct 和 π₀.₅。

任务 关键结果
Pick Up the Carrot（分布内） 部分分制（接触得 1/2），VLM2VLA 表现优于基线（论文未明确具体数值）
Put the Carrot On the Yellow Plate（分布内） 部分分制（接触得 1/2），VLM2VLA 表现优于基线（论文未明确具体数值）
Put the Eggplant In the Pan, Then Lift the Fish（边界分布） 规划策略评分含子任务分解正确性（1/5），VLM2VLA 优于 ECoT（论文未明确具体数值）
Pick Up the Carrot（多语言，分布外） 西班牙语/普通话/印地语指令，VLM2VLA 能识别 'gajar'（印地语胡萝卜同义词），但西班牙语和普通话未观察到
Pick Up the Item Above Ash Ketchum（分布外） 目标物体在流行文化图片上方，VLM2VLA 能正确识别并接触（论文未明确具体数值）

推理延迟（N=30，A100 GPU）：中位数 6.1 秒，均值 10.5 秒，标准差 14.3 秒，IQR 5.0-6.7 秒，最小值 3.8 秒，最大值 48.8 秒。约 10% 的情况因格式错误触发重试，少数试验超过 45 秒。

训练配置：Gemma-3-12B-IT，PEFT（LoRA），秩 r=16，α=32，目标模块含 q/k/v/o/up/down/gate 投影，BF16 精度，单节点 4×A100，1 个 epoch，约 300 GPU 小时。

边界与局限

论文未明确提及以下方面的系统性评估：高反射或透明物体的抓取性能、动态物体或多物体堆叠场景、灵巧手多指抓取、部署后的在线学习。推理延迟的高标准差（14.3 秒）表明存在计算瓶颈，约 10% 的格式错误触发重试机制，少数试验超过 45 秒，难以满足实时控制需求。验证器使用外部 Gemini 2.5 Pro，作者指出可训练模型自身执行验证但未实现。多语言泛化仅观察到印地语同义词 'gajar' 被正确识别，西班牙语和普通话输入未出现类似现象，说明跨语言泛化能力不均衡。动作令牌化映射仅覆盖 0-9 十个数字，实际动作值需量化到该范围，可能限制动作精度。

工程启示

复现时首先核对动作令牌映射表：0→<unused6133>（262035）至 9→<unused6142>（262044），确保与 Gemma-3-12B-IT 词汇表一致，否则微调时会出现令牌 ID 错位。数据后处理阈值（单维度 2.5 厘米、绝对 5 厘米）直接影响动作幅度分布，过小会导致预测动作趋近于零，过大则丢失精细操作能力，建议根据实际机器人工作空间调整。推理时温度设置敏感：运动规划用 0.1 保持确定性，动作预测用 0.5 引入适度随机性，子任务分解在分布外任务用 1.0 增加探索——这些超参数是经验值，换场景需重新调优。闭环保真器依赖 Gemini 2.5 Pro 的 API 调用，延迟和成本需纳入系统预算；若下游团队无法承受外部依赖，可考虑蒸馏验证器到小模型。训练使用 DeepSpeed ZeRO Stage 2 + LoRA，4×A100 约 300 GPU 小时，单卡可复现但需注意显存占用。评估时注意安全过滤器（末端执行器接触台面或墙壁时置零向下/向前命令），防止机械臂撞入环境。
