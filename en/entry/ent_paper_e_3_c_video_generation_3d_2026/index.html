Overview

E³C is a diffusion framework for fully controllable first-person video generation, proposed by Meta Reality Labs in collaboration with the University of Toronto. Its core contribution lies in decoupling persistent 3D environment memory (semi-dense point clouds + per-point VAE appearance features) from human-driven dynamics (ego pose tokens + exo skeletons), achieving unified geometric consistency and human control through dual-stream conditional injection (VACE Context Adapter + pose cross-attention). On the Nymeria dataset, E³C comprehensively outperforms existing 3D-aware and pose-conditioned baselines across visual quality, camera trajectory accuracy, object consistency, and ego/exo human control metrics.

What It Changes

First-person video generation has long been fragmented by two disconnected research lines: pose-conditioned models (e.g., PEVA, EgoControl) can control the human body but lack persistent memory of the 3D scene, leading to background drift and geometric collapse under rapid head motion; while 3D-consistent generators (e.g., VMem, Gen3C) are designed for general scenes and do not model self-occlusion or coupled motion with nearby people. What E³C truly changes is injecting "scene geometry" and "human dynamics" as two independent yet complementary conditional streams into the diffusion model, rather than attempting to implicitly model both in a single latent space. This decoupled design allows camera trajectory control (geometry-dependent) and human pose control (kinematics-dependent) to be optimized separately, and ablation experiments demonstrate that point cloud geometry conditioning improves FVD (from 1380 to 329) far more than any pose control module, indicating that geometric consistency is the primary bottleneck in first-person generation.

Another key change lies in the representation of ego pose. Existing methods project 3D joints into 2D skeletons overlaid on RGB conditioning, but the ego body frequently leaving the field of view results in sparse or even missing renderings. E³C introduces persistent ego pose tokens—encoding joints and wrist trajectories as sequence tokens injected directly into the DiT via cross-attention—which effectively provides the model with a "proprioceptive" channel rather than relying on visual visibility. This design improves Hand-F1 from 36.03 to 41.44, proving that implicit pose tokens are more robust than explicit rendering.

Method Breakdown

3D Environment Memory Construction

  • Run SLAM (Project Aria MPS) on context frames (first m=200 frames) to obtain a semi-dense point cloud P ∈ ℝ^(N×3), with each point assigned an RGB color C (sampled from observed frames, voxel-downsampled at 0.01m and average-pooled).
  • Per-point appearance features: Encode context frames with the Wan2.1 video VAE encoder E to obtain 16-channel latent maps (spatial resolution 1/8), project each 3D point onto the feature maps with bilinear interpolation sampling, and aggregate multi-view information via 0.02m voxel pooling in world space.

Viewpoint-Aligned Rendering and Conditional Injection

  • Given a target camera trajectory T_(1:n), project and render the augmented point cloud (colors + features) to each target viewpoint, obtaining RGB rendering c^pc and feature rendering c^feat.
  • Rasterized exo 2D skeletons are overlaid on c^pc to form c^ctrl; ego 3D joints and wrist SE(3) transforms are projected into 2D skeletons and small coordinate axes, also drawn on c^ctrl.
  • Dual-stream encoding: A video encoder encodes c^ctrl to obtain e^ctrl, while a lightweight 3D convolutional feature encoder (hidden width 1024, output 96 channels) encodes c^feat to obtain e^feat. The sum-fused result is injected into the video DiT via the VACE Context Adapter as a residual condition.
  • Key design: Visibility or depth maps are not explicitly input; the model implicitly learns to infer occlusion relationships.

Persistent Ego Pose Tokens

  • Input: ego 3D body joints p^(e,s) ∈ ℝ^(n×J×3) and 6DoF wrist poses p^(e,w) ∈ ℝ^(n×2×4×4) (camera coordinate frame).
  • Featureization: Joints use 3D coordinates + first/second-order temporal differences (15 dimensions); wrists use translation + continuous 6D rotation (27 dimensions).
  • Fusion: Body and wrist streams are fused via learned gating, aggregated with spatial Transformer + attention pooling, and propagated temporally.
  • Summary tokens: K=4 learned tokens cross-attend to n pose tokens, concatenated to obtain H^e ∈ ℝ^((n+4)×1536), conditioning the DiT via dedicated pose cross-attention.

Training and Inference

  • Flow matching objective: L = E[ w(t) ||(ε - z_0) - ε_θ(z_t, t; τ, C)||_2^2 ], with z_t = (1-σ_t)z_0 + σ_t ε.
  • Initialized from Wan2.1-VACE-1.3B, with LoRA rank 256 fine-tuning of the main DiT and context adapter; ego pose encoder, feature encoder, and pose cross-attention are trained from scratch.
  • Inference: 50-step FlowMatch, σ_shift=5.0, CFG ω=5.0.

Key Innovations

  1. Dual-Stream Conditional Decoupling Architecture: 3D environment memory (point cloud rendering + per-point features) and human dynamics (exo skeletons + ego pose tokens) are treated as independent conditional streams, injected separately via the VACE Adapter and cross-attention. This is the first time in first-person generation that representations of "static scenes" and "dynamic humans" are explicitly separated, allowing camera control and human control to be independently adjusted, with ablations proving they are complementary rather than redundant.

  2. Persistent Ego Pose Tokens: Ego joints and wrist trajectories are encoded as temporal sequence tokens and directly condition the DiT via cross-attention, rather than being projected as 2D renderings. This solves the sparse control signal problem caused by the ego body frequently leaving the field of view, effectively providing the model with a "proprioceptive" channel independent of visual visibility. The Hand-F1 improvement from 36.03 to 41.44 is direct evidence of this method's effectiveness.

  3. Per-Point VAE Appearance Features: Video VAE latent features are attached to 3D points and injected through a lightweight feature encoder after rendering. This provides richer texture priors than RGB point cloud colors alone, with LPIPS dropping from 0.440 to 0.424 and PSNR improving from 17.1 to 17.9, demonstrating that feature-level conditioning benefits generator perceptual quality more than pixel-level conditioning.

Experiments and Results

Evaluated on 100 clips from the Nymeria test set, compared against three baseline categories: 3D-aware generators (Splatfacto, Gen3C, VMem), fine-tuned VACE (points+exo), and first-person generators (PEVA, EgoControl, EgoTwin).

Ablation experiments (progressively adding conditions) show that point cloud geometry is the largest contributor (FVD 1380→329), per-point features improve perceptual quality (LPIPS 0.440→0.424), exo skeletons improve Exo-F1 (19.87→38.40), and encoded ego tokens yield the largest gains in Hand-F1 (36.03→41.44) and Hand-mIoU (19.36→24.76). In comparison with EgoTwin, E³C achieves I-FID 31.0 vs 98.2 and TErr 2.40cm vs 67.0cm, demonstrating significant advantages.

Boundaries and Limitations

  • Spatial memory assumes a mostly static environment, modeling dynamics only through human motion; performance degrades with moving objects or long-term scene changes.
  • Ego/exo human control conditions only motion, not appearance—appearance may drift when a person leaves and re-enters the field of view.
  • Semi-dense SLAM point clouds concentrate on high-gradient regions, underrepresenting low-texture areas (e.g., white walls), which may affect geometric consistency in textureless scenes.
  • The comparison protocol with EgoTwin cannot be fully aligned (original splits and implementations are unavailable), so results should be interpreted with caution.
  • Long-horizon generation beyond 80 frames is not evaluated, nor are outdoor scene-specific handling or non-human dynamic object control.

Engineering Insights

When reproducing or applying E³C, prioritize checking the following:

  1. SLAM point cloud quality is the ceiling: Ablations show point cloud conditioning contributes the most, but semi-dense SLAM is sparse in low-texture regions. If the target scene is texture-poor, consider supplementing with dense reconstruction or depth estimation; otherwise, geometric consistency will degrade significantly. It is recommended to first assess MPS point cloud coverage in the target environment.

  2. Feature voxel size requires tuning: RGB point memory uses 0.01m voxels, while feature memory uses 0.02m (since features are smoother). If scene scale varies significantly, these parameters may need recalibration—too small causes feature fragmentation, too large loses detail.

  3. Input coordinate frame for ego pose tokens: Joints and wrist poses are in the camera coordinate frame and include temporal differences. If obtaining data from other motion capture systems, ensure coordinate frame alignment (especially the SE(3) rotation representation of wrists); otherwise, pose cross-attention will learn incorrect mappings.

  4. High training cost: 64 H100 GPUs, 50 epochs, LoRA rank 256. If resources are limited, consider freezing the feature encoder and training only the pose branch; ablations show the +Encoded Ego gain (Hand-F1 +5.41) is relatively independent and may capture most benefits at lower cost.

  5. Evaluation metric pitfalls: PCK@10% is computed only on matched human boxes and should be interpreted jointly with Exo-F1; Hand-mIoU counts empty-empty frames as 1, which inflates scores. When reproducing evaluations, strictly follow the matching thresholds (τ_obj=0.5, τ_exo=0.2) and filtering rules (SAM3 area <1536 pixels filtered); otherwise, numbers are not comparable.
