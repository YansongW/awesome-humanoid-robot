Vesta: A Generalist Embodied Reasoning Model

Summary

Robots operating in open-world environments must seamlessly integrate localization, spatial reasoning, navigation, and long-horizon planning. While specialist models excel at individual tasks, deploying a multi-model stack is computationally expensive and prone to cascading errors. Institutions per source list: NVIDIA.

Overview

Vesta is a general-purpose embodied reasoning model fine-tuned from Qwen3-VL-8B, designed to unify grounding, navigation, spatial reasoning, and long-horizon planning into a single planner rather than stacking multiple expert models. Its core contribution lies in supervised fine-tuning on a mixture of six data categories and introducing a minimalist memory mechanism (fixed-budget image sampling + text subtask cache), significantly surpassing SOTA baselines and expert ensembles on academic benchmarks, offline planning, and real-robot tasks.

What It Changes

What this work truly changes is the default assumption about "how embodied agent capabilities are organized." Previously, navigation, grounding, and reasoning each operated in silos, with dedicated models and benchmarks for each capability. Deployment required either stacking multiple models (high computational cost, cascading errors) or hoping a single VLM would happen to perform well on a given task. Vesta demonstrates through data mixing and unified training that a single 8B model can simultaneously match or exceed expert-level performance across all embodied cognitive tasks, and this unification is not simply "capability stacking" but produces positive transfer—the unified model outperforms a pure navigation expert by 1.4 SR on navigation and a pure embodied expert by 3.9 average points on embodied cognition. This directly challenges the industry convention that "specialized models are necessarily superior to generalist models."

Another changed aspect is the design philosophy of memory mechanisms. Existing methods (MemER, MEM) all pursue smarter memory—learned retrievers, scene representations, event trackers. Vesta goes against the grain, using fixed-budget recent-frame sampling plus text subtask logs, achieving a 38.3% success rate improvement over an actor-only baseline on real robots. This shows that under a planner-actor hierarchical architecture, the "modality composition" of memory matters more than the "retrieval strategy"—image+text hybrid memory outperforms any single modality, while uniform sampling and recency-biased sampling are nearly indistinguishable. This serves as a sobering reminder for teams over-engineering memory mechanisms.

Method Breakdown

Overall Architecture

  • Base model: Qwen3-VL-8B, full-parameter fine-tuning (vision tower + projector + language backbone), pure bf16.
  • Training: 1 epoch, lr 1e-5, cosine schedule, weight decay 0.01, batch size 256, 128 H100 GPUs, FSDP full sharding, FlashAttention-2, sequence packing, truncation length 8192, max video frames 32.
  • All structured outputs (points, boxes) are decoded as text tokens through the language head, sharing the same decoder head as free-form answers—a key design for the unified interface.

Data Mixture (Six SFT Categories)

Data Category Proportion
Spatial Intelligence 27.1%
Navigation 21.8%
Grounding 20.8%
General VLM 16.2%
Embodied Reasoning 9.8%
Real Robot 4.3%

Grounding: Base–Tail Strategy

  • Base: Objects365, COCO, LVIS (broad category coverage).
  • Tail: First-person observations, manipulation-centric annotations, temporally evolving interaction sequences (adapted to partial observability and viewpoint changes).

Navigation: R2R-Style VLN Formulation

  • Episode e = (I, s₀, g), at decision point t observe pose sₜ, first-person image oₜ, sampled visual history Hₜ.
  • Optimization objective: max_θ 𝔼[𝟙{d(s_T, g) ≤ d_succ}], d_succ = 3.0m.
  • Outputs three action types: pixel target (↓ + normalized waypoint (u,v) ∈ [0,1000]²), turn sequence ({←,→}), stop.
  • Data: VLN-CE from R2R, RxR, ScaleVLN, simulation rendered.

Action Planning with Memory

  • Non-Markovian process: aₜ = π(o_{≤t}, a_{<t}, g), approximate state sₜ = Φ(oₜ, ℳₜ, g).
  • Before each subtask, generate four-stage CoT: Observation → Progress → Reasoning → Action, only aₜ is written to memory.
  • Memory device: tuple mᵢ = ⟨i, τᵢ, oᵢ, aᵢ, g⟩, historical images limited to at most K frames via sampling operator 𝒮ₜ, first frame always retained, supporting uniform or recency-biased sampling.

Hierarchical Execution Architecture (Real Robot)

  • Planner VLM (Vesta) outputs subtasks → Actor VLA (Gr00t-N1.6) executes actions.
  • Synchronous mode: planner inference is a blocking call (~1 second), actor paused when goal changes or maximum staleness τ_max is exceeded.
  • Asynchronous mode: planner thread runs continuously, control loop reads cached subtasks every tick without blocking.
  • Communication only through shared variable z (current subtask); planner memory is invisible to the actor.

Key Innovations

  1. Unified Planner Replaces Expert Ensembles: Vesta achieves 68.7 and 69.9 average scores on 11 cognitive benchmarks and 5 grounding benchmarks, respectively, surpassing all single-model baselines and exceeding the oracle ensemble by >10%. This is not simply "multi-task learning" but demonstrates positive transfer—the unified model outperforms a pure navigation expert by 1.4 SR on navigation and a pure embodied expert by 3.9 on embodied cognition. For engineering teams, this means no longer needing to maintain multiple models and switching logic.

  2. Effectiveness of the Minimalist Memory Device: Fixed-budget image sampling + text subtask cache, no learned retriever. Ablations show image+text hybrid memory (75.9 overall score) far exceeds image-only (63.1) and text-only (49.7), while uniform sampling and recency-biased sampling are nearly indistinguishable (75.9 vs 75.3). This proves that under a planner-actor architecture, the modality composition of memory is the primary bottleneck, and frame selection strategy is a secondary issue—providing clear priorities for memory mechanism design.

  3. Discovery of Transition Oversampling: Under default sampling, transition-phase data accounts for only ~25%. Increasing transition oversampling from 1× to 2× yields substantial gains in transition accuracy (58.1→68.1) and overall accuracy (73.6→75.9); increasing to 3× provides only marginal improvement and harms execution. This is an actionable data-engineering insight: in long-horizon tasks, task-switching moments (transitions) deserve more attention than execution phases.

Ablations (Tables 4, 5)

  • Unified vs Expert: Vesta averages 61.7, far exceeding navigation-only expert (26.0) and embodied-only expert (33.2), and the unified model matches or exceeds experts on their own tasks.
  • Transition oversampling: 2× is optimal (75.9), 1× gives 73.6, 3× gives 75.3 (harms execution).
  • Memory modality: image+text (75.9) > image-only (63.1) > text-only (49.7).

Boundaries and Limitations

  • Limited real-robot evaluation scope: Only a single platform (I2RT dual-arm YAM gripper) and three tasks, not covering humanoid robots (whole-body motion + dual-arm coupling), mobile manipulators (navigation-manipulation switching), or dexterous hands (fine-grained subtask vocabulary).
  • Scale limitations: All numbers are at 8B scale; the scaling behavior of embodied SFT data mixtures is far less understood than web data, and conclusions may not hold at larger scales.
  • Memory is not learned: The memory harness is fixed (uniform/recency sampling + text logs), memory itself is not treated as a learning objective, and lifelong learning (cross-episode consolidation, forgetting, re-retrieval) is not addressed.
  • Actor assumption: The current setup implicitly assumes the actor can faithfully execute a small set of natural language subtasks at a fixed control rate; if the actor's language-following ability is weak, planner advantages will be masked by execution errors (most real-robot failures are actor-driven).
  • What was not done: No evaluation on other robot platforms, no large-scale real-world multi-task deployment, no comparison with other generalist models at larger scales, no distillation or edge deployment experiments.

Engineering Takeaways

  • Verify data mixture ratios first: Vesta's success heavily depends on the proportions of six data categories (spatial intelligence 27.1%, navigation 21.8%, grounding 20.8%). Do not arbitrarily adjust ratios when reproducing; especially note that navigation data is indispensable—all general VLM baselines achieve SR=0.0 on R2R-CE, indicating navigation capability must be explicitly trained.
  • Transition oversampling is the easiest pitfall: Under default sampling, transition data accounts for only 25%; without adjustment, long-horizon task performance drops significantly (73.6 vs 75.9). It is recommended to explicitly track transition-phase proportions in the data pipeline and set 2× oversampling.
  • Memory modality matters more than retrieval strategy: If resources are limited, prioritize image+text hybrid memory and do not spend time tuning frame sampling strategies—uniform sampling and recency bias are nearly identical (75.9 vs 75.3).
  • Keep the hierarchical architecture's communication protocol simple: Planner and actor communicate only through shared variable z (current subtask); planner memory is invisible to the actor. Synchronous mode suits experimental reproduction; asynchronous mode suits production deployment (prioritizing motion smoothness).
  • Watch for actor bottlenecks in real-robot evaluation: Actor errors drive most failed episodes; always distinguish planner errors from actor errors during evaluation, otherwise planner performance will be misjudged. It is recommended to evaluate the actor's language-following ability separately first.
  • Training configuration can be reused directly: 1 epoch, lr 1e-5, weight decay 0.01, batch 256, 128 H100s, FSDP full sharding, FlashAttention-2, sequence packing, truncation 8192, max video frames 32—these parameters are explicitly stated in the paper and can serve as a direct starting point.
