Summary

Proposes STAR-Gen, a taxonomy of visual, semantic, and behavioral generalization for visuo-lingual robot manipulation policies, and instantiates it through 1,600+ real-world trials on Bridge V2 and ALOHA 2.

Sources

  • A Taxonomy for Evaluating Generalist Robot Manipulation Policies

概述

本文提出HumanoidGen框架，面向双臂+灵巧手人形机器人的全自动任务创建与演示收集，核心贡献在于将LLM规划与MCTS增强推理结合，在仿真中生成高质量、可扩展的演示数据，并构建了包含20个任务的HGen-Bench基准。作者通过空间标注、约束求解和场景缩放，解决了双臂灵巧操作中数据收集成本高、任务多样性不足的问题。

它改变了什么

现有机器人数据生成管线（VR遥操作、外骨骼）要求操作者具备熟练技能，且需部署大量真实物体，难以覆盖多样化任务。仿真基准如Aloha、PerAct2任务多样性有限，一般不涉及灵巧手；HumanoidBench和BiGym依赖VR或RL策略收集数据，成本高。HumanoidGen真正改变了这一局面：它不再依赖人工演示或RL探索，而是通过LLM+约束求解+MCTS的全自动管线，在仿真中生成高质量演示，将数据收集从“人工密集型”转变为“计算密集型”。

这一转变的深层意义在于：它打破了双臂灵巧操作数据收集的瓶颈，使得大规模、多样化的演示数据成为可能。作者通过空间标注（手部原子操作、资产固有信息）和约束求解，将LLM的语义理解转化为可执行的几何约束，从而在无需人工干预的情况下生成物理可行的操作序列。这为下游策略学习（如DP、DP3）提供了充足且高质量的训练数据，是迈向通用机器人操作策略的关键一步。

方法拆解

总体框架

HumanoidGen包含七个模块：空间标注、场景生成、约束生成、MCTS增强推理、数据收集、场景缩放、策略评估。

空间标注

  • 手部原子操作标注：定义关键点和三类轴（接近轴、附着轴、平行轴）。以“捏”为例，接近轴指定手接近预捏姿态的方向，附着轴指向手指运动方向（拇指尖到食指尖），平行轴垂直于前两者且平行于手掌平面。
  • 资产固有信息：指示资产自身功能（如杯子的倒水和存储功能对应不同点和轴）。
  • 资产操作标注：定义资产上可应用原子操作的点与轴，原子操作与资产非一一对应。

场景生成与任务分解

  • LLM规划器根据资产库信息、场景细节和任务要求生成任务设置代码，确定资产类别、数量、放置姿态等属性，并生成任务成功标准。
  • LLM将长时程任务分解为动作序列S = {S_1, S_2, ..., S_n}，每步S_i = (S_i^l, S_i^r)包含左右手部分，S_i^l, S_i^r ∈ {A_i, M_i}，A_i为手部操作，M_i为手臂运动。

约束求解

  • 建立三类坐标系：物体坐标系F_obj、手坐标系F_hand、世界坐标系F_world。每个坐标系F = (p_1, ..., p_k; v_1, ..., v_m)包含关键点和主轴。
  • 动作坐标系F_act动态组合参考系，约束c ∈ {C_path, C_goal}在F_act与F_all = F_obj ∪ F_hand ∪ {F_world}的几何元素之间施加几何关系（重合、平行、轴向对齐）。
  • 运动求解第一步：通过非线性优化获取目标末端执行器位姿e_T和目标手臂角度θ_T，优化目标为最小化Σ w_i c_i(u_act, u_all) + w_reg ||θ_T - θ_nominal||，约束包括运动学约束（e_T = f_FK(θ_T)）、关系动作约束和碰撞避免约束。使用pydrake库中的SNOPT求解器。
  • 运动求解第二步：利用mplib库中的约束运动规划器，在0 < t < T时最小化代价函数Cost(θ_t)，约束条件与第一步类似但针对路径约束C^path。

MCTS增强推理（STCR机制）

  • 分段（Segment）：按执行粒度将规划代码分段为多个步骤。
  • 截断（Truncate）：顺序执行分段步骤直到出错，截断失败点之后的步骤，保留有效段S_remain = {S_i | 1 ≤ i ≤ k-1}。
  • 合并（Combine）：合并意图一致的原子操作形成新执行序列S'remain = {S'_1, S'_2, ..., S'，其中k' < k-1。}
  • 恢复（Resume）：新节点存储已执行序列代码、错误代码和场景状态信息，节点被选中扩展时恢复。
  • MCTS选择策略：SelectPolicy(n) = arg max Q_DUCB(n, S′)，使用折扣因子γ ∈ (0, 1)平滑丢弃过时反馈记录。
  • MCTS反向传播：外在奖励R_extrinsic = 0，提出基于“有价值时刻”的内在探索值R_intrinsic，若生成的代码在执行中包含至少一个“有价值时刻”（如“成功抓取杯子”），则设置R_intrinsic = 1。

场景缩放

通过计算原始场景与新场景坐标系间的变换矩阵，将桌面级任务场景泛化到房间级场景，公式为O·α = O′·α′，其中α ∈ {p, v, P}，利用RoboCasa资产可泛化到超过120个场景。

关键创新

  1. 全自动演示生成管线：HumanoidGen无需人工演示或RL探索，通过LLM+约束求解+MCTS的全自动流程生成高质量演示。这一创新将数据收集从“人工密集型”转变为“计算密集型”，使得大规模、多样化的双臂灵巧操作数据成为可能。

  2. STCR机制（分段-截断-合并-恢复）：这是对LLM规划失败处理的核心创新。传统方法在LLM规划出错时往往需要重新生成整个计划，而STCR通过截断失败点、合并意图一致的原子操作、恢复执行，实现了对失败的高效利用。实验表明，在‘block stack single’任务中，Token消耗增加26%带来成功率提升55%，平均每次成功执行方法的Token消耗从24.17K降至19.63K，减少约20%。

  3. 基于“有价值时刻”的内在奖励：由于MCTS迭代在发现成功任务计划时结束，外在奖励R_extrinsic = 0，作者提出基于“有价值时刻”的内在探索值R_intrinsic。这一设计使得MCTS能够在没有外部奖励信号的情况下，通过识别执行过程中的关键成功事件（如“成功抓取杯子”）来引导搜索，显著提升了规划效率。

实验与结果

基准与设置

  • 基准：HGen-Bench，包含20个任务，使用Unitree H1-2人形机器人配Inspire灵巧手，每臂7自由度，每手6自由度，共26维动作空间。
  • 对比基线：RobotTwin（修改官方实现以添加灵巧手和额外标注，并提示LLM不进行主动动态碰撞管理）。
  • 推理模型：DeepSeek-R1。策略：2D扩散策略（DP）和3D扩散策略（DP3）。

边界与局限

  • 未考虑双臂策略学习中的先验（如人-物交互、几何约束、手臂运动基元），直接训练2D和3D扩散策略。
  • 部分任务策略表现出非平稳特性，即使20条演示下成功率较高，动作仍不稳定有风险（表中以‘*’标注）。例如Close Box Hard任务在20条演示时手臂快速随机移动偶尔碰巧关闭盒盖导致虚高成功率。
  • 对于挑战性任务（如长时程‘blocks stack easy’），DP和DP3在数据有限时性能明显下降；DP3建模高自由度动作和复杂长时程任务需要更多数据。
  • 未提及对真实机器人部署的验证。论文未明确。

工程启示

  • 复现核对：首先确认SAPIEN仿真引擎和Unitree H1-2机器人配置（26维动作空间）是否与论文一致。约束求解器使用pydrake库中的SNOPT，运动规划使用mplib库，自动资产标注使用Stable Diffusion编码器，这些依赖项需提前验证。
  • 数据采集：每任务收集100个演示样本，每个样本包含6个摄像头的RGB和深度图像、关节状态、动作真值。DP3输入点云裁剪至工作空间并下采样至1024个点，与关节角度一起作为输入。DP评估检查点为epochs 150、200、250；DP3评估检查点为epochs 1500、2000、2500。
  • 最容易踩坑：DP训练中某些任务在策略未学到有效策略时出现异常高的成功率（如Close Box Hard任务），这种行为不稳定且不安全。随着演示数量增加（如100条演示），手臂不再随机移动而是尝试有意的关闭动作，但由于DP缺乏空间理解和感知，手常与盖子碰撞，导致成功率反而降低。评估时需关注动作稳定性，而非仅看成功率。
  • 下游团队建议：对于需要精细手部控制的任务（如倒水、开盒），优先选择DP3而非DP；对于长时程任务（如积木堆叠），当前DP和DP3均难以学习，需考虑引入先验或更先进的长时域行为学习方法。
