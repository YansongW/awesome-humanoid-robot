Summary

This paper proposes the Therblig-Based Backbone Framework (TBBF), which decomposes long-horizon robot manipulation tasks into elemental therblig units offline and transfers trajectories to novel scenes online via Action Registration and LLM-guided visual correction.

Sources

  • A Backbone for Long-Horizon Robot Task Understanding

概述

本文提出Therblig-based Backbone Framework (TBBF)，将长时程机器人任务分解为基本动作元素（therbligs）作为骨干，结合元学习门控融合网络（MGSF）与LLM对齐策略（LAP-VC），实现零样本场景下的任务理解与轨迹迁移。核心贡献在于用动作基元替代端到端黑箱，在五个未见任务上达到94.4%成功率，显著优于现有基线。

它改变了什么

端到端机器人学习在长时程任务上的失败模式是结构性的：模型将轨迹预测与场景理解耦合在单一网络中，导致训练分布外的泛化能力急剧下降。现有方法在拾取-放置等短程任务上表现尚可，但一旦涉及多阶段操作（如倒液体、擦盘子），误差累积和场景偏移就会使策略崩溃。本文真正改变的是将“任务理解”从“动作生成”中解耦——用therbligs作为中间表征，让高层语义（做什么）与低层控制（怎么做）分离，从而把一次性演示中的技能迁移到新场景。

这一转变的实质是重新定义了机器人学习的归纳偏置：不再假设网络能从像素直接学到任务结构，而是显式注入动作基元的先验。这使系统在零样本场景中无需大量微调即可工作，同时保留了可解释性——每个therblig的分割结果都可以被检查和修正。相比PerAct、Diffuser等依赖大规模预训练或扩散采样的方法，TBBF在数据效率上具有本质优势。

方法拆解

框架总览

TBBF分为离线训练与在线测试两阶段。离线阶段训练MGSF网络进行therblig分割；在线阶段收集一次性演示后，通过ActionREG将therblig先验编码到图像中，再由LAP-VC修正动作点。

MGSF网络架构

  • 输入：机器人状态（关节角度、末端位姿、速度、力/扭矩）
  • 双分支结构：BiLSTM捕获时序依赖，Transformer建模长程上下文
  • 元递归门控融合：动态组合两分支输出，门控权重由元学习器生成，避免固定加权
  • 消融显示：无融合召回率79.77%，加融合84.29%，加门控90.92%，完整版94.37%

ActionREG编码

  • 使用SAM进行对象分割，YOLOv8检测候选对象
  • SIFT+FLANN特征匹配，PCA降维确定对象配置
  • 将therblig先验作为提示注入SAM，实现任务相关对象的推理

LAP-VC修正

  • 将预测点与场景图像输入LLM，使用预构建提示输出修正点
  • 平均对齐性能0.896，优于KNN、SIFT、ORB等传统方法

场景设置

  • SimScenario：仅两个任务相关未见对象
  • ComScenario：添加3-6个无关对象模拟杂乱环境

关键创新

  1. Therblig作为任务骨干：将工业工程中的动作基元引入机器人学习，提供比端到端更细粒度的任务分解。这不是简单的动作分割，而是建立了“任务语义”与“轨迹执行”之间的可解释桥梁，使技能迁移成为可能。

  2. 元递归门控融合（MGSF）：不同于MetaGross的简单拼接，MGSF引入自适应门控机制动态组合BiLSTM与Transformer输出。门控权重由元学习器生成，使网络能根据任务特性调整时序与语义特征的贡献比例，这是召回率从84.29%提升至94.37%的关键。

  3. LLM驱动的视觉修正（LAP-VC）：将LLM作为后处理校正器而非端到端控制器，利用其常识推理能力修正视觉预测中的累积误差。这种“预测-修正”范式避免了LLM直接控制机器人的不可靠性，同时利用了其语义理解优势。

与SOTA对比（表I）

Ours 94.4% vs PerAct 65%、Diffuser 54.4%、MimicPlay 55%、GLiDE 99.6%、Coarse to Fine 70%。GLiDE更高但需大规模预训练，TBBF在零样本一次性演示条件下达到此水平。

边界与局限

  • 依赖标准专家演示，对嘈杂或不专业演示鲁棒性差（论文未明确量化阈值）
  • 仅处理2D对象配置，未利用深度信息，3D场景泛化受限
  • 受对象阴影和光反射影响，视觉模块在极端光照下可能失效
  • 未与ACT、扩散策略对比，因这些方法需大数据集或聚焦离散子任务
  • 实验仅在UR5+折纸夹爪平台验证，未扩展到Panda或Kinova

工程启示

复现时先核对三个关键点：therblig标签协议（需两人标注，一人演示一人标注状态，标签一致性直接影响分割质量）、MGSF门控初始化（元学习器的初始权重对收敛影响大，建议使用预训练BiLSTM权重）、LAP-VC提示模板（LLM输出对提示措辞敏感，需针对任务调整）。最容易踩坑的是ComScenario中的对象数量——论文使用3-6个无关对象，超过此范围性能可能急剧下降。工程上建议先用SimScenario验证管线，再逐步增加场景复杂度。若下游团队需部署，优先关注Spoon-tilting类任务（成功率68%），这类涉及精细姿态调整的操作对therblig分割误差最敏感。
