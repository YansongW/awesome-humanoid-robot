Summary

Recent advancements in imitation learning have led to transformer-based behavior foundation models (BFMs) that enable multi-modal, human-like control for humanoid agents.

Sources

  • arXiv:2503.22886 Task Tokens: A Flexible Approach to Adapting Behavior Foundation Models

Overview

This paper proposes the Task Tokens method, which maps task objectives into token sequences via a task encoder to flexibly adapt Behavior Foundation Models. Through architecture ablation experiments and human preference studies, the authors validate the method's robustness across different encoder scales, with or without current pose concatenation, and with or without joint conditioning, while also evaluating the human-likeness quality of generated actions. The core contribution lies in providing a lightweight, modular task adaptation mechanism that adapts to multiple downstream tasks without fine-tuning the foundation model.

What It Changes

Behavior Foundation Models (such as robot manipulation or motion generation models) are typically pretrained on large-scale data, but downstream task adaptation often relies on full fine-tuning or complex prompt design, which is costly and inflexible. Task Tokens changes this paradigm: instead of modifying the foundation model's weights, it uses a learnable task encoder to convert task descriptions into compact token sequences that are injected as conditioning inputs. What truly changes is the trade-off between "adaptation cost" and "task scalability"—downstream teams no longer need to retrain or store model copies for each new task; they only need to train a lightweight encoder (MLP scale of just [256,256] or [512,512,512]) to dynamically switch tasks at inference time. This design reduces task adaptation from the "model level" to the "input level," marking a key step toward engineering deployment of behavior models.

Method Breakdown

Task Encoder Architecture

  • Input: task objective (e.g., direction, target position) concatenated with optional current pose (head/pelvis position).
  • Encoder: MLP, with two configurations—[256,256] (default) and [512,512,512] (Bigger MLP).
  • Output: Task Tokens, injected as conditioning token sequences into the transformer layers of the behavior foundation model.

Key Design Decisions

  • Joint Conditioning (J.C.): In Direction, Steering, and Reach tasks, joint states are input together with task tokens. Ablations show that J.C. significantly improves performance stability, especially with small encoders + no current pose (Steering Success improves from 84.28% to 86.88%).
  • Using Current Pose: Head/pelvis positions are concatenated with the task objective. Ablations show that this operation actually degrades performance without J.C. (e.g., dropping from 84.28% to 66.31% when Bigger MLP=False), suggesting that redundant pose information may interfere with task encoding.
  • Encoder Scale: [512,512,512] slightly outperforms [256,256] without J.C. (83.30% vs 84.28%, not significant), but with J.C. the two are nearly identical (87.58% vs 86.88%), indicating that a larger task encoder is not necessarily better—J.C. provides the more critical conditioning signal.

Human Study Protocol

  • Each question displays 3 side-by-side videos (randomly sampled sequences), and participants choose the action that looks most human-like.
  • Algorithm order is randomly shuffled, video camera angles are similar, and Task Tokens are guaranteed to appear each time.
  • Win rate formula: winning percentage^A_env = (# Task Tokens chosen) / (# Task Tokens chosen + # Algorithm A chosen).

Key Innovations

  1. "Input-level" abstraction for task adaptation: Encoding tasks as token sequences rather than modifying model weights allows a single foundation model to serve multiple tasks simultaneously, with near-zero task-switching cost. This is similar to prompt tuning but specifically designed for behavior sequence generation (e.g., combined with joint conditioning).
  2. Robustness analysis of redundant conditions: Ablations clearly show that "current pose concatenation" is harmful without J.C. (performance drops by 18 percentage points), providing practitioners with clear input design guidelines—do not blindly stack conditioning features.
  3. Rigor of human preference validation: 96 participants, 3 forms, randomly shuffled order per question, and win-rate calculation that excludes self-comparison bias, offering a reproducible evaluation protocol for "human-likeness" quality.

Boundaries and Limitations

The paper does not explicitly mention the following limitations: - No specific win-rate values for Task Tokens in the human study are reported, only the experimental protocol, making it impossible to quantify its relative advantage. - No discussion of token conflicts or attention interference during simultaneous multi-task inference. - No testing of encoder scales beyond [512,512,512] to determine performance ceilings, nor any explanation of the relationship between training data volume and encoder convergence. - Ablations are only reported on the Steering task; results for Direction and Reach tasks are not provided, leaving generalizability in question.

Engineering Insights

  • Prioritize enabling Joint Conditioning: Ablation data strongly indicates that J.C. is key to performance stability; it should be enabled by default in reproductions, especially for Direction, Steering, and Reach-type tasks.
  • Do not blindly concatenate current pose: Concatenating head/pelvis positions without J.C. significantly degrades performance (66.31% vs 84.28%); it is recommended to run ablations before deciding whether to introduce this feature.
  • Encoder scale selection: [256,256] is nearly on par with [512,512,512] when J.C. is enabled (86.88% vs 87.58%); prefer the smaller model to reduce overfitting risk and inference overhead.
  • Human evaluation protocol is reusable: The design of 96 participants, 3 forms, and randomly shuffled order is worth adopting, but note that random video sampling may introduce variance; consider fixing the random seed and increasing repetitions.
  • Most common pitfall: Current pose concatenation is a "performance killer" without J.C.; if the downstream task inherently contains pose information, be sure to verify whether it is redundant with task tokens.
