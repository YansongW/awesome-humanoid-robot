Summary

This paper presents a CAD-based human-robot interface that lets non-expert users program industrial robots by drawing paths in Autodesk Inventor, and compensates for environmental uncertainty using online feedback from a laser camera and a force/torque sensor.

Sources

  • High-level robot programming based on CAD: dealing with unpredictable environments

Overview

This paper proposes a high-level robot programming method based on a general-purpose 3D CAD software (Autodesk Inventor), where users directly draw paths and define tool poses in the CAD environment, and the system automatically generates robot programs, with online path adjustments via external sensors (laser camera, force/torque sensor) to handle unpredictable environments. The authors are from the University of Coimbra, Portugal (Pedro Neto et al.), and the core contribution lies in combining CAD integration, automatic program generation, and closed-loop sensory feedback, offering a low-cost, easy-to-use robot programming solution for small and medium-sized enterprises.

What It Changes

Traditional robot programming relies on teach pendants, which is time-consuming and requires specialized skills, making it difficult for SMEs to afford skilled operators. Existing CAD-based robot programming research is mostly partial solutions, lacking "global" automation from CAD to robot programs, and insufficiently addressing uncertainties in dynamic environments (e.g., model errors, calibration deviations, foreign objects). What this paper truly changes is: elevating the programming entry point from "teaching in the robot coordinate system" to "path drawing in the CAD assembly model," and, for the first time, systematically introducing external sensors (laser camera, force/torque) into a CAD-integrated framework for online path correction, enabling non-expert users to program via "drawing" while equipping robots to handle real-world environmental deviations. This differs from commercial CAR software (which requires standalone CAM/CAR platforms) and from pure offline programming (which cannot handle online disturbances).

Method Breakdown

User Workflow

  1. "Draw" the desired path (lines, splines, arcs) in Autodesk Inventor, and place simplified tool models along the path to define end-effector poses (position + orientation).
  2. Extract path point coordinates and the transformation matrix of each part model (relative to the assembly origin {U}) via the Inventor API.
  3. Convert the extracted information into robot programs (motion commands, reference frames, tool parameters).

Coordinate Transformations

  • Calibration defines frame {B} relative to {U}: BCT = BUT · UCT (Equation 1).
  • When computing BUT, the rotation matrix BUR = UBT^T, and the position BUorgP = -UBT^T · UBorgP (Equations 6, 7).
  • Key point: users must define frames in CAD and teach the frame pose to the robot in the real scene (offline-to-online mapping).

Interpolation Methods (for Risk Zones)

  • Identify risky paths (where end-effector orientation changes abruptly).
  • Discretize with equal spacing and compute the orientation at each interpolation point.
  • Position interpolation: direction vector W = Pj+1 - Pj, velocity distribution vi(k) = (Wi/|W|) · v(k) (Equation 10), sampling width Δt, interpolated position r(k) = r(0) + vi(k) · k · Δt (Equation 13).
  • Orientation interpolation: quaternion spherical linear interpolation (Slerp), Equations 14, 15.

Program Generation

  • Two stages: first define and parameterize positions/orientations, reference frames, and tools (Equation 16), then generate the program body, selecting motion commands (linear, joint, circular, or spline) based on the CAD line type.

Sensory Feedback

  • Laser camera (welding) and force/torque sensor (contour tracking) provide online path adjustments.
  • Closed-loop position control or force control (Fuzzy-PI and PI inference) is employed.

Key Innovations

  1. CAD as the Programming Interface: Users do not need to learn robot programming languages; they simply "draw paths" in CAD to generate programs, resulting in a short learning curve, and CAD modeling and programming occur on the same platform, avoiding the high costs and conversion losses of CAM/CAR software.
  2. Global Solution: Unlike existing research that addresses only partial aspects, this paper covers the complete chain from CAD path drawing, coordinate transformations, interpolation smoothing, to program generation and sensor-based online adjustment, based on a general-purpose CAD package (Inventor) rather than specialized software.
  3. Online Sensory Feedback Integration: Laser camera and force/torque sensors are incorporated into the CAD-based programming framework, allowing offline-generated paths to be corrected in real time to handle unpredictable factors such as calibration errors, model inaccuracies, and foreign objects—a capability generally missing in existing CAD-based research.

Experiments and Results

Contour tracking Motoman HP6 / NX100 JR3 6-DOF F/T sensor (Ethernet 100 Mbps) 20 Hz Force setpoint -15 N Axial force -30 to 0 N, position -5 to 10 mm (0-200 s), Fuzzy-PI and PI controllers
  • In Experiment 1, the robot path adjustment frequency was limited to 5 Hz, causing non-smooth corrections at higher welding speeds; the robot resolution of 0.01 mm made adjustments more abrupt.
  • In Experiment 2, force fluctuations arose from surface roughness and F/T data noise.

Boundaries and Limitations

  • The system is designed for specific technical applications (welding, contour tracking), not a general-purpose solution.
  • In Experiment 1, the 5 Hz adjustment frequency limit led to non-smooth corrections at high welding speeds; the 0.01 mm resolution made the adjustment process abrupt.
  • External sensor online adjustment may encounter: sensor collisions with the workspace, robot arm sent outside the work area, kinematic singularities, improper process parameter selection, and communication delays between sensor and controller.
  • Operators must ensure the workpiece is within the robot's work area, collision-free, and identify kinematic singularities.
  • On task failure, restarting the system after aborting may be complex (e.g., arc welding requires returning the torch to the stop point).
  • The paper does not specify data volume, training configurations (no machine learning), nor does it mention multi-sensor fusion strategies or handling of complex surfaces (non-linear/arc/spline).

Engineering Insights

  • Prioritize Verification for Reproduction: The coordinate transformation formulas (Equations 1, 6, 7) are central to offline-to-online mapping; calibration accuracy directly affects path precision; in experiments, deliberate rough calibration was used to simulate unpredictable environments, so in practice, tolerance to calibration errors should be assessed.
  • Interpolation Parameters Are Sensitive: Risk zone identification and Slerp interpolation (Equations 14, 15) are critical for handling abrupt orientation changes; the discretization width Δt and velocity distribution vi(k) must be adjusted based on actual path curvature, otherwise path jitter may occur.
  • Sensor Integration Is the Biggest Pitfall: The difference between 5 Hz adjustment frequency (Experiment 1) and 20 Hz (Experiment 2) is significant; high-frequency applications require consideration of communication delays and controller bandwidth; in force control, Fuzzy-PI parameters need tuning for surface roughness, otherwise force fluctuations are pronounced.
  • Downstream Teams Should Note: The system relies on the Autodesk Inventor API (VB/C#/C++), requiring a standalone application to extract CAD information (Autodesk Apprentice Server displays the model); communication components (PcRob, MotomanLib, JR3PCI) are all hardware-specific, so changing robots or sensors requires rewriting interfaces.
  • Safety Redundancy: Operators must manually confirm the work area, collisions, and singularities; the system has no automatic obstacle avoidance or singularity avoidance, so additional safety logic is needed for actual deployment.
