Summary

Learning long-horizon humanoid loco-manipulation poses a dual challenge: it requires not only the robust execution of meta-skills but also their seamless, closed-loop chaining equipped with autonomous recovery. Overview

OmniContact proposes "Contact Flow" as a unified interface between high-level semantic planning and low-level whole-body execution for humanoid mobile manipulation. Through hierarchical collaboration between the CF-Gen rule-based planner and the CF-Track reinforcement learning controller, it enables long-horizon, recoverable skill chaining. The core contribution lies in using sparsely non-uniformly sampled body trajectories coupled with four-dimensional binary contact signals, balancing expressiveness and compactness, significantly surpassing existing baselines in simulation.

What It Changes

Humanoid mobile manipulation has long been stuck on the choice of "representation": full human-object interaction (HOI) states offer high precision but suffer from dimensionality explosion, making high-level planning difficult; implicit skill embeddings are compact but uninterpretable, lacking reliability guarantees when composed. Existing RL approaches either rely on teleoperation for open-loop execution or require frame-by-frame full-body references, essentially sidestepping the core question of "how skills are invoked by high-level tasks." What OmniContact truly changes is elevating "contact" from an execution detail to a planning primitive—it no longer requires the high-level planner to predict dense kinematics, but only to output object-level goals, with contact flow serving as an intermediate language bridging semantics and physics. This shift allows foundation models like VLMs to intervene in long-horizon task decomposition while preserving the robustness and recovery capabilities of low-level policies—a paradigm shift in interface design.

Method Breakdown

Contact Flow Representation

  • Formalization: At time step t, contact flow F_t = {(b_{t+k}, c_{t+k})}_{k∈T}, where T = {0,1,2,3,4,8,12,16,24,32,50} are non-uniform future frame offsets.
  • b represents sparse body motion targets (torso, wrist, ankle positions and orientations), c ∈ {0,1}^4 is a four-dimensional binary contact signal specifying end-effector contact states.
  • Non-uniform sampling is dense at near horizons and sparse at far horizons, balancing short-term precision with long-term planning horizon.

CF-Track (Low-Level Controller)

  • A unified policy tracks contact flow targets, with input x_t = [F_t, H_t], where H_t is a K=5 step history buffer.
  • Observations include proprioception (joint kinematics, base orientation, end-effector positions, previous actions) and object states (relative 6D pose, bounding box).
  • Reward: r_t = λ_track·r_t^track + λ_amp·r_t^amp + λ_reg·r_t^reg, with optimal weights W_track–W_amp = 0.85–0.15.
  • Both Actor and Critic use Transformers (hidden dimensions [512,256,128], 3 layers, 8 heads) rather than MLPs.

CF-Gen (Mid-Level Planner)

  • Rule-based reference synthesizer: given object-level goals, current state, object pose and dimensions, generates dense reference motion.
  • Phase template library: each meta-skill is decomposed into ordered phase blocks (e.g., carrying: approach → pre-grasp → lift → walk → release), with each phase having explicit contact semantics.
  • Keyframe generation: IK is used only when precise end-effector placement is required (up to 20 iterations); pure locomotion phases only specify ankle orientations, with default nominal poses for the rest.
  • IK optimization variables: pelvis height z_pelvis, pelvis pitch θ_pitch, all joint DOFs q, strictly excluding pelvis roll and yaw.
  • Trajectory interpolation: LERP for translation and joints, SLERP for rotation.
  • Online replanning: monitored at 50 Hz; when deviation δ_t exceeds threshold ε, the current plan is aborted and replanning occurs from the current state.

Hierarchical Execution and VLM Integration

  • CF-Gen converts task goals into object-centric contact flow segments; CF-Track executes and continuously monitors. Upon phase completion or failure, CF-Gen updates the state and synthesizes the next segment.
  • The VLM (Gemini 3.1 Pro Preview) performs only object-level planning: identifying objects, assigning target regions/poses, selecting meta-skills, and outputting plans in JSON format—without predicting any low-level kinematics.

Key Innovations

  1. Contact flow as a composable intermediate representation: Explicitly encodes contact signals as binary temporal vectors coupled with sparse body trajectories. Ablations show that adding the contact term (C) improves the [T, EE] baseline success rate from 11.50% to 98.70%, proving that contact is a critical semantic anchor for skill composition rather than redundant detail.
  2. Decoupling rule-based planner from learned controller: CF-Gen generates references using heuristic phase templates and IK, while CF-Track tracks them with RL and smooths artifacts. This design avoids the fragility of end-to-end learning for long-horizon composition while keeping replanning logic transparent and debuggable.
  3. Minimal constraints on the VLM interface: Restricts foundation model outputs to a list of object-level subgoals, without requiring prediction of joint trajectories or contact timings. This enables open-vocabulary semantic reasoning (e.g., "put the cylinder in the basket") to directly drive contact-rich low-level execution, with attributable failure modes (vague grounding, infeasible layouts, execution deviations).

  • Online replanning provides significant gains: Push Suitcase improves from 82.5% to 94.5% (average 0.77 replans), Stack Boxes from 56.6% to 80.5% (0.96 replans).
  • Key ablation findings: Explicit contact modeling (C) is the primary driver of the success rate jump; adding full joint targets (Dof) instead causes failure (0.00%), indicating that over-specifying DOFs suppresses policy adaptability.
  • Reward balance: Pure tracking (1.0–0.0) achieves only 46.30% stability, while the optimal balance (0.85–0.15) reaches 98.70% success with 58.80% stability.
  • Robustness: Carry Box + Drop achieves 92.5% final success (average 1.64 replans), and 97.5% under Object Pose Offset.
  • Long-horizon: Protocol I (single-object sequential goals) achieves 100% survival over 40 minutes, but Protocol III (multi-object) drops to 10.0% survival over 40 minutes, with an average of 26.0 object drops.
  • Data scale: Scaling from 10% (2.2h) to 100% (22.3h) improves both success rate and object precision.

Boundaries and Limitations

The paper does not explicitly list a limitations statement, but inferences can be drawn from experiments: underactuated grippers limit fine manipulation, and extending contact flow to dexterous hands remains unfinished work; the rule-based CF-Gen performs poorly in highly dynamic scenarios (e.g., fast ball kicking), with the authors envisioning learnable data-driven methods to replace heuristic contact anchor generation. All quantitative results are obtained in simulation (trained in Isaac Lab, evaluated in MuJoCo), with real-world deployment only qualitatively demonstrated on Unitree G1 without quantitative data. Long-horizon multi-object tasks (Protocol III) show severe success degradation (only 10% over 40 minutes), indicating that skill chaining still suffers from cumulative errors as object count increases. Ball tasks have relatively low success rates (Relocate Ball 72.5%, Kick Ball 76.5%) due to the smooth rigid simulated balls being prone to sliding.

Engineering Insights

When reproducing, prioritize verifying three points: first, the contact flow sampling offsets T and history window K=5 configuration, which are key to representation compactness; second, the reward weights W_track–W_amp = 0.85–0.15, as deviation significantly impacts success rate (0.10% at 0.5–0.5); third, the IK optimization constraint excluding pelvis roll and yaw, which is a prerequisite for torso stability. The most common pitfall: adding full joint targets (Dof) destroys policy adaptability (success drops to 0.00%), so CF-Gen must only specify torso, wrist, and ankle when synthesizing references, leaving other DOFs to the policy's autonomous decisions. For downstream teams, we recommend adopting contact flow as the interface standard between modules—high-level planners output only object-level goals, low-level policies consume only contact flow, with no dense kinematics passed in between. The 50 Hz replanning frequency and deviation threshold ε should be tuned according to task dynamics; push tasks achieve significant success gains with an average of 0.77 replans, but multi-object long-horizon tasks see replan counts surge with drop events, requiring reserved computational headroom.
