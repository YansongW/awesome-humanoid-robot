Summary

Open-World Object Manipulation using Pre-trained Vision-Language Models (MOO), is a 2023 generalized vision-language-action model for robotic manipulation, introduced by Robotics at Google, and published at CoRL 2023.

Sources

  • MOO source

概述

本文提出 MOO（Masked Object-oriented）方法，利用冻结的开放词汇视觉-语言模型（Owl-ViT）在 episode 首帧将语言指令中的物体描述转化为单像素掩码，与原始图像拼接后输入端到端模仿学习策略（基于 RT-1 架构），实现对新物体类别、新环境与复杂纹理的开放世界操作泛化。作者将 MOO 与开放词汇导航 CoW 集成，形成 CoW-MOO 系统，并在真实移动操作机器人上验证了 pick、move near、knock over、place upright、place into 五种技能。

它改变了什么

传统流水线方法（检测-规划-控制）虽能泛化到多类别，但依赖精确物体定位，且受限于检测器封闭类别集；端到端策略虽鲁棒，但语言指令中未见过的物体描述对策略是分布外输入，无法泛化。MOO 的实质改变在于：不要求 VLM 提供精确状态估计，而是仅用其输出一个“语义锚点”（物体中心像素），将开放词汇的语义知识以极低信息量的方式注入策略，从而在不破坏端到端训练鲁棒性的前提下，获得对任意可见物体的操作能力。这打破了“语义泛化必须依赖精确感知”的隐含假设，使策略能学会容忍 VLM 的定位误差，同时保留对训练分布外物体的响应能力。

方法拆解

两阶段流程

  1. 物体定位：将指令 ℓ 用正则表达式拆分为动词 v 与名词短语 X（多物体提取序列 X, Y, ...）；以提示词 q = “An image of an X” 查询冻结的 Owl-ViT，输出边界框；取框中心像素作为物体表示。
  2. 策略推理：将物体掩码（单物体为 one-hot 通道，像素值 1.0；双物体时第一物体 1.0、第二物体 0.5）按通道拼接至当前图像及近期图像历史；语言指令去除物体描述后经 LLM 嵌入，通过 FiLM 条件化 EfficientNet 图像特征；Token Learner 压缩 token 集，Transformer 输出 7 自由度 delta 末端位姿动作 token。

关键设计决策

  • 掩码为单像素而非分割掩码：降低对 VLM 精确分割的依赖，使策略学会从粗略位置线索结合原始图像完成操作。
  • VLM 完全冻结：避免对机器人演示数据中的物体过拟合，保持开放词汇能力；策略在 VLM 在环下训练，隐式学习对检测错误的鲁棒性。
  • 物体信息仅首帧提取：后续帧由策略自行跟踪物体，将 VLM 重计算限制在 episode 开始，满足实时控制约束。
  • 动作空间：7 自由度 delta 末端位姿（x, y, z, roll, pitch, yaw, 夹爪），训练目标为动作负对数似然最小化。

模型规模

主模型 111M 参数；通过按常数因子缩小层宽与深度，得到 10.2M 与 2.37M 参数的消融版本。

关键创新

  1. 语义锚点注入而非语义特征拼接：以往方法将语言嵌入直接条件化策略，未见类别文本对策略是分布外；MOO 将物体描述转化为图像空间中的像素位置，使策略只需理解“哪里”而非“是什么”，从根本上绕开语言分布外问题。
  2. 对 VLM 错误的隐式鲁棒性：策略在冻结 VLM 在环下训练，能学会在检测框偏移、漏检或误检时仍通过原始图像观察完成任务，这是流水线方法不具备的特性。
  3. 多模态掩码输入兼容性：掩码可来自文本查询、图像查询（利用 Owl-ViT 多模态特性）或人类 GUI 点击，使 MOO 能处理文本难以描述或场景中存在重复物体的情形，扩展了适用边界。

MOO 在 pick 任务上相对最优基线提升约 50%（由表内数值 62→92、50→75 计算）；在 unseen 物体上，其他技能泛化与 pick 技能 unseen 性能持平，比次优基线好 50%（由表内数值 50→75 计算）。

方法 Open-World Objects Challenging Textures New Environments

在 Challenging Textures 场景，MOO 比基线好超过 7 倍（由表内数值 7→50 计算）。

数据与模型规模消融

  • 训练集 59051 个片段，减半为 29525 个；训练物体 106 个，减半为 53 个。100% 数据 + 100% 物体时 pick unseen 成功率为 75%；50% 数据 + 100% 物体与 100% 数据 + 50% 物体均降至 38%；10% 物体时 unseen 成功率为 0。结论：数据规模与物体多样性同等重要，且二者可部分相互替代。
  • 模型从 111M 缩至 10.2M 与 2.37M 时，seen 与 unseen 性能均显著下降（论文未明确具体数值）。

输入模态定性实验

MOO 可泛化至 PaLI 文本描述生成的掩码、图像查询掩码及人类 GUI 提供的 ground-truth 掩码，在重复物体与杂乱场景中能正确区分目标（定性结果，无定量数字）。

边界与局限

  • 掩码表示在多数但非所有情况下能唯一标识物体：苹果置于盘上时，以苹果为中心的掩码可能指向盘子或苹果。
  • 物理泛化受机器人数据多样性限制：即使 VLM 准确定位，策略仍可能无法抓取与训练演示形状或尺寸差异过大的新物体。
  • 无法处理涉及空间关系的复杂描述（如“盘子左边的小物体”）。
  • 模型规模受实时推理约束，未超过 111M 参数；作者预计放宽速度要求后更大模型会带来持续提升。
  • 排除了所有涉及抽屉的任务，因当前 VLM 难以检测抽屉；依赖提示工程，虽多数提示首次有效但需人工设计。
  • 输入模态实验仅定性评估，未报告定量数字；VLM 检测失败无显式处理机制，仅依赖策略训练时的隐式鲁棒性。

工程启示

  • 复现优先核对：VLM 检测器必须使用 Owl-ViT 且保持冻结；提示词统一前缀 “An image of a” 并包含颜色、大小、形状等描述性短语；物体掩码通道像素值严格按单物体 1.0、双物体 1.0/0.5 设置。
  • 最易踩坑点：物体信息仅在首帧提取，若策略在后续帧丢失目标（物体被移动或遮挡），无重检测机制——需确保训练数据中物体移动幅度与测试分布一致；另外，额外 90 个物体仅用于 pick 技能数据收集，其他技能仍依赖原始 16 物体，跨技能泛化依赖掩码通道的通用性。
  • 下游团队选型建议：若任务涉及抽屉、透明物体或高度依赖空间关系的指令，MOO 不适用；若场景存在重复物体或文本难以描述的物体，应优先采用图像查询或人类点击生成掩码的模态。
  • 数据效率启示：数据消融表明，增加训练集规模（不增加物体多样性）与增加物体多样性（不增加规模）可达到相近的泛化水平——在演示者时间预算有限时，优先增加物体种类而非重复采集同一物体的更多演示。
