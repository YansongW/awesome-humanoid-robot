Summary

DualTHOR: A Dual-Arm Humanoid Simulation Platform for Contingency-Aware Planning is a 2025 work on simulation benchmark for humanoid robots.

Sources

  • DualTHOR: A Dual-Arm Humanoid Simulation Platform for Contingency-Aware Planning (arXiv)

概述

DualTHOR 是一个基于 Unity 物理引擎、面向双臂人形机器人的高保真仿真平台，由作者团队开发，用于评估和提升 VLM 在双臂任务中的规划能力与鲁棒性。其核心贡献在于引入概率性 contingency 机制模拟真实世界动作结果的不确定性，并支持 Unitree H1 与 Agibot X1 两种人形机器人的连续交互控制。

它改变了什么

现有仿真平台（如 AI2-THOR、Habitat、Isaac Gym）的机器人形态局限于轮式或单臂，无法支撑双臂人形机器人的任务规划研究。更关键的是，这些平台的动作执行多为“flash-like”瞬变，即低层技能以瞬时切换完成，忽略了连续执行过程中的物理约束和潜在失败。这种理想化假设使得 VLM 在仿真中习得的规划策略难以迁移到真实世界——真实世界中拾取可能失败、物体可能破损、开关可能卡住，而现有平台无法提供这类反馈信号。

DualTHOR 真正改变的是评估范式：它不再将 VLM 规划视为在确定性环境中的序列决策，而是引入概率性意外机制，迫使模型在动作结果不确定时进行重新规划。这一转变使得仿真评估更接近真实部署场景，也为研究 VLM 的鲁棒性和自适应能力提供了可复现的实验平台。

方法拆解

平台架构

  • 基于 AI2-THOR 扩展，集成 Unity 物理引擎，支持双臂并行执行和基于插值的平滑运动。
  • 控制闭环通过 JSON over TCP 在 Python 后端与 Unity 引擎间双向通信；IK 服务通过 HTTP 跨平台访问，使用 OmniManip 进行位姿计算和 IK 求解。

机器人形态

  • Unitree H1：使用灵巧手，适合重物和高力交互；采用全身协调模型，使用 4×4 齐次变换矩阵，并考虑平衡约束。
  • Agibot X1：使用夹爪，适合精细操作；采用解耦 IK 方式，使用 3×3 旋转矩阵和平移向量。

Contingency 机制

  • 仅针对物体依赖型动作引入概率性结果，使用分类分布建模（如拾取“可倾倒”杯子时，80% 成功、10% 杯子破裂、10% 内容物洒出）。
  • 多步骤操作可扩展为多项分布；动作受对象状态约束（如“Cooked”状态不能再次 COOK，但仍可 pickupable）。
  • 当机械臂接近物体且距离低于预定义阈值时，渲染预测结果。

视觉与任务

  • 第一人称头部相机支持 360 度全景，第三人称相机包括后、前、左、右视角，水平视场角 160 度。
  • 任务分为三类：双臂必需、双臂可选、单臂任务，区分依据是物体特性（如填充液体时若无支撑平台则需双臂必需）。

工程机制

  • 任务重放（Undo/Redo）支持从共同初始状态探索不同轨迹，避免重新启动仿真实例。

关键创新

  1. 概率性 contingency 机制：这是首个在双臂人形仿真平台中系统化建模动作结果不确定性的工作。不同于现有平台假设动作执行必然成功，DualTHOR 允许用户设计失败概率（如 80% 成功、10% 破损、10% 洒出），使 VLM 评估从“能否完成任务”转向“能否在意外发生后重新规划”。这一设计直接回应了仿真到真实迁移的核心痛点。

  2. 双臂并行执行与形态差异建模：平台支持物体依赖型动作的并行执行（如一手持物、一手开盖），并针对 H1 和 X1 分别设计 IK 求解器——H1 的全身协调模型考虑平衡约束，X1 的解耦方式更轻量。这种形态差异建模使平台能评估 VLM 是否理解不同机器人臂的物理能力边界。

  3. 连续动作控制替代瞬变执行：通过 Unity 物理引擎和插值平滑运动，DualTHOR 提供连续的低层执行过程，而非瞬间状态切换。这使得 VLM 能观察到动作执行中的中间状态（如机械臂接近物体的过程），为学习空间和时间约束提供更丰富的数据。

实验与结果

实验在 356 个任务、10 个房间环境、68 个独特对象上进行，每个任务在 X1 和 H1 上各评估 50 次试验。基线包括专有 VLM（GPT-4o、Gemini 1.5 Pro）、开源 VLM（Qwen2.5-VL-7B、InternVL2.5-8B）及提示增强方法（LLM-Planner、RAP、DAG-Plan，基座为 GPT-4o）。所有模型温度设为 0，最大 token 长度 2048，输入图像 500×500 像素，最大环境步数 50。

结果显示：DAG-Plan 在简单任务中表现最佳，但在 Hard 难度下成功率急剧下降（如双臂必需任务从 36.54% 降至 11.69%），说明其规划策略缺乏对意外事件的鲁棒性。所有模型在双臂必需任务上的成功率显著低于单臂任务，表明双臂协调仍是 VLM 的短板。失败案例分析指出，DAG-Plan 未考虑左臂交互可达性，VLM 在右臂已占用时仍尝试使用右臂，缺乏结构推理能力。

边界与局限

作者承认当前场景多样性有限，灵活资产生成工具和更广泛机器人支持正在开发中。计划改进非网格定位、更可控的失败模式和多房间环境。未来工作应纳入多智能体协作评估。论文未明确提及对真实机器人部署的实验验证，仅强调平台旨在减少真实世界部署难度。此外，contingency 机制仅针对物体依赖型动作，物体独立型动作（如移动、旋转）不涉及概率性结果。更复杂的意外（如物体破损后需重新导航和识别等效物体）要求更强的重新规划能力，当前 VLM 在有限环境步数内难以实现。

工程启示

复现或使用 DualTHOR 时，首先核对 Unity 物理引擎版本与 AI2-THOR 资产兼容性，物体重新渲染是确保物理合理性的关键步骤。IK 服务依赖 OmniManip，需确认 HTTP 跨平台通信的延迟对闭环控制的影响——在 50 步最大环境步数限制下，IK 求解延迟可能成为瓶颈。最容易踩坑的是 contingency 概率设置：默认 80% 成功、10% 破损、10% 洒出的参数会显著影响 VLM 的重新规划行为，建议根据任务难度调整概率分布。对于下游团队，若目标是评估双臂协调能力，应优先使用双臂必需任务集（97 个 Open affordance-specific containers 任务），这些任务最能暴露 VLM 的结构推理缺陷。H1 在多数任务上表现优于 X1，但这是机器人形态差异（灵巧手 vs 夹爪）而非规划能力差异，对比时应控制这一变量。
