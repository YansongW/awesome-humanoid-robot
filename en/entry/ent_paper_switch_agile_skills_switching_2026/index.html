Overview

This paper proposes Switch, a hierarchical multi-skill switching system for humanoid robots. It constructs a Skill Graph (SG) to connect skill nodes that are similar in state but originally disconnected within motion data, and combines it with an online scheduler and graph-search planner to achieve robust, smooth, and online-replannable skill transitions. The system achieves a 100% switching success rate (SSR) on the Unitree G1, significantly outperforming the baseline (GMT as low as 2%), and addresses the issue of open-loop tracking becoming unstable under disturbances.

What It Changes

Existing whole-body control methods enable humanoid robots to perform single-skill, highly dynamic actions such as backflips and kicks. However, when it comes to switching between skills, problems emerge: either different skills are required to share common states, causing data requirements to explode combinatorially with the number of skills, or the system relies on feasible transitions that happen to exist in predefined trajectories—otherwise, the robot stumbles, staggers, or even loses control during switching. A deeper pain point is that these methods are essentially open-loop tracking of reference trajectories; once tracking errors accumulate beyond a threshold, the controller loses stability, which is dangerous in the physical world.

What Switch truly changes is transforming "skill switching" from "searching for transitions in data by chance" into "actively constructing a transition graph and planning online." It no longer assumes that transition states naturally exist in the data. Instead, it actively "bridges" skills through kinematic similarity and lets the policy learn feasible transitions on these bridges. Additionally, it introduces online replanning, enabling the system to autonomously select recovery paths when perturbed off the trajectory, rather than rigidly continuing to track an invalid reference. Methodologically, this advances multi-skill control from "open-loop execution" to "closed-loop decision-making."

Method Breakdown

Switch adopts a hierarchical architecture, centered on the coordination of three components:

Skill Graph (SG) Construction

  • Nodes: Every frame state \(\hat{s}^{\phi}_{t}\) from all skill reference sequences, i.e., \(V = \bigcup_{\phi\in\Phi}\{\hat{s}^{\phi}_{t}\}_{t=1}^{T_{\phi}}\).
  • Edges: Two types—(a) consecutive frame pairs within the same skill sequence; (b) cross-skill connections established via nearest-neighbor search: for frame \(i\) of source skill \(\phi_p\), find the nearest frame \(j = \arg\min_{t} d(\hat{s}^{\phi_p}_{i},\hat{s}^{\phi_q}_{t})\) in target skill \(\phi_q\) and connect them.
  • State Distance: Defined in a local coordinate frame (removing global x-y translation and yaw), \(d(\hat{s}^{m},\hat{s}^{n}) = \|q^{m}-q^{n}\|_1 + \|\dot{q}^{m}-\dot{q}^{n}\|_1 + \|\hat{p}^{m}-\hat{p}^{n}\|_1\).
  • Buffer Nodes: For cross-skill edges with large gaps, \(N\) buffer nodes are inserted, with the count determined by the distance between the edge endpoints—the larger the distance, the more buffers—to enhance switching smoothness.

Whole-Body Tracking Policy Training (PPO)

  • Observation: \(o_t = \langle s^{o}_{t}, g_t \rangle\), where \(s^{o}_{t}\) includes historical actions, gravity vector, joint positions/velocities, and root angular velocity; the guide \(g_t = \langle \hat{s}^{g}_{t}, \kappa_t \rangle\) contains reference local rigid-body positions and the remaining steps \(\kappa_t\) to the end of the buffer segment.
  • Reference State Initialization (RSI) Modification: Only states from the \(n\) steps before a skill transition are sampled as initial states, ensuring every training episode includes a skill transition.
  • Buffer-Aware Imitation Learning: During the buffer phase, the target state \(\hat{s}_{j}^{\phi_q}\) is used to compute rewards (rather than omitting rewards), guiding the model toward the target state to prevent severe deviations.
  • Unified Imitation Reward: A foot-ground contact reward (FGR) \(r^{\mathrm{FGR}}_{t} = \exp\left(-\lambda_c \sum_{i\in G} |c_{i,t} - c^{\mathrm{ref}}_{i,t}|\right)\) is introduced to address the issue where standard imitation rewards underestimate high-frequency foot-ground contact events (e.g., dance, martial arts), leading to conservative policies.
  • Curriculum Training: Three progressive curricula—skill augmentation curriculum (augmented trajectory ratio increases from 10% to 50%), reward penalty curriculum (regularization introduced gradually), and termination curriculum (deviation thresholds tightened gradually).

Online Scheduling and Planning

  • Deployment Edge Weights: Consecutive edges \(c=1\); cross-skill edges \(c(u\to v) = d(u,v) + \lambda_{\mathrm{sw}}[\![\,\text{skill}(u)\neq\text{skill}(v)\,]\!]\).
  • Graph-Search Planner: Runs reverse multi-source shortest paths from the target set \(T\), yielding a value function \(V^{*}\) and NextHop mapping, with a global view that can exploit overlapping reachable domains.
  • Nearest-Neighbor (NN) Planner: Selects entry points by nearest-neighbor similarity, with minimal latency, used for hardware deployment.
  • Intent-Driven Switching: The target set is defined as the prefix of the commanded skill \(T_{\text{cmd}}\); entry checks are based on local pose-velocity subspace similarity \(\mathrm{sim}\), handled in three tiers: \(\mathrm{sim}\le A\) connects directly, \(\mathrm{sim}\ge B\) delays switching and performs an emergency stop, and \(A<\mathrm{sim}<B\) evaluates top-\(k\) candidates by a composite score \(J(v) = \lambda_{\text{cost}}\,c(x,v) + V^{*}(v)\).
  • Safe Recovery: Triggered when similarity exceeds the threshold or the best candidate remains unsafe; the planner can use recovery skills as intermediate segments. During emergency stops, a damping controller overrides the policy, waiting for the system to come to rest before executing the recovery plan.

Key Innovations

  1. Skill Graph as a Data-Driven Prior: Unlike traditional methods that rely on feasible transition states existing in predefined trajectories, Switch actively builds connections between skills via kinematic similarity and inserts buffer nodes. This fundamentally bypasses the combinatorial explosion of collecting \(O(n^2)\) skill-pair transition data, transforming the switching problem into a path-planning problem on a graph.

  2. Buffer-Aware Imitation Learning and FGR Reward: Using the target state to compute rewards during the buffer phase, rather than omitting them, significantly promotes policy convergence and prevents performance collapse. The FGR reward addresses the underestimation of high-frequency foot-ground contact events (e.g., dance, martial arts) by standard imitation rewards, improving policy agility and motion fidelity.

  3. Online Replanning and Safe Recovery Mechanism: The system possesses closed-loop decision-making capability. When tracking errors exceed thresholds or disturbances occur, the scheduler can automatically trigger replanning, even using recovery skills (e.g., getting up) as intermediate segments. This upgrades the system from "open-loop tracking" to "closed-loop decision-making," a critical safeguard for real-world deployment safety.

Experiments and Results

Experiments were trained in IsaacGym and evaluated in MuJoCo (Sim2Sim), using the Unitree G1 (29 DoF). The motion dataset contains 4 skills, categorized by switching count into easy (1 switch), medium (2 switches), and hard (3 switches), with 50 trials per category. The SSR failure threshold is an average body position error exceeding 0.5 m.

Boundaries and Limitations

The paper does not explicitly list a limitations section for its own method, but the following can be inferred from factual points: - Data dependency: Skill graph construction relies on the coverage and quality of motion data. If kinematic differences between skills are too large (no similar states), the graph may be disconnected, and switching will still fail. - What was not done: No specific success rates for real-world experiments are mentioned; no quantitative comparison with other hierarchical RL methods (e.g., Hierarchical RL); no specific numbers for computational resources or training time. - Hyperparameter sensitivity: Key hyperparameters such as \(\lambda_c\), \(\lambda_{\mathrm{sw}}\), \(\lambda_{\text{cost}}\), thresholds \(A\), \(B\), and top-\(k\) are not given specific values, requiring manual tuning during reproduction, which may affect performance. - Inference frequency: Not mentioned; insufficient inference frequency could impact real-time performance during hardware deployment.

Engineering Insights

When reproducing or adopting Switch, the following points deserve the most attention: 1. First verify the similarity metric for skill graph construction: The state distance \(d(\cdot)\) is defined in a local coordinate frame (removing global x-y translation and yaw), which is key to ensuring effective cross-skill connections. If your skill data includes actions with large global displacement (e.g., running, jumping), align coordinate frames first; otherwise, similarity calculations will be distorted. 2. Buffer node count is key to smoothness: The number of buffer nodes is determined by the distance between edge endpoints—the larger the distance, the more buffers. If severe jitter occurs during switching, first check whether the buffer node count is sufficient; if switching is too slow, there may be too many buffers. 3. The FGR reward's \(\lambda_c\) needs tuning per skill type: For high-frequency foot-ground contact skills (dance, martial arts), FGR is critical; but for low-frequency contact skills (standing, slow walking), an overly large \(\lambda_c\) may introduce noise. It is recommended to set it in groups by skill type. 4. The RSI modification is not optional: Directly applying standard RSI to augmented trajectories hinders skill transition learning. Only states from the \(n\) steps before a skill transition must be sampled as initial states; otherwise, training may fail to converge. 5. Prefer the NN planner for deployment: Although the graph-search planner is globally optimal, it requires caching \(V^{*}\) and NextHop, incurring greater memory and computational overhead. The NN planner has minimal latency and is suitable for compute-constrained platforms like the onboard Jetson Orin NX. If switching fails, consider switching to the graph-search planner.
