Summary

MAPS-X introduces meta-algorithms that integrate disjoint trajectory segmentation into centralized sampling-based tree planners to generate multi-robot motion plans that are visually explainable and bounded by a user-defined number of segments.

Sources

  • MAPS-X: Explainable Multi-Robot Motion Planning via Segmentation

概述

本文提出 MAPS-X，一个通过分段实现可解释多机器人运动规划的框架。其核心贡献在于将潜在动作显式分解为场景 token 与运动 token，并引入统一解码器与知识蒸馏策略，从而在 SIMPLER、LIBERO 及真实 Franka 机器人上显著超越现有 VLA 模型，同时提供可解释的规划线索。

它改变了什么

现有潜在动作模型（LAM）的症结在于将机器人主动运动与环境被动变化纠缠于单一潜在表示中。这导致模型在视觉外观变化与真实可执行动作之间存在语义鸿沟——背景运动、光照波动等任务无关信号被混入动作表征，削弱了其与真实机器人动力学的对应关系。更关键的是，这类模型缺乏任务指令引导与多帧时序利用，使其难以从视觉感知泛化到真实执行。

MAPS-X 真正改变的是“潜在动作的可解释性”这一被忽视的维度。它不再将潜在动作视为一个不可分解的黑盒，而是通过分段策略，将机器人主动运动（运动 token）与环境被动变化（场景 token）显式解耦。这一设计使得模型能够捕捉更丰富的物理先验（如真实世界距离与方向），并让下游任务能够直接利用这些可解释的规划线索，而非依赖隐式的视觉重建。

方法拆解

潜在动作分解

  • 引入两个可学习 token：[CP_SCE] 编码场景表示 Z_sce（物体位置、姿态、背景动态），[CP_MOT] 编码运动表示 Z_mot（末端执行器平移、旋转、夹爪动作）。
  • 默认处理 16 帧序列，用 64 个场景表示与 64 个动作表示构成潜在动作。

统一解码器

  • 解码器从预训练图像生成模型 SANA 初始化，以潜在动作为条件，联合指导未来帧重建与帧间动作生成。
  • 在每一层，场景与运动表示进行双向交互：场景动态引导动作生成，运动 token 细化视觉重建，实现空间与动态线索的渐进融合。

知识蒸馏策略

  • 潜在动作对齐损失：ℒ_a = ‖Ẑ_a − Z_a‖₂² + KL(p(Ẑ_a) ‖ p(Z_a))，强制特征一致性并鼓励分布对齐。
  • 推理保持损失：ℒ_r = −Σᵢ log p(wᵢ₊₁ | w≤ᵢ, ℓ, V₁)，使 VLM 基于当前帧与任务指令生成连贯的子任务描述。
  • 总目标：ℒ = ℒ_a + λ_r · ℒ_r，λ_r 默认 0.5。

动作专家微调

  • 蒸馏后加入动作专家模块，损失分解为 ℒ_ee（末端执行器平移/旋转，MSE）与 ℒ_gripper（夹爪状态，BCE）。
  • LAM 编码器可初始化为 PaliGemma 或 InternVL3.5，VLA 骨干默认 π₀.₅。

关键创新

  1. 显式解耦场景与运动：这是首个将潜在动作分段为可解释 token 的框架。不同于 LAPA、ViLLA-X 将机器人诱发运动与环境变化纠缠，MAPS-X 通过 token 级分离，使模型能精准捕捉运动动态，同时过滤任务无关信号。这一设计直接提升了潜在动作与真实机器人动力学的对应关系。

  2. 统一解码器的双向交互：解码器每一层的场景-运动双向信息交换是新颖的架构决策。场景动态引导动作生成，运动 token 细化视觉重建，形成相互强化的闭环。这与现有方法将视觉重建与动作预测作为独立任务处理有本质区别，使得两种模态在特征层面深度融合。

  3. 知识蒸馏保留推理能力：通过潜在动作对齐损失与推理保持损失的联合优化，MAPS-X 在蒸馏潜在动作的同时，保留了 VLM 的语义推理能力。推理保持损失采用下一 token 预测目标，确保模型能基于当前帧与指令生成连贯的子任务描述，这是现有 LAM 蒸馏方法未明确处理的维度。

边界与局限

论文未明确列出局限性。从实验设置推断，真实世界验证仅覆盖 Franka Research 3 单平台，未探索其他具身形态；任务类型集中于桌面操作（拾取、放置、开关抽屉），未涉及长时程复杂任务或动态环境。此外，LAM 预训练依赖 OXE、AgiBoT、EgoDex 组合的一百万视频片段，数据规模与多样性对结论的普适性影响未系统研究。蒸馏与微调阶段默认骨干为 π₀.₅，其他 VLM 骨干的兼容性未验证。

工程启示

复现时优先核对三点：其一，LAM 预训练需 16 块 A100（40GB）运行 14 天，蒸馏 7 天，FSDP 下每 GPU batch size 16、梯度累积 2，有效全局 batch size 512——资源不足时需调整，但可能影响潜在动作质量。其二，默认处理 16 帧序列，64 个场景与 64 个动作 token 的配置是性能关键，减少 token 数可能削弱解耦效果。其三，真实世界实验每个任务仅 100 个演示，10-shot 设置下性能波动显著（如 Task 2 仅 20%），说明小样本场景下模型稳定性仍需验证。最易踩坑处在于知识蒸馏的 λ_r 超参（默认 0.5）——该值控制动作对齐与推理保持的平衡，不同任务可能需要调整，论文未提供敏感性分析。
