Summary

Manipulating suspended payloads with humanoid robots is challenging because the robot can only influence an underactuated, oscillatory load through whole-body motion and intermittent contact. Institutions per source list: 佛罗里达大学.

Overview

HOIST proposes a three-stage pipeline (teleoperation imitation, VLA fine-tuning, iterative batch RL refinement) that enables a humanoid robot to manipulate an underactuated suspended load through whole-body motion and intermittent contact. The core contribution is decoupling task adaptation from a fixed whole-body controller, fine-tuning only the high-level VLA policy and a noise-steering module to improve placement accuracy in a sample-efficient manner. In both simulation and real-world platforms, HOIST reduces translational placement error from 22.44 cm to 6.25 cm (simulation) and from 9.28 cm to 6.38 cm (real).

What It Changes

Suspended load manipulation has long been treated as a variant of "grasp-and-place," but the authors clearly identify it as an underactuated pendulum problem: the load continues to oscillate after the robot stops and drifts after contact, making standard imitation learning or end-to-end RL difficult to apply directly. Imitation learning provides safe initial behaviors but cannot optimize final placement accuracy, and errors accumulate during closed-loop execution; RL from scratch is neither safe nor sample-efficient on real humanoid robots. What HOIST truly changes is the boundary of "who learns what"—it does not train joint-level actuation or modify the whole-body controller, but instead compresses task adaptation entirely into the high-level command space (hand targets, navigation commands, base height), letting the policy learn "how to command" rather than "how to move." This division enables RL refinement to significantly improve accuracy with only 30 rollouts, rather than the millions of interactions required by traditional RL.

Method Breakdown

Problem Formulation

Humanoid hoisting is formulated as a task-conditioned, partially observable, closed-loop control problem. The observation is defined as: o_t = {I_ego,rgb_t, D_ego_t, I_side,rgb_t, x_r_t, ℓ, c_nav_{t-1}} It includes onboard RGB, depth, external side-view RGB (capturing the load-target relationship), proprioception, language instructions, and the previous navigation command. No contact force sensing or explicit load state input is assumed.

High-Level Policy Output

The policy predicts command increments for the future H steps: ΔU_t = π_θ(o_t) = (Δu_t, Δu_{t+1}, …, Δu_{t+H-1}) The single-step increment is: Δu_τ = [Δy_head_τ, Δy_L_τ, Δy_R_τ, Δc_nav_τ, Δh_base_τ] During execution, the first increment in the block is applied to update the current command: u_t = u_{t-1} + Δu_t.

Low-Level Execution

a_motor_t = π_wbc(x_r_t, u_t), using a fixed decoupled whole-body controller (GR00T Whole-Body Control), which is not trained or fine-tuned.

Three-Stage Pipeline

  1. Teleoperation Data Collection: A PICO VR headset guides complete hoisting sequences, storing trajectories τ_i = ({o_t, u_demo_t, a_motor_t}_{t=1}^{T_i}, y_i), where y_i is the trajectory-level outcome (placement error and residual motion).
  2. Supervised VLA Fine-Tuning: Based on GR00T N1.6, navigation commands are added as an extra modality to the VLM, and depth images and robot velocity are added to the flow-matching action expert. Only the last four VLM layers, the diffusion transformer action expert, and the new modality encoders are fine-tuned; everything else is frozen.
  3. RL Refinement: The fine-tuned policy is deployed to collect small batches of autonomous rollouts, labeled with a simple weighted reward (translational error + angular error). The initial noise of the flow-matching action expert is recorded, and an actor-critic is trained to predict which noise vector should be used. During RL, the VLA is frozen, and only the noise-steering module is updated, reusing VLM features to avoid repeated encoding.

Key Design Decisions

  • The high-level policy only decides short-horizon task-level motions, while the low-level controller handles balance and joint-level stability—letting the learned policy operate at the command layer.
  • Keeping the low-level motion prior fixed and shifting task adaptation to the high-level VLA and RL—avoiding the unsafety of joint-level exploration.
  • Starting from a teleoperation-fine-tuned policy rather than RL from scratch—avoiding tabula-rasa exploration.
  • Using iterative batch RL rather than additional demonstrations—autonomous rollouts reveal the policy's own biased trajectories, and task-level rewards learn noise corrections.

Key Innovations

  1. Noise-Steering RL (flow-matching-steering RL): Instead of directly updating VLA policy weights, it learns to predict the initial noise vector of the flow-matching action expert. This essentially compresses RL refinement into a low-dimensional "steering" problem, avoiding disruption of learned imitation behaviors while allowing task-level corrections. This is a lightweight alternative to the "RL fine-tuning of large models" paradigm.
  2. Task-Control Decoupling: Task adaptation is entirely placed in the high-level command space, with the low-level whole-body controller fixed. This allows RL to explore only 5-dimensional command increments rather than high-dimensional joint space, improving sample efficiency by several orders of magnitude—effective with just 30 rollouts.
  3. Multimodal Observation Fusion: Navigation commands are injected as an extra modality into the VLM, and depth images are added to the action expert. Ablations show that the combination outperforms either modality alone on the real platform in Δx+Δy (9.28 cm vs 12.06/11.20 cm).

Experiments and Results

Table 1: Placement accuracy with increasing RL rollout counts (simulation)

Method Δx (cm) Δy (cm) Δψ (deg) Δx+Δy (cm)
Human Expert Teleop 4.35 3.00 8.48 7.35
VLA-50 21.56 0.88 3.85 22.44
VLA-50 + 10 RL 15.09 1.83 4.58 16.92
VLA-50 + 20 RL 1.72 0.82 0.29 2.54
VLA-50 + 30 RL 5.16 1.09 2.76 6.25

20 rollouts achieve the best accuracy (2.54 cm), while 30 rollouts slightly degrade (6.25 cm), indicating an optimal rollout count and that over-refinement may overfit to current policy biases.

Table 2: Additional demonstrations vs RL refinement (real platform)

Method Demos RL rollouts Δx (cm) Δy (cm) Δψ (deg) Δx+Δy (cm)
VLA-50 50 0 1.60 7.68 14.5 9.28
VLA-80 80 0 0.54 8.03 27.0 8.57
HOIST 50 30 1.64 4.74 28.9 6.38

HOIST reduces Δx+Δy from 9.28 to 6.38 cm on the real platform, outperforming VLA-80 with 30 additional demonstrations (8.57 cm), but the angular error (28.9°) worsens, indicating that RL refinement primarily optimizes translational accuracy while angular control does not benefit.

Residual Motion Analysis

Compared to pure imitation policies, HOIST reduces IMU gyroscope response by about half and shows higher accelerometer readings—indicating reduced angular motion and more active correction, but both learned policies fall short of human teleoperation, possibly reflecting more frequent closed-loop corrections by humans.

Boundaries and Limitations

  • Low-level controller not adapted: The fixed whole-body controller is not fine-tuned for suspended load interactions, and the policy can only influence execution through limited interfaces (navigation, head, base height, hands), making it unable to explicitly adapt applied forces for different load weights, limiting handling of heavy loads.
  • No extension to load and suspension conditions: Different load weights, rope lengths, and suspension point variations were not tested.
  • No explicit safety constraints: No safety guardrails are present during RL refinement, and extreme cases may produce dangerous behaviors.
  • No study of humanoid-crane joint control: Listed as future work.
  • Angular error not improved: HOIST's Δψ on the real platform is 28.9°, higher than VLA-50 (14.5°) and VLA-80 (27.0°), and RL refinement does not address angular alignment.
  • Sensitivity to optimal rollout count: In simulation, 20 rollouts are best (2.54 cm), while 30 degrade (6.25 cm), indicating overfitting risk in RL refinement that requires monitoring in deployment.
  • Not specified in the paper: Inference frequency, the specific value of the action block horizon H, simulator type, training hyperparameters, and computational resources.

Engineering Insights

  • First verify the low-level controller's interface capabilities: HOIST's effectiveness relies entirely on the fixed whole-body controller's ability to stably track high-level commands. Before reproduction, confirm that your execution stack supports the 5-dimensional command inputs (navigation commands, head pose, base height, dual-hand targets); otherwise, you need to extend it yourself.
  • The RL refinement rollout count is a critical hyperparameter: In simulation, 20 rollouts are best, while 30 degrade. It is recommended to evaluate in increments of 5, monitoring the trade-off between Δx+Δy and Δψ to avoid overfitting to current policy biases.
  • Depth modality provides the largest single gain: Ablations show that depth input reduces Δx+Δy from 12.06 to 9.57 cm, so prioritize ensuring depth camera calibration and synchronization quality. The navigation command alone has limited effect, but the combination is optimal for Δy, so it is recommended to keep it.
  • Angular error is a blind spot: HOIST's Δψ worsens to 28.9° on the real platform. If the task is angle-sensitive, explicitly weight angular error in the reward or add angle-related observations.
  • Implementation essentials for noise-steering RL: Record the initial noise of the flow-matching action expert, train the actor to output a deterministic steering vector (rather than mean-variance sampling), and reuse the frozen policy's VLM features to avoid repeated encoding—this is key to sample efficiency.
  • Most common pitfall: Teleoperation data quality directly determines the VLA's initial behavior. If 50 demonstrations have insufficient coverage, RL refinement may not compensate; it is recommended to cover different load initial positions and oscillation states during teleoperation.
