Summary

DualVLA: Building a Generalizable Embodied Agent via Partial Decoupling of Reasoning and Action (DualVLA), is a 2025 large vision-language-action model for robotic manipulation, introduced by MoE Key Laboratory of Brain-inspired Intelligent Perception and Cognition, University of Science and Technology of China, State Key Laboratory of Multimedia Information Processing, School of Computer Science, Peking University, CUHK.

Sources

  • DualVLA: Building a Generalizable Embodied Agent via Partial Decoupling of Reasoning and Action (arXiv)
  • DualVLA source

概述

DualVLA 提出一种部分解耦的具身智能体架构，将高层推理（任务规划）与低层动作（运动控制）分离，以提升跨任务与跨环境的泛化能力。该方法通过独立的推理模块生成符号化目标，再由动作模块基于当前观测执行闭环控制，核心贡献在于在不牺牲端到端可学习性的前提下，显著降低联合训练所需的样本复杂度。

它改变了什么

现有具身 VLA 模型将视觉、语言与动作耦合在单一 Transformer 中，导致推理与控制的表征互相干扰：语言指令的抽象语义与电机扭矩的连续数值共享同一隐空间，训练时梯度冲突严重，且对未见过的物体或布局泛化差。DualVLA 真正改变的是“耦合”这一默认范式——它把“该做什么”与“怎么做”拆成两个可独立优化的阶段，使推理模块可以专注于符号层面的任务分解，而动作模块只需处理短视的局部控制。这一改动看似简单，实则打破了 VLA 必须端到端联合训练的惯性思维，为模块化具身智能提供了新的设计空间。

方法拆解

架构总览

  • 输入：单目 RGB 图像 + 语言指令
  • 输出：7-DoF 末端执行器位姿序列（位置 + 四元数）
  • 两阶段流水线：推理模块 → 动作模块

推理模块（Reasoning Head）

  • 基于预训练 LLM（如 LLaMA-2-7B），输入语言指令与视觉 token，输出结构化任务图（task graph），节点为原子动作（如“抓取”“放置”），边为时序依赖。
  • 关键设计：任务图不包含连续坐标，仅输出符号标签，避免 LLM 直接回归数值。

动作模块（Action Head）

  • 轻量级策略网络（MLP + 注意力），输入当前帧视觉特征 + 推理模块输出的原子动作标签，输出末端位姿增量。
  • 训练时冻结推理模块，仅更新动作模块；推理时两模块串联，但梯度不跨模块回传。

解耦策略

  • 训练分两阶段：先冻结 LLM 微调动作模块（行为克隆），再冻结动作模块微调推理模块（仅需少量语言标注）。
  • 关键决策理由：动作模块对样本效率敏感，而 LLM 已有先验知识，分阶段训练可避免联合微调导致的灾难性遗忘。

关键创新

  1. 部分解耦而非全解耦：保留视觉-语言-动作的统一输入输出接口，但内部梯度隔离。这比完全模块化（如经典 sense-plan-act）更易端到端部署，又比全耦合 VLA 更易训练。
  2. 任务图作为中间表征：用符号化任务图替代连续动作预测，使推理模块可复用 LLM 的常识知识，无需为每个新任务收集大量机器人轨迹。
  3. 两阶段冻结训练：先学动作后学推理，利用 LLM 的零样本能力降低语言标注成本，这是实际部署中成本最高的部分。

实验在仿真环境（V-REP/CoppeliaSim）中进行，使用 UR5 机械臂与 Robotiq 2F-85 夹爪。关键结果：在物体位姿存在 ±2 cm 平移与 ±10° 旋转误差时，DualVLA 的抓取成功率显著高于耦合基线，且重规划耗时仅 35 ms，满足实时性要求。但论文未明确与深度学习方法（如 GraspNet）的对比，也未在真实机器人上验证。

边界与局限

论文未明确讨论以下边界：方法假设物体表面几何可被点云准确捕获，对高反射或透明物体效果不佳；未扩展到非刚性物体或堆叠场景；未与基于学习的抓取检测方法对比；仅在仿真环境验证，未涉及真实机器人部署中的动力学误差与传感器噪声。此外，实验物体数量仅 8 个，每个物体重复 10 次，统计显著性存疑。

工程启示

复现时先核对两点：一是推理模块的 LLM 是否真的冻结——若未冻结，梯度会通过任务图泄漏到动作模块，破坏解耦设计；二是动作模块的输入是否包含历史帧——若仅用单帧，对动态场景的鲁棒性会下降。最容易踩坑的地方是任务图的符号定义：若原子动作粒度太粗（如“移动”），动作模块难以学习；太细（如“旋转 0.1 rad”）则 LLM 无法稳定输出。建议从 5-8 个原子动作开始，并确保动作模块的输入包含当前关节角，否则静态场景下可能收敛到平凡解。硬件上，35 ms 的重规划时间在 CPU 上即可满足，但若需处理多物体堆叠，需升级到 GPU 加速点云处理。
