## 概述

本文提出 Task Tokens 方法，通过任务编码器将任务目标映射为 token 序列，以灵活适配行为基础模型（Behavior Foundation Models）。作者通过架构消融实验和人类偏好研究，验证了该方法在不同编码器规模、是否拼接当前位姿及是否使用关节条件化下的鲁棒性，并评估了生成动作的类人质量。核心贡献在于提供了一种轻量、模块化的任务适配机制，无需微调基础模型即可适应多种下游任务。

## 它改变了什么

行为基础模型（如机器人操作或运动生成模型）通常在大规模数据上预训练，但下游任务适配往往依赖全量微调或复杂的 prompt 设计，代价高昂且灵活性差。Task Tokens 改变了这一范式：它不修改基础模型权重，而是通过一个可学习的任务编码器将任务描述转换为紧凑的 token 序列，作为条件输入注入模型。这真正改变的是“适配成本”与“任务可扩展性”之间的权衡——下游团队不再需要为每个新任务重新训练或存储模型副本，只需训练一个轻量编码器（MLP 规模仅 [256,256] 或 [512,512,512]），即可在推理时动态切换任务。这种设计将任务适配从“模型级”降维到“输入级”，是行为模型工程化部署的关键一步。

## 方法拆解

### 任务编码器架构
- 输入：任务目标（如方向、目标位置）与可选当前位姿（头部/骨盆位置）拼接。
- 编码器：MLP，两种配置——`[256,256]`（默认）与 `[512,512,512]`（Bigger MLP）。
- 输出：Task Tokens，作为条件 token 序列注入行为基础模型的 transformer 层。

### 关键设计决策
- **关节条件化（Joint Conditioning, J.C.）**：在 Direction、Steering、Reach 任务中，将关节状态与任务 token 一起输入。消融显示，J.C. 能显著提升性能稳定性，尤其在小编码器 + 无当前位姿组合下（Steering Success 从 84.28% 提升至 86.88%）。
- **当前位姿拼接（Using Current Pose）**：将 head/pelvis 位置与任务目标拼接。消融显示，该操作在无 J.C. 时反而降低性能（如 Bigger MLP=False 时从 84.28% 降至 66.31%），说明冗余的位姿信息可能干扰任务编码。
- **编码器规模**：`[512,512,512]` 在无 J.C. 时略优于 `[256,256]`（83.30% vs 84.28% 并不显著），但在有 J.C. 时两者几乎持平（87.58% vs 86.88%），表明任务编码器并非越大越好，J.C. 提供了更关键的条件信号。

### 人类研究协议
- 每问题展示 3 个并排视频（随机采样序列），参与者选择最像人类的动作。
- 算法顺序随机打乱，视频拍摄角度相似，Task Tokens 确保每次出现。
- 胜率公式：`winning percentage^A_env = (# Task Tokens chosen) / (# Task Tokens chosen + # Algorithm A chosen)`。

## 关键创新

1. **任务适配的“输入级”抽象**：将任务编码为 token 序列而非修改模型权重，使得一个基础模型可同时服务多个任务，且任务切换成本趋近于零。这与 prompt tuning 类似，但针对行为序列生成做了专门设计（如与关节条件化结合）。
2. **对冗余条件的鲁棒性分析**：通过消融明确“当前位姿拼接”在无 J.C. 时是有害的（性能下降 18 个百分点），这为实践者提供了明确的输入设计准则——不要盲目堆叠条件特征。
3. **人类偏好验证的严谨性**：96 人参与、3 份表单、每问题随机打乱顺序，胜率计算排除了自身对比偏差，为“类人”质量提供了可复现的评估协议。

## 工程启示

- **优先启用 Joint Conditioning**：消融数据强烈表明，J.C. 是性能稳定性的关键，复现时应默认开启，尤其在 Direction、Steering、Reach 类任务中。
- **不要盲目拼接当前位姿**：无 J.C. 时拼接 head/pelvis 位置会显著降低性能（66.31% vs 84.28%），建议先做消融再决定是否引入该特征。
- **编码器规模选择**：`[256,256]` 在有 J.C. 时与 `[512,512,512]` 几乎持平（86.88% vs 87.58%），优先选小模型以降低过拟合风险和推理开销。
- **人类评估协议可复用**：96 人、3 表单、随机打乱顺序的设计值得借鉴，但需注意视频采样随机性可能引入方差，建议固定随机种子并增加重复次数。
- **最易踩坑点**：当前位姿拼接在无 J.C. 时是“性能杀手”，若下游任务本身包含位姿信息，务必验证是否与任务 token 冗余。

## Overview

This paper proposes the Task Tokens method, which maps task objectives into token sequences via a task encoder to flexibly adapt Behavior Foundation Models. Through architectural ablation experiments and human preference studies, the authors validate the method's robustness across different encoder scales, with or without current pose concatenation, and with or without joint conditioning, while also evaluating the human-likeness quality of generated actions. The core contribution is a lightweight, modular task adaptation mechanism that adapts to multiple downstream tasks without fine-tuning the foundation model.

## What It Changes

Behavior Foundation Models (such as robot manipulation or motion generation models) are typically pretrained on large-scale data, but downstream task adaptation often relies on full fine-tuning or complex prompt design, which is costly and inflexible. Task Tokens changes this paradigm: instead of modifying foundation model weights, it uses a learnable task encoder to convert task descriptions into compact token sequences that are injected as conditioning inputs. What truly changes is the trade-off between "adaptation cost" and "task scalability"—downstream teams no longer need to retrain or store model copies for each new task; they only need to train a lightweight encoder (MLP scale of just [256,256] or [512,512,512]) to dynamically switch tasks at inference time. This design reduces task adaptation from the "model level" to the "input level," representing a key step toward engineering deployment of behavior models.

## Method Breakdown

### Task Encoder Architecture
- Input: task objective (e.g., direction, target position) concatenated with optional current pose (head/pelvis position).
- Encoder: MLP with two configurations—`[256,256]` (default) and `[512,512,512]` (Bigger MLP).
- Output: Task Tokens, injected as conditioning token sequences into the transformer layers of the behavior foundation model.

### Key Design Decisions
- **Joint Conditioning (J.C.)**: In Direction, Steering, and Reach tasks, joint states are input together with task tokens. Ablations show that J.C. significantly improves performance stability, especially with small encoders + no current pose (Steering Success increases from 84.28% to 86.88%).
- **Using Current Pose**: Head/pelvis positions are concatenated with the task objective. Ablations show that this operation degrades performance without J.C. (e.g., from 84.28% to 66.31% when Bigger MLP=False), suggesting that redundant pose information may interfere with task encoding.
- **Encoder Scale**: `[512,512,512]` slightly outperforms `[256,256]` without J.C. (83.30% vs 84.28%, not significant), but the two are nearly identical with J.C. (87.58% vs 86.88%), indicating that larger task encoders are not necessarily better and that J.C. provides the more critical conditioning signal.

### Human Study Protocol
- Each question displays 3 side-by-side videos (randomly sampled sequences), and participants choose the most human-like action.
- Algorithm order is randomly shuffled, video capture angles are similar, and Task Tokens are guaranteed to appear each time.
- Win rate formula: `winning percentage^A_env = (# Task Tokens chosen) / (# Task Tokens chosen + # Algorithm A chosen)`.

## Key Innovations

1. **"Input-level" abstraction for task adaptation**: Encoding tasks as token sequences rather than modifying model weights allows a single foundation model to serve multiple tasks simultaneously, with near-zero task-switching cost. This is similar to prompt tuning but specifically designed for behavior sequence generation (e.g., combined with joint conditioning).
2. **Robustness analysis of redundant conditions**: Ablations clearly show that "current pose concatenation" is harmful without J.C. (performance drops by 18 percentage points), providing practitioners with clear input design guidelines—do not blindly stack conditioning features.
3. **Rigor of human preference validation**: 96 participants, 3 forms, randomly shuffled order per question, and win rate calculation that excludes self-comparison bias provide a reproducible evaluation protocol for "human-likeness" quality.

## Boundaries and Limitations

The paper does not explicitly mention the following limitations:
- Specific win rate values for Task Tokens in the human study are not reported; only the experimental protocol is described, making it impossible to quantify its relative advantage.
- Token conflicts or attention interference during simultaneous multi-task inference are not addressed.
- The performance ceiling for encoder scales beyond `[512,512,512]` is not tested, nor is the relationship between training data volume and encoder convergence explained.
- Ablations are only reported on the Steering task; results for Direction and Reach tasks are not provided, raising questions about generalizability.

## Engineering Insights

- **Prioritize enabling Joint Conditioning**: Ablation data strongly indicates that J.C. is key to performance stability; it should be enabled by default when reproducing, especially for Direction, Steering, and Reach-type tasks.
- **Do not blindly concatenate current pose**: Without J.C., concatenating head/pelvis positions significantly degrades performance (66.31% vs 84.28%); it is recommended to run ablations before deciding whether to introduce this feature.
- **Encoder scale selection**: `[256,256]` is nearly on par with `[512,512,512]` when J.C. is enabled (86.88% vs 87.58%); prioritize the smaller model to reduce overfitting risk and inference overhead.
- **Human evaluation protocol is reusable**: The design with 96 participants, 3 forms, and randomly shuffled order is worth adopting, but note that random video sampling may introduce variance; it is recommended to fix random seeds and increase repetition counts.
- **Most common pitfall**: Current pose concatenation is a "performance killer" without J.C.; if the downstream task inherently includes pose information, be sure to verify whether it is redundant with task tokens.

## 그것이 바꾸는 것

행동 기반 모델(예: 로봇 조작 또는 운동 생성 모델)은 일반적으로 대규모 데이터로 사전 학습되지만, 하위 작업 적응은 종종 전체 미세 조정이나 복잡한 프롬프트 설계에 의존하여 비용이 높고 유연성이 떨어집니다. Task Tokens는 이러한 패러다임을 바꿉니다: 기본 모델 가중치를 수정하지 않고, 학습 가능한 작업 인코더를 통해 작업 설명을 컴팩트한 토큰 시퀀스로 변환하여 조건 입력으로 모델에 주입합니다. 이것이 실제로 바꾸는 것은 "적응 비용"과 "작업 확장성" 사이의 균형입니다—하위 팀은 더 이상 각 새 작업에 대해 모델 복사본을 재학습하거나 저장할 필요 없이, 경량 인코더(MLP 규모가 [256,256] 또는 [512,512,512]에 불과)만 학습하면 추론 시 동적으로 작업을 전환할 수 있습니다. 이 설계는 작업 적응을 "모델 수준"에서 "입력 수준"으로 축소하며, 이는 행동 모델의 엔지니어링 배포에 있어 핵심 단계입니다.

## 방법 분해

### 작업 인코더 아키텍처
- 입력: 작업 목표(예: 방향, 목표 위치)와 선택적 현재 자세(머리/골반 위치)를 연결.
- 인코더: MLP, 두 가지 구성—`[256,256]`(기본값) 및 `[512,512,512]`(Bigger MLP).
- 출력: Task Tokens, 조건 토큰 시퀀스로 행동 기반 모델의 transformer 레이어에 주입.

### 핵심 설계 결정
- **관절 조건화(Joint Conditioning, J.C.)**: Direction, Steering, Reach 작업에서 관절 상태를 작업 토큰과 함께 입력. 절제 실험은 J.C.가 특히 소형 인코더 + 현재 자세 없음 조합에서 성능 안정성을 크게 향상시킴을 보여줍니다(Steering Success가 84.28%에서 86.88%로 향상).
- **현재 자세 연결(Using Current Pose)**: head/pelvis 위치를 작업 목표와 연결. 절제 실험은 이 작업이 J.C.가 없을 때 오히려 성능을 저하시킴을 보여줍니다(예: Bigger MLP=False일 때 84.28%에서 66.31%로 감소). 이는 중복된 자세 정보가 작업 인코딩을 방해할 수 있음을 시사합니다.
- **인코더 규모**: `[512,512,512]`는 J.C.가 없을 때 `[256,256]`보다 약간 우수하지만(83.30% vs 84.28%는 유의미하지 않음), J.C.가 있을 때는 거의 동일합니다(87.58% vs 86.88%). 이는 작업 인코더가 클수록 좋은 것이 아니며, J.C.가 더 중요한 조건 신호를 제공함을 나타냅니다.

### 인간 연구 프로토콜
- 각 질문마다 3개의 나란히 배치된 비디오(무작위 샘플링 시퀀스)를 제시하고, 참가자는 가장 인간다운 행동을 선택.
- 알고리즘 순서는 무작위로 섞이고, 비디오 촬영 각도는 유사하며, Task Tokens는 항상 등장하도록 보장.
- 승률 공식: `winning percentage^A_env = (# Task Tokens chosen) / (# Task Tokens chosen + # Algorithm A chosen)`.

## 핵심 혁신

1. **작업 적응의 "입력 수준" 추상화**: 작업을 토큰 시퀀스로 인코딩하고 모델 가중치를 수정하지 않음으로써, 하나의 기본 모델이 동시에 여러 작업을 서비스할 수 있고 작업 전환 비용이 거의 0에 가깝습니다. 이는 prompt tuning과 유사하지만, 행동 시퀀스 생성을 위해 특별히 설계되었습니다(예: 관절 조건화와 결합).
2. **중복 조건에 대한 견고성 분석**: 절제 실험을 통해 "현재 자세 연결"이 J.C.가 없을 때 유해함(성능 18% 포인트 감소)을 명확히 하여, 실무자에게 명확한 입력 설계 지침을 제공합니다—조건 특징을 맹목적으로 쌓지 말 것.
3. **인간 선호도 검증의 엄격성**: 96명 참여, 3개 양식, 각 질문마다 무작위 순서, 승률 계산에서 자기 비교 편향을 배제하여 "인간 유사성" 품질에 대한 재현 가능한 평가 프로토콜을 제공합니다.

## 실험 및 결과

### 표 4: Task Encoder 아키텍처 절제(Steering Success Rate %)

| 구성 | Bigger MLP | Using Current Pose | J.C. | Success Rate (%) |
|---|---|---|---|---|
| Task Tokens + J.C. | True | True | 예 | **87.77 ± 7.14** |
| Task Tokens + J.C. | True | False | 예 | **87.58 ± 7.02** |
| Task Tokens + J.C. | False | False | 예 | **86.88 ± 6.65** |
| Task Tokens | False | False | 아니요 | 84.28 ± 7.72 |
| Task Tokens | True | False | 아니요 | 83.30 ± 10.06 |
| Task Tokens + J.C. | False | True | 예 | 79.47 ± 4.71 |
| Task Tokens | True | True | 아니요 | 78.59 ± 8.93 |
| Task Tokens | False | True | 아니요 | 66.31 ± 13.11 |

**핵심 해석**:
- J.C.를 사용할 때, "소형 인코더 + 현재 자세"를 제외한 모든 구성의 성공률이 >86%로, J.C.가 성능 안정성의 주요 원천임을 나타냅니다.
- J.C.를 사용하지 않을 때, "현재 자세 연결"은 크게 유해하며(66.31% vs 84.28%), 분산도 증가합니다(±13.11). 이는 중복 입력이 노이즈를 유발함을 시사합니다.
- 인간 연구: 96명 참여, 각 양식 40문항, Task Tokens 승률은 사실 요점에 구체적인 수치가 제공되지 않았지만, 실험 설계는 각 알고리즘과의 공정한 비교를 보장했습니다.

## 경계 및 한계

논문은 다음 한계를 명시적으로 언급하지 않았습니다:
- 인간 연구에서 Task Tokens의 구체적인 승률 수치를 보고하지 않고, 실험 프로토콜만 설명하여 상대적 우위를 정량화할 수 없습니다.
- 다중 작업 동시 추론 시 토큰 충돌 또는 어텐션 간섭 문제를 다루지 않았습니다.
- `[512,512,512]`를 초과하는 인코더 규모의 성능 상한을 테스트하지 않았고, 학습 데이터 양과 인코더 수렴 간의 관계도 설명하지 않았습니다.
- 절제 실험은 Steering 작업에서만 보고되었으며, Direction 및 Reach 작업의 결과는 제공되지 않아 일반화 가능성에 의문이 있습니다.

## 엔지니어링 시사점

- **Joint Conditioning 우선 활성화**: 절제 데이터는 J.C.가 성능 안정성의 핵심임을 강력히 시사하므로, 재현 시 기본적으로 활성화해야 합니다. 특히 Direction, Steering, Reach 유형의 작업에서 그렇습니다.
- **현재 자세를 맹목적으로 연결하지 말 것**: J.C.가 없을 때 head/pelvis 위치를 연결하면 성능이 크게 저하됩니다(66.31% vs 84.28%). 이 특징을 도입하기 전에 먼저 절제 실험을 수행할 것을 권장합니다.
- **인코더 규모 선택**: `[256,256]`은 J.C.가 있을 때 `[512,512,512]`와 거의 동일합니다(86.88% vs 87.58%). 과적합 위험과 추론 오버헤드를 줄이기 위해 작은 모델을 우선 선택하십시오.
- **인간 평가 프로토콜 재사용 가능**: 96명, 3개 양식, 무작위 순서 설계는 참고할 가치가 있지만, 비디오 샘플링 무작위성이 분산을 유발할 수 있으므로 무작위 시드를 고정하고 반복 횟수를 늘리는 것이 좋습니다.
- **가장 쉽게 빠지는 함정**: 현재 자세 연결은 J.C.가 없을 때 "성능 킬러"입니다. 하위 작업 자체에 자세 정보가 포함된 경우 작업 토큰과 중복되는지 반드시 검증하십시오.
