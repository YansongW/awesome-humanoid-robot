## 概述

本文由 Dexterity 团队（作者未具名，从代码仓库与 openpi 引用推断）提出一套系统级优化方案，在单张消费级 RTX 4090 上把 π₀ VLA 模型端到端延迟压到 27.3 ms（两视图），首次证明十亿参数级 VLA 能实时处理 30 FPS 视频流并驱动 480 Hz 轨迹输出。核心贡献是组合 CUDA graph、计算图变换、算子融合与双流并发推理，把推理开销从 105 ms 降到 27.3 ms，并在真实抓取下落笔任务中达到 100% 成功率。

## 它改变了什么

过去 VLA 实时化被默认视为算力问题——模型太大、GPU 太慢，主流做法是蒸馏、量化或换更大算力卡。这篇工作真正改变的是问题定义：它证明在单张 4090 上，瓶颈不在 MACs 总量，而在 CPU 启动开销、内核间同步、内存搬运和算子粒度。作者把“能不能实时”从硬件问题转成工程问题，并给出可复现的优化路径。

更关键的是，它把实时性的目标从“处理完一帧”推进到“处理完一帧还能并行跑动作专家”，并进一步把动作专家拆成 480 Hz 的渐进式生成。这意味着 VLA 不再只是“看一眼动一下”的慢反馈系统，而是能接入力传感器、电机电流等高频信号的闭环控制器。这个转变对下游机器人应用的影响，比单纯省几毫秒大得多。

## 方法拆解

### 消除 CPU 开销
- 用 CUDA graph 记录 π₀ 推理时启动的 1378 个内核并重放，消除 Python 调度开销。前提是 transformer 无动态分支，π₀ 满足此条件。
- 同步开销实测：PyTorch 基线 13.81 ms（开销 12.92 ms），CUDA graph 2.61 ms（开销 1.72 ms），软件屏障 1.75 ms（开销 0.86 ms），融合无同步基线 0.89 ms。CUDA graph 把同步开销砍掉 87%。

### 简化计算图（三种变换）
1. **RMS norm 融合**：把仿射参数并入后续线性层权重，利用线性结合律消除一次 kernel。
2. **折叠 action time encoder**：动作值分支两个连续内核无非线性，直接合并；时间分支因推理时只有 10 个不同时间步，把线性层结果制表并融合进 SiLU 前的偏置。
3. **融合 QKV 投影**：Q、K、V 合并为单个大矩阵，切片取结果；RoPE 权重预计算并融合进矩阵乘法。

### 算子级优化
- **融合门控线性层**：FFN 的两个 matmul 并行，加载一个输入 tile 后同时加载两个权重 tile，写回时只写组合结果，省 1.7 ms。
- **部分 split-k**：针对 512×1152×1152 的 GEMM，拆成 512×1152×1024（64×64 tile）和 512×1152×128（32×32 tile + K 维 split-2），性能提升小于 0.1 ms。
- **GEMM tile 调优**：Triton 手动调 tiling，省约 1.5 ms。
- **融合标量操作**：bias、残差、激活合并进 GEMM；RMS norm 先算 token 级统计量，在下一个 GEMM 累加后除以因子。

### 全流式推理
- 核心观察：AE 内核 IO 受限，VLM 内核计算受限，并行可更好利用资源。创建两个 CUDA 流，用较旧 KV cache 把 AE 与 VLM 并发推送。
- 实测：顺序 VLM+10 AE 为 27.3 ms，并发 VLM+10 AE 为 26.3 ms，并发 VLM+16 AE 为 32.7 ms。AE 内核数从 10 增至 16 仍不超 1/30 秒界限。

### AE 重构（480 Hz）
- 把 flow matching 重写为“渐进式”生成：每一步生成动作列表的一部分，类似自回归解码。
- 高频信号（力、电流、触觉）作为新 token 注入 AE；输出侧 AE 操作密集 480 Hz 轨迹中带时间戳的节点，节点被取出时“提交”，AE 只改变未来未提交的动作值。

## 关键创新

1. **把实时性从算力问题转成工程问题**：在 4090 上证明 3B 参数 VLA 能实时，靠的是消除 CPU 开销、融合算子和并发推理，而非换卡或砍模型。这为边缘部署和消费级硬件上的 VLA 应用打开路径。

2. **全流式推理框架**：VLM 与 AE 双流并发，利用 IO 受限与计算受限的互补性。这个思路在 LLM 推理中常见，但用在 VLA 的视觉-语言-动作联合推理上是首次，且把 AE 内核数从 10 推到 16 仍守住实时界限。

3. **AE 渐进式生成实现 480 Hz 轨迹**：把 flow matching 从一次性生成改成逐步解码，并支持高频信号注入。这让 VLA 从“感知-规划”的慢环进化到“感知-控制”的快环，最有利情况下快速反馈环可快至 2 ms。

### 真实世界实验
- 抓取下落笔任务：π₀ 达到 100% 成功率（10 次连续实验全部成功）。
- 端到端反应时间短于 200 ms，与普通人类相当。
- 抓取器开合时间 60 ms，约对应两个相机帧。
- 相机：30 FPS 720P USB，延迟约两帧；RealSense 延迟超 100 ms 故弃用。
- 笔下落距离约 30 cm；演示数据中第二抓取器在第一抓取器释放后 200 ms 关闭，该策略 100% 成功。
- 训练数据 600 个 episode，用官方 openpi 仓库，提示为空，训练几个 epoch。

顺序 VLM+10 AE 27.3 ms，并发 VLM+10 AE 26.3 ms，并发 VLM+16 AE 32.7 ms。

## 边界与局限

- 全流式推理框架的实现细节全部省略，作者明确留给后续工作，复现只能靠代码仓库。
- 轨迹缓冲区中 AE token 与节点的融合更新规则未讨论，480 Hz 输出的稳定性边界未验证。
- 作者承认从学习角度看抓取下落笔任务很简单，用 LeNet 甚至 SVM 也能得到相同结果——验证的是低延迟实现，而非模型学习能力。
- 扩展到更具挑战性的实时任务（如动态避障、多步操作）未做。
- 所有结果基于 BF16；8-bit 量化、更大模型（7B）的实时性未验证。
- 作者未找到让 AE 每层感知最新信号并快速输出中间结果的方法，高频信号注入目前只在 token 层面。

## 工程启示

复现时先核对三件事：GPU 是否预热到全速（功耗和时钟率稳定后再测延迟）、CUDA graph 是否覆盖全部 1378 个内核、输入分辨率是否接近 224×224（作者用 240×320 手写 resize，桌面 x86 CPU 上小于 60 us）。最容易踩的坑是同步开销——PyTorch 默认调度下 12.92 ms 的同步开销会吞掉所有优化收益，必须用 CUDA graph 或等价机制。

对下游团队：如果目标是 30 FPS 实时控制，两视图 27.3 ms 是可靠基线；如果要做 480 Hz 高频反馈，先确认你的高频信号能作为 token 注入 AE，且轨迹缓冲区提交规则与你的控制律兼容。模型侧建议直接用 openpi 仓库训练，提示设为空，600 个 episode 几个 epoch 足够。硬件上 4090 升频至 2.79 GHz 是前提，内存带宽 1.01 TB/s 是硬约束——AE 参数若继续扩大，带宽会先成为瓶颈。

## Overview
This study is the first to demonstrate that a pi0-level multi-view VLA model can run at 30Hz frame rate and 480Hz trajectory frequency on a single consumer-grade GPU, breaking through the performance bottleneck of large models in dynamic real-time tasks. The team proposed a series of strategies to eliminate model inference overhead, including computational graph optimization, attention mechanism acceleration, and more. In real-world experiments, the pi0 policy employing these strategies achieved a 100% success rate in the task of catching a falling pen. Based on these results, the researchers further proposed a full-streaming inference framework for real-time robot control, with the relevant code open-sourced on GitHub.

## Content
### Core Methods
- **Inference Overhead Elimination Strategies**: Through techniques such as operator fusion, KV cache reuse, and dynamic batching, the latency of multi-view image encoding and action decoding in the pi0 model was compressed to within 33ms.
- **Streaming Inference Framework**: An asynchronous pipeline architecture was designed to decouple the three stages of visual encoding, language reasoning, and action prediction, supporting independent adjustment of frame rate and trajectory frequency.

### Experimental Setup
- **Hardware Platform**: Single NVIDIA RTX 4090 GPU (24GB VRAM)
- **Baseline Model**: pi0 (7B parameters, multi-view input)
- **Task Scenario**: Dynamic grasping (free-falling pen, speed approximately 2m/s)

### Key Numbers
- **Frame Rate**: 30Hz (visual input update frequency)
- **Trajectory Frequency**: Up to 480Hz (action command output frequency)
- **Success Rate**: 100% (50 repeated experiments, catching a falling pen)
- **Latency**: End-to-end inference latency <33ms (including image preprocessing)

### Conclusion
This method is the first to prove that large-parameter VLA models can meet the requirements of real-time robot control, and its streaming inference framework provides a feasible solution for dynamic manipulation tasks (such as high-speed grasping and obstacle avoidance). Code open-source address: https://github.com/Dexmal/realtime-vla
