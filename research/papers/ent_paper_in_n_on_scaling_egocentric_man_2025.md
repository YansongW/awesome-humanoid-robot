## 概述

本文提出 In-N-On 框架，通过结合大规模野外人类操作视频与目标任务数据，提升服务机器人从自然语言指令生成操作程序的能力。系统由 CodeBotler（LLM 驱动的程序生成器）与 RoboEval（基于时序逻辑的轨迹评估基准）组成，并引入拒绝采样机制减少执行错误。核心贡献在于将评估从输入-输出正确性转向执行轨迹的时序属性验证，并系统分类 LLM 生成机器人程序的失败模式。

## 它改变了什么

现有代码补全基准只处理简单函数或低级技能，用输入-输出单元测试衡量程序正确性。但服务机器人任务（如“检查多少会议室没有标记”）的正确性取决于执行轨迹是否访问了所有会议室并检查标记，而非最终答案。自然语言措辞的微小变化会导致生成程序正确性显著波动，这暴露了当前评估范式的根本缺陷——它无法捕捉程序在执行过程中的语义正确性。

本文真正改变的是评估范式：从“程序是否产出正确结果”转向“执行轨迹是否满足任务规范”。这迫使 LLM 生成的程序不仅要语法正确，还要在符号模拟器中产生符合时序逻辑属性的行为序列。同时，通过多提示变体测试鲁棒性，将“措辞敏感性”从噪声变为可量化的评估维度。这种转变让机器人程序生成从“代码补全”升级为“任务规划验证”，为部署真实服务机器人提供了更可靠的保障。

## 方法拆解

### 总体架构
两阶段流水线：CodeBotler 生成程序，RoboEval 验证轨迹。

### CodeBotler 程序生成
- 使用 Python 嵌入式领域特定语言（eDSL）抽象机器人技能，如导航、抓取、检查。
- 通过 ROS Actions 提供机器人无关绑定，支持不同硬件平台。
- 给定少量示例（few-shot examples），LLM 将自然语言任务描述转换为 eDSL 程序。
- 生成程序由轻量级解释器在真实机器人上执行，与机器人特定技能交互。

### RoboEval 轨迹验证
- 在符号模拟器中执行生成程序，从不同初始世界状态生成多个程序轨迹。
- 为每个任务和初始状态定义时序逻辑属性，检查轨迹是否满足这些属性。
- 每个任务包含多个提示变体，测试程序生成的鲁棒性。

### 拒绝采样机制
基于初步发现，加入简单拒绝采样程序：对生成程序进行多次采样，筛选出通过时序检查的程序执行。该机制能立即改善机器人执行错误，无需额外训练。

### 关键设计决策
- 选择 eDSL 而非自然语言直接控制：提供结构化先验，减少 LLM 自由生成带来的语法错误。
- 符号模拟器而非真实环境验证：允许快速枚举多种初始状态，覆盖更广的场景分布。
- 时序逻辑而非最终状态检查：能捕捉任务执行过程中的顺序依赖和条件分支。

## 关键创新

1. **轨迹级时序验证**：首次将时序逻辑属性引入 LLM 生成机器人程序的评估。相比输入-输出测试，能捕捉“先访问所有会议室再得出结论”这类顺序约束，这是服务机器人任务的核心要求。该设计让评估从“结果正确”升级为“过程正确”。

2. **提示变体鲁棒性测试**：通过同一任务的多提示变体，量化 LLM 对措辞变化的敏感性。这暴露了 LLM 在自然语言理解上的脆弱性，为后续提示工程和模型改进提供了可操作的度量标准。

3. **失败模式分类体系**：系统分析 LLM 生成程序的失败类型，包括 Python 运行时错误、不可行机器人动作、未满足任务要求。该分类学为开发者提供了调试指南，能针对性改进 eDSL 设计或提示模板。

## 实验与结果

论文评估了多个最先进 LLM 在 RoboEval 基准上的表现，但提供的片段未包含具体实验数字。作者进行了全面的失败模式分析，产生了突出 LLM 常见陷阱的分类体系。拒绝采样机制被验证能立即改善机器人执行错误。

| 评估维度 | 结果 |
|---|---|
| 具体成功率 | 论文未明确 |
| 失败模式分类 | 已建立分类体系 |

结果含义：尽管 LLM 生成程序能力令人印象深刻，但仍易受多种失败影响。拒绝采样的有效性表明，通过简单的验证-重采样循环，可以在不增加模型复杂度的情况下显著提升可靠性。

## 边界与局限

论文未明确列出具体局限，但暗示 LLM 生成程序存在多种失败模式需进一步研究。作者未在提供的片段中讨论以下方面：多步长任务（超过 5 个关键帧）的验证、动态物体或非刚性物体的处理、低光照或遮挡场景下的性能、真实机器人长期部署测试。此外，方法依赖预训练 VLM 的常识推理，在领域偏移（如工业零件）时可能需要微调。论文未明确说明训练数据量、推理频率、硬件平台等复现细节。

## 工程启示

复现时先核对 eDSL 的技能抽象粒度——过粗会导致程序无法表达细粒度操作，过细则增加 LLM 生成难度。时序逻辑属性的定义是评估质量的关键，需确保属性覆盖任务的所有关键顺序约束，否则会漏掉错误轨迹。拒绝采样机制实现简单但效果显著，建议在部署前先实现基础版本，再逐步优化采样策略。

最容易踩坑的地方是提示变体的设计：变体差异过小无法测试鲁棒性，差异过大则可能引入歧义。建议从任务描述的关键名词、动词、顺序词三个维度系统生成变体。另外，符号模拟器的 fidelity 直接影响评估可信度——如果模拟器无法准确反映真实机器人动力学，通过验证的程序仍可能在真实环境失败。建议在模拟器中加入传感器噪声和执行不确定性，使评估更接近真实部署条件。

## 개요
이 연구는 먼저 인간의 1인칭 비디오 데이터의 이질성을 체계적으로 분석하여, 이를 두 가지 유형인 in-the-wild(야생 데이터)와 on-task(작업 데이터)로 구분하고, 확장 가능한 데이터 수집 및 사용 방안을 제시합니다. 이를 바탕으로 팀은 1,000시간 이상의 다양한 야생 1인칭 데이터와 20시간 이상의 목표 조작 작업에 직접 정렬된 작업 데이터를 포함하는 PHSD 데이터셋을 구축했습니다. 이 데이터셋을 활용하여 대규모 언어 조건 흐름 매칭 정책인 Human0을 훈련시키고, 도메인 적응 기술을 통해 인간과 휴머노이드 로봇 간의 차이를 줄였습니다. 실험 결과, Human0은 인간 데이터에서 명령 수행, 소수 샷 학습, 작업 데이터를 활용한 견고성 향상 등의 새로운 특성을 구현했습니다.

## 핵심 내용
### 방법
- 인간의 1인칭 비디오 데이터를 두 가지 유형으로 분류: **in-the-wild**(야생 데이터, 일상의 다양한 시나리오 포함) 및 **on-task**(작업 데이터, 목표 조작 작업에 직접 정렬).
- 확장 가능한 데이터 수집 및 사용 방안을 제시하고, 훈련 중 두 데이터 유형의 서로 다른 역할을 체계적으로 분석.

### 데이터셋
- **PHSD** 데이터셋 구축, 포함 내용:
  - **1,000시간 이상**의 다양한 in-the-wild 1인칭 데이터.
  - **20시간 이상**의 on-task 데이터, 목표 조작 작업에 직접 정렬.

### 모델 아키텍처
- **Human0** 훈련, 대규모 언어 조건 흐름 매칭 정책(language-conditioned flow matching policy).
- **도메인 적응** 기술 채택, 인간과 휴머노이드 로봇 간의 데이터 분포 차이 최소화.

### 실험 설정 및 주요 결과
- **명령 수행**: 인간 데이터에서만 학습하여 Human0이 언어 명령을 이해하고 실행할 수 있음.
- **소수 샷 학습**: 소량의 on-task 데이터를 활용하여 새로운 작업에 빠르게 적응.
- **견고성 향상**: on-task 데이터가 실제 환경에서 정책의 안정성을 크게 강화.
