## 概述

OneTwoVLA 是一个面向机器人操作任务的统一视觉-语言-动作模型，其核心设计是让模型在推理与动作两种模式间自适应切换，从而在长时程任务中显式输出推理内容、在动作执行时保持高效。该工作基于 π₀ 架构，通过引入 [BOR]/[BOA] 标记、参考图像输入、合成数据增强以及交互澄清训练，在真实 Franka 与 ARX 平台上验证了推理-动作一致性、多模态动作生成能力与部署效率。

## 它改变了什么

现有 VLA 模型（如 π₀）在真实操作中面临一个根本矛盾：要么只输出动作，缺乏对任务语义的显式推理，导致在长时程任务中无法进行规划调整或交互澄清；要么引入推理但推理过程与动作生成耦合过紧，导致部署时计算开销不可控。OneTwoVLA 真正改变的是将“推理”从动作生成的隐式伴随状态中剥离出来，变成一种可显式触发、可独立计时的模式。这意味着模型不再被迫在每个控制周期都进行深度推理，而是可以在关键时刻（如任务切换、指令模糊、错误恢复）才进入推理模式，其余时间以纯动作模式运行，从而在认知能力与实时性之间取得工程上可接受的平衡。

另一个重要改变在于数据层面。作者没有只依赖真实演示，而是用 Gemini 2.5 Pro 生成了 16,000 张合成图像，其中 6,000 张用于视觉接地、10,000 张用于长时程规划，并施加鱼眼畸变与合成夹爪增强。这实际上是把“推理能力”从视觉-语言预训练模型中蒸馏到机器人策略里的尝试，使得模型在未见物体上仍能保持一定泛化，尽管实验显示这种泛化仍然脆弱。

## 方法拆解

### 双模式架构
模型基于 π₀ 构建，输入为当前图像 `I_t`、参考图像 `I_ref`（对应最新推理内容时的观测）以及本体感觉状态（当前、0.05 秒前、0.25 秒前三个时刻）。输出侧引入两个特殊标记：
- `[BOR]`：开始推理，模型输出更新后的推理内容 `R̂`
- `[BOA]`：开始动作，模型输出动作序列

### 数据分段训练
演示数据被分为两类区间：
- **推理区间**：模型学习预测 `[BOR]` → 更新推理 → `[BOA]` → 动作，同时学习在推理未及时更新时基于旧推理预测动作
- **动作区间**：模型学习预测 `[BOA]` → 动作，并可选地基于过时推理预测 `[BOR]` 以缓解决策标记预测的类别不平衡

### 部署时序集成
动作模式下，策略每 0.2 秒生成时间上重叠的动作序列，实际执行动作通过指数加权平均多个预测得到，保证平滑性。推理模式仅在关键时刻触发，推理 token 数低于 20 时不影响执行效率。

### 合成数据与错误恢复
- 合成图像 16,000 张：6,000 张视觉接地（每张 17 对指令-推理对）、10,000 张长时程规划
- 针对油瓶滑落、漏勺抓取失败等特定失败场景专门收集恢复数据
- 长时程任务中训练模型在指令模糊时主动提问澄清（如“您想要哪种鸡尾酒？”）

### 训练配置
每个任务在 8×H100 GPU 上训练 30,000 步，约 10 小时，采用 π₀ 的超参数。

## 关键创新

1. **推理-动作解耦的双模式设计**：这是与现有 VLA 最本质的区别。模型可以在推理模式与动作模式间显式切换，而不是在每个控制周期都进行推理。这使得长时程任务中的认知开销被压缩到总时长的约 10%（Tomato-Egg 任务中推理占 8.7%，Mountain Fuji 任务中占 10.4%），而动作模式下的计算时间仅比 π₀ 多约 0.02 秒（0.082s → 0.102s）。

2. **参考图像输入机制**：在推理模式下，模型接收 `I_ref`（对应最新推理内容的图像观测），防止过时的文本描述与当前视觉输入产生混淆。这是一个工程上很巧妙的细节——它承认了推理内容可能滞后于环境变化，并主动用视觉锚点来校正。

3. **合成数据驱动的推理能力蒸馏**：用 Gemini 2.5 Pro 生成合成图像与指令-推理对，将大语言模型的视觉-语言推理能力迁移到机器人策略中。尽管 Open-World 视觉接地成功率仍低（3/40），但这为缺乏大规模真实机器人数据的研究社区提供了一条可复现的路径。

- π₀ 的动作 MSE 比 OneTwoVLA 高 56%

这验证了显式推理内容能打破 π₀ 的单模态行为偏好，使模型根据推理内容选择不同动作目标。

## 边界与局限

论文未明确给出所有失败案例的完整统计，但已承认以下边界：
- **未见物体泛化脆弱**：Open-World 实验中遇到训练数据中不存在的物体时表现不稳定（如指令抓取小篮球玩具却持续移向棋盘）
- **细粒度操作仍不可靠**：Tomato-Egg 中偶尔抓取不牢导致掉落，Cocktail 中倒橙汁时洒出
- **推理错误无纠正机制**：Hotpot 中误判食材位置（指令抓青江菜却尝试抓金针菇），模型动作跟随错误推理，说明认知与行为高度一致既是优点也是风险
- **ARX 平台能力未充分利用**：全向轮式底座和 1-DoF 躯干升降机构未在实验中启用
- **推理延迟存在上限**：超过 100 token 时机器人需暂停数秒，长推理链在实时场景中不可行

## 工程启示

复现或采用 OneTwoVLA 时，以下环节最值得关注：

1. **先核对推理-动作数据分段标注**：这是训练的核心，推理区间与动作区间的划分质量直接决定模型能否学会在关键时刻触发推理。建议先在小规模数据上验证 [BOR]/[BOA] 标记预测的准确率，再扩展数据量。

2. **参考图像 `I_ref` 的选取逻辑**：这是最容易踩坑的地方。`I_ref` 必须严格对应当前推理内容被生成时的图像观测，否则模型会因视觉-文本错位而混淆。建议在数据采集时记录推理内容与图像的时间戳对应关系。

3. **合成数据的质量门槛**：作者尝试 GPT-4o 但空间理解较弱，最终改用 Gemini 2.5 Pro。如果复现时使用其他生成模型，务必先在小样本上人工验证空间关系描述的准确性，否则视觉接地性能会大幅下降。

4. **部署时的推理频率控制**：推理 token 超过 100 时机器人会暂停数秒，实际部署中应设置推理触发条件（如任务切换、指令模糊、检测到失败），而非让模型自由决定推理时机。Tomato-Egg 中 5 次推理、16 秒总推理时间是一个合理的参考上限。

5. **多模态动作实验的演示收集**：每个物体 50 条演示、共 200 条，指令不指定左右。如果复现时演示中隐含了位置偏好（如总是先抓左侧），模型可能学不到多模态行为。建议在演示中刻意平衡左右选择。

## Overview

OneTwoVLA is a unified vision-language-action model designed for robotic manipulation tasks. Its core design enables the model to adaptively switch between reasoning and action modes, explicitly outputting reasoning content during long-horizon tasks while maintaining efficiency during action execution. Built upon the π₀ architecture, this work introduces [BOR]/[BOA] tokens, reference image inputs, synthetic data augmentation, and interactive clarification training, validating reasoning-action consistency, multimodal action generation, and deployment efficiency on real Franka and ARX platforms.

## What It Changes

Existing VLA models (such as π₀) face a fundamental contradiction in real-world manipulation: they either output actions only, lacking explicit reasoning about task semantics, which prevents planning adjustments or interactive clarification during long-horizon tasks; or they incorporate reasoning but couple it too tightly with action generation, leading to uncontrollable computational overhead during deployment. What OneTwoVLA truly changes is decoupling "reasoning" from the implicit accompanying state of action generation, turning it into a mode that can be explicitly triggered and independently timed. This means the model is no longer forced to perform deep reasoning every control cycle but can enter reasoning mode only at critical moments (such as task transitions, ambiguous instructions, or error recovery), operating in pure action mode the rest of the time, thereby achieving an engineering-acceptable balance between cognitive capability and real-time performance.

Another significant change lies at the data level. Rather than relying solely on real demonstrations, the authors used Gemini 2.5 Pro to generate 16,000 synthetic images—6,000 for visual grounding and 10,000 for long-horizon planning—with fisheye distortion and synthetic gripper augmentation applied. This is essentially an attempt to distill "reasoning capability" from vision-language pretrained models into robot policies, allowing the model to maintain some generalization on unseen objects, although experiments show this generalization remains fragile.

## Method Breakdown

### Dual-Mode Architecture
The model is built on π₀, taking as input the current image `I_t`, a reference image `I_ref` (corresponding to the observation at the time of the latest reasoning content), and proprioceptive states (current, 0.05s ago, and 0.25s ago). On the output side, two special tokens are introduced:
- `[BOR]`: Begin reasoning; the model outputs updated reasoning content `R̂`
- `[BOA]`: Begin action; the model outputs action sequences

### Data Segmentation Training
Demonstration data is divided into two types of segments:
- **Reasoning segments**: The model learns to predict `[BOR]` → updated reasoning → `[BOA]` → actions, while also learning to predict actions based on old reasoning when reasoning has not been updated in time
- **Action segments**: The model learns to predict `[BOA]` → actions, and optionally predicts `[BOR]` based on outdated reasoning to mitigate class imbalance in decision token prediction

### Deployment-Time Temporal Ensemble
In action mode, the policy generates temporally overlapping action sequences every 0.2 seconds, and the actually executed actions are obtained via exponentially weighted averaging of multiple predictions to ensure smoothness. Reasoning mode is triggered only at critical moments, and reasoning token counts below 20 do not affect execution efficiency.

### Synthetic Data and Error Recovery
- 16,000 synthetic images: 6,000 for visual grounding (17 instruction-reasoning pairs per image), 10,000 for long-horizon planning
- Recovery data specifically collected for failure scenarios such as oil bottle slippage and slotted spoon grasping failures
- In long-horizon tasks, the model is trained to proactively ask clarifying questions when instructions are ambiguous (e.g., "Which cocktail would you like?")

### Training Configuration
Each task is trained on 8×H100 GPUs for 30,000 steps, approximately 10 hours, using π₀'s hyperparameters.

## Key Innovations

1. **Dual-mode design with reasoning-action decoupling**: This is the most fundamental difference from existing VLAs. The model can explicitly switch between reasoning and action modes rather than reasoning every control cycle. This compresses cognitive overhead in long-horizon tasks to approximately 10% of total duration (8.7% reasoning in the Tomato-Egg task, 10.4% in the Mountain Fuji task), while computation time in action mode is only about 0.02s more than π₀ (0.082s → 0.102s).

2. **Reference image input mechanism**: In reasoning mode, the model receives `I_ref` (the image observation corresponding to the latest reasoning content), preventing confusion between outdated text descriptions and current visual input. This is an ingenious engineering detail—it acknowledges that reasoning content may lag behind environmental changes and proactively uses visual anchors to correct for this.

3. **Synthetic data-driven reasoning capability distillation**: Using Gemini 2.5 Pro to generate synthetic images and instruction-reasoning pairs transfers large language models' vision-language reasoning capabilities into robot policies. Although Open-World visual grounding success remains low (3/40), this provides a reproducible path for research communities lacking large-scale real robot data.

## Boundaries and Limitations

The paper does not provide complete statistics for all failure cases but acknowledges the following limitations:
- **Fragile generalization to unseen objects**: In Open-World experiments, performance is unstable when encountering objects not present in the training data (e.g., instructed to grasp a small basketball toy but persistently moving toward the chessboard)
- **Fine-grained manipulation remains unreliable**: Occasional grasping failures causing drops in Tomato-Egg, and orange juice spillage when pouring in Cocktail
- **No correction mechanism for reasoning errors**: In Hotpot, the model misjudges ingredient positions (instructed to grasp bok choy but attempts to grasp enoki mushrooms); the model's actions follow the erroneous reasoning, demonstrating that the high consistency between cognition and behavior is both an advantage and a risk
- **ARX platform capabilities underutilized**: The omnidirectional wheeled base and 1-DoF torso lift mechanism were not enabled in experiments
- **Reasoning latency has an upper bound**: Exceeding 100 tokens requires the robot to pause for several seconds, making long reasoning chains infeasible in real-time scenarios

## Engineering Insights

When reproducing or adopting OneTwoVLA, the following aspects deserve the most attention:

1. **Verify reasoning-action data segmentation labels first**: This is the core of training. The quality of reasoning segment versus action segment division directly determines whether the model learns to trigger reasoning at critical moments. It is recommended to validate [BOR]/[BOA] token prediction accuracy on small-scale data before scaling up.

2. **Selection logic for reference image `I_ref`**: This is the most error-prone area. `I_ref` must strictly correspond to the image observation at the time the current reasoning content was generated; otherwise, the model will be confused by vision-text misalignment. It is recommended to record timestamp correspondences between reasoning content and images during data collection.

3. **Quality threshold for synthetic data**: The authors tried GPT-4o but found its spatial understanding weak, ultimately switching to Gemini 2.5 Pro. If reproducing with other generation models, be sure to manually verify the accuracy of spatial relationship descriptions on small samples first; otherwise, visual grounding performance will degrade significantly.

4. **Reasoning frequency control during deployment**: When reasoning tokens exceed 100, the robot pauses for several seconds. In actual deployment, reasoning trigger conditions should be set (e.g., task transitions, ambiguous instructions, failure detection) rather than letting the model freely decide when to reason. The 5 reasoning instances and 16 seconds of total reasoning time in Tomato-Egg serve as a reasonable reference upper bound.

5. **Demonstration collection for multimodal action experiments**: 50 demonstrations per object, 200 total, with instructions not specifying left or right. If demonstrations implicitly contain positional bias during reproduction (e.g., always grasping the left side first), the model may fail to learn multimodal behavior. It is recommended to deliberately balance left/right choices in demonstrations.

## 무엇을 바꾸었는가

기존 VLA 모델(예: π₀)은 실제 조작에서 근본적인 모순에 직면합니다. 액션만 출력하여 작업 의미론에 대한 명시적 추론이 부족하여 장기 작업에서 계획 조정이나 상호작용 명확화가 불가능하거나, 추론을 도입하더라도 추론 과정이 액션 생성과 너무 밀접하게 결합되어 배포 시 계산 오버헤드를 제어할 수 없습니다. OneTwoVLA가 실제로 바꾼 것은 '추론'을 액션 생성의 암시적 동반 상태에서 분리하여 명시적으로 트리거하고 독립적으로 시간을 측정할 수 있는 모드로 만든 것입니다. 이는 모델이 더 이상 모든 제어 주기에서 심층 추론을 강제로 수행하지 않고, 중요한 순간(작업 전환, 명령 모호성, 오류 복구 등)에만 추론 모드로 전환하며, 나머지 시간은 순수 액션 모드로 실행하여 인지 능력과 실시간성 사이에서 공학적으로 수용 가능한 균형을 달성함을 의미합니다.

또 다른 중요한 변화는 데이터 측면에 있습니다. 저자는 실제 시연에만 의존하지 않고 Gemini 2.5 Pro를 사용하여 16,000장의 합성 이미지를 생성했으며, 그중 6,000장은 시각적 접지, 10,000장은 장기 계획에 사용하고 어안 왜곡과 합성 그리퍼 증강을 적용했습니다. 이는 사실상 '추론 능력'을 비전-언어 사전 훈련 모델에서 로봇 정책으로 증류하려는 시도로, 모델이 보지 못한 물체에서도 일정 수준의 일반화를 유지할 수 있게 하지만, 실험 결과 이러한 일반화는 여전히 취약함을 보여줍니다.

## 방법 분석

### 이중 모드 아키텍처
모델은 π₀를 기반으로 구축되며, 입력은 현재 이미지 `I_t`, 참조 이미지 `I_ref`(최신 추론 내용에 해당하는 관측), 그리고 고유 감각 상태(현재, 0.05초 전, 0.25초 전 세 시점)입니다. 출력 측에는 두 개의 특수 토큰이 도입됩니다:
- `[BOR]`: 추론 시작, 모델이 업데이트된 추론 내용 `R̂` 출력
- `[BOA]`: 액션 시작, 모델이 액션 시퀀스 출력

### 데이터 분할 훈련
시연 데이터는 두 가지 유형의 구간으로 나뉩니다:
- **추론 구간**: 모델이 `[BOR]` → 추론 업데이트 → `[BOA]` → 액션 예측을 학습하며, 추론이 적시에 업데이트되지 않을 때 이전 추론을 기반으로 액션을 예측하는 것도 학습
- **액션 구간**: 모델이 `[BOA]` → 액션 예측을 학습하고, 선택적으로 오래된 추론을 기반으로 `[BOR]`을 예측하여 결정 토큰 예측의 클래스 불균형 완화

### 배포 시퀀스 통합
액션 모드에서 정책은 0.2초마다 시간적으로 중첩되는 액션 시퀀스를 생성하며, 실제 실행 액션은 여러 예측의 지수 가중 평균을 통해 계산되어 부드러움을 보장합니다. 추론 모드는 중요한 순간에만 트리거되며, 추론 토큰 수가 20 미만일 때 실행 효율성에 영향을 미치지 않습니다.

### 합성 데이터 및 오류 복구
- 합성 이미지 16,000장: 6,000장 시각적 접지(각각 17쌍의 명령-추론 쌍), 10,000장 장기 계획
- 오일 병 미끄러짐, 스키머 그리퍼 실패 등 특정 실패 시나리오를 위한 복구 데이터 별도 수집
- 장기 작업에서 명령이 모호할 때 모델이 능동적으로 질문하여 명확화하도록 훈련(예: "어떤 칵테일을 원하십니까?")

### 훈련 구성
각 작업은 8×H100 GPU에서 30,000스텝, 약 10시간 훈련하며 π₀의 하이퍼파라미터를 사용합니다.

## 핵심 혁신

1. **추론-액션 분리 이중 모드 설계**: 기존 VLA와 가장 본질적인 차이점입니다. 모델은 모든 제어 주기에서 추론하는 대신 추론 모드와 액션 모드 사이를 명시적으로 전환할 수 있습니다. 이를 통해 장기 작업에서 인지 오버헤드가 총 시간의 약 10%로 압축되며(Tomato-Egg 작업에서 추론 8.7%, Mountain Fuji 작업에서 10.4%), 액션 모드의 계산 시간은 π₀보다 약 0.02초만 더 소요됩니다(0.082초 → 0.102초).

2. **참조 이미지 입력 메커니즘**: 추론 모드에서 모델은 `I_ref`(최신 추론 내용에 해당하는 이미지 관측)를 수신하여 오래된 텍스트 설명과 현재 시각적 입력 간의 혼동을 방지합니다. 이는 공학적으로 매우 영리한 세부 사항입니다. 추론 내용이 환경 변화보다 지연될 수 있음을 인정하고 시각적 앵커로 능동적으로 교정합니다.

3. **합성 데이터 기반 추론 능력 증류**: Gemini 2.5 Pro를 사용하여 합성 이미지와 명령-추론 쌍을 생성하여 대규모 언어 모델의 비전-언어 추론 능력을 로봇 정책으로 전이합니다. Open-World 시각적 접지 성공률이 여전히 낮지만(3/40), 이는 대규모 실제 로봇 데이터가 부족한 연구 커뮤니티에 재현 가능한 경로를 제공합니다.

## 실험 및 결과

### 시각적 접지 작업 (표 3)
| 설정 | OneTwoVLA-VL | OneTwoVLA | π₀ |
|---|---|---|---|
| Single-Env | 35/40 | 31/40 | 2/40 |
| Open-World | 29/40 | 3/40 | 1/40 |

OneTwoVLA-VL은 Single-Env에서 87.5%(표 내 35/40 계산) 성공률을 달성하여 π₀의 5%(표 내 2/40 계산)보다 크게 우수합니다. 그러나 Open-World에서 OneTwoVLA(VL 미세 조정 없음)는 3/40에 불과하여 합성 데이터가 시각적 접지 일반화에 기여하는 바가 제한적이며, 모델이 여전히 작업 내 미세 조정에 의존함을 보여줍니다.

### 다중 모드 액션 실험
- "큐브 잡기": OneTwoVLA는 왼쪽 9회, 오른쪽 11회 잡음; π₀는 항상 오른쪽 선택
- "병 잡기": OneTwoVLA는 왼쪽 8회, 오른쪽 12회 잡음; π₀는 항상 오른쪽 선택
- π₀의 액션 MSE는 OneTwoVLA보다 56% 높음

이는 명시적 추론 내용이 π₀의 단일 모드 행동 선호도를 깨뜨려 모델이 추론 내용에 따라 다른 액션 대상을 선택할 수 있게 함을 검증합니다.

### 배포 효율성 (NVIDIA 4090)
| 구성 | 입력 토큰 | 출력 토큰 | 계산 시간 |
|---|---|---|---|
| π₀ | 20 | — | 0.082초 |
| OneTwoVLA-Act-20 | 20 | 1 | 0.102초 |
| OneTwoVLA-Act-200 | 200 | 1 | 0.104초 |
| OneTwoVLA-Reason-20 | 200 | 20 | 0.853초 |
| OneTwoVLA-Reason-100 | 200 | 100 | 2.346초 |
| OneTwoVLA-Reason-200 | 200 | 200 | 4.361초 |

추론 토큰이 100을 초과하면 로봇이 몇 초간 멈춰야 하지만, 실제 배포에서는 추론이 소수의 중요한 순간에만 발생합니다.

### 장기 작업 예시
Tomato-Egg 총 소요 183초, 추론 5회 총 16초(8.7%); Mountain Fuji 총 소요 135초, 추론 5회 총 14초(10.4%).

## 경계 및 한계

논문은 모든 실패 사례의 완전한 통계를 명시적으로 제시하지 않았지만, 다음과 같은 경계를 인정했습니다:
- **보지 못한 물체 일반화 취약**: Open-World 실험에서 훈련 데이터에 없는 물체를 만날 때 불안정한 성능(예: 작은 농구 장난감을 잡으라는 명령에 계속 체스판으로 이동)
- **세밀한 조작 여전히 불안정**: Tomato-Egg에서 가끔 잡음이 불안정하여 떨어뜨림, Cocktail에서 오렌지 주스 따를 때 흘림
- **추론 오류에 대한 교정 메커니즘 없음**: Hotpot에서 재료 위치를 잘못 판단(청경채를 잡으라는 명령에 팽이버섯을 잡으려 함), 모델의 액션이 잘못된 추론을 따름. 인지와 행동의 높은 일관성은 장점이자 위험임을 보여줌
- **ARX 플랫폼 기능 미활용**: 전방향 바퀴 베이스와 1-DoF 몸통 승강 메커니즘이 실험에서 활성화되지 않음
- **추론 지연 상한 존재**: 100 토큰 초과 시 로봇이 몇 초간 멈춰야 하므로 긴 추론 체인은 실시간 시나리오에서 불가능

## 공학적 시사점

OneTwoVLA를 재현하거나 채택할 때 다음 단계가 가장 주목할 가치가 있습니다:

1. **추론-액션 데이터 분할 라벨링 먼저 검증**: 이것이 훈련의 핵심입니다. 추론 구간과 액션 구간의 분할 품질이 모델이 중요한 순간에 추론을 트리거할 수 있는지 여부를 직접 결정합니다. 소규모 데이터에서 [BOR]/[BOA] 토큰 예측 정확도를 먼저 검증한 후 데이터 양을 확장하는 것이 좋습니다.

2. **참조 이미지 `I_ref` 선택 로직**: 가장 함정에 빠지기 쉬운 부분입니다. `I_ref`는 현재 추론 내용이 생성될 때의 이미지 관측과 엄격히 일치해야 하며, 그렇지 않으면 모델이 시각-텍스트 불일치로 혼동합니다. 데이터 수집 시 추론 내용과 이미지의 타임스탬프 대응 관계를 기록하는 것이 좋습니다.

3. **합성 데이터 품질 기준**: 저자는 GPT-4o를 시도했지만 공간 이해가 약해 최종적으로 Gemini 2.5 Pro로 전환했습니다. 재현 시 다른 생성 모델을 사용한다면 소규모 샘플에서 공간 관계 설명의 정확성을 수동으로 검증해야 하며, 그렇지 않으면 시각적 접지 성능이 크게 저하됩니다.

4. **배포 시 추론 빈도 제어**: 추론 토큰이 100을 초과하면 로봇이 몇 초간 멈추므로, 실제 배포에서는 모델이 추론 시점을 자유롭게 결정하도록 두지 말고 추론 트리거 조건(작업 전환, 명령 모호성, 실패 감지 등)을 설정해야 합니다. Tomato-Egg의 5회 추론, 총 16초 추론 시간은 합리적인 참조 상한입니다.

5. **다중 모드 액션 실험의 시연 수집**: 각 물체당 50개 시연, 총 200개이며 명령은 좌우를 지정하지 않습니다. 재현 시 시연에 위치 선호도(예: 항상 왼쪽 먼저 잡기)가 암시되어 있으면 모델이 다중 모드 행동을 학습하지 못할 수 있습니다. 시연에서 좌우 선택을 의도적으로 균형 있게 하는 것이 좋습니다.
