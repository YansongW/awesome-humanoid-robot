## 概述

OccVLA 是一个面向自动驾驶的视觉-语言-动作（VLA）模型，由作者团队提出，核心贡献在于将隐式 3D 占用预测作为监督信号，统一了占用预测、视觉-语言推理与动作生成。该方法仅使用 2D 图像输入，通过共享的视觉-语言-占用骨干网络，在不增加推理计算开销的前提下，显著提升了模型的 3D 空间理解能力与下游规划性能。

## 它改变了什么

现有自动驾驶 VLM 的 3D 感知能力受限于两个瓶颈：一是依赖昂贵且稀疏的文本标注（如坐标或边界框）来隐式表达空间信息，可扩展性差；二是缺乏大规模 3D 视觉-语言预训练，导致模型丢失细粒度空间细节。此前的工作要么直接使用显式 3D 输入（如 LiDAR 点云），受限于数据规模与描述复杂度；要么仅监督文本输出，忽略了丰富的 3D 视觉模态。

OccVLA 真正改变了这一局面：它将密集 3D 占用预测从“可选的输入模态”转变为“必需的监督信号”，并使其成为模型内部的隐式推理过程。这意味着模型不再需要外部 3D 传感器或昂贵的 3D 标注来获得空间理解，而是通过自监督式的占用预测任务，迫使视觉编码器学习到更鲁棒的几何与结构特征。这种设计让 3D 空间理解成为模型的内在能力，而非外部附加模块，从而在保持 2D 视觉信息完整性的同时，解决了 3D 表示构建与密集监督获取的双重挑战。

## 方法拆解

OccVLA 的架构与训练流程可拆解为以下关键部分：

### 共享视觉-语言-占用（V-L-O）骨干
- 采用 Paligemma2-3B-224px 作为 VLM 骨干，通过交叉注意力机制将占用查询（occupancy tokens）与视觉特征融合。
- 占用 token 输出公式：`h_O^occ = O(softmax(h_Q^occ [h_K^img]^T / sqrt(d)) [h_V^img])`，其中 `h_Q`、`h_K`、`h_V` 分别为查询、键、值表示，`O` 为统一输出投影。
- 视觉 token 通过自注意力建模，公式为 `h_O^img = O(softmax(h_Q^img [h_K^img]^T / sqrt(d)) [h_V^img])`。
- 关键设计：文本推理时，文本 token 是否访问占用特征对输出质量无显著差异，因此语言推理阶段可跳过占用计算，不增加额外开销。

### 潜在占用预测
- 自动驾驶场景中约 90% 的 3D 空间为空，原始占用网格 `x ∈ R^{H×W×D}`（其中 `(H,W,D)=(200,200,16)`）内存密集，直接预测低效。
- 将目标占用映射到紧凑潜在空间 `y ∈ R^{H/r×W/r×F}`，`r` 为下采样率，`F` 为潜在特征维度。
- 占用模型输出隐藏状态 `h_O^occ`，通过线性投影器投影到 `z`，输入 VQ-VAE 解码器（初始化自 OccWorld 预训练权重），分类头将解码特征转换为 3D 占用预测。
- 训练时直接监督最终 3D 占用类别（而非潜在空间特征），因 VQ-VAE 编码会引入偏差；VQ-VAE 解码器学习率设为零（非完全冻结）以保持梯度流。

### 运动规划任务分解
- 遵循 DriveVLM 的两阶段范式：(1) 预测自然语言形式的高层元动作；(2) 使用轻量模型基于元动作生成精确未来坐标。
- 元动作包含两个正交组件：速度动作（保持速度、加速、减速）和方向动作（直行、左转、右转、左变道、右变道、停止）。
- 元动作预测使用链式思维（CoT）监督，输入为六视角图像和自车历史元动作，模型先生成场景描述，再推断驾驶员意图，最后输出未来元动作。
- 规划头采用简单 MLP 架构，输入元动作嵌入、上一时间步速度和 VLM 视觉 token，预测未来 3 秒车辆位置，不提供高层导航命令。

### 三阶段训练
- **阶段 1**：在自动驾驶场景预训练 VLM（使用 OmniDrive 采样数据）。
- **阶段 2**：占用-语言联合训练，总损失 `L = L_AR^text + λ L_NAR^occ`，其中 `L_AR^text` 为自回归语言建模损失，`L_NAR^occ` 为非自回归 3D 感知损失（交叉熵），`λ` 控制占用关注度。
- **阶段 3**：规划头训练，使用 MSE 损失监督轨迹坐标。

## 关键创新

1. **隐式占用监督机制**：这是首个将 3D 占用预测作为 VLM 内部监督信号而非外部输入或输出的工作。它让模型在推理时无需显式计算占用，却能通过训练阶段的密集 3D 监督获得空间理解，解决了 3D 标注稀疏与昂贵的核心矛盾。
2. **共享 V-L-O 骨干架构**：通过交叉注意力与自注意力的统一设计，让占用查询与视觉 token 在同一特征空间中交互，避免了传统方法中 3D 分支与语言分支割裂的问题。这种设计使得占用预测成为视觉-语言推理的“副产品”，而非独立模块。
3. **高效的数据构建管线**：速度标签通过加速度阈值分类直接获得，方向标签由 GPT-4o 基于 HD 地图分类，CoT 标注由 GPT-4o 生成，所有元动作经人工检查（约 20% 数据进一步细化）。这大幅降低了 3D 视觉-语言数据的标注成本，使方法具备可扩展性。

## 边界与局限

- 占用预测任务仅使用当前时间步输入，缺乏多时间戳图像输入，限制了对遮挡区域（如树后建筑）的处理能力。
- 未使用时间信息，尽管能有效利用当前时间步多视角图像生成高质量 3D 占用预测，但动态场景的时序建模能力未验证。
- 未提供高层导航命令，所有规划决策仅基于模型场景理解，在需要全局路径规划的复杂场景中可能受限。
- 未进行大规模 3D 视觉-语言预训练，虽然通过占用监督弥补，但预训练数据规模与多样性对泛化能力的影响论文未明确。
- 仅依赖相机输入，未使用额外 3D 输入（如 LiDAR 或显式占用），在恶劣光照或极端天气下的鲁棒性未验证。
- 占用预测 mIoU 约 10%，精度相对较低，可能限制其对细粒度空间结构的监督效果。

## 工程启示

- **复现核对点**：首先确认 VQ-VAE 解码器的“学习率设为零”实现细节——这是保持梯度流的关键，若完全冻结会导致训练不稳定。其次，阶段 2 的损失权重 `λ` 需要针对具体任务调参，论文未明确其默认值，建议从 1.0 开始网格搜索。
- **数据管线踩坑**：元动作标注依赖 GPT-4o 与 HD 地图，人工检查约 20% 数据细化。复现时需注意 GPT-4o 输出的方向标签与 HD 地图投影的坐标系对齐问题，否则会引入系统性偏差。
- **架构选型建议**：共享 V-L-O 骨干的交叉注意力设计对显存占用较高，8× A800 GPU 是底线配置。若资源受限，可考虑将占用查询数量减少或使用低秩近似，但需重新验证对 VQA 性能的影响。
- **下游团队指导**：规划头仅使用 MLP 预测未来 3 秒轨迹，未提供导航命令。若需集成到完整自动驾驶栈，需额外设计全局路径规划模块与 OccVLA 的输出对接。此外，推理时跳过占用计算虽不增加开销，但需确保部署框架支持条件分支执行，否则会引入不必要的计算浪费。

## Overview

OccVLA is a vision-language-action (VLA) model for autonomous driving, proposed by the author team. Its core contribution lies in using implicit 3D occupancy prediction as a supervision signal, unifying occupancy prediction, vision-language reasoning, and action generation. The method uses only 2D image inputs and, through a shared vision-language-occupancy backbone, significantly improves the model's 3D spatial understanding and downstream planning performance without increasing inference computational overhead.

## What It Changes

The 3D perception capabilities of existing autonomous driving VLMs are limited by two bottlenecks: first, they rely on expensive and sparse text annotations (such as coordinates or bounding boxes) to implicitly express spatial information, which suffers from poor scalability; second, they lack large-scale 3D vision-language pretraining, causing the model to lose fine-grained spatial details. Previous work either directly used explicit 3D inputs (such as LiDAR point clouds), constrained by data scale and description complexity, or only supervised text outputs, ignoring the rich 3D visual modality.

OccVLA truly changes this situation: it transforms dense 3D occupancy prediction from an "optional input modality" into a "mandatory supervision signal" and makes it an implicit reasoning process within the model. This means the model no longer needs external 3D sensors or expensive 3D annotations to gain spatial understanding; instead, through a self-supervised occupancy prediction task, it forces the visual encoder to learn more robust geometric and structural features. This design makes 3D spatial understanding an intrinsic capability of the model rather than an external add-on module, thereby addressing the dual challenges of 3D representation construction and dense supervision acquisition while maintaining the integrity of 2D visual information.

## Method Breakdown

The architecture and training pipeline of OccVLA can be decomposed into the following key components:

### Shared Vision-Language-Occupancy (V-L-O) Backbone
- Uses Paligemma2-3B-224px as the VLM backbone, fusing occupancy tokens with visual features via cross-attention.
- Occupancy token output formula: `h_O^occ = O(softmax(h_Q^occ [h_K^img]^T / sqrt(d)) [h_V^img])`, where `h_Q`, `h_K`, `h_V` are the query, key, and value representations, and `O` is the unified output projection.
- Visual tokens are modeled via self-attention, with the formula `h_O^img = O(softmax(h_Q^img [h_K^img]^T / sqrt(d)) [h_V^img])`.
- Key design: during text reasoning, whether text tokens access occupancy features makes no significant difference to output quality, so occupancy computation can be skipped during the language reasoning stage without adding extra overhead.

### Latent Occupancy Prediction
- In autonomous driving scenarios, approximately 90% of 3D space is empty, making the raw occupancy grid `x ∈ R^{H×W×D}` (where `(H,W,D)=(200,200,16)`) memory-intensive and inefficient for direct prediction.
- Maps the target occupancy into a compact latent space `y ∈ R^{H/r×W/r×F}`, where `r` is the downsampling rate and `F` is the latent feature dimension.
- The occupancy model outputs hidden states `h_O^occ`, projected via a linear projector to `z`, which is fed into a VQ-VAE decoder (initialized from OccWorld pretrained weights); a classification head converts the decoded features into 3D occupancy predictions.
- During training, the final 3D occupancy categories are directly supervised (rather than latent space features), because VQ-VAE encoding introduces bias; the VQ-VAE decoder learning rate is set to zero (not fully frozen) to maintain gradient flow.

### Motion Planning Task Decomposition
- Follows the two-stage paradigm of DriveVLM: (1) predict high-level meta-actions in natural language form; (2) use a lightweight model to generate precise future coordinates based on the meta-actions.
- Meta-actions contain two orthogonal components: speed actions (maintain speed, accelerate, decelerate) and direction actions (go straight, turn left, turn right, change left, change right, stop).
- Meta-action prediction uses chain-of-thought (CoT) supervision, with inputs of six-view images and the ego vehicle's historical meta-actions; the model first generates a scene description, then infers driver intent, and finally outputs future meta-actions.
- The planning head adopts a simple MLP architecture, taking meta-action embeddings, previous timestep velocity, and VLM visual tokens as inputs to predict the ego vehicle's positions over the next 3 seconds, without providing high-level navigation commands.

### Three-Stage Training
- **Stage 1**: Pretrain the VLM on autonomous driving scenes (using OmniDrive sampled data).
- **Stage 2**: Joint occupancy-language training with total loss `L = L_AR^text + λ L_NAR^occ`, where `L_AR^text` is the autoregressive language modeling loss, `L_NAR^occ` is the non-autoregressive 3D perception loss (cross-entropy), and `λ` controls the occupancy attention weight.
- **Stage 3**: Planning head training using MSE loss to supervise trajectory coordinates.

## Key Innovations

1. **Implicit Occupancy Supervision Mechanism**: This is the first work to use 3D occupancy prediction as an internal supervision signal for a VLM rather than as an external input or output. It allows the model to avoid explicit occupancy computation during inference while gaining spatial understanding through dense 3D supervision during training, resolving the core contradiction of sparse and expensive 3D annotations.
2. **Shared V-L-O Backbone Architecture**: Through a unified design of cross-attention and self-attention, occupancy queries and visual tokens interact within the same feature space, avoiding the fragmentation between 3D and language branches found in traditional methods. This design makes occupancy prediction a "byproduct" of vision-language reasoning rather than an independent module.
3. **Efficient Data Construction Pipeline**: Speed labels are obtained directly through acceleration threshold classification, direction labels are classified by GPT-4o based on HD maps, and CoT annotations are generated by GPT-4o; all meta-actions undergo manual inspection (with approximately 20% of data further refined). This significantly reduces the annotation cost of 3D vision-language data, making the method scalable.

## Boundaries and Limitations

- The occupancy prediction task only uses current timestep inputs, lacking multi-timestamp image inputs, which limits its ability to handle occluded regions (such as buildings behind trees).
- Temporal information is not used; although high-quality 3D occupancy prediction can be generated from multi-view images at the current timestep, temporal modeling capability for dynamic scenes has not been validated.
- No high-level navigation commands are provided; all planning decisions are based solely on the model's scene understanding, which may be limited in complex scenarios requiring global path planning.
- No large-scale 3D vision-language pretraining is performed; although occupancy supervision compensates to some extent, the impact of pretraining data scale and diversity on generalization is not explicitly addressed in the paper.
- Relies solely on camera input without additional 3D inputs (such as LiDAR or explicit occupancy), and robustness under poor lighting or extreme weather conditions has not been validated.
- The occupancy prediction mIoU is approximately 10%, which is relatively low and may limit its supervision effectiveness for fine-grained spatial structures.

## Engineering Insights

- **Reproduction Checkpoints**: First, confirm the implementation details of the VQ-VAE decoder's "learning rate set to zero"—this is key to maintaining gradient flow; fully freezing it would cause training instability. Second, the loss weight `λ` in Stage 2 needs tuning for specific tasks; the paper does not specify its default value, so it is recommended to start with a grid search from 1.0.
- **Data Pipeline Pitfalls**: Meta-action annotation relies on GPT-4o and HD maps, with approximately 20% of data refined through manual inspection. When reproducing, pay attention to the coordinate system alignment between GPT-4o's output direction labels and HD map projections; otherwise, systematic bias may be introduced.
- **Architecture Selection Recommendations**: The cross-attention design of the shared V-L-O backbone has high GPU memory requirements, with 8× A800 GPUs being the minimum configuration. If resources are constrained, consider reducing the number of occupancy queries or using low-rank approximations, but the impact on VQA performance must be re-validated.
- **Guidance for Downstream Teams**: The planning head only uses an MLP to predict trajectories for the next 3 seconds and does not provide navigation commands. If integration into a complete autonomous driving stack is needed, an additional global path planning module must be designed to interface with OccVLA's output. Additionally, although skipping occupancy computation during inference adds no overhead, it is necessary to ensure the deployment framework supports conditional branch execution; otherwise, unnecessary computational waste will be introduced.

## 개요

OccVLA는 자율주행을 위한 비전-언어-행동(VLA) 모델로, 저자 팀이 제안했으며, 핵심 기여는 암시적 3D 점유 예측을 감독 신호로 사용하여 점유 예측, 비전-언어 추론 및 행동 생성을 통합한 것입니다. 이 방법은 2D 이미지 입력만 사용하며, 공유된 비전-언어-점유 백본 네트워크를 통해 추론 계산 오버헤드를 증가시키지 않으면서 모델의 3D 공간 이해 능력과 하위 계획 성능을 크게 향상시킵니다.

## 무엇을 변화시켰는가

기존 자율주행 VLM의 3D 인식 능력은 두 가지 병목 현상에 제한됩니다: 첫째, 비싸고 희소한 텍스트 주석(예: 좌표 또는 경계 상자)에 의존하여 공간 정보를 암시적으로 표현하므로 확장성이 낮습니다; 둘째, 대규모 3D 비전-언어 사전 학습이 부족하여 모델이 세밀한 공간 세부 정보를 잃게 됩니다. 이전 연구들은 명시적 3D 입력(예: LiDAR 포인트 클라우드)을 직접 사용하여 데이터 규모와 설명 복잡성에 제한을 받거나, 텍스트 출력만 감독하여 풍부한 3D 시각 양식을 무시했습니다.

OccVLA는 이러한 상황을 실질적으로 변화시킵니다: 밀집 3D 점유 예측을 "선택적 입력 양식"에서 "필수 감독 신호"로 전환하고, 이를 모델 내부의 암시적 추론 과정으로 만듭니다. 이는 모델이 더 이상 외부 3D 센서나 비싼 3D 주석 없이 공간 이해를 얻을 수 있으며, 자기 지도식 점유 예측 작업을 통해 시각 인코더가 더 견고한 기하학적 및 구조적 특징을 학습하도록 강제합니다. 이 설계는 3D 공간 이해를 외부 추가 모듈이 아닌 모델의 내재적 능력으로 만들어, 2D 시각 정보의 완전성을 유지하면서 3D 표현 구축과 밀집 감독 획득의 이중 과제를 해결합니다.

## 방법 분석

OccVLA의 아키텍처와 훈련 프로세스는 다음과 같은 핵심 부분으로 분해할 수 있습니다:

### 공유 비전-언어-점유(V-L-O) 백본
- Paligemma2-3B-224px를 VLM 백본으로 사용하며, 교차 주의 메커니즘을 통해 점유 쿼리(occupancy tokens)와 시각 특징을 융합합니다.
- 점유 토큰 출력 공식: `h_O^occ = O(softmax(h_Q^occ [h_K^img]^T / sqrt(d)) [h_V^img])`, 여기서 `h_Q`, `h_K`, `h_V`는 각각 쿼리, 키, 값 표현이며, `O`는 통합 출력 투영입니다.
- 시각 토큰은 자기 주의를 통해 모델링되며, 공식은 `h_O^img = O(softmax(h_Q^img [h_K^img]^T / sqrt(d)) [h_V^img])`입니다.
- 핵심 설계: 텍스트 추론 시 텍스트 토큰이 점유 특징에 접근하는지 여부는 출력 품질에 유의미한 차이를 만들지 않으므로, 언어 추론 단계에서 점유 계산을 건너뛸 수 있어 추가 오버헤드가 없습니다.

### 잠재 점유 예측
- 자율주행 시나리오에서 약 90%의 3D 공간이 비어 있으며, 원시 점유 그리드 `x ∈ R^{H×W×D}`(여기서 `(H,W,D)=(200,200,16)`)는 메모리 집약적이므로 직접 예측은 비효율적입니다.
- 목표 점유를 컴팩트한 잠재 공간 `y ∈ R^{H/r×W/r×F}`에 매핑하며, `r`은 다운샘플링 비율, `F`는 잠재 특징 차원입니다.
- 점유 모델은 숨겨진 상태 `h_O^occ`를 출력하고, 선형 투영기를 통해 `z`로 투영한 후 VQ-VAE 디코더(OccWorld 사전 학습 가중치로 초기화)에 입력하며, 분류 헤드가 디코딩된 특징을 3D 점유 예측으로 변환합니다.
- 훈련 시 최종 3D 점유 클래스를 직접 감독합니다(잠재 공간 특징이 아닌). VQ-VAE 인코딩이 편향을 도입할 수 있기 때문입니다; VQ-VAE 디코더의 학습률은 0으로 설정되지만(완전히 동결되지 않음) 그래디언트 흐름을 유지합니다.

### 운동 계획 작업 분해
- DriveVLM의 2단계 패러다임을 따릅니다: (1) 자연어 형태의 고수준 메타 행동 예측; (2) 경량 모델을 사용하여 메타 행동을 기반으로 정확한 미래 좌표 생성.
- 메타 행동은 두 가지 직교 구성 요소를 포함합니다: 속도 행동(속도 유지, 가속, 감속) 및 방향 행동(직진, 좌회전, 우회전, 좌측 차선 변경, 우측 차선 변경, 정지).
- 메타 행동 예측은 사고 사슬(CoT) 감독을 사용하며, 입력은 6개 시점 이미지와 자차의 과거 메타 행동이며, 모델은 먼저 장면 설명을 생성한 다음 운전자 의도를 추론하고 마지막으로 미래 메타 행동을 출력합니다.
- 계획 헤드는 간단한 MLP 아키텍처를 사용하며, 입력은 메타 행동 임베딩, 이전 시간 단계 속도 및 VLM 시각 토큰이며, 미래 3초 차량 위치를 예측하고 고수준 내비게이션 명령은 제공하지 않습니다.

### 3단계 훈련
- **단계 1**: 자율주행 장면에서 VLM 사전 학습(OmniDrive 샘플링 데이터 사용).
- **단계 2**: 점유-언어 공동 훈련, 총 손실 `L = L_AR^text + λ L_NAR^occ`, 여기서 `L_AR^text`는 자기 회귀 언어 모델링 손실, `L_NAR^occ`는 비자기 회귀 3D 인식 손실(교차 엔트로피), `λ`는 점유 주의도를 제어합니다.
- **단계 3**: 계획 헤드 훈련, MSE 손실로 궤적 좌표를 감독합니다.

## 핵심 혁신

1. **암시적 점유 감독 메커니즘**: 3D 점유 예측을 VLM의 내부 감독 신호로 사용한 최초의 연구로, 외부 입력이나 출력이 아닙니다. 이를 통해 모델은 추론 시 점유를 명시적으로 계산할 필요 없이 훈련 단계의 밀집 3D 감독을 통해 공간 이해를 얻을 수 있어, 3D 주석의 희소성과 비용이라는 핵심 모순을 해결합니다.
2. **공유 V-L-O 백본 아키텍처**: 교차 주의와 자기 주의의 통합 설계를 통해 점유 쿼리와 시각 토큰이 동일한 특징 공간에서 상호 작용하도록 하여, 기존 방법에서 3D 분기와 언어 분기가 분리되는 문제를 피합니다. 이 설계는 점유 예측을 독립 모듈이 아닌 비전-언어 추론의 "부산물"로 만듭니다.
3. **효율적인 데이터 구축 파이프라인**: 속도 레이블은 가속도 임계값 분류를 통해 직접 얻고, 방향 레이블은 GPT-4o가 HD 맵을 기반으로 분류하며, CoT 주석은 GPT-4o가 생성하고 모든 메타 행동은 수동 검사를 거칩니다(약 20% 데이터 추가 정제). 이는 3D 비전-언어 데이터의 주석 비용을 크게 줄여 확장성을 확보합니다.

## 경계 및 한계

- 점유 예측 작업은 현재 시간 단계 입력만 사용하며, 다중 타임스탬프 이미지 입력이 부족하여 폐색 영역(예: 나무 뒤 건물) 처리 능력이 제한됩니다.
- 시간 정보를 사용하지 않으며, 현재 시간 단계의 다중 시점 이미지를 효과적으로 활용하여 고품질 3D 점유 예측을 생성할 수 있지만 동적 장면의 시계열 모델링 능력은 검증되지 않았습니다.
- 고수준 내비게이션 명령을 제공하지 않으며, 모든 계획 결정은 모델의 장면 이해에만 기반하므로 전역 경로 계획이 필요한 복잡한 장면에서 제한될 수 있습니다.
- 대규모 3D 비전-언어 사전 학습을 수행하지 않았으며, 점유 감독으로 보완하지만 사전 학습 데이터 규모와 다양성이 일반화 능력에 미치는 영향은 논문에서 명확히 다루지 않습니다.
- 카메라 입력에만 의존하며 추가 3D 입력(예: LiDAR 또는 명시적 점유)을 사용하지 않으므로 악천후나 극한 조명 조건에서의 견고성은 검증되지 않았습니다.
- 점유 예측 mIoU는 약 10%로 정확도가 상대적으로 낮아 세밀한 공간 구조에 대한 감독 효과를 제한할 수 있습니다.

## 엔지니어링 시사점

- **재현 체크포인트**: 먼저 VQ-VAE 디코더의 "학습률 0 설정" 구현 세부 사항을 확인하세요 — 이는 그래디언트 흐름을 유지하는 핵심이며, 완전히 동결하면 훈련이 불안정해질 수 있습니다. 둘째, 단계 2의 손실 가중치 `λ`는 특정 작업에 맞게 조정해야 하며, 논문에서 기본값을 명시하지 않았으므로 1.0에서 그리드 검색을 시작하는 것이 좋습니다.
- **데이터 파이프라인 함정**: 메타 행동 주석은 GPT-4o와 HD 맵에 의존하며, 약 20% 데이터는 수동 검사로 정제됩니다. 재현 시 GPT-4o가 출력하는 방향 레이블과 HD 맵 투영의 좌표계 정렬 문제에 주의해야 하며, 그렇지 않으면 체계적 편향이 도입될 수 있습니다.
- **아키텍처 선택 제안**: 공유 V-L-O 백본의 교차 주의 설계는 GPU 메모리 사용량이 높으므로 8× A800 GPU가 최소 구성입니다. 리소스가 제한된 경우 점유 쿼리 수를 줄이거나 저순위 근사를 고려할 수 있지만, VQA 성능에 미치는 영향을 재검증해야 합니다.
- **하위 팀 지침**: 계획 헤드는 MLP만 사용하여 미래 3초 궤적을 예측하며 내비게이션 명령을 제공하지 않습니다. 완전한 자율주행 스택에 통합하려면 전역 경로 계획 모듈을 추가 설계하여 OccVLA 출력과 연결해야 합니다. 또한 추론 시 점유 계산을 건너뛰는 것은 오버헤드를 추가하지 않지만, 배포 프레임워크가 조건부 분기 실행을 지원하는지 확인해야 하며, 그렇지 않으면 불필요한 계산 낭비가 발생합니다.
