## 概述

ZOZO, Inc. 旗下 Ryoichi Ando 维护的开源接触求解器，面向布料、固体、杆件、刚体与沙子的统一物理仿真，核心卖点是 GPU 单精度下的无穿透接触解析与弹性-接触耦合的“弹性包含动态刚度”（Elasticity-Inclusive Dynamic Stiffness）。项目以 Apache 2.0 协议开源，提供 Docker、Windows 原生可执行文件、Blender 插件与 JupyterLab 前端，并支持 LLM 驱动的 MCP 服务器，目标是在超过 1.8 亿接触的大规模场景中保持稳健与可复现。

## 它改变了什么

这个项目真正改变的不是“又一个接触求解器”，而是把“可复现的大规模物理仿真”从学术论文的附属品变成了一个可审计、可部署的工程制品。过去，接触求解器的论文往往只给出算法与少量示例，复现需要读者自行搭建环境、处理依赖、猜测参数；而这里，作者把求解器、前端、Docker 镜像、AWS/GCP/vast.ai 部署脚本、日志 API 全部开源，甚至给出了每个示例在特定 GPU 上的成本与帧时间——这等于把“实验”变成了“产品说明书”。

更关键的是，它改变了“接触求解器”与“弹性求解器”的关系。传统做法是两者分离：先解弹性，再处理接触，迭代直至收敛。而这里的“弹性包含动态刚度”意味着接触刚度不是事后修正，而是直接进入弹性系统的雅可比矩阵，让接触与变形在同一非线性求解中耦合。这直接回应了布料仿真中“穿透/交叉”（clipping/snagging）这一老大难问题——不是靠事后检测，而是在求解过程中就保证无穿透。

## 方法拆解

### 求解器架构
- 接触与弹性求解器均在 GPU 上运行，全部使用**单精度**（single precision），不使用双精度——这是对 GPU 内存带宽与算力的妥协，但通过符号力雅可比矩阵（symbolic force jacobians）保持数值稳健性。
- 可变形体使用**有限元方法（FEM）**，支持三角形（壳）与四面体（体）单元；杆件（rods）与刚体（基于 Painless Differentiable Rotation Dynamics）作为独立单元类型接入同一框架。

### 接触解析流程
- 接触解析保证**无穿透**（penetration-free），三角形应变有严格上限（示例默认 5%，可调至 1%）。
- 每步结束时执行**显式交叉检查**，若检测到交叉则报错——这意味着测试通过时，所有步骤在数学上无穿透。

### 弹性-接触耦合（Elasticity-Inclusive Dynamic Stiffness）
- 论文未明确给出具体公式，但根据项目描述，接触刚度被纳入弹性系统的动态刚度矩阵，而非作为外部约束迭代处理。
- 关键设计决策：将接触力对位移的导数（即接触刚度）与弹性刚度矩阵合并，形成统一的非线性系统，用 Newton 法求解。

### 前端与 API 设计
- 前端 API 采用**方法链**（method chaining），单一导入（`from frontend import App`），在管线内创建三角形/四面体（`.triangulate()` 与 `.tetrahedralize()`），不包含网格数据——用户需自行提供或下载网格。
- 提供日志查询 API，包括 `time-per-frame`、`newton-steps`、`num-contact`、`max-sigma` 等，便于监控与调试。

### 部署与集成
- 提供 Blender 插件（需 Blender 5+）与 JupyterLab 前端，两者与同一求解器引擎通信；支持远程 GPU 仿真（如 vast.ai）。
- 提供 MCP 服务器，允许 LLM 通过自然语言驱动仿真流程——这是将物理仿真接入 AI Agent 工作流的尝试。

## 关键创新

1. **弹性包含动态刚度（Elasticity-Inclusive Dynamic Stiffness）**：将接触刚度直接并入弹性系统的雅可比矩阵，而非作为外部约束迭代。这消除了传统“先弹性后接触”的交替迭代可能带来的收敛慢与穿透残留问题，是接触-变形耦合求解的实质性改进。

2. **单精度 GPU 大规模求解**：在 RTX 4090 上处理 8.2M 顶点、184.1M 接触的仿真，每帧 144.5 秒——这不仅是算法创新，更是工程能力的体现。单精度意味着内存占用减半，但需要符号雅可比矩阵来补偿精度损失，这一组合在公开项目中罕见。

3. **可复现性作为一等公民**：提供预编译 Docker 镜像、Windows 原生可执行文件、AWS/GCP/vast.ai 部署脚本、GitHub Actions 压力测试（连续 10 次运行加抖动），以及每个示例的成本与帧时间表——这改变了“论文代码”的交付标准，让下游用户可以直接评估是否值得采用。

## Overview

The open-source contact solver maintained by Ryoichi Ando at ZOZO, Inc., designed for unified physics simulation of cloth, solids, rods, rigid bodies, and sand. Its core selling points are penetration-free contact resolution under GPU single precision and the elasticity-contact coupling approach called "Elasticity-Inclusive Dynamic Stiffness." The project is open-sourced under the Apache 2.0 license, offering Docker images, native Windows executables, a Blender plugin, and a JupyterLab frontend, along with an LLM-driven MCP server. The goal is to maintain robustness and reproducibility in large-scale scenarios involving over 180 million contacts.

## What It Changes

What this project truly changes is not "yet another contact solver," but rather transforming "reproducible large-scale physics simulation" from an academic paper accessory into an auditable, deployable engineering artifact. In the past, papers on contact solvers often provided only algorithms and a few examples, requiring readers to set up environments, handle dependencies, and guess parameters for reproduction. Here, the author open-sources the solver, frontend, Docker images, AWS/GCP/vast.ai deployment scripts, and logging APIs, and even provides the cost and frame time for each example on specific GPUs—effectively turning "experiments" into "product documentation."

More critically, it changes the relationship between "contact solvers" and "elasticity solvers." Traditional approaches treat them separately: first solve elasticity, then handle contact, iterating until convergence. Here, "Elasticity-Inclusive Dynamic Stiffness" means contact stiffness is not a post-hoc correction but directly enters the Jacobian matrix of the elastic system, coupling contact and deformation within the same nonlinear solve. This directly addresses the long-standing problem of clipping/snagging in cloth simulation—not through post-hoc detection, but by guaranteeing penetration-free behavior during the solve itself.

## Method Breakdown

### Solver Architecture
- Both contact and elasticity solvers run on the GPU, entirely in **single precision**, with no double precision—a trade-off for GPU memory bandwidth and compute, but numerical robustness is maintained through symbolic force Jacobians.
- Deformable bodies use the **Finite Element Method (FEM)**, supporting triangular (shell) and tetrahedral (volume) elements; rods and rigid bodies (based on Painless Differentiable Rotation Dynamics) are integrated as separate element types within the same framework.

### Contact Resolution Pipeline
- Contact resolution guarantees **penetration-free** behavior, with a strict upper bound on triangle strain (5% by default in examples, adjustable to 1%).
- An explicit intersection check is performed at the end of each step, raising an error if intersections are detected—meaning that when tests pass, all steps are mathematically penetration-free.

### Elasticity-Contact Coupling (Elasticity-Inclusive Dynamic Stiffness)
- The paper does not explicitly provide the exact formulation, but based on the project description, contact stiffness is incorporated into the dynamic stiffness matrix of the elastic system rather than being treated as an external constraint iteratively.
- Key design decision: the derivative of contact forces with respect to displacement (i.e., contact stiffness) is merged with the elastic stiffness matrix to form a unified nonlinear system solved via Newton's method.

### Frontend and API Design
- The frontend API uses **method chaining**, with a single import (`from frontend import App`), creating triangles/tetrahedra within the pipeline (`.triangulate()` and `.tetrahedralize()`), and does not include mesh data—users must provide or download meshes themselves.
- Provides logging query APIs, including `time-per-frame`, `newton-steps`, `num-contact`, and `max-sigma`, for monitoring and debugging.

### Deployment and Integration
- Offers a Blender plugin (requiring Blender 5+) and a JupyterLab frontend, both communicating with the same solver engine; supports remote GPU simulation (e.g., vast.ai).
- Provides an MCP server allowing LLMs to drive simulation workflows via natural language—an attempt to integrate physics simulation into AI agent workflows.

## Key Innovations

1. **Elasticity-Inclusive Dynamic Stiffness**: Directly incorporates contact stiffness into the Jacobian matrix of the elastic system rather than treating it as an external constraint iteratively. This eliminates the slow convergence and residual penetration issues that can arise from traditional alternating "elasticity-then-contact" iterations, representing a substantive improvement in contact-deformation coupled solving.

2. **Single-Precision GPU Large-Scale Solving**: Handles simulations with 8.2M vertices and 184.1M contacts on an RTX 4090 at 144.5 seconds per frame—this is not just algorithmic innovation but a demonstration of engineering capability. Single precision halves memory usage but requires symbolic Jacobians to compensate for precision loss, a combination rarely seen in public projects.

3. **Reproducibility as a First-Class Citizen**: Provides precompiled Docker images, native Windows executables, AWS/GCP/vast.ai deployment scripts, GitHub Actions stress tests (10 consecutive runs with jitter), and cost/frame-time tables for every example—this changes the delivery standard for "paper code," allowing downstream users to directly evaluate whether adoption is worthwhile.

## Boundaries and Limitations

- **The paper does not explicitly provide** the detailed formulation and convergence proof for Elasticity-Inclusive Dynamic Stiffness; the mechanism is inferred only from the project description.
- The solver is **designed for offline use**, not real-time; large-scale examples (large-twist, large-five-twist, large-woven) are not included in GitHub Actions tests because they may take days to weeks to complete—meaning the stability of these examples has not been verified through automated regression testing.
- Supports **x86 architecture only**, not arm64; documentation and tutorial videos are "not polished enough," and the author welcomes community contributions.
- Maintenance is performed by a **single part-time individual** (Ryoichi Ando), so issue handling may be slow; direct pull requests are not accepted (due to copyright and licensing concerns), and contributions must be submitted via issues or forks.
- The main branch is frequently updated and may diverge from the paper; the reference implementation for the paper is on the sigasia-2024 branch, which receives only maintenance updates and does not include the latest algorithmic changes—meaning reproducing paper results requires using that specific branch.

## Engineering Insights

- **Check the branch first**: If the goal is to reproduce paper results, be sure to use the `sigasia-2024` branch rather than the main branch—the main branch contains the latest algorithmic changes that may diverge from the paper.
- **Hardware selection**: Large-scale simulations (>1M vertices) require an RTX 4090 or 5090; for small-to-medium scales (<200K vertices), an RTX 3090, 4070, or 5070 suffices. Single precision halves VRAM requirements, but note the CUDA 12.8+ driver requirements.
- **Most common pitfall**: Mesh data is not included in the project; users must create or download meshes themselves—meaning the "out-of-the-box" experience breaks at the mesh preparation stage. It is recommended to first run small examples like `yarn` or `drape` to verify the environment before scaling up.
- **Cost estimation**: AWS L4 instances cost approximately $1/hour, with small examples ranging from $0.01–$0.39; large-scale examples should be estimated based on vast.ai costs for RTX 4090 (<$0.5/hour)—but the per-frame times for large-scale examples (46–437 seconds) mean a 2,000-frame simulation takes 1–10 days, so budgets must be planned in advance.
- **The logging API is a debugging powerhouse**: Metrics such as `time-per-frame`, `newton-steps`, `num-contact`, and `max-sigma` should serve as acceptance criteria—if `max-sigma` exceeds the strain limit, contact stiffness or time step size likely needs adjustment.

## 개요

ZOZO, Inc. 소속 Ryoichi Ando가 유지보수하는 오픈소스 접촉 솔버로, 천, 고체, 봉, 강체, 모래를 위한 통합 물리 시뮬레이션을 대상으로 한다. 핵심 판매 포인트는 GPU 단정밀도에서의 무관통 접촉 해석과 탄성-접촉 커플링의 "탄성 포함 동적 강성"(Elasticity-Inclusive Dynamic Stiffness)이다. 프로젝트는 Apache 2.0 라이선스로 오픈소스이며, Docker, Windows 네이티브 실행 파일, Blender 플러그인, JupyterLab 프런트엔드를 제공하고, LLM 기반 MCP 서버를 지원한다. 목표는 1.8억 개 이상의 접촉이 있는 대규모 시나리오에서 견고성과 재현성을 유지하는 것이다.

## 무엇을 바꾸었는가

이 프로젝트가 실제로 바꾼 것은 "또 하나의 접촉 솔버"가 아니라, "재현 가능한 대규모 물리 시뮬레이션"을 학술 논문의 부산물에서 감사 가능하고 배포 가능한 엔지니어링 산출물로 전환한 것이다. 과거에는 접촉 솔버 논문이 알고리즘과 소수의 예시만 제공하는 경우가 많았고, 재현하려면 독자가 직접 환경을 구축하고, 의존성을 처리하고, 파라미터를 추측해야 했다. 그러나 여기서 저자는 솔버, 프런트엔드, Docker 이미지, AWS/GCP/vast.ai 배포 스크립트, 로그 API를 모두 오픈소스로 공개했으며, 각 예시의 특정 GPU에서의 비용과 프레임 시간까지 제공한다. 이는 "실험"을 "제품 설명서"로 바꾼 셈이다.

더 중요한 점은 "접촉 솔버"와 "탄성 솔버"의 관계를 바꾸었다는 것이다. 전통적인 방식은 두 가지를 분리하는 것이다: 먼저 탄성을 풀고, 그다음 접촉을 처리하며, 수렴할 때까지 반복한다. 반면 여기서의 "탄성 포함 동적 강성"은 접촉 강성이 사후 수정이 아니라 탄성 시스템의 야코비 행렬에 직접 들어가며, 접촉과 변형이 동일한 비선형 솔버에서 커플링되도록 한다. 이는 천 시뮬레이션의 고질적인 문제인 "관통/걸림"(clipping/snagging)에 직접 대응한다. 사후 감지가 아니라 솔버 과정에서 무관통을 보장하는 것이다.

## 방법 분석

### 솔버 아키텍처
- 접촉 및 탄성 솔버는 모두 GPU에서 실행되며, 전부 **단정밀도**(single precision)를 사용하고 배정밀도는 사용하지 않는다. 이는 GPU 메모리 대역폭과 연산 능력에 대한 타협이지만, 기호 힘 야코비 행렬(symbolic force jacobians)을 통해 수치적 견고성을 유지한다.
- 변형체는 **유한요소법(FEM)**을 사용하며, 삼각형(셸) 및 사면체(체적) 요소를 지원한다. 봉(rods)과 강체(Painless Differentiable Rotation Dynamics 기반)는 독립 요소 유형으로 동일한 프레임워크에 연결된다.

### 접촉 해석 프로세스
- 접촉 해석은 **무관통**(penetration-free)을 보장하며, 삼각형 변형률에는 엄격한 상한이 있다(예시 기본값 5%, 1%까지 조정 가능).
- 각 단계 종료 시 **명시적 교차 검사**를 수행하며, 교차가 감지되면 오류를 보고한다. 이는 테스트가 통과하면 모든 단계가 수학적으로 무관통임을 의미한다.

### 탄성-접촉 커플링(Elasticity-Inclusive Dynamic Stiffness)
- 논문에는 구체적인 공식이 명시적으로 제공되지 않았지만, 프로젝트 설명에 따르면 접촉 강성은 탄성 시스템의 동적 강성 행렬에 포함되며, 외부 제약 조건으로 반복 처리되지 않는다.
- 핵심 설계 결정: 접촉력의 변위에 대한 도함수(즉, 접촉 강성)를 탄성 강성 행렬과 병합하여 통합 비선형 시스템을 형성하고, Newton 법으로 푼다.

### 프런트엔드 및 API 설계
- 프런트엔드 API는 **메서드 체이닝**(method chaining)을 사용하며, 단일 임포트(`from frontend import App`)로 파이프라인 내에서 삼각형/사면체를 생성한다(`.triangulate()` 및 `.tetrahedralize()`). 메시 데이터는 포함되지 않으며, 사용자가 직접 제공하거나 다운로드해야 한다.
- 로그 조회 API를 제공하며, `time-per-frame`, `newton-steps`, `num-contact`, `max-sigma` 등을 포함하여 모니터링 및 디버깅을 지원한다.

### 배포 및 통합
- Blender 플러그인(Blender 5+ 필요)과 JupyterLab 프런트엔드를 제공하며, 둘 다 동일한 솔버 엔진과 통신한다. 원격 GPU 시뮬레이션(vast.ai 등)을 지원한다.
- MCP 서버를 제공하여 LLM이 자연어로 시뮬레이션 프로세스를 구동할 수 있게 한다. 이는 물리 시뮬레이션을 AI 에이전트 워크플로우에 연결하려는 시도이다.

## 핵심 혁신

1. **탄성 포함 동적 강성(Elasticity-Inclusive Dynamic Stiffness)**: 접촉 강성을 외부 제약 조건으로 반복 처리하는 대신 탄성 시스템의 야코비 행렬에 직접 통합한다. 이는 전통적인 "탄성 먼저, 접촉 나중"의 교대 반복이 가져올 수 있는 수렴 저하와 관통 잔여 문제를 제거하며, 접촉-변형 커플링 솔버의 실질적인 개선이다.

2. **단정밀도 GPU 대규모 솔버**: RTX 4090에서 8.2M 정점, 184.1M 접촉 시뮬레이션을 처리하며, 프레임당 144.5초가 소요된다. 이는 알고리즘 혁신일 뿐만 아니라 엔지니어링 역량의 표현이다. 단정밀도는 메모리 사용량을 절반으로 줄이지만, 정밀도 손실을 보상하기 위해 기호 야코비 행렬이 필요하며, 이러한 조합은 공개 프로젝트에서 드물다.

3. **재현성을 일급 시민으로**: 사전 컴파일된 Docker 이미지, Windows 네이티브 실행 파일, AWS/GCP/vast.ai 배포 스크립트, GitHub Actions 스트레스 테스트(연속 10회 실행에 지터 추가), 각 예시의 비용 및 프레임 시간표를 제공한다. 이는 "논문 코드"의 전달 기준을 바꾸어, 하류 사용자가 채택할 가치가 있는지 직접 평가할 수 있게 한다.

### 스트레스 테스트
- GitHub Actions에서 대규모를 제외한 모든 예시가 Linux와 Windows에서 연속 10회 실행되며, 각 실행마다 물체 위치에 작은 지터가 적용된다. 단 한 번의 실패도 전체 테스트 스위트 실패로 간주된다.
- 각 단계 종료 시 명시적 교차 검사를 수행하며, 교차가 감지되면 오류를 보고한다. 테스트가 통과하면 모든 단계가 무관통임을 보장한다.

### 결과 의미
- 대규모 예시의 프레임당 시간(46-437초)은 이 시뮬레이션이 **오프라인 시뮬레이션**임을 나타내며, 실시간이 아니다. 그러나 소규모 예시(yarn 0.25분, drape 2.67분 등)는 대화형 속도에 도달할 수 있다.
- 최대 변형률이 1%-10%로 제어되어 변형률 제한 메커니즘이 효과적임을 보여주지만, 예시별 변형률 상한의 차이가 크다(기본 5%, fitting은 10% 허용).

## 경계 및 한계

- **논문에 명시적으로** Elasticity-Inclusive Dynamic Stiffness의 구체적인 공식 유도와 수렴성 증명이 제공되지 않았으며, 프로젝트 설명에서 메커니즘을 추론한 것뿐이다.
- 솔버는 **오프라인 설계**이며 실시간이 아니다. 대규모 예시(large-twist, large-five-twist, large-woven)는 완료에 수일에서 수주가 걸릴 수 있으므로 GitHub Actions 테스트에 포함되지 않았다. 이는 이러한 예시의 안정성이 자동화된 회귀 검증을 거치지 않았음을 의미한다.
- **x86 아키텍처만** 지원하며 arm64는 지원하지 않는다. 문서와 튜토리얼 비디오가 "충분히 정교하지 않으며", 저자는 커뮤니티 기여를 환영한다.
- 프로젝트 유지보수는 **단독 파트타임**(Ryoichi Ando)으로 이루어지며, issue 처리가 느릴 수 있다. 직접 pull request는 받지 않으며(저작권 및 라이선스 문제), issue 또는 fork를 통해 제출해야 한다.
- 메인 브랜치는 자주 업데이트되며 논문과 일치하지 않을 수 있다. 논문 참조 구현은 sigasia-2024 브랜치에 있으며, 유지보수 업데이트만 수행되고 최신 알고리즘 변경은 포함되지 않는다. 이는 논문 결과를 재현하려면 특정 브랜치를 사용해야 함을 의미한다.

## 엔지니어링 시사점

- **브랜치 먼저 확인**: 논문 결과를 재현하는 것이 목표라면 메인 브랜치가 아닌 `sigasia-2024` 브랜치를 반드시 사용해야 한다. 메인 브랜치에는 최신 알고리즘 변경이 포함되어 논문과 일치하지 않을 수 있다.
- **하드웨어 선택**: 대규모 시뮬레이션(>1M 정점)은 RTX 4090 또는 5090이 필요하다. 중소규모(<200K 정점)는 RTX 3090, 4070 또는 5070으로 충분하다. 단정밀도는 VRAM 요구량을 절반으로 줄이지만, CUDA 12.8+ 드라이버 요구 사항에 주의해야 한다.
- **가장 흔한 함정**: 메시 데이터는 프로젝트에 포함되지 않으며, 사용자가 직접 생성하거나 다운로드해야 한다. 이는 "즉시 사용 가능"한 경험이 메시 준비 단계에서 중단됨을 의미한다. 먼저 `yarn` 또는 `drape` 같은 소규모 예시로 환경을 검증한 후 점진적으로 규모를 확대하는 것이 좋다.
- **비용 추정**: AWS L4 인스턴스는 약 $1/시간이며, 소규모 예시 비용은 $0.01-$0.39이다. 대규모 예시는 RTX 4090 기준 vast.ai 비용(<$0.5/시간)으로 추정해야 한다. 그러나 대규모 예시의 프레임당 시간(46-437초)은 2,000프레임 시뮬레이션에 1-10일이 소요됨을 의미하므로, 예산을 사전에 계획해야 한다.
- **로그 API는 디버깅의 핵심 도구**: `time-per-frame`, `newton-steps`, `num-contact`, `max-sigma` 지표를 수용 기준으로 사용해야 한다. `max-sigma`가 변형률 제한을 초과하면 접촉 강성 또는 시간 단계 크기를 조정해야 한다.
