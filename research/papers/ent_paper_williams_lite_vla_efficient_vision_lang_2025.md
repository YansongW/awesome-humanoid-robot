## 概述

LiteVLA 面向 CPU-only 边缘机器人，将视觉-语言-动作（VLA）系统从云端 GPU 部署转向机载实时控制。作者基于 SmolVLM-256M 骨干，通过 LoRA 微调、4-bit NF4 量化与混合精度设计，在 Raspberry Pi 4 上实现约 11.11 秒/查询的推理延迟，并集成 ROS 2 完成 TurtleBot 4 的移动控制。核心贡献在于验证了受限硬件上端到端 VLA 自主性的可行性，同时明确量化与延迟的工程边界。

## 它改变了什么

现有 VLA 系统（PaLM-E、RT-2）依赖云端算力与大规模预训练，在野外、地下等无基础设施场景中完全失效。作者真正改变的，是将 VLA 从“远程大脑”变为“机载反射”——不是简单压缩模型，而是重新设计推理与控制的耦合方式，使 CPU 上的慢推理（0.09 Hz）仍能驱动实时运动。这打破了此前 SmolVLA 仅验证静态机械臂异步控制的局限，首次在移动机器人上实现“边想边动”的闭环。

但这一改变并非免费：推理延迟从 GPU 的毫秒级变为 CPU 的分钟级（FP32 下约 18 分钟/前向），迫使作者引入量化与动作分块（Action Chunking）来弥合感知-执行时间差。其本质是牺牲单步决策质量换取系统级可行性，这为后续边缘 VLA 设计设定了新的权衡基准。

## 方法拆解

### 数据采集与对齐
- 通过遥操作 TurtleBot 4 采集 RGB 图像与动作命令，形成时间序列 𝒯 = {(I_t, a_t, τ_t)}，用时间戳 τ_t 同步视觉与运动，确保一一对应。
- 预处理：图像 resize 至 224×224，归一化 normalize(I_t) = (I_t − μ)/σ，随机水平翻转增强。
- 数据集划分：训练集与验证集比例 0.85 : 0.15。

### 微调策略
- 使用 LoRA（rank r = 8，缩放 α = 8，dropout p = 0.1）微调 SmolVLM-256M 骨干，适配器仅应用于 transformer 投影层（query、key、value、output、gating），冻结其余参数。
- 目标函数：𝔼_{(I_t,a_t)∼D_train}[ℒ(f_{Θ_0+Δ_LoRA}(I_t), a_t)]，在 CPU 后端训练约 2 个 epoch。

### 量化与推理
- 采用 4-bit NF4 量化，混合精度设计（NF4 骨干 + FP32 投影头），通过 llama-cpp 运行时实现 CPU-only 推理。
- 全量化（NF4 投影头）导致输出不稳定，故投影头保留 FP32——这是关键设计决策，牺牲部分压缩率换取语义输出可靠性。

### 控制闭环
- 推理输出语义动作字符串（如 forward_0.2_3.0s 或 turn_left_0.1_2.5s），解析后发布为 geometry_msgs/Twist 命令。
- 使用 Action Chunking：低层运动控制器在高层次推理异步运行时保持可预测控制，弥补 0.09 Hz 推理频率与实时执行之间的鸿沟。

## 关键创新

1. **CPU-only 端到端 VLA 闭环**：首次在无 GPU/NPU 的 Raspberry Pi 4 上实现移动机器人实时自主控制，而非仅静态操作。这改变了边缘机器人对云端推理的依赖范式，为灾害区、地下设施等场景提供了自包含方案。

2. **混合精度量化策略**：发现全量化（NF4 投影头）导致幻觉输出，而保留投影头 FP32 可稳定推理。这一发现挑战了“全量化无损”的普遍假设，为边缘 VLA 的量化边界提供了实证依据。

3. **动作分块与慢推理解耦**：通过语义动作字符串（含时长参数）与底层 Twist 命令的异步执行，使 11.11 秒/查询的推理速率仍能驱动连续运动。这是对“实时性”定义的重新诠释——系统级实时而非单步实时。

## 实验与结果

| 配置 | 推理延迟（Raspberry Pi 4 CPU） | 备注 |
|------|-------------------------------|------|
| SmolVLM-256（FP32） | ∼ 11 s | 基线，未微调 |
| LiteVLA（FP32，未量化） | ∼ 18 min | 实时控制不可行 |
| LiteVLA（混合精度，4b + FP32） | ∼ 2 min | 稳定，9× 加速 |
| LiteVLA（NF4 全量化，4b） | ∼ 1.5 min | 输出不稳定 |

- 训练数据：15083 个图像-动作对（总采集超 60000 帧，实验用约 13000 张），子集含 1152 个后退样本，前、左、右、停止各约 2990 个。
- 量化效果：4-bit NF4 实现约 75% 内存降低，最高 9× 推理加速（由表内 18 min → 2 min 计算）。
- 系统平均每查询 VLA 推理延迟约 11.11 秒（0.09 Hz）。

结果含义：混合精度是唯一可行的工程折中——全量化虽快但不可用，FP32 虽准但太慢。9× 加速（由表内 18 min → 2 min 计算）足以将推理从“不可用”拉入“可实验”区间，但 0.09 Hz 仍远低于人类操作频率，动作分块是弥补这一差距的关键。

## 边界与局限

- 推理延迟受限于 Raspberry Pi 4 CPU 算力，FP32 模型约 18 分钟/前向传播，实时控制不可行——论文未明确在更强 CPU（如 x86 边缘设备）上的扩展性。
- 全量化投影头导致严重退化，产生不稳定或幻觉输出，因此所有实验保留 FP32 投影头——量化压缩表征粒度，偶尔导致粗粒度动作预测。
- 硬件限制：RGB 帧采集、归一化和量化模型执行竞争同一 CPU 核心，持续运行下出现延迟尖峰；热降频导致 CPU 频率缩放和时序不一致；内存带宽限制批次大小和上下文长度，时间推理限于单帧视野。
- 训练数据仅来自手动遥操作，可能未覆盖真实世界导航条件的全部多样性，模型对非结构化或室外环境的泛化仍是开放问题。
- 未在无人机上实验（仅提出路线图）；未实现自主导航于未见环境；未进行多智能体、多模态融合、持续/RL、联邦安全等后续阶段实验。

## 工程启示

- **先核对推理延迟预算**：若目标平台 CPU 弱于 Raspberry Pi 4（1.5 GHz 四核），混合精度配置可能仍不够快；若强于，可尝试减少动作分块长度以提升响应性。
- **投影头必须保持 FP32**：这是最容易踩坑处——盲目全量化会得到看似更快但输出幻觉的模型。复现时务必检查 GGUF 量化配置中投影头的精度设置。
- **数据采集需覆盖动作多样性**：当前子集（1,152 后退 vs 2,990 前进）存在明显不平衡，复现时应平衡各类动作样本，否则模型可能偏向高频动作。
- **热降频是隐性杀手**：持续运行下 CPU 频率缩放会导致推理延迟漂移，建议在测试协议中加入预热与温度监控，否则延迟数据不可复现。
- **下游团队集成时**：Action Chunking 的时长参数（如 forward_0.2_3.0s）需与底层控制器的时间预算匹配，否则会出现“推理未完成但动作已结束”的窗口期。

## 개요
Lite VLA는 GPS 제약 환경에서 엣지 로봇의 자원 효율적 추론 요구를 위해, 통합형 컴팩트 비전-언어 모델과 다중 모달 인식을 결합한 프레임워크를 제안한다. 이 프레임워크는 전통적 방식이 인식과 운동을 분리하던 한계를 극복하여, 로봇이 온보드 하드웨어만으로 동적 환경에서 이동과 추론을 동시에 수행할 수 있게 한다. 실험 검증 결과, 이 시스템은 작업 정확도를 유지하면서도 계산 오버헤드를 크게 줄여, 소형 VLM의 엣지 배포 성공 사례 중 초기 사례로 자리 잡았다. 이 작업은 서비스 로봇, 재난 대응, 국방 등의 분야에서 확장 가능한 자율성의 기반을 마련한다.

### 방법 아키텍처

- **혁신 포인트**: 인식과 운동 제어의 실시간 협력을 구현하여, 로봇이 이동 중에도 단계적 처리가 아닌 동시에 장면 추론을 수행한다.

### 실험 설정
- **하드웨어 플랫폼**: CPU 기반 이동 로봇으로, 온보드 계산 자원만 사용한다.
- **평가 지표**: 계산 효율성(추론 지연 시간), 작업 정확도(장면 이해 및 동작 실행), 시스템 응답 속도(엔드투엔드 지연 시간).

### 핵심 수치 및 결론
- **성능 균형**: 실험을 통해 엄격한 계산 제약 조건에서도 모델이 높은 작업 정확도와 낮은 지연 응답을 동시에 유지할 수 있음을 입증한다.
- **배포 검증**: 이동 로봇에서 소형 VLM의 동시 추론과 운동 제어를 성공적으로 구현하여, 엣지 자율 시스템의 최초 재현 가능 사례를 제공한다.
- **응용 전망**: 서비스 로봇, 재난 구조, 국방 등 로컬 실시간 의사 결정이 필요한 시나리오에 적합하다.
