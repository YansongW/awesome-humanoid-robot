## 概述

vS-Graphs 是一个基于 ORB-SLAM 3.0 的实时 RGB-D 视觉 SLAM 框架，通过新增建筑构件识别与结构元素识别两个线程，将墙面、地面、房间、走廊等语义实体作为约束紧密耦合进 SLAM 优化，构建层次化 3D 场景图。在标准基准与自建数据集上，相比最先进 VSLAM 方法平均降低轨迹误差 3.38%，真实世界序列最高降低 9.58%，且仅凭视觉特征达到与 LiDAR 方法相当的语义检测精度。

## 它改变了什么

现有 VSLAM 系统在“语义丰富且可解释的地图”这一目标上长期停滞：要么只做像素级语义标注（如语义分割），要么将场景图作为后处理输出而不参与优化（如 Hydra）。S-Graphs 虽然证明了场景图约束能提升 LiDAR SLAM 精度，但视觉方案一直缺乏同等深度的耦合——视觉特征噪声大、平面提取不稳定，导致多数方法选择“先建图、后理解”的松耦合路线。vS-Graphs 真正改变的是：将房间、走廊这类高层结构实体直接作为图优化中的顶点与边，让语义理解反向约束相机位姿与地图几何，而非仅仅作为可视化副产品。这意味着地图不再只是“带标签的点云”，而是可优化、可推理的结构化表示，且这一过程在实时性（22 FPS）上首次达到实用门槛。

## 方法拆解

### 系统架构
基于 ORB-SLAM 3.0 多线程框架，新增两个核心线程：
- **Building Component Recognition**（关键帧级别）：识别墙面与地面
- **Structural Element Recognition**（每 2 秒周期）：推断房间与走廊

### 建筑构件识别流程
1. **语义过滤**：使用 YOSO 实时全景分割，仅保留墙（wall）和地面（floor）类别，得到点集 P̂_ψ^K = {p_j | L_pj ∈ Ψ}
2. **预处理**：下采样降噪，再按距离过滤（θ_min ≤ ‖p_ζ‖ ≤ θ_max）
3. **平面拟合**：RANSAC 提取平面 π，法向量 n ∈ ℝ³，满足 d(p_r, π) ≤ ε
4. **结构验证**：墙必须垂直（法向量水平），地面必须水平（法向量垂直）

### 结构元素识别
- **走廊判定**：两面平行相对墙（法向量夹角满足 n_wall^Ki · n_wall^Kj ≥ cos(ϑ)）+ 一垂直地面
- **房间判定**：四面墙组成两对平行相对表面（式13：n_wall^a · n_wall^b ≥ cos(ϑ) 且 |n_wall^a · n_wall^c| ≤ sin(ϑ)）+ 包围地面
- **关联条件**：欧氏距离 ≤ ρ 且法向量夹角 ≤ η

### 优化约束
- 走廊顶点代价（式12）：c_{δ_c^K} = Σ_t ||ν̂_c - f(π_wall^{Ki}, π_wall^{Kj}, π_ground^{Kq}, ϱ_w, ϱ_g)||²_{Λ}
- 房间顶点代价（式14）：c_{δ_r^K} = Σ_t ||ν̂_r - f(Π_p1, Π_p2, π_ground^{Kq}, ϱ_w, ϱ_g)||²_{Λ}
- 标记约束（式15）：σ_m(^G K, m_i^K) = ||^L m_i ⊞ ^G K ⊟ ^G m_{i1}||²_{Λ}，但标记不主导建图，仅作语义增强

### 关键设计决策
- 结构元素每 2 秒运行一次，避免每帧计算的高开销
- 标记检测独立于主线程，且不依赖标记存在（区别于 [24,25]）
- 所有语义实体以马氏距离形式加入因子图，与视觉里程计因子联合优化

## 关键创新

1. **场景图参与优化而非后处理**：Hydra 等视觉方法构建场景图但不回馈优化；vS-Graphs 将房间/走廊质心作为可优化顶点，其代价函数直接耦合墙面参数与地面参数，形成闭环约束。这是视觉 SLAM 中首次实现高层结构实体与底层几何的紧耦合。

2. **纯视觉达到 LiDAR 级语义精度**：表 2 显示，vS-Graphs 在建筑构件检测上（如 office-suite：P=0.94, R=1.00）与基于 LiDAR 的 S-Graphs（P=0.89, R=0.94）相当甚至更优，且无需任何深度传感器以外的硬件。这打破了“视觉语义检测精度不足”的固有假设。

3. **层次化表示的可扩展性**：场景图结构（图 3）将低层几何（点云、平面）与高层语义（房间、走廊）分层组织，支持增量式地图扩展。相比稠密重建，vS-Graphs 生成地图平均少 10.15% 的点，却携带更丰富的结构化信息，为下游导航、交互提供直接可用的拓扑语义。

## 边界与局限

- **仅支持 RGB-D 输入**：未提及单目或双目适配，限制了室外与低成本传感器场景
- **平面假设强**：依赖墙面/地面为平面，弯曲墙面（图 8a）或非规则几何环境无法处理
- **低纹理场景脆弱**：均匀涂漆走廊导致特征匹配失败，误差传播至高层结构识别
- **语义误分类无容错**：分割错误（图 8b）直接产生错误场景图，无检测置信度反馈机制
- **关联阈值敏感**：过松/过紧的 ρ、η 阈值显著影响构件识别（图 8c-8d），未提供自适应策略
- **未做动态环境与室外测试**：论文未明确
- **无计算资源量化**：GPU 显存占用、CPU 负载等未报告

## 工程启示

- **复现优先核对三点**：① YOSO 分割模型权重与输入分辨率——直接影响墙/地面点云质量；② 关联阈值 ρ（欧氏距离）与 η（法向量夹角）——论文未给默认值，需按场景标定；③ 结构元素识别周期（2 秒）与关键帧频率的匹配，避免漏检短走廊。
- **最易踩坑**：RANSAC 平面拟合的 ε 阈值。视觉点云噪声大，ε 过小导致墙面断裂，过大则误合并不同平面。建议先统计点云到拟合平面的残差分布再定阈值。
- **下游集成建议**：场景图顶点（房间/走廊质心）可直接作为导航拓扑节点，但需注意 vS-Graphs 当前不含“floor”实体（作者明确剔除），若下游需要地面语义需自行扩展。
- **性能取舍参考**：若任务对帧率敏感（如无人机避障），22 FPS 可能不足；可考虑降低结构元素识别频率（如 3-4 秒）或仅在关键帧触发，换取更高跟踪帧率。
- **标记使用策略**：ArUco 标记仅作语义增强（如房间标签），不参与位姿约束。若需绝对尺度或闭环增强，需自行添加标记约束权重。

## Overview

vS-Graphs is a real-time RGB-D visual SLAM framework based on ORB-SLAM 3.0. It adds two threads for building component recognition and structural element recognition, tightly coupling semantic entities such as walls, floors, rooms, and corridors into SLAM optimization as constraints to build a hierarchical 3D scene graph. On standard benchmarks and self-collected datasets, it reduces trajectory error by an average of 3.38% compared to state-of-the-art VSLAM methods, with up to 9.58% reduction on real-world sequences, and achieves semantic detection accuracy comparable to LiDAR-based methods using only visual features.

## What It Changes

Existing VSLAM systems have long stalled on the goal of "semantically rich and interpretable maps": they either only perform pixel-level semantic annotation (e.g., semantic segmentation) or treat scene graphs as post-processing outputs without participating in optimization (e.g., Hydra). While S-Graphs demonstrated that scene graph constraints can improve LiDAR SLAM accuracy, visual approaches have lacked equally deep coupling—visual features are noisy and plane extraction is unstable, leading most methods to adopt a loose-coupling approach of "first map, then understand." What vS-Graphs truly changes is: directly using high-level structural entities such as rooms and corridors as vertices and edges in graph optimization, allowing semantic understanding to inversely constrain camera pose and map geometry, rather than merely serving as a visualization byproduct. This means the map is no longer just a "labeled point cloud" but an optimizable, inferable structured representation, and this process reaches practical usability in real time (22 FPS) for the first time.

## Method Breakdown

### System Architecture
Built on the ORB-SLAM 3.0 multi-threaded framework, two core threads are added:
- **Building Component Recognition** (keyframe level): identifies walls and floors
- **Structural Element Recognition** (every 2 seconds): infers rooms and corridors

### Building Component Recognition Pipeline
1. **Semantic Filtering**: Uses YOSO real-time panoptic segmentation, retaining only wall and floor categories, yielding point set P̂_ψ^K = {p_j | L_pj ∈ Ψ}
2. **Preprocessing**: Downsampling for noise reduction, followed by distance filtering (θ_min ≤ ‖p_ζ‖ ≤ θ_max)
3. **Plane Fitting**: RANSAC extracts plane π with normal vector n ∈ ℝ³, satisfying d(p_r, π) ≤ ε
4. **Structural Validation**: Walls must be vertical (normal vector horizontal), floors must be horizontal (normal vector vertical)

### Structural Element Recognition
- **Corridor detection**: Two parallel opposing walls (normal vectors satisfying n_wall^Ki · n_wall^Kj ≥ cos(ϑ)) + one perpendicular floor
- **Room detection**: Four walls forming two pairs of parallel opposing surfaces (Eq. 13: n_wall^a · n_wall^b ≥ cos(ϑ) and |n_wall^a · n_wall^c| ≤ sin(ϑ)) + enclosing a floor
- **Association conditions**: Euclidean distance ≤ ρ and normal vector angle ≤ η

### Optimization Constraints
- Corridor vertex cost (Eq. 12): c_{δ_c^K} = Σ_t ||ν̂_c - f(π_wall^{Ki}, π_wall^{Kj}, π_ground^{Kq}, ϱ_w, ϱ_g)||²_{Λ}
- Room vertex cost (Eq. 14): c_{δ_r^K} = Σ_t ||ν̂_r - f(Π_p1, Π_p2, π_ground^{Kq}, ϱ_w, ϱ_g)||²_{Λ}
- Marker constraint (Eq. 15): σ_m(^G K, m_i^K) = ||^L m_i ⊞ ^G K ⊟ ^G m_{i1}||²_{Λ}, but markers do not dominate mapping, serving only as semantic enhancement

### Key Design Decisions
- Structural elements run every 2 seconds to avoid the high cost of per-frame computation
- Marker detection is independent of the main thread and does not rely on marker presence (unlike [24,25])
- All semantic entities are added to the factor graph in Mahalanobis distance form, jointly optimized with visual odometry factors

## Key Innovations

1. **Scene graph participates in optimization rather than post-processing**: Visual methods like Hydra build scene graphs but do not feed back into optimization; vS-Graphs treats room/corridor centroids as optimizable vertices whose cost functions directly couple wall and floor parameters, forming closed-loop constraints. This is the first tight coupling of high-level structural entities with low-level geometry in visual SLAM.

2. **Pure vision achieves LiDAR-level semantic accuracy**: Table 2 shows vS-Graphs achieves comparable or better building component detection (e.g., office-suite: P=0.94, R=1.00) compared to LiDAR-based S-Graphs (P=0.89, R=0.94), without any hardware beyond depth sensors. This breaks the long-held assumption that "visual semantic detection accuracy is insufficient."

3. **Scalability of hierarchical representation**: The scene graph structure (Fig. 3) organizes low-level geometry (point clouds, planes) and high-level semantics (rooms, corridors) hierarchically, supporting incremental map expansion. Compared to dense reconstruction, vS-Graphs generates maps with an average of 10.15% fewer points while carrying richer structured information, providing directly usable topological semantics for downstream navigation and interaction.

## Experiments and Results

Experiments were conducted on vS-Graphs (a real-time RGB-D VSLAM framework built on ORB-SLAM 3.0), comparing trajectory estimation accuracy against three baselines—ORB-SLAM 3.0, BAD SLAM, and ElasticFusion—and comparing scene understanding performance against LiDAR-based S-Graphs and Hydra. Evaluation used four public benchmark datasets—ICL, OpenLORIS, ScanNet, TUM-RGBD—as well as the self-collected AutoSense real-world dataset (with LiDAR ground truth). Each system was run 8 times on dataset instances, with Absolute Trajectory Error (ATE, in meters) as the metric; scene understanding was evaluated using Precision and Recall for building components (BC) and structural elements (SE) detection accuracy; mapping accuracy was measured by Root Mean Square Error (RMSE); and runtime was recorded in FPS. Marker-dependent methods and neural field SLAM were excluded to ensure direct comparability.

## Boundaries and Limitations

- **RGB-D input only**: No monocular or stereo adaptation is mentioned, limiting outdoor and low-cost sensor scenarios
- **Strong planarity assumption**: Relies on walls/floors being planar; curved walls (Fig. 8a) or non-regular geometric environments cannot be handled
- **Fragile in low-texture scenes**: Uniformly painted corridors cause feature matching failures, with errors propagating to high-level structure recognition
- **No tolerance for semantic misclassification**: Segmentation errors (Fig. 8b) directly produce incorrect scene graphs, with no detection confidence feedback mechanism
- **Sensitive association thresholds**: Overly loose or tight ρ, η thresholds significantly affect component recognition (Fig. 8c-8d), with no adaptive strategy provided
- **No dynamic environment or outdoor testing**: Not explicitly addressed in the paper
- **No computational resource quantification**: GPU memory usage, CPU load, etc., are not reported

## Engineering Insights

- **Three key points to verify first for reproduction**: ① YOSO segmentation model weights and input resolution—directly affect wall/floor point cloud quality; ② Association thresholds ρ (Euclidean distance) and η (normal vector angle)—the paper does not provide default values, requiring scene-specific calibration; ③ Matching between the structural element recognition period (2 seconds) and keyframe frequency to avoid missing short corridors.
- **Most common pitfall**: The ε threshold in RANSAC plane fitting. Visual point clouds are noisy; too small ε causes wall fragmentation, while too large ε incorrectly merges different planes. It is recommended to first analyze the residual distribution of point clouds relative to the fitted plane before setting the threshold.
- **Downstream integration suggestion**: Scene graph vertices (room/corridor centroids) can directly serve as navigation topology nodes, but note that vS-Graphs currently does not include "floor" entities (explicitly excluded by the authors); if floor semantics are needed downstream, they must be extended.
- **Performance trade-off reference**: If the task is frame-rate sensitive (e.g., drone obstacle avoidance), 22 FPS may be insufficient; consider reducing the structural element recognition frequency (e.g., to 3-4 seconds) or triggering only on keyframes to achieve higher tracking frame rates.
- **Marker usage strategy**: ArUco markers serve only as semantic enhancement (e.g., room labels) and do not participate in pose constraints. If absolute scale or loop closure enhancement is needed, marker constraint weights must be added manually.

## 개요

vS-Graphs는 ORB-SLAM 3.0 기반의 실시간 RGB-D 비주얼 SLAM 프레임워크로, 건축 구성 요소 인식과 구조 요소 인식이라는 두 개의 스레드를 추가하여 벽, 바닥, 방, 복도 등의 의미론적 개체를 제약 조건으로 SLAM 최적화에 긴밀하게 결합하고 계층적 3D 장면 그래프를 구축합니다. 표준 벤치마크와 자체 구축 데이터셋에서 최신 VSLAM 방법 대비 평균 궤적 오차를 3.38% 줄였으며, 실제 세계 시퀀스에서는 최대 9.58%까지 감소시켰고, 시각적 특징만으로 LiDAR 기반 방법과 동등한 의미론적 탐지 정확도를 달성했습니다.

## 무엇이 바뀌었는가

기존 VSLAM 시스템은 "의미론적으로 풍부하고 해석 가능한 지도"라는 목표에서 오랫동안 정체되어 있었습니다: 픽셀 수준의 의미론적 주석(예: 의미론적 분할)만 수행하거나, 장면 그래프를 최적화에 참여시키지 않는 후처리 출력으로만 사용했습니다(예: Hydra). S-Graphs는 장면 그래프 제약이 LiDAR SLAM 정확도를 향상시킬 수 있음을 증명했지만, 비주얼 방식은 동등한 수준의 결합이 부족했습니다—시각적 특징은 노이즈가 많고 평면 추출이 불안정하여 대부분의 방법이 "먼저 지도 구축, 이후 이해"라는 느슨한 결합 방식을 선택했습니다. vS-Graphs가 진정으로 바꾼 것은: 방, 복도와 같은 고수준 구조 개체를 그래프 최적화의 정점과 간선으로 직접 사용하여 의미론적 이해가 카메라 포즈와 지도 기하학을 역으로 제약하게 한 것입니다. 단순한 시각화 부산물이 아니라 말입니다. 이는 지도가 더 이상 "레이블이 붙은 포인트 클라우드"가 아니라 최적화 가능하고 추론 가능한 구조화된 표현임을 의미하며, 이 과정이 실시간성(22 FPS)에서 처음으로 실용적 기준을 충족했습니다.

## 방법 분석

### 시스템 아키텍처
ORB-SLAM 3.0 멀티스레드 프레임워크 기반으로 두 개의 핵심 스레드를 추가합니다:
- **건축 구성 요소 인식**(키프레임 수준): 벽과 바닥 인식
- **구조 요소 인식**(2초 주기): 방과 복도 추론

### 건축 구성 요소 인식 프로세스
1. **의미론적 필터링**: YOSO 실시간 범주형 분할을 사용하여 벽(wall)과 바닥(floor) 범주만 유지, 포인트 집합 P̂_ψ^K = {p_j | L_pj ∈ Ψ} 획득
2. **전처리**: 다운샘플링으로 노이즈 제거 후 거리 필터링(θ_min ≤ ‖p_ζ‖ ≤ θ_max)
3. **평면 피팅**: RANSAC으로 평면 π 추출, 법선 벡터 n ∈ ℝ³, d(p_r, π) ≤ ε 충족
4. **구조 검증**: 벽은 수직(법선 벡터 수평), 바닥은 수평(법선 벡터 수직)

### 구조 요소 인식
- **복도 판정**: 두 개의 평행한 마주보는 벽(법선 벡터 각도가 n_wall^Ki · n_wall^Kj ≥ cos(ϑ) 충족) + 하나의 수직 바닥
- **방 판정**: 네 개의 벽이 두 쌍의 평행한 마주보는 표면(식 13: n_wall^a · n_wall^b ≥ cos(ϑ) 및 |n_wall^a · n_wall^c| ≤ sin(ϑ)) + 바닥을 둘러쌈
- **연관 조건**: 유클리드 거리 ≤ ρ 및 법선 벡터 각도 ≤ η

### 최적화 제약
- 복도 정점 비용(식 12): c_{δ_c^K} = Σ_t ||ν̂_c - f(π_wall^{Ki}, π_wall^{Kj}, π_ground^{Kq}, ϱ_w, ϱ_g)||²_{Λ}
- 방 정점 비용(식 14): c_{δ_r^K} = Σ_t ||ν̂_r - f(Π_p1, Π_p2, π_ground^{Kq}, ϱ_w, ϱ_g)||²_{Λ}
- 마커 제약(식 15): σ_m(^G K, m_i^K) = ||^L m_i ⊞ ^G K ⊟ ^G m_{i1}||²_{Λ}, 그러나 마커는 지도 구축을 지배하지 않으며 의미론적 강화만 수행

### 핵심 설계 결정
- 구조 요소는 2초마다 실행되어 프레임별 계산의 높은 오버헤드 방지
- 마커 감지는 메인 스레드와 독립적이며 마커 존재에 의존하지 않음([24,25]와 차별화)
- 모든 의미론적 개체는 마할라노비스 거리 형태로 팩터 그래프에 추가되어 시각적 오도메트리 팩터와 공동 최적화

## 핵심 혁신

1. **장면 그래프가 후처리가 아닌 최적화에 참여**: Hydra와 같은 비주얼 방법은 장면 그래프를 구축하지만 최적화에 피드백하지 않습니다; vS-Graphs는 방/복도 질량 중심을 최적화 가능한 정점으로 사용하며, 그 비용 함수가 벽 파라미터와 바닥 파라미터를 직접 결합하여 폐루프 제약을 형성합니다. 이는 비주얼 SLAM에서 고수준 구조 개체와 저수준 기하학의 긴밀한 결합을 최초로 구현한 것입니다.

2. **순수 비주얼로 LiDAR급 의미론적 정확도 달성**: 표 2는 vS-Graphs가 건축 구성 요소 탐지(예: office-suite: P=0.94, R=1.00)에서 LiDAR 기반 S-Graphs(P=0.89, R=0.94)와 동등하거나 더 우수함을 보여주며, 깊이 센서 외의 추가 하드웨어가 필요 없습니다. 이는 "비주얼 의미론적 탐지 정확도 부족"이라는 기존 가정을 깨뜨립니다.

3. **계층적 표현의 확장성**: 장면 그래프 구조(그림 3)는 저수준 기하학(포인트 클라우드, 평면)과 고수준 의미론(방, 복도)을 계층적으로 구성하여 증분식 지도 확장을 지원합니다. 조밀한 재구성과 비교하여 vS-Graphs가 생성하는 지도는 평균 10.15% 적은 포인트를 가지면서도 더 풍부한 구조화된 정보를 담고 있어, 다운스트림 내비게이션과 상호작용에 직접 사용 가능한 토폴로지 의미론을 제공합니다.

- **궤적 정확도 전반적 향상**: vS-Graphs는 27개 시퀀스 중 18개에서 ORB-SLAM 3.0보다 우수한 결과를 얻었으며 평균 3.38% 향상(표 내 각 시퀀스 Diff. 합산 계산), 실제 세계 AutoSense 데이터셋의 room-corrdr 시퀀스에서 최대 9.58% 향상(표 내 0.240→0.217 계산)을 달성했습니다. 이러한 이점은 긴 실제 세계 시퀀스에서 특히 두드러지며, 정밀하게 국소화된 건축 구성 요소와 구조 요소 제약의 통합에 기인합니다; 빠른 카메라 움직임(deer-gr)과 노이즈가 많은 포인트 클라우드(office1-7) 시나리오에서는 부정확한 지도 구축과 위치 추정이 결과에 부정적인 영향을 미쳤습니다.
- **시각적 특징으로 LiDAR급 장면 이해 달성**: vS-Graphs는 시각적 입력만으로 건축 구성 요소와 구조 요소 탐지 정확도에서 LiDAR 기반 S-Graphs와 동등한 수준(BC 정밀도 0.86–0.94 대 0.89–1.00, SE 정밀도 모두 1.00)에 도달하여 시각적 특징 처리와 장면 그래프 생성의 효과성을 검증했습니다. Hydra는 "wall" 개체를 직접 제공하지 않아 "room" 요소만으로 성능이 평가되었습니다; vS-Graphs의 현재 구현에는 "floor" 개체가 포함되지 않아 분석에서 제외되었습니다.
- **실시간성과 지도 구축 효율성의 균형**: vS-Graphs는 22 ± 3 FPS로 실행되어 20 FPS 실시간 임계값을 초과하지만 ORB-SLAM 3.0의 29 ± 3 FPS보다는 약간 낮습니다. 그러나 약 10.15% 더 적은 지도 포인트로 더 견고한 RMSE(논문은 구체적인 RMSE 수치를 명시하지 않음)를 달성하여 풍부한 의미론적 장면 이해를 위한 합리적인 절충으로 간주됩니다. 낮은 텍스처 시나리오(예: 균일하게 페인트된 복도)는 특징 매칭에 영향을 미치며, 평면 표면 탐지에 의존하는 것은 비정형 기하학 환경에서의 적용성을 제한합니다.

## 경계 및 한계

- **RGB-D 입력만 지원**: 단안 또는 스테레오 적응에 대한 언급이 없어 실외 및 저비용 센서 시나리오가 제한됨
- **평면 가정 강함**: 벽/바닥이 평면임을 가정하여 곡선 벽(그림 8a) 또는 비정형 기하학 환경을 처리할 수 없음
- **낮은 텍스처 시나리오에서 취약**: 균일하게 페인트된 복도는 특징 매칭 실패를 유발하며 오류가 고수준 구조 인식으로 전파됨
- **의미론적 오분류에 대한 내결함성 없음**: 분할 오류(그림 8b)는 잘못된 장면 그래프를 직접 생성하며 탐지 신뢰도 피드백 메커니즘이 없음
- **연관 임계값에 민감**: 너무 느슨하거나 너무 엄격한 ρ, η 임계값은 구성 요소 인식에 큰 영향을 미치며(그림 8c-8d), 적응형 전략이 제공되지 않음
- **동적 환경 및 실외 테스트 미수행**: 논문에 명시되지 않음
- **계산 리소스 정량화 없음**: GPU 메모리 사용량, CPU 부하 등이 보고되지 않음

## 엔지니어링 시사점

- **재현 시 우선 확인할 세 가지**: ① YOSO 분할 모델 가중치와 입력 해상도—벽/바닥 포인트 클라우드 품질에 직접 영향; ② 연관 임계값 ρ(유클리드 거리)와 η(법선 벡터 각도)—논문에 기본값이 없으므로 시나리오별 보정 필요; ③ 구조 요소 인식 주기(2초)와 키프레임 빈도의 일치—짧은 복도 누락 방지.
- **가장 함정에 빠지기 쉬운 부분**: RANSAC 평면 피팅의 ε 임계값. 시각적 포인트 클라우드는 노이즈가 많아 ε이 너무 작으면 벽이 끊어지고, 너무 크면 다른 평면이 잘못 병합됩니다. 포인트 클라우드에서 피팅 평면까지의 잔차 분포를 먼저 통계적으로 확인한 후 임계값을 결정하는 것이 좋습니다.
- **다운스트림 통합 제안**: 장면 그래프 정점(방/복도 질량 중심)은 내비게이션 토폴로지 노드로 직접 사용할 수 있지만, vS-Graph스의 현재 버전에는 "floor" 개체가 포함되지 않으므로(저자가 명시적으로 제외) 다운스트림에서 바닥 의미론이 필요하면 직접 확장해야 합니다.
- **성능 절충 참고**: 프레임 속도에 민감한 작업(예: 드론 장애물 회피)에서는 22 FPS가 부족할 수 있습니다; 구조 요소 인식 빈도를 낮추거나(예: 3-4초) 키프레임에서만 트리거하여 더 높은 추적 프레임 속도를 얻을 수 있습니다.
- **마커 사용 전략**: ArUco 마커는 의미론적 강화(예: 방 레이블)에만 사용되며 포즈 제약에는 참여하지 않습니다. 절대 스케일이나 폐루프 강화가 필요하면 마커 제약 가중치를 직접 추가해야 합니다.
