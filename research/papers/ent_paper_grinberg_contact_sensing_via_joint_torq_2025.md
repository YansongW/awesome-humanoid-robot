## 概述

本文提出一种融合分布式关节力矩传感器与单个髋部力/力矩（FT）传感器的足式机器人腿部接触检测与定位框架，基于广义动量观测器实现无需复杂摩擦建模的实时接触感知。作者来自美国高校（受NSF资助），核心贡献在于利用基座FT传感器补足关节力矩信息在运动链上的累积模糊性，实现亚厘米级接触定位与低于0.2 N的力估计误差。

## 它改变了什么

足式机器人接触感知长期被简化为“足端触觉”问题，但大腿和小腿的非预期碰撞在杂乱环境中是稳定性破坏的主要来源。现有方案要么依赖电机电流估计力矩（受非线性摩擦、背隙、迟滞影响严重），要么依赖触觉皮肤（更新率慢、硬件脆弱、不适合高冲击工况），要么仅用广义动量观测器检测碰撞却无法定位到具体连杆。本文真正改变的是：将“检测”升级为“检测+定位+力估计”的完整闭环，且不引入任何摩擦模型——这是工程实用性的关键跃迁。

更本质的突破在于对信息论层面的补全：仅靠2-DoF关节力矩传感器，外部力的三个未知数（F_x, F_z, 接触位置p_c）在数学上不可解。作者没有增加更多关节力矩传感器（成本高、布线复杂），而是巧妙地在髋部加装单个商用FT传感器，用基座处的完整力/力矩读数闭合方程。这种“分布式关节传感+单点基座传感”的混合架构，在成本、复杂度和信息完整性之间找到了实用平衡点。

## 方法拆解

### 1. 广义动量观测器（残差计算）
- 机器人动力学：M(q)q̈ + C(q,q̇)q̇ + g(q) + τ_ext = τ_sen
- 利用性质 Ṁ = C + Cᵀ，定义广义动量 P = M(q)q̇，得到 Ṗ = Cᵀq̇ − g + τ_sen − τ_ext
- 残差观测器：r(t) = K[P(t) − p_int(t) − P₀]，K为对角增益，p_int为积分器状态
- 离散化更新：p_int(t+Δt) = p_int(t) + [u + r(t)]Δt，其中 u = Cᵀq̇ − g + τ_sen
- 碰撞判定：‖r(t)‖ > ε_res（阈值取0.06）

### 2. 碰撞连杆识别
- 对n连杆开链，碰撞发生在连杆c时，前c个残差分量上升，远端残差保持为零
- 识别规则：c = max{i ∈ {1,…,n} : |r_i(t)| > ε_res}

### 3. 基座FT传感器补全接触计算
- 仅靠[τ₁,τ₂]ᵀ无法唯一确定(F_x, F_z, p_c)，基座FT提供Fᵇ := [F_xᵇ, F_yᵇ, M_yᵇ]ᵀ
- 扩展广义坐标含3个虚拟关节[x,y,z]，广义力 w = S(Cq̇ + g − Bτ_sen)，忽略Hq̈（假设关节加速度可忽略）
- 净意外力 Fᵘ = w − Fᵇ，接触力 F_c = −[F_xᵘ, F_zᵘ]ᵀ

### 4. 接触位置求解
- 假设接触点在连杆c的起点p₁和终点p₂之间：p_c = p₁ + α(p₂ − p₁)，α ∈ [0,1]
- 静力矩平衡：M_yᵘ + p_c ∧ F_xzᵘ = 0，解得 α = −(M_yᵘ + p₁ ∧ F_xzᵘ) / ((p₂ − p₁) ∧ F_xzᵘ)
- 若0 ≤ α ≤ 1，则碰撞物理上位于连杆c上

### 5. 硬件实现
- 关节力矩传感器：自制应变片式，全惠斯通电桥，1 kΩ应变片，5 V激励，6061铝制传感器体
- 数据采集：24位ADC（ADS127L21EVM-PDK），Arduino Due经SPI通信，采样率3–4 kSps
- 控制器：PD控制器1 kHz运行，动量碰撞估计连续运行

## 关键创新

1. **混合传感架构**：分布式关节力矩传感器+单个基座FT传感器的组合，在数学上闭合了接触定位问题（3未知数3方程），同时避免了在每条连杆上安装FT传感器的成本与复杂度。这是对“关节力矩传感器信息不足”问题的优雅工程解。

2. **无需摩擦建模的接触定位**：广义动量观测器天然对未建模摩擦鲁棒，残差信号直接反映外部碰撞，无需识别摩擦参数。相比基于电机电流的方法（RMSE 0.1638 Nm vs 0.0317 Nm），精度提升5倍以上，且实现简单。

3. **实时性与精度兼顾**：整个流程（残差计算→连杆识别→力/位置求解）为解析计算，无迭代优化，适合1 kHz控制循环。仿真与硬件实验均验证亚厘米级定位精度（误差<13.5 mm，约为连杆长度7%），力误差<0.15 N（约为施加力2%）。

## 边界与局限

- **共线模糊问题**：当施加外力与局部连杆几何近乎共线时，接触点求解变得病态，解对力或构型的小扰动敏感，误差升高（作者在热图中观察到一条误差升高线）。
- **加速度忽略假设**：基座FT传感器计算中省略Hq̈项，在高速动态运动（如奔跑、跳跃）中该假设可能失效，导致力估计偏差增大。
- **实验范围有限**：仅验证2-DoF平面机械臂，未做多连杆（>2）硬件实验；未涉及动态行走/奔跑工况；未与触觉皮肤方案直接对比。
- **实时性能未量化**：论文未给出计算延迟或吞吐量的定量指标，仅说明“连续运行”。
- **硬件负载限制**：Link 2因执行器力矩较低，测试负载仅0.05–0.1 kg，未覆盖高冲击场景。

## 工程启示

1. **先核对信息完整性**：复现前务必确认你的机器人是否具备“关节力矩传感器+基座FT传感器”的组合。若只有关节力矩传感器，接触定位问题在数学上不可解（3未知数2方程），必须增加传感维度。

2. **摩擦是最大敌人**：电机电流估计力矩的RMSE（0.1638 Nm）是关节力矩传感器（0.0317 Nm）的5倍。若你的执行器有中等以上减速比，强烈建议采用输出轴力矩传感器而非电流估计，否则残差观测器的信噪比会显著恶化。

3. **阈值调参是关键**：残差阈值ε_res = 0.06在本文的物理参数下有效，但该值依赖连杆质量、惯量和传感器噪声水平。建议先用仿真（MATLAB ode45）扫描你的机器人参数，确定合适的阈值范围，再上硬件。

4. **共线退化需规避**：当外力方向与连杆轴线接近平行时，接触位置求解会病态。工程上可加入几何约束（如限制α范围）或融合其他传感（如IMU）来缓解，但论文未提供解决方案。

5. **数据同步是隐性成本**：mjbots控制器、FT传感器、ADC三路数据流需同步后实时转发至MATLAB。建议在架构设计阶段就规划好同步机制（如时间戳对齐），否则实时性会大打折扣。

6. **硬件选型参考**：髋部FT传感器选用PixONE（Bota Systems）仅用平面分量；关节力矩传感器自制（全惠斯通电桥+6061铝），FEA验证0.4 Nm负载下应变。若预算有限，可考虑商用微型力矩传感器，但需注意刚度匹配。

## Overview

This paper proposes a framework for contact detection and localization on legged robot legs that fuses distributed joint torque sensors with a single hip force/torque (FT) sensor. It leverages a generalized momentum observer to achieve real-time contact perception without complex friction modeling. The authors are from U.S. universities (funded by NSF), and the core contribution lies in using the base FT sensor to compensate for the cumulative ambiguity of joint torque information along the kinematic chain, achieving sub-centimeter contact localization and force estimation errors below 0.2 N.

## What It Changes

Contact perception in legged robots has long been simplified as a "foot tactile" problem, but unintended collisions on the thigh and shank are a major source of stability loss in cluttered environments. Existing approaches either rely on motor current for torque estimation (severely affected by nonlinear friction, backlash, and hysteresis), rely on tactile skins (slow update rates, fragile hardware, unsuitable for high-impact conditions), or use generalized momentum observers to detect collisions without localizing them to specific links. What this paper truly changes is upgrading "detection" to a complete closed loop of "detection + localization + force estimation" without introducing any friction model—a critical leap in engineering practicality.

A more fundamental breakthrough lies in completing the information-theoretic picture: with only 2-DoF joint torque sensors, the three unknowns of the external force (F_x, F_z, contact position p_c) are mathematically unsolvable. Rather than adding more joint torque sensors (costly and complex to route), the authors cleverly install a single commercial FT sensor at the hip, using the full force/torque reading at the base to close the equations. This hybrid architecture of "distributed joint sensing + single-point base sensing" strikes a practical balance among cost, complexity, and information completeness.

## Method Breakdown

### 1. Generalized Momentum Observer (Residual Computation)
- Robot dynamics: M(q)q̈ + C(q,q̇)q̇ + g(q) + τ_ext = τ_sen
- Using the property Ṁ = C + Cᵀ, define generalized momentum P = M(q)q̇, yielding Ṗ = Cᵀq̇ − g + τ_sen − τ_ext
- Residual observer: r(t) = K[P(t) − p_int(t) − P₀], where K is a diagonal gain and p_int is the integrator state
- Discrete update: p_int(t+Δt) = p_int(t) + [u + r(t)]Δt, where u = Cᵀq̇ − g + τ_sen
- Collision detection: ‖r(t)‖ > ε_res (threshold set to 0.06)

### 2. Collision Link Identification
- For an n-link open chain, when a collision occurs on link c, the first c residual components rise while distal residuals remain zero
- Identification rule: c = max{i ∈ {1,…,n} : |r_i(t)| > ε_res}

### 3. Base FT Sensor Completing Contact Computation
- With only [τ₁,τ₂]ᵀ, (F_x, F_z, p_c) cannot be uniquely determined; the base FT provides Fᵇ := [F_xᵇ, F_yᵇ, M_yᵇ]ᵀ
- Extend generalized coordinates with 3 virtual joints [x,y,z], generalized force w = S(Cq̇ + g − Bτ_sen), neglecting Hq̈ (assuming joint accelerations are negligible)
- Net unexpected force Fᵘ = w − Fᵇ, contact force F_c = −[F_xᵘ, F_zᵘ]ᵀ

### 4. Contact Position Solution
- Assume the contact point lies between the start p₁ and end p₂ of link c: p_c = p₁ + α(p₂ − p₁), α ∈ [0,1]
- Static moment balance: M_yᵘ + p_c ∧ F_xzᵘ = 0, yielding α = −(M_yᵘ + p₁ ∧ F_xzᵘ) / ((p₂ − p₁) ∧ F_xzᵘ)
- If 0 ≤ α ≤ 1, the collision physically lies on link c

### 5. Hardware Implementation
- Joint torque sensors: custom strain-gauge type, full Wheatstone bridge, 1 kΩ strain gauges, 5 V excitation, 6061 aluminum sensor body
- Data acquisition: 24-bit ADC (ADS127L21EVM-PDK), Arduino Due via SPI communication, sampling rate 3–4 kSps
- Controller: PD controller running at 1 kHz, momentum-based collision estimation running continuously

## Key Innovations

1. **Hybrid Sensing Architecture**: The combination of distributed joint torque sensors and a single base FT sensor mathematically closes the contact localization problem (3 unknowns, 3 equations) while avoiding the cost and complexity of installing FT sensors on every link. This is an elegant engineering solution to the "insufficient joint torque sensor information" problem.

2. **Contact Localization Without Friction Modeling**: The generalized momentum observer is inherently robust to unmodeled friction; the residual signal directly reflects external collisions without requiring friction parameter identification. Compared to motor-current-based methods (RMSE 0.1638 Nm vs 0.0317 Nm), accuracy improves by more than 5× with simpler implementation.

3. **Real-Time Performance and Accuracy Combined**: The entire pipeline (residual computation → link identification → force/position solution) is analytical with no iterative optimization, suitable for 1 kHz control loops. Both simulation and hardware experiments validate sub-centimeter localization accuracy (error < 13.5 mm, approximately 7% of link length) and force errors < 0.15 N (approximately 2% of applied force).

## Boundaries and Limitations

- **Collinearity Ambiguity**: When the applied external force is nearly collinear with the local link geometry, the contact point solution becomes ill-conditioned, with the solution sensitive to small perturbations in force or configuration, leading to elevated errors (the authors observe a line of elevated error in the heatmap).
- **Acceleration Neglect Assumption**: The base FT sensor computation omits the Hq̈ term; under high-speed dynamic motions (e.g., running, jumping), this assumption may fail, increasing force estimation bias.
- **Limited Experimental Scope**: Only a 2-DoF planar arm is validated; no multi-link (>2) hardware experiments; no dynamic walking/running conditions; no direct comparison with tactile skin approaches.
- **Real-Time Performance Not Quantified**: The paper does not provide quantitative metrics for computational latency or throughput, only stating "continuous operation."
- **Hardware Load Limitations**: Link 2, due to lower actuator torque, was tested only with loads of 0.05–0.1 kg, not covering high-impact scenarios.

## Engineering Insights

1. **Verify Information Completeness First**: Before reproduction, confirm that your robot has the "joint torque sensor + base FT sensor" combination. With only joint torque sensors, the contact localization problem is mathematically unsolvable (3 unknowns, 2 equations); additional sensing dimensions are required.

2. **Friction Is the Biggest Enemy**: Motor-current-based torque estimation RMSE (0.1638 Nm) is 5× that of joint torque sensors (0.0317 Nm). If your actuator has a moderate or higher reduction ratio, strongly consider output-shaft torque sensors over current estimation; otherwise, the signal-to-noise ratio of the residual observer will degrade significantly.

3. **Threshold Tuning Is Critical**: The residual threshold ε_res = 0.06 is effective under this paper's physical parameters, but the value depends on link mass, inertia, and sensor noise levels. We recommend first scanning your robot's parameters in simulation (MATLAB ode45) to determine an appropriate threshold range before moving to hardware.

4. **Avoid Collinearity Degeneracy**: When the external force direction is nearly parallel to the link axis, the contact position solution becomes ill-conditioned. Engineering mitigations could include geometric constraints (e.g., limiting the α range) or fusing other sensing modalities (e.g., IMU), but the paper does not provide a solution.

5. **Data Synchronization Is a Hidden Cost**: The mjbots controller, FT sensor, and ADC data streams must be synchronized and forwarded to MATLAB in real time. We recommend planning the synchronization mechanism (e.g., timestamp alignment) at the architecture design stage; otherwise, real-time performance will be severely compromised.

6. **Hardware Selection Reference**: The hip FT sensor uses a PixONE (Bota Systems) utilizing only the planar components; joint torque sensors are custom-built (full Wheatstone bridge + 6061 aluminum), with FEA validating strain under 0.4 Nm loads. If budget-constrained, commercial miniature torque sensors are an option, but stiffness matching must be considered.

## 개요

본 논문은 분산형 관절 토크 센서와 단일 고관절 힘/토크(FT) 센서를 융합한 보행 로봇 다리의 접촉 감지 및 위치 파악 프레임워크를 제안한다. 일반화된 운동량 관측기를 기반으로 복잡한 마찰 모델링 없이 실시간 접촉 인식을 구현한다. 저자는 미국 대학 소속(NSF 지원), 핵심 기여는 베이스 FT 센서를 활용하여 운동학적 체인에서 관절 토크 정보의 누적 모호성을 보완하고, 서브센티미터 수준의 접촉 위치 파악과 0.2 N 미만의 힘 추정 오차를 달성한 것이다.

## 그것이 바꾼 것

보행 로봇의 접촉 인식은 오랫동안 "발끝 촉각" 문제로 단순화되어 왔지만, 혼잡한 환경에서 허벅지와 종아리의 예상치 못한 충돌은 안정성을 파괴하는 주요 원인이다. 기존 방식은 모터 전류 기반 토크 추정(비선형 마찰, 백래시, 히스테리시스의 영향이 큼), 촉각 피부(업데이트 속도가 느리고 하드웨어가 취약하며 고충격 조건에 부적합), 또는 일반화된 운동량 관측기로 충돌을 감지하지만 특정 링크로 위치를 특정할 수 없는 등의 한계가 있었다. 본 논문이 실제로 바꾼 것은 "감지"를 "감지 + 위치 파악 + 힘 추정"의 완전한 폐루프로 업그레이드하면서도 어떤 마찰 모델도 도입하지 않았다는 점이다. 이는 공학적 실용성의 핵심 도약이다.

더 본질적인 돌파구는 정보 이론적 측면의 보완에 있다. 2-DoF 관절 토크 센서만으로는 외부 힘의 세 가지 미지수(F_x, F_z, 접촉 위치 p_c)가 수학적으로 풀리지 않는다. 저자는 관절 토크 센서를 추가하는 대신(비용이 높고 배선이 복잡함), 고관절에 상용 FT 센서 하나를 교묘하게 장착하여 베이스에서의 완전한 힘/토크 판독값으로 방정식을 닫았다. 이러한 "분산형 관절 센싱 + 단일 베이스 센싱"의 하이브리드 아키텍처는 비용, 복잡성, 정보 완전성 사이에서 실용적인 균형을 찾았다.

## 방법 분해

### 1. 일반화된 운동량 관측기(잔차 계산)
- 로봇 동역학: M(q)q̈ + C(q,q̇)q̇ + g(q) + τ_ext = τ_sen
- Ṁ = C + Cᵀ 성질을 이용하여 일반화된 운동량 P = M(q)q̇를 정의하면, Ṗ = Cᵀq̇ − g + τ_sen − τ_ext
- 잔차 관측기: r(t) = K[P(t) − p_int(t) − P₀], K는 대각 이득, p_int는 적분기 상태
- 이산화 업데이트: p_int(t+Δt) = p_int(t) + [u + r(t)]Δt, 여기서 u = Cᵀq̇ − g + τ_sen
- 충돌 판정: ‖r(t)‖ > ε_res (임계값 0.06)

### 2. 충돌 링크 식별
- n링크 개방 사슬에서 충돌이 링크 c에서 발생하면, 처음 c개의 잔차 성분이 상승하고 원위 잔차는 0을 유지
- 식별 규칙: c = max{i ∈ {1,…,n} : |r_i(t)| > ε_res}

### 3. 베이스 FT 센서를 통한 접촉 계산 보완
- [τ₁,τ₂]ᵀ만으로는 (F_x, F_z, p_c)를 유일하게 결정할 수 없으며, 베이스 FT는 Fᵇ := [F_xᵇ, F_yᵇ, M_yᵇ]ᵀ를 제공
- 3개의 가상 관절 [x,y,z]를 포함하도록 일반화 좌표를 확장하고, 일반화 힘 w = S(Cq̇ + g − Bτ_sen), Hq̈ 항은 무시(관절 가속도 무시 가능 가정)
- 순수 예상치 못한 힘 Fᵘ = w − Fᵇ, 접촉 힘 F_c = −[F_xᵘ, F_zᵘ]ᵀ

### 4. 접촉 위치 계산
- 접촉점이 링크 c의 시작점 p₁과 끝점 p₂ 사이에 있다고 가정: p_c = p₁ + α(p₂ − p₁), α ∈ [0,1]
- 정적 모멘트 평형: M_yᵘ + p_c ∧ F_xzᵘ = 0, α = −(M_yᵘ + p₁ ∧ F_xzᵘ) / ((p₂ − p₁) ∧ F_xzᵘ)로 계산
- 0 ≤ α ≤ 1이면 충돌이 물리적으로 링크 c에 위치

### 5. 하드웨어 구현
- 관절 토크 센서: 자체 제작 스트레인 게이지 방식, 풀 휘트스톤 브리지, 1 kΩ 스트레인 게이지, 5 V 여기, 6061 알루미늄 센서 본체
- 데이터 수집: 24비트 ADC(ADS127L21EVM-PDK), Arduino Due가 SPI 통신, 샘플링 속도 3–4 kSps
- 제어기: PD 제어기 1 kHz 실행, 운동량 충돌 추정 연속 실행

## 핵심 혁신

1. **하이브리드 센싱 아키텍처**: 분산형 관절 토크 센서 + 단일 베이스 FT 센서의 조합은 수학적으로 접촉 위치 파악 문제(3개의 미지수, 3개의 방정식)를 닫으면서도 각 링크에 FT 센서를 설치하는 비용과 복잡성을 피한다. 이는 "관절 토크 센서 정보 부족" 문제에 대한 우아한 공학적 해법이다.

2. **마찰 모델링 없는 접촉 위치 파악**: 일반화된 운동량 관측기는 본질적으로 모델링되지 않은 마찰에 강건하며, 잔차 신호가 외부 충돌을 직접 반영하므로 마찰 파라미터 식별이 필요 없다. 모터 전류 기반 방법(RMSE 0.1638 Nm vs 0.0317 Nm)과 비교하여 정확도가 5배 이상 향상되고 구현이 간단하다.

3. **실시간성과 정확성의 균형**: 전체 프로세스(잔차 계산→링크 식별→힘/위치 계산)는 해석적 계산으로 반복 최적화가 없어 1 kHz 제어 루프에 적합하다. 시뮬레이션과 하드웨어 실험 모두 서브센티미터 위치 정확도(오차 <13.5 mm, 링크 길이의 약 7%)와 힘 오차 <0.15 N(인가 힘의 약 2%)을 검증했다.

## 경계 및 한계

- **공선 모호성 문제**: 외부 힘이 로컬 링크 기하학과 거의 공선일 때 접촉점 계산이 병적 상태가 되어 해가 힘이나 구성의 작은 교란에 민감해지고 오차가 증가한다(저자는 히트맵에서 오차 증가선을 관찰).
- **가속도 무시 가정**: 베이스 FT 센서 계산에서 Hq̈ 항을 생략하는데, 고속 동적 운동(예: 달리기, 점프)에서는 이 가정이 유효하지 않아 힘 추정 편향이 커질 수 있다.
- **실험 범위 제한**: 2-DoF 평면 매니퓰레이터만 검증했으며, 다중 링크(>2) 하드웨어 실험은 수행하지 않았다. 동적 보행/달리기 조건은 다루지 않았고, 촉각 피부 방식과의 직접 비교도 없다.
- **실시간 성능 미정량화**: 논문은 계산 지연이나 처리량에 대한 정량적 지표를 제공하지 않고 "연속 실행"이라고만 명시한다.
- **하드웨어 하중 제한**: Link 2는 액추에이터 토크가 낮아 테스트 하중이 0.05–0.1 kg에 불과하며, 고충격 시나리오는 다루지 않았다.

## 공학적 시사점

1. **정보 완전성 먼저 확인**: 재현 전에 로봇이 "관절 토크 센서 + 베이스 FT 센서" 조합을 갖추었는지 반드시 확인하라. 관절 토크 센서만 있다면 접촉 위치 파악 문제는 수학적으로 풀리지 않으며(3개의 미지수, 2개의 방정식), 센싱 차원을 추가해야 한다.

2. **마찰이 가장 큰 적**: 모터 전류 기반 토크 추정의 RMSE(0.1638 Nm)는 관절 토크 센서(0.0317 Nm)의 5배이다. 액추에이터에 중간 이상의 감속비가 있다면 전류 추정 대신 출력축 토크 센서를 강력히 권장한다. 그렇지 않으면 잔차 관측기의 신호 대 잡음비가 현저히 악화된다.

3. **임계값 튜닝이 핵심**: 잔차 임계값 ε_res = 0.06은 본 논문의 물리적 파라미터에서 유효하지만, 이 값은 링크 질량, 관성, 센서 노이즈 수준에 의존한다. 먼저 시뮬레이션(MATLAB ode45)으로 로봇 파라미터를 스캔하여 적절한 임계값 범위를 결정한 후 하드웨어에 적용하라.

4. **공선 퇴화 회피 필요**: 외부 힘 방향이 링크 축과 거의 평행할 때 접촉 위치 계산이 병적 상태가 된다. 공학적으로 기하학적 제약(예: α 범위 제한)을 추가하거나 다른 센싱(예: IMU)을 융합하여 완화할 수 있지만, 논문은 해결책을 제시하지 않는다.

5. **데이터 동기화는 숨은 비용**: mjbots 제어기, FT 센서, ADC의 세 데이터 스트림은 동기화된 후 실시간으로 MATLAB에 전달되어야 한다. 아키텍처 설계 단계에서 동기화 메커니즘(예: 타임스탬프 정렬)을 계획하지 않으면 실시간성이 크게 저하된다.

6. **하드웨어 선택 참고**: 고관절 FT 센서는 PixONE(Bota Systems)을 사용하고 평면 성분만 활용한다. 관절 토크 센서는 자체 제작(풀 휘트스톤 브리지 + 6061 알루미늄)이며, FEA로 0.4 Nm 하중에서의 변형률을 검증했다. 예산이 제한적이라면 상용 미니어처 토크 센서를 고려할 수 있지만 강성 매칭에 주의해야 한다.
