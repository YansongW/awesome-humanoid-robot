## 概述

这是一个完全开源的桌面级双轮腿机器人项目，基于 ESP32、simpleFOC 和常见低成本传感器构建，目标是让全球最小的此类平台易于学习、复现和远程控制。核心贡献在于提供完整的硬件设计文件（机械模型、PCB 源文件）与软件栈（Arduino IDE + WebSocket 网页遥控），将复杂的轮腿平衡机器人门槛降到极低。

## 它改变了什么

这个项目真正改变的是机器人入门生态的“最小可行单元”。以往轮腿平衡机器人要么是昂贵的商业套件，要么是散落各处的 DIY 碎片，缺乏一个从机械到 PCB 再到固件全链路闭环、且足够小的参考设计。它把“能做出来”变成了“照着做就能跑”，用 3.5k Stars 证明了社区对这种“可复现的极致微型化”的饥渴。

它改变的第二个点是控制入口。用浏览器网页 + WebSocket 替代了专用遥控器或上位机，让 Android、iOS、Windows 等任何有浏览器的设备都能直接操控，这消除了跨平台开发的最大痛点。对教育场景和极客入门而言，这比任何 API 文档都更直观。

## 方法拆解

### 硬件分层
- **机械**：提供 `OriginalRobotModel.stp` 整机模型，将零件分为 `Parts-Manufactured`（3D 打印/CNC/面板切割）与 `Parts-Purchased`（标准件）两类，明确分工。
- **PCB**：共 4 块板，设计环境为 LCEDA。主控板以 ESP32 为核心，电机驱动芯片为 L6234PD013TR，编码器用 AS5600（I2C），IMU 为 MPU6050（与右侧编码器共用 I2C 总线）。舵机调试板将两路串口通过时分复用合并为一路信号线。

### 软件与标定
- 轮子无刷电机基于 simpleFOC 驱动，在 Arduino IDE 中开发，推荐 esp32 版本 2.0.3。
- 总线舵机左右 ID 分别为 1 和 2，腿完全蹲下至机械极限的标定值为 2048，需用 FEETECH Debug Software 配置。
- 网页代码存储在 flash 中，通过 WebSocket 传输 JSON。支持 AP（设备作热点）与 STA（连接现有网络）两种 WiFi 模式。

### 启动流程
1. 连接 XH2.54 电池插头并上电，红灯亮表示通电。
2. FOC 电机初始化（轮子轻微移动），腿开始运动。
3. 蓝灯亮表示电量充足，否则需充电。
4. 按 EN 键重启，连接以 `WL` 开头的 WiFi（密码为 WiFi 名称小写）。
5. 浏览器访问 `192.168.1.11`，点击 “Robot go!” 按钮，手动扶稳后机器人站立。

## 关键创新

1. **全链路开源的最小化封装**：从 STP 模型到 LCEDA 原理图再到 Arduino 代码，全部公开且零件清单明确。这不是论文式的概念验证，而是可直接下单加工的“生产级”开源方案，极大降低了复现成本。
2. **网页即遥控器**：用 WebSocket + JSON 将控制端抽象为浏览器页面，绕过了所有操作系统差异。这一设计让“零安装”成为可能，对教学演示和快速上手意义重大。
3. **时分复用串口**：舵机调试板将两路串口合并为一路信号线，减少了线束和接口数量，在微型化平台上这是很实际的工程取舍。

## 工程启示

复现时最先核对的是**舵机标定值 2048**——这是机械极限位置，若你的打印件公差不同，这个值可能导致腿无法正确蹲下或过行程损坏舵机。其次是 esp32 版本必须锁定 2.0.3，WebSocket 库在 `3.Software/libraries` 中，版本不匹配会导致编译失败或运行时崩溃。

最容易踩坑的是 I2C 总线共用：MPU6050 与右侧 AS5600 共用同一 I2C 接口，若地址冲突或线序错误，初始化会静默失败，表现为轮子不动但蓝灯亮。建议先单独测试每个传感器地址。另外，GH1.25 4PIN 双头线推荐长度 15cm（由白名单数字 1.25 与 15 计算，原文推荐 15cm），过短会拉扯 PCB，过长则增加重量和缠绕风险。

对下游团队而言，若想基于此平台做二次开发，优先替换的是总线舵机——其调试依赖 FEETECH 专用软件，若想集成到自有控制框架，需要先解决串口时分复用的协议解析。WiFi 默认地址 `192.168.1.11` 在 STA 模式下可能冲突，建议在代码中改为 DHCP 或可配置静态 IP。
