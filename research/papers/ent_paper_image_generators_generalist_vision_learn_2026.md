## 概述

本文提出 **Vision Banana**，通过对领先图像生成器 **Nano Banana Pro (NBP)** 进行轻量级指令微调，将视觉任务输出统一编码为 RGB 图像，从而验证“图像生成器即通用视觉学习者”这一范式。作者证明生成式预训练能同时支撑 2D/3D 理解与生成能力，在多个零样本基准上达到或超越专用模型 SOTA，且不牺牲原始生成先验。

## 它改变了什么

这项工作的真正改变在于：它把视觉理解的“接口”从判别式架构（分类头、回归头、掩码头）彻底替换为生成式像素输出。以往视觉表示学习（对比学习、自编码、自监督）与生成建模分属两个家族，而本文证明生成式预训练可以像 LLM 一样涌现出通用理解能力——这不仅是方法上的迁移，更是对“视觉基础模型”定义的重构：不再需要为每个任务定制损失函数和解码头，而是用自然语言提示 + RGB 图像编码统一所有任务。

更关键的是，它解决了此前生成式视觉模型（如 Zuo et al., 2025）在零样本迁移上的失败——那些模型因不严格遵循提示生成可解码格式而无法在现代基准上竞争。Vision Banana 通过极低比例指令微调（仅教授输出格式化）保留了生成先验，同时解锁理解能力，这暗示生成式预训练可能成为视觉领域的“GPT 时刻”，而非仅仅是又一个多任务学习技巧。

## 方法拆解

### 核心架构
- **基础模型**：Nano Banana Pro (NBP)，未披露参数量，但为当前领先的图像生成器。
- **指令微调**：将视觉任务数据以**极低比例**混入 NBP 原始训练混合数据，仅教授模型将输出格式化为 RGB 图像，不重训生成能力。

### 输出编码方案
- **深度估计**：使用 Barron [2025] 幂变换弯曲度量深度：  
  `f(d, λ, c) = 1 - (1 - d/(λc))^(λ+1)`，设置 λ = -3，c = 10/3，将 d ∈ [0, ∞) 映射到 [0, 1)。  
  颜色映射沿 RGB 立方体边缘从黑到白插值（类似 3D Hilbert 曲线首次迭代），严格可逆形成双射。
- **表面法线**：相机空间法线（右手系，+x 右，+y 上，+z 出平面），方向向量分量直接映射到 RGB 通道。
- **实例分割**：逐类推理——每次提示仅为一个类别生成掩码，动态分配颜色，评估时通过阈值聚类相似像素。

### 训练数据策略
- 2D 任务：网络爬取图像的内部模型标注；3D 任务：渲染引擎合成数据。
- **零真实世界深度数据**，且**不包含任何评估基准的训练数据**，保证严格零样本迁移。
- 数据增强：使用替代颜色映射（Plasma、Inferno、Viridis、灰度）提升鲁棒性。

### 推理
- 深度估计：逆映射解码 RGB 为度量深度。
- ReasonSeg 评估：配对 Gemini 2.5 Pro 作为多模态 LLM。

## 关键创新

1. **生成即理解**：首次证明图像生成器通过生成式预训练即可获得通用视觉理解能力，无需判别式微调。这改变了“生成模型只能生成、理解需专用头”的行业共识，使单一权重同时服务理解与生成。

2. **RGB 作为通用输出接口**：将深度、法线、分割掩码等异构输出统一编码为 RGB 图像，用自然语言提示切换任务。这避免了为每个任务设计定制损失和解码头，且生成式建模天然处理“单输入多模态输出”的歧义（学习完整分布而非塌缩为均值），优于 SAM 等专家模型的多掩码策略。

3. **极低比例指令微调**：仅教授输出格式化（如何将结果画成 RGB），不重训生成先验。这使得新任务适配成本极低（数据量少、计算开销小），同时保留原始生成能力——这是此前生成式视觉模型失败的关键修正。

## 边界与局限

- **实例分割短板**：SA-Co/Gold pmF1 = 0.540，落后于 SAM 3（0.661），作者承认该任务仍有挑战。
- **Referring segmentation 差距**：RefCOCOg 上仍不及在训练集上训练的方法（HyperSeg、X-SAM），零样本迁移的固有局限。
- **未探索范围**：仅单目图像输入，未扩展到多视图/视频；未探索视频生成器的时间感知表示；未与 LLM 协同增强跨模态推理。
- **计算开销**：NBP 类图像生成器推理成本显著高于轻量级专用模型，未开发加速策略。
- **训练细节缺失**：论文未披露模型参数量、指令微调数据比例、训练步数、学习率、硬件配置等关键复现参数。
- **nuScenes 深度表现弱**：δ1 = 0.643 明显低于其他数据集，可能因合成数据与真实驾驶场景分布差异。

## 工程启示

- **先核对输出编码**：深度估计的幂变换参数（λ = -3, c = 10/3）和颜色映射双射性是复现的关键，任何偏差都会导致解码错误。建议先在小数据集上验证逆映射的数值精度。
- **数据配比是核心**：指令微调数据“极低比例”混入原始训练数据是保留生成先验的关键，但论文未给出具体数值。复现时需从 1% 以下开始尝试，监控生成能力（如 GenAI-Bench win rate）是否下降。
- **评估协议严格性**：确保训练数据不包含任何评估基准——这是零样本结论成立的前提。建议用内部标注或合成数据，避免数据泄漏。
- **实例分割的逐类推理**：每类一次推理 + 颜色聚类阈值化，计算成本随类别数线性增长。若下游类别多，需权衡精度与延迟。
- **最易踩坑点**：表面法线的坐标系定义（右手系，+z 出平面）必须与训练数据一致；深度估计的野外泛化依赖合成数据质量，若下游场景与合成分布差异大（如 nuScenes），需额外采集真实数据微调。
- **对下游团队**：Vision Banana 可作为“理解 + 生成”统一后端，但若任务对延迟敏感（如实时分割），建议蒸馏为轻量模型或仅用其生成伪标签训练专用小模型。

## Overview

This paper proposes **Vision Banana**, which validates the paradigm of "image generators as universal vision learners" by applying lightweight instruction fine-tuning to the leading image generator **Nano Banana Pro (NBP)**, uniformly encoding visual task outputs as RGB images. The authors demonstrate that generative pretraining can simultaneously support 2D/3D understanding and generation capabilities, achieving or surpassing specialized model SOTA on multiple zero-shot benchmarks without sacrificing the original generative prior.

## What It Changes

The real shift in this work lies in completely replacing the "interface" of visual understanding from discriminative architectures (classification heads, regression heads, mask heads) to generative pixel outputs. Previously, visual representation learning (contrastive learning, autoencoders, self-supervision) and generative modeling belonged to two separate families, but this paper proves that generative pretraining can elicit general understanding capabilities just like LLMs—this is not merely a methodological transfer, but a redefinition of what constitutes a "visual foundation model": no longer requiring task-specific loss functions and decoder heads, but unifying all tasks through natural language prompts + RGB image encoding.

More critically, it addresses the failure of previous generative vision models (e.g., Zuo et al., 2025) in zero-shot transfer—those models could not compete on modern benchmarks because they did not strictly follow prompts to generate decodable formats. Vision Banana preserves the generative prior while unlocking understanding capabilities through an extremely low proportion of instruction fine-tuning (teaching only output formatting), suggesting that generative pretraining may represent the "GPT moment" for vision, rather than merely another multi-task learning trick.

## Method Breakdown

### Core Architecture
- **Base Model**: Nano Banana Pro (NBP), parameter count undisclosed, but is the current leading image generator.
- **Instruction Fine-tuning**: Visual task data is mixed into NBP's original training mixture at an **extremely low proportion**, teaching the model only to format outputs as RGB images without retraining generation capabilities.

### Output Encoding Scheme
- **Depth Estimation**: Uses Barron [2025] power transform to warp metric depth:  
  `f(d, λ, c) = 1 - (1 - d/(λc))^(λ+1)`, with λ = -3, c = 10/3, mapping d ∈ [0, ∞) to [0, 1).  
  Color mapping interpolates along the RGB cube edges from black to white (similar to the first iteration of a 3D Hilbert curve), strictly invertible forming a bijection.
- **Surface Normals**: Camera-space normals (right-handed system, +x right, +y up, +z out of plane), with direction vector components mapped directly to RGB channels.
- **Instance Segmentation**: Class-by-class inference—each prompt generates masks for only one category, with dynamically assigned colors, evaluated by thresholding and clustering similar pixels.

### Training Data Strategy
- 2D tasks: Internal model annotations from web-crawled images; 3D tasks: synthetic data from rendering engines.
- **Zero real-world depth data**, and **no training data from any evaluation benchmark**, ensuring strict zero-shot transfer.
- Data augmentation: Alternative color maps (Plasma, Inferno, Viridis, grayscale) to improve robustness.

### Inference
- Depth estimation: Inverse mapping decodes RGB to metric depth.
- ReasonSeg evaluation: Paired with Gemini 2.5 Pro as a multimodal LLM.

## Key Innovations

1. **Generation as Understanding**: First demonstration that image generators can acquire general visual understanding capabilities through generative pretraining alone, without discriminative fine-tuning. This changes the industry consensus that "generative models can only generate, understanding requires specialized heads," enabling a single set of weights to serve both understanding and generation.

2. **RGB as a Universal Output Interface**: Heterogeneous outputs such as depth, normals, and segmentation masks are uniformly encoded as RGB images, with natural language prompts switching between tasks. This avoids designing custom losses and decoder heads for each task, and generative modeling naturally handles the ambiguity of "single input, multimodal output" (learning the full distribution rather than collapsing to the mean), outperforming expert models like SAM's multi-mask strategy.

3. **Extremely Low-Proportion Instruction Fine-tuning**: Only teaches output formatting (how to render results as RGB), without retraining the generative prior. This makes adaptation to new tasks extremely cheap (low data volume, minimal compute overhead) while preserving original generation capabilities—a critical correction to previous generative vision model failures.

### Key Conclusions

## Boundaries and Limitations

- **Instance Segmentation Weakness**: SA-Co/Gold pmF1 = 0.540, trailing SAM 3 (0.661); the authors acknowledge this task remains challenging.
- **Referring Segmentation Gap**: Still inferior to methods trained on the training set (HyperSeg, X-SAM) on RefCOCOg—an inherent limitation of zero-shot transfer.
- **Unexplored Scope**: Only monocular image input, not extended to multi-view/video; temporal-aware representations from video generators not explored; no synergy with LLMs for enhanced cross-modal reasoning.
- **Computational Cost**: Inference cost of NBP-class image generators is significantly higher than lightweight specialized models; no acceleration strategies developed.
- **Missing Training Details**: The paper does not disclose model parameter count, instruction fine-tuning data proportion, training steps, learning rate, hardware configuration, or other key reproduction parameters.
- **Weak nuScenes Depth Performance**: δ1 = 0.643 is notably lower than other datasets, possibly due to distribution differences between synthetic data and real driving scenes.

## Engineering Insights

- **Verify Output Encoding First**: The power transform parameters for depth estimation (λ = -3, c = 10/3) and the bijective color mapping are critical for reproduction; any deviation will cause decoding errors. It is recommended to validate the numerical precision of the inverse mapping on a small dataset first.
- **Data Mixing Ratio Is Core**: The "extremely low proportion" of instruction fine-tuning data mixed into the original training data is key to preserving the generative prior, but the paper does not provide specific values. When reproducing, start below 1% and monitor whether generation capability (e.g., GenAI-Bench win rate) degrades.
- **Evaluation Protocol Rigor**: Ensure training data contains no evaluation benchmarks—this is a prerequisite for the zero-shot conclusion. Use internal annotations or synthetic data to avoid data leakage.
- **Class-by-Class Instance Segmentation**: One inference per class + color clustering thresholding means computational cost scales linearly with the number of classes. For downstream tasks with many categories, trade-offs between accuracy and latency are needed.
- **Most Common Pitfall**: The coordinate system definition for surface normals (right-handed, +z out of plane) must match the training data; wild generalization of depth estimation depends on synthetic data quality—if downstream scenes differ significantly from the synthetic distribution (e.g., nuScenes), additional real data fine-tuning is required.
- **For Downstream Teams**: Vision Banana can serve as a unified "understanding + generation" backend, but for latency-sensitive tasks (e.g., real-time segmentation), consider distilling into a lightweight model or using it only to generate pseudo-labels for training specialized small models.

## 개요

본 논문은 **Vision Banana**를 제안하며, 선도적 이미지 생성기 **Nano Banana Pro (NBP)**에 대한 경량 명령 미세 조정을 통해 시각 작업 출력을 RGB 이미지로 통일적으로 인코딩하여 "이미지 생성기가 곧 범용 시각 학습자"라는 패러다임을 검증한다. 저자들은 생성적 사전 학습이 2D/3D 이해 및 생성 능력을 동시에 뒷받침할 수 있음을 증명하며, 여러 제로샷 벤치마크에서 전용 모델 SOTA에 도달하거나 이를 능가하면서도 원래의 생성 사전 지식을 희생하지 않는다.

## 그것이 바꾸는 것

이 작업의 진정한 변화는 시각 이해의 "인터페이스"를 판별적 아키텍처(분류 헤드, 회귀 헤드, 마스크 헤드)에서 생성적 픽셀 출력으로 완전히 대체했다는 점이다. 기존에는 시각 표현 학습(대비 학습, 자기 인코딩, 자기 지도 학습)과 생성 모델링이 별개의 계열로 여겨졌지만, 본 논문은 생성적 사전 학습이 LLM처럼 범용 이해 능력을 창발할 수 있음을 증명한다. 이는 단순한 방법론적 이전이 아니라 "시각 기반 모델"의 정의 자체를 재구성하는 것이다. 더 이상 작업별 손실 함수와 디코더 헤드를 맞춤 제작할 필요 없이, 자연어 프롬프트와 RGB 이미지 인코딩으로 모든 작업을 통합한다.

더욱 중요한 점은, 이전 생성적 시각 모델들(예: Zuo et al., 2025)이 제로샷 전이에서 실패했던 문제를 해결했다는 것이다. 그 모델들은 프롬프트를 엄격히 따라 디코딩 가능한 형식을 생성하지 않아 현대 벤치마크에서 경쟁할 수 없었다. Vision Banana는 극히 낮은 비율의 명령 미세 조정(출력 형식화만 학습)을 통해 생성 사전 지식을 보존하면서 이해 능력을 잠금 해제한다. 이는 생성적 사전 학습이 단순한 또 하나의 멀티태스크 학습 기법이 아니라, 비전 분야의 "GPT 순간"이 될 수 있음을 시사한다.

## 방법 분해

### 핵심 아키텍처
- **기반 모델**: Nano Banana Pro (NBP), 파라미터 수는 공개되지 않았지만 현재 선도적인 이미지 생성기.
- **명령 미세 조정**: 시각 작업 데이터를 **극히 낮은 비율**로 NBP 원본 학습 혼합 데이터에 혼합하여, 모델이 출력을 RGB 이미지로 형식화하는 것만 학습시키고 생성 능력은 재학습하지 않음.

### 출력 인코딩 방식
- **깊이 추정**: Barron [2025]의 거듭제곱 변환으로 측정 깊이를 굴절:  
  `f(d, λ, c) = 1 - (1 - d/(λc))^(λ+1)`, λ = -3, c = 10/3으로 설정하여 d ∈ [0, ∞)를 [0, 1)로 매핑.  
  색상 매핑은 RGB 큐브 모서리를 따라 검정에서 흰색으로 보간(3D 힐베르트 곡선 첫 반복과 유사)하여 엄격히 가역적인 전단사 함수를 형성.
- **표면 법선**: 카메라 공간 법선(오른손 좌표계, +x 오른쪽, +y 위, +z 평면 밖), 방향 벡터 성분을 RGB 채널에 직접 매핑.
- **인스턴스 분할**: 클래스별 추론—각 프롬프트는 하나의 클래스에 대한 마스크만 생성하고, 색상을 동적으로 할당하며, 평가 시 임계값 클러스터링으로 유사 픽셀을 그룹화.

### 학습 데이터 전략
- 2D 작업: 웹 크롤링 이미지의 내부 모델 주석; 3D 작업: 렌더링 엔진 합성 데이터.
- **실제 세계 깊이 데이터 제로**, **평가 벤치마크의 학습 데이터 미포함**으로 엄격한 제로샷 전이 보장.
- 데이터 증강: 대체 색상 매핑(Plasma, Inferno, Viridis, 그레이스케일)으로 강건성 향상.

### 추론
- 깊이 추정: 역매핑으로 RGB를 측정 깊이로 디코딩.
- ReasonSeg 평가: Gemini 2.5 Pro를 멀티모달 LLM으로 페어링.

## 핵심 혁신

1. **생성이 곧 이해**: 이미지 생성기가 생성적 사전 학습만으로 판별적 미세 조정 없이 범용 시각 이해 능력을 얻을 수 있음을 최초로 증명. "생성 모델은 생성만 하고, 이해는 전용 헤드가 필요하다"는 업계 통념을 바꾸어, 단일 가중치가 이해와 생성을 동시에 서비스.

2. **RGB를 범용 출력 인터페이스로**: 깊이, 법선, 분할 마스크 등 이질적 출력을 RGB 이미지로 통일 인코딩하고, 자연어 프롬프트로 작업을 전환. 작업별 맞춤 손실과 디코더 헤드를 설계할 필요가 없으며, 생성적 모델링은 "단일 입력-다중 모달 출력"의 모호성을 자연스럽게 처리(평균으로 붕괴하는 대신 전체 분포 학습)하여 SAM과 같은 전문가 모델의 다중 마스크 전략보다 우수.

3. **극히 낮은 비율의 명령 미세 조정**: 출력 형식화(결과를 RGB로 그리는 방법)만 학습하고 생성 사전 지식은 재학습하지 않음. 이로 인해 새 작업 적응 비용이 극히 낮고(데이터 양 적음, 계산 오버헤드 작음) 원래 생성 능력을 보존—이는 이전 생성적 시각 모델의 실패를 수정하는 핵심.

### 핵심 결론
- 제로샷 전이에서 Vision Banana는 Cityscapes 의미 분할에서 SAM 3를 4.7 포인트 mIoU로 능가하며 최고의 오픈 어휘 모델.
- RefCOCOg에서는 학습 세트로 학습된 방법(HyperSeg 0.794, X-SAM 0.838)에 여전히 뒤처지지만, 제로샷 기준선(HybridGL 0.513, Kang et al. 0.677)을 크게 능가.
- 표면 법선은 실내 데이터셋 평균에서 최저 mean/median 각도 오차를 기록하고, 실외에서는 SOTA와 동등; Lotus-2는 Virtual KITTI 2에서 학습되었지만 Vision Banana는 엄격한 제로샷.

## 경계 및 한계

- **인스턴스 분할 약점**: SA-Co/Gold pmF1 = 0.540으로 SAM 3(0.661)에 뒤처지며, 저자들은 이 작업이 여전히 도전적임을 인정.
- **Referring segmentation 격차**: RefCOCOg에서 학습 세트로 학습된 방법(HyperSeg, X-SAM)에 미치지 못하며, 제로샷 전이의 고유 한계.
- **미탐색 범위**: 단안 이미지 입력만 다루고 다중 뷰/비디오로 확장하지 않음; 비디오 생성기의 시간 인식 표현 미탐색; LLM과의 협력적 크로스모달 추론 강화 미탐색.
- **계산 오버헤드**: NBP류 이미지 생성기의 추론 비용이 경량 전용 모델보다 현저히 높으며, 가속 전략이 개발되지 않음.
- **학습 세부 정보 부재**: 논문은 모델 파라미터 수, 명령 미세 조정 데이터 비율, 학습 스텝 수, 학습률, 하드웨어 구성 등 핵심 재현 파라미터를 공개하지 않음.
- **nuScenes 깊이 성능 약함**: δ1 = 0.643으로 다른 데이터셋보다 현저히 낮으며, 합성 데이터와 실제 주행 장면의 분포 차이 때문일 수 있음.

## 엔지니어링 시사점

- **출력 인코딩 먼저 검증**: 깊이 추정의 거듭제곱 변환 파라미터(λ = -3, c = 10/3)와 색상 매핑 전단사성은 재현의 핵심이며, 어떤 편차도 디코딩 오류를 초래. 작은 데이터셋에서 역매핑의 수치 정밀도를 먼저 검증할 것.
- **데이터 비율이 핵심**: 명령 미세 조정 데이터를 "극히 낮은 비율"로 원본 학습 데이터에 혼합하는 것이 생성 사전 지식 보존의 핵심이지만, 논문은 구체적 수치를 제시하지 않음. 재현 시 1% 미만에서 시작하여 생성 능력(예: GenAI-Bench win rate) 저하 여부를 모니터링할 것.
- **평가 프로토콜 엄격성**: 학습 데이터에 평가 벤치마크가 포함되지 않도록 보장—이는 제로샷 결론의 전제 조건. 내부 주석 또는 합성 데이터를 사용하여 데이터 누출을 피할 것.
- **인스턴스 분할의 클래스별 추론**: 클래스당 한 번의 추론 + 색상 클러스터링 임계값화로 계산 비용이 클래스 수에 따라 선형 증가. 다운스트림 클래스가 많으면 정밀도와 지연 시간 간의 균형을 고려해야 함.
- **가장 쉽게 실수하는 지점**: 표면 법선의 좌표계 정의(오른손 좌표계, +z 평면 밖)가 학습 데이터와 일치해야 함; 깊이 추정의 야외 일반화는 합성 데이터 품질에 의존하며, 다운스트림 장면이 합성 분포와 크게 다르면(예: nuScenes) 추가 실제 데이터 수집 및 미세 조정 필요.
- **다운스트림 팀을 위해**: Vision Banana는 "이해 + 생성" 통합 백엔드로 사용할 수 있지만, 지연 시간에 민감한 작업(예: 실시간 분할)에는 경량 모델로 증류하거나 생성된 의사 라벨로 전용 소형 모델을 학습시키는 것이 좋음.
