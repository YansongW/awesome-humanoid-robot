## 概述

OSCAR 是一个动作条件的视频世界模型，通过 2D 运动学骨架渲染作为统一条件表示，在 Cosmos-Predict2.5-2B 上微调，并利用大规模机器人+人类第一视角视频联合训练，实现了跨四个机器人具身（Franka Panda、KUKA iiwa、AgiBot G1、Toyota HSR）的精确动作跟随与泛化。其核心贡献在于用无纹理骨架渲染替代潜在动作或密集几何条件，在保持动作约束力的同时摆脱了对 URDF 资产和特定纹理的依赖，并首次系统验证了人类数据对机器人视频生成的正迁移。

## 它改变了什么

这个工作真正改变的，是动作条件世界模型在「表达力-泛化-数据规模」三角关系上的僵局。此前显式几何条件（点图、网格）虽然动作精确，但要么过拟合外观（Kinema4D 在 OOD 退化），要么依赖 URDF 资产（网格渲染无法跨具身）；潜在动作方法虽通用但动作跟随模糊。OSCAR 用 2D 骨架渲染同时解决了两个问题：它只依赖运动学链（换具身只需更新运动学规格），且无纹理迫使模型学习运动学与真实运动间的映射而非记忆外观。更重要的是，这使人类手部视频（EgoDex、EPIC-Kitchens）能直接作为训练数据——此前没有任何动作条件世界模型做到这一点，因为人类手与机器人夹爪的几何表示无法统一。这实际上把机器人视频生成的训练数据池从约 10.9k 小时机器人数据扩展到额外 929 小时人类数据，且证明了正迁移。

## 方法拆解

### 条件表示：2D 运动学骨架渲染
- 将操作器（机器人臂或人手）的运动学链投影为 2D 线条图，作为第二 RGB 视频流 S₁:T，与目标视频逐帧对齐。
- 关键设计：骨架无纹理、仅含运动学链。更换具身只需替换运动学三元组 (M, q_t, o_k)，其中 M 为运动学模型（URDF 或 MANO 手模型），q_t 为关节角，o_k 为相机外参。
- 对人类手部：交换为 MANO 手模型，五指自由度高于两指夹爪，但统一渲染为相同 2D 线条图；骨架约束粗略运动，预训练视频先验填充细粒度视觉细节。

### 条件注入
- 骨架渲染 S₁:T 经 WAN 2.1 VAE 编码为骨架潜在 z^s，与目标视频潜在 z^v 形状相同（均为 (T, C, H, W)）。
- 分别用 patch embedder PE_v 和 PE_s 嵌入 DiT 隐藏维度 D=2048，然后将两个 token 张量逐元素相加，馈入 DiT 去噪。
- 训练时以 0.2 概率将 S₁:T 置零（classifier-free guidance），推理时 guidance scale w=6。

### 数据管道（四阶段）
1. **数据策展**：从 RH20T（cfg5/cfg7）、DROID、AgiBot World、InternData-A1、AIROA-MoMa、EgoDex、EPIC-Kitchens 收集源视频 2,165,359 片段。
2. **数据过滤**：四个机制——长度≥70 帧；静态相机（相机运动小于阈值）；有意义动作（非平凡操作器动作序列）；可见骨架（可见骨架百分比低于阈值则剔除）。
3. **语义去重**：两阶段——第一阶段 SigLIP 图像嵌入（5 帧均匀采样）余弦相似度>0.95 标记配对；第二阶段提取 64 步重采样操作器轨迹，逐步骤 RMS 距离低于自适应阈值标记重复。
4. **数据标注**：Qwen3-VL-30B-A3B-Instruct 生成 80–100 词英文描述，机器人数据与人类数据用相同系统提示词；DROID 片段采样率降至 1–2 fps（因长度约为其他源 5 倍），其他源 15 fps。

### 训练配置
- 基础模型：Cosmos-Predict2.5-2B（rectified-flow 目标），WAN 2.1 VAE。
- 优化器：AdamW，lr=3×10⁻⁵，batch size=16。
- 时间步采样：logit-normal 分布加重加权，shift=5。
- 数据平衡：频率温度加权 wᵢ ∝ n_frames,i^(1/T)，T=3。
- 训练窗口 81 帧，起始帧用梯形先验偏向抓取/释放事件。
- 两阶段：阶段 1 在四个机器人具身上训练 15k 迭代；阶段 2 在完整机器人+人类混合数据上继续训练（warm-start）。

### 潜在动作路径（消融用）
- 每臂 7 维动作（3 平移+3 旋转+1 夹爪），帧间差分在前一帧局部坐标系表达，平移/旋转差分缩放 20 倍。
- 多本体对齐：统一 14 维向量，双臂拼接，单臂后 7 维置零。
- 注入：D 维 token 加到时间步嵌入，3D 维 token 加到 adaptive LayerNorm 调制信号。

## 关键创新

1. **骨架渲染作为跨具身统一条件**：这是第一个用 2D 运动学骨架同时覆盖机器人臂和人手的动作条件世界模型。关键创新在于「无纹理」——模型必须显式学习运动学与真实运动的关系，而非记忆机器人外观，这直接缓解了 OOD 退化。相比网格渲染（依赖 URDF 资产）和点图（过拟合外观），骨架在表达力和泛化间取得了更好的平衡。

2. **人类数据正迁移的实证**：在机器人-only 训练基础上加入 85,827 个人类手部片段（EgoDex+EPIC-Kitchens），所有指标持续改善（FVD 从 7.69 降至 7.08，FID 从 16.37 降至 15.07）。这首次证明人类第一视角视频能有效补充机器人数据稀缺问题，且 warm-start 策略（先机器人后混合）比从头混合收敛更快。

3. **可复现的评估协议**：建立了 200 片段跨四具身评估基准（按 N 平方根配额平衡长尾），并首次用 RoboArena 平台（65 会话×7 策略=455 单元）验证视频生成质量与下游策略评估的相关性（Spearman ρ=0.750，Pearson r=0.852），用 GPT-5 作为 VLM 评分器（与人类标签匹配 78/100）。

## 边界与局限

- **数据规模受标定质量限制**：相机内参/外参误差直接降低骨架-RGB 对齐，限制了可可靠转换的原始视频数量。这是当前最大瓶颈——不是模型容量，而是标定质量。
- **静态相机假设**：仅关注机器人动作，相机运动留待未来工作。这意味着对移动操作中主动视觉（active perception）场景不适用。
- **2B 骨干上限**：仅用 2B 参数，作者承认扩展到更大骨干可能进一步提升，但需要更多计算。
- **VLM 评分器偏保守**：GPT-5 召回率仅 0.66，会漏报约 1/3 的真实成功，低估成功率而非高估。策略评估的绝对成功率数字需谨慎解读。
- **AIROA-MoMa 泛化不足**：移动底座+臂组合在训练数据中占比极小（3,712/180,657 ≈ 2%），OSCAR 在该子集上落后于 Genie Envisioner，说明长尾具身仍需更多数据。
- **消融定量细节未公开**：表 3 仅在正文提及，附录仅提供定性图；人类数据定量评估指标未给出。

## 工程启示

- **复现优先核对数据管道**：过滤后仅保留 180,657/2,165,359 片段（8.3% 保留率），其中语义去重（SigLIP>0.95 + 64 步轨迹 RMS）是关键步骤。若跳过去重，重复片段会主导训练并损害泛化。建议先复现 DROID 的 1–2 fps 降采样（因其片段长度约为其他源 5 倍）和 RH20T 的 cfg5/cfg7 选择（cfg1 缺本体感受、cfg3 外参标定错误）。
- **骨架渲染实现要点**：条件注入是「骨架潜在 z^s 与目标潜在 z^v 逐元素相加」，而非拼接——这要求两者 VAE 编码后形状完全一致。更换具身时只需更新运动学三元组 (M, q_t, o_k)，但必须确保相机外参 o_k 与骨架渲染的投影矩阵严格对齐，否则骨架-RGB 偏移会直接损害生成质量。
- **训练策略**：warm-start（先机器人 15k 迭代，再混合人类数据）比从头混合收敛更快且效果更好。数据平衡用频率温度加权 T=3，可提升小数据源（如 AIROA-MoMa 仅 3,712 片段）的权重。训练窗口 81 帧，起始帧用梯形先验偏向抓取/释放事件——这利用了夹爪开合信号，对操作视频生成至关重要。
- **评估协议**：指标在前 49 帧计算（遵循 Kinema4D 协议）；策略评估用 GPT-5 评分时注意其保守性（召回率 0.66），建议同时报告 MMRV 和 Spearman ρ 而非仅绝对成功率。相机标定用 MoGe-v2（内参）+ CtRNet-X（外参，BPnP 对 URDF 正运动学）——这是复现策略评估的最大工程风险点。
- **最易踩坑**：IRASim 的 7-DoF 动作接口与双臂 AgiBot G1 和移动底座 AIROA-MoMa 不兼容，对比时需排除；EnerVerse-AC 参数量未官方报告（作者实测 U-Net 可训练参数 1.46B）；Kinema4D 推理极慢（0.089 FPS），若做策略评估需预留充足时间。

## Overview

OSCAR is an action-conditioned video world model that uses 2D kinematic skeleton rendering as a unified conditioning representation. It is fine-tuned on Cosmos-Predict2.5-2B and jointly trained on large-scale robot and human egocentric video data, achieving precise action following and generalization across four robot embodiments (Franka Panda, KUKA iiwa, AgiBot G1, Toyota HSR). Its core contribution lies in replacing latent actions or dense geometric conditioning with texture-free skeleton rendering, which maintains action constraints while eliminating dependence on URDF assets and specific textures. It also provides the first systematic validation of positive transfer from human data to robot video generation.

## What It Changes

What this work truly changes is the deadlock in the "expressiveness-generalization-data scale" triangle for action-conditioned world models. Previously, explicit geometric conditioning (point clouds, meshes) achieved precise actions but either overfit appearance (Kinema4D degrades on OOD) or relied on URDF assets (mesh rendering cannot transfer across embodiments); latent action methods were general but had vague action following. OSCAR solves both problems with 2D skeleton rendering: it depends only on kinematic chains (switching embodiments only requires updating kinematic specifications), and the texture-free design forces the model to learn the mapping between kinematics and real motion rather than memorizing appearance. More importantly, this enables human hand videos (EgoDex, EPIC-Kitchens) to be used directly as training data—no prior action-conditioned world model has achieved this because the geometric representations of human hands and robot grippers could not be unified. This effectively expands the training data pool for robot video generation from approximately 10.9k hours of robot data to an additional 929 hours of human data, and demonstrates positive transfer.

## Method Breakdown

### Conditioning Representation: 2D Kinematic Skeleton Rendering
- Projects the kinematic chain of the manipulator (robot arm or human hand) into a 2D line drawing, serving as a second RGB video stream S₁:T, aligned frame-by-frame with the target video.
- Key design: the skeleton is texture-free and contains only kinematic chains. Switching embodiments only requires replacing the kinematic triplet (M, q_t, o_k), where M is the kinematic model (URDF or MANO hand model), q_t is the joint angles, and o_k is the camera extrinsic parameters.
- For human hands: swaps in the MANO hand model, where five fingers have higher degrees of freedom than a two-finger gripper, but both are uniformly rendered as the same 2D line drawing; the skeleton constrains coarse motion, while the pretrained video prior fills in fine-grained visual details.

### Conditioning Injection
- The skeleton rendering S₁:T is encoded via the WAN 2.1 VAE into a skeleton latent z^s, with the same shape as the target video latent z^v (both (T, C, H, W)).
- Patch embedders PE_v and PE_s embed them into the DiT hidden dimension D=2048, and the two token tensors are then added element-wise and fed into the DiT for denoising.
- During training, S₁:T is zeroed out with probability 0.2 (classifier-free guidance); at inference, the guidance scale is w=6.

### Data Pipeline (Four Stages)
1. **Data Curation**: Collects 2,165,359 source video clips from RH20T (cfg5/cfg7), DROID, AgiBot World, InternData-A1, AIROA-MoMa, EgoDex, and EPIC-Kitchens.
2. **Data Filtering**: Four mechanisms—length ≥ 70 frames; static camera (camera motion below threshold); meaningful action (non-trivial manipulator action sequence); visible skeleton (clips with visible skeleton percentage below threshold are removed).
3. **Semantic Deduplication**: Two stages—Stage 1 uses SigLIP image embeddings (5 uniformly sampled frames) with cosine similarity > 0.95 to flag pairs; Stage 2 extracts 64-step resampled manipulator trajectories and flags duplicates when per-step RMS distance falls below an adaptive threshold.
4. **Data Annotation**: Qwen3-VL-30B-A3B-Instruct generates 80–100 word English descriptions, with the same system prompt for robot and human data; DROID clips are downsampled to 1–2 fps (due to being approximately 5× longer than other sources), while other sources use 15 fps.

### Training Configuration
- Base model: Cosmos-Predict2.5-2B (rectified-flow objective), WAN 2.1 VAE.
- Optimizer: AdamW, lr=3×10⁻⁵, batch size=16.
- Timestep sampling: logit-normal distribution with heavier weighting, shift=5.
- Data balancing: frequency temperature weighting wᵢ ∝ n_frames,i^(1/T), T=3.
- Training window of 81 frames, with the starting frame biased toward grasp/release events via a trapezoidal prior.
- Two stages: Stage 1 trains on four robot embodiments for 15k iterations; Stage 2 continues training on the full robot+human mixed data (warm-start).

### Latent Action Path (for Ablation)
- 7-dimensional actions per arm (3 translation + 3 rotation + 1 gripper), with frame-to-frame differences expressed in the previous frame's local coordinate system; translation/rotation differences are scaled by 20×.
- Multi-embodiment alignment: unified 14-dimensional vector, concatenated for dual arms, with the last 7 dimensions zeroed for single arms.
- Injection: D-dimensional token added to the timestep embedding; 3D-dimensional token added to the adaptive LayerNorm modulation signal.

## Key Innovations

1. **Skeleton Rendering as a Cross-Embodiment Unified Conditioning**: This is the first action-conditioned world model to use 2D kinematic skeletons to cover both robot arms and human hands. The key innovation is "texture-free"—the model must explicitly learn the relationship between kinematics and real motion rather than memorizing robot appearance, which directly mitigates OOD degradation. Compared to mesh rendering (which depends on URDF assets) and point clouds (which overfit appearance), skeletons achieve a better balance between expressiveness and generalization.

2. **Empirical Evidence of Positive Transfer from Human Data**: Adding 85,827 human hand clips (EgoDex+EPIC-Kitchens) on top of robot-only training consistently improves all metrics (FVD from 7.69 to 7.08, FID from 16.37 to 15.07). This is the first demonstration that human egocentric video can effectively supplement robot data scarcity, and the warm-start strategy (robot first, then mixed) converges faster than mixing from the beginning.

3. **Reproducible Evaluation Protocol**: Establishes a 200-clip cross-four-embodiment evaluation benchmark (balanced for long-tail via N-square-root quotas), and is the first to use the RoboArena platform (65 sessions × 7 policies = 455 units) to validate the correlation between video generation quality and downstream policy evaluation (Spearman ρ=0.750, Pearson r=0.852), using GPT-5 as a VLM scorer (matching human labels on 78/100).

## Boundaries and Limitations

- **Data scale limited by calibration quality**: Camera intrinsic/extrinsic errors directly degrade skeleton-RGB alignment, limiting the amount of raw video that can be reliably converted. This is the current biggest bottleneck—not model capacity, but calibration quality.
- **Static camera assumption**: Only robot actions are considered; camera motion is left for future work. This means the method is not applicable to active perception scenarios in mobile manipulation.
- **2B backbone ceiling**: Only 2B parameters are used; the authors acknowledge that scaling to larger backbones may yield further improvements but requires more compute.
- **VLM scorer is conservative**: GPT-5 has a recall of only 0.66, missing approximately 1/3 of true successes, underestimating rather than overestimating success rates. Absolute success rate numbers in policy evaluation should be interpreted with caution.
- **Insufficient generalization on AIROA-MoMa**: The mobile base + arm combination accounts for a very small proportion of training data (3,712/180,657 ≈ 2%), and OSCAR lags behind Genie Envisioner on this subset, indicating that long-tail embodiments still require more data.
- **Ablation quantitative details not disclosed**: Table 3 is only mentioned in the main text; the appendix provides only qualitative figures; quantitative evaluation metrics for human data are not provided.

## Engineering Insights

- **Prioritize reproducing the data pipeline**: Only 180,657/2,165,359 clips (8.3% retention rate) remain after filtering, where semantic deduplication (SigLIP>0.95 + 64-step trajectory RMS) is a critical step. If deduplication is skipped, duplicate clips will dominate training and harm generalization. It is recommended to first reproduce DROID's 1–2 fps downsampling (since its clip length is approximately 5× that of other sources) and RH20T's cfg5/cfg7 selection (cfg1 lacks proprioception, cfg3 has incorrect extrinsic calibration).
- **Skeleton rendering implementation details**: Conditioning injection is "element-wise addition of skeleton latent z^s and target latent z^v," not concatenation—this requires both to have identical shapes after VAE encoding. Switching embodiments only requires updating the kinematic triplet (M, q_t, o_k), but the camera extrinsic parameters o_k must be strictly aligned with the skeleton rendering's projection matrix; otherwise, skeleton-RGB offset will directly degrade generation quality.
- **Training strategy**: Warm-start (15k robot iterations first, then mixed human data) converges faster and performs better than mixing from the beginning. Data balancing uses frequency temperature weighting T=3, which increases the weight of small data sources (e.g., AIROA-MoMa with only 3,712 clips). The training window is 81 frames, with the starting frame biased toward grasp/release events via a trapezoidal prior—this leverages gripper open/close signals and is critical for manipulation video generation.
- **Evaluation protocol**: Metrics are computed on the first 49 frames (following the Kinema4D protocol); when using GPT-5 for policy evaluation scoring, note its conservatism (recall 0.66), and it is recommended to report both MMRV and Spearman ρ rather than only absolute success rates. Camera calibration uses MoGe-v2 (intrinsics) + CtRNet-X (extrinsics, BPnP against URDF forward kinematics)—this is the biggest engineering risk point in reproducing policy evaluation.
- **Most common pitfalls**: IRASim's 7-DoF action interface is incompatible with the dual-arm AgiBot G1 and the mobile base AIROA-MoMa, so it should be excluded from comparisons; EnerVerse-AC's parameter count is not officially reported (the authors measured 1.46B trainable U-Net parameters); Kinema4D inference is extremely slow (0.089 FPS), so sufficient time should be reserved for policy evaluation.

## 개요

OSCAR는 2D 운동학적 스켈레톤 렌더링을 통합 조건 표현으로 사용하는 동작 조건부 비디오 세계 모델로, Cosmos-Predict2.5-2B에서 미세 조정되었으며, 대규모 로봇 + 인간 1인칭 비디오 데이터를 결합하여 학습함으로써 4가지 로봇 체현(Franka Panda, KUKA iiwa, AgiBot G1, Toyota HSR)에 걸친 정밀한 동작 추종과 일반화를 달성했습니다. 핵심 기여는 잠재 동작이나 밀집 기하 조건을 무질감 스켈레톤 렌더링으로 대체하여 동작 구속력을 유지하면서 URDF 자산과 특정 질감에 대한 의존성을 제거하고, 인간 데이터가 로봇 비디오 생성에 미치는 긍정적 전이를 최초로 체계적으로 검증한 것입니다.

## 무엇을 바꾸었는가

이 작업이 실제로 바꾼 것은 동작 조건부 세계 모델의 '표현력-일반화-데이터 규모' 삼각 관계의 교착 상태입니다. 기존의 명시적 기하 조건(포인트 클라우드, 메시)은 동작이 정밀하지만, 외관에 과적합되거나(Kinema4D는 OOD에서 성능 저하), URDF 자산에 의존하거나(메시 렌더링은 체현 간 전이가 불가능), 잠재 동작 방법은 범용적이지만 동작 추종이 모호했습니다. OSCAR는 2D 스켈레톤 렌더링으로 두 가지 문제를 동시에 해결했습니다. 운동학적 체인에만 의존하고(체현 변경 시 운동학 사양만 업데이트), 무질감 처리로 모델이 외관을 기억하는 대신 운동학과 실제 동작 간의 매핑을 학습하도록 강제합니다. 더 중요한 것은, 이로 인해 인간 손 비디오(EgoDex, EPIC-Kitchens)를 직접 훈련 데이터로 사용할 수 있게 되었다는 점입니다. 이전에는 어떤 동작 조건부 세계 모델도 인간 손과 로봇 그리퍼의 기하 표현을 통합할 수 없어 이를 달성하지 못했습니다. 이는 실제로 로봇 비디오 생성의 훈련 데이터 풀을 약 10.9k 시간의 로봇 데이터에서 추가 929시간의 인간 데이터로 확장했으며, 긍정적 전이를 입증했습니다.

## 방법 분해

### 조건 표현: 2D 운동학적 스켈레톤 렌더링
- 조작기(로봇 팔 또는 인간 손)의 운동학적 체인을 2D 선 그림으로 투영하여 두 번째 RGB 비디오 스트림 S₁:T로 사용하며, 대상 비디오와 프레임 단위로 정렬됩니다.
- 핵심 설계: 스켈레톤은 질감이 없고 운동학적 체인만 포함합니다. 체현 변경 시 운동학 삼중항 (M, q_t, o_k)만 교체하면 되며, 여기서 M은 운동학 모델(URDF 또는 MANO 손 모델), q_t는 관절 각도, o_k는 카메라 외부 파라미터입니다.
- 인간 손의 경우: MANO 손 모델로 교체하며, 다섯 손가락의 자유도가 두 손가락 그리퍼보다 높지만 동일한 2D 선 그림으로 통합 렌더링됩니다. 스켈레톤은 대략적인 동작을 구속하고, 사전 학습된 비디오 사전 지식이 세밀한 시각적 세부 사항을 채웁니다.

### 조건 주입
- 스켈레톤 렌더링 S₁:T는 WAN 2.1 VAE로 인코딩되어 스켈레톤 잠재 z^s가 되며, 대상 비디오 잠재 z^v와 형태가 동일합니다(둘 다 (T, C, H, W)).
- 각각 patch embedder PE_v와 PE_s로 DiT 히든 차원 D=2048에 임베딩한 후, 두 토큰 텐서를 요소별로 더하여 DiT 디노이징에 입력합니다.
- 훈련 시 0.2 확률로 S₁:T를 0으로 설정(classifier-free guidance), 추론 시 guidance scale w=6.

### 데이터 파이프라인(4단계)
1. **데이터 큐레이션**: RH20T(cfg5/cfg7), DROID, AgiBot World, InternData-A1, AIROA-MoMa, EgoDex, EPIC-Kitchens에서 소스 비디오 2,165,359개 클립 수집.
2. **데이터 필터링**: 4가지 메커니즘 — 길이 ≥70프레임; 정적 카메라(카메라 움직임이 임계값 미만); 의미 있는 동작(비자명한 조작기 동작 시퀀스); 가시 스켈레톤(가시 스켈레톤 비율이 임계값 미만이면 제거).
3. **의미론적 중복 제거**: 2단계 — 1단계는 SigLIP 이미지 임베딩(5프레임 균일 샘플링) 코사인 유사도 >0.95인 쌍을 표시; 2단계는 64단계 리샘플링 조작기 궤적을 추출하여 단계별 RMS 거리가 적응형 임계값 미만인 중복을 표시.
4. **데이터 주석**: Qwen3-VL-30B-A3B-Instruct가 80–100단어 영어 설명 생성, 로봇 데이터와 인간 데이터에 동일한 시스템 프롬프트 사용; DROID 클립은 샘플링 속도를 1–2fps로 낮춤(길이가 다른 소스의 약 5배이므로), 다른 소스는 15fps.

### 훈련 구성
- 기본 모델: Cosmos-Predict2.5-2B(rectified-flow 목적), WAN 2.1 VAE.
- 옵티마이저: AdamW, lr=3×10⁻⁵, batch size=16.
- 시간 단계 샘플링: logit-normal 분포 가중치, shift=5.
- 데이터 균형: 빈도 온도 가중치 wᵢ ∝ n_frames,i^(1/T), T=3.
- 훈련 창 81프레임, 시작 프레임은 사다리꼴 사전 확률로 그리핑/릴리스 이벤트에 편향.
- 2단계: 1단계는 4개 로봇 체현에서 15k 반복 훈련; 2단계는 전체 로봇+인간 혼합 데이터에서 계속 훈련(warm-start).

### 잠재 동작 경로(소거 연구용)
- 팔당 7차원 동작(3 병진 + 3 회전 + 1 그리퍼), 프레임 간 차분을 이전 프레임 로컬 좌표계로 표현, 병진/회전 차분을 20배 스케일링.
- 다중 본체 정렬: 통합 14차원 벡터, 양팔 연결, 단일 팔은 뒤 7차원을 0으로 설정.
- 주입: D차원 토큰을 시간 단계 임베딩에 추가, 3D 차원 토큰을 adaptive LayerNorm 변조 신호에 추가.

## 핵심 혁신

1. **스켈레톤 렌더링을 통한 체현 간 통합 조건**: 로봇 팔과 인간 손을 동시에 2D 운동학적 스켈레톤으로 다루는 최초의 동작 조건부 세계 모델입니다. 핵심 혁신은 '무질감' — 모델이 로봇 외관을 기억하는 대신 운동학과 실제 동작의 관계를 명시적으로 학습해야 하며, 이는 OOD 성능 저하를 직접 완화합니다. 메시 렌더링(URDF 자산 의존)과 포인트 클라우드(외관 과적합)에 비해 스켈레톤은 표현력과 일반화 사이에서 더 나은 균형을 달성합니다.

2. **인간 데이터 긍정적 전이의 실증**: 로봇 전용 훈련에 85,827개의 인간 손 클립(EgoDex+EPIC-Kitchens)을 추가하여 모든 지표가 지속적으로 개선되었습니다(FVD 7.69→7.08, FID 16.37→15.07). 이는 인간 1인칭 비디오가 로봇 데이터 부족 문제를 효과적으로 보완할 수 있음을 처음으로 입증했으며, warm-start 전략(로봇 먼저, 혼합 나중)이 처음부터 혼합하는 것보다 수렴이 더 빠릅니다.

3. **재현 가능한 평가 프로토콜**: 4개 체현에 걸친 200클립 평가 벤치마크(N 제곱근 할당으로 긴 꼬리 균형)를 구축하고, RoboArena 플랫폼(65세션×7정책=455유닛)으로 비디오 생성 품질과 하위 정책 평가 간의 상관관계를 처음으로 검증했습니다(Spearman ρ=0.750, Pearson r=0.852). GPT-5를 VLM 스코어러로 사용(인간 라벨과 78/100 일치).

스켈레톤 조건은 정책 순위 상관관계에서 최적(ρ=0.750)이며, 성공률 예측 오차가 가장 작습니다(SISR_Δ=1.73퍼센트 포인트).

### 체현별 성능(표 6-11)
OSCAR는 AgiBot G1(PSNR 23.70), DROID(21.60), InternData(27.65), RH20T-cfg5(26.92), RH20T-cfg7(25.85)에서 모두 최적입니다. AIROA-MoMa에서만 Genie Envisioner에 뒤처집니다(PSNR 20.77 vs 23.31). 이는 이동 베이스+팔 조합이 훈련 데이터에서 차지하는 비중이 극히 작기 때문입니다(3,712클립).

## 경계 및 한계

- **데이터 규모는 캘리브레이션 품질에 제한됨**: 카메라 내부/외부 파라미터 오차는 스켈레톤-RGB 정렬을 직접 저하시켜 안정적으로 변환 가능한 원본 비디오 수를 제한합니다. 이는 현재 가장 큰 병목입니다 — 모델 용량이 아니라 캘리브레이션 품질입니다.
- **정적 카메라 가정**: 로봇 동작에만 초점을 맞추며, 카메라 움직임은 향후 작업으로 남겨둡니다. 이는 이동 조작의 능동 시각(active perception) 시나리오에는 적용할 수 없음을 의미합니다.
- **2B 백본 상한**: 2B 파라미터만 사용하며, 저자는 더 큰 백본으로 확장하면 추가 개선이 가능하지만 더 많은 계산이 필요하다고 인정합니다.
- **VLM 스코어러 보수적**: GPT-5의 재현율은 0.66에 불과하여 실제 성공의 약 1/3을 놓치며, 성공률을 과대평가하지 않고 과소평가합니다. 정책 평가의 절대 성공률 수치는 주의 깊게 해석해야 합니다.
- **AIROA-MoMa 일반화 부족**: 이동 베이스+팔 조합이 훈련 데이터에서 차지하는 비중이 극히 작으며(3,712/180,657 ≈ 2%), OSCAR는 이 하위 집합에서 Genie Envisioner에 뒤처집니다. 긴 꼬리 체현에는 여전히 더 많은 데이터가 필요함을 시사합니다.
- **소거 연구 정량 세부 사항 미공개**: 표 3은 본문에서만 언급되고, 부록에는 정성적 그림만 제공됩니다. 인간 데이터 정량 평가 지표는 제공되지 않았습니다.

## 엔지니어링 시사점

- **재현 시 데이터 파이프라인 우선 확인**: 필터링 후 180,657/2,165,359클립(8.3% 보존율)만 유지되며, 의미론적 중복 제거(SigLIP>0.95 + 64단계 궤적 RMS)가 핵심 단계입니다. 중복 제거를 건너뛰면 중복 클립이 훈련을 지배하고 일반화를 저해합니다. DROID의 1–2fps 다운샘플링(클립 길이가 다른 소스의 약 5배이므로)과 RH20T의 cfg5/cfg7 선택(cfg1은 고유 수용 감각 부족, cfg3은 외부 파라미터 캘리브레이션 오류)을 먼저 재현하는 것이 좋습니다.
- **스켈레톤 렌더링 구현 요점**: 조건 주입은 '스켈레톤 잠재 z^s와 대상 잠재 z^v의 요소별 덧셈'이며, 연결이 아닙니다 — 이는 두 VAE 인코딩 후 형태가 완전히 동일해야 함을 요구합니다. 체현 변경 시 운동학 삼중항 (M, q_t, o_k)만 업데이트하면 되지만, 카메라 외부 파라미터 o_k와 스켈레톤 렌더링의 투영 행렬이 엄격히 정렬되어야 합니다. 그렇지 않으면 스켈레톤-RGB 오프셋이 생성 품질을 직접 저하시킵니다.
- **훈련 전략**: warm-start(로봇 15k 반복 먼저, 인간 데이터 혼합 나중)가 처음부터 혼합하는 것보다 수렴이 빠르고 효과가 좋습니다. 데이터 균형은 빈도 온도 가중치 T=3을 사용하여 작은 데이터 소스(예: AIROA-MoMa 3,712클립)의 가중치를 높일 수 있습니다. 훈련 창 81프레임, 시작 프레임은 사다리꼴 사전 확률로 그리핑/릴리스 이벤트에 편향 — 이는 그리퍼 개폐 신호를 활용하며 조작 비디오 생성에 중요합니다.
- **평가 프로토콜**: 지표는 처음 49프레임에서 계산됩니다(Kinema4D 프로토콜 준수). 정책 평가 시 GPT-5 스코어링의 보수성(재현율 0.66)에 주의하고, 절대 성공률만이 아닌 MMRV와 Spearman ρ를 함께 보고하는 것이 좋습니다. 카메라 캘리브레이션은 MoGe-v2(내부 파라미터) + CtRNet-X(외부 파라미터, BPnP 대 URDF 정운동학)를 사용 — 이는 정책 평가 재현의 가장 큰 엔지니어링 위험 지점입니다.
- **가장 흔한 함정**: IRASim의 7-DoF 동작 인터페이스는 양팔 AgiBot G1과 이동 베이스 AIROA-MoMa와 호환되지 않으므로 비교 시 제외해야 합니다. EnerVerse-AC의 파라미터 수는 공식적으로 보고되지 않았습니다(저자 실측 U-Net 훈련 가능 파라미터 1.46B). Kinema4D는 추론이 매우 느리므로(0.089FPS), 정책 평가 시 충분한 시간을 확보해야 합니다.
