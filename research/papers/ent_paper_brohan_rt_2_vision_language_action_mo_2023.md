## 概述

RT-2 是 Google 提出的视觉-语言-动作（VLA）模型，将机器人动作离散化为文本 token，与网络规模数据共同微调预训练 VLM（PaLI-X、PaLM-E），实现端到端机器人控制。核心贡献在于证明互联网级视觉-语言预训练可以直接迁移到低层控制策略，带来显著的泛化提升和涌现式语义推理能力。

## 它改变了什么

在 RT-2 之前，LLM/VLM 在机器人领域的应用被严格限定在“高层规划”角色——解析指令、输出子目标，而底层动作执行仍由独立训练的小模型（如 RT-1）完成。这种割裂意味着底层控制器永远无法从互联网规模的语义知识中获益，其泛化能力受限于机器人演示数据的规模和多样性。RT-2 真正改变的，是打破了这条边界：它让同一个模型既理解“把苹果放到和杯子同色的容器里”这种抽象语义，又能直接输出末端执行器的 7 维动作向量。这不仅是架构上的简化，更是对“机器人数据稀缺”这一根本瓶颈的回应——与其暴力收集数百万条机器人轨迹，不如复用 VLM 在数十亿图文对上习得的世界知识。

## 方法拆解

### 动作编码与 token 化
- 基于 RT-1 的离散化方案：6 自由度末端执行器位姿（位置+旋转）+ 夹爪开合 + 终止命令，连续维度均匀量化到 256 个 bin，动作表示为 8 个整数。
- 动作 token 映射：PaLI-X 直接复用 0-255 的整数 token；PaLM-E 则从词表中挑选 256 个最少使用的 token 作为动作词汇，避免与自然语言 token 冲突。

### 输入输出格式
- 输入采用标准 VQA 格式：“Q: what action should the robot take to [指令]? A:”，输出为动作 token 字符串。
- 推理时对动作任务施加输出约束，仅采样有效动作 token；标准 VQA 任务不受限。

### 共微调（Co-Fine-Tuning）
- 关键设计：将机器人数据与原始网络数据（WebLI、VQA、图文交错等）混合训练，而非仅用机器人数据微调。通过提高机器人数据采样权重平衡批次比例（PaLI-X 约 50%，PaLM-E 约 66%）。
- 动机：仅微调会导致模型遗忘网络预训练知识，共微调则让策略持续暴露于抽象视觉概念，从而获得更强的泛化。

### 实时推理
- 部署于多 TPU 云服务，通过网络查询实现闭环控制，可同时服务多个机器人。55B 模型推理频率 1-3 Hz，5B 模型约 5 Hz。

### 链式思维变体
- 在数据中增加“Plan”步骤，先用自然语言描述动作意图，再输出动作 token。仅微调几百步，定性观察有效。

## 关键创新

1. **动作即文本的统一表征**：将连续动作空间离散化为文本 token，使机器人控制与 VLM 的 next-token 预测目标完全对齐。这一设计看似简单，却让模型无需任何架构改动即可复用预训练权重，是 VLA 范式的奠基性工作。
2. **共微调策略**：不是“先预训练后微调”的两阶段，而是将机器人数据与网络数据持续混合训练。消融实验证明共微调显著优于仅微调（55B 模型未见平均成功率 63% vs 52%），这揭示了保持预训练知识“鲜活”的重要性。
3. **涌现式语义推理**：在未见过的指令上（如“move apple to 3”、“move the coke can to the person with glasses”），RT-2 无需额外示范即达到 60% 平均成功率，是 RT-1（17%）的 3 倍以上。这证明互联网预训练带来的符号理解、多语言、基础推理能力可以零样本迁移到动作生成。

## 边界与局限

- **物理技能无新增**：RT-2 不会获得机器人数据中未出现的新动作能力，只能以新方式组合已有技能。作者明确承认这是数据集技能轴多样性不足的结果。
- **特定操作失败**：按特定部位抓取（如手柄）、新奇运动（毛巾擦拭、工具使用）、灵巧操作（折叠毛巾）、多层间接推理等场景表现不佳。
- **计算成本**：55B 模型推理仅 1-3 Hz，难以满足高频控制需求；作者建议未来探索量化和蒸馏。
- **链式思维未量化**：仅做了定性观察，无定量评估。
- **55B 从零训练未评估**：因 5B 从零训练表现差（9%）而跳过，无法确认更大规模是否改变结论。

## 工程启示

- **复现优先级**：先核对动作 token 映射方案——PaLI-X 直接复用整数 token，PaLM-E 需挑选最少用 token，两者实现细节不同，选错会导致训练不收敛。
- **共微调是核心**：不要跳过网络数据混合。消融显示仅微调会让 55B 模型未见泛化从 63% 掉到 52%，5B 模型差距更大。机器人数据采样权重（50%-66%）是关键超参数。
- **规模敏感**：5B 与 55B 在未见泛化上差距显著（44% vs 63%），如果资源受限，优先保证模型规模而非训练步数。
- **推理频率是硬约束**：55B 模型 1-3 Hz 只适合慢速操作任务；若需高频控制，考虑 5B 版本或蒸馏方案。
- **评估协议**：未见环境 Easy 与 Hard 差距极大（63% vs 35%），报告结果时务必区分难度层级，否则会高估模型能力。

### 核心内容


#### 是什么：RT-2 的准确定义
RT-2 属于 **方法**（method）类型实体，英文全称为 *RT-2 Vision-Language-Action Model*，韩文名称为 *RT-2 비전-언어-동작 모델*。其所属领域编码为 `07_ai_models_algorithms`，理论深度为 `method` 层级，状态为 `active`。

在实体分类学的本体论承诺中，RT-2 属于**信息实体（Information Entity）**——它以符号和数据形式存在，不占据时空、不具有质量。它与 `paper`、`algorithm`、`dataset` 同属一个大类，但更准确地说是"方法"而非"算法"：它不提供单一的数学求解步骤，而是定义了一种将视觉-语言预训练知识转化为机器人动作输出的建模范式。

RT-2 的核心思想可以概括为一句话：**把机器人的动作当作语言来写**。它将动作表示为文本 token（如"移动到 (x, y, z)"），与图像、指令一起输入到统一的 Transformer 模型中，通过自回归方式逐 token 生成动作序列。这样，模型在互联网图文数据上学到的语义知识——比如"杯子是什么""打开抽屉意味着什么"——就能直接迁移到机器人控制中。

#### 为什么存在：痛点与历史定位
在 RT-2 出现之前，机器人学习面临一个根本性矛盾：**机器人数据稀缺，而互联网数据丰富**。传统方法（如行为克隆、强化学习）依赖大量机器人演示数据，采集成本极高；而互联网上数以亿计的图文对虽然蕴含丰富的语义知识，却无法直接用于机器人控制。

RT-2 的历史定位正是为了解决这一矛盾。它属于 VLA（Vision-Language-Action）模型家族，其前身 RT-1 已经证明了"用 Transformer 统一视觉-语言-动作"的可行性，但 RT-1 的训练数据仍主要来自机器人演示。RT-2 的突破在于：**将网络规模的视觉-语言知识作为预训练基础，再通过少量机器人数据微调**，从而大幅降低对机器人数据的依赖。

这一思路与同时期的 Unified-IO 2 一脉相承——后者将图像、文本、音频、动作、边界框等多种模态的输入输出 token 化到共享语义空间，由单一编码器-解码器 Transformer 处理，并在 120 个数据集的集成上微调。RT-2 则更聚焦于机器人动作生成这一下游任务。

#### 原理拆解
**① 动作即文本：统一 token 空间的建模基础**

RT-2 的底层假设是：机器人的动作可以离散化为有限集合，并映射为文本 token。例如，机械臂的末端位姿变化可以被编码为"移动到 (x, y, z)，旋转 (roll, pitch, yaw)"这样的文本序列。这样，动作生成就变成了一个条件文本生成问题：

$$
p(a_t \mid v_t, l) = \prod_{i=1}^{N} p(t_{a,i} \mid t_{a,<i}, v_t, l)
$$

其中 $v_t$ 为当前视觉观测，$l$ 为语言指令，$t_{a,i}$ 为动作序列的第 $i$ 个 token，$N$ 为动作 token 总数。模型通过最大化条件概率来训练，推理时则用自回归解码逐 token 生成动作。

**② 知识迁移：从 VLM 到 VLA 的权重继承**

RT-2 的关键工程决策是**直接继承预训练 VLM 的权重**。它不从头训练，而是将 PaLI-X 或 PaLM-E 等 VLM 的骨干网络作为初始化，在机器人数据上继续微调。这样，模型在互联网图文上学到的物体识别、空间关系理解、指令跟随等能力被完整保留，只需学习"如何将语义理解映射为动作"这一新映射。

**③ 与 RT-Affordance 的对比：中间表示的选择**

RT-2 直接输出动作 token，而 RT-Affordance 则采用分层架构：先由可供性规划器（affordance planner）根据任务语言生成关键阶段的机器人姿态序列，再由策略执行器（policy executor）以该计划为条件生成具体动作。RT-Affordance 的动机是：直接输出动作的表示在复杂任务中上下文不足，而语言、目标图像等中间表示又存在过度指定问题。可供性（即任务关键阶段机器人姿态）兼具表达力与轻量性，且能通过迁移大规模互联网数据集知识实现高效学习。这两种路径代表了 VLA 设计的两种哲学：**端到端直接映射** vs **分层中间表示**。

HiRT 的对比尤其值得注意：它指出现有 VLA 模型依赖数十亿参数的 VLM 后端，虽具备强大泛化能力，但高计算成本与推理延迟使其主要适用于准静态任务。HiRT 通过分层设计实现灵活的频率-性能权衡——低频运行的 VLM 提取时不变特征，高频视觉策略基于这些特征进行实时交互，在静态任务中保持成功率的同时将控制频率翻倍，在动态操作任务中显著超越基线方法。这揭示了 RT-2 类端到端模型的一个核心局限：**推理延迟与高频控制之间的矛盾**。

#### 谁在用：应用案例
RT-2 及其 VLA 家族主要应用于以下场景：

1. **语义泛化操作**：面对未见过的物体或场景，RT-2 能利用互联网图文知识理解"这是什么""应该怎么处理"，从而完成传统方法无法泛化的操作任务。例如，模型在训练中从未见过某个特定品牌的杯子，但通过视觉-语言预训练学到的"杯子"概念，仍能正确抓取。

2. **指令跟随**：用户用自然语言描述任务（如"把红色方块放到蓝色盘子旁边"），RT-2 将语言指令与视觉观测联合编码，生成对应的动作序列。

3. **多任务学习**：RT-2 在多个任务上联合训练，共享同一个模型参数，避免了为每个任务单独训练一个策略的开销。

4. **与分层方法结合**：如 RT-Affordance 所示，可供性规划器可以生成关键姿态序列，再由执行器细化动作——这种分层设计可以弥补 RT-2 直接输出动作在复杂任务中的上下文不足问题。

#### 局限与边界
1. **推理延迟**：RT-2 依赖数十亿参数的 VLM 后端，推理延迟高，主要适用于准静态任务。HiRT 的实验数据表明，基线 VLA 模型的推理延迟约为 320ms，而 HiRT 通过分层设计将其降至 50ms（按语料数据推算，HiRT 延迟约为基线的 15.6%）。对于需要高频反馈的动态操作（如抓取移动物体），RT-2 类端到端模型难以胜任。

2. **动作表示的离散化精度**：将连续动作离散化为文本 token 会引入量化误差。动作空间的粒度选择需要在表达力与模型复杂度之间权衡。

3. **数据分布偏移**：RT-2 在互联网图文上预训练，但机器人操作场景的视觉分布与互联网图片存在差异（如视角、光照、背景），可能导致域偏移问题。

4. **缺乏物理一致性保证**：RT-2 生成的动作序列不保证满足动力学约束（如关节力矩极限、摩擦锥约束）。在真实机器人上部署时，需要额外的安全过滤层或后处理优化。

#### 常见误区
1. **"RT-2 是通用机器人控制器"**——错。RT-2 是方法而非完整系统，它不包含运动规划、力控制、安全监控等模块。它生成的是高层动作指令，底层执行仍需传统控制栈。

2. **"RT-2 不需要机器人数据"**——错。RT-2 虽然大幅降低了对机器人数据的依赖，但仍需一定量的机器人演示数据进行微调。它真正改变的是**数据效率**，而非彻底摆脱机器人数据。

3. **"VLA 模型可以直接部署到人形机器人"**——错。人形机器人是高维、欠驱动、强耦合系统，RT-2 类模型的动作空间通常针对机械臂设计，直接迁移到人形机器人需要重新定义动作表示并处理全身协调问题。

4. **"动作 token 化与连续控制等价"**——错。离散 token 化会丢失精细的力控信息，对于需要精确力交互的任务（如装配、打磨），RT-2 类方法力有不逮。

## Overview

RT-2 is a Vision-Language-Action (VLA) model proposed by Google that discretizes robot actions into text tokens and co-fine-tunes a pre-trained VLM (PaLI-X, PaLM-E) with web-scale data to achieve end-to-end robot control. The core contribution lies in demonstrating that internet-scale vision-language pre-training can be directly transferred to low-level control policies, yielding significant generalization improvements and emergent semantic reasoning capabilities.

## What It Changed

Before RT-2, LLM/VLM applications in robotics were strictly confined to the "high-level planning" role—parsing instructions and outputting sub-goals—while low-level action execution was still handled by independently trained small models (e.g., RT-1). This separation meant that low-level controllers could never benefit from internet-scale semantic knowledge, and their generalization was limited by the size and diversity of robot demonstration data. What RT-2 truly changed was breaking this boundary: it enabled the same model to both understand abstract semantics like "put the apple into the container that matches the cup's color" and directly output the 7-dimensional action vector for the end-effector. This is not merely an architectural simplification but a response to the fundamental bottleneck of "robot data scarcity"—rather than laboriously collecting millions of robot trajectories, it is better to reuse the world knowledge that VLMs have acquired from billions of image-text pairs.

## Method Breakdown

### Action Encoding and Tokenization
- Based on RT-1's discretization scheme: 6-DoF end-effector pose (position + rotation) + gripper open/close + termination command, with continuous dimensions uniformly quantized into 256 bins, representing actions as 8 integers.
- Action token mapping: PaLI-X directly reuses integer tokens 0-255; PaLM-E selects 256 least-used tokens from the vocabulary as action tokens to avoid conflicts with natural language tokens.

### Input-Output Format
- Input uses the standard VQA format: "Q: what action should the robot take to [instruction]? A:", with output as a string of action tokens.
- During inference, output constraints are applied to action tasks, sampling only valid action tokens; standard VQA tasks remain unconstrained.

### Co-Fine-Tuning
- Key design: mixing robot data with original web data (WebLI, VQA, interleaved image-text, etc.) for training, rather than fine-tuning solely on robot data. Batch proportions are balanced by increasing the sampling weight of robot data (approximately 50% for PaLI-X, 66% for PaLM-E).
- Motivation: fine-tuning alone causes the model to forget pre-trained web knowledge, whereas co-fine-tuning keeps the policy continuously exposed to abstract visual concepts, resulting in stronger generalization.

### Real-Time Inference
- Deployed on multi-TPU cloud services, enabling closed-loop control via network queries and serving multiple robots simultaneously. The 55B model infers at 1-3 Hz, while the 5B model runs at approximately 5 Hz.

### Chain-of-Thought Variant
- Adds a "Plan" step to the data, first describing the action intent in natural language, then outputting action tokens. Fine-tuned for only a few hundred steps, with qualitative observations showing effectiveness.

## Key Innovations

1. **Unified Representation of Actions as Text**: Discretizing the continuous action space into text tokens aligns robot control perfectly with the VLM's next-token prediction objective. This design, though seemingly simple, allows the model to reuse pre-trained weights without any architectural changes—a foundational work for the VLA paradigm.
2. **Co-Fine-Tuning Strategy**: Rather than a two-stage "pre-train then fine-tune" approach, robot data and web data are continuously mixed during training. Ablation experiments show that co-fine-tuning significantly outperforms fine-tuning alone (63% vs 52% unseen average success for the 55B model), revealing the importance of keeping pre-trained knowledge "alive."
3. **Emergent Semantic Reasoning**: On unseen instructions (e.g., "move apple to 3," "move the coke can to the person with glasses"), RT-2 achieves a 60% average success rate without additional demonstrations—more than 3 times that of RT-1 (17%). This proves that symbolic understanding, multilingual capabilities, and basic reasoning from internet pre-training can transfer zero-shot to action generation.

## Boundaries and Limitations

- **No New Physical Skills**: RT-2 does not acquire new action capabilities absent from robot data; it can only combine existing skills in novel ways. The authors explicitly acknowledge this as a result of insufficient skill-axis diversity in the dataset.
- **Specific Operation Failures**: Poor performance in scenarios such as grasping specific parts (e.g., handles), novel movements (towel wiping, tool use), dexterous manipulation (folding towels), and multi-step indirect reasoning.
- **Computational Cost**: The 55B model infers at only 1-3 Hz, making it difficult to meet high-frequency control demands; the authors suggest exploring quantization and distillation in the future.
- **Chain-of-Thought Not Quantified**: Only qualitative observations were made, with no quantitative evaluation.
- **55B from Scratch Not Evaluated**: Skipped due to poor performance of the 5B from-scratch model (9%), leaving it unclear whether larger scale would change the conclusion.

## Engineering Insights

- **Reproduction Priority**: First verify the action token mapping scheme—PaLI-X directly reuses integer tokens, while PaLM-E requires selecting least-used tokens; the implementation details differ, and choosing incorrectly can cause training divergence.
- **Co-Fine-Tuning Is Core**: Do not skip web data mixing. Ablations show that fine-tuning alone drops the 55B model's unseen generalization from 63% to 52%, with an even larger gap for the 5B model. The robot data sampling weight (50%-66%) is a critical hyperparameter.
- **Scale Sensitivity**: The gap between 5B and 55B on unseen generalization is significant (44% vs 63%); if resources are constrained, prioritize model scale over training steps.
- **Inference Frequency Is a Hard Constraint**: The 55B model's 1-3 Hz is only suitable for slow manipulation tasks; for high-frequency control, consider the 5B version or distillation approaches.
- **Evaluation Protocol**: The gap between Easy and Hard unseen environments is substantial (63% vs 35%); difficulty levels must be distinguished when reporting results, otherwise model capabilities will be overestimated.

## 개요

RT-2는 Google이 제안한 비전-언어-행동(VLA) 모델로, 로봇의 행동을 이산화된 텍스트 토큰으로 변환하고, 네트워크 규모의 데이터로 사전 학습된 VLM(PaLI-X, PaLM-E)을 공동 미세 조정하여 엔드투엔드 로봇 제어를 구현합니다. 핵심 기여는 인터넷 규모의 비전-언어 사전 학습이 저수준 제어 정책으로 직접 전이될 수 있음을 증명하고, 상당한 일반화 향상과 창발적 의미 추론 능력을 가져왔다는 점입니다.

## 무엇을 바꾸었는가

RT-2 이전에는 LLM/VLM의 로봇 분야 적용이 '고수준 계획' 역할로 엄격히 제한되었습니다. 즉, 명령을 해석하고 하위 목표를 출력하는 역할이었으며, 저수준 행동 실행은 여전히 독립적으로 학습된 소형 모델(예: RT-1)이 수행했습니다. 이러한 분리는 저수준 컨트롤러가 인터넷 규모의 의미론적 지식의 혜택을 결코 받을 수 없음을 의미하며, 그 일반화 능력은 로봇 시연 데이터의 규모와 다양성에 제한되었습니다. RT-2가 진정으로 바꾼 것은 이 경계를 허문 것입니다. 동일한 모델이 "사과를 컵과 같은 색의 용기에 넣어라"와 같은 추상적 의미를 이해하면서도 엔드 이펙터의 7차원 행동 벡터를 직접 출력할 수 있게 했습니다. 이는 아키텍처의 단순화일 뿐만 아니라 '로봇 데이터 희소성'이라는 근본적 병목에 대한 대응입니다. 수백만 개의 로봇 궤적을 무리하게 수집하는 대신, VLM이 수십억 개의 이미지-텍스트 쌍에서 학습한 세계 지식을 재사용하는 것입니다.

## 방법 분석

### 행동 인코딩 및 토큰화
- RT-1 기반 이산화 방식: 6자유도 엔드 이펙터 포즈(위치+회전) + 그리퍼 개폐 + 종료 명령, 연속 차원을 256개 bin으로 균일 양자화하여 행동을 8개의 정수로 표현.
- 행동 토큰 매핑: PaLI-X는 0-255 정수 토큰을 직접 재사용; PaLM-E는 어휘집에서 가장 적게 사용되는 256개 토큰을 행동 어휘로 선택하여 자연어 토큰과의 충돌을 방지.

### 입력 및 출력 형식
- 입력은 표준 VQA 형식: "Q: what action should the robot take to [명령]? A:", 출력은 행동 토큰 문자열.
- 추론 시 행동 작업에는 출력 제약을 적용하여 유효한 행동 토큰만 샘플링; 표준 VQA 작업은 제약 없음.

### 공동 미세 조정(Co-Fine-Tuning)
- 핵심 설계: 로봇 데이터를 원본 네트워크 데이터(WebLI, VQA, 이미지-텍스트 인터리브 등)와 혼합하여 학습하며, 로봇 데이터만으로 미세 조정하지 않음. 로봇 데이터 샘플링 가중치를 높여 배치 비율을 균형 있게 조정(PaLI-X 약 50%, PaLM-E 약 66%).
- 동기: 미세 조정만 수행하면 모델이 네트워크 사전 학습 지식을 망각하게 되며, 공동 미세 조정은 정책이 추상적 시각 개념에 지속적으로 노출되어 더 강력한 일반화를 얻을 수 있게 함.

### 실시간 추론
- 다중 TPU 클라우드 서비스에 배포되어 네트워크 쿼리를 통한 폐루프 제어를 구현하며, 여러 로봇을 동시에 서비스할 수 있음. 55B 모델 추론 주파수는 1-3 Hz, 5B 모델은 약 5 Hz.

### 사고 사슬 변형
- 데이터에 "Plan" 단계를 추가하여 먼저 자연어로 행동 의도를 설명한 후 행동 토큰을 출력. 수백 단계만 미세 조정하여 정성적으로 효과를 관찰.

## 핵심 혁신

1. **행동을 텍스트로 표현하는 통합 표현**: 연속 행동 공간을 텍스트 토큰으로 이산화하여 로봇 제어와 VLM의 next-token 예측 목표를 완전히 정렬. 이 설계는 단순해 보이지만 모델이 아키텍처 변경 없이 사전 학습 가중치를 재사용할 수 있게 하며, VLA 패러다임의 기초 작업입니다.
2. **공동 미세 조정 전략**: '사전 학습 후 미세 조정'의 2단계가 아니라 로봇 데이터와 네트워크 데이터를 지속적으로 혼합 학습. 소거 실험에서 공동 미세 조정이 미세 조정만 수행한 것보다 현저히 우수함(55B 모델 미경험 평균 성공률 63% vs 52%)을 증명하여 사전 학습 지식을 '생생하게' 유지하는 중요성을 밝힘.
3. **창발적 의미 추론**: 미경험 명령(예: "move apple to 3", "move the coke can to the person with glasses")에서 RT-2는 추가 시연 없이 평균 성공률 60%에 도달하며, 이는 RT-1(17%)의 3배 이상입니다. 이는 인터넷 사전 학습이 제공하는 기호 이해, 다국어, 기초 추론 능력이 제로샷으로 행동 생성에 전이될 수 있음을 증명합니다.

## 경계 및 한계

- **물리적 기술 추가 없음**: RT-2는 로봇 데이터에 없는 새로운 행동 능력을 얻지 못하며, 기존 기술을 새로운 방식으로 조합할 수만 있습니다. 저자는 이것이 데이터셋의 기술 축 다양성 부족 때문임을 명시적으로 인정.
- **특정 조작 실패**: 특정 부위(예: 손잡이) 잡기, 새로운 동작(수건 닦기, 도구 사용), 정교한 조작(수건 접기), 다층 간접 추론 등의 시나리오에서 성능 저하.
- **계산 비용**: 55B 모델 추론은 1-3 Hz에 불과하여 고주파 제어 요구를 충족하기 어려움; 저자는 향후 양자화 및 증류 탐구를 제안.
- **사고 사슬 미정량화**: 정성적 관찰만 수행, 정량적 평가 없음.
- **55B 처음부터 학습 미평가**: 5B 처음부터 학습 성능 저하(9%)로 인해 건너뛰었으며, 더 큰 규모가 결론을 바꿀 수 있는지 확인 불가.

## 공학적 시사점

- **재현 우선순위**: 먼저 행동 토큰 매핑 방식을 확인 — PaLI-X는 정수 토큰을 직접 재사용, PaLM-E는 가장 적게 사용되는 토큰을 선택해야 하며, 구현 세부 사항이 다르므로 잘못 선택하면 학습이 수렴하지 않을 수 있음.
- **공동 미세 조정이 핵심**: 네트워크 데이터 혼합을 건너뛰지 말 것. 소거 실험에서 미세 조정만 수행하면 55B 모델의 미경험 일반화가 63%에서 52%로 떨어지며, 5B 모델은 차이가 더 큼. 로봇 데이터 샘플링 가중치(50%-66%)가 핵심 하이퍼파라미터.
- **규모 민감성**: 5B와 55B는 미경험 일반화에서 현저한 차이(44% vs 63%)를 보이므로, 자원이 제한된 경우 학습 단계 수보다 모델 규모를 우선시.
- **추론 주파수는 하드 제약**: 55B 모델의 1-3 Hz는 저속 조작 작업에만 적합; 고주파 제어가 필요하면 5B 버전 또는 증류 방안 고려.
- **평가 프로토콜**: 미경험 환경 Easy와 Hard의 차이가 매우 큼(63% vs 35%), 결과 보고 시 난이도 수준을 반드시 구분해야 하며, 그렇지 않으면 모델 능력을 과대평가할 수 있음.
