## 概述

这篇综述由领域内研究者撰写，系统梳理了机器人学习中的进度奖励建模（Progress Reward Modeling）。其核心贡献在于提出一个统一视角，将碎片化的文献按接口、方法与数据三个层面组织，并识别出四种构建范式，为后续研究与工程实践提供了清晰的坐标系。

## 它改变了什么

长期以来，机器人学习依赖终端成功信号作为唯一奖励来源，这在长时程、高维、动态的任务中尤为致命——稀疏的反馈迫使智能体在大量决策后才能获得任何有用信息，而中间过程的好坏完全不可见。进度估计（progress estimation）被视为解药，但该领域本身陷入混乱：类似术语描述不同问题，评估协议各异，方法之间难以比较，报告结果的实际意义也常常模糊不清。

这篇综述真正改变的是领域内的“认知地图”。它没有提出新算法，而是将散落的文献重新组织为三个连接步骤——接口、方法与数据，并识别出四种构建范式（冻结基础模型、时间/相对监督、指令调优、程序化构建）。这种结构化视角让研究者能快速定位自己的工作坐标，也让下游工程师能根据任务特性选择合适的方法族，而非在论文迷宫中盲目试错。

## 方法拆解

综述以三个视角拆解进度奖励建模，每个视角内部又有细分类别。

### 接口视角（第2节）：模型作为任务条件黑盒
- **任务状态表示**：
  - 单观测输入：低延迟、易在线使用，但视觉相似状态可能因执行历史不同而含义不同。
  - 时间上下文输入：轨迹前缀或短窗口（在线）或完整轨迹（离线），更长上下文提供更强时间证据但削弱在线可用性。
  - 比较式输入：通过比较两个参考状态（动作前后、初始与当前等）估计进度，但局部比较可能遗漏长时程依赖，成对判断链可能累积误差。
  - 状态访问接口：使用环境代码、模拟器API或本体感觉特征，最适用于模拟或仪器化环境，真实世界通常不现实。
- **任务目标规范**：
  - 语言条件：易于编码、兼容现有VLM，但语言可能欠指定物理细节，尤其任务变长、更组合化时。
  - 视觉条件：目标图像或演示轨迹捕获难以言说的物理细节，但需人工策划且对视角、具身差异敏感。
  - 结构化/程序化目标：通过谓词、约束或生成的目标函数表达，支持精确密集奖励，但依赖显式状态变量访问，开放世界不可用。
- **模型输出形式**：
  - 状态级标量分数：最常用，但含义取决于校准方式。
  - 进度增量：预测转换是否改善状态（如VLAC、ARM），与RL自然对齐但描述局部改进。
  - 排序：相对且间接，需转换为标量奖励。
  - 程序化输出：输出可执行奖励函数，灵活但可靠性取决于代码质量。

### 方法视角（第3节）：四种构建范式
- **冻结基础模型作为语义奖励评分器**：不训练，直接从预训练模型提取信号（如CLIP式图像-文本相似度、TOPReward的“true” token概率）。零样本可用，但分数是语义先验而非校准奖励，需归一化、阈值化或差分。
- **从时间和相对监督学习**：常见监督源是成功演示中的时间顺序（后期状态更接近完成）或偏好/排序信息（如RL-VLM-F、Rank2Reward）。相对监督易收集，但不直接提供标量奖励。
- **指令调优的进度预测**：将进度估计表述为显式指令遵循任务，通过任务特定提示定义进度判断，然后微调VLM（如RoboReward、VLAC、ProgressLM）。关键思想是进度预测成为模型指令遵循能力的一部分，而非隐式副产品。
- **程序化奖励构建**：将进度估计翻译为代码、谓词或结构化奖励逻辑（如Text2Reward、Eureka）。在任务可分解为显式子目标时有效，但将挑战转移到任务分解与特征设计。

### 数据与基准视角（第4节）
- 按人类参与程度组织数据构建：人类遥操作、人类在环标注、全自动时间结构监督、基础模型自动标注、数据增强。
- 按三个评估目标分组基准：进度保真度（标量校准、时间一致性）、鲁棒性与泛化（视角、具身、非单调执行）、下游效用（在线策略学习、离线重标注、检索过滤、规划）。

## 关键创新

1. **统一视角的提出**：首次将碎片化的进度奖励文献按接口、方法、数据三个层面系统组织，识别出四种构建范式。这不是简单的分类学，而是揭示了不同方法之间的深层联系——例如指令调优范式将进度预测从视觉表示学习的副产品转变为显式监督的指令遵循能力，这一洞察改变了研究者对问题本质的理解。

2. **评估维度的系统化**：将基准测试从单一的成功率或误差指标扩展为三个层次——进度保真度（标量校准、时间一致性）、鲁棒性与泛化（视角、具身、非单调执行）、下游效用（在线学习、离线重标注、检索、规划）。特别强调“策略性能提升本身不能证明奖励是忠实的进度估计器”，这一区分对实验设计有直接指导意义。

3. **对未来方向的明确诊断**：指出当前模型在细粒度敏感性、自适应时间建模、高效在线推理和长时程记忆四个方面的具体缺陷，并给出可操作的改进建议（如流式视觉编码器、分层奖励查询、紧凑任务记忆）。这些诊断基于对现有方法局限的细致分析，而非泛泛而谈。

## 边界与局限

作者明确承认的局限包括：单观测输入无法区分视觉相似但历史不同的状态；时间上下文输入在在线可用性与时间证据之间权衡；比较式接口可能遗漏长时程依赖且成对判断链累积误差；状态访问接口在真实世界通常不可用。语言目标欠指定物理细节，视觉目标对视角和具身差异敏感，结构化目标依赖显式状态变量。冻结基础模型的分数是语义先验而非校准奖励，偏好输出仅相对定义进度，程序化方法的可靠性取决于代码质量。人类驱动数据构建昂贵且主观，全自动时间结构监督假设进度与时间充分相关，基础模型自动标注继承模型偏差。

此外，作者指出当前模型普遍缺乏细粒度敏感性（稀疏采样帧可能错过精确对齐等小变化）、固定速率假设（真实进度往往不均匀，存在突然增加和长平台期）、推理延迟（大型VLM难以在每个控制步骤使用）以及长时程记忆缺失（视觉相似观测可能对应不同阶段）。论文未明确讨论计算资源需求、不同方法族之间的定量性能对比，以及这些方法在真实物理机器人上的部署经验。

## 工程启示

对于希望复现或选择进度奖励方法的工程师，以下几点值得优先核对：

1. **先明确任务特性再选方法族**：如果任务可分解为显式子目标且状态变量可访问，程序化构建（如Text2Reward）最可靠；如果只有语言指令和视觉输入，指令调优范式（如VLAC）更合适；如果追求零样本快速部署，冻结基础模型可作为起点但必须配合归一化和阈值化。

2. **警惕“平滑即正确”的陷阱**：许多方法使用时间顺序作为监督，鼓励进度随时间平滑增加，但真实任务往往有突然跳跃和平台期。评估时务必加入非单调执行测试（失败、回退、重试），否则模型可能只是学会了“经过时间越长进度越高”的捷径。

3. **在线推理成本是隐藏瓶颈**：大型VLM处理多帧并推理后才能产生奖励，对离线评估可接受，但难以在每个控制步骤使用。建议采用分层策略——轻量模型高频调用处理局部更新，大型模型仅在重要任务转换或不确定状态时调用。

4. **评估指标必须分层**：策略性能提升本身不能证明奖励是忠实的进度估计器。应同时报告标量校准（回归误差、相关性）、时间一致性（排序准确率、秩相关）和下游效用（在线学习、离线重标注）三类指标，否则可能被单一指标误导。

5. **最容易踩坑的地方**：视觉条件目标对视角变化和具身差异极其敏感，跨具身迁移时务必重新校准；程序化方法的奖励可能对实现精确但与预期行为不一致（当符号变量无法捕获任务重要方面时）；数据增强中的合成失败必须保持物理合理性，否则模型会利用可识别的伪影。

## Overview
Robotic learning takes place in dynamic environments with large behavior spaces. A terminal success signal only tells the robot whether the task is completed. It does not explain whether the current behavior is making progress, remaining unchanged, or undoing earlier progress. For this reason, recent studies have increasingly explored progress rewards that provide feedback during task execution. However, the current literature lacks a shared framework. Existing methods use different observations, goal specifications, output signals, supervision sources, and evaluation protocols. This makes it difficult to compare them and understand what their results actually validate. In this survey, we provide a unified view of progress reward modeling for robotic learning. We organize the field in three connected steps. We first study the interface of a progress model. This defines the problem from the outside by asking what information the model receives and what form of progress signal it produces. We then move inside the model and study the methods used to construct this signal. This reveals the different assumptions and mechanisms behind progress estimation and reward generation. Finally, we examine the data and benchmarks that support these methods. This shows how progress supervision is obtained and what different evaluations actually measure. Together, these three perspectives connect what a progress model is, how it is built, and how its quality is validated. We further summarize the main limitations of current approaches and discuss future research directions.

### 인터페이스 관점(제2절): 모델을 작업 조건 블랙박스로
- **작업 상태 표현**:
  - 단일 관측 입력: 낮은 지연 시간, 온라인 사용 용이하지만, 시각적으로 유사한 상태가 실행 이력에 따라 의미가 다를 수 있음.
  - 시간 컨텍스트 입력: 궤적 접두사 또는 짧은 창(온라인) 또는 전체 궤적(오프라인), 더 긴 컨텍스트는 더 강한 시간적 증거를 제공하지만 온라인 사용성을 약화시킴.
  - 비교식 입력: 두 참조 상태(행동 전후, 초기와 현재 등)를 비교하여 진행도를 추정하지만, 국소 비교는 장기 의존성을 놓칠 수 있고, 쌍별 판단 체인은 오류를 누적할 수 있음.
  - 상태 접근 인터페이스: 환경 코드, 시뮬레이터 API 또는 고유 감각 특징을 사용하며, 시뮬레이션이나 계측된 환경에 가장 적합하고, 실제 세계에서는 일반적으로 비현실적임.
- **작업 목표 명세**:
  - 언어 조건: 인코딩 용이, 기존 VLM과 호환되지만, 언어는 물리적 세부 사항을 불충분하게 지정할 수 있으며, 특히 작업이 길어지고 더 조합적일 때.
  - 시각 조건: 목표 이미지 또는 데모 궤적은 표현하기 어려운 물리적 세부 사항을 포착하지만, 수동 큐레이션이 필요하고 시점, 구현 차이에 민감함.
  - 구조화/절차적 목표: 술어, 제약 조건 또는 생성된 목표 함수를 통해 표현되며, 정밀한 밀집 보상을 지원하지만 명시적 상태 변수 접근에 의존하고, 개방형 세계에서는 사용 불가능함.
- **모델 출력 형태**:
  - 상태 수준 스칼라 점수: 가장 일반적이지만, 의미는 보정 방식에 따라 달라짐.
  - 진행도 증분: 전환이 상태를 개선하는지 예측(예: VLAC, ARM), RL과 자연스럽게 정렬되지만 국소 개선을 설명함.
  - 순위: 상대적이고 간접적이며, 스칼라 보상으로 변환해야 함.
  - 절차적 출력: 실행 가능한 보상 함수를 출력하며, 유연하지만 신뢰성은 코드 품질에 달려 있음.

### 방법 관점(제3절): 네 가지 구축 패러다임
- **동결 기반 모델을 의미론적 보상 평가자로**: 훈련 없이 사전 훈련된 모델에서 직접 신호 추출(예: CLIP식 이미지-텍스트 유사도, TOPReward의 'true' 토큰 확률). 제로샷 사용 가능하지만, 점수는 의미론적 사전 지식이지 보정된 보상이 아니므로 정규화, 임계값 설정 또는 차분이 필요함.
- **시간 및 상대적 감독에서 학습**: 일반적인 감독 원천은 성공 데모의 시간적 순서(후기 상태가 완료에 더 가까움) 또는 선호도/순위 정보(예: RL-VLM-F, Rank2Reward). 상대적 감독은 수집이 쉽지만, 스칼라 보상을 직접 제공하지 않음.
- **명령 튜닝을 통한 진행도 예측**: 진행도 추정을 명시적 명령 따르기 작업으로 표현하고, 작업 특정 프롬프트로 진행도 판단을 정의한 후 VLM을 미세 조정(예: RoboReward, VLAC, ProgressLM). 핵심 아이디어는 진행도 예측이 모델의 명령 따르기 능력의 일부가 되는 것이지, 암시적 부산물이 아니라는 것.
- **절차적 보상 구축**: 진행도 추정을 코드, 술어 또는 구조화된 보상 논리로 변환(예: Text2Reward, Eureka). 작업이 명시적 하위 목표로 분해 가능할 때 효과적이지만, 도전 과제를 작업 분해와 특징 설계로 전가함.

### 데이터 및 벤치마크 관점(제4절)
- 인간 참여 정도에 따라 데이터 구축을 조직: 인간 원격 조작, 인간 인더루프 주석, 완전 자동 시간 구조 감독, 기반 모델 자동 주석, 데이터 증강.
- 세 가지 평가 목표에 따라 벤치마크 그룹화: 진행도 충실도(스칼라 보정, 시간 일관성), 견고성 및 일반화(시점, 구현, 비단조 실행), 하류 효용(온라인 정책 학습, 오프라인 재주석, 검색 필터링, 계획).

## 핵심 혁신

1. **통합 관점 제시**: 처음으로 파편화된 진행도 보상 문헌을 인터페이스, 방법, 데이터의 세 가지 수준으로 체계적으로 조직하고 네 가지 구축 패러다임을 식별. 단순한 분류학이 아니라, 서로 다른 방법 간의 깊은 연결을 드러냄—예를 들어 명령 튜닝 패러다임은 진행도 예측을 시각 표현 학습의 부산물에서 명시적 감독의 명령 따르기 능력으로 전환하며, 이 통찰은 연구자의 문제 본질 이해를 바꿈.

2. **평가 차원의 체계화**: 벤치마크 테스트를 단일 성공률 또는 오류 지표에서 세 가지 수준으로 확장—진행도 충실도(스칼라 보정, 시간 일관성), 견고성 및 일반화(시점, 구현, 비단조 실행), 하류 효용(온라인 학습, 오프라인 재주석, 검색, 계획). 특히 '정책 성능 향상 자체가 보상이 충실한 진행도 추정기임을 증명하지 못한다'는 점을 강조하며, 이 구분은 실험 설계에 직접적인 지침을 제공.

3. **미래 방향에 대한 명확한 진단**: 현재 모델이 세밀한 민감도, 적응형 시간 모델링, 효율적인 온라인 추론, 장기 기억의 네 가지 측면에서 구체적 결함을 지적하고 실행 가능한 개선 제안(예: 스트리밍 비주얼 인코더, 계층적 보상 쿼리, 컴팩트 작업 메모리)을 제공. 이러한 진단은 기존 방법의 한계에 대한 세밀한 분석에 기반하며, 막연한 논의가 아님.

## 실험 및 결과

이 리뷰 논문의 본문에는 구체적인 실험 설정, 기준선 또는 정량적 결과 수치가 포함되어 있지 않습니다. 언급된 벤치마크 유형은 다음과 같습니다:

| 평가 차원 | 핵심 지표 유형 |
|---------|------------|
| 스칼라 보정 | 회귀 오류, 상관관계 |
| 시간 일관성 | 순위 정확도, 순위 상관, 단조성 지표 |
| 상대적 진행도 | 쌍별 비교 판단 |
| 작업 접지 | 반사실적 명령, 불일치 비디오-언어 쌍 |
| 응답 가능성/불확실성 | 선택적 예측, 기권, 신뢰도 보정 |

문서에는 구체적인 숫자, 표 또는 정량적 결과가 제공되지 않습니다. 언급된 모든 벤치마크 범주는 정성적 설명이며, 정량화된 결과가 없습니다. 논문은 성공률, 오류 값, 매개변수 수 또는 훈련 구성에 대해 명시적으로 보고하지 않습니다.

## 경계 및 한계

저자가 명시적으로 인정한 한계는 다음과 같습니다: 단일 관측 입력은 시각적으로 유사하지만 이력이 다른 상태를 구분할 수 없음; 시간 컨텍스트 입력은 온라인 사용성과 시간적 증거 사이에서 절충; 비교식 인터페이스는 장기 의존성을 놓칠 수 있고 쌍별 판단 체인이 오류를 누적; 상태 접근 인터페이스는 실제 세계에서 일반적으로 사용 불가능. 언어 목표는 물리적 세부 사항을 불충분하게 지정하고, 시각 목표는 시점과 구현 차이에 민감하며, 구조화된 목표는 명시적 상태 변수에 의존. 동결 기반 모델의 점수는 의미론적 사전 지식이지 보정된 보상이 아니며, 선호 출력은 진행도를 상대적으로만 정의하고, 절차적 방법의 신뢰성은 코드 품질에 달려 있음. 인간 주도 데이터 구축은 비용이 많이 들고 주관적이며, 완전 자동 시간 구조 감독은 진행도가 시간과 충분히 상관관계가 있다고 가정하고, 기반 모델 자동 주석은 모델 편향을 계승함.

또한 저자는 현재 모델이 일반적으로 세밀한 민감도 부족(희소 샘플링 프레임이 정밀 정렬과 같은 작은 변화를 놓칠 수 있음), 고정 비율 가정(실제 진행도는 종종 불균일하며, 갑작스러운 증가와 긴 평탄기가 존재), 추론 지연(대형 VLM은 모든 제어 단계에서 사용하기 어려움), 장기 기억 부족(시각적으로 유사한 관측이 다른 단계에 해당할 수 있음)을 지적합니다. 논문은 계산 리소스 요구 사항, 서로 다른 방법군 간의 정량적 성능 비교, 실제 물리적 로봇에서의 배포 경험에 대해 명시적으로 논의하지 않습니다.

## 엔지니어링 시사점

진행도 보상 방법을 재현하거나 선택하려는 엔지니어에게 다음 사항을 우선적으로 확인하는 것이 좋습니다:

1. **작업 특성을 먼저 명확히 한 후 방법군 선택**: 작업이 명시적 하위 목표로 분해 가능하고 상태 변수에 접근할 수 있다면 절차적 구축(예: Text2Reward)이 가장 신뢰할 수 있음; 언어 명령과 시각 입력만 있다면 명령 튜닝 패러다임(예: VLAC)이 더 적합; 제로샷 빠른 배포를 원한다면 동결 기반 모델을 출발점으로 사용할 수 있지만 반드시 정규화와 임계값 설정을 병행해야 함.

2. **'평활하면 올바르다'는 함정 경계**: 많은 방법이 시간적 순서를 감독으로 사용하여 진행도가 시간에 따라 평활하게 증가하도록 장려하지만, 실제 작업은 종종 갑작스러운 점프와 평탄기가 있음. 평가 시 반드시 비단조 실행 테스트(실패, 롤백, 재시도)를 포함해야 하며, 그렇지 않으면 모델이 '시간이 길어질수록 진행도가 높다'는 지름길만 학습할 수 있음.

3. **온라인 추론 비용은 숨은 병목**: 대형 VLM은 여러 프레임을 처리하고 추론한 후에야 보상을 생성할 수 있어, 오프라인 평가에는 허용 가능하지만 모든 제어 단계에서 사용하기 어려움. 계층적 전략을 권장—경량 모델은 고빈도로 호출하여 국소 업데이트를 처리하고, 대형 모델은 중요한 작업 전환 또는 불확실한 상태에서만 호출.

4. **평가 지표는 반드시 계층화**: 정책 성능 향상 자체는 보상이 충실한 진행도 추정기임을 증명하지 못함. 스칼라 보정(회귀 오류, 상관관계), 시간 일관성(순위 정확도, 순위 상관), 하류 효용(온라인 학습, 오프라인 재주석)의 세 가지 유형 지표를 동시에 보고해야 하며, 그렇지 않으면 단일 지표에 오도될 수 있음.

5. **가장 함정에 빠지기 쉬운 부분**: 시각 조건 목표는 시점 변화와 구현 차이에 극도로 민감하며, 구현 간 전이 시 반드시 재보정 필요; 절차적 방법의 보상은 구현이 정확하더라도 기대 행동과 일치하지 않을 수 있음(기호 변수가 작업의 중요한 측면을 포착하지 못할 때); 데이터 증강의 합성 실패는 물리적 합리성을 유지해야 하며, 그렇지 않으면 모델이 식별 가능한 인공물을 이용하게 됨.
