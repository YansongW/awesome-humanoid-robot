## 概述

IHMC 机器人实验室提出了一套面向双足人形机器人快速门穿越的行为架构，核心是基于行为树（BT）的在线行为编写与执行框架。该工作通过支持运行时行为修改、任务相对坐标与螺旋轨迹原语，在 Nadia 人形机器人上实现了 20-30 秒的多种门穿越行为，并配套了基于 YOLO 与平面提取的门机构检测系统。

## 它改变了什么

这项工作的真正改变在于将人形机器人腿臂协同操作（loco-manipulation）的行为编写从“离线规划-部署-执行”的慢循环，推进到了“在线编辑-即时执行-快速迭代”的交互式范式。此前，即便是 IHMC 在 DARPA 机器人挑战赛中获得最佳门穿越奖的方法，其速度也远慢于本工作实现的 20-30 秒水平。作者明确指出，机器人要达到与人类相当的速度和性能，才能在城市作业中跟随人类团队，而现有系统仍远未达到。该架构的提出，正是为了压缩行为开发周期，使操作员能在真实硬件上以分钟级速度调整动作序列，从而支撑对动态环境（如门、碎片）的快速响应。

另一个关键改变在于对“行为”本身的重构。作者没有采用标准行为树的预定义返回类型（success/failure/running），而是实现了一个通用节点接口，支持 JSON 序列化、机器人端执行与操作员端 UI 渲染。这种设计将行为从代码逻辑中解放出来，变成了可实时编辑、保存、加载的数据资产。同时，通过“execute after”字段实现的分层并发执行，使得动作可以按顺序开始但提前完成，这为缩短门穿越总时间提供了机制基础。此外，任务相对坐标系的引入，使得动作定义不再绑定于机器人基座或世界坐标，而是相对于门把手、门板等环境物体，这显著提升了行为在不同场景下的可迁移性。

## 方法拆解

### 行为树架构与在线编辑
- 行为以分层 JSON 文件存储，根节点创建或加载后，操作员通过界面编辑树，树及所有节点的属性和执行数据自动持续与机器人的工作副本同步。
- 与标准 BT 不同，本实现在每个 tick 更新所有节点，且不使用预定义返回类型，而是实现通用接口用于存储子节点、JSON 保存/加载、机器人端执行和操作员端 UI 渲染。
- 支持两种执行模式：手动逐步模式（点击按钮执行下一个动作，可选是否允许并发）和自主执行模式（机器人按行为逻辑继续执行）。

### 动作原语与组合
- 动作原语包括脚步、手臂、手、胸部、骨盆轨迹，可组装成 Affordance Templates（ATs）。
- 每个原语动作实现入口条件（on-entry）和出口条件（on-exit），入口条件用于门控动作执行，出口条件确定成功或失败，参考级联 Lyapunov 漏斗概念。
- 分层并发执行通过每个动作原语节点上的“execute after”字段实现，该字段指向一个先前动作作为其完成依赖，使动作按顺序开始但可能更早执行（Algorithm 1）。

### 关键原语设计
- **任务相对坐标系**：动作设置在任务相对坐标系中，操作员可通过 3D 姿态 gizmo 交互式编辑任务相对变换。
- **脚步规划**：支持预指定或在线规划（IHMC footstep planner），以及程序化“turn-walk-turn”模式；在线规划时将目标姿态垂直吸附到地面，使用两个帧相对点（point to face 和 point to stand at）。
- **螺旋轨迹（screw primitive）**：受文献[28]启发，参数化螺旋轨迹由 3D 轴、旋转角度和沿轴平移量定义，轨迹从执行前手部姿态在线生成，具有抓握不变性（grasp-invariant）。
- **手臂轨迹**：支持预设关节角或在线 IK 解算的帧相对手部姿态，可调轨迹时间、权重和增益。

### 全身控制与感知
- 全身控制使用基于动量的框架，围绕二次规划（QP）求解器，管理脚-地接触和手部力限制抓取的 QP 约束。
- 动态行走使用 IHMC 开发的行走行为，包含站立、转移、摆动状态的状态机，使用瞬时捕获点（ICP）建模平衡动力学，使用质心力矩枢轴（CMP）。
- 状态估计结合运动学脚-地接触本体感觉（骨盆位置）和骨盆安装 IMU（骨盆方向），使用基于踝关节扭矩传感器的虚拟脚开关（经毛刺滤波和延迟补偿）。
- 门机构检测流程（8 步）：ZED 2i 相机朝前下方倾斜 43°；彩色数据经 YOLO 获得机构分割；平面区域提取器获得门板平面；机构上深度点的质心用于位置，门板平面的法线用于方向。

## 关键创新

1. **在线行为编写与执行闭环**：这是最核心的创新。行为树、节点属性与执行数据在操作员 UI 与机器人工作副本间持续同步，允许操作员在真实机器人上即时创建、修改和执行行为，无需重新部署。这直接解决了行为开发周期长的问题，使一年内创建超过二十种可工作的腿臂协同操作行为成为可能。

2. **螺旋轨迹原语的抓握不变性**：针对旋钮或杠杆手柄这类旋转机构，螺旋轨迹从执行前手部姿态在线生成，由 3D 轴、旋转角度和沿轴平移量定义。其抓握不变性意味着即使手部抓握点有偏差，轨迹依然有效，这显著降低了对精确抓握的依赖，提高了行为在真实硬件上的鲁棒性。

3. **任务相对坐标与感知系统的结合**：将动作定义在任务相对坐标系中，并配套了基于 YOLO 与平面提取的门机构检测系统。检测系统输出机构位姿（位置用深度点质心，方向用门板平面法线），直接提供给行为运行时用于行为创作和执行。这种“感知-行为”的紧耦合设计，使得行为可以针对环境物体而非固定坐标进行定义，提升了行为的泛化能力。

## 实验与结果

实验在 IHMC 与 Boardwalk Robotics 开发的 Nadia 人形机器人上进行，该机器人具有 6 自由度腿、3 自由度脊柱、7 自由度手臂、1 自由度夹爪。实验任务覆盖六种门穿越变体，改变推/拉、左/右铰链，以及旋钮、推杆和杠杆手柄三种开启机构。

## 边界与局限

作者明确承认，机器人仍远未达到人类速度和性能，这在城市作业中跟随人类团队是必要的。主要减速因素包括不必要的脚步、暂停和最大行走速度。轨迹主要在位置空间定义，作者认为转向基于力和冲击的动作定义将简化动作定义、增加扰动鲁棒性。系统严重依赖人类作者和操作员的智慧，缓解方法包括实现更高级的规划器（如站位和抓握生成、无碰撞运动规划）。

感知系统无法检测门框，必须假设门在首次看到时是关闭的；门框检测算法将支持任意初始条件下的门穿越，但对于初始半开的门还需要额外的规划启发式。状态估计的位置估计容易在三个方面漂移：脚接触检测不准确、脚滑动、双脚未同时着地。实验环境受限：机器人被束缚在液压泵上且无法承受摔倒，因此建造了没有顶部框架的门模型；实验室门使用真实住宅和商业门硬件，安装了弹簧闭门器并用于部分实验。论文未提及在非实验室环境（室外）的验证情况，也未对门穿越行为的具体失败模式进行定量分析。

## 工程启示

对于希望复现或借鉴此架构的团队，以下几点值得优先核对：

1. **行为树运行时与 UI 的同步机制**：这是在线编辑的基础。需确认节点属性与执行数据如何在 UI 与机器人工作副本间同步，以及“每个 tick 更新所有节点”的实现细节，这直接决定了行为修改的实时性。

2. **螺旋轨迹原语的参数化**：调参主要涉及将螺旋轴与手柄和门板的旋转轴对齐。复现时需重点验证 3D 轴、旋转角度和沿轴平移量的定义方式，以及轨迹从执行前手部姿态在线生成的逻辑，这是抓握不变性的关键。

3. **感知系统的稳定性阈值**：检测系统要求 YOLO 检测到机构且有效的平面区域关联在 1 秒窗口内至少占传感器帧的 60%。复现时需注意 YOLO 训练数据的构成（1000 张真实 + 1000 张合成，15% 不含门/把手），以及平面区域提取器与深度点质心计算的配合。

4. **最容易踩坑的地方**：感知到的物体帧可能存在显著的姿态误差，导致目标姿态脚步无法与地面良好对齐，影响稳健行走。作者为此采用垂直吸附到地面的方法，复现时需注意这一补偿机制。另外，门把手抓握调参是最敏感的部分之一，操作员通常使用手动调参和触发抓握动作的迭代过程，直到结果可靠；主要参数包括夹持力、轨迹持续时间和手部方向。

## 개요
이 연구는 인간형 로봇이 도시 전투와 같은 시나리오에서 팀원으로 활동할 때 문을 통과하는 핵심 능력의 부재에 초점을 맞춘다. 저자들은 GPU 가속 인식 시스템(신경망과 고전 컴퓨터 비전의 결합)과 트리 기반 상호작용 행동 조정 시스템을 통합한 행동 아키텍처를 제안하며, 기존의 전신 운동 및 보행 컨트롤러를 활용하여 이동 중 조작을 지원한다. 이 시스템은 보지 못한 문 유형에 대한 행동을 빠르게 작성할 수 있게 하며, 계층적 동시 실행을 통해 속도를 향상시킨다. 최종적으로 Nadia 인간형 로봇에서 빠른 문 통과를 위한 실제 로봇 시연을 구현했으며, 운영자-로봇 상호 의존성 분석 차트를 제공하여 인간 인지와 인공지능의 결합을 탐구한다.

### 행동 아키텍처 설계
- **인식 시스템**: GPU 가속 신경망과 고전 컴퓨터 비전을 결합하여 실외 환경에서 문 메커니즘(손잡이, 밀기/당기기 표시 등)을 감지한다.
- **행동 조정 시스템**: 트리 기반 구조로 행동을 모델링하며, 논리적 반응성과 동작 시퀀스를 지원하고 계층적 동시 실행을 통해 속도를 향상시킨다.
- **전신 컨트롤러**: 기존의 전신 운동 및 보행 컨트롤러를 기반으로 이동 중 조작(loco-manipulation)을 지원한다.
- **빠른 행동 작성**: 보지 못한 문 유형에 대한 행동을 빠르게 작성할 수 있으며, 작성된 행동의 재사용성을 구현한다.
