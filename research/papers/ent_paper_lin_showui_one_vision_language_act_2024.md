## 概述

ShowUI 是一个基于 Qwen2-VL-2B 的轻量级视觉-语言-动作（VLA）模型，专为 GUI 视觉智能体设计。其核心贡献在于提出 UI 引导的视觉 token 选择以降低计算成本、交错视觉-语言-动作流式框架以统一 GUI 任务，以及构建小规模高质量指令跟随数据集。该模型在零样本截图 grounding 上达到 75.1% 准确率，并在网页、移动端和在线环境导航中展现竞争力。

## 它改变了什么

GUI 智能体领域长期依赖 HTML、无障碍树或 OCR 等 oracle 数据源，这与真实用户仅凭截图操作的情境严重脱节。ShowUI 真正改变了这一范式，它证明了纯视觉输入足以驱动可靠的 GUI 理解与操作，从而降低了模型对结构化数据源的依赖，拓宽了应用边界。此外，高分辨率 UI 截图在视觉语言模型中的计算开销是实际部署的主要瓶颈，ShowUI 通过 UI 引导的 token 选择，在不牺牲 grounding 精度的前提下显著削减了计算量，这为资源受限场景下的 GUI 智能体落地提供了可行路径。

该工作还改变了 GUI 任务建模的方式。以往视觉、语言和动作常被分开处理或简单拼接，而 ShowUI 的交错流式框架将三者统一在一个序列中，使模型能更自然地处理多轮交互中的历史信息。同时，作者对数据质量的强调——即小规模、高指令质量的数据集优于大规模、噪声多的数据——也挑战了“数据越多越好”的惯性思维，为后续数据策展提供了新准则。

## 方法拆解

### UI-Guided Visual Token Selection
- 在 RGB 空间中构建 UI 连通图，将每个图像 patch 视为节点，通过查找连通分量捕获冗余区域（如大面积空白）。
- 该图引导自注意力块跳过部分冗余 token，无需额外可学习参数，直接降低计算成本。
- 训练时掩码比率为 0.75，跨层插入在第 14 层；推理时对每个分量均匀采样 token，确保模型能看到所有分量，以保持最优精度。

### Interleaved Vision-Language-Action Streaming
- 将视觉 token、语言指令和动作输出交错排列在单一序列中，统一建模跨模态交互。
- 流式设置中历史数量设为 2，有效管理多轮对话中的上下文。

### 数据策展与增强
- 使用 PyAutoGUI 解析器从 22 个代表性场景采集网页截图，过滤静态文本元素，保留视觉信息丰富的元素。
- 利用 GPT-4o 辅助增强 OmniAct 桌面注释，生成三类描述：外观（Appearance）、空间关系（Spatial-relationship）、情境（Situational），每类不超过 15 个词。
- 数据重采样：各数据集权重设为 (Web:Mobile:Desktop:GUIAct-Web:GUIAct-Mobile) = (1:1:1:1:1)，实现平衡采样。

### 动作 README 模板
- 动作格式化为字典：{'action':'action_type', 'value':'element', 'position':[x,y]}，position 为相对坐标，缩放到 0-1 范围。
- 动作空间按 action_type 模板化，包含动作描述，便于模型生成结构化输出。

### 训练配置
- 使用 LoRA 微调，rank 为 64，alpha 为 128，应用于语言模型和视觉编码器，可学习参数占总参数的 4%。
- 使用 DeepSpeed Zero-2 和 SDPA 注意力机制，学习率设为 1e-4，最大视觉 patch 数为 1280 1280。

## 关键创新

1. **UI 引导的视觉 token 选择**：不同于通用的 token 剪枝或合并方法，该方法利用 GUI 的结构化布局特性（如冗余空白区域）构建连通图，在降低计算成本的同时保留了元素定位所需的细粒度位置信息。这是首个专门针对 GUI 场景设计的 token 选择策略，其无需额外参数的设计也保证了训练效率。

2. **交错视觉-语言-动作流式框架**：将视觉、语言和动作统一在一个交错序列中，而非简单拼接或分步处理。这种设计使模型能更自然地处理多轮交互中的历史信息，为 GUI 智能体的端到端训练提供了新的序列建模范式。

3. **小规模高质量数据策展**：通过过滤静态文本元素和 GPT-4o 辅助增强，仅用 22K 网页截图和 8K 桌面注释即可达到甚至超越大规模数据集（如 SeeClick 的 270K 截图）的性能。这证明了数据质量而非数量是提升 GUI 智能体能力的关键，为数据稀缺场景提供了可复用的方法论。

## 实验与结果

实验主要围绕 Screenspot 基准上的 grounding 数据消融展开，并辅以 Mind2Web、AITW 和 MiniWob 的导航性能评估。

| 数据组成 | 元素数 | 截图数 | Desktop Ele.Acc | Desktop Act.Acc | Web Ele.Acc | Web Act.Acc | Mobile Ele.Acc | Mobile Act.Acc | 平均 |
|---------|--------|--------|-----------------|-----------------|-------------|-------------|---------------|---------------|------|
| Web (vis) | 22K | 576K | 83.6 | 60.3 | 75.3 | 60.3 | 72.4 | 62.1 | 69.0 |
| OmniAct | 100 | 2K | 85.7 | 59.8 | 78.4 | 52.1 | 79.6 | 52.9 | 68.7 |
| OmniAct (diverse) | 100 | 8K | 88.3 | 66.8 | 76.3 | 57.9 | 79.1 | 57.3 | 70.9 |
| Joint-Training | 119K | 1.6M | 90.8 | 66.4 | 75.3 | 51.4 | 80.0 | 63.1 | 71.2 |
| Balanced Sampling | 119K | 1.6M | 91.6 | 69.0 | 81.8 | 59.0 | 83.0 | 65.5 | 74.9 |

关键发现：
- 数据质量优于数量：OmniAct 仅 2K 元素即可与网页数据相当，经 GPT-4o 增强后（8K）显著提升泛化能力。
- 过滤静态文本可减少元素数量而不影响性能，表明静态文本信息量低。
- 平衡采样带来 3.7% 准确率提升（由表内 71.2 → 74.9 计算），并在各单独设置中保持性能。

在导航任务中，ShowUI 在 Mind2Web、AITW 和 MiniWob 上均展现出竞争力，但作者指出在线环境（MiniWob）中零样本与微调性能差距显著，表明离线指令微调不足以应对交互式场景。

## 边界与局限

- 模型仅支持单步 grounding 和导航，缺乏多步规划或推理能力。
- 在未见领域（如 Mind2Web 的跨网站、跨域）上性能欠佳，需更多样化的视觉训练数据。
- 在线环境（MiniWob）中零样本与微调性能差距大，离线训练不足以覆盖交互式设置。
- 不支持截图以外的多模态输入（如文本、音频），限制了更丰富交互场景的应用。
- token 选择方法在复杂 UI 布局中可能丢弃关键 token，需进一步研究自适应选择策略。
- 论文未明确模型在超长序列或极端高分辨率下的行为，也未报告推理延迟的具体数值。

## 工程启示

复现或应用 ShowUI 时，首先应核对数据策展流程：过滤静态文本元素和 GPT-4o 增强是性能提升的关键，直接使用原始注释可能无法复现报告结果。其次，平衡采样策略（各数据集权重 1:1:1:1:1）对最终精度影响显著，不可省略。训练时注意 LoRA 配置（rank 64, alpha 128）和掩码比率 0.75，推理时需使用完整 token 序列以保证精度。最易踩坑之处在于 token 选择方法在复杂布局中可能丢失关键信息，若下游任务涉及密集元素交互，建议评估自适应选择策略或降低掩码比率。此外，模型对在线环境的适应性有限，若目标场景需要多步交互，需考虑结合强化学习或在线微调。

## 개요
ShowUI는 기존 GUI 에이전트가 HTML과 같은 텍스트 메타정보에 의존하여 시각적 인식 능력이 부족한 문제를 해결하는 것을 목표로 합니다. 이 모델은 UI 기반 시각 토큰 선택을 통해 스크린샷을 UI 연결 그래프로 구축하고, 적응적으로 중복 관계를 식별하며 자기 주의(self-attention)에서 토큰 선택을 최적화하여 계산 비용을 줄입니다. 동시에, 인터리브된 시각-언어-행동 흐름은 GUI 작업의 다양한 요구를 통합하여 내비게이션 중 시각-행동 기록 또는 다중 턴 쿼리-행동 시퀀스 쌍을 효과적으로 관리합니다. 또한, 정교한 데이터 정리 및 재샘플링 전략을 통해 모델은 256K 데이터만으로 훈련하여 제로샷 스크린샷 위치 파악에서 75.1% 정확도를 달성하고 1.4배 속도 향상을 실현합니다.

## 핵심 내용
### 방법
- **UI 기반 시각 토큰 선택**: 스크린샷을 UI 연결 그래프로 모델링하고, 그래프 구조를 통해 중복 시각 토큰을 적응적으로 식별하며, 자기 주의 블록에서 선택 기준으로 사용하여 33%의 중복 토큰을 줄입니다.
- **인터리브된 시각-언어-행동 흐름**: GUI 작업의 시각, 언어, 행동 요구를 유연하게 통합하여 내비게이션 중 시각-행동 기록 관리 또는 각 스크린샷의 다중 턴 쿼리-행동 시퀀스 쌍을 지원하여 훈련 효율성을 향상시킵니다.
- **소규모 고품질 명령 데이터셋**: 데이터 정리 및 재샘플링 전략을 통해 데이터 유형 불균형 문제를 해결하고 256K 데이터만으로 훈련합니다.

### 실험 설정 및 결과
- **모델 규모**: 경량 2B 파라미터 모델.
- **제로샷 스크린샷 위치 파악**: 보지 못한 스크린샷 작업에서 75.1% 정확도 달성.
- **효율성 향상**: UI 기반 토큰 선택이 훈련 중 33%의 중복 시각 토큰을 줄이고 1.4배 속도 향상을 실현.
- **내비게이션 실험**: 웹 환경 Mind2Web, 모바일 환경 AITW 및 온라인 환경 MiniWob에서 모델의 유효성을 검증.

ShowUI는 시각적 인식과 효율적인 토큰 선택을 통해 GUI 시각 에이전트의 성능을 크게 향상시키며, 여러 벤치마크에서 잠재력을 입증합니다. 모델 코드는 오픈소스로 공개되었습니다.
