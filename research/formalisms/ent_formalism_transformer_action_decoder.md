## 概述

Transformer 动作解码器形式化（Transformer Action Decoder Formalism）是一种使用 Transformer 架构和学习的动作 token 词表，从视觉-语言上下文解码机器人动作的形式化生成框架。它将连续动作空间离散化为 token 序列，通过自回归方式逐 token 生成动作，从而复用语言模型的训练与推理生态。它真正改变的不是动作预测的精度本身，而是让机器人动作生成与大规模预训练语言模型共享同一套形式化接口。

## 核心内容

### 是什么：准确定义

Transformer 动作解码器形式化属于**形式化方法**类型，所属领域包括 AI 模型与算法、基础学科，价值链层级为智能层与 foundations。其核心思想可拆解为三个组件：

1. **视觉-语言编码器**：将观测图像与语言指令编码为上下文向量，通常采用视觉编码器（如 DINOv2、SigLIP）与语言模型骨干（如 Llama 2）的融合结构；
2. **动作 token 词表**：将连续动作空间按自由度量化分箱，每个 bin 映射到词表尾部的一个 token，形成"动作词表"；
3. **自回归解码器**：基于 Transformer 解码器，按条件概率逐 token 生成动作序列，再解码回连续动作值。

该形式化框架的数学表达为：给定观测 $o_t$ 与语言指令 $\ell$，策略网络按自回归方式生成动作 token 序列 $y_1, y_2, \dots, y_D$，其联合概率分解为：

$$
p_\theta(a_t \mid o_t, \ell) = \prod_{i=1}^{D} p_\theta(y_i \mid o_t, \ell, y_{<i})
$$

其中 $D$ 为动作 token 序列长度，$y_{<i}$ 表示已生成的 token 前缀，$\theta$ 为网络参数。最终动作通过解码器映射回连续空间：$\hat{a}_t = \mathrm{decode}(y_1, y_2, \dots, y_D)$。

### 为什么存在：痛点与历史定位

在 VLA（视觉-语言-动作）模型出现之前，机器人策略学习面临一个根本性断裂：视觉-语言模型（VLM）的输入输出都是离散 token，而机器人动作是连续向量。早期方案给 VLM 外挂回归头直接输出连续动作，但回归头丢掉了语言模型的生成式训练管线——无法复用"下一个 token 预测"这一经过互联网规模数据验证的预训练目标。

Transformer 动作解码器形式化的历史定位在于：它把动作生成转化为与文本生成同构的序列建模问题，从而让机器人策略能够直接继承 LLM 的三大资产——预训练权重、自回归推理生态、以及参数高效微调方法（如 LoRA）。这一形式化由 RT 系列模型确立，被 OpenVLA 等开源 VLA 继承并标准化。

### 原理拆解

**① 动作量化：连续空间到离散 token 的映射**

动作量化的标准流程是：对每个自由度的连续动作值按均匀分箱离散化（RT-2 使用 256 个 bin），将 bin 编号映射到语言模型词表中（常用词表尾部最少使用的 token，避免与文本冲突）。量化误差的上界由 bin 宽度决定，因此增加 bin 数量可提升精度，但会扩大词表规模、增加优化难度。

**② 自回归生成：条件概率的链式分解**

Transformer 解码器按因果注意力掩码逐位置生成 token。每一步的条件概率 $p_\theta(y_i \mid o_t, \ell, y_{<i})$ 由解码器最后一层的 softmax 输出给出。推理时采用贪心解码或束搜索，训练时采用教师强制（teacher forcing）最大化似然。

**③ 视觉-语言上下文融合**

视觉编码器（如 DINOv2 与 SigLIP 双编码器）提取的图像特征与语言指令的文本嵌入拼接后，作为解码器的交叉注意力输入。这一设计使动作生成同时受视觉观测与语义指令约束，实现"看得到什么、被要求做什么、就生成什么动作"的闭环。

### 横向对比

**与连续动作回归头对比**：回归头直接输出连续向量，训练目标为均方误差，无法复用 LLM 的生成式预训练；动作 token 预测则完全复用 LLM 训练管线，但引入量化误差与序列长度开销。

**与扩散/流匹配动作头对比**：扩散策略（Diffusion Policy）在连续空间直接生成动作轨迹，避免了量化误差，但需要额外的扩散模型架构与采样过程，无法与 LLM 共享骨干。OpenVLA 在 29 个任务上以 7B 参数超越 RT-2-X（55B）16.5% 的绝对任务成功率，并优于 Diffusion Policy 20.4%（来源：arXiv:2406.09246）。

**与 FAST 频域压缩对比**：FAST 将动作序列变换到频域后仅预测低频分量，显著缩短 token 序列长度；动作 token 预测则直接对时域动作逐维量化，序列长度与动作维度成正比。

### 谁在用·应用案例

**OpenVLA（2024）**：斯坦福等机构发布的开源 VLA，7B 参数，在 Open X-Embodiment 约 97 万条真实机器人片段上预训练，支持 LoRA 微调与量化部署（来源：arXiv:2406.09246）。其动作解码采用离散 token 自回归生成，确立了开源 VLA 的事实标准。

**RT-2（2023）**：Google 提出的闭源 VLA，首次将动作 token 预测形式化引入机器人策略，展示了互联网知识迁移到动作生成的可行性。RT-2-X 为跨具身扩展版本，参数量达 55B（来源：arXiv:2406.09246 对比数据）。

**WAM4D（2026）**：在因果视频-动作 Transformer 中引入空间注册令牌，训练时将预训练几何先验注入动作生成，推理时移除注册分支以保持轻量（来源：邻居卡 ent_paper_wam4d_fast_4d_world_action_mod_2026）。

### 局限与边界

1. **量化误差**：均匀分箱的离散化必然引入精度损失，对需要亚毫米级精度的精细操作（如装配、插拔）可能成为瓶颈。工程判断：可通过增加 bin 数量或采用非均匀量化缓解，但会增大词表与优化难度。

2. **序列长度与推理延迟**：动作 token 序列长度与动作维度成正比，高自由度人形机器人（如全身 30+ 自由度）的序列长度可达数百 token，自回归逐 token 生成带来显著推理延迟，难以满足高频控制需求。

3. **数据依赖**：动作 token 词表需要从机器人演示数据中学习，跨具身泛化依赖数据多样性。OpenVLA 的 970k 条数据虽覆盖多本体，但极端场景覆盖仍有限（来源：arXiv:2406.09246）。

4. **因果一致性与模态泄露**：在多模态融合（视频、动作、几何）场景中，需设计因果混合注意力防止非因果信息泄露（来源：邻居卡 ent_paper_wam4d_fast_4d_world_action_mod_2026）。

### 常见误区

1. **"动作 token 预测就是简单量化"**——错。量化只是第一步，关键在于 token 与语言模型词表的映射策略、自回归生成的目标函数设计，以及视觉-语言上下文的融合方式。这些设计共同决定了策略的泛化能力。

2. **"Transformer 动作解码器只适用于 VLA"**——错。该形式化同样适用于纯动作生成任务（如人形机器人全身运动生成），ScaleMoGen 将其扩展为逐尺度预测，从粗到细生成运动 token 图（来源：邻居卡 ent_paper_scalemogen_autoregressive_next_2026）。

3. **"参数量越大越好"**——错。OpenVLA 以 7B 参数超越 55B 的 RT-2-X 16.5%，说明数据质量与架构设计比单纯扩大参数更关键（来源：arXiv:2406.09246）。

4. **"自回归生成必然慢"**——需区分场景。对低频决策（如任务规划、轨迹生成）自回归延迟可接受；对高频反馈控制（如 1kHz 力矩控制）则需蒸馏为前馈网络或采用并行解码。

## Overview

The Transformer Action Decoder Formalism is a formal generative framework that uses a Transformer architecture and a learned action token vocabulary to decode robot actions from visual-linguistic context. It discretizes the continuous action space into token sequences and generates actions token-by-token in an autoregressive manner, thereby reusing the training and inference ecosystem of language models. What it truly changes is not the precision of action prediction itself, but rather enabling robot action generation to share the same formal interface as large-scale pretrained language models.

## Content

### What It Is: Precise Definition

The Transformer Action Decoder Formalism belongs to the **formal method** type, with its domain including AI models and algorithms, foundational disciplines, and its value chain level being the intelligence layer and foundations. Its core idea can be decomposed into three components:

1. **Vision-Language Encoder**: Encodes observed images and language instructions into context vectors, typically using a fusion structure of vision encoders (e.g., DINOv2, SigLIP) and language model backbones (e.g., Llama 2);
2. **Action Token Vocabulary**: Quantizes the continuous action space into bins per degree of freedom, with each bin mapped to a token at the tail of the vocabulary, forming an "action vocabulary";
3. **Autoregressive Decoder**: Based on the Transformer decoder, generates action token sequences token-by-token according to conditional probabilities, then decodes them back into continuous action values.

The mathematical expression of this formal framework is: given observation $o_t$ and language instruction $\ell$, the policy network generates the action token sequence $y_1, y_2, \dots, y_D\) autoregressively, with its joint probability decomposed as:

$$
p_\theta(a_t \mid o_t, \ell) = \prod_{i=1}^{D} p_\theta(y_i \mid o_t, \ell, y_{<i})
$$

where $D$ is the length of the action token sequence, $y_{<i}$ denotes the already generated token prefix, and $\theta$ is the network parameters. The final action is mapped back to continuous space via the decoder: $\hat{a}_t = \mathrm{decode}(y_1, y_2, \dots, y_D)$.

### Why It Exists: Pain Points and Historical Positioning

Before the emergence of VLA (Vision-Language-Action) models, robot policy learning faced a fundamental disconnect: the inputs and outputs of vision-language models (VLMs) were discrete tokens, while robot actions were continuous vectors. Early approaches attached regression heads to VLMs to directly output continuous actions, but regression heads discarded the generative training pipeline of language models—making it impossible to reuse the "next token prediction" pretraining objective validated on internet-scale data.

The historical positioning of the Transformer Action Decoder Formalism lies in: it transforms action generation into a sequence modeling problem isomorphic to text generation, thereby allowing robot policies to directly inherit three major assets of LLMs—pretrained weights, the autoregressive inference ecosystem, and parameter-efficient fine-tuning methods (such as LoRA). This formalism was established by the RT series of models and was inherited and standardized by open-source VLAs such as OpenVLA.

### Principle Breakdown

**① Action Quantization: Mapping Continuous Space to Discrete Tokens**

The standard pipeline for action quantization is: discretize the continuous action values of each degree of freedom via uniform binning (RT-2 uses 256 bins), and map the bin indices to tokens in the language model vocabulary (commonly using the least-used tokens at the tail of the vocabulary to avoid conflicts with text). The upper bound of quantization error is determined by the bin width, so increasing the number of bins improves precision but expands the vocabulary size and increases optimization difficulty.

**② Autoregressive Generation: Chain Decomposition of Conditional Probabilities**

The Transformer decoder generates tokens position-by-position under a causal attention mask. The conditional probability at each step, $p_\theta(y_i \mid o_t, \ell, y_{<i})$, is given by the softmax output of the final decoder layer. Inference uses greedy decoding or beam search, while training uses teacher forcing to maximize likelihood.

**③ Vision-Language Context Fusion**

Image features extracted by vision encoders (such as the dual DINOv2 and SigLIP encoders) are concatenated with the text embeddings of language instructions and used as cross-attention inputs to the decoder. This design ensures that action generation is simultaneously constrained by visual observations and semantic instructions, achieving a closed loop of "generate actions according to what is seen and what is requested."

### Horizontal Comparison

**Comparison with continuous action regression heads**: Regression heads directly output continuous vectors with mean squared error as the training objective, unable to reuse the generative pretraining of LLMs; action token prediction fully reuses the LLM training pipeline but introduces quantization error and sequence length overhead.

**Comparison with diffusion/flow-matching action heads**: Diffusion Policy generates action trajectories directly in continuous space, avoiding quantization error, but requires additional diffusion model architecture and sampling processes, and cannot share the backbone with LLMs. OpenVLA surpasses RT-2-X (55B) by 16.5% absolute task success rate on 29 tasks with 7B parameters, and outperforms Diffusion Policy by 20.4% (source: arXiv:2406.09246).

**Comparison with FAST frequency-domain compression**: FAST transforms action sequences into the frequency domain and predicts only low-frequency components, significantly shortening token sequence length; action token prediction directly quantizes time-domain actions dimension-by-dimension, with sequence length proportional to action dimensionality.

### Who Uses It: Application Cases

**OpenVLA (2024)**: An open-source VLA released by Stanford and other institutions, with 7B parameters, pretrained on approximately 970k real robot episodes from Open X-Embodiment, supporting LoRA fine-tuning and quantized deployment (source: arXiv:2406.09246). Its action decoding uses discrete token autoregressive generation, establishing the de facto standard for open-source VLAs.

**RT-2 (2023)**: A closed-source VLA proposed by Google, which first introduced the action token prediction formalism into robot policies, demonstrating the feasibility of transferring internet knowledge to action generation. RT-2-X is the cross-embodiment extended version with 55B parameters (source: comparison data in arXiv:2406.09246).

**WAM4D (2026)**: Introduces spatial registration tokens in a causal video-action Transformer, injecting pretrained geometric priors into action generation during training, and removing the registration branch during inference to maintain lightweight operation (source: neighbor card ent_paper_wam4d_fast_4d_world_action_mod_2026).

### Limitations and Boundaries

1. **Quantization error**: Uniform binning discretization inevitably introduces precision loss, which may become a bottleneck for fine manipulation requiring sub-millimeter precision (e.g., assembly, plugging/unplugging). Engineering judgment: this can be mitigated by increasing the number of bins or using non-uniform quantization, but this increases vocabulary size and optimization difficulty.

2. **Sequence length and inference latency**: Action token sequence length is proportional to action dimensionality. For high-degree-of-freedom humanoid robots (e.g., 30+ degrees of freedom across the whole body), sequence length can reach hundreds of tokens, and token-by-token autoregressive generation introduces significant inference latency, making it difficult to meet high-frequency control requirements.

3. **Data dependency**: The action token vocabulary needs to be learned from robot demonstration data, and cross-embodiment generalization depends on data diversity. Although OpenVLA's 970k episodes cover multiple embodiments, coverage of extreme scenarios remains limited (source: arXiv:2406.09246).

4. **Causal consistency and modality leakage**: In multimodal fusion scenarios (video, action, geometry), causal mixed attention must be designed to prevent non-causal information leakage (source: neighbor card ent_paper_wam4d_fast_4d_world_action_mod_2026).

### Common Misconceptions

1. **"Action token prediction is just simple quantization"**—Wrong. Quantization is only the first step; the key lies in the mapping strategy of tokens to the language model vocabulary, the design of the objective function for autoregressive generation, and the fusion method of vision-language context. These designs collectively determine the generalization capability of the policy.

2. **"The Transformer Action Decoder is only applicable to VLAs"**—Wrong. This formalism is equally applicable to pure action generation tasks (such as whole-body motion generation for humanoid robots). ScaleMoGen extends it to scale-by-scale prediction, generating motion token maps from coarse to fine (source: neighbor card ent_paper_scalemogen_autoregressive_next_2026).

3. **"Larger parameter counts are always better"**—Wrong. OpenVLA surpasses RT-2-X (55B) by 16.5% with 7B parameters, indicating that data quality and architecture design are more critical than simply scaling up parameters (source: arXiv:2406.09246).

4. **"Autoregressive generation is inherently slow"**—Scenario-dependent. For low-frequency decision-making (such as task planning and trajectory generation), autoregressive latency is acceptable; for high-frequency feedback control (such as 1kHz torque control), distillation into feedforward networks or parallel decoding is required.

- `ent_paper_scalemogen_autoregressive_next_2026` — Extends autoregressive action generation to scale-by-scale prediction, demonstrating a variant of this formalism in the motion generation domain.
- `ent_paper_chen_combatvla_an_efficient_vision_2025` — Explores another technical route for efficient vision-language-action models, contrasting with action token prediction.
- `ent_self_attention_equation` — Self-attention is the core computational unit of the Transformer decoder, and action token generation relies on its causal masked variant.

## 개요

Transformer 액션 디코더 형식론(Transformer Action Decoder Formalism)은 Transformer 아키텍처와 학습된 액션 토큰 어휘를 사용하여 시각-언어 컨텍스트에서 로봇 액션을 디코딩하는 형식적 생성 프레임워크입니다. 연속 액션 공간을 토큰 시퀀스로 이산화하고, 자기회귀 방식으로 토큰별 액션을 생성하여 언어 모델의 훈련 및 추론 생태계를 재사용합니다. 이 형식론이 실제로 바꾸는 것은 액션 예측 정확도 자체가 아니라, 로봇 액션 생성을 대규모 사전 훈련 언어 모델과 동일한 형식적 인터페이스를 공유하도록 만드는 것입니다.

## 핵심 내용

### 무엇인가: 정확한 정의

Transformer 액션 디코더 형식론은 **형식적 방법** 유형에 속하며, 관련 분야는 AI 모델 및 알고리즘, 기초 학문이며, 가치 사슬 계층은 지능 계층 및 foundations입니다. 핵심 아이디어는 세 가지 구성 요소로 분해할 수 있습니다:

1. **시각-언어 인코더**: 관측 이미지와 언어 명령을 컨텍스트 벡터로 인코딩하며, 일반적으로 시각 인코더(예: DINOv2, SigLIP)와 언어 모델 백본(예: Llama 2)의 융합 구조를 채택합니다;
2. **액션 토큰 어휘**: 연속 액션 공간을 자유도별로 양자화하여 빈(bin)으로 나누고, 각 빈을 어휘 끝부분의 토큰에 매핑하여 "액션 어휘"를 형성합니다;
3. **자기회귀 디코더**: Transformer 디코더를 기반으로 조건부 확률에 따라 토큰별로 액션 시퀀스를 생성한 후, 다시 연속 액션 값으로 디코딩합니다.

이 형식적 프레임워크의 수학적 표현은 다음과 같습니다: 관측 $o_t$와 언어 명령 $\ell$이 주어졌을 때, 정책 네트워크는 자기회귀 방식으로 액션 토큰 시퀀스 $y_1, y_2, \dots, y_D$를 생성하며, 결합 확률은 다음과 같이 분해됩니다:

$$
p_\theta(a_t \mid o_t, \ell) = \prod_{i=1}^{D} p_\theta(y_i \mid o_t, \ell, y_{<i})
$$

여기서 $D$는 액션 토큰 시퀀스 길이, $y_{<i}$는 이미 생성된 토큰 접두사, $\theta$는 네트워크 파라미터입니다. 최종 액션은 디코더를 통해 연속 공간으로 매핑됩니다: $\hat{a}_t = \mathrm{decode}(y_1, y_2, \dots, y_D)$.

### 왜 존재하는가:痛点과 역사적 위치

VLA(시각-언어-액션) 모델이 등장하기 전, 로봇 정책 학습은 근본적인 단절에 직면했습니다: 시각-언어 모델(VLM)의 입력과 출력은 모두 이산 토큰인 반면, 로봇 액션은 연속 벡터입니다. 초기 접근법은 VLM에 회귀 헤드를 부착하여 연속 액션을 직접 출력했지만, 회귀 헤드는 언어 모델의 생성적 훈련 파이프라인을 잃어버렸습니다 — 인터넷 규모 데이터로 검증된 "다음 토큰 예측" 사전 훈련 목표를 재사용할 수 없었습니다.

Transformer 액션 디코더 형식론의 역사적 위치는 다음과 같습니다: 액션 생성을 텍스트 생성과 동형인 시퀀스 모델링 문제로 변환하여, 로봇 정책이 LLM의 세 가지 핵심 자산 — 사전 훈련 가중치, 자기회귀 추론 생태계, 그리고 파라미터 효율적 미세 조정 방법(예: LoRA) — 을 직접 상속할 수 있게 합니다. 이 형식론은 RT 시리즈 모델에 의해 확립되었으며, OpenVLA와 같은 오픈소스 VLA에 의해 계승되고 표준화되었습니다.

### 원리 분해

**① 액션 양자화: 연속 공간에서 이산 토큰으로의 매핑**

액션 양자화의 표준 프로세스는 다음과 같습니다: 각 자유도의 연속 액션 값을 균일 빈으로 이산화하고(RT-2는 256개 빈 사용), 빈 번호를 언어 모델 어휘에 매핑합니다(일반적으로 텍스트와의 충돌을 피하기 위해 어휘 끝부분의 가장 덜 사용되는 토큰 사용). 양자화 오차의 상한은 빈 폭에 의해 결정되므로, 빈 수를 늘리면 정밀도가 향상되지만 어휘 규모가 커지고 최적화 난이도가 증가합니다.

**② 자기회귀 생성: 조건부 확률의 체인 분해**

Transformer 디코더는 인과적 어텐션 마스크를 통해 위치별로 토큰을 생성합니다. 각 단계의 조건부 확률 $p_\theta(y_i \mid o_t, \ell, y_{<i})$는 디코더 마지막 레이어의 softmax 출력으로 주어집니다. 추론 시에는 탐욕 디코딩 또는 빔 서치를 사용하고, 훈련 시에는 교사 강제(teacher forcing)로 우도를 최대화합니다.

**③ 시각-언어 컨텍스트 융합**

시각 인코더(예: DINOv2와 SigLIP 이중 인코더)가 추출한 이미지 특징과 언어 명령의 텍스트 임베딩을 결합하여 디코더의 교차 어텐션 입력으로 사용합니다. 이 설계는 액션 생성이 시각 관측과 의미적 명령에 동시에 제약을 받아 "무엇이 보이는지, 무엇을 하라는 요청인지, 그에 맞는 액션을 생성하는지"의 폐루프를 구현합니다.

### 횡적 비교

**연속 액션 회귀 헤드와 비교**: 회귀 헤드는 연속 벡터를 직접 출력하며, 훈련 목표는 평균 제곱 오차로 LLM의 생성적 사전 훈련을 재사용할 수 없습니다; 액션 토큰 예측은 LLM 훈련 파이프라인을 완전히 재사용하지만 양자화 오차와 시퀀스 길이 오버헤드를 도입합니다.

**확산/플로우 매칭 액션 헤드와 비교**: 확산 정책(Diffusion Policy)은 연속 공간에서 액션 궤적을 직접 생성하여 양자화 오차를 피하지만, 추가적인 확산 모델 아키텍처와 샘플링 과정이 필요하며 LLM과 백본을 공유할 수 없습니다. OpenVLA는 29개 작업에서 7B 파라미터로 RT-2-X(55B)를 16.5%의 절대 작업 성공률로 능가하고, Diffusion Policy보다 20.4% 우수합니다(출처: arXiv:2406.09246).

**FAST 주파수 영역 압축과 비교**: FAST는 액션 시퀀스를 주파수 영역으로 변환한 후 저주파 성분만 예측하여 토큰 시퀀스 길이를 크게 줄입니다; 액션 토큰 예측은 시간 영역 액션을 차원별로 직접 양자화하므로 시퀀스 길이가 액션 차원에 비례합니다.

### 누가 사용하는가·응용 사례

**OpenVLA(2024)**: 스탠포드 등 기관이 발표한 오픈소스 VLA, 7B 파라미터, Open X-Embodiment의 약 97만 개 실제 로봇 세그먼트에서 사전 훈련, LoRA 미세 조정 및 양자화 배포 지원(출처: arXiv:2406.09246). 액션 디코딩은 이산 토큰 자기회귀 생성을 채택하여 오픈소스 VLA의 사실상 표준을 확립했습니다.

**RT-2(2023)**: Google이 제안한 비공개 VLA, 처음으로 액션 토큰 예측 형식론을 로봇 정책에 도입하여 인터넷 지식의 액션 생성으로의 전이 가능성을 보여주었습니다. RT-2-X는 교차-구현 확장 버전으로 파라미터 수가 55B에 달합니다(출처: arXiv:2406.09246 비교 데이터).

**WAM4D(2026)**: 인과적 비디오-액션 Transformer에 공간 등록 토큰을 도입하고, 훈련 시 사전 훈련된 기하학적 사전 지식을 액션 생성에 주입하며, 추론 시 등록 분기를 제거하여 경량성을 유지합니다(출처: 이웃 카드 ent_paper_wam4d_fast_4d_world_action_mod_2026).

### 한계와 경계

1. **양자화 오차**: 균일 빈 이산화는 필연적으로 정밀도 손실을 도입하며, 서브밀리미터 정밀도가 필요한 정밀 작업(예: 조립, 플러그 삽입)에서 병목이 될 수 있습니다. 공학적 판단: 빈 수를 늘리거나 비균일 양자화를 채택하여 완화할 수 있지만, 어휘와 최적화 난이도가 증가합니다.

2. **시퀀스 길이와 추론 지연**: 액션 토큰 시퀀스 길이는 액션 차원에 비례하며, 고자유도 휴머노이드 로봇(예: 전신 30+ 자유도)의 시퀀스 길이는 수백 토큰에 달할 수 있어, 자기회귀 토큰별 생성이 상당한 추론 지연을 초래하여 고주파 제어 요구를 충족하기 어렵습니다.

3. **데이터 의존성**: 액션 토큰 어휘는 로봇 시연 데이터에서 학습해야 하며, 교차-구현 일반화는 데이터 다양성에 의존합니다. OpenVLA의 970k개 데이터는 다중 본체를 포함하지만 극단적 시나리오 커버리지는 여전히 제한적입니다(출처: arXiv:2406.09246).

4. **인과적 일관성과 모달리티 누출**: 다중 모달리티 융합(비디오, 액션, 기하학) 시나리오에서는 비인과적 정보 누출을 방지하기 위해 인과적 혼합 어텐션을 설계해야 합니다(출처: 이웃 카드 ent_paper_wam4d_fast_4d_world_action_mod_2026).

### 일반적인 오해

1. **"액션 토큰 예측은 단순한 양자화다"** — 틀림. 양자화는 첫 단계일 뿐이며, 핵심은 토큰과 언어 모델 어휘의 매핑 전략, 자기회귀 생성의 목적 함수 설계, 그리고 시각-언어 컨텍스트의 융합 방식에 있습니다. 이러한 설계가 정책의 일반화 능력을 함께 결정합니다.

2. **"Transformer 액션 디코더는 VLA에만 적용된다"** — 틀림. 이 형식론은 순수 액션 생성 작업(예: 휴머노이드 전신 운동 생성)에도 동일하게 적용되며, ScaleMoGen은 이를 스케일별 예측으로 확장하여 조대한 것에서 세밀한 것으로 운동 토큰 그래프를 생성합니다(출처: 이웃 카드 ent_paper_scalemogen_autoregressive_next_2026).

3. **"파라미터 수가 많을수록 좋다"** — 틀림. OpenVLA는 7B 파라미터로 55B의 RT-2-X를 16.5% 능가하여, 데이터 품질과 아키텍처 설계가 단순한 파라미터 확장보다 더 중요함을 보여줍니다(출처: arXiv:2406.09246).

4. **"자기회귀 생성은 필연적으로 느리다"** — 시나리오를 구분해야 합니다. 저주파 의사결정(예: 작업 계획, 궤적 생성)에서는 자기회귀 지연이 허용 가능합니다; 고주파 피드백 제어(예: 1kHz 토크 제어)에서는 피드포워드 네트워크로 증류하거나 병렬 디코딩을 채택해야 합니다.
