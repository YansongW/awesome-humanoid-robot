## 概述

正运动学（Forward Kinematics）是人形机器人运动学中的核心方法，它解决的是"给定关节角，末端执行器在哪里"这一根本问题。通过连乘各连杆的齐次变换矩阵或指数积公式，正运动学将关节空间映射到操作空间，为逆运动学、动力学分析、轨迹规划与运动学校准提供基础。它真正改变的不是单个关节的计算方式，而是让整个机器人系统拥有了从"内部状态"到"外部行为"的统一描述语言。

## 核心内容

### 是什么：准确定义

正运动学（forward kinematics）解决：给定关节角 $\mathbf{q}$，计算末端执行器在基坐标系中的位姿。通过连乘各连杆变换矩阵得到：

$$
{}^0\mathbf{T}_n(\mathbf{q}) = {}^0\mathbf{T}_1(q_1) \cdot {}^1\mathbf{T}_2(q_2) \cdots {}^{n-1}\mathbf{T}_n(q_n)
$$

末端位姿由 ${}^0\mathbf{T}_n$ 的旋转部分 $\mathbf{R}$ 和平移部分 $\mathbf{p}$ 给出。这里，**关节空间（joint space）** 是以关节变量为坐标的空间，**操作空间（task/operational space）** 是以末端位姿为坐标的空间，**末端执行器（end-effector）** 是机器人与环境交互的末端装置。正运动学本质上是这两个空间之间的一个确定性映射：给定一组关节角，末端位姿是唯一确定的，不存在多解问题——这与逆运动学形成鲜明对比。

### 为什么存在：痛点与历史定位

在机器人学发展的早期，工程师面临的核心问题是：如何系统性地描述一个多连杆机构的末端位置与姿态？直观的几何画图法在 2-DOF 平面臂上尚可应付，但面对 6-DOF 甚至 7-DOF 的空间机构时，逐杆推导三角关系变得极其繁琐且容易出错。

Denavit-Hartenberg 参数法（DH 法）的出现解决了这一痛点：它以连杆坐标系为媒介，把正运动学表示为一系列相邻坐标系变换的连乘。这种方法系统、通用，成为工业机器人时代的标准工具。然而，DH 法也有其局限——它要求为每一根连杆定义中间坐标系，这在机构设计中并不直观。设计者往往更关心**关节轴（joint axis）**本身在空间中的几何位置与方向，而不是那些中间坐标系。**旋量理论（screw theory）**与**指数积公式（Product of Exponentials, PoE）**正是从关节轴的几何直观出发描述机器人运动学的方法，它真正改变的不是计算精度，而是"我们如何思考机器人运动学"的方式。

### 原理拆解

**① DH 参数法：相邻坐标系的连乘**

DH 法用四个参数描述相邻连杆之间的变换：$(\theta_i, d_i, a_i, \alpha_i)$，分别对应关节角、连杆偏距、连杆长度和连杆扭角。每个参数对应一个基本变换，连乘得到相邻坐标系变换矩阵 ${}^{i-1}\mathbf{T}_i$。正运动学就是将这些矩阵依次相乘，最终得到 ${}^0\mathbf{T}_n$。这个过程的计算量随关节数线性增长，非常适合计算机实现。

**② 指数积公式（PoE）：从关节轴几何出发**

在三维空间中，一个单位旋量可用 6 维向量 $\mathbf{S} = (\boldsymbol{\omega}, \mathbf{v})$ 表示。对于转动关节，$\|\boldsymbol{\omega}\| = 1$，$\mathbf{v} = -\boldsymbol{\omega} \times \mathbf{q}$，其中 $\mathbf{q}$ 为轴上任意一点；对于移动关节，$\boldsymbol{\omega} = \mathbf{0}$，$\|\mathbf{v}\| = 1$。把旋量写成 $4 \times 4$ 矩阵形式 $[\mathbf{S}]$，则**矩阵指数（matrix exponential）** $e^{[\mathbf{S}]\theta}$ 给出沿该螺旋轴运动 $\theta$（转动角或移动距离）所产生的齐次变换。

PoE 正运动学公式为：

$$
\mathbf{T}(\boldsymbol{\theta}) = e^{[\mathbf{S}_1]\theta_1} \, e^{[\mathbf{S}_2]\theta_2} \, \cdots \, e^{[\mathbf{S}_n]\theta_n} \, \mathbf{M}
$$

其中 $\mathbf{M}$ 是机器人处于零位时末端在基坐标系中的位姿。以 2-DOF 平面臂为例，若两个关节轴均为 z 轴，则：

$$
\mathbf{S}_1 = \begin{bmatrix} 0 \\ 0 \\ 1 \\ 0 \\ 0 \\ 0 \end{bmatrix}, \quad
\mathbf{S}_2 = \begin{bmatrix} 0 \\ 0 \\ 1 \\ 0 \\ -L_1 \\ 0 \end{bmatrix}
$$

正运动学为：

$$
\mathbf{T}(\theta_1, \theta_2) = e^{[\mathbf{S}_1]\theta_1} \, e^{[\mathbf{S}_2]\theta_2} \, \mathbf{M}
$$

PoE 的优势在于：它直接以关节轴的空间几何为输入，不需要为每个连杆定义坐标系，且与视觉系统、运动学校准的表示方式天然兼容。

**③ 正运动学的导数：Jacobian 矩阵**

Jacobian 矩阵可从正运动学 $\mathbf{x} = f(\mathbf{q})$ 直接对 $\mathbf{q}$ 求导得到：

$$
\mathbf{J}(\mathbf{q}) = \frac{\partial f(\mathbf{q})}{\partial \mathbf{q}} \in \mathbb{R}^{m \times n}
$$

其中 $\mathbf{x}$ 为末端操作空间坐标（位置、姿态或其组合），$\mathbf{q}$ 为关节坐标。对于 $n$ 关节机械臂，$\mathbf{J}$ 的第 $i$ 列 $\mathbf{j}_i$ 表示第 $i$ 个关节以单位速度运动时末端产生的操作空间速度。Jacobian 不仅是速度映射的桥梁，也是奇异性分析、可操作性度量与力控制的基础。

### 关键参数与规格

正运动学的核心参数包括：

| 参数 | 含义 | 典型值/范围 | 说明 |
|---|---|---|---|
| 关节数 $n$ | 串联链中的自由度数量 | 6–7（人形机器人臂部） | 7-DOF 提供冗余，增强避障与灵巧性 |
| 连杆长度 $a_i$ | 相邻关节轴线的垂直距离 | 0.25–0.45 m（人形臂部） | 决定工作空间大小 |
| 连杆偏距 $d_i$ | 相邻关节轴线沿公共法线的距离 | 0–0.3 m | 影响臂部紧凑性 |
| 连杆扭角 $\alpha_i$ | 相邻关节轴线之间的夹角 | 0°–90° | 决定关节轴的空间朝向 |
| 关节角范围 | 每个关节的允许运动范围 | ±90°–±180° | 受机械限位与线缆约束 |

以 7-DOF 机械臂改进型 DH 正运动学为例，其计算流程为：定义 DH 参数表 → 计算各连杆齐次变换矩阵 → 连乘得到 ${}^0\mathbf{T}_7$ → 提取末端位置 $\mathbf{p}$ 与姿态 $\mathbf{R}$。该过程在 Python 中可用 `numpy` 高效实现，单次计算耗时在微秒量级（工程判断）。

### 横向对比

**正运动学 vs. 逆运动学**：正运动学是"从关节到末端"的确定性映射，计算简单、结果唯一；逆运动学是"从末端到关节"的反向求解，通常无解析解，且可能存在多解或无解。对于满足 **Pieper 条件** 的 6-DOF 机械臂（腕部三轴交于一点），存在解析闭式解；对于 7-DOF 或更一般构型，常用数值方法：Jacobian 伪逆、梯度下降、优化（如 Levenberg-Marquardt）或神经网络近似。

**DH 法 vs. PoE 法**：DH 法系统、通用，适合标准化建模与教学；PoE 法从关节轴几何出发，更直观、与视觉标定兼容性好，且避免了 DH 法中坐标系原点选取的歧义。在实际工程中，两者可互为验证。

**串联机构 vs. 并联机构**：并联机构的正运动学通常比逆运动学困难：给定支链长度求动平台位姿可能有多个解；而逆运动学（由位姿求支链长度）通常更直接。这与串联机构形成鲜明对比——串联机构的正运动学简单、逆运动学复杂，而并联机构恰好相反。

### 谁在用·应用案例

**① 7-DOF 机械臂改进型 DH 正运动学（Python 算例）**：定义 7-DOF 串联机械臂的改进型 DH 参数表，计算各连杆齐次变换矩阵并提取末端位姿。该算例使用 `numpy`，可在任意 Python 环境中运行，是运动学入门与验证的标准示例。

**② 工作空间蒙特卡洛采样**：通过随机生成关节角，用正运动学计算末端位置，收集所有位置点形成点云，绘制 3D 可达空间。该方法用于评估机器人工作空间是否覆盖目标任务区域，是人形机器人设计阶段的重要验证手段。

**③ 运动学校准**：以 DH 模型为例，每个连杆有四个名义参数 $(\theta_i, d_i, a_i, \alpha_i)$，可引入微小误差 $(\Delta\theta_i, \Delta d_i, \Delta a_i, \Delta\alpha_i)$。末端位置误差与参数误差之间的关系可通过正运动学对参数求导得到：

$$
\Delta \mathbf{p} = \sum_{i=1}^{n} \left( \frac{\partial \mathbf{p}}{\partial a_i} \Delta a_i + \frac{\partial \mathbf{p}}{\partial \alpha_i} \Delta \alpha_i + \frac{\partial \mathbf{p}}{\partial d_i} \Delta d_i + \frac{\partial \mathbf{p}}{\partial \theta_i} \Delta \theta_i \right) = \mathbf{J}_{\text{cal}} \, \Delta \boldsymbol{\phi}
$$

通过测量数据估计真实几何参数，可显著提升**绝对定位精度（absolute accuracy）**——即末端实际位姿与指令位姿的一致程度。相比之下，**重复定位精度（repeatability）** 主要由传动与传感器决定，与运动学校准关系较小。

**④ 3-DOF 平面机械臂正运动学与 Jacobian**：以连杆长度 $L = [0.4, 0.35, 0.25]$ m 为例，正运动学计算末端位置：

```python
def fk_planar(q):
    x = L[0]*np.cos(q[0]) + L[1]*np.cos(q[0]+q[1]) + L[2]*np.cos(q[0]+q[1]+q[2])
    y = L[0]*np.sin(q[0]) + L[1]*np.sin(q[0]+q[1]) + L[2]*np.sin(q[0]+q[1]+q[2])
    return np.array([x, y])
```

该算例同时给出 2×3 Jacobian 矩阵的解析构造，用于速度映射与奇异性分析。

### 局限与边界

正运动学的核心局限在于：**它只回答"末端在哪里"，不回答"末端应该在哪里"**。具体而言：

1. **模型依赖**：正运动学基于名义几何参数，实际装配误差、连杆柔性、关节间隙都会导致计算位姿与真实位姿的偏差。运动学校准可以部分补偿，但无法完全消除。
2. **不包含动力学信息**：正运动学只描述几何关系，不涉及力、力矩、惯量等动力学量。对于需要力控制或柔顺控制的任务，必须结合动力学模型。
3. **奇异性问题**：在奇异位形附近，Jacobian 矩阵秩亏，速度映射失效。虽然正运动学本身不受影响，但依赖 Jacobian 的逆运动学与速度控制会面临数值不稳定。
4. **计算复杂度**：对于高自由度系统（如人形机器人全身 30+ 自由度），正运动学的连乘计算虽然单次开销小，但在实时控制循环中频繁调用时仍需注意计算效率（工程判断）。

### 常见误区

1. **"正运动学就是 DH 参数连乘"**——不全面。DH 法是经典方法，但 PoE 法从关节轴几何出发，更直观且与视觉标定兼容性更好。两者是等价的不同表示，选择取决于应用场景。
2. **"正运动学结果一定准确"**——错。正运动学基于名义参数，实际几何误差会导致计算位姿与真实位姿的偏差。这正是运动学校准存在的意义。
3. **"正运动学只适用于串联机构"**——不准确。并联机构也有正运动学，只是通常比逆运动学更困难，且可能存在多解。
4. **"正运动学与逆运动学是互逆关系"**——在数学上，正运动学是单射，逆运动学是它的反函数；但在工程上，逆运动学通常没有解析解，且多解性使得"互逆"并不直接成立。

## Overview

Forward Kinematics is a core method in humanoid robot kinematics, addressing the fundamental question: "Given joint angles, where is the end-effector?" By chaining homogeneous transformation matrices of each link or using the Product of Exponentials formula, forward kinematics maps joint space to operational space, providing the foundation for inverse kinematics, dynamics analysis, trajectory planning, and kinematic calibration. What it truly changes is not how individual joints are computed, but rather giving the entire robot system a unified descriptive language from "internal state" to "external behavior."

## Content

### What It Is: Precise Definition

Forward kinematics addresses: given joint angles \(\mathbf{q}\), compute the pose of the end-effector in the base coordinate frame. This is achieved by chaining the transformation matrices of each link:

$$
{}^0\mathbf{T}_n(\mathbf{q}) = {}^0\mathbf{T}_1(q_1) \cdot {}^1\mathbf{T}_2(q_2) \cdots {}^{n-1}\mathbf{T}_n(q_n)
$$

The end-effector pose is given by the rotation part \(\mathbf{R}\) and translation part \(\mathbf{p}\) of \({}^{0}\mathbf{T}_n\). Here, **joint space** is the space with joint variables as coordinates, **task/operational space** is the space with end-effector pose as coordinates, and the **end-effector** is the terminal device through which the robot interacts with the environment. Forward kinematics is essentially a deterministic mapping between these two spaces: given a set of joint angles, the end-effector pose is uniquely determined with no multiple-solution issue—this contrasts sharply with inverse kinematics.

### Why It Exists: Pain Points and Historical Context

In the early days of robotics, engineers faced a core problem: how to systematically describe the position and orientation of the end of a multi-link mechanism? Intuitive geometric drawing methods sufficed for 2-DOF planar arms, but for spatial mechanisms with 6-DOF or even 7-DOF, deriving trigonometric relationships link by link became extremely tedious and error-prone.

The Denavit-Hartenberg parameter method (DH method) addressed this pain point: it uses link coordinate frames as intermediaries, expressing forward kinematics as a chain of transformations between adjacent coordinate frames. This method is systematic, general, and became the standard tool of the industrial robot era. However, the DH method has its limitations—it requires defining intermediate coordinate frames for each link, which is not intuitive in mechanism design. Designers are often more concerned with the geometric position and orientation of the **joint axes** themselves in space, rather than those intermediate coordinate frames. **Screw theory** and the **Product of Exponentials (PoE)** formula approach robot kinematics from the geometric intuition of joint axes. What this truly changes is not computational accuracy, but rather "how we think about robot kinematics."

### Principle Breakdown

**① DH Parameter Method: Chaining Adjacent Coordinate Frames**

The DH method uses four parameters to describe the transformation between adjacent links: \((\theta_i, d_i, a_i, \alpha_i)\), corresponding to joint angle, link offset, link length, and link twist, respectively. Each parameter corresponds to a basic transformation, and their product yields the adjacent coordinate frame transformation matrix \({}^{i-1}\mathbf{T}_i\). Forward kinematics is simply multiplying these matrices sequentially to obtain \({}^{0}\mathbf{T}_n\). The computational cost of this process grows linearly with the number of joints, making it well-suited for computer implementation.

**② Product of Exponentials (PoE): Starting from Joint Axis Geometry**

In three-dimensional space, a unit screw can be represented by a 6-dimensional vector \(\mathbf{S} = (\boldsymbol{\omega}, \mathbf{v})\). For a revolute joint, \(\|\boldsymbol{\omega}\| = 1\) and \(\mathbf{v} = -\boldsymbol{\omega} \times \mathbf{q}\), where \(\mathbf{q}\) is any point on the axis; for a prismatic joint, \(\boldsymbol{\omega} = \mathbf{0}\) and \(\|\mathbf{v}\| = 1\). Writing the screw as a \(4 \times 4\) matrix \([\mathbf{S}]\), the **matrix exponential** \(e^{[\mathbf{S}]\theta}\) gives the homogeneous transformation resulting from motion \(\theta\) (rotation angle or translation distance) along that screw axis.

The PoE forward kinematics formula is:

$$
\mathbf{T}(\boldsymbol{\theta}) = e^{[\mathbf{S}_1]\theta_1} \, e^{[\mathbf{S}_2]\theta_2} \, \cdots \, e^{[\mathbf{S}_n]\theta_n} \, \mathbf{M}
$$

where \(\mathbf{M}\) is the pose of the end-effector in the base frame when the robot is at its zero position. Taking a 2-DOF planar arm as an example, if both joint axes are along the z-axis, then:

$$
\mathbf{S}_1 = \begin{bmatrix} 0 \\ 0 \\ 1 \\ 0 \\ 0 \\ 0 \end{bmatrix}, \quad
\mathbf{S}_2 = \begin{bmatrix} 0 \\ 0 \\ 1 \\ 0 \\ -L_1 \\ 0 \end{bmatrix}
$$

The forward kinematics is:

$$
\mathbf{T}(\theta_1, \theta_2) = e^{[\mathbf{S}_1]\theta_1} \, e^{[\mathbf{S}_2]\theta_2} \, \mathbf{M}
$$

The advantage of PoE is that it directly takes the spatial geometry of joint axes as input, requires no coordinate frame definition for each link, and is naturally compatible with the representation methods used in vision systems and kinematic calibration.

**③ Derivative of Forward Kinematics: The Jacobian Matrix**

The Jacobian matrix can be obtained by directly differentiating the forward kinematics \(\mathbf{x} = f(\mathbf{q})\) with respect to \(\mathbf{q}\):

$$
\mathbf{J}(\mathbf{q}) = \frac{\partial f(\mathbf{q})}{\partial \mathbf{q}} \in \mathbb{R}^{m \times n}
$$

where \(\mathbf{x}\) is the end-effector operational space coordinate (position, orientation, or a combination), and \(\mathbf{q}\) is the joint coordinate. For an \(n\)-joint manipulator, the \(i\)-th column \(\mathbf{j}_i\) of \(\mathbf{J}\) represents the operational space velocity of the end-effector produced when the \(i\)-th joint moves at unit velocity. The Jacobian is not only the bridge for velocity mapping but also the foundation for singularity analysis, manipulability measures, and force control.

### Key Parameters and Specifications

The core parameters of forward kinematics include:

| Parameter | Meaning | Typical Value/Range | Description |
|---|---|---|---|
| Number of joints \(n\) | Number of DOF in the serial chain | 6–7 (humanoid arm) | 7-DOF provides redundancy, enhancing obstacle avoidance and dexterity |
| Link length \(a_i\) | Perpendicular distance between adjacent joint axes | 0.25–0.45 m (humanoid arm) | Determines workspace size |
| Link offset \(d_i\) | Distance between adjacent joint axes along the common normal | 0–0.3 m | Affects arm compactness |
| Link twist \(\alpha_i\) | Angle between adjacent joint axes | 0°–90° | Determines spatial orientation of joint axes |
| Joint angle range | Allowable motion range of each joint | ±90°–±180° | Constrained by mechanical limits and cable routing |

Taking the modified DH forward kinematics of a 7-DOF manipulator as an example, the computational procedure is: define the DH parameter table → compute each link's homogeneous transformation matrix → multiply sequentially to obtain \({}^{0}\mathbf{T}_7\) → extract end-effector position \(\mathbf{p}\) and orientation \(\mathbf{R}\). This process can be efficiently implemented in Python using `numpy`, with single computation times on the order of microseconds (engineering judgment).

### Horizontal Comparison

**Forward Kinematics vs. Inverse Kinematics**: Forward kinematics is a deterministic mapping "from joints to end-effector," with simple computation and a unique result; inverse kinematics is the reverse solution "from end-effector to joints," typically lacking closed-form solutions and potentially having multiple solutions or none. For 6-DOF manipulators satisfying the **Pieper condition** (where the wrist's three axes intersect at a point), closed-form analytical solutions exist; for 7-DOF or more general configurations, numerical methods are commonly used: Jacobian pseudoinverse, gradient descent, optimization (e.g., Levenberg-Marquardt), or neural network approximation.

**DH Method vs. PoE Method**: The DH method is systematic and general, suitable for standardized modeling and teaching; PoE starts from joint axis geometry, is more intuitive, has better compatibility with vision calibration, and avoids the ambiguity in choosing coordinate frame origins inherent in the DH method. In practical engineering, the two can serve as cross-validation for each other.

**Serial Mechanisms vs. Parallel Mechanisms**: Forward kinematics for parallel mechanisms is typically more difficult than inverse kinematics: given leg lengths, finding the moving platform pose may have multiple solutions; whereas inverse kinematics (from pose to leg lengths) is usually more direct. This contrasts sharply with serial mechanisms—where forward kinematics is simple and inverse kinematics is complex—while parallel mechanisms exhibit the opposite behavior.

### Who Uses It: Application Cases

**① Modified DH Forward Kinematics for a 7-DOF Manipulator (Python Example)**: Define the modified DH parameter table for a 7-DOF serial manipulator, compute each link's homogeneous transformation matrix, and extract the end-effector pose. This example uses `numpy` and can run in any Python environment, serving as a standard example for kinematics introduction and verification.

**② Monte Carlo Workspace Sampling**: By randomly generating joint angles, forward kinematics computes end-effector positions, collecting all position points to form a point cloud and plotting the 3D reachable space. This method is used to evaluate whether the robot's workspace covers the target task region and is an important validation tool during the humanoid robot design phase.

**③ Kinematic Calibration**: Taking the DH model as an example, each link has four nominal parameters \((\theta_i, d_i, a_i, \alpha_i)\), to which small errors \((\Delta\theta_i, \Delta d_i, \Delta a_i, \Delta\alpha_i)\) can be introduced. The relationship between end-effector position error and parameter errors can be obtained by differentiating forward kinematics with respect to the parameters:

$$
\Delta \mathbf{p} = \sum_{i=1}^{n} \left( \frac{\partial \mathbf{p}}{\partial a_i} \Delta a_i + \frac{\partial \mathbf{p}}{\partial \alpha_i} \Delta \alpha_i + \frac{\partial \mathbf{p}}{\partial d_i} \Delta d_i + \frac{\partial \mathbf{p}}{\partial \theta_i} \Delta \theta_i \right) = \mathbf{J}_{\text{cal}} \, \Delta \boldsymbol{\phi}
$$

Estimating true geometric parameters from measurement data can significantly improve **absolute accuracy**—the degree of agreement between the actual end-effector pose and the commanded pose. In contrast, **repeatability** is primarily determined by transmission and sensors and is less related to kinematic calibration.

**④ Forward Kinematics and Jacobian for a 3-DOF Planar Manipulator**: With link lengths \(L = [0.4, 0.35, 0.25]\) m, forward kinematics computes the end-effector position:

```python
def fk_planar(q):
    x = L[0]*np.cos(q[0]) + L[1]*np.cos(q[0]+q[1]) + L[2]*np.cos(q[0]+q[1]+q[2])
    y = L[0]*np.sin(q[0]) + L[1]*np.sin(q[0]+q[1]) + L[2]*np.sin(q[0]+q[1]+q[2])
    return np.array([x, y])
```

This example also provides the analytical construction of the 2×3 Jacobian matrix, used for velocity mapping and singularity analysis.

### Limitations and Boundaries

The core limitation of forward kinematics is: **it only answers "where the end-effector is," not "where the end-effector should be."** Specifically:

1. **Model Dependence**: Forward kinematics is based on nominal geometric parameters; actual assembly errors, link flexibility, and joint clearances all cause deviations between computed and true poses. Kinematic calibration can partially compensate but cannot completely eliminate these.
2. **No Dynamic Information**: Forward kinematics only describes geometric relationships and does not involve forces, torques, inertias, or other dynamic quantities. For tasks requiring force control or compliant control, a dynamic model must be incorporated.
3. **Singularity Issues**: Near singular configurations, the Jacobian matrix becomes rank-deficient and velocity mapping fails. Although forward kinematics itself is unaffected, inverse kinematics and velocity control that rely on the Jacobian face numerical instability.
4. **Computational Complexity**: For high-DOF systems (such as a full humanoid robot with 30+ DOF), although the per-call cost of forward kinematics chaining is small, computational efficiency still requires attention when invoked frequently in real-time control loops (engineering judgment).

### Common Misconceptions

1. **"Forward kinematics is just DH parameter chaining"**—Incomplete. The DH method is the classical approach, but the PoE method starts from joint axis geometry, is more intuitive, and has better compatibility with vision calibration. The two are equivalent but different representations; the choice depends on the application scenario.
2. **"Forward kinematics results are always accurate"**—Wrong. Forward kinematics is based on nominal parameters; actual geometric errors cause deviations between computed and true poses. This is precisely why kinematic calibration exists.
3. **"Forward kinematics only applies to serial mechanisms"**—Inaccurate. Parallel mechanisms also have forward kinematics, but it is typically more difficult than inverse kinematics and may have multiple solutions.
4. **"Forward kinematics and inverse kinematics are inverse operations"**—Mathematically, forward kinematics is injective and inverse kinematics is its inverse function; but in engineering, inverse kinematics typically has no closed-form solution, and the multiplicity of solutions means "inverse" is not directly established.

## 개요

정운동학(Forward Kinematics)은 휴머노이드 로봇 운동학의 핵심 방법으로, "주어진 관절각에서 말단 실행기가 어디에 있는가"라는 근본적인 문제를 해결한다. 각 링크의 동차 변환 행렬 또는 지수곱 공식을 연속적으로 곱함으로써, 정운동학은 관절 공간을 작업 공간에 매핑하며, 역운동학, 동역학 해석, 궤적 계획 및 운동학 보정의 기초를 제공한다. 이것이 진정으로 바꾸는 것은 개별 관절의 계산 방식이 아니라, 로봇 전체 시스템이 "내부 상태"에서 "외부 행동"으로의 통일된 표현 언어를 갖게 한다는 점이다.

## 핵심 내용

### 무엇인가: 정확한 정의

정운동학(forward kinematics)은 다음을 해결한다: 관절각 $\mathbf{q}$가 주어졌을 때, 말단 실행기의 기준 좌표계에서의 자세를 계산한다. 각 링크의 변환 행렬을 연속적으로 곱하여 얻는다:

$$
{}^0\mathbf{T}_n(\mathbf{q}) = {}^0\mathbf{T}_1(q_1) \cdot {}^1\mathbf{T}_2(q_2) \cdots {}^{n-1}\mathbf{T}_n(q_n)
$$

말단 자세는 ${}^0\mathbf{T}_n$의 회전 부분 $\mathbf{R}$과 병진 부분 $\mathbf{p}$로 주어진다. 여기서 **관절 공간(joint space)**은 관절 변수를 좌표로 하는 공간이고, **작업 공간(task/operational space)**은 말단 자세를 좌표로 하는 공간이며, **말단 실행기(end-effector)**는 로봇과 환경이 상호작용하는 말단 장치이다. 정운동학은 본질적으로 이 두 공간 사이의 결정론적 매핑이다: 주어진 관절각 집합에 대해 말단 자세는 유일하게 결정되며 다중 해 문제가 없다—이는 역운동학과 뚜렷한 대조를 이룬다.

### 왜 존재하는가:痛点과 역사적 위치

로봇공학 발전 초기에 엔지니어들이 직면한 핵심 문제는: 다중 링크 메커니즘의 말단 위치와 자세를 체계적으로 어떻게 기술할 것인가였다. 직관적인 기하학적 도면법은 2-DOF 평면 팔에서는 감당할 수 있었지만, 6-DOF 또는 7-DOF 공간 메커니즘을面对할 때 링크별 삼각 관계를 유도하는 것은 매우 번거롭고 오류가 발생하기 쉬웠다.

Denavit-Hartenberg 매개변수법(DH법)의 등장은 이痛点을 해결했다: 링크 좌표계를 매개체로 하여 정운동학을 일련의 인접 좌표계 변환의 연속 곱으로 표현한다. 이 방법은 체계적이고 범용적이며 산업용 로봇 시대의 표준 도구가 되었다. 그러나 DH법에도 한계가 있다—각 링크에 대해 중간 좌표계를 정의해야 하며, 이는 메커니즘 설계에서 직관적이지 않다. 설계자는 종종 **관절 축(joint axis)** 자체의 공간에서의 기하학적 위치와 방향에 더 관심을 가지며, 중간 좌표계에는 관심이 없다. **나선 이론(screw theory)**과 **지수곱 공식(Product of Exponentials, PoE)**은 바로 관절 축의 기하학적 직관에서 출발하여 로봇 운동학을 기술하는 방법으로, 이것이 진정으로 바꾸는 것은 계산 정밀도가 아니라 "로봇 운동학을 어떻게 사고하는가"의 방식이다.

### 원리 분해

**① DH 매개변수법: 인접 좌표계의 연속 곱**

DH법은 네 개의 매개변수로 인접 링크 사이의 변환을 기술한다: $(\theta_i, d_i, a_i, \alpha_i)$는 각각 관절각, 링크 오프셋, 링크 길이, 링크 비틀림 각도에 해당한다. 각 매개변수는 하나의 기본 변환에 대응하며, 연속 곱을 통해 인접 좌표계 변환 행렬 ${}^{i-1}\mathbf{T}_i$를 얻는다. 정운동학은 이 행렬들을 순차적으로 곱하여 최종적으로 ${}^0\mathbf{T}_n$을 얻는 것이다. 이 과정의 계산량은 관절 수에 따라 선형적으로 증가하며 컴퓨터 구현에 매우 적합하다.

**② 지수곱 공식(PoE): 관절 축 기하학에서 출발**

3차원 공간에서 단위 나선은 6차원 벡터 $\mathbf{S} = (\boldsymbol{\omega}, \mathbf{v})$로 표현할 수 있다. 회전 관절의 경우 $\|\boldsymbol{\omega}\| = 1$, $\mathbf{v} = -\boldsymbol{\omega} \times \mathbf{q}$이며, 여기서 $\mathbf{q}$는 축 위의 임의의 점이다; 병진 관절의 경우 $\boldsymbol{\omega} = \mathbf{0}$, $\|\mathbf{v}\| = 1$이다. 나선을 $4 \times 4$ 행렬 형태 $[\mathbf{S}]$로 쓰면, **행렬 지수(matrix exponential)** $e^{[\mathbf{S}]\theta}$는 해당 나선 축을 따라 $\theta$(회전 각도 또는 병진 거리)만큼 운동할 때 생성되는 동차 변환을 제공한다.

PoE 정운동학 공식은 다음과 같다:

$$
\mathbf{T}(\boldsymbol{\theta}) = e^{[\mathbf{S}_1]\theta_1} \, e^{[\mathbf{S}_2]\theta_2} \, \cdots \, e^{[\mathbf{S}_n]\theta_n} \, \mathbf{M}
$$

여기서 $\mathbf{M}$은 로봇이 영점 위치에 있을 때 말단의 기준 좌표계에서의 자세이다. 2-DOF 평면 팔을 예로 들면, 두 관절 축이 모두 z축이면:

$$
\mathbf{S}_1 = \begin{bmatrix} 0 \\ 0 \\ 1 \\ 0 \\ 0 \\ 0 \end{bmatrix}, \quad
\mathbf{S}_2 = \begin{bmatrix} 0 \\ 0 \\ 1 \\ 0 \\ -L_1 \\ 0 \end{bmatrix}
$$

정운동학은 다음과 같다:

$$
\mathbf{T}(\theta_1, \theta_2) = e^{[\mathbf{S}_1]\theta_1} \, e^{[\mathbf{S}_2]\theta_2} \, \mathbf{M}
$$

PoE의 장점은: 관절 축의 공간 기하학을 직접 입력으로 사용하며 각 링크에 대해 좌표계를 정의할 필요가 없고, 비전 시스템 및 운동학 보정의 표현 방식과 자연스럽게 호환된다는 점이다.

**③ 정운동학의 도함수: Jacobian 행렬**

Jacobian 행렬은 정운동학 $\mathbf{x} = f(\mathbf{q})$에서 $\mathbf{q}$에 대해 직접 미분하여 얻을 수 있다:

$$
\mathbf{J}(\mathbf{q}) = \frac{\partial f(\mathbf{q})}{\partial \mathbf{q}} \in \mathbb{R}^{m \times n}
$$

여기서 $\mathbf{x}$는 말단 작업 공간 좌표(위치, 자세 또는 그 조합)이고, $\mathbf{q}$는 관절 좌표이다. $n$ 관절 로봇 팔의 경우 $\mathbf{J}$의 $i$번째 열 $\mathbf{j}_i$는 $i$번째 관절이 단위 속도로 운동할 때 말단에서 생성되는 작업 공간 속도를 나타낸다. Jacobian은 속도 매핑의 다리 역할을 할 뿐만 아니라 특이점 분석, 조작성 측정 및 힘 제어의 기초이다.

### 핵심 매개변수와 사양

정운동학의 핵심 매개변수는 다음과 같다:

| 매개변수 | 의미 | 일반값/범위 | 설명 |
|---|---|---|---|
| 관절 수 $n$ | 직렬 체인의 자유도 수 | 6–7 (휴머노이드 로봇 팔) | 7-DOF는 여유도를 제공하여 장애물 회피와 기민성 강화 |
| 링크 길이 $a_i$ | 인접 관절 축 사이의 수직 거리 | 0.25–0.45 m (휴머노이드 팔) | 작업 공간 크기 결정 |
| 링크 오프셋 $d_i$ | 공통 법선을 따른 인접 관절 축 사이의 거리 | 0–0.3 m | 팔의 컴팩트성에 영향 |
| 링크 비틀림 각도 $\alpha_i$ | 인접 관절 축 사이의 각도 | 0°–90° | 관절 축의 공간 방향 결정 |
| 관절각 범위 | 각 관절의 허용 운동 범위 | ±90°–±180° | 기계적 리미트와 케이블 제약에 영향 |

7-DOF 로봇 팔의 수정 DH 정운동학을 예로 들면 계산流程는: DH 매개변수 테이블 정의 → 각 링크의 동차 변환 행렬 계산 → 연속 곱으로 ${}^0\mathbf{T}_7$ 얻기 → 말단 위치 $\mathbf{p}$와 자세 $\mathbf{R}$ 추출. 이 과정은 Python에서 `numpy`로 효율적으로 구현할 수 있으며 단일 계산 시간은 마이크로초 수준이다(공학적 판단).

### 횡적 비교

**정운동학 vs. 역운동학**: 정운동학은 "관절에서 말단으로"의 결정론적 매핑으로 계산이 간단하고 결과가 유일하다; 역운동학은 "말단에서 관절로"의 역방향 해법으로 일반적으로 해석적 해가 없으며 다중 해 또는 무해가 존재할 수 있다. **Pieper 조건**을 만족하는 6-DOF 로봇 팔(손목 세 축이 한 점에서 교차)의 경우 해석적 폐쇄형 해가 존재한다; 7-DOF 또는 더 일반적인 구성의 경우 일반적으로 수치적 방법을 사용한다: Jacobian 유사역행렬, 경사 하강법, 최적화(예: Levenberg-Marquardt) 또는 신경망 근사.

**DH법 vs. PoE법**: DH법은 체계적이고 범용적이며 표준화된 모델링과 교육에 적합하다; PoE법은 관절 축 기하학에서 출발하여 더 직관적이고 비전 보정과의 호환성이 좋으며 DH법에서 좌표계 원점 선택의 모호성을 피한다. 실제 공학에서는 두 방법을 상호 검증에 사용할 수 있다.

**직렬 메커니즘 vs. 병렬 메커니즘**: 병렬 메커니즘의 정운동학은 일반적으로 역운동학보다 어렵다: 주어진 지지 다리 길이로 이동 플랫폼 자세를 구하는 것은 여러 해가 있을 수 있다; 반면 역운동학(자세에서 지지 다리 길이를 구하는 것)은 일반적으로 더 직접적이다. 이는 직렬 메커니즘과 뚜렷한 대조를 이룬다—직렬 메커니즘은 정운동학이 간단하고 역운동학이 복잡한 반면, 병렬 메커니즘은 정반대이다.

### 누가 사용하는가·응용 사례

**① 7-DOF 로봇 팔 수정 DH 정운동학 (Python 계산 예)**: 7-DOF 직렬 로봇 팔의 수정 DH 매개변수 테이블을 정의하고 각 링크의 동차 변환 행렬을 계산하여 말단 자세를 추출한다. 이 계산 예는 `numpy`를 사용하며 모든 Python 환경에서 실행할 수 있고, 운동학 입문과 검증의 표준 예시이다.

**② 작업 공간 Monte Carlo 샘플링**: 관절각을 무작위로 생성하고 정운동학으로 말단 위치를 계산하여 모든 위치 점을 수집해 점군을 형성하고 3D 도달 가능 공간을 그린다. 이 방법은 로봇 작업 공간이 목표 작업 영역을覆盖하는지 평가하는 데 사용되며 휴머노이드 로봇 설계 단계의 중요한 검증 수단이다.

**③ 운동학 보정**: DH 모델을 예로 들면 각 링크에는 네 개의 명목 매개변수 $(\theta_i, d_i, a_i, \alpha_i)$가 있으며 작은 오차 $(\Delta\theta_i, \Delta d_i, \Delta a_i, \Delta\alpha_i)$를 도입할 수 있다. 말단 위치 오차와 매개변수 오차 사이의 관계는 정운동학을 매개변수에 대해 미분하여 얻을 수 있다:

$$
\Delta \mathbf{p} = \sum_{i=1}^{n} \left( \frac{\partial \mathbf{p}}{\partial a_i} \Delta a_i + \frac{\partial \mathbf{p}}{\partial \alpha_i} \Delta \alpha_i + \frac{\partial \mathbf{p}}{\partial d_i} \Delta d_i + \frac{\partial \mathbf{p}}{\partial \theta_i} \Delta \theta_i \right) = \mathbf{J}_{\text{cal}} \, \Delta \boldsymbol{\phi}
$$

측정 데이터를 통해 실제 기하학적 매개변수를 추정하면 **절대 위치 정밀도(absolute accuracy)**—즉 말단의 실제 자세와 명령 자세의 일치 정도—를 크게 향상시킬 수 있다. 반면 **반복 위치 정밀도(repeatability)**는 주로 구동계와 센서에 의해 결정되며 운동학 보정과의 관련성은 적다.

**④ 3-DOF 평면 로봇 팔 정운동학과 Jacobian**: 링크 길이 $L = [0.4, 0.35, 0.25]$ m를 예로 들면 정운동학으로 말단 위치를 계산한다:

```python
def fk_planar(q):
    x = L[0]*np.cos(q[0]) + L[1]*np.cos(q[0]+q[1]) + L[2]*np.cos(q[0]+q[1]+q[2])
    y = L[0]*np.sin(q[0]) + L[1]*np.sin(q[0]+q[1]) + L[2]*np.sin(q[0]+q[1]+q[2])
    return np.array([x, y])
```

이 계산 예는 동시에 2×3 Jacobian 행렬의 해석적 구성을 제공하여 속도 매핑과 특이점 분석에 사용한다.

### 한계와 경계

정운동학의 핵심 한계는: **"말단이 어디에 있는가"만 답할 뿐 "말단이 어디에 있어야 하는가"는 답하지 않는다**는 점이다. 구체적으로:

1. **모델 의존성**: 정운동학은 명목 기하학적 매개변수에 기반하며 실제 조립 오차, 링크 유연성, 관절 간극은 계산된 자세와 실제 자세의 편차를 초래한다. 운동학 보정은 부분적으로 보상할 수 있지만 완전히 제거할 수는 없다.
2. **동역학 정보 미포함**: 정운동학은 기하학적 관계만 기술하며 힘, 토크, 관성 등의 동역학적 양을 다루지 않는다. 힘 제어 또는 컴플라이언트 제어가 필요한 작업에는 동역학 모델을 결합해야 한다.
3. **특이점 문제**: 특이 자세 부근에서 Jacobian 행렬의 랭크가 부족하여 속도 매핑이失效한다. 정운동학 자체는 영향을 받지 않지만 Jacobian에 의존하는 역운동학과 속도 제어는 수치적 불안정성에 직면한다.
4. **계산 복잡도**: 고자유도 시스템(예: 휴머노이드 로봇 전신 30+ 자유도)의 경우 정운동학의 연속 곱 계산은 단일 오버헤드가 작지만 실시간 제어 루프에서 빈번히 호출될 때 계산 효율에 주의해야 한다(공학적 판단).

### 일반적인 오해

1. **"정운동학은 DH 매개변수 연속 곱이다"**—불완전하다. DH법은 고전적 방법이지만 PoE법은 관절 축 기하학에서 출발하여 더 직관적이고 비전 보정과의 호환성이 더 좋다. 둘은 동등한 다른 표현이며 선택은 응용 시나리오에 달려 있다.
2. **"정운동학 결과는 반드시 정확하다"**—틀렸다. 정운동학은 명목 매개변수에 기반하며 실제 기하학적 오차는 계산된 자세와 실제 자세의 편차를 초래한다. 이것이 바로 운동학 보정이 존재하는 이유이다.
3. **"정운동학은 직렬 메커니즘에만 적용된다"**—정확하지 않다. 병렬 메커니즘에도 정운동학이 있지만 일반적으로 역운동학보다 어렵고 다중 해가 존재할 수 있다.
4. **"정운동학과 역운동학은 상호 역 관계이다"**—수학적으로 정운동학은 단사 함수이고 역운동학은 그 역함수이다; 그러나 공학적으로 역운동학은 일반적으로 해석적 해가 없으며 다중 해성으로 인해 "상호 역"이 직접적으로 성립하지 않는다.
