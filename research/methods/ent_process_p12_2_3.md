## 概述

技能库与任务规划（Skill Library and Task Planning）是人形机器人 VLA / WAM / AI 算法集成阶段（P12）中编号为 P12.2.3 的路线图工序节点，属于方法（method）类型，归属领域为 `07_ai_models_algorithms`，价值链层级为 `intelligence`。它解决的是"高层任务如何分解为可复用技能、低层如何由 VLA/控制执行"的层级衔接问题，核心方法工具包括 LLM+PDDL、Behavior Trees、Skill Library 与失败恢复机制。它真正改变的不是单个算法的规划精度，而是让机器人从"能做一个动作"变成"能完成一件多步骤的事"。

## 核心内容

### 是什么：准确定义

技能库与任务规划是 P12.2（VLA 与操作策略）工作包下的一个三级子任务，负责将自然语言或高层指令转化为可执行的技能序列。其设计思考逻辑为：**高层任务分解为可复用技能；低层由 VLA/控制执行**。这意味着系统存在一条清晰的层级边界——上层负责"做什么、按什么顺序做"，下层负责"每个动作具体怎么做"。

该节点的方法/工具组合为：**LLM+PDDL、Behavior Trees、Skill Library、失败恢复**。其中：

- **LLM+PDDL**：用大语言模型将自然语言任务翻译为 PDDL（Planning Domain Definition Language）形式的规划域与问题定义，实现符号层面的任务分解；
- **Behavior Trees**：用行为树组织技能的执行逻辑，支持条件分支、顺序组合与并行控制；
- **Skill Library**：沉淀可复用的原子技能库，每个技能封装了从感知条件到执行参数的完整接口；
- **失败恢复**：在执行失败时触发回退、重试或替代技能，保证任务级鲁棒性。

该节点的关键约束为**技能覆盖度、失败恢复、实时性**，完成标准/输出物为**多步骤任务执行视频、技能库清单、失败恢复率**。

### 为什么存在：痛点与历史定位

在早期机器人任务执行中，规划与执行是割裂的：经典 PDDL 规划器能生成符号层面的动作序列，但无法处理真实世界的感知噪声与执行误差；而端到端学习模型（如直接输出动作的神经网络）虽然对单步操作鲁棒，却难以应对长时序、多步骤的任务组合。技能库与任务规划正是为弥合这一鸿沟而存在。

它的历史定位可以概括为：**在符号规划与反应式控制之间插入一层"可复用的技能抽象"**。这一层既保留了 PDDL 的因果推理能力，又通过 Behavior Trees 引入执行时的条件判断与失败处理，同时借助 Skill Library 避免每次任务都从零开始规划。它真正改变的不是任务规划的成功率，而是让机器人系统具备了"面对新任务时不必重新编程"的泛化能力。

### 原理拆解

**① 任务分解：从自然语言到 PDDL 的语义映射**

LLM 接收高层指令（如"把桌上的苹果放到篮子里"），将其解析为 PDDL 的谓词逻辑与动作模式。PDDL 规划器在符号空间中搜索动作序列，生成满足目标条件的计划。这一层的输出不是关节角度，而是一串技能标识符及其参数。

**② 技能执行：Behavior Trees 的组织逻辑**

行为树以根节点向下逐帧执行，支持四种组合节点：Sequence（顺序执行，任一失败则整体失败）、Selector（选择执行，任一成功则整体成功）、Parallel（并行执行）、Decorator（条件修饰）。技能库中的每个技能对应行为树的一个叶节点，叶节点内部封装了调用 VLA 模型或底层控制器的接口。

**③ 失败恢复：状态机与回退策略**

当某个技能执行失败时，行为树通过 Decorator 节点捕获失败信号，触发恢复策略。恢复策略可以是重试（Retry）、回退到上一技能（Fallback）或切换到替代技能（Alternative）。失败恢复率即衡量这一机制有效性的核心 KPI。

**④ 层级衔接：技能库与 VLA 的接口契约**

每个技能定义了一个标准接口：输入为感知状态（如物体位姿、抓取点）、输出为动作参数（如目标关节轨迹）。VLA 模型负责将技能参数映射为具体的电机指令。这一接口契约保证了技能库的复用性——同一个"抓取"技能可以服务于不同的高层任务。

### 局限与边界

1. **技能覆盖度瓶颈**：技能库的泛化能力受限于已沉淀的技能种类。面对未覆盖的新技能，系统无法直接执行，需要人工补充技能定义（工程判断）。
2. **LLM 规划的不确定性**：LLM 将自然语言映射为 PDDL 时可能产生语义歧义或规划错误，需要人工校验或引入约束规则（工程判断）。
3. **实时性约束**：PDDL 规划在复杂任务下可能耗时较长，需通过预计算或增量规划缓解（工程判断）。
4. **失败恢复的边界**：失败恢复机制只能处理已定义的失败模式，对未知异常（如传感器完全失效）无法保证恢复成功率（工程判断）。

### 常见误区

1. **"技能库就是动作库"**——错。技能库封装的不只是动作参数，还包括前置条件、后置条件与失败处理逻辑，是一个完整的执行契约。
2. **"LLM 能直接替代 PDDL"**——错。LLM 擅长语义理解，但缺乏因果推理的严谨性；PDDL 提供符号层面的可验证性，两者是互补关系。
3. **"失败恢复就是重试"**——错。重试只是恢复策略之一，更有效的恢复是回退到上一技能或切换到替代技能，这需要行为树的结构支持。
4. **"任务规划与运动规划无关"**——错。技能库的接口必须与底层运动规划对齐，否则技能参数无法被 VLA/控制层正确执行。

## Overview

The Skill Library and Task Planning is a roadmap process node numbered P12.2.3 within the VLA / WAM / AI algorithm integration phase (P12) of humanoid robots. It is of the method type, belongs to the domain `07_ai_models_algorithms`, and sits at the `intelligence` level of the value chain. It addresses the hierarchical linkage problem of "how high-level tasks are decomposed into reusable skills and how low-level execution is handled by VLA/control." The core method tools include LLM+PDDL, Behavior Trees, Skill Library, and failure recovery mechanisms. What it truly changes is not the planning accuracy of a single algorithm, but rather enabling the robot to evolve from "being able to perform an action" to "being able to complete a multi-step task."

## Content

### What It Is: Precise Definition

The Skill Library and Task Planning is a third-level subtask under the P12.2 (VLA and manipulation policies) work package, responsible for converting natural language or high-level instructions into executable skill sequences. Its design logic is: **high-level tasks are decomposed into reusable skills; low-level execution is handled by VLA/control**. This implies a clear hierarchical boundary in the system—the upper layer is responsible for "what to do and in what order," while the lower layer handles "how each action is specifically executed."

The method/tool combination for this node is: **LLM+PDDL, Behavior Trees, Skill Library, failure recovery**. Specifically:

- **LLM+PDDL**: Uses large language models to translate natural language tasks into PDDL (Planning Domain Definition Language) planning domains and problem definitions, enabling symbolic-level task decomposition;
- **Behavior Trees**: Uses behavior trees to organize skill execution logic, supporting conditional branching, sequential composition, and parallel control;
- **Skill Library**: Accumulates a library of reusable atomic skills, each encapsulating a complete interface from perceptual conditions to execution parameters;
- **Failure Recovery**: Triggers fallback, retry, or alternative skills upon execution failure to ensure task-level robustness.

The key constraints for this node are **skill coverage, failure recovery, and real-time performance**. The completion criteria/deliverables are **multi-step task execution videos, skill library inventory, and failure recovery rate**.

### Why It Exists: Pain Points and Historical Positioning

In early robot task execution, planning and execution were disconnected: classical PDDL planners could generate symbolic-level action sequences but could not handle real-world perceptual noise and execution errors; end-to-end learning models (such as neural networks that directly output actions) were robust for single-step operations but struggled with long-horizon, multi-step task compositions. The Skill Library and Task Planning exists precisely to bridge this gap.

Its historical positioning can be summarized as: **inserting a layer of "reusable skill abstraction" between symbolic planning and reactive control**. This layer preserves the causal reasoning capability of PDDL, introduces runtime conditional judgment and failure handling through Behavior Trees, and leverages the Skill Library to avoid planning from scratch for every task. What it truly changes is not the success rate of task planning, but rather endowing the robot system with the generalization capability of "not needing to be reprogrammed when facing new tasks."

### Principle Breakdown

**① Task Decomposition: Semantic Mapping from Natural Language to PDDL**

The LLM receives high-level instructions (e.g., "put the apple on the table into the basket"), parsing them into PDDL predicate logic and action schemas. The PDDL planner searches for action sequences in symbolic space, generating a plan that satisfies the goal conditions. The output of this layer is not joint angles, but a sequence of skill identifiers and their parameters.

**② Skill Execution: Organizational Logic of Behavior Trees**

Behavior trees execute frame-by-frame from the root node downward, supporting four types of composite nodes: Sequence (execute in order; fails if any child fails), Selector (selectively execute; succeeds if any child succeeds), Parallel (execute concurrently), and Decorator (conditional modifiers). Each skill in the skill library corresponds to a leaf node in the behavior tree, with the leaf node internally encapsulating the interface for invoking the VLA model or low-level controller.

**③ Failure Recovery: State Machines and Fallback Strategies**

When a skill execution fails, the behavior tree captures the failure signal through Decorator nodes and triggers recovery strategies. Recovery strategies can be retry, fallback to the previous skill, or switching to an alternative skill. The failure recovery rate is the core KPI measuring the effectiveness of this mechanism.

**④ Hierarchical Linkage: Interface Contract between Skill Library and VLA**

Each skill defines a standard interface: inputs are perceptual states (e.g., object poses, grasp points), and outputs are action parameters (e.g., target joint trajectories). The VLA model is responsible for mapping skill parameters to specific motor commands. This interface contract ensures the reusability of the skill library—the same "grasp" skill can serve different high-level tasks.

### Who Uses It: Application Cases

This node is a standard process under the P12.2 work package, applicable to all humanoid robot product development scenarios requiring multi-step manipulation. Typical applications include:

- **Home services**: Decomposing the "clear the dining table" task into a skill sequence of "identify utensils → grasp → move to the sink → place";
- **Industrial assembly**: Decomposing the "assemble parts" task into a skill sequence of "locate → grasp → align → insert → fasten";
- **Logistics sorting**: Decomposing the "sort packages" task into a skill sequence of "identify labels → grasp → classify and place".

In engineering practice, the execution of this node follows a five-step method: P12.2.3.1 input organization and goal quantification, P12.2.3.2 algorithm/control scheme design, P12.2.3.3 algorithm implementation and simulation validation, P12.2.3.4 algorithm tuning and performance validation, P12.2.3.5 documentation output and downstream delivery.

### Limitations and Boundaries

1. **Skill coverage bottleneck**: The generalization capability of the skill library is limited by the types of skills already accumulated. For new skills not yet covered, the system cannot execute directly and requires manual supplementation of skill definitions (engineering judgment).
2. **Uncertainty in LLM planning**: When the LLM maps natural language to PDDL, semantic ambiguity or planning errors may occur, requiring manual verification or the introduction of constraint rules (engineering judgment).
3. **Real-time constraints**: PDDL planning can be time-consuming for complex tasks, requiring mitigation through precomputation or incremental planning (engineering judgment).
4. **Boundaries of failure recovery**: The failure recovery mechanism can only handle predefined failure modes and cannot guarantee recovery success for unknown anomalies (e.g., complete sensor failure) (engineering judgment).

### Common Misconceptions

1. **"The skill library is just an action library"**—Wrong. The skill library encapsulates not only action parameters but also preconditions, postconditions, and failure handling logic; it is a complete execution contract.
2. **"LLM can directly replace PDDL"**—Wrong. LLMs excel at semantic understanding but lack the rigor of causal reasoning; PDDL provides verifiability at the symbolic level. The two are complementary.
3. **"Failure recovery is just retrying"**—Wrong. Retrying is only one recovery strategy; more effective recovery involves falling back to the previous skill or switching to an alternative skill, which requires structural support from behavior trees.
4. **"Task planning is unrelated to motion planning"**—Wrong. The interfaces of the skill library must align with low-level motion planning; otherwise, skill parameters cannot be correctly executed by the VLA/control layer.

스킬 라이브러리와 태스크 플래닝(Skill Library and Task Planning)은 휴머노이드 로봇 VLA / WAM / AI 알고리즘 통합 단계(P12)에서 번호 P12.2.3으로 지정된 로드맵 공정 노드로, 메서드(method) 유형에 속하며, 소속 도메인은 `07_ai_models_algorithms`, 가치 사슬 계층은 `intelligence`입니다. 이는 "상위 태스크를 어떻게 재사용 가능한 스킬로 분해하고, 하위를 어떻게 VLA/제어로 실행할지"라는 계층적 연결 문제를 해결하며, 핵심 방법 도구로는 LLM+PDDL, Behavior Trees, Skill Library 및 실패 복구 메커니즘이 포함됩니다. 이것이 실제로 바꾸는 것은 단일 알고리즘의 플래닝 정밀도가 아니라, 로봇이 "하나의 동작을 할 수 있는 것"에서 "여러 단계의 작업을 완료할 수 있는 것"으로 변화하게 하는 것입니다.

### 무엇인가: 정확한 정의

스킬 라이브러리와 태스크 플래닝은 P12.2(VLA 및 조작 정책) 워크패키지 내의 3차 하위 태스크로, 자연어 또는 상위 명령을 실행 가능한 스킬 시퀀스로 변환하는 역할을 담당합니다. 설계 사고 논리는 다음과 같습니다: **상위 태스크는 재사용 가능한 스킬로 분해되고, 하위는 VLA/제어로 실행됩니다**. 이는 시스템에 명확한 계층 경계가 존재함을 의미합니다——상위 계층은 "무엇을, 어떤 순서로 할지"를 담당하고, 하위 계층은 "각 동작을 구체적으로 어떻게 수행할지"를 담당합니다.

이 노드의 방법/도구 조합은 다음과 같습니다: **LLM+PDDL, Behavior Trees, Skill Library, 실패 복구**. 그중:

- **LLM+PDDL**: 대규모 언어 모델을 사용하여 자연어 태스크를 PDDL(Planning Domain Definition Language) 형식의 플래닝 도메인 및 문제 정의로 변환하여, 기호 수준의 태스크 분해를 구현합니다;
- **Behavior Trees**: 행동 트리로 스킬 실행 로직을 구성하여, 조건 분기, 순차 조합 및 병렬 제어를 지원합니다;
- **Skill Library**: 재사용 가능한 원자 스킬 라이브러리를 축적하며, 각 스킬은 인식 조건부터 실행 파라미터까지의 완전한 인터페이스를 캡슐화합니다;
- **실패 복구**: 실행 실패 시 롤백, 재시도 또는 대체 스킬을 트리거하여 태스크 수준의 견고성을 보장합니다.

이 노드의 핵심 제약 조건은 **스킬 커버리지, 실패 복구, 실시간성**이며, 완료 기준/산출물은 **다단계 태스크 실행 비디오, 스킬 라이브러리 목록, 실패 복구율**입니다.

### 왜 존재하는가: 문제점과 역사적 위치

초기 로봇 태스크 실행에서 플래닝과 실행은 분리되어 있었습니다: 고전적 PDDL 플래너는 기호 수준의 동작 시퀀스를 생성할 수 있었지만, 실제 세계의 인식 노이즈와 실행 오차를 처리할 수 없었습니다. 반면, 엔드투엔드 학습 모델(예: 동작을 직접 출력하는 신경망)은 단일 단계 조작에는 견고했지만, 장기 시퀀스 및 다단계 태스크 조합에는 대응하기 어려웠습니다. 스킬 라이브러리와 태스크 플래닝은 바로 이 간극을 메우기 위해 존재합니다.

그 역사적 위치는 다음과 같이 요약할 수 있습니다: **기호 플래닝과 반응형 제어 사이에 "재사용 가능한 스킬 추상화" 계층을 삽입하는 것**. 이 계층은 PDDL의 인과 추론 능력을 유지하면서, Behavior Trees를 통해 실행 시 조건 판단과 실패 처리를 도입하고, Skill Library를 활용하여 매번 태스크를 처음부터 플래닝하지 않도록 합니다. 이것이 실제로 바꾸는 것은 태스크 플래닝의 성공률이 아니라, 로봇 시스템이 "새로운 태스크에 직면했을 때 다시 프로그래밍할 필요 없는" 일반화 능력을 갖추게 하는 것입니다.

### 원리 분석

**① 태스크 분해: 자연어에서 PDDL로의 의미 매핑**

LLM은 상위 명령(예: "테이블 위의 사과를 바구니에 넣어")을 수신하여 PDDL의 술어 논리 및 동작 패턴으로 파싱합니다. PDDL 플래너는 기호 공간에서 동작 시퀀스를 검색하여 목표 조건을 충족하는 계획을 생성합니다. 이 계층의 출력은 관절 각도가 아니라, 일련의 스킬 식별자와 그 파라미터입니다.

**② 스킬 실행: Behavior Trees의 구성 논리**

행동 트리는 루트 노드에서 아래로 프레임별로 실행되며, 네 가지 구성 노드를 지원합니다: Sequence(순차 실행, 하나라도 실패하면 전체 실패), Selector(선택 실행, 하나라도 성공하면 전체 성공), Parallel(병렬 실행), Decorator(조건 수식). 스킬 라이브러리의 각 스킬은 행동 트리의 리프 노드에 해당하며, 리프 노드 내부에는 VLA 모델 또는 하위 제어기를 호출하는 인터페이스가 캡슐화되어 있습니다.

**③ 실패 복구: 상태 머신과 롤백 전략**

특정 스킬 실행이 실패하면, 행동 트리는 Decorator 노드를 통해 실패 신호를 캡처하여 복구 전략을 트리거합니다. 복구 전략은 재시도(Retry), 이전 스킬로 롤백(Fallback) 또는 대체 스킬로 전환(Alternative)이 될 수 있습니다. 실패 복구율은 이 메커니즘의 효과성을 측정하는 핵심 KPI입니다.

**④ 계층 연결: 스킬 라이브러리와 VLA의 인터페이스 계약**

각 스킬은 표준 인터페이스를 정의합니다: 입력은 인식 상태(예: 물체 자세, 그립 포인트), 출력은 동작 파라미터(예: 목표 관절 궤적)입니다. VLA 모델은 스킬 파라미터를 구체적인 모터 명령으로 매핑합니다. 이 인터페이스 계약은 스킬 라이브러리의 재사용성을 보장합니다——동일한 "그립" 스킬이 서로 다른 상위 태스크에 서비스할 수 있습니다.

### 누가 사용하는가·응용 사례

이 노드는 P12.2 워크패키지의 표준 공정으로, 다단계 조작이 필요한 모든 휴머노이드 로봇 제품 개발 시나리오에 적용됩니다. 대표적인 응용 사례는 다음과 같습니다:

- **가정 서비스**: "식탁 정리" 태스크를 "식기 인식→그립→식기 세척조로 이동→배치" 스킬 시퀀스로 분해;
- **산업 조립**: "부품 조립" 태스크를 "위치 확인→그립→정렬→삽입→고정" 스킬 시퀀스로 분해;
- **물류 분류**: "택배 분류" 태스크를 "라벨 인식→그립→분류 배치" 스킬 시퀀스로 분해.

공학 실무에서 이 노드의 실행은 5단계 방법을 따릅니다: P12.2.3.1 입력 정리 및 목표 정량화, P12.2.3.2 알고리즘/제어 방안 설계, P12.2.3.3 알고리즘 구현 및 시뮬레이션 검증, P12.2.3.4 알고리즘 튜닝 및 성능 검증, P12.2.3.5 문서 출력 및 하위 전달.

### 한계와 경계

1. **스킬 커버리지 병목**: 스킬 라이브러리의 일반화 능력은 축적된 스킬 종류에 제한됩니다. 미커버된 새 스킬에 직면하면 시스템이 직접 실행할 수 없으며, 수동으로 스킬 정의를 추가해야 합니다(공학적 판단).
2. **LLM 플래닝의 불확실성**: LLM이 자연어를 PDDL로 매핑할 때 의미적 모호성 또는 플래닝 오류가 발생할 수 있으며, 수동 검증 또는 제약 규칙 도입이 필요합니다(공학적 판단).
3. **실시간성 제약**: 복잡한 태스크에서 PDDL 플래닝이 오래 걸릴 수 있으며, 사전 계산 또는 증분 플래닝으로 완화해야 합니다(공학적 판단).
4. **실패 복구의 경계**: 실패 복구 메커니즘은 정의된 실패 모드만 처리할 수 있으며, 알 수 없는 이상(예: 센서 완전 고장)에 대해서는 복구 성공률을 보장할 수 없습니다(공학적 판단).

### 흔한 오해

1. **"스킬 라이브러리는 동작 라이브러리다"**——틀림. 스킬 라이브러리는 동작 파라미터뿐만 아니라 선행 조건, 후행 조건 및 실패 처리 로직까지 캡슐화한 완전한 실행 계약입니다.
2. **"LLM이 PDDL을 직접 대체할 수 있다"**——틀림. LLM은 의미 이해에 강하지만 인과 추론의 엄밀성이 부족합니다. PDDL은 기호 수준의 검증 가능성을 제공하며, 둘은 상호 보완 관계입니다.
3. **"실패 복구는 재시도다"**——틀림. 재시도는 복구 전략 중 하나일 뿐이며, 더 효과적인 복구는 이전 스킬로 롤백하거나 대체 스킬로 전환하는 것으로, 행동 트리의 구조적 지원이 필요합니다.
4. **"태스크 플래닝은 모션 플래닝과 무관하다"**——틀림. 스킬 라이브러리의 인터페이스는 하위 모션 플래닝과 정렬되어야 하며, 그렇지 않으면 스킬 파라미터가 VLA/제어 계층에서 올바르게 실행될 수 없습니다.
