## 概述

RT-2 视觉-语言-动作模型（RT-2 Vision-Language-Action Model）是一种将网络规模的视觉-语言知识迁移到机器人控制的 VLA 方法。它建立在视觉-语言模型（VLM）基础之上，将机器人动作直接表示为文本 token，从而让模型能够利用互联网级别的图文知识进行语义理解和泛化操作。它真正改变的不是机器人"看见"的能力，而是机器人"理解指令并执行动作"的推理链路——把语言、视觉与动作统一到同一个自回归框架中。

## 核心内容

### 是什么：RT-2 的准确定义

RT-2 属于 **方法**（method）类型实体，英文全称为 *RT-2 Vision-Language-Action Model*，韩文名称为 *RT-2 비전-언어-동작 모델*。其所属领域编码为 `07_ai_models_algorithms`，理论深度为 `method` 层级，状态为 `active`。

在实体分类学的本体论承诺中，RT-2 属于**信息实体（Information Entity）**——它以符号和数据形式存在，不占据时空、不具有质量。它与 `paper`、`algorithm`、`dataset` 同属一个大类，但更准确地说是"方法"而非"算法"：它不提供单一的数学求解步骤，而是定义了一种将视觉-语言预训练知识转化为机器人动作输出的建模范式。

RT-2 的核心思想可以概括为一句话：**把机器人的动作当作语言来写**。它将动作表示为文本 token（如"移动到 (x, y, z)"），与图像、指令一起输入到统一的 Transformer 模型中，通过自回归方式逐 token 生成动作序列。这样，模型在互联网图文数据上学到的语义知识——比如"杯子是什么""打开抽屉意味着什么"——就能直接迁移到机器人控制中。

### 为什么存在：痛点与历史定位

在 RT-2 出现之前，机器人学习面临一个根本性矛盾：**机器人数据稀缺，而互联网数据丰富**。传统方法（如行为克隆、强化学习）依赖大量机器人演示数据，采集成本极高；而互联网上数以亿计的图文对虽然蕴含丰富的语义知识，却无法直接用于机器人控制。

RT-2 的历史定位正是为了解决这一矛盾。它属于 VLA（Vision-Language-Action）模型家族，其前身 RT-1 已经证明了"用 Transformer 统一视觉-语言-动作"的可行性，但 RT-1 的训练数据仍主要来自机器人演示。RT-2 的突破在于：**将网络规模的视觉-语言知识作为预训练基础，再通过少量机器人数据微调**，从而大幅降低对机器人数据的依赖。

这一思路与同时期的 Unified-IO 2 一脉相承——后者将图像、文本、音频、动作、边界框等多种模态的输入输出 token 化到共享语义空间，由单一编码器-解码器 Transformer 处理，并在 120 个数据集的集成上微调。RT-2 则更聚焦于机器人动作生成这一下游任务。

### 原理拆解

**① 动作即文本：统一 token 空间的建模基础**

RT-2 的底层假设是：机器人的动作可以离散化为有限集合，并映射为文本 token。例如，机械臂的末端位姿变化可以被编码为"移动到 (x, y, z)，旋转 (roll, pitch, yaw)"这样的文本序列。这样，动作生成就变成了一个条件文本生成问题：

$$
p(a_t \mid v_t, l) = \prod_{i=1}^{N} p(t_{a,i} \mid t_{a,<i}, v_t, l)
$$

其中 $v_t$ 为当前视觉观测，$l$ 为语言指令，$t_{a,i}$ 为动作序列的第 $i$ 个 token，$N$ 为动作 token 总数。模型通过最大化条件概率来训练，推理时则用自回归解码逐 token 生成动作。

**② 知识迁移：从 VLM 到 VLA 的权重继承**

RT-2 的关键工程决策是**直接继承预训练 VLM 的权重**。它不从头训练，而是将 PaLI-X 或 PaLM-E 等 VLM 的骨干网络作为初始化，在机器人数据上继续微调。这样，模型在互联网图文上学到的物体识别、空间关系理解、指令跟随等能力被完整保留，只需学习"如何将语义理解映射为动作"这一新映射。

**③ 与 RT-Affordance 的对比：中间表示的选择**

RT-2 直接输出动作 token，而 RT-Affordance 则采用分层架构：先由可供性规划器（affordance planner）根据任务语言生成关键阶段的机器人姿态序列，再由策略执行器（policy executor）以该计划为条件生成具体动作。RT-Affordance 的动机是：直接输出动作的表示在复杂任务中上下文不足，而语言、目标图像等中间表示又存在过度指定问题。可供性（即任务关键阶段机器人姿态）兼具表达力与轻量性，且能通过迁移大规模互联网数据集知识实现高效学习。这两种路径代表了 VLA 设计的两种哲学：**端到端直接映射** vs **分层中间表示**。

HiRT 的对比尤其值得注意：它指出现有 VLA 模型依赖数十亿参数的 VLM 后端，虽具备强大泛化能力，但高计算成本与推理延迟使其主要适用于准静态任务。HiRT 通过分层设计实现灵活的频率-性能权衡——低频运行的 VLM 提取时不变特征，高频视觉策略基于这些特征进行实时交互，在静态任务中保持成功率的同时将控制频率翻倍，在动态操作任务中显著超越基线方法。这揭示了 RT-2 类端到端模型的一个核心局限：**推理延迟与高频控制之间的矛盾**。

### 谁在用：应用案例

RT-2 及其 VLA 家族主要应用于以下场景：

1. **语义泛化操作**：面对未见过的物体或场景，RT-2 能利用互联网图文知识理解"这是什么""应该怎么处理"，从而完成传统方法无法泛化的操作任务。例如，模型在训练中从未见过某个特定品牌的杯子，但通过视觉-语言预训练学到的"杯子"概念，仍能正确抓取。

2. **指令跟随**：用户用自然语言描述任务（如"把红色方块放到蓝色盘子旁边"），RT-2 将语言指令与视觉观测联合编码，生成对应的动作序列。

3. **多任务学习**：RT-2 在多个任务上联合训练，共享同一个模型参数，避免了为每个任务单独训练一个策略的开销。

4. **与分层方法结合**：如 RT-Affordance 所示，可供性规划器可以生成关键姿态序列，再由执行器细化动作——这种分层设计可以弥补 RT-2 直接输出动作在复杂任务中的上下文不足问题。

### 局限与边界

1. **推理延迟**：RT-2 依赖数十亿参数的 VLM 后端，推理延迟高，主要适用于准静态任务。HiRT 的实验数据表明，基线 VLA 模型的推理延迟约为 320ms，而 HiRT 通过分层设计将其降至 50ms（按语料数据推算，HiRT 延迟约为基线的 15.6%）。对于需要高频反馈的动态操作（如抓取移动物体），RT-2 类端到端模型难以胜任。

2. **动作表示的离散化精度**：将连续动作离散化为文本 token 会引入量化误差。动作空间的粒度选择需要在表达力与模型复杂度之间权衡。

3. **数据分布偏移**：RT-2 在互联网图文上预训练，但机器人操作场景的视觉分布与互联网图片存在差异（如视角、光照、背景），可能导致域偏移问题。

4. **缺乏物理一致性保证**：RT-2 生成的动作序列不保证满足动力学约束（如关节力矩极限、摩擦锥约束）。在真实机器人上部署时，需要额外的安全过滤层或后处理优化。

### 常见误区

1. **"RT-2 是通用机器人控制器"**——错。RT-2 是方法而非完整系统，它不包含运动规划、力控制、安全监控等模块。它生成的是高层动作指令，底层执行仍需传统控制栈。

2. **"RT-2 不需要机器人数据"**——错。RT-2 虽然大幅降低了对机器人数据的依赖，但仍需一定量的机器人演示数据进行微调。它真正改变的是**数据效率**，而非彻底摆脱机器人数据。

3. **"VLA 模型可以直接部署到人形机器人"**——错。人形机器人是高维、欠驱动、强耦合系统，RT-2 类模型的动作空间通常针对机械臂设计，直接迁移到人形机器人需要重新定义动作表示并处理全身协调问题。

4. **"动作 token 化与连续控制等价"**——错。离散 token 化会丢失精细的力控信息，对于需要精确力交互的任务（如装配、打磨），RT-2 类方法力有不逮。

## Overview

The RT-2 Vision-Language-Action Model is a VLA approach that transfers web-scale vision-language knowledge to robot control. Built upon vision-language models (VLMs), it represents robot actions directly as text tokens, enabling the model to leverage internet-scale image-text knowledge for semantic understanding and generalized manipulation. What it truly changes is not the robot's ability to "see," but the robot's reasoning chain for "understanding instructions and executing actions"—unifying language, vision, and action within a single autoregressive framework.

The core idea of RT-2 can be summarized in one sentence: **write robot actions as language**. It represents actions as text tokens (e.g., "move to (x, y, z)"), inputs them together with images and instructions into a unified Transformer model, and generates action sequences token by token through autoregression. In this way, the semantic knowledge the model learns from internet image-text data—such as "what a cup is" or "what opening a drawer means"—can be directly transferred to robot control.

### Why It Exists: Pain Points and Historical Positioning

Before RT-2, robot learning faced a fundamental contradiction: **robot data is scarce, while internet data is abundant**. Traditional methods (such as behavioral cloning and reinforcement learning) rely on large amounts of robot demonstration data with extremely high collection costs; meanwhile, the hundreds of millions of image-text pairs on the internet contain rich semantic knowledge but cannot be directly used for robot control.

RT-2's historical positioning is precisely to resolve this contradiction. It belongs to the VLA (Vision-Language-Action) model family. Its predecessor, RT-1, had already demonstrated the feasibility of "unifying vision-language-action with Transformers," but RT-1's training data still came primarily from robot demonstrations. RT-2's breakthrough lies in: **using web-scale vision-language knowledge as the pretraining foundation, then fine-tuning with a small amount of robot data**, thereby greatly reducing dependence on robot data.

This approach shares a lineage with the contemporaneous Unified-IO 2—the latter tokenizes inputs and outputs across multiple modalities (image, text, audio, action, bounding box) into a shared semantic space, processes them with a single encoder-decoder Transformer, and fine-tunes on an ensemble of 120 datasets. RT-2 focuses more specifically on the downstream task of robot action generation.

### Principle Breakdown

**① Action as Text: The Modeling Foundation of a Unified Token Space**

RT-2's underlying assumption is that robot actions can be discretized into a finite set and mapped to text tokens. For example, changes in a robotic arm's end-effector pose can be encoded as text sequences like "move to (x, y, z), rotate (roll, pitch, yaw)". In this way, action generation becomes a conditional text generation problem:

$$
p(a_t \mid v_t, l) = \prod_{i=1}^{N} p(t_{a,i} \mid t_{a,<i}, v_t, l)
$$

where $v_t$ is the current visual observation, $l$ is the language instruction, $t_{a,i}$ is the $i$-th token of the action sequence, and $N$ is the total number of action tokens. The model is trained by maximizing the conditional probability, and during inference, actions are generated token by token via autoregressive decoding.

**② Knowledge Transfer: Weight Inheritance from VLM to VLA**

RT-2's key engineering decision is to **directly inherit the weights of a pretrained VLM**. Rather than training from scratch, it initializes the backbone network from VLMs such as PaLI-X or PaLM-E and continues fine-tuning on robot data. In this way, the object recognition, spatial relationship understanding, and instruction-following capabilities learned from internet image-text data are fully preserved, and the model only needs to learn the new mapping of "how to translate semantic understanding into actions."

**③ Comparison with RT-Affordance: The Choice of Intermediate Representation**

RT-2 directly outputs action tokens, whereas RT-Affordance adopts a hierarchical architecture: first, an affordance planner generates robot pose sequences for key stages based on the task language, and then a policy executor generates concrete actions conditioned on that plan. RT-Affordance's motivation is that direct action-output representations lack sufficient context in complex tasks, while intermediate representations such as language or goal images suffer from over-specification. Affordances (i.e., robot poses at task-critical stages) combine expressiveness with lightweightness and can be learned efficiently by transferring knowledge from large-scale internet datasets. These two paths represent two philosophies of VLA design: **end-to-end direct mapping** vs. **hierarchical intermediate representation**.

### Who Uses It: Application Cases

RT-2 and its VLA family are mainly applied in the following scenarios:

1. **Semantic generalization manipulation**: When facing unseen objects or scenes, RT-2 can leverage internet image-text knowledge to understand "what this is" and "how it should be handled," thereby completing manipulation tasks that traditional methods cannot generalize to. For example, even if the model has never seen a specific brand of cup during training, it can still correctly grasp it through the concept of "cup" learned during vision-language pretraining.

2. **Instruction following**: Users describe tasks in natural language (e.g., "put the red cube next to the blue plate"), and RT-2 jointly encodes the language instruction and visual observation to generate the corresponding action sequence.

3. **Multi-task learning**: RT-2 is jointly trained on multiple tasks, sharing the same model parameters, avoiding the overhead of training a separate policy for each task.

4. **Combination with hierarchical methods**: As demonstrated by RT-Affordance, an affordance planner can generate key pose sequences, which are then refined into actions by an executor—this hierarchical design can compensate for the insufficient context of RT-2's direct action output in complex tasks.

### Limitations and Boundaries

1. **Inference latency**: RT-2 relies on VLM backends with billions of parameters, resulting in high inference latency and making it mainly suitable for quasi-static tasks. Experimental data from HiRT shows that the baseline VLA model has an inference latency of approximately 320ms, while HiRT reduces it to 50ms through hierarchical design (based on corpus data, HiRT's latency is approximately 15.6% of the baseline). For dynamic manipulation requiring high-frequency feedback (such as grasping moving objects), end-to-end models like RT-2 are inadequate.

2. **Discretization precision of action representation**: Discretizing continuous actions into text tokens introduces quantization errors. The granularity of the action space requires a trade-off between expressiveness and model complexity.

3. **Data distribution shift**: RT-2 is pretrained on internet image-text data, but the visual distribution of robot manipulation scenarios differs from internet images (e.g., viewpoint, lighting, background), which may lead to domain shift problems.

4. **Lack of physical consistency guarantees**: The action sequences generated by RT-2 are not guaranteed to satisfy dynamic constraints (such as joint torque limits or friction cone constraints). When deployed on real robots, additional safety filtering layers or post-processing optimization are needed.

### Common Misconceptions

1. **"RT-2 is a general-purpose robot controller"**—Wrong. RT-2 is a method, not a complete system; it does not include motion planning, force control, safety monitoring, or other modules. It generates high-level action commands, while low-level execution still requires a traditional control stack.

2. **"RT-2 does not need robot data"**—Wrong. Although RT-2 greatly reduces dependence on robot data, it still requires a certain amount of robot demonstration data for fine-tuning. What it truly changes is **data efficiency**, not the complete elimination of robot data.

3. **"VLA models can be directly deployed to humanoid robots"**—Wrong. Humanoid robots are high-dimensional, underactuated, and strongly coupled systems. The action space of RT-2-type models is typically designed for robotic arms; direct transfer to humanoid robots requires redefining action representations and addressing whole-body coordination issues.

4. **"Action tokenization is equivalent to continuous control"**—Wrong. Discrete tokenization loses fine-grained force control information. For tasks requiring precise force interaction (such as assembly or polishing), RT-2-type methods fall short.

## 개요

RT-2 비전-언어-동작 모델(RT-2 Vision-Language-Action Model)은 웹 규모의 비전-언어 지식을 로봇 제어로 전이하는 VLA 방법론입니다. 이는 비전-언어 모델(VLM)을 기반으로 구축되어 로봇의 동작을 텍스트 토큰으로 직접 표현함으로써, 모델이 인터넷 수준의 이미지-텍스트 지식을 활용하여 의미론적 이해와 일반화 조작을 수행할 수 있게 합니다. 이것이 진정으로 바꾸는 것은 로봇이 "보는" 능력이 아니라, 로봇이 "지시를 이해하고 동작을 실행하는" 추론 체인입니다. 즉, 언어, 시각, 동작을 동일한 자기회귀 프레임워크로 통합합니다.

## 핵심 내용

### 무엇인가: RT-2의 정확한 정의

RT-2는 **방법론**(method) 유형의 개체에 속하며, 영문 전체 명칭은 *RT-2 Vision-Language-Action Model*, 한국어 명칭은 *RT-2 비전-언어-동작 모델*입니다. 해당 분야 코드는 `07_ai_models_algorithms`이며, 이론적 깊이는 `method` 수준, 상태는 `active`입니다.

개체 분류학의 존재론적 약속에서 RT-2는 **정보 개체(Information Entity)**에 속합니다. 이는 기호와 데이터 형태로 존재하며, 시공간을 차지하지 않고 질량을 가지지 않습니다. `paper`, `algorithm`, `dataset`과 같은 대분류에 속하지만, 더 정확히는 "알고리즘"이 아닌 "방법론"입니다. 이는 단일한 수학적 해법 절차를 제공하는 것이 아니라, 비전-언어 사전 학습 지식을 로봇 동작 출력으로 변환하는 모델링 패러다임을 정의합니다.

RT-2의 핵심 아이디어는 한 문장으로 요약할 수 있습니다: **로봇의 동작을 언어로 작성하는 것**. 이는 동작을 텍스트 토큰(예: "(x, y, z)로 이동")으로 표현하고, 이미지, 지시와 함께 통합 Transformer 모델에 입력하여 자기회귀 방식으로 토큰별 동작 시퀀스를 생성합니다. 이렇게 함으로써 모델이 인터넷 이미지-텍스트 데이터에서 학습한 의미론적 지식(예: "컵이 무엇인지", "서랍을 여는 것이 무엇을 의미하는지")이 로봇 제어에 직접 전이될 수 있습니다.

### 왜 존재하는가: 문제점과 역사적 위치

RT-2가 등장하기 전, 로봇 학습은 근본적인 모순에 직면해 있었습니다: **로봇 데이터는 희소하고, 인터넷 데이터는 풍부하다**는 점입니다. 전통적인 방법(행동 복제, 강화 학습 등)은 대량의 로봇 시연 데이터에 의존하며 수집 비용이 매우 높습니다. 반면 인터넷의 수억 개의 이미지-텍스트 쌍은 풍부한 의미론적 지식을 담고 있지만 로봇 제어에 직접 사용할 수 없습니다.

RT-2의 역사적 위치는 바로 이 모순을 해결하는 데 있습니다. 이는 VLA(Vision-Language-Action) 모델 패밀리에 속하며, 전신인 RT-1은 "Transformer로 비전-언어-동작을 통합하는 것"의 타당성을 입증했지만, RT-1의 훈련 데이터는 여전히 주로 로봇 시연에 의존했습니다. RT-2의 돌파구는 다음과 같습니다: **웹 규모의 비전-언어 지식을 사전 학습 기반으로 삼고, 소량의 로봇 데이터로 미세 조정**하여 로봇 데이터에 대한 의존도를 크게 낮춘 것입니다.

이 접근 방식은 같은 시기의 Unified-IO 2와 맥을 같이합니다. 후자는 이미지, 텍스트, 오디오, 동작, 경계 상자 등 다양한 양식의 입력-출력 토큰을 공유 의미 공간으로 토큰화하고, 단일 인코더-디코더 Transformer로 처리하며, 120개 데이터셋의 통합에서 미세 조정합니다. RT-2는 로봇 동작 생성이라는 하위 작업에 더 초점을 맞춥니다.

### 원리 분석

**① 동작은 곧 텍스트: 통합 토큰 공간의 모델링 기반**

RT-2의 기본 가정은 로봇의 동작이 유한 집합으로 이산화되고 텍스트 토큰으로 매핑될 수 있다는 것입니다. 예를 들어, 로봇 팔의 끝단 자세 변화는 "이동 (x, y, z), 회전 (roll, pitch, yaw)"과 같은 텍스트 시퀀스로 인코딩될 수 있습니다. 이렇게 하면 동작 생성은 조건부 텍스트 생성 문제가 됩니다:

$$
p(a_t \mid v_t, l) = \prod_{i=1}^{N} p(t_{a,i} \mid t_{a,<i}, v_t, l)
$$

여기서 $v_t$는 현재 시각 관측, $l$은 언어 지시, $t_{a,i}$는 동작 시퀀스의 $i$번째 토큰, $N$은 동작 토큰의 총 개수입니다. 모델은 조건부 확률을 최대화하도록 훈련되며, 추론 시에는 자기회귀 디코딩으로 토큰별 동작을 생성합니다.

**② 지식 전이: VLM에서 VLA로의 가중치 상속**

RT-2의 핵심 엔지니어링 결정은 **사전 학습된 VLM의 가중치를 직접 상속**하는 것입니다. 처음부터 훈련하는 것이 아니라 PaLI-X 또는 PaLM-E와 같은 VLM의 백본 네트워크를 초기화로 사용하고 로봇 데이터에서 계속 미세 조정합니다. 이렇게 함으로써 모델이 인터넷 이미지-텍스트에서 학습한 객체 인식, 공간 관계 이해, 지시 따르기 등의 능력이 완전히 보존되며, "의미론적 이해를 동작으로 매핑하는 방법"이라는 새로운 매핑만 학습하면 됩니다.

**③ RT-Affordance와의 비교: 중간 표현의 선택**

RT-2는 동작 토큰을 직접 출력하는 반면, RT-Affordance는 계층적 아키텍처를 채택합니다: 먼저 어포던스 플래너(affordance planner)가 작업 언어를 기반으로 핵심 단계의 로봇 자세 시퀀스를 생성하고, 그다음 정책 실행기(policy executor)가 해당 계획을 조건으로 구체적인 동작을 생성합니다. RT-Affordance의 동기는 직접 동작 출력 표현이 복잡한 작업에서 맥락이 부족하고, 언어나 목표 이미지와 같은 중간 표현은 과도한 지정 문제가 있다는 것입니다. 어포던스(즉, 작업 핵심 단계의 로봇 자세)는 표현력과 경량성을 모두 갖추고 있으며, 대규모 인터넷 데이터셋 지식의 전이를 통해 효율적인 학습이 가능합니다. 이 두 경로는 VLA 설계의 두 가지 철학을 대표합니다: **엔드투엔드 직접 매핑** vs **계층적 중간 표현**.

### 누가 사용하는가: 적용 사례

RT-2 및 VLA 패밀리는 주로 다음 시나리오에 적용됩니다:

1. **의미론적 일반화 조작**: 본 적 없는 객체나 장면에 직면했을 때, RT-2는 인터넷 이미지-텍스트 지식을 활용하여 "이것이 무엇인지", "어떻게 처리해야 하는지"를 이해하고, 전통적인 방법으로는 일반화할 수 없는 조작 작업을 완료할 수 있습니다. 예를 들어, 모델이 훈련 중 특정 브랜드의 컵을 본 적이 없더라도 비전-언어 사전 학습에서 학습한 "컵" 개념을 통해 올바르게 집을 수 있습니다.

2. **지시 따르기**: 사용자가 자연어로 작업을 설명하면(예: "빨간 블록을 파란 접시 옆에 놓아라"), RT-2는 언어 지시와 시각 관측을 결합하여 인코딩하고 해당 동작 시퀀스를 생성합니다.

3. **다중 작업 학습**: RT-2는 여러 작업에서 공동 훈련하며 동일한 모델 매개변수를 공유하므로, 각 작업마다 별도의 정책을 훈련하는 비용을 피할 수 있습니다.

4. **계층적 방법과의 결합**: RT-Affordance에서 볼 수 있듯이, 어포던스 플래너가 핵심 자세 시퀀스를 생성하고 실행기가 동작을 세분화할 수 있습니다. 이러한 계층적 설계는 RT-2가 직접 동작을 출력할 때 복잡한 작업에서 발생하는 맥락 부족 문제를 보완할 수 있습니다.

### 한계와 경계

1. **추론 지연**: RT-2는 수십억 매개변수의 VLM 백엔드에 의존하여 추론 지연이 높으며, 주로 준정적 작업에 적합합니다. HiRT의 실험 데이터에 따르면 기준 VLA 모델의 추론 지연은 약 320ms인 반면, HiRT는 계층적 설계를 통해 이를 50ms로 낮췄습니다(말뭉치 데이터 기준, HiRT 지연은 기준의 약 15.6%). 고주파 피드백이 필요한 동적 조작(예: 움직이는 물체 집기)에서는 RT-2 유형의 엔드투엔드 모델이 적합하지 않습니다.

2. **동작 표현의 이산화 정밀도**: 연속 동작을 텍스트 토큰으로 이산화하면 양자화 오류가 발생합니다. 동작 공간의 세분화 수준 선택은 표현력과 모델 복잡성 사이의 균형이 필요합니다.

3. **데이터 분포 이동**: RT-2는 인터넷 이미지-텍스트에서 사전 학습되지만, 로봇 조작 장면의 시각 분포는 인터넷 이미지와 차이가 있습니다(예: 시점, 조명, 배경). 이로 인해 도메인 이동 문제가 발생할 수 있습니다.

4. **물리적 일관성 보장 부재**: RT-2가 생성하는 동작 시퀀스는 동역학 제약(관절 토크 한계, 마찰 원뿔 제약 등)을 충족한다는 보장이 없습니다. 실제 로봇에 배포할 때는 추가적인 안전 필터 계층이나 후처리 최적화가 필요합니다.

### 일반적인 오해

1. **"RT-2는 범용 로봇 컨트롤러다"** — 틀렸습니다. RT-2는 완전한 시스템이 아닌 방법론이며, 운동 계획, 힘 제어, 안전 모니터링 등의 모듈을 포함하지 않습니다. 이는 고수준 동작 지시를 생성하며, 저수준 실행은 여전히 전통적인 제어 스택이 필요합니다.

2. **"RT-2는 로봇 데이터가 필요 없다"** — 틀렸습니다. RT-2는 로봇 데이터에 대한 의존도를 크게 낮추었지만, 여전히 일정량의 로봇 시연 데이터로 미세 조정이 필요합니다. 이것이 진정으로 바꾸는 것은 **데이터 효율성**이며, 로봇 데이터를 완전히 없애는 것이 아닙니다.

3. **"VLA 모델을 휴머노이드 로봇에 직접 배포할 수 있다"** — 틀렸습니다. 휴머노이드 로봇은 고차원, 저구동, 강결합 시스템이며, RT-2 유형 모델의 동작 공간은 일반적으로 로봇 팔을 위해 설계되었습니다. 휴머노이드 로봇으로 직접 전이하려면 동작 표현을 재정의하고 전신 조정 문제를 처리해야 합니다.

4. **"동작 토큰화와 연속 제어는 동등하다"** — 틀렸습니다. 이산 토큰화는 정밀한 힘 제어 정보를 잃게 되며, 정밀한 힘 상호작용이 필요한 작업(조립, 연마 등)에서는 RT-2 유형 방법이 역부족입니다.
