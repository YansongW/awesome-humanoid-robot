# 2단계: 이족 보행 플랫폼 – 시뮬레이션에서 첫 번째 걷는 로봇까지

이족 보행(biped)은 '휴머노이드'의 핵심이자, 0→1 단계에서 가장 높은 확률로 실패하는 부분입니다. 이 단계의 목표: 오픈소스 이족/바퀴형 플랫폼을 선택하고, 먼저 시뮬레이션에서 제어 스택을 실행한 후, 실제 하드웨어를 제작하여 평지에서 안정적으로 보행하는 것입니다. 모든 계획 데이터는 [공개 조사 아카이브](https://github.com/YansongW/awesome-humanoid-robot/tree/main/data/roadmap/research/) (접속일 2026-07-01, 각 항목별 출처 표기)에서 가져왔습니다.

## 1. 시뮬레이션 우선: 하드웨어 없이 제어 스택 실행

**무엇을 할까**: 모터 하나를 구매하기 전에, 컴퓨터에 물리 시뮬레이터를 설치하고 이족 보행 모델의 기립과 보행을 실행합니다. 두 가지 주요 경로:

- [MuJoCo](/entry/ent_software_mujoco_physics_engine_2022/): 가볍고 무료이며, 노트북으로도 실행 가능. OpenLoong의 [OpenLoong-Dyn-Control](https://github.com/loongOpen/OpenLoong-Dyn-Control/blob/main/README-zh.md)은 MuJoCo에 배포된 MPC + WBC 전신 제어 프레임워크로, 보행/점프/맹목 장애물 밟기 예제를 포함합니다 – 하드웨어 코드 한 줄 작성하지 않고도 전체 크기 휴머노이드의 고전적 제어 파이프라인을 학습할 수 있습니다 (출처: openloong-qinglong.md).
- [Isaac Lab](/entry/ent_software_nvidia_isaac_lab_2024/): GPU 대규모 병렬 시뮬레이션, 강화 학습 훈련에 적합, NVIDIA 그래픽 카드 필요. Berkeley Humanoid Lite의 디렉토리는 Isaac Lab에 따라 구성되어 있으며, URDF/MJCF/USD 세 가지 형식을 모두 제공합니다 (출처: berkeley-humanoid-lite.md).

**왜**: 이족 보행 복제 실패의 가장 큰 원인은 조립이 아니라 "하드웨어는 조립했지만 제어가 작동하지 않아 전원을 켜자마자 넘어지는" 경우입니다. 시뮬레이션은 "알고리즘 오류"와 "하드웨어 오류"를 분리하여, 실제 기계에서는 하드웨어 차원만 확인하면 됩니다. 시뮬레이터 선정에 대한 자세한 내용은 [제23장 시뮬레이션 및 물리 엔진](/wiki/chapters/chapter-23/)을 참조하세요.

**당신의 상황 분석**: NVIDIA 그래픽 카드 없음, 예산 제로 → MuJoCo + OpenLoong-Dyn-Control, 비용 없이 MPC+WBC 본 과정 학습. RTX 그래픽 카드 보유, RL 경로 선택 → Isaac Lab 설치, 이후 Berkeley 선택 시 훈련 환경이 매끄럽게 연결됨. 순수 Python 배경 → `pip install upkie`로 PyBullet에서 균형 예제 실행 (출처: upkie.md), 당일 긍정적 피드백 가능.

## 2. 균형 이론 사다리: 순서대로 학습, 건너뛰지 말 것

이족 보행 균형은 사다리와 같으며, 각 단계마다 하나의 카드가 있고, 시뮬레이션에서 한 단계를 검증한 후 다음 단계로 올라갑니다.

**1단계: ZMP (영점 모멘트 점)**
- 무엇을 할까: [Zero Moment Point](/entry/ent_method_zero_moment_point/) 이해 – 로봇이 넘어지지 않기 위한 필요충분조건은 지면 반력의 등가 작용점이 지지 다각형 내에 있는 것. 시뮬레이션에서 ZMP가 지지 영역을 벗어날 때와 로봇이 넘어질 때를 관찰.
- 왜: ZMP는 이족 보행 안정성의 가장 고전적인 판단 기준이며, 이후 보행 계획은 모두 "ZMP 제어"에 기반. 배경은 [제14장 로봇 제어 기초](/wiki/chapters/chapter-14/) 및 [제15장 운동 생성 및 Locomotion](/wiki/chapters/chapter-15/) 참조.
- 당신의 상황 분석: 바퀴형(Upkie) 경로도 학습 필요 – 지지 다각형을 두 바퀴 접지점 연결선으로 대체하면 됨.

**2단계: 보행 계획 (Gait Planning)**
- 무엇을 할까: [보행 계획](/entry/ent_method_gait_planning/) 학습: 목표 속도가 주어졌을 때, 스윙 발 착지점, 지지/스윙 위상 전환 타이밍 및 질량 중심 궤적을 생성하는 방법. 입문 고전은 LIPM (선형 도립 진자 모델) + 포착점 분석.
- 왜: 보행 계획은 의사 결정 계층(발을 어디에 디딜지), MPC/WBC는 실행 계층(관절에 힘을 어떻게 가할지); 계층화해야 "방향이 틀어졌을 때" 착지점 오류인지 힘 제어 문제인지 파악 가능.
- 당신의 상황 분석: RL 경로는 개념 이해만으로 충분 – 정책이 스스로 착지점 학습; MPC 경로는 반드시 완전히 이해해야 함.

**3단계: MPC (모델 예측 제어)**
- 무엇을 할까: [모델 예측 제어](/entry/ent_method_model_predictive_control/) 이해: 각 단계마다 단순화된 동역학을 사용하여 미리 시간 창을 예측하고, 최적화 문제를 풀며, 첫 번째 단계만 실행하고, 롤링 방식으로 진행. OpenLoong의 MuJoCo 예제에서 가중치를 변경하여 보행 품질 변화 관찰.
- 왜: MPC는 제약 조건(발 미끄러짐 방지, 토크 제한)을 명시적으로 처리하며, 고동적 이족 보행의 주류 실제 기계 방식 – BRUCE는 가변 주기 MPC로 보행/달리기/점프 구현 (출처: bruce-westwood.md).
- 당신의 상황 분석: 수학적 기초 충분 → MPC 상한선 최고; 수학적 기초 보통 → 수동 MPC 생략, 직접 RL 경로 사용.

**4단계: 전신 제어 WBC (Whole-Body Control)**
- 무엇을 할까: [전신 제어](/entry/ent_method_whole_body_control/) 이해: 전신 관절 토크를 작업 우선순위가 있는 2차 계획법(QP)으로 해결 – 먼저 넘어지지 않고 발이 미끄러지지 않도록 보장, 남은 여유를 팔 등 부차적 작업에 할당.
- 왜: 수십 자유도의 휴머노이드에서 단일 관절 PID는 결합 동역학을 제어할 수 없음; MPC의 출력은 WBC에 의해 각 관절에 할당됨 (OpenLoong은 MPC+WBC 아키텍처).
- 당신의 상황 분석: RL 경로는 유도 깊이 파고들지 않아도 되지만, sim-to-real 문제 해결 시 기대 토크와 실제 토크의 차이는 중요한 진단 신호.

**5단계: RL 경로**
- 무엇을 할까: [PPO](/entry/ent_algorithm_ppo/) + [도메인 무작위화](/entry/ent_method_domain_randomization/) + [sim-to-real](/entry/ent_method_sim_to_real/) 조합: 시뮬레이션에서 PPO로 보행 정책 훈련, 훈련 시 마찰, 질량, 모터 지연 등 파라미터를 무작위화한 후, 제로샷으로 실제 기계에 배포. ToddlerBot (MuJoCo/MJX + PPO) 및 Berkeley Humanoid Lite (Isaac Lab)은 모두 이 경로의 오픈소스 완전 구현체입니다 (출처: 각각의 조사 아카이브).
- 왜: RL은 수동 모델링 및 파라미터 튜닝의 과중한 작업을 우회하며, 이 두 기계에서 "개인 재현 가능"함이 검증됨. sim2real 격차의 본질은 "모델링하지 않은 물리 부분"이며, 도메인 무작위화는 정책이 이에 둔감하게 만듦.
- 당신의 상황 분석: GPU 보유, ML 배경 → 주 경로, ToddlerBot 또는 Berkeley 우선; GPU 없음 → 클라우드 컴퓨팅 임대 훈련, 또는 MPC 경로로 복귀 (OpenLoong 예제는 CPU로 실행 가능).

## 4. 복제 프로세스 분해

문서가 완비된 플랫폼(ToddlerBot / Berkeley)을 템플릿으로, 총 8단계, 각 단계는 "액션 → 원리 → 자기 분석".

**Step 1 구매 목록(BOM) 확인**: 공식 BOM에서 주문하고 수령 가격과 납기 기록(Berkeley 기술 보고서는 미국/중국 두 가지 BOM 제공, 중국은 중국 기준으로 조달). 모터와 컴퓨터가 비용의 대부분(ToddlerBot의 90%)을 차지하므로, 예산 삭감은 적절한 곳에서 해야 함. BOM에 명시되지 않은 사양의 대체품은 공급업체에 매개변수 확인 필요.

**Step 2 3D 프린팅 구조 부품**: 공식 파일로 프린팅(ToddlerBot은 MakerWorld, Berkeley는 GitHub Releases); 사이클로이드 기어는 일반 데스크탑 FDM + PLA로 충분(공식 60시간 내구성 테스트 완료)——구조 정밀도가 백래시를 결정하고, 백래시가 크면 힘 제어 떨림 발생, 임의로 재료 변경 금지. 프린터가 없으면 온라인 프린팅 서비스 이용, 기능 부품은 공식과 동일한 충전율/재료 지정.

**Step 3 기계 조립**: 모듈별 조립(한쪽 다리 → 한쪽 팔 → 몸통 → 최종 조립), 각 모듈 조립 후 수동으로 원활함과 간섭 확인, 최종 조립 후 몇 배의 재작업 방지. 손재주가 적으면 서보 버스 플랫폼 선택(나사 조임 및 케이블 연결 위주); 자체 개발 액추에이터에 도전한다면, 먼저 6512 한 대를 무부하 테스트 통과 후 22대批量 생산.

**Step 4 영점 보정 및 시스템 식별(sysID)**: 프린팅 지그로 각 관절을 기계적 영점에 맞추고 오프셋 기록; 동일 모델 모터는 한 번 sysID 수행, 매개변수를 시뮬레이션 모델에 반영. 이것이 sim-to-real의 기초——ToddlerBot의 디지털 트윈 방식(지그 1분 보정 + 동일 모델 모터 1회 sysID)이 제로샷 전이의 핵심. sysID를 건너뛰면 "시뮬레이션은 안정적, 실제 로봇은 떨림" 현상 발생.

**Step 5 시뮬레이션 정렬**: 측정된 질량, 무게 중심, 영점, 모터 매개변수를 모두 URDF/MJCF에 반영하고, 보행 전략 재실행하여 시뮬레이션에서 여전히 안정적인지 확인(MPC 가중치 재조정 / RL 필요시 재훈련)——가공 오차로 실제 로봇은 설계도와 다르므로, 정렬은 이를 인정하고 명시화하는 것. RL 방식은 ±10% 질량 오차에 덜 민감하고, MPC 방식은 더 세심해야 함.

**Step 6 첫 전원 공급(Smoke Test)**: 걸이대에 매달기(양발 지면 이탈) → 비상 정지 회로 검증 → 관절별로 소폭 정현파 스윙 가능하게 함 → 온도, 전류, 통신 확인. 전기적 오류는 이 단계에서 집중적으로 드러나며, 매달린 상태에서는 어떤 제어 불능도 추락 없음; 비상 정지는 이때 반드시 유효성 확인. 두 명 작업: 한 명은 인터페이스 모니터링, 한 명은 비상 정지 담당.

**Step 7 서기**: 걸이대 점진적 하중 제거 → 양발 지면 접촉 정적 서기 → 무게 중심 소폭 흔들기 및 가벼운 밀기 회복 추가. 서기는 걷기의 부분 집합——서기 제어 루프(발목/엉덩이 전략) 조정 완료 시, 걷기는 단지 평형점을 지지 영역 밖으로 주기적으로 이동시켜 포착하는 것. RL 방식에서 이 단계가 실패하면 Step 4/5로 돌아가 보정 정렬 확인, 실제 로봇에서 보상 함수를 억지로 튜닝하지 말 것.

**Step 8 걷기**: 제자리 걷기 → 직선 → 회전 → 정해진 시간 연속 걷기, 배터리 전압, 모터 온도, 넘어짐 횟수 기록. 작동 시간은 파일 기준으로 관리: ToddlerBot RL 보행 실제 19분(과열로 주파수 낮춤까지), Berkeley 6S 4000 mAh LiPo 약 30분, BRUCE 약 20분——동등 수준 도달 시 정상.

## 5. 승인 기준

모든 기준 통과 시 다음 단계 진입 가능:

1. **시뮬레이션 관문**: 선택한 플랫폼 공식 예제(또는 자체 훈련 전략)가 MuJoCo/Isaac Lab에서 시뮬레이션 시간 10분 연속 보행 중 넘어지지 않고, 무작위 외부 힘 교란 후 회복 가능.
2. **서기 관문**: 실제 로봇이 걸이대 없이 완전 하중 정적 서기 ≥ 5분, 각 관절 모터 온도가 공식 한계 미만(명시되지 않은 모델은 공급업체에 확인 필요).
3. **걷기 관문**: 평평한 단단한 지면에서 연속 보행 ≥ 10분, 넘어짐 없음, 현저한 편향 없음(누적 요 < 90°).
4. **교란 저항 관문**: 보행/서기 중 한 손으로 가볍게 밀기(약 5–10 N, 0.5 s 이내) 후 균형 회복, 넘어지지 않음, 보호적 종료 상태 진입 없음.
5. **보호 관문**: 걸이대 보호 하에 인위적으로 넘어짐 상황 유발, 비상 정지 및 낙하 보호 작동——지면 접촉 전 관절 힘 해제 또는 댐핑 모드 진입, 구조 부품 파손 없음(참조: ToddlerBot은 약 7회 추락 견딤, 수리는 21분 프린팅 + 14분 조립만 필요).
6. **안전 관문**: 비상 정지 버튼 누름부터 동력 차단까지의 응답 시간 시연 가능; 배터리 충전 및 보관全程 리튬 배터리 안전 규정 준수.

## 6. 안전 수칙

하나라도 충족되지 않으면 실제 기기에 전원을 공급하지 마십시오:

- **비상 정지(E-Stop)**: 소프트웨어 체인과 독립적인 하드웨어 수준의 [비상 정지 시스템](/entry/ent_component_emergency_stop_system_2024/)이 필수입니다. 버튼을 누르면 메인 컨트롤러를 거치지 않고 물리적으로 모터 동력을 차단합니다. BRUCE에는 독립적인 무선 비상 정지 장치가 탑재되어 있습니다(출처: bruce-westwood.md). 자체 복제 플랫폼은 최소한 유선 비상 정지 장치를 작업자 손이 닿는 곳에 두어야 합니다.
- **거치대/보호 프레임**: 최초 전원 공급, 기립, 보행의 세 가지 단계는 반드시 거치대 또는 상부 보호 로프 아래에서 수행해야 합니다. 3.4kg의 ToddlerBot도 넘어지면 수리가 필요하며, 16kg의 Berkeley가 쓰러지면 사람과 장비 모두 손상될 수 있습니다. 디버깅 시 손가락이 기어 맞물림 영역과 관절 가동 범위에 닿지 않도록 하고, 모터를 활성화하기 전에 아무도 로봇에 접촉하지 않았는지 확인하십시오.
- **리튬 배터리 안전**: LiPo는 데스크탑급 휴머노이드에서 가장 큰 화재 위험 요소입니다. 충전 시 반드시 상주 감시가 필요하며, 방폭 백/내화 용기를 사용해야 합니다. 과방전, 팽창, 낙하된 배터리는 즉시 폐기하며, 규격은 [리튬 배터리 기술 카드](/entry/ent_tech_li_battery_humanoid/)를 참조하십시오. 6S 4000mAh와 같은 대용량 배터리의 단락 에너지는 데스크탑 주변 물품을 점화하기에 충분하므로, 배선 전에 극성을 다시 한번 확인하십시오.

## 7. 일반적인 문제점 및 점검

| 증상 | 가능한 원인 | 점검 조치 |
|---|---|---|
| 시뮬레이션에서는 안정적이나 실제 기기에서 떨리거나 넘어짐(sim-to-real gap) | 영점 보정 오차; sysID 미수행; 질량/마찰 모델링 편차 | 지그 교정 및 시스템 식별 재수행; URDF/MJCF 질량과 실제 측정값 대조; RL 방식의 [도메인 무작위화](/entry/ent_method_domain_randomization/) 범위를 확대하여 재훈련 |
| 보행 몇 분 후 보행이 약해지고 성능 저하 | 액추에이터 과열로 인한 클럭 저하(ToddlerBot 실제 측정 시 19분 만에 과열 클럭 저하 발생) | 모터 온도 원격 측정값 확인; 연속 작동 시간 단축 또는 방열 추가; 장시간 피크 토크 영역에서 작동 중인지 확인 |
| 정지 상태에서 한쪽으로 천천히 기울어짐 | [IMU](/entry/ent_component_imu_2024/) 영점 편차 드리프트; 자세 필터 발산 | 30초간 정지 후 자세 판독값 드리프트 여부 확인; 영점 보정 재수행; 필터 공분산 매개변수 확인 |
| 관절 고주파 떨림, 윙윙거리는 소음 | 게인 과다; 백래시 큼; 버스 패킷 손실로 인한 피드백 지연 | 게인 낮추고 재측정; 관절 수동 회전으로 백래시 감지; 패킷 손실률 통계(기준: ToddlerBot 50Hz, Berkeley 250Hz CAN) |
| 보행 명령 시 즉시 앞으로 넘어짐 | 착지점 계획이 질량 중심보다 지연됨; 지지/스윙 위상 전환 타이밍 오류 | 먼저 시뮬레이션에서 동일 명령 재현; [보행 계획](/entry/ent_method_gait_planning/)과 대조하여 착지점과 ZMP 궤적 동기화 확인 |
| 넘어진 후 동일 구조 부품 반복 파손; 배터리 지속 시간이 문서상 수치보다 현저히 낮음 | 구형 출력 부품 사용; 배터리 노후화; 특정 관절 지속적 대전류 | 저장소의 최신 출력 부품 및 변경 로그 확인; 배터리 내부 저항 측정; 각 관절 전류 분포 확인으로 이상 관절 식별 - 일반적으로 조립 과도한 조임 또는 보정 오류 |
