# M06 · 펌웨어와 캘리브레이션: 쇳덩이가 처음으로 명령을 이해하게 하기

**전체 위치**: M05 조립 완료 후, M07 벤치 테스트 전. 입력은 조립되었지만 아직 "지능화"되지 않은 관절 모듈이고, 출력은 **통신 가능하고, 캘리브레이션 완료되었으며, 세 루프가 조정된 관절 모듈**입니다. M07은 이를 벤치에 올려 데이터로 다리에 장착할 자격이 있는지 결정합니다. 이 페이지는 [1단계 개요](../stage-1-actuator.md)의 6단계(폐루프 제어 계단)를 단계별로 상세히 설명합니다.

**전제 조건**: M05 조립 승인 완료(전 구간 걸림 없음, 무부하 전류 정상); 드라이버 보드, 모터, 엔코더, 케이블 번들 준비 완료; 컴퓨터에 드라이버 보드 전용 상위 툴 설치 완료.

이론 배경: [FOC(자계 방향 제어)](/entry/ent_method_foc_motor_control/), [PID 제어](/entry/ent_method_pid_control/), [전류-속도-위치 세 루프 종속 연결](/entry/ent_principle_current_velocity_position_loops/) 카드, 교과서는 [제4장 액추에이터](/wiki/chapters/chapter-04/) 및 [제14장 로봇 제어 기초](/wiki/chapters/chapter-14/) 참조.

## 1단계: 펌웨어 플래싱 및 버전 고정

【무엇을 할까】펌웨어는 M04에서 선택한 드라이버 보드에 따라 결정되며, 해당 보드에 맞게 선택합니다:

| 드라이버 보드 | 펌웨어 경로 | 비고 |
|---|---|---|
| ST B-G431B-ESC1 | Berkeley Humanoid Lite 오픈 소스 FOC 펌웨어 | 보드 $19; 실제 로봇 저수준 코드는 해당 저장소 `berkeley_humanoid_lite_lowlevel` 하위 디렉토리(C 언어, 훈련 스택과 독립적——`data/roadmap/research/berkeley-humanoid-lite.md`) |
| ODrive | ODrive 공식 펌웨어 + odrivetool | Berkeley 방식은 ODrive / moteus / VESC와도 호환 가능(조사 파일) |
| moteus | moteus 공식 펌웨어 + tview | 펌웨어와 상위 툴 버전이 일치해야 함 |

플래싱 세 가지 작업을 순서대로 수행:

1. 툴체인 설치(ST 계열은 ST-Link + STM32CubeProgrammer 또는 DFU 모드 사용; 먼저 bootloader 진입 가능 여부와 칩 정보 읽기 가능 여부 확인);
2. 플래싱 후 **즉시 펌웨어 버전/커밋 기록**——전체 22대의 액추에이터(Berkeley 구성은 6512×10대 + 5010×12대, 조사 파일)는 동일한 버전을 플래싱해야 함. 버전 혼용 = 통신 프로토콜 및 기본 매개변수 불일치;
3. 출고 기본 매개변수 백업(덤프하여 파일로 저장), 조정 실패 시 원클릭 복원 가능.

【왜】펌웨어는 드라이버 보드의 "운영 체제"입니다: FOC 정류, 세 루프 계산, CAN 프로토콜 스택이 모두 포함됩니다. 버전 혼용은 대량 디버깅에서 가장 교묘한 함정입니다——현상은 "이 관절은 말을 잘 듣는데 저 관절은 안 듣는다"이며, 3일 후에야 펌웨어가 두 커밋 차이인 것을 발견합니다.

【당신의 상황 분석】Berkeley 방식을 그대로 따르세요: 해당 문서에서 지정한 펌웨어 버전을 사용하고, main 브랜치의 최신 커밋을 따라가지 마세요. 자체 개발 펌웨어: "컴파일 가능, 플래싱 가능, 버전 읽기 가능"을 스크립트로 고정하세요. 22대 양산 시 자신에게 감사할 것입니다.

## 2단계: 모터 매개변수 입력——하나만 잘못 입력해도 전체가 실패

【무엇을 할까】각 모터에 대해 네 가지 핵심 매개변수를 입력하고, 매개변수 등록표에 기록합니다(동일 모델의 모터도 개체 차이가 있으므로 각각 등록):

| 매개변수 | 획득 방법 | 잘못 입력 시 결과 |
|---|---|---|
| 극 쌍 수 | 자석 수 세기: 극 쌍 수 = 자석 조각 수 ÷ 2; 또는 모터 매뉴얼 확인 | 정류 오류——윙윙거림, 회전 안 함 또는 불규칙한 떨림 |
| 상 저항 R | 매뉴얼 값; 또는 밀리옴 미터/LCR 미터로 선간 저항 측정 ÷ 2(성형 결선) | 전류 루프 이득 불일치 |
| 상 인덕턴스 L | 매뉴얼 값; 또는 LCR 미터(1 kHz 대역)로 선간 인덕턴스 측정 ÷ 2 | 전류 루프 자동 튜닝 실패 |
| KV 값 | M02 선정 시 결정된 매뉴얼 값 | 속도 피드포워드 및 최고 속도 추정 모두 오류 |

계산 예(성형 결선 환산): 임의의 두 상 간 선간 저항 0.20 Ω 측정 시, 상 저항 = 0.20 ÷ 2 = 0.10 Ω; 선간 인덕턴스도 동일하게 2로 나눕니다.

【왜】이 네 가지 숫자는 FOC의 "신분증 정보"입니다: 극 쌍 수는 전기각과 기계각의 변환을 결정하고(전기각 = 기계각 × 극 쌍 수), R/L은 전류 루프 이득의 물리적 크기를 결정하며, KV는 속도-전압 매핑을 결정합니다. 드라이버 보드의 자동 튜닝도 본질적으로 이 숫자들을 추정하는 것입니다——추정값은 매뉴얼/실측값과 반드시 대조해야 하며, 한 자릿수 차이가 나면 배선 또는 측정에 문제가 있음을 의미합니다.

【당신의 상황 분석】드론 [브러시리스 DC 모터](/entry/ent_component_bldc_motor/)(예: Berkeley가 사용하는 MAD M6C12 150KV, $129, 조사 파일) 매뉴얼에는 R/L이 없는 경우가 많습니다: 100달러대 LCR 미터를 구매할 가치가 있습니다; 없으면 드라이버 보드의 자동 튜닝 값을 사용하되, 등록표에 "출처: 자동 튜닝, 재측정 안 함"이라고 표시하고, M07의 Kt 캘리브레이션이 검증을 대신해 줄 것입니다.

## 3단계: 엔코더 오프셋 캘리브레이션——전기각 영점과 기계적 영점 정렬

【무엇을 할까】FOC는 정류를 위해 고정자에 대한 회전자 자극의 정확한 각도를 알아야 하지만, [관절 엔코더](/entry/ent_component_joint_encoder_2024/)를 장착할 때 영점은 무작위입니다. 자동 캘리브레이션 원리: 드라이버 보드가 느리게 회전하는 개루프 전류 벡터를 주입하면, 회전자가 전자기 토크에 의해 "끌려" 회전하며, d축에 정렬될 때 엔코더 판독값을 기록합니다——이것이 오프셋(offset)입니다. 캘리브레이션 후 반드시 **플래시에 저장**하고, 전원을 껐다 켠 후 판독값이 여전히 있는지 확인합니다.

검증 기준(엔지니어링 권장 값, 드라이버 보드 매뉴얼에 따라 확인 필요): 연속 5회 전원 재인가 후 재캘리브레이션 시, 오프셋 드리프트 < 5° 전기각. 드리프트가 기준을 초과하면 자석 또는 엔코더 설치에 문제가 있는 것이므로, 매개변수 조정으로 해결 불가능, M05로 돌아가 조립 상태 확인.

【왜】오프셋이 조금만 틀려도 모터는 여전히 회전하지만, 출력 토크는 약 cos(오프셋 오차 각도)만큼 감소하고, 추가 전류는 모두 열로 변합니다; 90° 전기각까지 틀리면 모터가 전혀 힘을 내지 못합니다. 매 전원 인가 시 오프셋이 드리프트하면, 매일 낯선 모터를 켜는 것과 같습니다.

【당신의 상황 분석】캘리브레이션 실패/오프셋 불규칙 점프 시 확인 순서: 엔코더 원시 판독값이 깨끗한지(모터를 손으로 돌려 판독값이 단조 증가하는지 확인) → 자석과 칩의 동축도 → 캘리브레이션 전류가 충분한지(회전자를 끌지 못하면 캘리브레이션 전류를 증가시키되, 상 전류 정격을 초과하지 않도록 주의). 자기 엔코더는 설치 동축도와 상선 전자기 간섭에 민감하므로([제5장 센싱 및 지각 하드웨어](/wiki/chapters/chapter-05/)), 엔코더 케이블은 대전류 상선에서 멀리 떨어뜨리세요.

## 4단계: 세 루프 튜닝 계단——내부에서 외부로, 단계별 길들이기

【무엇을 할까】엄격히 **전류 루프 → 속도 루프 → 위치 루프** 순서로 튜닝하고, 각 단계는 계단 응답으로 검증 통과 후 다음 단계로 진행합니다. 대역폭은 5–10배씩 감소시킵니다([세 루프 종속 연결](/entry/ent_principle_current_velocity_position_loops/) 카드의 원칙): 내부 루프는 외부 루프보다 훨씬 빨라야 하며, 그래야 외부 루프가 내부 루프를 "이상적인 액추에이터"로 간주할 수 있습니다.

1. **전류 루프**: R/L로 이득을 추정하거나, 드라이버 보드의 자동 튜닝을 직접 사용합니다. 극점 배치 추정식(엔지니어링 일반 시작점, 드라이버 보드 매뉴얼에 따라 확인 필요):

   ```
   L = 0.05 mH = 0.00005 H, R = 0.10 Ω, 목표 대역폭 fc = 500 Hz
   ωc = 2π × fc = 2π × 500 ≈ 3142 rad/s
   Kp_i = L × ωc = 0.00005 × 3142 ≈ 0.16
   Ki_i = R × ωc = 0.10 × 3142 ≈ 314
   ```

   계단 응답 검증: 정격의 30–50% 전류 계단 인가, 상승 시간(ms 단위)과 링잉 확인——링잉이 많으면 대역폭 감소.

2. **속도 루프**: 대역폭은 전류 루프의 1/5–1/10로 설정(위 예시 500 Hz → 50–100 Hz, 엔지니어링 권장 값). 정격의 20% 작은 속도 계단으로 검증; 이득 과다의 전형적인 증상은 모터 고주파 울음(고주파 윙윙거림)이며, 즉시 이득 감소.
3. **위치 루프**: 대역폭을 다시 5–10배 감소(10–20 Hz 수준, 엔지니어링 권장 값). 30° 계단 응답 검증: 오버슈트 < 10%, 정상 상태 오차 < 0.5°([1단계 개요](../stage-1-actuator.md) 기준과 일치, M07에서 부하 상태 재측정). 오버슈트가 크면 P를 바로 낮추지 말고——**속도 피드포워드**를 추가하는 것이 근본적인 해결책인 경우가 많습니다: 위치 명령이 변경될 때 동기적으로 속도 명령을 피드포워드하면, 오차가 누적되기 전에 상쇄됩니다.

【왜】세 루프 종속 연결의 물리적 의미: 전류 루프는 "얼마나 많은 힘을 낼지"(토크 ∝ 전류), 속도 루프는 "얼마나 빨리 회전할지", 위치 루프는 "어디에 멈출지"를 담당합니다. 외부 루프 대역폭이 내부 루프를 초과하면, 근시안적인 사람이 현미경을 지휘하는 것과 같아——필연적으로 진동합니다. 이것은 [PID 제어](/entry/ent_method_pid_control/)를 종속 연결 구조에서 사용하는 표준 방법이며, 이론은 [제14장 로봇 제어 기초](/wiki/chapters/chapter-14/) 참조.

【당신의 상황 분석】드라이버 보드에 전류 루프가 내장된 경우(Berkeley 펌웨어, ODrive, moteus 모두 내장): 당신의 작업은 주로 속도 루프와 위치 루프입니다. 오실로스코프가 없는 경우: 상위 툴의 파형 기록 기능(tview / odrivetool / 사용자 정의 로그)으로 충분하며, 샘플링 속도는 최소한 테스트 대상 루프 대역폭의 10배 이상이어야 합니다. 서보 모터 경로는 세 루프가 내부에 폐쇄되어 있으므로, 이 단계는 "매뉴얼을 읽고 레지스터를 조정하는" 것으로 축소됩니다.

## 5단계: 통신 네트워킹 및 파라미터 아카이빙

【수행할 작업】

1. **CAN ID 할당**: 각 장치를 개별적으로 전원을 켜고, 기본 ID를 할당표의 고유 ID로 변경한 후 라벨(관절명 + ID)을 부착합니다. 모든 변경이 완료된 후 네트워킹합니다. 할당표는 "왼쪽 엉덩이 pitch = 0x01" 형식으로 문서화합니다.
2. **통일된 보레이트**: 전체 네트워크에 동일한 속도를 적용합니다. 참고값: Berkeley는 CAN 2.0 @ 1 Mbps를 사용하며, 각 사지에 하나의 버스, USB-CAN 어댑터를 통해 메인 컨트롤러에 연결, 단일 버스 최대 64개 장치(조사 문서 기준).
3. **송수신 테스트**: 상위 컴퓨터가 250 Hz로 전체 네트워크 관절에 대해 송수신을 수행합니다(Berkeley 액추에이터 및 IMU 통신 250 Hz 기준, 조사 문서 참조). 1시간 연속으로 끊김 없음, 오류 프레임 급증 없음이 통과 기준입니다(판단 기준은 [1단계 개요](../stage-1-actuator.md)와 동일).
4. **파라미터 아카이빙**: 각 관절의 최종 파라미터(모터 파라미터 + 오프셋 + 3루프 게인 + ID)를 파일로 저장하고, git 저장소 + 테이블로 이중 백업합니다.

버스 부하 용량 대략 계산(엔지니어링 권장값, 프레임 길이에 따라 재계산): 확장 프레임 최대 부하 약 130 µs/프레임, 6개 관절이 하나의 버스(Berkeley 각 사지 버스 약 5–6대), 250 Hz 양방향 송수신 = 6 × 250 × 2 × 130 µs ≈ 점유율 39%, 양호; 12대를 모두 하나의 버스에 연결하면 80%에 근접하므로 반드시 버스를 분할해야 합니다.

【이유】[CAN 버스](/entry/ent_technology_can_bus_2024/)는 여러 노드가 한 쌍의 선을 공유합니다. ID 충돌 시 두 장치가 동일한 프레임을 동시에 전송하면 오류 프레임이 눈덩이처럼 불어나 버스 폭풍이 발생하고 전체 네트워크가 마비됩니다. 또한 현상은 "무작위 끊김"으로 나타나 위치 파악이 매우 어렵습니다. 파라미터 아카이빙은 M07 및 전체 기기 단계의 생명줄입니다: 22개의 관절 중 3개월 후에는 아무도 7번 관절의 오프셋을 기억하지 못합니다.

【상황 분석 방법】네트워킹의 첫 번째 단계는 항상 전원을 차단하고 CANH-CANL 저항을 측정하는 것입니다: 양쪽 끝에 각각 120 Ω 터미네이터가 있을 때 약 60 Ω이어야 합니다. 무한대 = 터미네이터 미연결, 60 Ω보다 훨씬 낮음 = 터미네이터 과다 연결([1단계 개요](../stage-1-actuator.md) 점검표 참조). 통신 프로토콜 및 미들웨어 선택은 [제22장 소프트웨어 미들웨어](/wiki/chapters/chapter-22/)를 참조하십시오.

## 승인 기준

- [ ] 모든 관절 펌웨어 버전이 일치하고, 버전 번호/커밋이 기록되어 있으며, 출고 기본 파라미터가 백업되었습니다.
- [ ] 각 모터 파라미터(극수/R/L/KV)가 개별적으로 등록되고, 출처(매뉴얼/실측/자체 튜닝)가 명시되었습니다.
- [ ] 전원 켜짐 자동 보정 통과, 연속 5회 반복 보정 오프셋 드리프트 < 5° 전기각(또는 드라이버 보드 매뉴얼 지정값), 보정 결과가 플래시에 기록되었습니다.
- [ ] 3루프 튜닝 완료: 무부하 30° 계단 응답 오버슈트 < 10%, 정상 상태 오차 < 0.5°, 곡선이 아카이빙되었습니다.
- [ ] CAN 네트워킹 완료: ID 할당표 문서화, 250 Hz 송수신 1시간 연속 끊김 없음.
- [ ] 모든 파라미터가 저장되고 이중 백업(git + 테이블)되어, 한 번의 명령으로 모든 관절에 다시 기록할 수 있습니다.

## 일반적인 문제 및 점검

| 증상 | 가능한 원인 | 점검 조치 |
|---|---|---|
| 전원을 켤 때마다 다시 보정해야 함 | 보정 결과가 플래시에 기록되지 않음 | 보정 후 저장 명령 실행, 전원 차단 후 재시작하여 확인 |
| 네트워킹 후 버스 폭풍, 전체 네트워크 끊김 | 두 관절의 ID 충돌 | 개별적으로 전원을 켜 ID 변경, 라벨 부착 후 네트워킹 |
| 모터 고주파 울음, 만지면 저림 | 속도 루프 게인 과다 | 속도 루프 Kp 절반으로 줄여 테스트; 대역폭이 전류 루프의 1/5 이하인지 확인 |
| 보정할 때마다 오프셋 드리프트 | 자석 느슨함 / 엔코더 설치 편심 | 자석 접착 및 동축도 확인, M05로 돌아가 조립 수정 |
| 모터 역회전, 무력 또는 윙윙거리며 회전 안 함 | 상 순서 오류 / 극수 입력 오류 | 개루프 소전류 회전 테스트로 상 순서 확인; 자석 재계수 |
| 전류 루프 자체 튜닝 실패 | R/L 입력값 터무니없음 / 상선 접촉 불량 | LCR 미터로 재측정; 3상 배선 및 납땜 지점 확인 |
| 저속 크리핑, 덜컹거림 | 전류 루프 대역폭 너무 낮음 / 엔코더 분해능 부족 | 전류 루프 대역폭 높임; 엔코더 비트 수 및 설치 동축도 확인 |
