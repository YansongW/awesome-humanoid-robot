# M12 · 시뮬레이션 서기와 걷기: 먼저 안정적으로 서고, 그다음 걷기

**전체 위치**: [M11 시뮬레이션 엔지니어링 준비](m11-sim-setup.md) 바로 다음. 입력은 로드 가능하고 접촉이 합리적인 시뮬레이션 모델; 출력은 **두 가지 인도물**: ① PD 서기 데모 (10분 동안 넘어지지 않음 + 밀기 회복); ② 서면화된 보행 기술 경로 결정 (고전 MPC/WBC 또는 RL) — [M13](m13-rl-training.md)은 RL 경로를 따라 심층 훈련 진행.

**전제 조건**: M11 검수 전부 통과 (기준 검사 4가지 전부 통과); [Stage 0](../stage-0-foundations.md)의 PD 서기 감각 유지 — 이 작업 단계 1은 그 확장판.

이론 배경: [제14장 로봇 제어 기초](/wiki/chapters/chapter-14/), [제15장 운동 생성 및 Locomotion](/wiki/chapters/chapter-15/), [제23장 시뮬레이션 및 물리 엔진](/wiki/chapters/chapter-23/); 균형 이론 계단의 전체 버전은 [단계 2 개요](../stage-2-biped.md) 섹션 2 참조.

## 단계 1: PD 서기 — 걷기의 입장권

【무엇을 할 것인가】세 가지를 순서대로 수행:

1. **제로 모멘트 서기 자세 설계**: 각 관절 목표 각도 (발목/무릎/엉덩이 보상)로 질량 중심 투영이 지지 다각형 중심 근처에 오도록 — M11의 keyframe으로 시작하여 미세 조정하여 표류하지 않도록 함;
2. **위치 PD 제어**: M11의 주파수 계층화 (물리 1 kHz, 제어 100 Hz 수준) 연결:

```python
# 위치 PD 메인 루프: 목표 각도 추적 + 토크 제한 (제한은 M11 단계 3과 동일)
tau = kp * (q_des - q) - kd * dq
tau = np.clip(tau, -tau_max, tau_max)
```

3. **판단 기준 계단식 단계별 검수**: 10초 → 60초 → 10분 동안 넘어지지 않음; 그런 다음 몸통에 작은 충격량 교란을 가해 회복 가능해야 통과. 게인 조정: 먼저 P 후 D — P는 떨릴 듯 말 듯할 때까지 증가시키고, D로 떨림을 억제; 고주파 떨림은 먼저 P를 낮추고, 여전히 떨리면 시뮬레이션 스텝 크기 확인.

【왜 하는가】서기는 걷기의 부분 집합: 서기 루프 (발목/엉덩이 전략)를 조정하면 걷기는 단지 평형점을 주기적으로 지지 영역 밖으로 이동시킨 후 포착하는 것 ([단계 2](../stage-2-biped.md) 복제 프로세스 Step 7의 관점). PD 서기가 검증하는 것은 **모델 정확성** — 영점, 축, 질량 속성 ([시뮬레이션 매뉴얼](../playbooks/sim-setup.md) 3단 로켓 첫 번째 단계), 이 단계를 통과하지 못하면 이후는 모두 헛수고.

【당신의 상황 분석】서지 못하면 먼저 파라미터를 조정하지 말고 "모델 오류 → 게인 오류 → 스텝 크기 오류" 순서로 점검: 제로 모멘트 서스펜션 통과했는가 (M11 단계 6)? 질량 중심 투영 계산했는가? 게인을 절반으로 줄이면 현상이 변하는가?

## 단계 2: 균형 이론 계단 — ZMP, LIPM 및 계층 구조

【무엇을 할 것인가】순서대로 세 단계 학습 (자세한 내용은 [단계 2](../stage-2-biped.md) 섹션 2 참조):

1. **[ZMP (제로 모멘트 포인트)](/entry/ent_method_zero_moment_point/)** : 지면 반력 등가 작용점이 지지 다각형 내에 있어야 넘어지지 않음. 시뮬레이션에서 ZMP 궤적을 그리거나 출력하여 지지 영역을 벗어날 때와 로봇이 넘어질 때 관찰;
2. **LIPM 선형 역진자**: 전신을 "질량 중심 + 무질량 다리"로 단순화, 질량 중심 높이 일정 가정 하에 해석적 해 존재, 평지 ZMP 추정:

```
# 평지 LIPM 근사: x_zmp = x_com - (z_com / g) * x_ddot_com
x_zmp = x_com - (z_com / 9.81) * x_ddot_com
```

3. **[보행 계획](/entry/ent_method_gait_planning/) 및 계층 구조**: 주어진 목표 속도에 대해 스윙 발 착지점과 이중 지지/스윙 위상 전환 타이밍 결정 (입문 고전은 LIPM + 포착점 분석: 발을 내딛지 않으면 어디로 넘어질지, 그곳에 발을 내딛음); 그리고 계층적 인식 구축: **착지점 계획 → 질량 중심 궤적 → WBC 할당 → 관절 토크**.

【왜 하는가】ZMP는 이족 보행 안정성의 가장 고전적인 판단 기준이며, 모든 넘어짐을 진단하는 첫 번째 도구; 계층 구조를 통해 "비뚤어짐"이 착지점 오류 (의사 결정 계층)인지 힘 제어 미흡 (실행 계층)인지 파악 가능. 이 인식 없이 바로 RL을 적용하면 넘어졌을 때 모델 오류인지 제어 오류인지 구분 불가. 체계적 유도는 [제14장](/wiki/chapters/chapter-14/) 및 [제15장](/wiki/chapters/chapter-15/) 참조.

【당신의 상황 분석】RL 경로: 개념 이해만 하면 됨 (전략이 스스로 착지점 학습), 그러나 ZMP 관찰 연습은 필수; MPC 경로: LIPM 유도는 완전히 숙지해야 하며, 이는 단계 3의 MPC 예측 모델.

## 단계 3: 고전 경로 실습 — OpenLoong MPC+WBC 실행

【무엇을 할 것인가】OpenLoong-Dyn-Control 실행: [MuJoCo](/entry/ent_software_mujoco_physics_engine_2022/)에 배포된 MPC+WBC 전신 제어 프레임워크, **보행/점프/맹목 장애물 밟기** 세 가지 예제 포함, 실제 프로토타입에서 보행 및 맹목 장애물 밟기 구현 완료, Apache-2.0 ([OpenLoong-Dyn-Control](https://github.com/loongOpen/OpenLoong-Dyn-Control/blob/main/README-zh.md)):

```bash
git clone https://github.com/loongOpen/OpenLoong-Dyn-Control.git
# 의존성 설치 및 컴파일은 저장소 README 엄격히 따름 (버전은 저장소 업데이트에 따라 변하므로 선택한 버전에 맞게 확인)
```

실행 후 **직접 수정**하고 기록: MPC 가중치, 보행 빈도, 보폭, 각 항목 수정 시 보행 품질 변화 기록 (안정성/속도 추종/떨림). 동시에 역할 분담 파악: [MPC (모델 예측 제어)](/entry/ent_method_model_predictive_control/)는 시간 창을 롤링 예측하고 제약 조건이 있는 최적화를 풀어 "향후 몇 걸음 어떻게 밟고, 어떻게 힘을 쓸지" 담당; [WBC (전신 제어)](/entry/ent_method_whole_body_control/)는 작업 목표를 우선순위에 따라 전신 관절 토크에 할당하여 "이 박자에 각 관절이 얼마나 힘을 낼지" 담당; [Pinocchio](/entry/ent_software_pinocchio/)는 효율적인 강체 동역학 라이브러리로, MPC/WBC가 동역학 항을 계산할 때 거의 필수적으로 사용.

【왜 하는가】이것은 하드웨어 없이 전신 크기 인간형 고전 제어 파이프라인을 학습할 수 있는 기성 교재 — Qinglong 전신 185 cm/80 kg+는 개인이 복제 불가능하지만 제어 프레임워크는 자유롭게 학습 가능 (아카이브 관점). 직접 파라미터를 수정하고 보행 품질 변화를 보면 논문 10편 읽는 것보다 직관 형성이 빠름.

【당신의 상황 분석】컴파일 실행 불가: 저장소 README 엄격히 따라 의존성 버전 확인, 임의 업그레이드 금지. 수학 따라가기 어려움: 먼저 "파라미터 조정 가능한 블랙박스"로 사용, "파라미터 → 현상" 대응 관계 기록, 유도는 나중에 보충.

## 단계 4: RL 경로 예행연습 — 파이프라인만 증명, 훈련 시작 안 함

【무엇을 할 것인가】한 가지만 수행: M13에서 사용할 공식 환경을 당신의 기기에서 실행 — [Isaac Lab](/entry/ent_software_nvidia_isaac_lab_2024/) 인간형 예제 또는 [MuJoCo Playground](/entry/ent_paper_202501_mujoco_playground_2025/), obs/action/reward 데이터 흐름이 돌아가는지 확인, FPS 및 VRAM/CPU 점유율 기록:

```bash
# Isaac Lab 공식 인간형 환경 스모크 테스트 (작업 이름 및 스크립트 경로는 선택한 버전 공식 문서에 따라 확인)
./isaaclab.sh -p <공식 RL 예제 스크립트> --task=<인간형 작업 이름> --num_envs=16 --headless --max_iterations=2
# 기록: FPS, nvidia-smi VRAM 점유율, obs/action 차원
```

**훈련 시작 안 함**: 공식 베이스라인 실행, 자체 모델 교체, 보상 조정은 [M13](m13-rl-training.md) 단계 1–3의 작업, 이 단계는 파이프라인 리허설만 수행하여 "이 기기에서 실행 가능함" 증명.

【왜 하는가】RL 스택의 환경/의존성/버전 문제는 매우 시간 소모적이며, 지금 노출하면 M13에서 바로 훈련 시작 가능; FPS 및 하드웨어 점유율 데이터는 M13의 병렬 환경 수 설정 결정 ([PPO](/entry/ent_algorithm_ppo/)는 처리량 소모).

【당신의 상황 분석】NVIDIA GPU 없음: MuJoCo Playground/MJX 또는 CPU 소규모 환경으로 데이터 흐름 먼저 검증; GPU 있음: Isaac Lab 공식 인간형 작업을 두 iter 빈 실행하거나 공식 사전 훈련 checkpoint 로드 평가, 데이터 흐름 로그 스크린샷 저장.

## 단계 5: 경로 결정——기록하라, 표류하지 말라

【무엇을】아래 표를 참고하여 주 경로를 선택하고 제작 일지에 기록하라(두 가지 모두 시도할 수 있으나, 주종과 이유를 명확히 써야 한다):

| 차원 | 고전 MPC/WBC | RL（[PPO](/entry/ent_algorithm_ppo/) + 도메인 무작위화） |
|---|---|---|
| 개발량 | 유도 및 구현량이 많지만, OpenLoong 기성 프레임워크를 배울 수 있음 | 훈련 파이프라인은 기성, 보상 엔지니어링이 새로운 작업량 |
| 수학적 난이도 | 높음(동역학 + 최적화) | 중간(개념만 이해하면 시작 가능, 보상 조정은 실험 과학) |
| 하드웨어 요구사항 | CPU 실행 가능(MuJoCo) | N 카드 훈련이 더 원활함(Isaac Lab), CPU도 가능하지만 한 자릿수 느림 |
| 설명 가능성 | 높음——각 토크의 근거가 명확함 | 낮음——정책은 블랙박스 |
| 실제 기기 사례 | BRUCE 가변 주기 MPC로 보행/달리기/점프 구현(bruce-westwood.md) | ToddlerBot, Berkeley 모두 제로샷 [sim-to-real](/entry/ent_method_sim_to_real/) 보행 구현(각 문서) |

【왜】두 길 모두 통하지만, 당신의 시간은 주 경로 하나에만 충분하다. 결정을 기록하는 것은 M13/[M14](m14-sim-to-real.md) 점검 시 방향이 표류하지 않도록 하기 위함이다.[2단계](../stage-2-biped.md) 의사 결정 트리의 기준도 동일하게 적용된다: 첫 번째 기기의 핵심 KPI는 "걷게 하는 것"이지, 한 번에 완벽하게 만드는 것이 아니다.

【당신의 상황 분석】수학에 강하고 제어를 완전히 이해하고 싶다 → MPC/WBC 주 경로, OpenLoong이 교재이다. ML 배경 + GPU 보유 → RL 주 경로로 M13까지 직행한다. 둘 다 시도하고 싶다 → 주 경로 RL, 보조 경로로 OpenLoong 코드를 읽어 제어 구조를 이해한다(또는 반대). 하지만 일지에 반드시 주 경로가 무엇인지 명확히 기록해야 한다.

## 검수 기준

- [ ] PD 자세 유지 10분 시뮬레이션 시간 동안 넘어지지 않고, 몸통을 살짝 밀었을 때 회복 가능(화면 녹화存档).
- [ ] ZMP 관찰 기록 작성: 자세 유지 및 밀림 상황에서 ZMP가 지지 다각형 내에 있는지, 그림과 결론 포함.
- [ ] OpenLoong 예제 또는 공식 RL 환경 중 최소 하나 실행 성공(화면 녹화 + 매개변수 변경/데이터 흐름 기록存档).
- [ ] 경로 결정 문서화: 주 경로/보조 경로, 이유, 예상 위험을 제작 일지에 기록.
- [ ] 주 경로가 RL인 경우: M13에 필요한 공식 환경 실행 가능 확인, FPS 및 하드웨어 점유율 기록.

## 일반적인 문제점 및 점검

| 증상 | 가능한 원인 | 점검 조치 |
|---|---|---|
| PD 자세 유지 시 고주파 떨림, 윙윙거림 | P 게인 과다 / 시뮬레이션 스텝 크기 과다 | P 절반으로 줄여 재측정; 스텝 크기 줄여 비교; 댐핑을 강성으로 잘못 입력했는지 확인 |
| 자세 유지 시 천천히 한쪽으로 기울어짐 | 질량 중심 투영이 지지 영역 중심에서 벗어남 / 모델 좌우 비대칭 | 질량 중심 투영 출력; M10으로 돌아가 미러 조인트 축 확인 |
| 발바닥이 미끄러져 서 있지 못함 | 마찰 계수过低 또는 접촉이 너무 부드러움 | M11 4단계로 돌아가 friction과 solref 조정 |
| 밀면 바로 넘어지고 회복 불가 | D 게인 부족 / 발목 토크 제한이 너무 빡빡함 | D 증가 후 재측정; 발목 액추에이터 제한 확인(M11 3단계) |
| 바로 RL로 뛰어들어 넘어짐의 원인을 모름 | 균형 이론 단계 건너뜀 | 2단계로 돌아가 ZMP 관찰 수행; PD 자세 유지 검수 후 RL 논의 |
| OpenLoong 예제 실행 불가 | 의존성 버전 불일치 | 저장소 README에 따라 버전을 엄격히 확인하고, 자체적으로 의존성을 업그레이드하지 말 것 |
