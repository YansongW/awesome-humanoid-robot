# 0→1 휴머노이드 로봇 제작: 로드맵 개요

!!! note "안전은 면책 조항이 아니라 프로세스의 일부입니다"
    이 로드맵은 실제 하드웨어를 다룹니다: 리튬 배터리, 24–48 V 버스, kg 단위로 움직이는 금속 구조물, 정지 시 손가락을 다칠 수 있는 관절 토크. 안전은 선언이 아니라 프로세스에 내장됩니다 – 전기 검수는 [M09 최초 전원 인가 smoke test](missions/m09-mechanical-assembly.md) 참조, 보행 보호는 [M14 단계별 잠금 해제](missions/m14-sim-to-real.md) 참조, 장기 안전 엔지니어링은 [M20 신뢰성, 유지보수 및 안전](missions/m20-reliability-safety.md) 참조.

## 이 저장소의 세 가지 용도: 검색, 학습, 제작

이 저장소는 동시에 "지도", "책", 그리고 "시공도"입니다. 동일한 개념이 세 계층에서 각각 한 번씩 등장하며 역할이 다릅니다:

| 용도 | 진입점 | 언제 사용하는가 | 예시 |
|------|------|-----------|------|
| **검색**: 지식 그래프 | [/search/](/search/) 및 카드 페이지 | 낯선 용어를 만나거나 특정 개체의 매개변수/출처/상하위 관계가 필요할 때 | [CAN 버스](/entry/ent_technology_can_bus_2024/)가 무엇인지, 어디에 사용되는지 검색 |
| **학습**: Wiki 저서 | [/wiki/](/wiki/) | 특정 분야를 체계적으로 이해해야 할 때 (30장 + 부록, 연구 논문 기준으로 작성) | [제14장 로봇 제어 기초](/wiki/chapters/chapter-14/)를 읽어 WBC 이해 |
| **제작**: 본 로드맵 | 지금 보고 있는 이 계층 | 휴머노이드 로봇을 0부터 1까지 직접 만들고 싶을 때 | [단계 0](stage-0-foundations.md)의 검수 기준을 항목별로 통과 |

세 계층의 전형적인 연동 방식: 로드맵에서 특정 단계를 수행하다가 → 막히는 개념을 카드 페이지에서 매개변수와 출처 확인 → 완전히 이해하려면 Wiki 해당 장에서 체계적으로 학습. 로드맵은 Wiki의 긴 유도 과정을 반복하지 않고, "이 단계에서 무엇을 할지, 왜 하는지, 제대로 했는지 어떻게 판단할지"만 알려줍니다.

## 로드맵 페이지 읽는 법: 세 부분 구성과 데이터 규율

본 로드맵의 각 실무 단계는 세 부분으로 구성되며, 이것이 일반 튜토리얼과의 차이점입니다:

1. **【무엇을 할 것인가】** 구체적이고 실행 가능하며 완료 표시가 있는 동작;
2. **【왜 하는가】** 이 단계의 배경 원리와 해당 지식 카드 및 Wiki 장으로의 링크, 깊이 파고들고 싶다면 진입점 제공;
3. **【당신의 상황에 따른 분석】** 자신의 예산, 시나리오, 기술 배경에 따라 선택을 안내 – 동일한 목표라도 순수 소프트웨어 배경과 기계 배경의 접근 방식이 다릅니다.

데이터 규율: 본문에 등장하는 구체적인 매개변수(가격, 토크, 자유도, 소비 전력 등)는 모두 근처에 1차 출처 URL(개체 카드 또는 공식 저장소/논문 링크)을 표시합니다; 신뢰할 수 있는 출처를 찾을 수 없는 경우 "공급업체에 직접 확인 필요"라고 명시하며, 숫자를 조작하지 않습니다.

## 4단계 지도

| 단계 | 목표 | 예상 시간 (취미 투자) | 예산 규모 | 검수 (판단 기준 요약) |
|------|------|---------------------|----------|------------------|
| **Stage 0 기초 다지기**[→ 페이지](stage-0-foundations.md) | 입장권 획득: 수학 4종 세트, Python/C++ 및 ROS 2, 회로 개념, URDF 읽기 | 6–10주 (주당 8–10시간) | ≈ ¥0: 소프트웨어 전부 오픈소스; 선택적으로 3D 프린팅 시험 제작 가능, 비용은 공급업체에 직접 확인 필요 | 이족 보행 URDF 하나 읽기; MuJoCo에서 이족 모델을 ≥ 10초 동안 서 있게 하기 |
| **Stage 1 관절 만들기**[→ 페이지](stage-1-actuator.md) | 작업대에서 검수 통과한 액추에이터 모듈 제작: 모터 + 감속기 + 센서 + 드라이버 + 제어 전체 링크 완전 이해 | 4–8주 (추정) | 단일 관절 수백~수천 위안 규모: QDD 방식 단일 BOM 약 $157–188 (Berkeley 6512, 출처: [EECS-2025-207 기술 보고서 BOM](https://www2.eecs.berkeley.edu/Pubs/TechRpts/2025/Archive/EECS-2025-207.pdf)); 서보/하모닉 방식 가격은 공급업체에 직접 확인 필요 | 지표표 문서화; 30° 계단 응답 오버슈트 < 10%; 1 Hz 사인파 추적 진폭 감쇠 < 10%; 통신 링크 1시간 연속 무장애 |
| **Stage 2 이족 보행 플랫폼**[→ 페이지](stage-2-biped.md) | 시뮬레이션 우선 제어 스택 실행 후, 오픈소스 이족/바퀴형 플랫폼 복제하여 평지 안정 보행 구현 | 3–6개월 (추정) | 플랫폼에 따라 예산 결정: Upkie 약 $3,000, Berkeley Humanoid Lite 약 $3,236–4,312, ToddlerBot 약 $6,000 (출처: 각 플랫폼 공식 페이지: [Upkie](https://hackaday.io/project/185729-upkie-wheeled-biped-robots), [Berkeley Humanoid Lite](https://www2.eecs.berkeley.edu/Pubs/TechRpts/2025/Archive/EECS-2025-207.pdf), [ToddlerBot](https://arxiv.org/html/2502.00893v2)); 약 ¥2만–5만 위안 규모, 환율 및 조달 채널 변동으로 직접 계산 필요 | 시뮬레이션 연속 보행 10분간 넘어지지 않음; 실제 기기 서 있기 ≥ 5분, 평지 연속 보행 ≥ 10분, 가벼운 밀기 회복 가능, 비상 정지 시연 가능 |
| **Stage 3 완전한 휴머노이드**[→ 페이지](stage-3-humanoid.md) | 이족 보행 위에 상체 추가: 팔, 말단 효과기, 인식 스택 및 지능 계층, 종단 간 작업 완료 | 6개월 이상, 지속적 반복 | 추가 수천~수만 위안 (팔/손/카메라/연산 보드, 선택한 방식에 따라 직접 계산) | 음성 명령 듣기 → 자율적으로 테이블로 이동 → 컵 인식 및 집기; IK 무작위 샘플링 해결 성공률 ≥ 95%, 말단 위치 오차 ≤ 2 cm |

두 가지 설명:

- **시간은 추정치**이며, 주당 8–10시간 취미 투자 기준으로 환산; 전일제로 하면 약 1/3로 단축 가능. 배경에 따라 크게 달라지므로 다음 절 참조.
- **예산에는** 이미 보유한 범용 장비(컴퓨터, 멀티미터, 인두기)가 포함되지 않음. 상용 완제품 플랫폼은 다른 가격대: ROBOTIS OP3 판매가 $13,764.35 (출처: [ROBOTIS US 스토어 페이지](https://www.robotis.us/robotis-op3-us/), 2026년 페이지 스냅샷), 이것이 본 로드맵 Stage 2에서 완제품 대신 오픈소스 플랫폼을 권장하는 이유 중 하나.

## 이 로드맵의 경계

"하지 않는 것"을 명확히 하는 것이 "하는 것"을 약속하는 것보다 당신의 시간을 더 잘 보호합니다:

- **논문 소개 목록이 아닙니다**. 최신 알고리즘(VLA, 세계 모델 등)은 Wiki 18-20장에서 체계적으로 다루며, 로드맵은 "로봇 제작에 필요할 때"만 이를 가리킵니다. 먼저 로봇을 일어서게 한 후, 똑똑하게 만드는 것을 논하세요.
- **처음부터 모든 것을 자체 개발하는 경로가 아닙니다**. Stage 2는 첫 번째 로봇을 위해 성숙한 오픈소스 플랫폼 위에 구축할 것을 명확히 권장합니다. 20+ 자유도를 가진 구조와 구동을 처음부터 설계하는 것은 팀 단위, 다중 로봇 반복 작업 수준의 작업량이며, 개인 첫 로봇의 합리적인 목표가 아닙니다. [공개 조사 아카이브](https://github.com/YansongW/awesome-humanoid-robot/tree/main/data/roadmap/research/)에서 Berkeley Humanoid Lite, ToddlerBot, Poppy, ROBOTIS OP3 등 후보 플랫폼에 대한 비용 및 진입 장벽 분석이 하나씩 제공되므로, 선정 시 직접 읽어보세요.
- **구매 조언 및 안전 매뉴얼이 아닙니다**. 모든 플랫폼 비교는 출처를 확인할 수 있는 사실과 trade-off만을 제시합니다. 주문 전에 최신 가격, 라이선스(일부 오픈소스 설계 파일은 비상업적 라이선스입니다, 예: ToddlerBot, 출처: [ToddlerBot GitHub](https://github.com/hshi74/toddlerbot)) 및 규정 준수 요구 사항을 직접 확인하세요.
- **직선 진행을 보장하지 않습니다**. 실제 상황은 종종 Stage 1에서 드라이버 하나를 태워 Stage 0 3단계로 돌아가 전기 공학을 다시 배우거나, Stage 2 시뮬레이션이 제대로 작동하지 않아 1단계로 돌아가 역학을 보충하는 경우입니다. 로드맵의 가치는 당신이 현재 어디에 있는지, 다음에 어디로 가야 하는지를 알게 하는 것이지, 되돌아가는 것을 금지하는 것이 아닙니다.

## 당신의 배경에 따라 입구 선택

### 순수 소프트웨어 배경 (CS / AI / 알고리즘 엔지니어)

당신의 약점은 코드가 아니라 **물리적 직관과 전기 공학 상식**에 있습니다. 제안:

1. 수학 4종 세트 중 [고전 역학](/entry/ent_foundation_classical_mechanics/)만 보충하고, 나머지는 Stage 0의 판단 기준으로 자가 점검하여 통과하면 건너뛰세요.
2. 절약한 시간을 Stage 0의 3단계(회로 및 CAN)와 4단계(시뮬레이션 기립)에 투자하세요. 전자는 Stage 1에서 실제 하드웨어를 태우지 않도록 보호하고, 후자는 당신의 역학 직관 훈련장입니다.
3. 3D 프린팅 상식을 건너뛰지 마세요. Stage 2의 구조 부품은 프린팅에 크게 의존합니다(Berkeley Humanoid Lite는 사이클로이드 감속기까지 프린팅됩니다, 출처: [Berkeley Humanoid Lite 논문](https://arxiv.org/abs/2504.17249)).

### 하드웨어 배경 (기계 / 전자 / 자동화 엔지니어)

당신의 약점은 **소프트웨어 공학 및 현대 제어/학습 알고리즘**에 있습니다. 제안:

1. Stage 0 1단계에서 [확률론](/entry/ent_foundation_probability_theory/)과 [볼록 최적화](/entry/ent_foundation_convex_optimization/)를 중점적으로 보충하세요. 3단계 회로 부분은 30분 만에 개념을 훑어보면 됩니다.
2. Python/ROS 2/git은 반드시 판단 기준에 도달해야 합니다. "이해만 하면 된다"고 생각하지 마세요. Stage 1부터 모든 작업은 코드 안에서 이루어집니다.
3. 공차, 조립, 안전에 대한 당신의 직관은 귀중한 자산이며, Stage 1(테스트벤치 관절)과 Stage 2(전체 로봇 복제)에서 그 가치가 발휘됩니다.

### 기초가 없는 학생

Stage 0 순서대로 성실히 진행하되, **각 단계에 데드라인을 설정하세요**: 각 절의 "어느 정도까지 배워야 충분한가" 판단 기준을 확인하고, 기준에 도달하면 즉시 넘어가고 문제를 다시 풀지 마세요. 제안:

1. 먼저 Wiki [제1장 서론](/wiki/chapters/chapter-01/)을 읽어 전체 그림을 이해하고, 자신이 어떤 시스템을 만들고 있는지 알게 하세요.
2. 전체 시간 예산을 ×1.5로 잡으세요. 예산표의 금액은 당신에게 변함이 없습니다(Stage 0은 원래 거의 무료입니다).
3. 가장 큰 위험은 "끝없는 기초 다지기"입니다. Stage 0의 검증 기준이 이를 방지하기 위한 것입니다. 항목별로 통과하고, 통과하면 즉시 Stage 1으로 진입하세요. 부족한 것은 Stage 1에서 알려줄 것입니다.

## 카드 페이지의 단계 배지

이 저장소의 카드 페이지(`/entry/...`)에서 `Stage 0 · 기초 기반`과 같은 배지를 볼 수 있습니다. 의미 규칙은 다음과 같습니다:

- **배지 = 학습 시기 힌트**: 해당 항목이 로드맵에서 "가장 먼저 반드시 알아야 하는" 단계입니다. 예를 들어 [URDF 로봇 설명 형식](/entry/ent_technology_urdf_robot_description_format_2024/)은 Stage 0으로 표시되는데, 이를 이해하는 것이 시뮬레이션 입문의 전제 조건이기 때문입니다.
- **하나의 카드에 여러 배지가 있을 수 있음**: 여러 단계에 걸쳐 반복적으로 사용되는 항목(예: [ROS 2 미들웨어](/entry/ent_software_ros_2_middleware_2024/))은 그것이 중요해지는 각 단계를 표시합니다.
- **배지는 난이도나 중요도 평가가 아님**: Stage 0 항목이 "간단하다"는 의미가 아니며, Stage 3 항목이 "고급이다"는 의미도 아닙니다. 단지 로봇 제작 과정에서 나타나는 위치를 나타냅니다.
