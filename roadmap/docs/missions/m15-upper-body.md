# M15 · 上肢与末端执行器：给会走的机器长出手

**全局位置**：Stage 2 行走平台六关验收通过（M14）之后，Stage 3 的第一个任务。输入是一台会走的双足 + Stage 1 的执行器选型方法，输出是**双臂 + 末端执行器装调完成、IK 求解可用**的上半身。下游 M16 感知栈要往头/腕装相机，M17 遥操作要驱动手臂与末端——本任务是它们共同的载体。

**前置条件**：[M14 · sim-to-real 部署与行走验收](m14-sim-to-real.md) 通过；会用 M01 的关节指标算法；会走 M10 的 URDF 流程（臂要并入整机模型）；执行器选型四问见[执行器选型手册](../playbooks/actuator-selection.md)。

理论背景：[七自由度机械臂](/entry/ent_component_7dof_arm_2024/)、[正运动学](/entry/ent_method_forward_kinematics/)、[逆运动学](/entry/ent_method_inverse_kinematics/)、[灵巧手](/entry/ent_component_dexterous_hand_2024/)卡片，[第 16 章 操作与抓取](/wiki/chapters/chapter-16/)、[第 8 章 人形机器人设计原理](/wiki/chapters/chapter-08/)、[第 9 章 关键子系统设计](/wiki/chapters/chapter-09/)与 [第 4 章 执行器](/wiki/chapters/chapter-04/)。

## 步骤 1：臂构型与自由度分配

【做什么】先定每臂自由度，再算关节指标。三档取舍：

| 构型 | 能力 | 代价 | 先例 |
|---|---|---|---|
| 7 DoF（肩 3、肘 1、腕 3） | 冗余自由度：末端不动时肘部仍可转动，绕障、避奇异 | 成本、线束、控制复杂度最高 | ToddlerBot 每臂 7 DoF，用 Dynamixel 总线舵机（toddlerbot.md） |
| 6 DoF | 可达任意位姿，无冗余 | 少一轴，避奇异靠路径规划 | 工业臂标准构型 |
| 5 DoF | 牺牲腕部一个姿态轴 | 最省，桌面定点抓取够用 | Berkeley Humanoid Lite 每臂 5 DoF（berkeley-humanoid-lite.md） |

首机建议从轻量 5–6 DoF 起步。关节指标复用 M01 杠杆算法，算例（肩屈伸关节）：臂 + 手共 1.2 kg，末端抓 0.5 kg，质心等效臂长 0.25 m，动态安全系数 2：

```
τ ≥ (1.2 + 0.5) × 9.81 × 0.25 × 2 ≈ 8.3 N·m
```

执行器两条路线：复用 Stage 1 自研模组，或舵机总线（腕部等小扭矩关节尤其合适，如 [Dynamixel XM430](/entry/ent_component_dynamixel_xm430_w210_t/) 谱系；扭矩/价格按型号向供应商确认）。

【为什么】自由度是"能力—成本—复杂度"的三选一：每多一个关节，多一份 BOM、一条线束、一个故障点。首机的 KPI 是"端到端抓起一个杯子"，不是复刻人臂解剖——两台标杆机用 5–7 DoF 都完成了操作演示，构型按任务选，不按执念选。冗余度的价值见[七自由度机械臂](/entry/ent_component_7dof_arm_2024/)卡片。

【你的情况怎么分析】只做桌面定点抓取：5–6 DoF 起步；明确要双手配合、绕障操作：7 DoF。峰值扭矩 < 4 N·m 的关节用舵机省心；要力控/反驱（将来做柔顺操作）就上 QDD，接受成本与调参工作量（对比见[执行器选型手册](../playbooks/actuator-selection.md)）。

## 步骤 2：结构集成与整机平衡

【做什么】

1. **惯量回填**：臂的质量/质心/惯量必须进 URDF（回 M10 流程），合并整机模型后重算总质心——臂不建模，行走策略看到的就是错误的动力学。
2. **肩座刚度与走线**：肩根是整条臂的悬臂支点，支架变形直接吃掉末端精度；线束随关节扭转预留余量（扭转环或滑环），腕部多圈旋转场合尤其要算。
3. **行走臂姿**：行走时双臂收拢（肘屈、臂贴身）降惯量，把收拢姿态写进行走策略的默认关节角。
4. **质心补偿概念**：操作前先问"伸手后整机质心投影还在支撑域内吗"，超出就调整站姿或分步伸手。

【为什么】装上臂的整机已不是 M14 验收时的那台：质心上移、惯量变大、行走的动态余量变小。建模先行能把"加臂后不会走"暴露在读仿真阶段，而不是在实机上摔出来。系统论述见 [第 9 章 关键子系统设计](/wiki/chapters/chapter-09/) 与 [第 8 章 人形机器人设计原理](/wiki/chapters/chapter-08/)。

【你的情况怎么分析】复刻平台（ToddlerBot/Berkeley）官方模型已含臂，本步做实物称重核对即可；自研平台按 M10 惯性三步走（CAD 读取 / 称重几何近似 / 摆动法）。加臂后先在仿真重跑站立与行走，必要时按 M13 流程 fine-tune 策略，再上吊架验证——顺序不能反。

## 步骤 3：末端执行器——先夹爪，留接口，再升级

【做什么】

1. **首版：电动平行夹爪**（舵机/电机直驱）。抓杯子类任务，夹爪成功率远高于没调好的灵巧手（[Stage 3 总览](../stage-3-humanoid.md) 3.2 节经验）。
2. **快换接口**：腕部做成机械定位法兰 + 统一供电/通信插头，换末端不动臂——ToddlerBot 的平行夹爪与柔顺手掌即可 2 分钟快换（toddlerbot.md）。
3. **升级路径**（按任务选，背景见[灵巧手](/entry/ent_component_dexterous_hand_2024/)卡片）：

| 方案 | 自由度/驱动 | 特点 | 适合谁 |
|---|---|---|---|
| 平行夹爪 | 1 DoF | 便宜可靠，抓取类型有限 | 首版端到端跑通 |
| [LEAP 灵巧手](/entry/ent_component_leap_hand/) | 16 DoF，Dynamixel 直驱 + 3D 打印 | 开源低成本拟人手，BOM 需向项目方确认 | 操作学习研究起步 |
| [Allegro 灵巧手](/entry/ent_component_allegro_hand/) | 16 DoF 四指，扭矩控制关节、ROS 兼容 | 商用可靠，价格需向供应商确认 | 要可靠性的场景 |

4. **抓取类型学**：先分清任务要力握（攥住，靠接触面积）还是精捏（捏起，靠指尖对指）——杯子/工具是力握，硬币/薄片是精捏，类型决定末端形态与自由度需求。

【为什么】灵巧手的 16 个自由度同时是 16 倍的控制与数据需求，首版就上等于同时开两条战线。快换接口的价值在第二版才显现——预留它是首版最便宜的远见。

【你的情况怎么分析】首机：夹爪 + 快换法兰，别犹豫。要做模仿学习研究：从 LEAP 起步（开源可改）；预算充足、要稳定性：Allegro。腱驱 vs 连杆：腱驱手指惯量小但维护烦，连杆刚度高好建模，首只手建议直驱或连杆。

## 步骤 4：运动学求解——FK 建链，IK 求解，验证成功率

【做什么】

1. **FK**：按 URDF 建立基座→末端的齐次变换链（[正运动学](/entry/ent_method_forward_kinematics/)），逐关节与实物比对——手动摆角度，FK 输出末端位姿 vs 卡尺/标定板实测。
2. **IK**：数值法起步，Jacobian 伪逆迭代求解；奇异附近改用阻尼最小二乘（DLS）。几何结构简单的臂可推解析解（[逆运动学](/entry/ent_method_inverse_kinematics/)）。
3. **7 DoF 冗余利用**：在零空间加次级目标（抬肘避障、远离关节限位）：

```
q̇ = J⁺·ẋ + (I − J⁺J)·∇H(q)        # H：抬肘/避限位的势函数
```

4. **工具**：ROS 生态成熟 IK 求解器优先；教学目的可 Python + numpy 手写 Jacobian。
5. **验证**：工作空间内随机抽 100 个目标位姿统计求解成功率——Stage 3 验收线 ≥95%（[Stage 3 总览](../stage-3-humanoid.md)）。

【为什么】操作的本质是坐标变换与求逆：视觉（M16）给出杯子位置后，靠 IK 把它翻译成 5–7 个关节角。奇异位形是数值法死穴——臂伸直时 Jacobian 秩亏，伪逆输出关节速度爆炸，DLS 用一点精度换数值稳定。零空间是 7 DoF 的"免费午餐"：末端不动，臂的姿态还能优化。

【你的情况怎么分析】验证顺序：仿真抽查 → 空载轨迹 → 带载轨迹，别反。成功率 < 95% 先查目标点是否在工作空间外；真机末端到位误差目标 ≤2 cm（Stage 3 判据，建议阈值），超差先查肩座刚度与零点标定，再怀疑算法。

## 步骤 5：全身 TF 与操作基元——把臂装回整机的坐标世界

【做什么】

1. **臂并入整机 URDF/TF 树**：以 base_link 为统一根节点，腿、躯干、臂、末端、相机一条变换链可查（M16 的相机外参也挂这棵树）。
2. **相机布局选型**：眼在手外（头/胸相机，视野大但遮挡多、标定链长）vs 眼在手上（腕相机，近景精确但视野小）——首版头相机即可，腕部预留安装位与走线。
3. **抓取基元状态机**：预抓姿态 → 接近（慢速直线）→ 闭合 → 负载确认（电流/位置反馈）→ 撤回，每段带超时与失败回退。
4. **行走-操作互斥**：先站定再操作（[Stage 3 总览](../stage-3-humanoid.md) 经验）——伸手时下肢锁定站立控制，操作完成收回臂再走，互斥写进软件互锁。

【为什么】人形没有固定基座，末端精度 = 臂精度 + 躯干姿态误差 + 足端滑移的叠加（[Stage 3 总览](../stage-3-humanoid.md) 3.1 节）——边走边抓是研究课题，站定再抓是工程智慧。状态机把"抓取"拆成可观测、可回退的小段，失败时能定位到哪一段，而不是面对一个"抓不起来"的黑箱。

【你的情况怎么分析】TF 树先画在纸上：每个 frame 的父节点与变换来源（URDF 静态 / 标定外参）写清楚。基元状态机用 Python 状态循环手写即可，不必上行为树框架；行走-操作互斥靠软件强制，不靠操作员自觉。

## 验收标准

- [ ] 臂构型与自由度分配成文，各关节峰值扭矩有算式、有数字、有安全系数（≥2）取值理由。
- [ ] 臂质量/质心/惯量已回填 URDF，整机模型重算质心通过，仿真站立/行走复测稳定。
- [ ] 末端快换接口（机械定位 + 电气插头）装调完成，夹爪开合受控。
- [ ] FK 与实物逐关节比对通过；IK 随机 100 目标求解成功率 ≥95%。
- [ ] 真机末端到位误差 ≤2 cm（空载，建议阈值），空载/带载轨迹复现录屏存档。
- [ ] 站定伸手操作全流程整机不倾倒（或有质心补偿且实测有效）。
- [ ] 抓取基元状态机五段齐全（含超时与失败回退），真机抓取演示成功。

## 常见坑与排查

| 症状 | 可能原因 | 排查动作 |
|---|---|---|
| 奇异附近关节跳变/速度爆炸 | 目标过奇异位形，伪逆发散 | 换阻尼最小二乘；目标点做可达性过滤；7 DoF 用零空间避奇异 |
| 加臂后行走性能劣化 | 臂惯量没进模型 | 回步骤 2 回填 URDF，仿真重测后 fine-tune 行走策略 |
| 腕部线束反复断 | 扭转余量不足，疲劳断裂 | 线束留扭转环；多圈旋转场合评估滑环 |
| 夹爪闭合时与腕部干涉 | 末端与腕关节碰撞体未建模 | 回 URDF 补 collision 几何；IK 加自碰撞检查 |
| IK 报求解失败 | 目标在工作空间外 | 可视化查目标点；先做工作空间分析再给目标 |
| 伸手时整机晃动倾倒 | 未做质心补偿 / 速度过大 | 降速复测；站定操作；伸手前查质心投影 |
