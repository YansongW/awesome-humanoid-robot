# M13 · 强化学习训练：在仿真里摔一万次，换实机一次站稳

**全局位置**：仿真模型已调通（M11）、能 PD 站立（M12）之后。输入是仿真环境 + 你的机器人模型，输出是一个**在域随机化下稳定行走的 RL 策略**（checkpoint），交给 M14 做 sim-to-real 部署。

**前置条件**：M10 模型校验通过；M11 环境就绪；有一块能跑 Isaac Lab 的 GPU（显存需求见[计算平台选型手册](../playbooks/compute-selection.md)，按你所选环境核对）。

理论背景：[PPO](/entry/ent_algorithm_ppo/)、[域随机化](/entry/ent_method_domain_randomization/)、[sim-to-real 迁移](/entry/ent_method_sim_to_real/)卡片，[第 18 章 模仿学习与策略学习](/wiki/chapters/chapter-18/)与 [第 23 章 仿真与物理引擎](/wiki/chapters/chapter-23/)；参考实现见 [MuJoCo Playground](/entry/ent_paper_202501_mujoco_playground_2025/) 与 [Isaac Lab](/entry/ent_software_nvidia_isaac_lab_2024/) 官方人形示例。

## 步骤 1：先跑通官方基线，再谈自己的机器人

【做什么】不要第一天就训自己的模型。先在 [Isaac Lab](/entry/ent_software_nvidia_isaac_lab_2024/)（或 MuJoCo Playground）里跑通官方人形/四足行走环境：默认配置训几百 iter，确认 reward 曲线上升、评测能走。然后把自己的 URDF/MJCF 换进去，**先用官方奖励函数**训一版。

【为什么】官方环境帮你隔离变量：管线（obs/action/reward/reset）先证明是对的，剩下的问题就都是"我的模型/奖励"的问题。Berkeley Humanoid Lite 的 RL 行走就是先复现参考管线再迁移自研模型，最终做到零样本 sim-to-real（[arXiv:2504.17249](https://arxiv.org/abs/2504.17249)）。

【你的情况怎么分析】GPU 显存不够跑 4096 并行环境：砍到 512–1024，曲线会慢但能吃；没有 NVIDIA GPU：MuJoCo + CPU 也能训（慢一个量级），先把环境逻辑调对。

## 步骤 2：定义观测、动作与 episode 结构

【做什么】写下三张清单：

1. **观测 obs**：关节位置/速度、IMU 姿态与角速度（[IMU](/entry/ent_component_imu_2024/)）、上一帧动作；进阶加相位时钟（sin/cos 步态相位）。**不要**堆原始点云/图像——先在状态空间学会走。
2. **动作 action**：各关节目标位置（PD 跟踪），按 M10 的 effort/velocity 限位裁剪；缩放系数写成配置，别硬编码。
3. **episode**：时长 10–20 s；摔倒（躯干俯仰角超限、高度过低）即终止；平地随机起点。

【为什么】观测决定了策略"能看见什么"：少了学不成（如缺相位会步态混乱），多了训不动。动作用位置目标而非直接力矩，是为了让底层 PD 替你吸收实机的执行器非理想性——这是 sim-to-real 的关键设计，见[阻抗控制](/entry/ent_method_impedance_control/)与[准直驱执行器](/entry/ent_technology_quasi_direct_drive_actuator_2024/)卡片。

【你的情况怎么分析】实机上拿不到的观测不要放进策略（如基座线速度真值）——除非你有状态估计方案，否则部署时观测缺失 = 策略报废。先在仿真里把 obs 管线写成"可切换真值/估计值"两档。

## 步骤 3：奖励函数——从能站到能走

【做什么】奖励项逐个加，每加一个训一版看曲线，**不要一次全上**。推荐顺序与典型权重思路（具体数值按平台调，以下为常见起点，需自行实验校核）：

| 顺序 | 奖励项 | 作用 | 起点量级 |
|---|---|---|---|
| 1 | 存活/直立 | 不摔倒的保底 | +1/步 |
| 2 | 线速度跟踪 | 跟踪目标速度（先前后走，再转向） | exp(-4·err²) |
| 3 | 姿态/高度 | 躯干俯仰、质心高度惩罚 | -1·err² |
| 4 | 能耗与平滑 | 力矩、力矩变化率惩罚 | -1e-4·Στ² |
| 5 | 步态 shaping | 双支撑/摆动相切换、抬脚高度 | 相位相关小权重 |

【为什么】reward hacking 是 RL 第一大坑：只奖速度会学成原地抖腿，只奖直立会学成站桩不动。"逐项加、逐项看"才能定位是哪一项把策略带歪。奖励设计的系统讨论见 [第 18 章 模仿学习与策略学习](/wiki/chapters/chapter-18/)。

【你的情况怎么分析】曲线平台期超过 2 倍预期 iter 数：先查是不是某惩罚项权重压过了速度项（最常见的死法），把主导项权重砍半再训。每次实验记录配置与曲线截图——调奖励是实验科学，不是玄学。

## 步骤 4：域随机化——给策略打"现实疫苗"

【做什么】在[域随机化](/entry/ent_method_domain_randomization/)里至少覆盖四类，范围按你的实机不确定度估：

| 随机化项 | 建议范围起点 | 对应现实误差 |
|---|---|---|
| link 质量/质心 | ±10–15% | 装配与称重误差（M10 步骤 3） |
| 地面摩擦系数 | 0.5–1.2 | 地板/地砖/地毯差异 |
| 执行器延迟与强度 | 延迟 0–20 ms；力矩 ×0.85–1.0 | 驱动响应与电池电压波动 |
| 随机推力扰动 | 每 5–8 s 一次，≤ 50 N·0.2 s | 碰撞与滑移 |

【为什么】仿真和现实之间的差距（reality gap）不是单一误差，而是所有小误差的叠加；域随机化让策略对"一个误差范围"鲁棒，而不是对"一个精确模型"过拟合。范围太宽学不成，太窄过不了真机——从窄开始，逐步加宽。理论见 [第 23 章 仿真与物理引擎](/wiki/chapters/chapter-23/)。

【你的情况怎么分析】不知道摩擦系数范围？拿鞋底在目标地面上拖测（弹簧秤拉滑块估算）。M14 的系统辨识会回来精修执行器延迟与质量两项——先把范围留宽。

## 步骤 5：训练、评估与 checkpoint 选择

【做什么】

1. 用 [PPO](/entry/ent_algorithm_ppo/) 默认超参起步（lr 3e-4、clip 0.2、entropy 0.01 常见起点，需按环境校核），并行环境数按显存拉满；
2. 每 50–100 iter 存 checkpoint，训练曲线（reward/ep_len/各项惩罚分量）进 TensorBoard 或等效工具；
3. **选 checkpoint 不看最高 reward，看鲁棒评测**：在最大随机化强度 + 推力扰动下连测 100 episode，挑"摔倒率最低且速度达标"的那个。

【为什么】训练后期的 reward 峰往往是过拟合当前随机化种子的假象；鲁棒评测才对应实机表现。Berkeley 的做法是在强化随机化下验证通过再谈实机（berkeley-humanoid-lite 档案）。

【你的情况怎么分析】评测视频逐条看：步态僵硬但能抗推 = 可以上实机（M14 会继续磨）；步态漂亮但一推就倒 = 回步骤 4 加宽随机化。留 2–3 个候选 checkpoint 带去 M14，实机表现才是终审。

## 验收标准

- [ ] 官方基线环境复现成功（截图/曲线存档）。
- [ ] obs/action/episode 三张清单成文，与实机可获取观测对齐。
- [ ] 奖励项逐项添加记录完整，最终配置与曲线存档。
- [ ] 域随机化覆盖质量/摩擦/延迟/推力四类，范围有估算依据。
- [ ] 鲁棒评测（最大随机化 + 扰动）下连续 100 episode 摔倒率 ≤ 10%，前进速度达标。
- [ ] 2–3 个候选 checkpoint 归档，供 M14 实机筛选。

## 常见坑与排查

| 症状 | 可能原因 | 排查动作 |
|---|---|---|
| reward 不涨 | 奖励权重失衡 / 观测缺关键量 / 动作缩放错误 | 逐项砍奖励定位；对照步骤 2 清单；打印 action 实际范围 |
| 原地抖腿不前进 | 速度项权重过低 / 关节力矩限制过死 | 提高速度跟踪权重；核对 effort 限位（M10 步骤 4） |
| 训练发散曲线崩 | lr 过高 / 奖励数值爆炸（某分量量级失控） | lr 降半；逐分量打印归一化 |
| 仿真很好、随机化一开就摔 | 随机化范围一步到位太宽 | 范围砍半，每 500 iter 加宽一档（课程式） |
| 策略对某侧腿"偏科" | 模型左右不对称（URDF 镜像错误） | 回 M10 查镜像关节轴向 |
