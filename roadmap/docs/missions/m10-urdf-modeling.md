# M10 · URDF 建模与导出：把铁疙瘩变成可计算的模型

**全局位置**：整机装完（M09）或结构定型后，仿真（M11–M13）之前。输入是你的机械设计（CAD 或实物），输出是一份**通过校验的 URDF 模型包**（urdf 文件 + mesh + 惯性参数），它是 M11 仿真转换、M12 站立、M13 强化学习的共同地基。

**前置条件**：能读懂 URDF 结构（[Stage 0](../stage-0-foundations.md) 的仿真初体验）；结构尺寸与质量分布已确定。

理论背景：[URDF 机器人描述格式](/entry/ent_technology_urdf_robot_description_format_2024/)卡片与 [第 22 章 软件中间件](/wiki/chapters/chapter-22/)、[第 23 章 仿真与物理引擎](/wiki/chapters/chapter-23/)。

## 步骤 1：定 link/joint 树与命名规范

【做什么】先在纸上画出运动学树：基座（base_link）→ 髋 → 腿 → 踝 → 足，躯干 → 肩 → 臂 → 腕。然后定下三条命名规则并全程遵守：

1. 侧别前缀：`l_` / `r_`（左右腿臂）；
2. 关节类型后缀：`_pitch` / `_roll` / `_yaw`（旋转轴）；
3. 每个 link 的坐标系：**原点在该关节轴线上，z 轴沿关节轴**（与导出器默认一致，后面少踩坑）。

【为什么】90% 的 URDF 问题不是格式错，是**坐标系约定不一致**：轴线画反、原点漂移、左右镜像写错。先在纸上冻结约定，再开软件。关节类型（revolute/prismatic/fixed）与轴向的规范见[URDF 机器人描述格式](/entry/ent_technology_urdf_robot_description_format_2024/)卡片。

【你的情况怎么分析】复刻开源平台（M08）：直接用官方 URDF，本任务只做步骤 4（惯性校核）与步骤 6（校验），其余跳过。自研结构：老老实实走完六步。

## 步骤 2：从 CAD 导出骨架

【做什么】三条路线任选：

| 路线 | 工具 | 适合谁 |
|---|---|---|
| SolidWorks 导出 | `sw_urdf_exporter` 插件 | 结构在 SolidWorks 里设计 |
| Onshape 导出 | `onshape-to-robot` | 云端 CAD、多人协作 |
| 手写 URDF/xacro | 文本编辑器 + xacro 宏 | 结构简单或要参数化（腿长可调） |

导出后第一件事：在 RViz 或 `urdf-viz` 里打开，**逐关节手动拖动**，确认轴向与正负方向与步骤 1 的约定一致。

【为什么】导出器生成的骨架常有冗余 fixed 关节与嵌套 frame，轴向约定也未必符合你的规范；xacro 宏能把 20 个相似关节收敛成一个参数化模板，改一处全局生效。手写骨架前先确认你能在脑子里把每个 joint 的 `origin rpy` 讲出来。

【你的情况怎么分析】没有 CAD 模型只有实物：用卡尺量关节距，直接手写 xacro，桌面级机器人十几个 link 半天能写完；mesh 文件（步骤 5）可以先用几何体（box/cylinder）占位。

## 步骤 3：填惯性参数——模型的灵魂

【做什么】每个 link 必须有 `<inertial>`：`mass`、`origin`（质心）、`inertia`（转动惯量 3×3）。三条获取路径按精度排序：

1. **CAD 材料赋值后读取**：给每个零件赋真实材料密度，CAD 直接输出质心与惯量张量；
2. **实物称重 + 几何近似**：称重得 mass，用等效几何体（长方体/圆柱）惯量公式估算；
3. **摆动法测周期**：悬挂摆动测周期反推惯量（精度最高，操作最繁，详见 [第 9 章 关键子系统设计](/wiki/chapters/chapter-09/) 与[系统辨识](/entry/ent_method_system_identification/)卡片）。

执行器占质量大头：把 M02 选的电机/减速器质量按数据手册填入对应 link，不要均摊。

【为什么】仿真里 80% 的"玄学摔倒"源于惯性参数错误：质量错 20%，控制器整定全废；惯量张量差一个量级，动态响应完全两样。M14 sim-to-real 时还会回来用系统辨识精修这些数。

【你的情况怎么分析】打印件用 CAD 密度 × 打印填充率折算（PLA 约 1.24 g/cm³ × 填充率）。首版允许 10–15% 误差，但**质心位置必须实测验证**：把实物 link 用绳吊起来，垂线交点就是质心，和模型对不上就改。

## 步骤 4：关节限位、传动比与安全边界

【做什么】为每个 revolute 关节填 `<limit>`：`lower/upper`（角度限位，度→弧度）、`effort`（扭矩上限，取 M01 指标表的峰值扭矩）、`velocity`（转速上限，取 M01 的额定转速换算 rad/s）。有减速比的传动写明 `<transmission>` 或在注释里标减速比（M03 的值）。

【为什么】仿真器按限位约束运动；RL 训练（M13）里动作裁剪也读这些值——effort 填大了，策略会学出实机执行不了的动作，sim-to-real 直接失败。安全相关的软件限位必须比机械硬限位小 5–10°。

【你的情况怎么分析】限位角度从结构图纸量，量不到就把实物关节掰到两端用角度尺测。effort 用电机峰值扭矩 × 减速比 × 效率（0.7–0.9 估计值，需按减速器类型校核——M03）。

## 步骤 5：visual 与 collision 几何分离

【做什么】

- `<visual>`：放精细 mesh（STL/DAE），只为好看；
- `<collision>`：放**简化几何**——优先 box/cylinder/sphere 组合，或 convex hull 简化后的 mesh；每个 link 的碰撞体顶点数控制在几百以内。

足底碰撞体单独处理：用平底 box，尺寸略小于实际足底（避免边缘误触），摩擦参数留给 M11 调。

【为什么】物理引擎按 collision 几何算接触，复杂 mesh 既慢又不稳定（尖角、自交）；视觉 mesh 再漂亮对仿真零贡献。[MuJoCo 物理引擎](/entry/ent_software_mujoco_physics_engine_2022/)与 [Gazebo](/entry/ent_software_gazebo/) 的官方文档都把"碰撞体简化"列为性能与稳定性的首要建议。

【你的情况怎么分析】3D 打印件直接用打印 STL 做 visual；collision 用 CAD 里同名零件的外接 box 手工写，比转 convex hull 更可控。mesh 单位注意 STL 是毫米还是米——URDF 默认米，导出时缩放出错是经典坑。

## 步骤 6：校验与导出交付

【做什么】依次通过四道关：

1. `check_urdf model.urdf`：运动学树解析无错；
2. RViz / urdf-viz 可视化：轴向、限位、mesh 缩放正确；
3. 质量报告：全模型总质量 = 实物称重 ±10%，总质心位置合理（站立时投影在支撑面内）；
4. 打包交付：`robot_description/`（urdf + meshes + 一个 README 记录坐标系约定与惯性来源），提交版本管理。

【为什么】这四关是 M11 的入场券——模型转换（URDF→MJCF/USD）会把小错误放大成"仿真一跑就飞"。交付包进版本管理，M13 改模型时你才知道改了什么。

【你的情况怎么分析】校验报错优先查：`origin` 漏写单位（度 vs 弧度）、惯性张量非正定、mesh 路径大小写。三样占了 URDF 报错的绝大多数。

## 验收标准

- [ ] 运动学树与命名规范成文（一张纸：树图 + 轴向约定）。
- [ ] `check_urdf` 通过，RViz 逐关节拖动轴向/方向正确。
- [ ] 每个 link 有惯性参数，总质量与实物称重偏差 ≤ 10%，质心吊线验证通过。
- [ ] 每个 revolute 关节有 limit（角度/effort/velocity），数值与 M01 指标表一致。
- [ ] visual/collision 几何分离，碰撞体为简化几何。
- [ ] 模型包入库（含坐标系约定 README），可供 M11 直接转换。

## 常见坑与排查

| 症状 | 可能原因 | 排查动作 |
|---|---|---|
| RViz 里模型"炸开"或乱飞 | 关节 origin 写错 / mesh 单位错（mm 当 m） | 逐级注释 joint 排查；mesh 缩放 ×0.001 试试 |
| 仿真站立时 slowly 倾倒 | 质心位置错 / 总质量与实物不符 | 吊线法复测质心；重新称重比对 |
| 转换 MJCF 报惯性张量错误 | 惯量矩阵非正定（手写估错） | 检查 ixx/iyy/izz 满足三角不等式，用 CAD 重导 |
| RL 策略学不会站立 | effort/velocity 限位虚高 | 回步骤 4 按电机真实能力重填 |
| 左右腿行为不对称 | 镜像关节轴向/正负号写反 | 对照命名规范逐关节核查 rpy 与 axis |
