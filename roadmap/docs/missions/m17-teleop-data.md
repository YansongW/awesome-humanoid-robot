# M17 · 遥操作与数据采集：模仿学习的粮食是这样种出来的

**全局位置**：手臂（M15）与感知栈（M16）就绪之后、模仿学习训练（M18）之前。输入是一台可安全运动的机器人 + 一套标定好的感知栈，输出是 **≥50 条过质检的 episode 数据集**——M18 的训练脚本直接拿去用，不再返工。

**前置条件**：M16 验收通过（感知输出稳定、时间同步已核查）；机器人可安全上电运动，急停回路可用（见 [阶段 3 总览](../stage-3-humanoid.md) 步骤 15）。

理论背景：[第 17 章 遥操作与人机协作](/wiki/chapters/chapter-17/) 讲遥操作系统设计，[第 21 章 数据基础设施](/wiki/chapters/chapter-21/) 讲数据管线，[附录 B 关键数据集清单](/wiki/appendices/appendix-b/) 是可对标的公开数据集。

## 步骤 1：遥操作方案选择

【做什么】四档对比，按预算与任务选一档：

| 方案 | 成本量级 | 数据质量 | 适合谁 |
|---|---|---|---|
| leader-follower 主从臂（[ALOHA](/entry/ent_technology_aloha_teleoperation_system_2023/) 路线） | 整套约 2 万美元级（卡片口径） | 高：同构映射、关节级对应 | 双臂精细操作 |
| VR 手柄/头显 | 消费级 VR 设备价 | 中：末端位姿 + 姿态重定向 | 移动人形、全身遥操作 |
| 外骨骼 | 需自行向供应商确认 | 高但穿戴繁琐 | 研究型团队 |
| 键盘/摇杆 | 几乎为零 | 低：速度慢、动作粗糙 | 兜底验证管线 |

两个重要变体：

- **无整机也能采**：[UMI 夹爪接口](/entry/ent_technology_umi_gripper_interface_2024/)——手持夹爪 + 腕部相机，人拿着夹爪做演示即可采训练数据（卡片口径）。
- **移动人形务实分工**：下肢摇杆定点 + 上肢主从，借鉴 [Mobile ALOHA](/entry/ent_technology_mobile_aloha_2024/) 的全身遥操作思路（Stage 3 口径）——别指望一边遥操作走路一边做精细抓握。

锚点：[ToddlerBot](/entry/ent_robot_system_toddlerbot/) 用同构示教臂（握把内嵌 FSR 力敏电阻）+ 掌机摇杆按键，2.0 版加 Meta Quest 2 VR 遥操作；Berkeley Humanoid Lite 用 SteamVR 基站 + 手柄遥操作双臂完成魔方、写字、搭积木演示（均为 `data/roadmap/research/` 调研档案口径）。

【为什么】遥操作一石三鸟：验证硬件可达性、采集模仿学习数据、建立任务 baseline（Stage 3）。VR 路线有两个硬约束：**延迟**（端到端延迟到百毫秒量级操作员手感明显变差，工程经验值，按你的系统实测）与**晕动症**——先小流量测延迟，再排长时采集。

【你的情况怎么分析】预算极紧：UMI 先采起来，格式对齐，后面换真机复用；有双足人形：上肢主从 + 下肢摇杆定点；只想验证管线：摇杆兜底跑通"录制 → 回放 → 训练"闭环，再升级设备。

## 步骤 2：采集管线搭建

【做什么】把"录什么、怎么录、存哪"冻结成规范：

1. **记录字段**（与 Stage 3 步骤 9 一致）：多视角图像（头部 + 双腕）、关节状态（位置/速度）、动作（主从映射后的目标关节位置）、语言指令、时间戳。
2. **统一帧率**：所有流统一采样到 **10–30 Hz**（工程建议值，按存储与算力实测定档），对齐复用 M16 的时间同步设施。
3. **存储格式**：[ROS 2](/entry/ent_software_ros_2_middleware_2024/) bag 起步；要对接开源训练生态就用 [LeRobot](/entry/ent_software_lerobot_2024/) 或 RLDS 风格——[Open X-Embodiment](/entry/ent_dataset_open_x_embodiment/) 正是用统一 RLDS 格式聚合跨本体百万级演示帧，是 VLA 预训练标准语料（卡片口径）。
4. **目录与命名**：`任务名/日期/操作员/episode_序号`，元数据（标定版本、指令文本、成功标签）随包落盘。

【为什么】格式决定复用性：字段缺一项（比如没存语言指令），后面想训指令条件策略就得整批重采。命名规范让"哪条数据是哪个标定版本采的"可追溯——标定过期的批次必须能整批筛出。

【你的情况怎么分析】单机单任务：bag + 一个解析脚本就够；计划多任务/多机器人：直接对齐 LeRobot/OXE 格式，一开始就别发明私有格式。

## 步骤 3：任务与场景设计

【做什么】

1. **单任务起步**：第一个任务固定为"抓杯子放到盒子"，跑通全链路再扩品类。
2. **场景随机化清单**：物体位置/姿态（工作空间内均匀撒）、光照（亮度/方向变化）、背景（换桌布/杂物）、干扰物（逐步加入无关物体）。每条开录前掷骰子决定本条随机化档位。
3. **指令模板化**："把{物体}放到{容器}"式模板，词表冻结，episode 里存的指令字符串一律从模板生成。
4. **成功判据先定义死**：例如"夹爪闭合后物体悬停 3 s 不掉、最终落入容器"——每条 episode 当场打成功/失败标签。

【为什么】策略学到的是数据分布：只采"杯子在正中央"，它就只会在正中央抓。随机化清单就是策略的泛化边界，要写在采集计划里而不是凭当天心情。成功判据模糊会造成标签噪声——M18 训练时表现为"同样的演示有的能学有的学不动"。

【你的情况怎么分析】桌面固定机：随机化先做物体位置/姿态两项（性价比最高）；光照与背景等单任务成功率稳定后再加。每加一档随机化，episode 预算相应翻倍。

## 步骤 4：采集执行规范

【做什么】

1. **质量 > 数量**：动作平稳、速度适中（操作员觉得"有点慢"的节奏正好）、无遮挡；画面里永远同时看得到末端与目标物。
2. **失败 episode 处置**：演示中途失败的整集**保留并打失败标签**，但 M18 训练默认只用成功集；操作员主动演示的"从失误中恢复"片段（掉了重抓）单独标记——恢复数据教策略纠错，价值高，但占比控制在两三成以内（工程建议值），免得策略学会"故意失误"。
3. **产能预期**：熟练操作员每小时 10–20 条量级（工程建议值，含场景重置与抽检）；50 条高质量数据按 3–5 个工作时规划。
4. **即时回放抽检**：每采 5–10 条回放 1 条，查画面、时间对齐、标签；多人采集时记录每条的操作员 ID——风格差异是数据分布的一部分。

【为什么】模仿学习对演示质量极度敏感：又抖又快的演示，策略学出来就是又抖又快。即时抽检把"采了一天才发现时间戳全漂"这类事故压缩在 10 条以内。

【你的情况怎么分析】单人项目：自己定节奏，宁可一天 20 条高质量；多人轮班：开工前统一看 3 条"标准示范"校准手感，收工互查对方 2 条。

## 步骤 5：数据质检与划分

【做什么】

1. **自动质检脚本**，每条 episode 过三关：
   - 时间对齐：图像与动作时间戳错位 < 1 帧量级（工程建议值）；
   - 掉帧检测：各流实际帧率 vs 目标帧率，掉帧率超标即标黄；
   - 图像质量：模糊（拉普拉斯方差）、过曝/欠曝（直方图）按阈值筛。
2. **训练/验证 9:1 划分**：按 episode 随机分，验证集一经划定即冻结，M18 每次实验用同一份。
3. **数据集卡（dataset card）**：机器人型号/传感器配置/标定版本/采集日期/任务定义/指令模板/条数与统计，一页成文。[DROID](/entry/ent_dataset_droid/) 是分布式多实验室采集的规范参照（卡片口径，局限：只覆盖固定臂）；[Open X-Embodiment](/entry/ent_dataset_open_x_embodiment/) 是跨本体聚合的格式参照。

【为什么】"数据能不能用"不靠回忆靠脚本：质检报告（对齐误差、掉帧率、模糊占比）存档后，M18 训练出问题时可以先排除数据嫌疑。数据集卡是你一个月后、或别人接手时唯一的真相来源。

【你的情况怎么分析】50 条也要走全套：脚本一次写好，500 条时零成本复用；验证集 5 条也要留——没有冻结验证集，M18 的每次"提升"都无法归因。

## 验收标准

- [ ] ≥50 条过质检的 episode（Stage 3 判据），成功/失败标签齐全。
- [ ] 记录字段与帧率规范成文，且实测可被 M18 训练脚本直接读取。
- [ ] 场景随机化清单与指令模板冻结，episode 覆盖随机化各档。
- [ ] 质检报告存档：时间对齐误差、掉帧率、图像质量统计有数字。
- [ ] 训练/验证 9:1 划分完成，验证集冻结。
- [ ] 数据集卡成文：含机器人/传感器/标定版本/日期/任务定义/统计与操作员信息。
- [ ] 数据有备份：原始 bag 与解析后格式各一份，异盘或异地存放。

## 常见坑与排查

| 症状 | 可能原因 | 排查动作 |
|---|---|---|
| 策略动作总比画面慢半拍 | 图像-动作时间戳漂移未察觉 | 质检脚本查对齐误差；回 M16 查双机对时 |
| 回放时某段图像卡帧 | 采集掉帧（USB 带宽/磁盘写入瓶颈） | 查掉帧报告；降分辨率或换 SSD；回 M16 查 USB 拓扑 |
| 策略学出抖动动作 | 演示本身又快又抖 | 抽检回放演示视频；降操作节奏重采 |
| 物体换个位置就抓不到 | 只采了中心区/单一姿态 | 对照随机化清单补采边角与多样姿态 |
| 成功率统计忽高忽低 | 成功判据执行不一致 | 成功判据写成逐条 checklist，判标签时照打钩 |
| 磁盘爆了或数据丢失 | 无备份、bag 只存一份 | 采集当日双备份；存储余量纳入开工检查 |
| 多人数据风格分裂 | 操作员手感差异未记录 | 数据集卡记操作员 ID；开工前统一示范校准 |
